타입의 2대 분류

C# 타입은 크게 value type과 reference type으로 나뉜다. 이 구분은 메모리 저장 위치, 복사 의미, 동등 비교까지 모든 동작에 영향을 준다.

분류종류저장 위치기본값
value typestruct, enum, 기본 숫자 타입(int, double, bool, char), DateTime, Guid스택 또는 객체 내부0 / false
reference typeclass, interface, delegate, string, 배열힙 (스택에는 참조만)null

다만 "스택에 저장된다"는 표현은 단순화한 설명이다. value type이라도 클래스 필드로 들어가면 그 객체의 일부로 힙에 함께 놓인다. 핵심은 "변수가 값 자체를 들고 있느냐, 참조만 들고 있느냐"이다.

// value type 정의
public struct Point
{
    public int X;
    public int Y;
}

// reference type 정의
public class Person
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}

Point p = new Point { X = 3, Y = 4 };        // 스택에 저장
Person person = new Person { Name = "Alice" }; // 힙에 객체, 스택에는 참조

value vs reference 의미

복사 의미

value type을 다른 변수에 대입하면 값 전체가 복사된다. reference type은 참조(주소)만 복사되어 두 변수가 같은 객체를 가리킨다.

// value type
Point a = new Point { X = 1, Y = 2 };
Point b = a;           // 값 복사 (별도 객체)
b.X = 100;
Console.WriteLine(a.X); // 1 (a는 안 바뀜)

// reference type
Person p1 = new Person { Name = "Alice" };
Person p2 = p1;        // 참조 복사 (같은 객체)
p2.Name = "Bob";
Console.WriteLine(p1.Name); // "Bob" (같이 바뀜)
실행 결과
1 Bob

함수 인자 전달

기본 전달 방식은 값 전달이다. value type은 값 자체가, reference type은 참조 값이 복사된다. 참조형 매개변수의 내부 필드를 바꾸면 원본 객체에 반영되지만, 매개변수에 새 객체를 대입해도 호출자의 변수는 바뀌지 않는다.

void Modify(Point p) { p.X = 99; }
void Rename(Person person) { person.Name = "Changed"; }
void Replace(Person person) { person = new Person { Name = "New" }; }

Point pt = new Point { X = 1 };
Modify(pt);
Console.WriteLine(pt.X);        // 1  (값 복사이므로 원본 영향 없음)

Person p = new Person { Name = "Origin" };
Rename(p);
Console.WriteLine(p.Name);      // "Changed"  (같은 객체의 필드를 수정)

Replace(p);
Console.WriteLine(p.Name);      // "Changed"  (매개변수만 다른 객체를 가리킴)

원본 변수 자체를 바꾸려면 ref 키워드를 쓴다. 출력 전용으로 받고 싶다면 out을 사용한다.

void Increment(ref int n) { n++; }
void TryParse(string s, out int result) { result = int.Parse(s); }

int x = 10;
Increment(ref x);
Console.WriteLine(x); // 11

TryParse("42", out int y);
Console.WriteLine(y); // 42

동등 비교

value type의 ==는 값 비교이지만, reference type의 기본 ==는 참조 비교다(즉 같은 객체인지). Equals는 타입에 따라 다르며, string·record는 값 의미로 오버라이드되어 있다.

int i1 = 5, i2 = 5;
Console.WriteLine(i1 == i2);          // True (값 비교)

Person p1 = new Person { Name = "A" };
Person p2 = new Person { Name = "A" };
Console.WriteLine(p1 == p2);          // False (다른 객체)
Console.WriteLine(p1.Equals(p2));     // False (기본은 참조 비교)

string s1 = "hello", s2 = "hello";
Console.WriteLine(s1 == s2);          // True (string은 값 비교로 오버로드됨)

박싱과 언박싱

value type을 object나 인터페이스 참조로 다룰 때 일어나는 변환이다. value를 힙에 새 객체로 감싸는 동작이 박싱(boxing), 다시 꺼내는 것이 언박싱(unboxing)이다.

int n = 42;
object boxed = n;        // 박싱: 힙에 객체 할당, n의 값을 그 안에 복사
int unboxed = (int)boxed; // 언박싱: 캐스팅으로 값 추출

// 박싱이 일어나는 흔한 상황
ArrayList list = new ArrayList();
list.Add(1);             // int → object 박싱
list.Add(2);
list.Add(3);

int sum = 0;
foreach (object o in list)
{
    sum += (int)o;       // 매 반복마다 언박싱
}
박싱은 비싸다 힙 할당 + 복사 + GC 부담이 따라온다. 루프에서 박싱이 반복되면 성능이 크게 떨어진다. 제네릭 컬렉션(List<int>, Dictionary<int, T>)을 쓰면 박싱이 일어나지 않는다. ArrayList는 레거시이며 사용을 피한다.

인터페이스 호출도 박싱을 유발할 수 있다.

int x = 10;
IComparable c = x;       // 박싱 발생 (struct → 인터페이스)
c.CompareTo(20);

// 제네릭 + 제약을 쓰면 박싱 없이 호출 가능
void Compare<T>(T a, T b) where T : IComparable<T>
{
    a.CompareTo(b);      // T가 struct여도 박싱 없음
}

nullable 타입

value type은 본래 null을 가질 수 없다. ?를 붙이면 Nullable<T> 구조체로 감싸져 null 표현이 가능해진다.

int a = null;       // 컴파일 에러
int? b = null;      // OK — Nullable<int>
int? c = 42;

if (c.HasValue)
{
    Console.WriteLine(c.Value);   // 42
}

// null 병합 연산자 ??
int d = b ?? -1;    // b가 null이면 -1 사용

// null 조건부 연산자 ?.
string? name = person?.Name;
int? len = name?.Length;

nullable reference types (C# 8+)

참조형은 원래 항상 null을 받을 수 있었고, 이로 인한 NullReferenceException이 끊이지 않았다. C# 8부터 nullable reference types(NRT) 기능을 켜면 reference type도 nullable/non-nullable을 명시적으로 구분한다.

// .csproj 또는 파일 상단에 활성화
// <Nullable>enable</Nullable>
#nullable enable

string s1 = null;     // 경고: null을 non-nullable에 대입
string? s2 = null;    // OK — null 허용

void Print(string? s)
{
    Console.WriteLine(s.Length);  // 경고: null 가능
    if (s != null)
    {
        Console.WriteLine(s.Length); // OK — 흐름 분석으로 null 아님 확인
    }
    Console.WriteLine(s!.Length); // null-forgiving — 개발자가 null 아님을 보증
NRT는 런타임 강제가 아니다 컴파일러 분석/경고일 뿐 런타임에 null이 막히지는 않는다. 그래도 코드 의도를 명확히 하고 NPE를 크게 줄여 준다. 새 프로젝트에서는 반드시 켠다.

string은 reference지만 immutable

string은 reference type이지만 두 가지 특수성이 있다.

  • 불변(immutable) — 한 번 만들면 내용을 바꿀 수 없다. s + "x"처럼 보이는 수정은 사실 새 문자열을 만든다.
  • 값 의미의 비교 — ==가 참조가 아니라 내용을 비교하도록 오버로드되어 있다.
string a = "hello";
string b = "hello";
Console.WriteLine(a == b);                 // True (내용 비교)
Console.WriteLine(ReferenceEquals(a, b));  // True도 흔함 — interning으로 동일 객체 재사용

string c = a + " world";   // 새 문자열 객체 생성
// a는 그대로 "hello"

// 반복 수정은 StringBuilder를 쓴다
var sb = new StringBuilder();
for (int i = 0; i < 1000; i++)
{
    sb.Append(i);          // 매번 새 string 만들지 않음
}
string result = sb.ToString();
+= 반복은 함정 루프 안에서 s += "x"는 매번 새 string과 새 할당을 만든다. n번 반복하면 O(n²) 할당이다. 다량의 문자열 조립에는 StringBuilder나 string.Concat·string.Join을 쓴다.

record와 record struct

C# 9에서 추가된 record는 값 의미의 reference type이다. C# 10의 record struct는 그 value 버전이다. 컴파일러가 구조적 동등성 비교, ToString, with 식 등을 자동 생성한다.

// 위치 매개변수 record (가장 간결)
public record Point2D(double X, double Y);

// 일반 record
public record Person
{
    public string Name { get; init; } = "";
    public int Age { get; init; }
}

var p1 = new Point2D(1.0, 2.0);
var p2 = new Point2D(1.0, 2.0);

Console.WriteLine(p1 == p2);            // True — 구조적 동등성
Console.WriteLine(p1.ToString());       // Point2D { X = 1, Y = 2 }

// with 식 — 일부 속성만 바꾼 복사본
var p3 = p1 with { Y = 99.0 };          // (1.0, 99.0), p1은 그대로

// 분해(deconstruction)
var (x, y) = p1;

record struct

public readonly record struct Pixel(byte R, byte G, byte B);

Pixel a = new(255, 0, 0);
Pixel b = a with { R = 128 };  // value 복사 + 일부 수정
Console.WriteLine(a == b);     // False (R 다름)
구분저장동등성주 용도
class힙참조일반 객체, 정체성 있는 엔티티
struct값값(직접 정의)작은 값, Point/Size 등
record힙구조적DTO, 불변 데이터 모델
record struct값구조적작은 불변 값 타입

제네릭과 타입 제약

C# 제네릭은 C++ 템플릿과 비슷하지만 런타임에 타입 정보가 보존되고, 컴파일이 아닌 JIT 시점에 타입별 코드가 만들어진다(value type별, reference type은 공유).

// 제네릭 클래스
public class Box<T>
{
    public T Value { get; set; } = default!;
    public void Print() => Console.WriteLine(Value);
}

var b1 = new Box<int> { Value = 42 };
var b2 = new Box<string> { Value = "hi" };

// 제네릭 메서드
public static T Max<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) >= 0 ? a : b;
}

int m = Max(3, 7);
string s = Max("apple", "banana");

타입 제약(where)

제약의미
where T : classreference type만 허용 (T가 null 가능)
where T : structvalue type만 허용 (T가 nullable 아님)
where T : new()매개변수 없는 public 생성자 보장
where T : IDisposable특정 인터페이스/기반 클래스를 구현
where T : SomeBaseClass특정 클래스를 상속
where T : unmanaged참조 필드 없는 값 타입 (interop용)
where T : notnullnull 불가 (NRT 활성 시)
where T : U다른 타입 매개변수 U의 하위 타입
// 복합 제약
public class Repository<T> where T : class, IEntity, new()
{
    public T Create() => new T();      // new() 제약 덕에 가능
    public int GetId(T item) => item.Id; // IEntity 제약 덕에 가능
}

// unmanaged — 픽셀 같은 POD 처리에 유용
public unsafe void Fill<T>(Span<T> buffer, T value) where T : unmanaged
{
    for (int i = 0; i < buffer.Length; i++) buffer[i] = value;
}

공변·반공변

제네릭 인터페이스/델리게이트의 타입 매개변수에 out(공변) 또는 in(반공변)을 붙이면 상속 관계가 제네릭 타입으로 "전파"된다.

  • 공변(covariant) out T — T를 반환만 한다. 더 파생된 타입으로 → 더 기본 타입으로 대입 가능.
  • 반공변(contravariant) in T — T를 입력만 받는다. 반대 방향 대입 가능.
// IEnumerable<out T> — 공변
IEnumerable<string> strings = new List<string> { "a", "b" };
IEnumerable<object> objects = strings;  // OK — string은 object의 하위, T 위치는 반환만

// IComparer<in T> — 반공변
IComparer<object> objCmp = Comparer<object>.Default;
IComparer<string> strCmp = objCmp;       // OK — object 비교기를 string 비교기로 사용

// 배열은 (안전하지 않은) 공변
object[] arr = new string[3];
arr[0] = 42;   // 컴파일 OK, 런타임 ArrayTypeMismatchException
외우는 요령 out은 출력(반환) 위치에서만, in은 입력 위치에서만 쓰인다는 뜻. 그래서 위쪽(out: 더 일반적인 타입)이나 아래쪽(in: 더 특수한 타입) 한 방향으로만 안전하게 대입할 수 있다.

delegate와 event

delegate는 메서드를 변수처럼 다루는 reference type이다. C++의 함수 포인터 + std::function에 가깝다.

// 직접 정의하는 delegate
public delegate int BinaryOp(int a, int b);

BinaryOp add = (a, b) => a + b;
BinaryOp mul = (a, b) => a * b;
Console.WriteLine(add(2, 3));  // 5

// 표준 제네릭 delegate
Func<int, int, int> sub = (a, b) => a - b;
Action<string> log = msg => Console.WriteLine(msg);
Predicate<int> isPositive = n => n > 0;

// 멀티캐스트 — + 로 체인 가능
Action<string> loggers = log;
loggers += msg => File.AppendAllText("log.txt", msg);
loggers("hello"); // 두 핸들러 모두 호출

event는 delegate를 외부에서 안전하게 구독/해제할 수 있게 캡슐화한 키워드다. 자세한 패턴은 이후 다른 글에서 다룬다.

public class Button
{
    public event EventHandler? Clicked;

    public void RaiseClick()
    {
        Clicked?.Invoke(this, EventArgs.Empty);
    }
}

var btn = new Button();
btn.Clicked += (s, e) => Console.WriteLine("clicked");
btn.RaiseClick();

인터페이스 vs 추상 클래스

특성interfaceabstract class
다중 구현/상속다중 구현 가능단일 상속만
필드불가 (속성은 가능)가능
생성자없음있음 (호출 가능)
구현 포함C# 8+ default method 가능일반 메서드 포함 자유
주 용도능력/계약(can-do)공통 기반(is-a) + 부분 구현
// 인터페이스 — 능력
public interface IShape
{
    double Area();              // 추상 멤버

    // C# 8+ default 메서드
    string Describe() => $"shape with area {Area()}";
}

public interface IDrawable
{
    void Draw();
}

// 다중 구현
public class Circle : IShape, IDrawable
{
    public double Radius { get; init; }
    public double Area() => Math.PI * Radius * Radius;
    public void Draw() => Console.WriteLine($"circle r={Radius}");
}

// 추상 클래스 — 공통 기반 + 부분 구현
public abstract class Animal
{
    public string Name { get; }
    protected Animal(string name) { Name = name; }

    public abstract string Sound();
    public void Introduce() => Console.WriteLine($"{Name} says {Sound()}");
}

public class Dog : Animal
{
    public Dog(string name) : base(name) { }
    public override string Sound() => "woof";
}
선택 기준 "할 수 있는 것"(behavior contract)은 인터페이스, "무엇인가"(공통 상태 + 일부 구현)는 추상 클래스. WPF/MVVM 코드에서는 INotifyPropertyChanged, ICommand 같은 인터페이스를 매우 자주 만난다.

C++ 개발자 관점

struct과 class가 의미가 다르다

C++에서 struct와 class의 차이는 기본 접근 지정자(public vs private) 정도다. C#에서는 본질적으로 다른 카테고리다.

구분C++C#
structclass와 동일(기본 public)value type — 복사, 스택 가능
classclass(기본 private)reference type — 항상 힙

"참조"의 의미가 다르다

C++의 T&는 호출 지점 문법으로 결정된다. 같은 타입을 T(복사), T&(참조), T*(포인터)로 자유롭게 받을 수 있다. C#은 다르다.

  • 타입이 value/reference 의미를 결정한다. class로 선언했으면 어디서 받든 참조다.
  • 호출 지점 수식자는 ref, out, in 정도이며, 의미가 좁다(원본 변수 자체에 대한 참조 전달).
// C++
void f(Point p);     // 값 복사
void g(Point& p);    // 참조 (호출자 선택의 여지 없음, 시그니처가 결정)
void h(const Point& p);
Point pt; f(pt); g(pt); h(pt);
// C# — 타입 자체가 value/reference 의미를 가짐
void F(Point p) { }    // Point가 struct면 값 복사
void G(Person p) { }   // Person이 class면 참조 복사 (객체는 공유)

// 원본 변수 자체를 참조로 받고 싶을 때만 ref
void Swap(ref int a, ref int b) { (a, b) = (b, a); }
int x = 1, y = 2;
Swap(ref x, ref y);   // 호출자도 ref 표기 필수

수명 관리

C++은 RAII와 스마트 포인터로 수명을 명시한다. C#은 GC가 reference type을 관리한다. 그러나 파일/소켓/네이티브 핸들 같은 외부 자원은 IDisposable + using으로 결정론적으로 해제해야 한다.

// using 선언 (C# 8+) — 스코프 종료 시 Dispose
using var file = File.OpenRead("a.bin");
// ... 사용 ...
// 메서드 종료 시 자동 file.Dispose()

흔한 함정

가변 struct을 reference처럼 다루기

public struct Counter
{
    public int Value;
    public void Increment() => Value++;
}

var list = new List<Counter> { new Counter() };
list[0].Increment();              // 컴파일 에러 또는 효과 없음 — 인덱서가 복사본 반환
Console.WriteLine(list[0].Value); // 0

// 회피: 값을 꺼내서 수정 후 다시 넣거나, 애초에 struct을 immutable로 설계
var c = list[0];
c.Increment();
list[0] = c;
struct은 immutable이 기본 가변 struct은 복사 시점마다 직관에 어긋나는 동작을 만든다. readonly struct로 선언하고, 변경이 필요하면 with로 새 인스턴스를 만든다.

큰 struct을 값으로 넘기기

public struct BigData     // 256바이트 가정
{
    public fixed byte Buffer[256];
}

void Process(BigData d) { /* ... */ }  // 호출마다 256바이트 복사

// 회피: in 매개변수로 읽기 전용 참조 전달
void Process(in BigData d) { /* d는 읽기 전용 */ }

가이드라인: struct은 보통 16바이트 이하로 유지한다. 그보다 크면 class로 만들거나 in 매개변수로 전달한다.

의도치 않은 박싱

int n = 42;

// 문자열 보간 — ToString이 호출되므로 박싱 없음
Console.WriteLine($"n = {n}");

// 그러나 object로 받는 API는 박싱 유발
void LogAny(object value) { /* ... */ }
LogAny(n);                  // 박싱

// 제네릭 + 제약을 쓰면 박싱 회피
void LogAny<T>(T value) { /* ... */ }
LogAny(n);                  // 박싱 없음 (T = int)

// LINQ도 박싱 주의 — IEnumerable<object> 등
var list = new List<int> { 1, 2, 3 };
var sum = list.Sum();       // 박싱 없음 (전용 오버로드)

nullable 비활성에서의 NullReferenceException

// NRT가 꺼진 코드 — 컴파일러가 도와주지 않음
string GetName(Person p) => p.Name;  // p가 null이면 NRE

GetName(null);   // 런타임 폭발

// 방어 코드
string GetName(Person? p) => p?.Name ?? "(unknown)";

// 또는 ArgumentNullException으로 명시
string GetName(Person p)
{
    ArgumentNullException.ThrowIfNull(p);
    return p.Name;
}
새 프로젝트는 NRT 켜고 시작 프로젝트 파일에 <Nullable>enable</Nullable>를 넣는 것이 가장 비용 대비 효과가 큰 한 줄이다. NRE 종류의 버그 대부분을 컴파일 단계에서 잡아낸다.

struct의 기본 생성자

public struct Vec2
{
    public double X, Y;
    public Vec2(double x, double y) { X = x; Y = y; }
}

Vec2 v = new Vec2();   // 모든 필드가 0
Vec2 w = default;      // 동일 — 모든 필드 0
// 매개변수 없는 사용자 정의 생성자는 C# 10부터만 허용되며, default와 동작이 다를 수 있음
