책 개요

Effective Modern C++

저자Scott Meyers
출판O'Reilly Media, 2014
분량42개 Item, 약 330쪽
읽은 날2026-05-15
4.5 / 5.0

Effective Modern C++는 Scott Meyers가 2014년에 펴낸 책이다. 1990년대부터 이어진 Effective C++ 시리즈의 "모던 편"에 해당한다. 기존 Effective C++, More Effective C++가 C++98/03을 다뤘다면, 이 책은 C++11과 C++14에서 새로 들어온 기능을 다룬다.

부제가 말해주듯, 이 책은 "C++11/14를 어떻게 효과적으로(effectively) 쓸 것인가"에 집중한다. 문법 입문서가 아니라, 이미 새 기능의 존재는 아는 사람에게 그 기능을 언제·왜·어떻게 써야 하는지를 알려주는 책이다.

대상 독자는 C++ 기본 문법을 아는 중급 이상 개발자다. 특히 C++98/03 시절에 C++을 배운 뒤 모던 C++로 넘어오려는 사람에게 가장 잘 맞는다. 참고로 이 책은 Scott Meyers가 C++ 분야에서 펴낸 마지막 저작이기도 하다.

핵심 메시지

이 책의 핵심 메시지는 한 문장으로 요약된다. "모던 C++의 새 기능은 그냥 쓰는 게 아니라, 동작 원리를 이해하고 써야 한다."

Meyers는 42개의 항목(Item)으로 내용을 나눈다. 각 Item은 하나의 구체적인 조언을 제목으로 달고 있고, 그 조언이 왜 옳은지를 표준의 동작 규칙으로 증명한다. 시리즈 전통대로 Item 제목 자체가 결론이라, 목차만 훑어도 핵심 가이드라인이 손에 들어온다.

중요한 점은 이 책이 "이렇게 써라"라는 규칙의 나열에 그치지 않는다는 것이다. 각 조언마다 왜 그래야 하는지, 언제는 예외인지까지 파고든다. 그래서 같은 분량의 다른 책보다 밀도가 높고, 한 Item을 제대로 소화하는 데 시간이 걸린다.

"Effective" 시리즈의 형식 각 Item은 "~하라(Prefer / Use / Avoid …)" 형태의 명령형 제목 + 근거 설명 + 기억할 점(Things to Remember) 요약으로 끝난다. 바쁘면 제목과 요약만 봐도 되고, 깊이 알고 싶으면 본문을 읽으면 된다.

책의 구조

책은 주제별 챕터로 나뉘고, 각 챕터 안에 여러 Item이 들어간다. 큰 흐름은 다음과 같다.

챕터 주제다루는 내용
타입 추론auto, decltype, 템플릿 타입 추론 규칙. 컴파일러가 타입을 어떻게 결정하는지.
autoauto를 적극 쓰되, 추론 결과가 의도와 다를 때의 함정과 대처법.
모던 C++ 기능 전반{} 초기화, nullptr, 별칭 선언, enum class, =delete, override, constexpr, noexcept 등.
스마트 포인터unique_ptr / shared_ptr / weak_ptr 선택 기준, make 함수 활용, pImpl 이디엄.
rvalue 참조 · 이동 · 완벽 전달이동 의미론, forwarding reference, std::move / std::forward, 완벽 전달의 실패 케이스.
람다 표현식캡처 방식 선택, init capture, std::bind보다 람다를 선호하는 이유.

각 챕터가 독립적이라 순서대로 읽지 않아도 된다. 다만 "타입 추론" 챕터는 뒤의 forwarding reference 설명의 토대가 되므로 먼저 읽어두는 편이 좋다.

핵심 주제

auto의 함정

책은 auto를 적극적으로 쓰라고 권하지만, 동시에 추론 결과가 직관과 어긋나는 경우를 경고한다. 대표적인 것이 프록시 타입 문제다.

std::vector<bool> flags = GetFlags();

// 의도: bool 하나를 받고 싶다
auto b = flags[0];   // 실제 타입은 bool이 아니라
                     // std::vector<bool>::reference (프록시)

// flags가 소멸하면 b는 댕글링이 될 수 있다
bool real = flags[0];   // 이렇게 명시하거나
auto fixed = static_cast<bool>(flags[0]);   // 강제 변환

여기서 얻는 교훈은 "auto는 보이지 않는 프록시 타입까지 그대로 추론한다"는 것이다. 편하다고 무조건 쓰는 게 아니라, 추론 규칙을 알고 써야 한다.

스마트 포인터 선택

스마트 포인터 챕터의 결론은 단순하다. 기본은 unique_ptr, 공유 소유가 진짜 필요할 때만 shared_ptr다. shared_ptr은 제어 블록과 atomic 참조 카운트라는 비용을 동반하므로 습관적으로 쓰면 안 된다는 점을 강조한다. 또한 객체 생성은 가능하면 make_unique / make_shared로 하되, 그 함수들의 한계(custom deleter 미지원 등)도 함께 설명한다.

이동 의미론과 완벽 전달

이 책에서 가장 어렵고, 가장 가치 있는 부분이다. Meyers는 T&&가 항상 rvalue 참조인 것은 아니라고 지적한다. 템플릿 매개변수나 auto&& 자리에서는 forwarding reference(흔히 universal reference라 부르는 것)로 동작하며, 이때만 std::forward를 써야 한다.

// T&&가 rvalue reference인 경우 → std::move
void SetName(std::string&& name)
{
    m_name = std::move(name);
}

// T&&가 forwarding reference인 경우 → std::forward
template <typename T>
void Relay(T&& arg)
{
    Target(std::forward<T>(arg));   // lvalue/rvalue 성질 보존
}
std::move와 std::forward는 "아무것도 이동/전달하지 않는다" 둘 다 단지 캐스팅일 뿐이다. std::move는 무조건 rvalue로 캐스팅하고, std::forward는 조건부로 캐스팅한다. 이 사실을 모르면 완벽 전달이 왜 실패하는지 영원히 이해할 수 없다 — 책이 이 점을 집요하게 짚는다.

람다 캡처

람다 챕터는 캡처 방식의 위험을 다룬다. 기본 캡처 모드([&], [=])는 댕글링 참조나 의도치 않은 this 캡처를 부르기 쉬우므로, 캡처할 대상을 명시적으로 적으라고 권한다. C++14에서 추가된 init capture(generalized lambda capture)로 이동 전용 객체도 캡처할 수 있게 된 점도 소개한다.

std::async

동시성 챕터에서는 std::thread를 직접 다루기보다 std::async를 우선 고려하라고 한다. 스레드 고갈, 예외 전파, 결과 회수 같은 문제를 표준이 알아서 처리해 주기 때문이다. 다만 실행 정책(launch::async vs launch::deferred)을 명시하지 않으면 동작이 구현에 맡겨진다는 함정도 함께 경고한다.

인상 깊은 점

가장 인상 깊었던 점은 이 책이 단순한 "이렇게 써라" 모음이 아니라는 것이다. 보통의 베스트 프랙티스 책은 규칙을 던지고 끝나지만, Meyers는 표준이 그렇게 동작하는 이유를 끝까지 파고든다. 타입 추론 규칙, 참조 축약(reference collapsing), 제어 블록 구조 같은 "원리"를 먼저 깔고, 그 위에서 조언을 도출한다.

각 Item은 결론이 아니라 "왜 그 결론에 도달했는가"를 보여주는 데 지면을 쓴다. 그래서 한 번 이해하면 비슷한 새 상황에서도 스스로 판단할 수 있게 된다.
— 책을 읽으며 정리한 소감

또 하나 인상적인 것은 함정과 예외 케이스를 숨기지 않는다는 점이다. auto의 프록시 타입 문제, make_shared의 weak count 메모리 점유, 완벽 전달이 실패하는 경우들(중괄호 초기화, 0/NULL, 비트필드 등)을 솔직하게 다 늘어놓는다. "새 기능은 만능이 아니다"라는 균형 잡힌 시각이 신뢰를 준다.

핵심 교훈

1 새 기능은 동작 원리를 알고 써야 한다 — auto, forwarding reference, shared_ptr 모두 "편하니까" 쓰면 함정에 빠진다. 추론 규칙과 내부 구조를 이해한 뒤 써야 한다.
2 std::move / std::forward는 캐스팅일 뿐이다 — 무언가를 실제로 이동시키는 것은 이동 생성자/대입 연산자다. 이 구분이 이동 의미론 이해의 출발점이다.
3 기본은 unique_ptr — 소유권을 타입으로 표현하고, 공유가 진짜 필요할 때만 shared_ptr의 비용을 감수한다.
4 명시적인 것이 안전하다 — 람다 캡처는 명시적으로, std::async의 실행 정책도 명시적으로. 컴파일러의 "알아서"에 의존하지 않는다.
5 함정을 아는 것이 기능을 아는 것 — 어떤 기능을 "안다"는 것은 그 기능이 무너지는 경계 케이스까지 안다는 뜻이다.

누구에게 / 어떻게 읽나

이 책은 C++ 입문서가 아니다. 클래스, 템플릿, 표준 라이브러리의 기본은 이미 안다는 전제로 쓰여 있다. 문법을 처음 배우는 사람에게는 너무 어렵다.

가장 잘 맞는 독자는 C++11 이전 스타일로 C++을 익힌 뒤 모던 C++로 넘어오려는 사람이다. raw 포인터, 수동 메모리 관리, C++98식 코드에 익숙한 사람이 "왜 이제는 이렇게 안 쓰는가"를 가장 깊이 체감할 수 있다.

처음부터 끝까지 읽기보다 항목별 참고서로 42개 Item이 비교적 독립적이라, 통독한 뒤에는 책상 옆에 두고 필요할 때 해당 Item만 다시 펴보는 방식이 잘 맞는다. 코드 리뷰에서 "이거 Item 몇 번 위반"이라고 짚을 수 있을 정도가 되면 충분히 소화한 것이다.

시대 맥락

이 책은 C++14 기준으로 쓰였다. 2014년 출간 이후 C++17, C++20, C++23이 차례로 나왔으므로, 일부 내용은 보강이 필요하다.

책의 내용이후 표준의 변화
std::make_unique가 C++14 추가C++14 이후 표준이므로 현재는 당연히 사용 가능
구조적 바인딩 없이 std::tie 사용C++17의 structured bindings로 더 간결해짐
람다에서 auto 매개변수(C++14)C++20에서 템플릿 람다로 더 정교한 제어 가능
std::thread 직접 관리의 어려움C++20 std::jthread로 일부 해소

그럼에도 핵심 원리는 여전히 유효하다. 타입 추론 규칙, 이동 의미론, 완벽 전달, 스마트 포인터 선택 기준은 표준이 바뀌어도 그대로다. C++17/20을 별도로 공부하더라도, 그 토대가 되는 사고방식은 이 책에서 얻는 것이 가장 빠르다.

이 블로그와의 연결

이 블로그의 C++ 시리즈를 쓰면서 Effective Modern C++를 여러 번 참조했다. 시리즈의 상당수 글이 이 책의 Item과 직접 맞닿아 있다.

블로그 글관련 Item 주제
스마트 포인터 깊이 보기Item 18~22 — unique_ptr / shared_ptr / weak_ptr, make 함수, pImpl
이동 의미론 정리Item 23~30 — std::move / std::forward, forwarding reference, 완벽 전달
constexpr 다지기Item 15 — 가능하면 constexpr을 쓰라
람다와 함수 객체Item 31~34 — 캡처 방식, init capture, 람다 선호

즉, C++ 시리즈를 쭉 읽었다면 사실상 이 책의 후반부를 한 번 훑은 셈이다. 반대로 이 책을 먼저 읽으면 시리즈 글들이 "어디서 온 조언인지" 더 또렷하게 보인다.

한 줄 평

모던 C++을 "쓸 줄 안다"에서 "왜 그렇게 쓰는지 안다"로 끌어올려 주는 책이다. 0.5점을 깎은 이유는 순전히 시간 탓이다 — C++14 기준이라 C++17 이후를 별도로 보충해야 하고, 입문자에게는 진입 장벽이 높다. 하지만 그 핵심 원리는 10년이 지나도 낡지 않았다.

모던 C++ 기능을 "외워서 쓰는" 단계에서 "이해하고 쓰는" 단계로 넘어가게 해주는 필독서
