머신비전 측정이란?

머신비전 측정은 이미지에서 객체의 치수·거리·각도·지름 같은 물리량을 정량적으로 뽑아내는 작업이다. "이 부품이 있다/없다"를 판정하는 검출과 달리, 측정은 "이 핀의 길이가 12.04 mm다"처럼 수치를 돌려준다. 산업 검사의 핵심이며, 공차 판정·조립 정렬·품질 통계의 바탕이 된다.

측정의 흐름은 대체로 같다. 엣지(10편)를 뽑고, 윤곽(13편)으로 객체 형태를 잡고, 그 위에 기하 연산을 얹어 길이·각도를 계산한 뒤, 픽셀 단위 결과를 실측 단위(mm)로 환산한다.

측정 항목입력대표 함수
거리 / 길이두 점 또는 두 엣지cv::norm, boundingRect
폭 / 길이 / 각도기울어진 윤곽minAreaRect
직선 방향엣지 점 집합fitLine
지름 / 중심원·타원 윤곽fitEllipse, minEnclosingCircle
각도두 직선 또는 두 벡터atan2, 벡터 내적
코너 위치 (정밀)코너 근방 픽셀cornerSubPix
측정은 "픽셀 좌표 → 기하량 → 실측 단위"의 3단 변환이다 OpenCV가 돌려주는 모든 좌표는 픽셀이다. 픽셀 좌표로 길이·각도를 계산한 뒤, 마지막에 캘리브레이션 계수를 곱해 mm로 바꾼다. 이 마지막 단계를 빼먹으면 측정이 아니라 그냥 픽셀 세기다.

측정의 전제 — 캘리브레이션과 안정적 엣지

측정 코드를 짜기 전에 두 가지가 먼저 갖춰져야 한다. 이게 없으면 아무리 정교한 기하 계산을 해도 의미가 없다.

캘리브레이션 — 픽셀과 실측의 다리

카메라 캘리브레이션(18편)은 렌즈 왜곡을 보정하고 픽셀 1개가 실제 몇 mm인지를 알려준다. 왜곡이 보정되지 않으면 이미지 가장자리의 직선이 휘어 보이고, 같은 부품이 화면 중앙에 있을 때와 모서리에 있을 때 측정값이 달라진다.

// 캘리브레이션으로 얻은 카메라 행렬과 왜곡 계수
cv::Mat cameraMatrix, distCoeffs;
// ... calibrateCamera 결과를 파일에서 읽어온다 ...

// 측정 전 왜곡 보정 — 직선이 직선으로 펴진다
cv::Mat undistorted;
cv::undistort(rawImage, undistorted, cameraMatrix, distCoeffs);

// 이후 모든 측정은 undistorted 위에서 수행한다

안정적인 엣지와 윤곽

측정의 정밀도는 결국 엣지를 얼마나 일관되게 잡느냐에 달려 있다. 조명이 흔들리거나 초점이 나가면 엣지 위치가 픽셀 단위로 출렁이고, 그 출렁임이 그대로 측정 오차가 된다. 측정용 이진화는 검출용보다 더 보수적으로, 임계값에 둔감하게 잡아야 한다.

캘리브레이션 없는 측정은 측정이 아니다 "픽셀 = mm"라고 가정하거나, 화면 한가운데서 한 번 잰 mm/pixel 값을 전체 화면에 그대로 쓰면 안 된다. 렌즈 왜곡과 원근 때문에 위치마다 픽셀 크기가 다르다. 정밀 측정이 목적이라면 캘리브레이션은 선택이 아니라 전제다.

거리·치수 측정

가장 기본은 두 점 사이의 직선 거리다. cv::norm에 두 점의 차이를 넣으면 유클리드 거리가 나온다.

cv::Point2f p1(120.0f, 80.0f);
cv::Point2f p2(360.0f, 250.0f);

// 두 점 사이 거리 (픽셀)
double distPx = cv::norm(p1 - p2);

std::cout << "거리: " << distPx << " px" << std::endl;
실행 결과 (콘솔)
거리: 293.939 px

윤곽의 폭과 높이는 boundingRect로 잡는다. 윤곽을 감싸는 축에 정렬된 최소 사각형을 돌려준다. 객체가 화면 축과 나란할 때 가장 단순하고 빠르다.

std::vector<std::vector<cv::Point>> contours;
cv::findContours(binary, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

for (const auto& contour : contours)
{
    // 축 정렬 바운딩 박스
    cv::Rect box = cv::boundingRect(contour);

    int widthPx = box.width;
    int heightPx = box.height;

    std::cout << "폭 " << widthPx << " px, 높이 " << heightPx << " px" << std::endl;
}

두 엣지 사이의 간격을 잴 때는, 한쪽 엣지의 점들에서 다른 쪽 엣지(또는 직선)까지의 수직 거리를 구해 평균을 낸다. 점 하나만 쓰면 노이즈에 휘둘리므로 여러 점을 평균하는 것이 핵심이다.

// 한 점에서 직선(점 a를 지나고 방향이 dir인 직선)까지의 수직 거리
double pointToLineDistance(const cv::Point2f& pt,
                           const cv::Point2f& a, const cv::Point2f& dir)
{
    cv::Point2f ap = pt - a;
    // 외적의 크기 / 방향 벡터 크기 = 수직 거리
    double cross = ap.x * dir.y - ap.y * dir.x;
    return std::abs(cross) / cv::norm(dir);
}

회전 사각형 측정 (minAreaRect)

부품이 화면 축과 나란하다는 보장은 없다. 컨베이어 위에서 비스듬히 흘러가는 객체의 실제 폭과 길이를 재려면 minAreaRect를 쓴다. 윤곽을 감싸는 회전된 최소 면적 사각형을 돌려준다.

boundingRect는 축에 정렬되어 비스듬한 객체를 과대 측정한다. minAreaRect는 객체를 따라 회전해 center·size·angle을 돌려준다.
// 회전된 최소 면적 사각형
cv::RotatedRect rr = cv::minAreaRect(contour);

cv::Point2f center = rr.center;   // 중심 (픽셀)
float w = rr.size.width;          // 한 변
float h = rr.size.height;         // 다른 변
float angle = rr.angle;           // 기울기 (도)

// 객체의 길이와 폭 — 긴 쪽이 길이, 짧은 쪽이 폭
float length = std::max(w, h);
float breadth = std::min(w, h);

std::cout << "길이 " << length << " px, 폭 " << breadth
          << " px, 각도 " << angle << " deg" << std::endl;

// 네 꼭짓점이 필요하면 points()로 꺼낸다
cv::Point2f corners[4];
rr.points(corners);
minAreaRect의 angle 해석은 OpenCV 버전에 따라 다르다 OpenCV 4.5 이전에는 angle이 [-90, 0) 범위였고, 4.5부터는 (0, 90] 범위로 바뀌었다. width/height와 angle의 짝짓기 규칙도 함께 달라졌다. 그래서 "긴 변 = 길이"처럼 angle에 직접 의존하지 않는 방식으로 폭·길이를 정하고, 방향이 필요하면 points()로 꼭짓점을 꺼내 직접 벡터를 계산하는 편이 버전에 안전하다.

선·원 피팅 (fitLine·fitEllipse)

엣지에서 뽑은 점들은 노이즈 때문에 완벽한 직선이나 원이 아니다. 피팅은 이 점 무리에 가장 잘 맞는 이상적인 도형을 최소제곱으로 끼워 맞춰, 노이즈를 평균해 없애는 기법이다.

fitLine — 점들로 직선 적합

fitLine은 점 집합에 직선을 맞춰 (vx, vy, x0, y0)을 돌려준다. (vx, vy)는 정규화된 방향 벡터, (x0, y0)은 직선 위의 한 점이다.

// 엣지에서 뽑은 점들 (한 변을 따라 늘어선 점들)
std::vector<cv::Point2f> edgePoints = collectEdgePoints(binary);

cv::Vec4f line;
// DIST_L2: 최소제곱. 0, 0.01은 기본 파라미터
cv::fitLine(edgePoints, line, cv::DIST_L2, 0, 0.01, 0.01);

cv::Point2f dir(line[0], line[1]);   // 방향 벡터 (단위 벡터)
cv::Point2f pt(line[2], line[3]);    // 직선 위의 한 점

// 직선의 기울기 각도 (도)
double lineAngle = std::atan2(dir.y, dir.x) * 180.0 / CV_PI;
DIST_L2 대신 DIST_HUBER를 쓰면 이상치에 강해진다 엣지 점에 튀는 값이 섞이면 DIST_L2 적합선이 그쪽으로 끌려간다. cv::DIST_HUBER나 cv::DIST_L1은 멀리 떨어진 점의 영향을 줄여 더 견고한 직선을 준다. 측정용 직선 피팅에는 Huber가 무난하다.

fitEllipse — 타원 적합으로 지름·중심

구멍이나 원형 부품의 지름과 중심을 잴 때는 fitEllipse를 쓴다. 윤곽 점에 타원을 맞춰 RotatedRect를 돌려준다 — center는 타원 중심, size는 두 축의 길이다.

// 타원 적합에는 최소 5개 점이 필요하다
if (contour.size() >= 5)
{
    cv::RotatedRect ell = cv::fitEllipse(contour);

    cv::Point2f center = ell.center;          // 타원(구멍) 중심
    float majorAxis = std::max(ell.size.width, ell.size.height);
    float minorAxis = std::min(ell.size.width, ell.size.height);

    // 원형 부품이면 두 축이 거의 같다 → 평균을 지름으로
    float diameter = (majorAxis + minorAxis) / 2.0f;

    std::cout << "구멍 중심 (" << center.x << ", " << center.y
              << "), 지름 " << diameter << " px" << std::endl;
}

minEnclosingCircle — 감싸는 최소 원

minEnclosingCircle은 모든 점을 포함하는 가장 작은 원을 돌려준다. fitEllipse가 점들의 평균적 형태에 맞춘다면, 이쪽은 최대 외접 개념이라 의미가 다르다. 부품이 원 안에 다 들어오는지 같은 포함 검사에 어울린다.

cv::Point2f center;
float radius;
cv::minEnclosingCircle(contour, center, radius);

std::cout << "외접원 반지름 " << radius << " px" << std::endl;
함수맞추는 도형측정 의미
fitLine직선 (최소제곱)변의 방향, 기울기 각도
fitEllipse타원 (점들의 평균 형태)구멍 지름·중심, 진원도
minEnclosingCircle최소 외접 원포함 검사, 최대 크기
boundingRect축 정렬 사각형축에 나란한 객체의 폭·높이
minAreaRect회전 최소 사각형기울어진 객체의 폭·길이·각도

각도 측정

각도는 두 직선이 이루는 사이각, 또는 한 직선이 기준축과 이루는 기울기로 잰다. 핵심은 atan2와 벡터 내적이다.

두 직선의 사이각

각 직선의 방향 벡터를 구한 뒤, 두 벡터의 내적으로 사이각을 계산한다. 내적은 |a||b|cosθ이므로 정규화하면 cosθ가 바로 나온다.

// 두 방향 벡터 사이의 각도 (도, 0~180)
double angleBetween(const cv::Point2f& v1, const cv::Point2f& v2)
{
    double dot = v1.x * v2.x + v1.y * v2.y;
    double n1 = cv::norm(v1);
    double n2 = cv::norm(v2);

    // 0으로 나누기 방지
    if (n1 < 1e-9 || n2 < 1e-9)
    {
        return 0.0;
    }

    double cosTheta = dot / (n1 * n2);
    // 부동소수 오차로 범위를 벗어날 수 있으니 클램프
    cosTheta = std::max(-1.0, std::min(1.0, cosTheta));

    return std::acos(cosTheta) * 180.0 / CV_PI;
}

기준축 대비 기울기

한 직선이 수평축과 이루는 각도는 atan2(dy, dx)로 구한다. atan2는 사분면을 구분해 -180~180도를 돌려주므로, 단순 atan보다 안전하다.

cv::Point2f a(100.0f, 200.0f);
cv::Point2f b(340.0f, 120.0f);

cv::Point2f v = b - a;
double angleDeg = std::atan2(v.y, v.x) * 180.0 / CV_PI;

// minAreaRect의 angle을 그대로 쓰는 대신, 꼭짓점에서 직접 계산하면
// 버전에 무관하게 일관된 각도를 얻는다
cv::Point2f corners[4];
rr.points(corners);
cv::Point2f edge = corners[1] - corners[0];   // 한 변 벡터
double rectAngle = std::atan2(edge.y, edge.x) * 180.0 / CV_PI;
각도는 캘리브레이션 계수와 무관하다 길이는 mm/pixel을 곱해야 하지만, 각도는 비율이라 픽셀 좌표에서 잰 값이 그대로 실제 각도다 — 단, 화소가 정사각형(픽셀 가로세로비 1)이고 렌즈 왜곡이 보정된 경우에 한한다. 비정방 화소나 큰 왜곡이 있으면 각도도 틀어진다.

서브픽셀 정밀도

윤곽과 엣지가 돌려주는 좌표는 기본적으로 정수 픽셀 단위다. 하지만 객체의 진짜 경계는 픽셀 격자에 딱 맞아떨어지지 않는다. 픽셀 단위 측정은 ±0.5 px의 양자화 오차를 안고 가는데, 정밀 측정에서는 이게 치명적이다. 서브픽셀 기법은 픽셀 사이의 위치를 보간으로 추정해 정밀도를 10배 이상 끌어올린다.

cornerSubPix — 코너 정밀화

cornerSubPix는 정수 좌표로 잡은 코너를 입력받아, 주변 밝기 기울기를 분석해 실수 좌표로 정밀화한다. 코너 근방에서 "기울기와 변위 벡터가 수직"이라는 조건을 반복적으로 만족시켜 위치를 미세 조정한다.

// 1단계: 정수 픽셀 단위로 코너 후보를 잡는다
std::vector<cv::Point2f> corners;
cv::goodFeaturesToTrack(gray, corners, 20, 0.01, 10);

// 2단계: 서브픽셀로 정밀화
cv::Size winSize(5, 5);          // 탐색 윈도우 절반 크기
cv::Size zeroZone(-1, -1);       // 무시 영역 없음
cv::TermCriteria criteria(
    cv::TermCriteria::EPS + cv::TermCriteria::MAX_ITER, 40, 0.001);

cv::cornerSubPix(gray, corners, winSize, zeroZone, criteria);

// corners는 이제 (123.47, 88.21)처럼 소수점 좌표를 가진다

엣지 프로파일 보간

한 방향으로 밝기 단면(프로파일)을 뜨면, 엣지에서 밝기가 급변한다. 이 변화의 1차 미분이 최대가 되는 위치가 엣지인데, 미분 곡선의 정점 주변 세 점에 포물선을 끼워 맞추면 정점의 실수 위치를 얻는다. 이게 엣지 서브픽셀화의 기본 원리다.

// 1D 프로파일에서 기울기 최대 지점을 서브픽셀로 찾는다.
// peakIndex 주변 세 점에 포물선을 맞춰 정점 위치를 보간한다.
double subPixelPeak(const std::vector<double>& grad, int peakIndex)
{
    if (peakIndex <= 0 || peakIndex >= (int)grad.size() - 1)
    {
        return peakIndex;
    }

    double yPrev = grad[peakIndex - 1];
    double yCurr = grad[peakIndex];
    double yNext = grad[peakIndex + 1];

    double denom = yPrev - 2.0 * yCurr + yNext;
    if (std::abs(denom) < 1e-9)
    {
        return peakIndex;
    }

    // 포물선 정점의 보정량 (-0.5 ~ 0.5)
    double offset = 0.5 * (yPrev - yNext) / denom;
    return peakIndex + offset;
}
구분픽셀 단위서브픽셀
좌표 형식정수 (cv::Point)실수 (cv::Point2f)
전형적 정밀도±0.5 px±0.05 px 이하
대표 기법findContours, 정수 코너cornerSubPix, 프로파일 보간
비용거의 없음약간의 추가 연산
적합한 용도존재 검사, 대략적 위치공차 판정, 정밀 치수
서브픽셀 없이 정밀 측정을 기대하면 안 된다 ±0.5 px의 양자화 오차는 1 px = 10 µm 배율에서 ±5 µm다. 정밀 부품의 공차가 ±3 µm라면 픽셀 단위 측정만으로는 애초에 판정이 불가능하다. 정밀 측정이 목적이면 서브픽셀은 필수이고, 그 전에 엣지 품질부터 확보해야 한다.

픽셀→실측 변환

측정의 마지막 단계는 픽셀 값을 실제 단위로 바꾸는 것이다. 핵심은 mm/pixel 계수 하나다. 이 계수를 구하는 방법은 두 가지다.

캘리브레이션 기반

체커보드 캘리브레이션(18편)을 하면 카메라 행렬과, 작업 평면까지의 거리를 알 때 픽셀 크기를 정확히 산출할 수 있다. 렌즈 왜곡까지 보정되므로 화면 전체에서 일관된 계수를 쓸 수 있다.

기준 물체(스케일 바) 기반

간단한 현장에서는 크기를 정확히 아는 기준 물체를 함께 촬영해 계수를 뽑는다. 예를 들어 10.00 mm 게이지 블록이 이미지에서 412 px로 잡혔다면 계수는 10.00 / 412 mm/px다.

// 기준 물체로 mm/pixel 계수를 산출한다
double knownLengthMm = 10.00;     // 게이지 블록 실제 길이
double measuredPx = 412.0;        // 이미지에서 잰 픽셀 길이

double mmPerPixel = knownLengthMm / measuredPx;   // 약 0.02427 mm/px

// 이제 모든 픽셀 측정값을 실측으로 환산한다
double partWidthPx = 305.7;       // minAreaRect로 잰 부품 폭
double partWidthMm = partWidthPx * mmPerPixel;

std::cout << "부품 폭: " << partWidthMm << " mm" << std::endl;
실행 결과 (콘솔)
부품 폭: 7.41917 mm
기준 물체는 측정 대상과 같은 평면에 있어야 한다 스케일 바가 측정 대상보다 카메라에 가깝거나 멀면 원근 때문에 픽셀 크기가 달라져 계수가 틀어진다. 기준 물체는 반드시 측정 대상과 같은 작업 거리(같은 평면)에 놓고 촬영해야 한다. 깊이가 다른 면을 한 계수로 재면 그만큼 오차가 난다.

측정 신뢰성

한 번 잘 잰 값보다 매번 같은 값이 나오는 것이 산업 측정에서는 더 중요하다. 측정 시스템 자체의 변동을 관리해야 한다.

반복성 — 조명·초점·정렬

  • 조명 반복성: 조명이 흔들리면 엣지 위치가 출렁인다. 측정 셀은 외광을 차단하고 동일 광원을 쓴다.
  • 초점 안정성: 초점이 나가면 엣지가 번져 측정값이 커진다. 고정 초점 + 일정 작업 거리를 유지한다.
  • 측정 ROI 정렬: 대상이 매번 조금씩 다른 위치에 오면, 먼저 객체를 찾아 ROI를 객체에 맞춰 정렬한 뒤 측정한다.

여러 번 측정해 평균

같은 대상을 여러 번 측정해 평균을 내면 랜덤 노이즈가 줄어든다. 표준편차를 함께 기록하면 측정 시스템이 얼마나 안정적인지 정량적으로 알 수 있다.

// 같은 대상을 N회 측정해 평균과 표준편차를 구한다
std::vector<double> samples;
for (int i = 0; i < 10; ++i)
{
    cv::Mat frame = grabFrame();
    double value = measurePartWidth(frame);   // mm 단위 측정 결과
    samples.push_back(value);
}

cv::Scalar meanVal, stddevVal;
cv::meanStdDev(samples, meanVal, stddevVal);

std::cout << "평균 " << meanVal[0] << " mm, "
          << "표준편차 " << stddevVal[0] << " mm" << std::endl;
Gage R&R로 이어진다 측정 시스템의 반복성(Repeatability)과 재현성(Reproducibility)을 정량 평가하는 것이 Gage R&R이다. 비전 측정도 예외가 아니어서, 같은 부품을 여러 번·여러 조건에서 재고 그 변동이 공차 대비 얼마인지 따진다. 스마트 공장 시리즈의 Gage R&R 글에서 이 절차를 자세히 다룬다.

실전 — 부품 검사

지금까지의 조각을 모아 실제 검사 시나리오를 구성한다.

부품 치수 검사 (공차 판정)

부품 폭을 재서 설계 공차 안에 있는지 OK/NG를 판정한다.

struct InspectResult
{
    double widthMm;
    bool isPass;
};

InspectResult inspectWidth(const std::vector<cv::Point>& contour,
                           double mmPerPixel)
{
    cv::RotatedRect rr = cv::minAreaRect(contour);
    double widthPx = std::min(rr.size.width, rr.size.height);
    double widthMm = widthPx * mmPerPixel;

    // 설계값 7.40 mm, 공차 ±0.05 mm
    const double kNominal = 7.40;
    const double kTolerance = 0.05;

    InspectResult result;
    result.widthMm = widthMm;
    result.isPass = std::abs(widthMm - kNominal) <= kTolerance;
    return result;
}

구멍 지름·위치 측정

내부 구멍을 찾아 지름과 중심 좌표를 재고, 설계 위치와의 편차를 계산한다.

// RETR_CCOMP로 외곽과 내부 구멍을 함께 찾는다
std::vector<std::vector<cv::Point>> contours;
std::vector<cv::Vec4i> hierarchy;
cv::findContours(binary, contours, hierarchy,
                 cv::RETR_CCOMP, cv::CHAIN_APPROX_SIMPLE);

for (size_t i = 0; i < contours.size(); ++i)
{
    // hierarchy[i][3] != -1 이면 자식 윤곽 = 내부 구멍
    if (hierarchy[i][3] != -1 && contours[i].size() >= 5)
    {
        cv::RotatedRect ell = cv::fitEllipse(contours[i]);
        double diameterMm =
            (ell.size.width + ell.size.height) / 2.0 * mmPerPixel;

        std::cout << "구멍 지름 " << diameterMm << " mm, "
                  << "중심 (" << ell.center.x << ", "
                  << ell.center.y << ") px" << std::endl;
    }
}

각도 검사

두 변의 직선을 각각 피팅한 뒤 사이각을 재서, 90도 ± 공차를 벗어나는지 본다.

// 두 변에서 각각 엣지 점을 모아 직선을 피팅한다
cv::Vec4f lineA, lineB;
cv::fitLine(edgePointsA, lineA, cv::DIST_HUBER, 0, 0.01, 0.01);
cv::fitLine(edgePointsB, lineB, cv::DIST_HUBER, 0, 0.01, 0.01);

cv::Point2f dirA(lineA[0], lineA[1]);
cv::Point2f dirB(lineB[0], lineB[1]);

double cornerAngle = angleBetween(dirA, dirB);

const double kRightAngle = 90.0;
const double kAngleTol = 0.5;        // ±0.5도
bool angleOk = std::abs(cornerAngle - kRightAngle) <= kAngleTol;

std::cout << "코너 각도 " << cornerAngle << " deg — "
          << (angleOk ? "OK" : "NG") << std::endl;

흔한 함정

측정 코드는 컴파일도 잘 되고 숫자도 그럴듯하게 나오기 때문에, 함정을 밟아도 한참 모르고 지나가기 쉽다.

캘리브레이션 없이 픽셀 = 실측 가정

"대충 1 px ≈ 0.02 mm"는 측정이 아니라 추측이다 캘리브레이션이나 기준 물체 없이 임의의 계수를 쓰면, 화면 위치에 따라 수 % 오차가 생기고 렌즈 왜곡까지 더해진다. 검사 시스템이라면 반드시 캘리브레이션 또는 같은 평면의 스케일 바로 계수를 산출하고, 주기적으로 재검증한다.

서브픽셀 없이 정밀 측정 기대

정수 좌표의 한계를 인정해야 한다 findContours의 정수 윤곽으로 잰 길이는 ±0.5 px 양자화 오차를 항상 안고 있다. 공차가 픽셀 분해능에 근접하면 픽셀 단위로는 판정 자체가 불가능하다. 정밀 측정에는 cornerSubPix나 프로파일 보간을 반드시 끼운다.

minAreaRect angle 해석 오류

앞서 본 대로 minAreaRect의 angle 범위와 width/height 짝짓기 규칙은 OpenCV 4.5를 경계로 바뀌었다. 이전 버전 기준으로 짠 각도 코드를 새 버전에서 그대로 돌리면 각도가 90도 어긋나거나 폭과 길이가 뒤바뀐다. angle 값에 직접 의존하지 말고, points()로 꼭짓점을 꺼내 변 벡터에서 각도를 직접 계산한다.

엣지 품질이 측정 정밀도를 결정한다

아무리 정교한 피팅도 나쁜 엣지를 구원하지 못한다 fitEllipse, fitLine, 서브픽셀 모두 입력 엣지가 일관될 때만 의미가 있다. 조명이 불안정하거나 초점이 흐리면 엣지가 프레임마다 출렁이고, 그 변동이 그대로 측정 표준편차가 된다. 측정 정밀도를 높이려면 알고리즘보다 조명·광학을 먼저 손봐야 한다.

측정 ROI가 대상에 맞지 않으면 무의미

측정 ROI가 대상에서 벗어나 있으면, 엉뚱한 엣지나 배경 노이즈를 측정값으로 잡는다. 대상이 매번 같은 위치에 온다는 보장이 없으므로, 먼저 객체를 찾아(검출) 그 위치·각도에 맞춰 ROI를 정렬한 다음 측정해야 한다. 정렬되지 않은 ROI의 측정값은 숫자가 나와도 신뢰할 수 없다.

정리하면 측정 전에 캘리브레이션으로 mm/pixel을 확보하고, 엣지가 일관되게 잡히도록 조명·광학을 안정시킨다. 기울어진 객체는 minAreaRect로, 직선·원은 피팅으로, 정밀 좌표는 서브픽셀로 잡는다. minAreaRect의 각도는 꼭짓점에서 직접 계산하고, 측정 ROI는 객체에 정렬하며, 여러 번 측정해 평균과 표준편차로 신뢰성을 관리한다.
