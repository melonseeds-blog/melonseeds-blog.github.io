링크 요약에 왜 RPA 얘기가 나오나

AI에게 웹페이지를 요약시키는 가장 단순한 방법은 링크를 그냥 붙여 넣는 것이다. 그런데 이게 잘 안 될 때가 있다. 로그인이 필요한 페이지, 버튼을 눌러야 내용이 나오는 페이지, JavaScript로 나중에 그려지는 페이지 — 이런 곳은 링크만 줘서는 AI가 실제 내용을 못 본다.

그래서 나오는 이야기가 "사람이 브라우저에서 하는 동작을 대신 시켜서 내용을 긁어온 뒤 AI에 넣어라"다. 이 "사람 동작을 대신하는 자동화"가 바로 RPA다.

RPA란 무엇인가

RPA(Robotic Process Automation)는 사람이 브라우저나 프로그램에서 하는 반복 작업을 자동으로 수행하는 기술이다. 실제 화면을 조작하듯 동작하기 때문에, 사람이 하던 일을 거의 그대로 대신할 수 있다.

예를 들어 다음 같은 일을 자동으로 한다.

  • 웹사이트 접속과 로그인
  • 버튼 클릭·검색어 입력
  • JavaScript가 실행돼 화면이 다 그려질 때까지 대기
  • 화면에 표시된 내용 추출
  • 엑셀로 저장
  • ChatGPT·Claude 같은 AI에 자동으로 전달

일반 크롤러 vs RPA

둘 다 "웹에서 내용을 가져온다"는 점은 같지만, 동작 방식이 다르다. 일반 크롤러는 서버가 보내주는 HTML을 그대로 받는다. 그래서 접속 직후 화면에 아직 안 그려진 내용(JavaScript가 나중에 채우는 부분)은 못 가져온다. RPA는 실제 브라우저를 조작하기 때문에, 사람이 보는 최종 화면 그대로를 가져올 수 있다.

구분일반 크롤러RPA(브라우저 자동화)
동작서버 HTML을 직접 요청실제 브라우저를 조작
JavaScript 페이지못 가져오는 경우 많음화면이 다 그려진 뒤 가져옴
로그인·클릭어렵거나 복잡사람처럼 수행
속도·비용가볍고 빠름무겁고 느림
적합한 곳공개된 정적 페이지로그인·동적·클릭이 필요한 곳

대표 RPA 도구

  • UiPath — 가장 유명한 상용 RPA. 기업 업무 자동화에 널리 쓰인다.
  • Microsoft Power Automate Desktop — 무료로 시작할 수 있어 진입 장벽이 낮다(Windows에 포함).
  • Automation Anywhere — 대표적인 엔터프라이즈 RPA 플랫폼.
  • Selenium — 개발자가 오래 써 온 브라우저 자동화 도구.
  • Playwright — 최근 AI 에이전트·개발자들이 많이 쓰는 브라우저 자동화. JavaScript 사이트 처리가 강하다.
넓은 의미의 RPA UiPath·Power Automate처럼 "업무 자동화 제품"만 RPA로 부르기도 하고, Selenium·Playwright 같은 브라우저 자동화 라이브러리까지 넓게 포함하기도 한다. 이 글에서는 "사람의 브라우저 동작을 대신하는 자동화"를 통틀어 다룬다.

AI 전처리 자동화 흐름

"웹 내용을 긁어 AI에 넣는다"는 건 결국 아래 흐름을 자동으로 도는 것이다. 강의에서 말하는 RPA 활용도 이 그림이다.

  • 1RPA 실행 — 정해진 시각이나 트리거로 시작
  • 2웹사이트 접속
  • 3로그인(필요한 경우)
  • 4검색·필터로 원하는 페이지로 이동
  • 5JavaScript까지 모두 로딩될 때까지 대기
  • 6필요한 내용만 추출
  • 7ChatGPT·Claude·Codex 등 AI에 자동 전달
  • 8요약 또는 분석 결과 받기

회사 업무에 붙이면

매일 반복하는 업무라면 이 흐름 전체를 자동화할 수 있다. 예를 들어:

  • 사내 시스템 로그인 → Jira 이슈 수집 → Confluence 문서 읽기
  • 뉴스 기사 수집, ERP 데이터 조회
  • 엑셀 생성 후 AI에게 "오늘 변경사항 요약해줘" 요청

사람이 아침마다 하던 "여기저기 들어가 확인하고 정리하기"를 자동으로 돌려 두고, 요약본만 받아 보는 식이다.

요즘 많이 쓰는 조합

실무에서 자주 보이는 조합은 다음과 같다.

조합특징
Power Automate + ChatGPT비개발 업무 자동화에 무난
UiPath + ChatGPT기업 표준 RPA + AI
Playwright + Claude/ChatGPT개발자가 가장 많이 쓰는 축. JS 사이트에 강함
n8n + AI최근 매우 인기. 노드 연결형 워크플로 자동화
Make.com + AI노코드 자동화 + AI 연계
단순 요약이라면 RPA는 과할 수 있다 그냥 공개된 웹페이지 내용을 AI에 넣는 정도라면, 무거운 RPA보다 Playwright + Firecrawl + MCP 같은 가벼운 조합이 더 적합하다. RPA의 진짜 강점은 로그인·클릭 같은 사람의 동작을 대신해야 할 때 나온다. 목적에 맞게 고르는 게 핵심이다.

정리 — 언제 무엇을

  • RPA는 "사람 동작 대행" — 로그인·클릭·대기·추출을 브라우저에서 그대로 해내, 링크만으로는 못 읽는 페이지도 AI에 넘길 수 있다.
  • 단순 공개 페이지 요약 — Playwright + Firecrawl + MCP 같은 가벼운 조합으로 충분하다.
  • 로그인·반복 업무 자동화 — 여기서 RPA(또는 Playwright·n8n)가 빛난다. 사내 시스템·Jira·ERP까지 엮어 요약본만 받아 볼 수 있다.
  • 개발자라면 — Codex·Claude를 이미 쓰고 있다면 Playwright + n8n + MCP 조합을 익혀 두는 편이 업무 자동화에 훨씬 유용하다.
