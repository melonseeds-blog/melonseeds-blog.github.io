1. 소개 - MCP와 플러그인이란?

MCP - Claude Code의 확장 통로

Claude Code는 기본 내장 도구(Read, Edit, Bash 등)만으로도 강력하지만, 실제 업무에서는 브라우저, 이슈 트래커, 모니터링 대시보드, 사내 데이터베이스 같은 외부 시스템과 연결해야 할 때가 많다. 이 연결을 담당하는 것이 MCP(Model Context Protocol)다.

MCP는 Anthropic이 공개한 개방형 표준으로, AI 도구와 외부 서비스를 잇는 공통 규격이다. MCP 서버를 하나 연결하면 Claude Code는 그 서비스의 도구를 자기 도구처럼 직접 호출한다. 다른 도구의 데이터를 채팅에 복사해서 붙여넣고 있다면, 그것이 바로 MCP 서버를 연결할 신호다.

플러그인과 MCP 서버의 관계

Claude Code에서 "플러그인"과 "MCP 서버"는 자주 혼용되지만 층위가 다르다. 정리하면 다음과 같다.

구분 설명 추가 방법
MCP 서버 외부 도구/데이터를 노출하는 단일 연결. 도구(tool)와 리소스를 제공 claude mcp add ...
플러그인 슬래시 명령어, 스킬, 서브에이전트, MCP 서버 등을 묶은 패키지 /plugin install ...
마켓플레이스 여러 플러그인을 모아 배포하는 저장소(git 리포 등) /plugin marketplace add ...

이 글에서 소개하는 도구는 대부분 MCP 서버 형태이며, 마지막 항목인 mcp-server-dev는 Anthropic 공식 플러그인이다. 플러그인은 MCP 서버를 내부에 번들로 포함할 수 있어서, 플러그인을 설치하면 관련 MCP 서버가 자동으로 켜진다.

알아두기 MCP 서버 설정은 세 가지 범위(scope)로 저장된다. local(현재 프로젝트, 본인만), project(.mcp.json에 저장, 팀 공유), user(모든 프로젝트, 본인만). 팀과 공유할 도구는 --scope project, 개인 도구는 --scope user를 쓴다.

신뢰와 보안 먼저

MCP 서버를 추가하기 전에 그 서버를 신뢰할 수 있는지 반드시 확인해야 한다. 외부 콘텐츠를 가져오는 서버는 프롬프트 인젝션(prompt injection) 위험에 노출될 수 있기 때문이다. 공식/준공식 서버 위주로 쓰고, 출처가 불분명한 서버는 피한다.

2. 한눈에 보는 요약 표

이 글에서 소개하는 10개 도구를 표로 먼저 정리한다. 자세한 설명은 각 섹션에서 다룬다.

이름 용도 이럴 때 추천
Playwright MCP 브라우저 자동 조작 / 테스트 / 스크래핑 UI 변경 후 실제 화면을 직접 확인시키고 싶을 때
GitHub MCP 이슈 / PR / 리포 관리 이슈 내용을 그대로 구현하거나 PR을 리뷰할 때
Filesystem MCP 지정 디렉터리의 파일 읽기/쓰기 프로젝트 밖 특정 폴더만 안전하게 열어주고 싶을 때
Context7 MCP 라이브러리 최신 버전 문서 조회 최신 API로 정확한 코드를 작성하게 하고 싶을 때
Sequential Thinking MCP 복잡한 문제를 단계적으로 추론 설계나 디버깅 등 사고 과정을 구조화하고 싶을 때
Sentry MCP 프로덕션 에러 / 이슈 트래킹 실제 에러 로그를 보고 원인을 찾게 하고 싶을 때
Slack MCP 메시지 검색 / 전송 / 채널 연동 Slack에 올라온 정보를 작업에 바로 끌어오고 싶을 때
Vercel MCP 배포 / 프로젝트 / 로그 관리 배포 상태와 빌드 로그를 채팅에서 바로 확인하고 싶을 때
Supabase MCP DB 테이블 / 쿼리 / 마이그레이션 관리 스키마와 데이터를 보면서 코드를 작성하게 하고 싶을 때
mcp-server-dev 나만의 MCP 서버 스캐폴딩 (공식 플러그인) 사내 도구를 MCP 서버로 직접 만들고 싶을 때
TIP MCP 서버를 많이 붙여도 걱정할 필요 없다. Claude Code의 Tool Search 기능이 기본 활성화되어 있어서, 세션 시작 시에는 도구 이름만 로드하고 실제 필요할 때 정의를 가져온다. 컨텍스트 윈도우 낭비가 거의 없다.

3. Playwright MCP - 브라우저 자동화

무엇인가

Playwright MCP는 Microsoft가 만든 공식 MCP 서버로, Claude Code가 브라우저를 직접 조작하게 해준다. 페이지 이동, 클릭, 폼 입력, 스크린샷, 데이터 추출, 로그인 세션 유지까지 가능하다. 핵심은 이미지 인식 모델 없이 접근성 트리(accessibility snapshot) 기반으로 페이지 구조를 읽는다는 점이다. 그래서 빠르고 안정적이다.

어떨 때 유용한가

  • UI 변경 검증 - 코드를 수정한 뒤 "localhost를 열어서 버튼이 의도대로 보이는지 확인해"라고 하면 실제 화면을 직접 본다
  • E2E 테스트 작성/실행 - "로그인 플로우가 test@example.com으로 동작하는지 테스트해"처럼 시나리오를 자연어로 검증
  • 웹 스크래핑 - 로그인이 필요한 페이지에서 세션을 유지한 채 데이터를 추출

설치 방법

로컬 stdio 서버로 추가한다. 처음 실행 시 Playwright가 필요한 브라우저 바이너리(기본 Chromium)를 자동 설치한다.

# Add Playwright MCP as a local stdio server
claude mcp add playwright -- npx -y @playwright/mcp@latest

# Verify
claude mcp list

.mcp.json에 직접 작성하려면 다음과 같다.

{
  "mcpServers": {
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}

사용 예제

# 개발 서버를 띄운 상태에서:
"localhost:3000을 열어서 체크아웃 페이지를 모바일 화면으로 스크린샷 찍어줘"

"검색창에 'melon'을 입력하고 결과가 나오는지 확인해줘"

"로그인 후 대시보드 페이지의 접근성 트리를 보여줘"
활용 팁 "코드 수정 → 빌드 → Playwright로 화면 확인"을 한 번의 지시로 묶으면, Claude Code가 자기가 만든 UI를 스스로 눈으로 검증하는 루프가 완성된다. 프런트엔드 작업에서 특히 강력하다.

4. GitHub MCP - 이슈와 PR 관리

무엇인가

GitHub MCP는 GitHub가 제공하는 원격 HTTP MCP 서버다. 이슈, 풀 리퀘스트, 리포지터리를 Claude Code 안에서 직접 읽고 다룰 수 있다. GitHub 개인 액세스 토큰(PAT)을 헤더로 전달하여 인증한다.

어떨 때 유용한가

  • 이슈 기반 구현 - "이슈 #4521에 설명된 기능을 구현하고 PR을 만들어줘"
  • PR 리뷰 - "PR #456을 리뷰하고 개선점을 제안해줘"
  • 이슈 정리 - "방금 발견한 버그로 새 이슈를 만들어줘", "나한테 할당된 열린 PR을 모두 보여줘"

설치 방법

먼저 GitHub 토큰 설정에서 작업할 리포에 접근 가능한 fine-grained 토큰을 발급한다. 그다음 원격 HTTP 서버로 추가한다. 

# Add GitHub MCP with a personal access token
claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \
  --header "Authorization: Bearer YOUR_GITHUB_PAT"

사용 예제

"이번 주에 머지된 PR 목록과 각 변경 요약을 정리해줘"

"PR #312의 변경사항을 보고 테스트가 빠진 부분이 있는지 알려줘"

# MCP 리소스로 이슈를 직접 참조할 수도 있다
"@github:issue://123 을 분석하고 수정 방향을 제안해줘"
주의 PAT는 민감 정보다. --scope project로 추가하면 토큰이 .mcp.json에 들어가 버전 관리에 노출될 수 있다. 개인 토큰은 --scope user(기본 local)로 추가하거나, .mcp.json에 환경 변수 확장(${GITHUB_PAT})을 사용한다.

5. Filesystem MCP - 파일시스템 접근

무엇인가

Filesystem MCP는 Model Context Protocol 공식 예제 서버 중 하나로, 지정한 디렉터리에 대한 파일 읽기/쓰기/검색 도구를 제공한다. Claude Code는 이미 현재 프로젝트 파일에 접근하지만, 이 서버는 프로젝트 바깥의 특정 폴더를 명시적으로 허용해줄 때 유용하다.

어떨 때 유용한가

  • 공유 자산 폴더 접근 - 디자인 에셋, 데이터 파일이 들어 있는 별도 폴더를 읽기 허용
  • 여러 프로젝트 횡단 작업 - 참조용 다른 리포를 읽기 전용으로 열어두기
  • 접근 범위 제한 - 허용한 디렉터리 밖으로는 접근하지 못하게 경계를 명확히 설정

설치 방법

로컬 stdio 서버로 추가하며, 허용할 디렉터리 경로를 인자로 넘긴다.

# Allow Claude to access two specific directories
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem \
  /Users/me/shared-assets /Users/me/reference-repo

.mcp.json 형식은 다음과 같다.

{
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/me/shared-assets"
      ]
    }
  }
}

사용 예제

"shared-assets 폴더에서 svg 파일 목록을 보여줘"

"reference-repo의 config 패턴을 참고해서 우리 프로젝트 설정을 맞춰줘"
알아두기 인자로 넘긴 디렉터리만 접근 가능하다. 허용 경로를 좁게 잡을수록 안전하다. 시스템 루트나 홈 디렉터리 전체를 넘기는 것은 피한다.

6. Context7 MCP - 최신 라이브러리 문서

무엇인가

Context7 MCP는 Upstash가 만든 서버로, 라이브러리의 버전별 최신 문서를 실시간으로 가져온다. LLM은 학습 시점 이후의 API 변경을 모르기 때문에 옛날 문법으로 코드를 쓰는 경우가 많은데, Context7는 이 문제를 해결한다.

어떨 때 유용한가

  • 최신 API로 코딩 - 빠르게 바뀌는 프레임워크(Next.js, React 등)의 현재 버전 문법으로 정확하게 작성
  • 버전 마이그레이션 - 특정 버전의 변경점을 문서에서 직접 확인하며 코드 이전
  • 낯선 라이브러리 사용 - 처음 쓰는 라이브러리의 정확한 사용법을 문서 기반으로 받기

설치 방법

무료로도 쓸 수 있지만, context7.com에서 API 키를 발급받으면 더 높은 요청 한도를 얻는다. 모든 프로젝트에서 쓰도록 --scope user로 추가하는 경우가 많다. 

# Local stdio server (with API key)
claude mcp add --scope user context7 -- npx -y @upstash/context7-mcp \
  --api-key YOUR_API_KEY

# Or as a remote HTTP server
claude mcp add --scope user --transport http \
  --header "CONTEXT7_API_KEY: YOUR_API_KEY" \
  context7 https://mcp.context7.com/mcp

사용 예제

# 프롬프트 끝에 "use context7"를 붙이는 패턴이 흔하다
"Next.js 15 App Router로 서버 액션 예제를 작성해줘. use context7"

"이 코드를 React 19 최신 문법으로 마이그레이션해줘. use context7"
활용 팁 프롬프트에 use context7를 명시하면 Claude가 코드 작성 전에 해당 라이브러리 문서를 먼저 조회한다. "환각으로 만든 존재하지 않는 API"를 줄이는 데 효과적이다.

7. Sequential Thinking MCP - 단계적 추론

무엇인가

Sequential Thinking MCP는 Model Context Protocol 공식 예제 서버로, 복잡한 문제를 구조화된 사고 단계로 나누어 풀게 하는 도구를 제공한다. 생각을 한 덩어리로 쏟아내는 대신, 단계를 명시적으로 쪼개고 필요하면 이전 단계를 수정·분기하며 반성적으로(reflective) 진행한다.

어떨 때 유용한가

  • 아키텍처 설계 - 여러 제약을 동시에 고려해야 하는 설계 결정을 단계별로 검토
  • 까다로운 디버깅 - 가설을 세우고 검증하며 원인을 좁혀가는 과정을 명시적으로 진행
  • 요구사항 분해 - 모호한 요구사항을 작은 작업 단위로 쪼개는 계획 단계

설치 방법

API 키 없이 바로 쓸 수 있는 로컬 stdio 서버다.

# Add Sequential Thinking MCP
claude mcp add --scope user sequential-thinking \
  -- npx -y @modelcontextprotocol/server-sequential-thinking
{
  "mcpServers": {
    "sequential-thinking": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-sequential-thinking"]
    }
  }
}

사용 예제

"이 모듈의 순환 의존성을 어떻게 끊을지 단계적으로 분석해줘"

"결제 실패 버그의 원인을 가설-검증 방식으로 차근차근 좁혀줘"
알아두기 최신 Claude 모델은 자체 추론 능력이 이미 강력하다. Sequential Thinking은 만능 가속기가 아니라, 사고 과정을 눈에 보이게 구조화하고 싶을 때 쓰는 도구로 이해하는 것이 좋다.

8. Sentry MCP - 에러 트래킹

무엇인가

Sentry MCP는 에러 모니터링 서비스 Sentry가 제공하는 공식 원격 HTTP 서버다. 프로덕션에서 실제로 발생한 에러, 스택 트레이스, 이슈 데이터를 Claude Code가 직접 조회한다. OAuth 2.0으로 인증한다.

어떨 때 유용한가

  • 실데이터 기반 디버깅 - "지난 24시간 동안 가장 흔한 에러가 뭐야?"
  • 스택 트레이스 분석 - "에러 ID abc123의 스택 트레이스를 보여줘"
  • 회귀 추적 - "이 새 에러는 어느 배포에서 들어왔어?"

설치 방법

원격 HTTP 서버로 추가한 뒤, /mcp 명령으로 OAuth 인증을 진행한다.

# Add Sentry MCP
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
# Claude Code 안에서 인증 실행
/mcp
# 브라우저가 열리면 Sentry 계정으로 로그인

사용 예제

"오늘 발생 빈도 상위 5개 에러를 정리하고 각각 원인 후보를 알려줘"

"에러 ID xyz789를 보고 관련 코드를 찾아서 수정안을 제안해줘"
활용 팁 OAuth 인증이 필요한 원격 서버는 추가만으로는 동작하지 않는다. /mcp를 실행해 인증을 마쳐야 한다. /mcp 패널에서 각 서버의 도구 개수와 연결 상태를 한눈에 볼 수 있다.

9. Slack MCP - 메시지 연동

무엇인가

Slack MCP는 Slack이 제공하는 공식 원격 HTTP 서버다. Slack 워크스페이스에서 메시지를 검색하고, 읽고, 보내고, 채널과 캔버스, 사용자 정보를 다룰 수 있다. OAuth로 워크스페이스 인증을 거친다.

어떨 때 유용한가

  • 맥락 끌어오기 - "Slack #design 채널에 올라온 새 시안을 보고 이메일 템플릿을 업데이트해줘"
  • 논의 요약 - "어제 #incident 채널의 장애 논의를 요약해줘"
  • 결과 공유 - 작업 완료 후 특정 채널에 결과 메시지 전송

설치 방법

원격 HTTP 서버로 추가한 뒤 /mcp로 OAuth 인증한다.

# Add Slack MCP
claude mcp add --transport http slack https://mcp.slack.com/mcp

# Claude Code 안에서
/mcp

OAuth 권한 범위를 좁히고 싶다면 .mcp.json에서 oauth.scopes를 지정한다.

{
  "mcpServers": {
    "slack": {
      "type": "http",
      "url": "https://mcp.slack.com/mcp",
      "oauth": {
        "scopes": "channels:read chat:write search:read"
      }
    }
  }
}

사용 예제

"#release 채널에서 'v2.3' 관련 메시지를 검색해서 정리해줘"

"빌드가 통과되면 #dev 채널에 완료 메시지를 보내줘"
주의 Slack MCP는 메시지를 보낼 수도 있다. 의도치 않은 전송을 막으려면 OAuth 범위를 필요한 만큼만 부여하고, 메시지 전송이 포함된 작업은 결과를 확인한 뒤 진행한다.

10. Vercel MCP - 배포와 프로젝트 관리

무엇인가

Vercel MCP는 Vercel이 제공하는 공식 원격 HTTP 서버다. https://mcp.vercel.com 주소로 연결하며, OAuth 2.0으로 인증한다. Vercel 프로젝트와 배포(deployment)를 Claude Code 안에서 직접 조회하고 관리하며, Vercel 공식 문서 검색도 지원한다. 인증 없이 쓸 수 있는 공개 도구(문서 검색)와 인증이 필요한 도구(프로젝트/배포 관리)로 나뉜다.

어떨 때 유용한가

  • 배포 상태 확인 - "최근 프로덕션 배포가 성공했어? 실패했다면 어느 커밋이야?"
  • 빌드 로그 분석 - "방금 실패한 배포의 빌드 로그를 보고 원인을 찾아줘"
  • Vercel 설정 문의 - "Next.js 프로젝트에서 환경 변수를 추가하는 방법을 Vercel 문서에서 찾아줘"

설치 방법

원격 HTTP 서버로 추가한 뒤 /mcp 명령으로 OAuth 인증을 진행한다.

# Add Vercel MCP
claude mcp add --transport http vercel https://mcp.vercel.com
# Claude Code 안에서 인증 실행
/mcp
# 브라우저가 열리면 Vercel 계정으로 로그인

.mcp.json에 직접 작성하려면 다음과 같다.

{
  "mcpServers": {
    "vercel": {
      "type": "http",
      "url": "https://mcp.vercel.com"
    }
  }
}

사용 예제

"내 Vercel 프로젝트 목록과 각각의 최근 배포 상태를 정리해줘"

"가장 최근 배포의 빌드 로그에서 에러를 찾아 수정안을 제안해줘"

"이 프로젝트의 프리뷰 배포 URL을 알려줘"
주의 Vercel MCP에 연결하면 AI 도구가 본인 Vercel 계정과 동일한 권한을 갖는다. 공식 엔드포인트(https://mcp.vercel.com)가 맞는지 반드시 확인하고, 배포·설정을 바꾸는 작업은 사람이 직접 확인하는 단계를 두는 것이 좋다.

11. Supabase MCP - 데이터베이스 관리

무엇인가

Supabase MCP는 Supabase가 제공하는 공식 원격 HTTP 서버로, https://mcp.supabase.com/mcp 주소로 연결한다. 데이터베이스 테이블 조회, SQL 쿼리 실행, 마이그레이션 적용, Edge Function 배포, 프로젝트 설정과 API 키 조회, TypeScript 타입 생성, 공식 문서 검색까지 여러 도구 그룹을 제공한다. 기본 인증은 브라우저 기반 OAuth이며, CI 환경에서는 개인 액세스 토큰(personal access token)을 헤더로 전달할 수도 있다.

어떨 때 유용한가

  • 스키마 기반 코딩 - "users 테이블 구조를 보고 그에 맞는 타입 정의와 쿼리 함수를 작성해줘"
  • 마이그레이션 작성 - "orders 테이블에 status 컬럼을 추가하는 마이그레이션을 만들고 적용해줘"
  • 데이터 확인 - "지난 7일간 가입자 수를 쿼리해서 보여줘"

설치 방법

원격 HTTP 서버로 추가한 뒤 /mcp로 OAuth 인증한다. project_ref 쿼리 파라미터로 특정 프로젝트에만 접근하도록 범위를 좁히고, read_only=true로 읽기 전용 모드를 걸 수 있다. 

# Add Supabase MCP (scoped to one project, read-only)
claude mcp add --transport http supabase \
  "https://mcp.supabase.com/mcp?project_ref=YOUR_PROJECT_REF&read_only=true"

# Claude Code 안에서
/mcp

CI 환경 등에서 개인 액세스 토큰을 쓰려면 .mcp.json에 다음과 같이 작성한다.

{
  "mcpServers": {
    "supabase": {
      "type": "http",
      "url": "https://mcp.supabase.com/mcp?project_ref=${SUPABASE_PROJECT_REF}",
      "headers": {
        "Authorization": "Bearer ${SUPABASE_ACCESS_TOKEN}"
      }
    }
  }
}

사용 예제

"현재 데이터베이스의 테이블 목록과 각 테이블의 컬럼을 정리해줘"

"products 테이블에 재고 컬럼을 추가하는 마이그레이션을 작성해줘"

"이 프로젝트의 TypeScript 타입을 생성해서 src/types에 반영해줘"
주의 프로덕션 데이터베이스에는 연결하지 않는다. 개발용 프로젝트에 붙이고, 민감한 데이터를 다룰 때는 read_only=true로 쓰기를 막는다. project_ref로 프로젝트를 한정하면 다른 프로젝트 데이터에 접근하지 못하게 막을 수 있다.

12. MCP Server Dev - 직접 서버 만들기

무엇인가

mcp-server-dev는 Anthropic이 공식 제공하는 플러그인이다. 앞의 도구들이 이미 만들어진 MCP 서버를 연결하는 것이라면, 이 플러그인은 나만의 MCP 서버를 직접 만들도록 도와준다. 사내 API나 도구를 Claude Code에 연결하고 싶을 때 출발점이 된다.

어떨 때 유용한가

  • 사내 도구 연동 - 회사 내부 시스템을 MCP 서버로 감싸 Claude Code에서 호출
  • 커스텀 워크플로우 - 팀 전용 데이터 소스나 자동화를 도구로 노출
  • 학습 - MCP 서버 구조를 실제 스캐폴딩으로 익히기

설치 방법

플러그인은 claude mcp add가 아니라 /plugin install로 설치한다.

# Claude Code 안에서 실행
/plugin install mcp-server-dev@claude-plugins-official

# 현재 세션에서 활성화
/reload-plugins

사용 예제

# 플러그인이 제공하는 스킬 실행
/mcp-server-dev:build-mcp-server

# Claude가 용도를 물어본 뒤 원격 HTTP 또는 로컬 stdio 서버를 스캐폴딩한다
알아두기 플러그인은 마켓플레이스를 통해 배포된다. claude-plugins-official은 Anthropic 공식 마켓플레이스다. 다른 마켓플레이스를 쓰려면 /plugin marketplace add <git-url>로 먼저 등록한 뒤 /plugin install한다.

13. 설치와 운영 팁

MCP 관리 명령어 정리

명령어 기능
claude mcp add ... MCP 서버 추가 (옵션은 서버 이름 앞에, -- 뒤에 실행 명령)
claude mcp add-json <name> '<json>' JSON 설정으로 서버 추가
claude mcp list 설정된 모든 서버 목록 보기
claude mcp get <name> 특정 서버의 상세 설정 확인
claude mcp remove <name> 서버 제거
/mcp (세션 안에서) 서버 연결 상태 확인 및 OAuth 인증
/plugin install <name>@<marketplace> 플러그인 설치
/plugin marketplace add <url> 플러그인 마켓플레이스 등록

옵션 순서에 주의

claude mcp add에서 가장 흔한 실수는 옵션 위치다. --transport, --env, --scope, --header 같은 옵션은 반드시 서버 이름 앞에 와야 한다. 그리고 --(더블 대시)가 서버 이름과 실제 실행 명령을 구분한다. 

# 올바른 형식
claude mcp add --transport stdio --env KEY=value myserver -- npx -y some-server

# --env는 서버에 전달할 환경 변수, -- 뒤는 서버 실행 명령

민감 정보는 환경 변수로

API 키나 토큰을 .mcp.json에 그대로 적으면 버전 관리에 노출된다. Claude Code는 .mcp.json에서 환경 변수 확장을 지원하므로, 키는 환경 변수로 빼낸다. 

{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": {
        "Authorization": "Bearer ${API_KEY}"
      }
    }
  }
}

${VAR}는 환경 변수 값으로, ${VAR:-default}는 값이 없으면 기본값으로 확장된다.

범위 선택 가이드

  • local (기본) - 현재 프로젝트에서 본인만. 실험적 설정, 개인 자격 증명에 적합
  • project - .mcp.json에 저장되어 팀 공유. 프로젝트 공통 도구에 적합. 단, 키는 환경 변수로
  • user - 모든 프로젝트에서 본인만. Context7, Sequential Thinking 같은 범용 도구에 적합
보안 체크리스트 출처가 불분명한 MCP 서버는 추가하지 않는다. 외부 콘텐츠를 가져오는 서버는 프롬프트 인젝션 위험이 있다. project 범위로 공유하는 서버에는 토큰을 직접 적지 않는다. 메시지 전송·파일 쓰기 권한이 있는 서버는 결과를 꼭 확인한다.

정리

  1. Playwright MCP로 Claude가 자기 UI를 직접 눈으로 검증하게 한다
  2. GitHub / Sentry / Slack MCP로 이슈·에러·메시지를 채팅 안으로 끌어온다
  3. Context7 MCP로 최신 문서 기반 코딩, 환각 API를 줄인다
  4. Filesystem / Sequential Thinking MCP로 접근 범위와 사고 과정을 명시적으로 다룬다
  5. Vercel / Supabase MCP로 배포 상태와 데이터베이스를 채팅 안에서 직접 다룬다
  6. mcp-server-dev로 사내 도구를 직접 MCP 서버로 만든다
  7. 키는 환경 변수로, 범위는 용도에 맞게, 신뢰할 수 있는 서버만 추가한다
