카메라 캘리브레이션이란?

카메라 캘리브레이션(camera calibration)은 카메라의 광학적 특성을 수치로 구하는 작업이다. 렌즈와 센서가 3차원 세상을 어떻게 2차원 이미지로 바꾸는지 — 그 변환 규칙을 숫자로 알아내는 것이다. 구체적으로는 초점거리, 주점, 렌즈 왜곡 같은 값들을 측정한다.

왜 필요한가. 이미지 한 장에서 픽셀 좌표 (320, 240)을 읽었다고 하자. 그 픽셀이 실세계에서 몇 mm 떨어진 점인지, 어느 방향에 있는지는 카메라의 특성을 모르면 알 수 없다. 캘리브레이션은 픽셀 좌표를 실세계 좌표와 연결하는 전제다. 이게 없으면 픽셀은 그저 색깔이 칠해진 격자일 뿐이고, 측정도 3D 복원도 불가능하다.

산업 측정 검사의 출발점 "이 부품의 구멍 지름이 5.00 mm인가"를 카메라로 판정하려면, 픽셀 거리를 mm로 변환할 수 있어야 한다. 그 변환의 정확도는 캘리브레이션 품질에 그대로 묶여 있다. 캘리브레이션을 대충 하면 그 위에 쌓는 모든 측정이 흔들린다.

카메라 모델 — 핀홀 모델

카메라가 3D 점을 2D로 바꾸는 과정을 수학적으로 단순화한 것이 핀홀 카메라 모델(pinhole camera model)이다. 렌즈를 아주 작은 구멍 하나로 가정한다. 3차원 공간의 점에서 나온 빛이 그 구멍을 통과해 반대편 이미지 평면에 한 점으로 맺힌다.

3D 점 P가 광학 중심을 지나 이미지 평면에 점 p로 투영된다. 이 투영 규칙을 숫자로 기술하는 것이 카메라 모델이다.

이 투영 과정은 두 단계로 나뉜다. 먼저 외부 파라미터가 월드 좌표의 3D 점을 카메라 기준 좌표로 옮긴다(회전 + 이동). 그다음 내부 파라미터가 카메라 좌표의 3D 점을 이미지 평면의 픽셀로 투영한다. 식으로 쓰면 다음과 같다.

// 핀홀 모델의 투영 식 (동차 좌표 표기)
//
//   s * [u, v, 1]^T  =  K * [ R | t ] * [X, Y, Z, 1]^T
//
//   [X,Y,Z]  : 월드 좌표의 3D 점
//   [R | t]  : 외부 파라미터 (회전 행렬 R, 이동 벡터 t)
//   K        : 내부 파라미터 행렬 (카메라 행렬)
//   [u,v]    : 결과 픽셀 좌표
//   s        : 스케일 인자 (깊이에 의해 정해짐)
//
// 여기에 더해 렌즈 왜곡이 [u,v]를 비선형으로 비튼다.

캘리브레이션이 하는 일은 결국 이 식의 K, 왜곡 계수, 그리고 각 촬영의 R·t를 데이터로부터 거꾸로 푸는 것이다.

내부 파라미터 (intrinsic)

내부 파라미터는 카메라 한 대의 고유한 광학 특성이다. 카메라를 어디에 두든 바뀌지 않고, 렌즈·센서 조합에만 의존한다. 카메라 좌표의 3D 점을 이미지 픽셀로 투영하는 규칙을 담는다.

네 개의 핵심 값이 있다. 초점거리 fx, fy(픽셀 단위)와 주점 cx, cy(광축이 이미지와 만나는 점, 보통 이미지 중앙 근처)다. 이들을 3×3 행렬로 묶은 것이 카메라 행렬 K다.

// 카메라 행렬 K (3x3)
//
//       | fx   0   cx |
//   K = |  0  fy   cy |
//       |  0   0    1 |
//
//   fx, fy : 초점거리 (픽셀 단위). 보통 fx ≈ fy
//   cx, cy : 주점 좌표 (픽셀)

cv::Mat cameraMatrix = (cv::Mat_<double>(3, 3) <<
    1400.0,    0.0,  960.0,
       0.0, 1400.0,  540.0,
       0.0,    0.0,    1.0);

// 개별 값 꺼내 쓰기
double fx = cameraMatrix.at<double>(0, 0);
double cx = cameraMatrix.at<double>(0, 2);
파라미터기호의미단위
초점거리 Xfx가로 방향 초점거리픽셀
초점거리 Yfy세로 방향 초점거리픽셀
주점 Xcx광축의 가로 위치픽셀
주점 Ycy광축의 세로 위치픽셀
초점거리가 mm가 아니라 픽셀인 이유 렌즈의 물리적 초점거리(예: 16 mm)를 센서의 픽셀 크기로 나눈 값이 fx, fy다. 픽셀 단위로 두면 센서 해상도와 무관하게 투영 식이 깔끔해진다. fx와 fy가 다르면 픽셀이 정사각형이 아니라는 뜻이다.

렌즈 왜곡 (distortion)

핀홀 모델은 빛이 직진한다고 가정하지만, 실제 렌즈는 빛을 휘게 한다. 그 결과 직선이 이미지에서 곡선으로 보이는데, 이를 렌즈 왜곡이라 한다. 왜곡은 크게 두 종류다.

방사 왜곡 (radial distortion)

이미지 중심에서 멀어질수록 심해지는 왜곡이다. 광각 렌즈에서 두드러진다. 직선이 바깥으로 부푸는 배럴 왜곡(barrel), 안으로 휘는 핀쿠션 왜곡(pincushion) 두 패턴이 있다. 계수 k1, k2, k3로 모델링한다.

접선 왜곡 (tangential distortion)

렌즈와 센서가 완벽히 평행하지 않을 때 생긴다. 이미지의 일부 영역이 실제보다 가깝거나 멀게 보인다. 계수 p1, p2로 모델링한다.

// OpenCV의 왜곡 계수 벡터 — 순서가 고정되어 있다
//
//   distCoeffs = [ k1, k2, p1, p2, k3 ]
//
//   k1, k2, k3 : 방사 왜곡 계수
//   p1, p2     : 접선 왜곡 계수

cv::Mat distCoeffs = (cv::Mat_<double>(1, 5) <<
    -0.28, 0.12, 0.0005, -0.0003, -0.04);

// 왜곡이 거의 없는 고급 렌즈라면 0에 가까운 값이 나온다.
// 광각·저가 렌즈일수록 k1의 절댓값이 커진다.
왜곡 계수종류역할
k1방사1차 방사 왜곡 — 영향이 가장 큼
k2방사2차 방사 왜곡
k3방사3차 방사 왜곡 — 초광각에서만 의미
p1접선센서 기울어짐 보정 (세로)
p2접선센서 기울어짐 보정 (가로)
배럴 vs 핀쿠션 체커보드의 바깥쪽 직선이 바깥으로 볼록하면 배럴(k1 < 0 경향), 안으로 오목하면 핀쿠션(k1 > 0 경향)이다. 보정 후에는 이 직선들이 다시 곧게 펴진다 — 보정이 잘 됐는지 눈으로 확인하는 가장 쉬운 방법이다.

외부 파라미터 (extrinsic)

외부 파라미터는 카메라와 대상의 상대적인 위치 관계를 나타낸다. 내부 파라미터와 달리, 카메라나 대상을 움직이면 바뀐다. 월드 좌표계의 점을 카메라 좌표계로 옮기는 변환이며, 회전 행렬 R(3×3)과 이동 벡터 t(3×1)로 구성된다.

// 외부 파라미터 — 월드 좌표 -> 카메라 좌표 변환
//
//   [X_cam, Y_cam, Z_cam]^T  =  R * [X_world, Y_world, Z_world]^T  +  t
//
//   R : 3x3 회전 행렬 (카메라가 어느 방향을 보는가)
//   t : 3x1 이동 벡터 (카메라가 어디에 있는가)

// calibrateCamera는 R을 회전 벡터(rvec) 형태로 돌려준다.
// Rodrigues 변환으로 3x3 행렬과 상호 변환한다.
cv::Mat rvec, tvec;        // 한 장의 촬영에 대한 외부 파라미터
cv::Mat rotationMatrix;
cv::Rodrigues(rvec, rotationMatrix);   // rvec(3x1) -> R(3x3)
내부는 하나, 외부는 촬영마다 따로 캘리브레이션에서 체커보드를 20장 찍었다면, 내부 파라미터 K와 왜곡 계수는 전체에 공통인 한 세트가 나온다. 반면 외부 파라미터 R·t는 촬영 한 장마다 따로 나온다 — 매번 체커보드의 위치·각도가 달랐기 때문이다.

체커보드 캘리브레이션 절차

가장 널리 쓰이는 방법은 체커보드(체스판 패턴)를 이용하는 것이다. 패턴의 코너 간격을 정확히 알고 있으므로, 여러 각도에서 찍은 이미지의 코너 위치만으로 카메라 파라미터를 역산할 수 있다. 이 아이디어가 그 유명한 Zhang's method(장정유의 방법, 2000)이고 OpenCV의 calibrateCamera가 이를 구현한다.

단계작업OpenCV 함수
①여러 각도·기울기로 체커보드 촬영 (15~20장)—
②각 이미지에서 체커보드 코너 검출findChessboardCorners
③검출된 코너를 서브픽셀 정밀도로 다듬기cornerSubPix
④대응점 집합으로 카메라 파라미터 추정calibrateCamera

준비 — 3D 기준점 좌표 만들기

체커보드의 내부 코너들이 실세계에서 어디 있는지를 정의한다. 보드가 평면이므로 Z = 0으로 두고, 정사각형 한 칸의 실제 크기(mm)를 곱한다.

#include <opencv2/opencv.hpp>
#include <vector>

// 체커보드 내부 코너 수 (가로 9, 세로 6) — 칸 수가 아니라 코너 수
const cv::Size kBoardSize(9, 6);
const float kSquareSize = 25.0f;   // 정사각형 한 칸 = 25 mm

// 보드 한 장의 3D 기준점 (Z=0 평면)
std::vector<cv::Point3f> objectTemplate;
for (int row = 0; row < kBoardSize.height; ++row)
{
    for (int col = 0; col < kBoardSize.width; ++col)
    {
        objectTemplate.emplace_back(col * kSquareSize,
                                    row * kSquareSize,
                                    0.0f);
    }
}

②③ 코너 검출 + 서브픽셀 정밀화

각 이미지에서 코너를 찾고, 정수 픽셀로 나온 좌표를 cornerSubPix로 소수점 단위까지 다듬는다. 정밀도가 캘리브레이션 품질을 좌우한다.

std::vector<std::vector<cv::Point3f>> objectPoints;  // 모든 이미지의 3D 점
std::vector<std::vector<cv::Point2f>> imagePoints;   // 모든 이미지의 2D 코너
cv::Size imageSize;

std::vector<std::string> files = { "calib01.jpg", "calib02.jpg", /* ... */ };

for (const auto& file : files)
{
    cv::Mat image = cv::imread(file, cv::IMREAD_COLOR);
    if (image.empty())
    {
        std::cerr << "이미지 로드 실패: " << file << std::endl;
        continue;
    }

    cv::Mat gray;
    cv::cvtColor(image, gray, cv::COLOR_BGR2GRAY);
    imageSize = gray.size();

    // ② 체커보드 코너 검출
    std::vector<cv::Point2f> corners;
    bool found = cv::findChessboardCorners(
        gray, kBoardSize, corners,
        cv::CALIB_CB_ADAPTIVE_THRESH | cv::CALIB_CB_NORMALIZE_IMAGE);

    if (!found)
    {
        std::cerr << "코너 검출 실패: " << file << std::endl;
        continue;   // 이 이미지는 버린다
    }

    // ③ 서브픽셀 정밀화
    cv::TermCriteria criteria(
        cv::TermCriteria::EPS + cv::TermCriteria::MAX_ITER, 30, 0.001);
    cv::cornerSubPix(gray, corners, cv::Size(11, 11), cv::Size(-1, -1),
                     criteria);

    objectPoints.push_back(objectTemplate);
    imagePoints.push_back(corners);

    // (선택) 검출 결과를 눈으로 확인
    cv::drawChessboardCorners(image, kBoardSize, corners, found);
    cv::imshow("corners", image);
    cv::waitKey(100);
}

④ calibrateCamera로 파라미터 추정

모은 대응점 집합을 calibrateCamera에 넘기면 내부 파라미터, 왜곡 계수, 그리고 촬영별 외부 파라미터가 한 번에 나온다.

cv::Mat cameraMatrix, distCoeffs;
std::vector<cv::Mat> rvecs, tvecs;   // 촬영별 외부 파라미터

// 반환값은 전체 RMS 재투영 오차
double rms = cv::calibrateCamera(
    objectPoints, imagePoints, imageSize,
    cameraMatrix, distCoeffs, rvecs, tvecs);

std::cout << "RMS 재투영 오차: " << rms << " px" << std::endl;
std::cout << "카메라 행렬 K:\n" << cameraMatrix << std::endl;
std::cout << "왜곡 계수:\n" << distCoeffs << std::endl;

// 결과를 파일로 저장해 두면 매번 다시 캘리브레이션할 필요가 없다
cv::FileStorage fs("calibration.yml", cv::FileStorage::WRITE);
fs << "camera_matrix" << cameraMatrix;
fs << "dist_coeffs" << distCoeffs;
fs << "image_size" << imageSize;
fs.release();
실행 결과 (콘솔)
RMS 재투영 오차: 0.231 px 카메라 행렬 K: [1402.7, 0, 958.3; 0, 1401.9, 541.2; 0, 0, 1] 왜곡 계수: [-0.2814, 0.1187, 0.00041, -0.00029, -0.0376]
findChessboardCorners의 패턴 크기는 내부 코너 수다 체커보드가 가로 10칸·세로 7칸이라면 cv::Size(9, 6)을 넘겨야 한다 — 칸 수가 아니라 칸과 칸 사이의 내부 코너 수다. 여기서 한 칸씩 잘못 세면 모든 이미지에서 검출이 실패한다. 가장 흔한 첫 실수다.

재투영 오차 (reprojection error)

재투영 오차는 캘리브레이션 품질을 재는 지표다. 추정한 파라미터로 3D 기준점을 다시 이미지에 투영해 보고, 실제로 검출했던 코너 위치와 얼마나 어긋나는지를 픽셀 단위로 측정한다. 낮을수록 좋다.

// 이미지별 재투영 오차를 직접 계산해 본다
double totalError = 0.0;
size_t totalPoints = 0;

for (size_t i = 0; i < objectPoints.size(); ++i)
{
    std::vector<cv::Point2f> projected;

    // 추정한 파라미터로 3D 점을 다시 2D로 투영
    cv::projectPoints(objectPoints[i], rvecs[i], tvecs[i],
                      cameraMatrix, distCoeffs, projected);

    // 실제 검출 코너와의 거리(L2 norm)
    double err = cv::norm(imagePoints[i], projected, cv::NORM_L2);

    double imgError = err * err;
    totalError += imgError;
    totalPoints += objectPoints[i].size();

    std::cout << "이미지 " << i << " 오차: "
              << std::sqrt(imgError / objectPoints[i].size())
              << " px" << std::endl;
}

double meanError = std::sqrt(totalError / totalPoints);
std::cout << "전체 평균 재투영 오차: " << meanError << " px" << std::endl;
RMS 오차해석
< 0.3 px매우 우수 — 정밀 측정에 바로 사용 가능
0.3 ~ 0.5 px양호 — 일반적인 검사 용도로 충분
0.5 ~ 1.0 px보통 — 촬영 추가나 재촬영 고려
> 1.0 px불량 — 코너 오검출, 각도 단조, 보드 평탄도 의심
재투영 오차를 확인하지 않으면 캘리브레이션을 한 게 아니다 calibrateCamera는 입력이 엉망이어도 어떻게든 숫자를 뱉는다. RMS 오차를 보지 않으면 그 결과가 쓸 만한지 알 방법이 없다. 특정 이미지의 오차만 유독 크다면 그 이미지를 빼고 다시 돌리는 것이 좋다.

왜곡 보정 — undistort / remap

파라미터를 구했으면 이제 이미지에서 렌즈 왜곡을 제거할 수 있다. 휘었던 직선이 곧게 펴진다. 방법은 두 가지다.

undistort — 한 장짜리 간단한 보정

이미지 한 장만 보정하면 된다면 undistort 한 줄로 끝난다.

cv::Mat distorted = cv::imread("distorted.jpg");
cv::Mat undistorted;

// 카메라 행렬 + 왜곡 계수로 왜곡 제거
cv::undistort(distorted, undistorted, cameraMatrix, distCoeffs);

cv::imwrite("undistorted.jpg", undistorted);

initUndistortRectifyMap + remap — 반복 처리용 (빠름)

undistort는 호출할 때마다 보정 맵을 새로 계산한다. 같은 카메라로 들어오는 영상 스트림을 매 프레임 보정한다면 낭비다. 맵을 한 번만 만들어 두고 remap으로 재사용하면 훨씬 빠르다.

// 보정 맵은 한 번만 계산한다 (루프 밖에서)
cv::Mat map1, map2;
cv::initUndistortRectifyMap(
    cameraMatrix, distCoeffs, cv::Mat(),       // R = 단안이면 비워둠
    cameraMatrix, imageSize,                   // 새 카메라 행렬
    CV_16SC2, map1, map2);

// 매 프레임은 remap만 — 맵 재계산이 없어 빠르다
cv::VideoCapture cap(0);
cv::Mat frame, corrected;
while (cap.read(frame))
{
    cv::remap(frame, corrected, map1, map2, cv::INTER_LINEAR);
    cv::imshow("corrected", corrected);
    if (cv::waitKey(1) == 27) break;   // ESC 종료
}
getOptimalNewCameraMatrix로 검은 테두리 조절 보정하면 이미지 가장자리에 검은 영역이 생긴다. getOptimalNewCameraMatrix에 alpha 값을 주면, 검은 영역을 모두 잘라낼지(alpha=0) 모든 픽셀을 남길지(alpha=1) 선택할 수 있다. 이 행렬을 initUndistortRectifyMap의 새 카메라 행렬로 넘긴다.

캘리브레이션 결과 활용

캘리브레이션 결과는 단순히 이미지를 곧게 펴는 데서 끝나지 않는다. 픽셀과 실세계를 잇는 다리이므로, 그 위에 여러 응용이 쌓인다.

활용내용
정밀 측정픽셀 거리를 mm로 변환해 부품 치수·위치·각도를 측정
3D 복원스테레오 카메라나 다중 시점으로 깊이·형상 복원
자세 추정 (PnP)알려진 3D 점과 이미지 대응으로 카메라/대상의 6자유도 자세 계산
AR실세계 좌표에 정확히 정합되는 가상 객체 합성

예를 들어 평면 위에 놓인 대상을 측정한다면, 캘리브레이션된 카메라로 보정한 이미지에서 픽셀 좌표를 실세계 좌표로 변환할 수 있다.

// 알려진 3D 점들과 이미지 대응으로 대상의 자세를 구한다 (PnP)
std::vector<cv::Point3f> objectPts = /* 대상의 3D 좌표 */;
std::vector<cv::Point2f> imagePts  = /* 이미지에서 검출한 2D 좌표 */;

cv::Mat rvec, tvec;
bool ok = cv::solvePnP(objectPts, imagePts,
                       cameraMatrix, distCoeffs, rvec, tvec);

if (ok)
{
    // tvec = 카메라 기준 대상의 위치 (캘리브레이션 단위, 보통 mm)
    std::cout << "대상까지 거리: " << cv::norm(tvec) << " mm" << std::endl;
}
산업 측정 검사의 필수 전제 "픽셀 → mm" 변환 정확도가 곧 측정 정확도다. 캘리브레이션 없이 픽셀당 고정 비율(예: 0.05 mm/px)을 쓰면, 렌즈 왜곡 때문에 이미지 중심부와 가장자리의 실제 비율이 달라 측정값이 위치마다 흔들린다. 정밀 검사 시스템이 캘리브레이션을 가장 먼저 하는 이유다.

캘리브레이션 잘하는 팁

캘리브레이션은 입력 이미지의 품질이 전부다. 같은 알고리즘이라도 어떻게 촬영했느냐에 따라 RMS 오차가 몇 배씩 차이 난다.

팁이유
체커보드를 화면 전체에 채워가며 촬영가장자리 왜곡 정보가 있어야 k1~k3이 잘 추정됨
다양한 각도·기울기로 촬영기울임이 있어야 초점거리와 왜곡이 분리되어 풀림
충분한 장수 (15~20장)장수가 많아야 노이즈가 평균화되어 안정적
초점을 고정하고 촬영초점이 바뀌면 초점거리가 바뀌어 한 세트로 안 묶임
체커보드는 평평하고 단단한 판에 부착종이가 휘면 "평면" 가정이 깨져 오차가 커짐
조명을 균일하게, 반사 없이코너 검출 성공률과 서브픽셀 정밀도가 올라감
"중앙·코너·기울임"을 의식하며 촬영한다 보드를 이미지 중앙, 네 모서리, 그리고 좌우·상하로 기울인 자세까지 골고루 담는다. 한자리에서 살짝씩만 움직여 찍은 20장보다, 자세가 확실히 다른 12장이 더 좋은 결과를 낸다.

흔한 함정

캘리브레이션이 실패하거나, 성공한 줄 알았는데 측정이 안 맞을 때 의심할 지점들이다.

체커보드 코너 검출 실패

findChessboardCorners가 false만 돌려준다 조명이 어둡거나 불균일하면, 초점이 안 맞으면, 보드가 화면 밖으로 잘리면 검출이 실패한다. CALIB_CB_ADAPTIVE_THRESH와 CALIB_CB_NORMALIZE_IMAGE 플래그를 켜고, 그래도 안 되면 촬영 환경(조명·초점)부터 손본다. 알고리즘 탓이 아니라 사진 탓인 경우가 대부분이다.

장수 부족 · 각도 단조로움

다 정면에서 찍은 30장보다 자세가 다양한 15장 보드를 카메라와 거의 평행하게만 찍으면, 초점거리와 거리가 수학적으로 구분되지 않아(불량 조건) 파라미터가 엉뚱한 값으로 수렴한다. 장수만 늘리는 게 아니라 각도와 기울기의 다양성을 늘려야 한다.

재투영 오차를 확인하지 않음

RMS 오차를 안 보고 결과를 그냥 쓴다 calibrateCamera의 반환값(RMS 오차)을 무시하면, 품질이 나쁜 파라미터인지 알 수 없다. 1 px가 넘는 오차로 측정 시스템을 구축해 놓고 "측정이 왜 안 맞지" 하는 경우가 흔하다. 오차를 먼저 확인하고, 큰 이미지는 빼고 다시 돌린다.

캘리브레이션 후 렌즈·초점을 건드림

초점 링을 돌리는 순간 캘리브레이션은 무효다 내부 파라미터는 렌즈·초점 상태에 묶여 있다. 캘리브레이션을 끝낸 뒤 줌을 바꾸거나 초점을 다시 맞추거나 렌즈를 교체하면, 저장해 둔 K와 왜곡 계수는 더 이상 그 카메라를 설명하지 못한다. 산업 현장에서는 캘리브레이션 후 초점·조리개 링을 테이프나 락으로 고정한다.

패턴 크기를 칸 수로 착각

findChessboardCorners에 넘기는 것은 내부 코너 수 앞서도 강조했지만 가장 자주 반복되는 실수다. 가로 10칸 보드의 가로 내부 코너는 9개다. cv::Size(10, 7)이 아니라 cv::Size(9, 6)을 넘겨야 한다. 한 칸 잘못 세면 모든 이미지에서 found == false가 되어 캘리브레이션 자체가 시작되지 않는다.
정리하면 패턴 크기는 내부 코너 수로 정확히, 다양한 각도로 15~20장, 코너 검출이 실패하면 촬영 환경부터, 끝나면 RMS 오차를 반드시 확인, 그리고 캘리브레이션 후 렌즈·초점은 절대 건드리지 않는다. 이 다섯 가지가 쓸 만한 캘리브레이션과 못 쓰는 캘리브레이션을 가른다.
