왜 이 시리즈를 시작했나

트렌드는 의외로 구두로 전해 듣는 경우가 많다. 어떤 코딩 에이전트가 좋아졌다더라, 이런 기능이 생겼다더라 — 그렇게 듣고 나서야 몇 달 늦게 따라가게 된다. 정보원이 사라지면 그 격차는 더 벌어진다.

그래서 흐름을 사람이 아니라 정기 기록에 의존하기로 했다. 매달 한 편, 그달의 큰 변화를 같은 형식으로 모아 둔다. 깊은 분석보다 "무엇이 바뀌었고 왜 중요한가"를 빠르게 훑는 데 목적이 있다. 더 파고들 주제는 별도 글로 이어 간다.

이달의 헤드라인

  • Claude Fable 5 등장. Anthropic이 6월 새 프런티어 모델을 내놨다. 다수 추론 벤치마크에서 최상위권으로 보도된다.
  • 코딩 에이전트 2강 체제 고착. Claude Code와 Codex(OpenAI)가 서로 다른 강점으로 공존한다. 한쪽이 다른 쪽을 압도했다기보다 용도가 갈렸다.
  • 에이전트의 "안전·자동화" 강화. Claude Code에 보안 점검 플러그인과 다수 서브에이전트를 묶는 동적 워크플로가 더해졌다.

프런티어 모델 동향

6월의 가장 큰 사건은 Anthropic Claude Fable 5의 등장이다. 추론 중심 벤치마크에서 당시 최상위권으로 보도됐고, 코딩·복잡 추론 과제에서 한 단계 올라섰다는 평가가 나왔다. 같은 시기 OpenAI는 GPT-5.6, Google은 Gemini 3.2로 라인업을 갱신했다. 큰 그림은 "분기마다 한 단계씩 올라가는" 흐름이 6월에도 이어졌다는 것이다.

실무에서 체감되는 변화는 벤치 점수 자체보다 기본값의 이동이다. 코딩 작업의 표준 모델 티어가 한 단계씩 올라가고, 어려운 과제에 더 많은 추론을 쓰는 설정(이른바 high/extra-high effort)이 보편화됐다. 즉 "더 똑똑한 모델"보다 "기본으로 더 깊게 생각하는 설정"이 자리 잡는 중이다.

벤치마크 수치는 그대로 믿지 않는다 모델 비교 점수는 측정 방식·버전·시점에 따라 출렁인다. 이 글의 수치는 6월 시점의 외부 보도·서드파티 비교 기준이며, 절대값보다 "어느 방향으로 움직였나"를 보는 게 안전하다. 정확한 사양은 각 공식 발표를 확인한다.

코딩 에이전트 — Claude Code vs Codex

요즘 가장 많이 듣는 이야기가 "Codex가 좋아졌다더라"다. 6월 기준으로 보면 절반만 맞다. 둘은 경쟁하지만 설계 철학이 다르고, 그래서 잘하는 일이 다르다.

벤치마크는 지표에 따라 엇갈려 "접전"으로 요약된다. 더 실질적인 차이는 일하는 방식이다. Claude Code는 코드베이스를 폭넓게 읽고 계획을 세운 뒤 감독 아래 진행하는 데 강하고, Codex는 클라우드 샌드박스에서 브라우저·파일시스템까지 다루며 빠르게 실행하는 데 강하다. 현재 Codex가 가진 컴퓨터 사용·브라우저 사용을 Claude Code는 갖고 있지 않다는 점이 실무에서 가장 자주 언급되는 격차다.

현장 컨센서스 — 숙련 개발자 다수는 둘 다 쓴다. 고품질·보안·맥락이 중요한 작업은 Claude Code, 싸고 빠른 자율 작업은 Codex로 나눠 맡기는 식이다. "하나만 고르는" 질문 자체가 점점 의미를 잃는 중이다.

도구·기능 업데이트

6월 전후로 Claude Code 쪽에서 눈에 띄는 변화가 이어졌다.

보안 점검 플러그인

코드 편집·diff·커밋을 실시간으로 보며 위험 패턴(SQL 인젝션, 명령 주입, XSS, 하드코딩된 키 등 다수 취약점 유형)을 자동으로 짚어 주는 플러그인이 마켓플레이스에 추가됐다. 에이전트가 "짜는 것"에서 "안전하게 짜는지 감시하는 것"으로 역할을 넓히는 흐름이다.

동적 워크플로 (다수 서브에이전트 오케스트레이션)

Claude가 스크립트를 직접 작성해 수십~수백 개의 서브에이전트를 조율하는 동적 워크플로가 도입됐다. 대규모 리뷰·마이그레이션·감사처럼 한 컨텍스트로는 감당하기 어려운 작업을 병렬로 쪼개 처리하는 방향이다.

auto mode 확대

권한 프롬프트를 매번 띄우는 대신 백그라운드 안전 점검으로 대체하는 auto mode가 서드파티 제공 환경(Bedrock·Vertex·Foundry 등)으로 확대됐다. 함께 샌드박스 자격증명 차단, 조직 단위 모델 제한 같은 거버넌스 기능도 보강됐다.

읽는 법 모델 경쟁(누가 몇 점)보다, 에이전트가 무엇을 자동화하기 시작했는지를 보는 게 트렌드 파악에 더 유용하다. 6월의 키워드는 "안전 점검의 자동화"와 "다수 에이전트 병렬화"였다.
