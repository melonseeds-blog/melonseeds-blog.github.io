직접 짜지 않고 라이브러리를 쓰는 이유

13, 14편에서 리덕션과 스캔을 직접 짜 봤다. 원리를 익히는 데는 좋지만, 제품 코드에서 같은 일을 매번 직접 짜면 문제가 생긴다. GPU 세대가 바뀔 때마다 블록 크기, 펼치기 정도, 메모리 접근 방식을 다시 튜닝해야 하고, 경계 조건 버그도 계속 따라다닌다. NVIDIA는 이런 기본 병렬 알고리즘을 라이브러리로 제공한다.

라이브러리성격비유
ThrustSTL 같은 고수준 인터페이스. 컨테이너와 알고리즘 함수GPU용 <algorithm>, std::vector
CUB저수준 부품. 장치 전체, 블록, 워프 단위 알고리즘커널을 짤 때 끼워 쓰는 부품 상자

둘 다 CUDA Toolkit에 기본으로 들어 있는 헤더 전용 라이브러리라 따로 설치하거나 링크할 것이 없다. 최근에는 libcu++와 함께 CCCL(CUDA C++ Core Libraries)이라는 하나의 프로젝트로 묶여 관리된다. Thrust의 GPU 쪽 구현 대부분이 실제로는 CUB를 호출하므로, 둘은 같은 엔진의 다른 손잡이라고 보면 된다.

Thrust 기본 - 컨테이너와 알고리즘

#include <thrust/host_vector.h>
#include <thrust/device_vector.h>
#include <thrust/sort.h>
#include <thrust/reduce.h>
#include <thrust/sequence.h>

int main()
{
    thrust::host_vector<float> h(1 << 20);
    for (size_t i = 0; i < h.size(); ++i) h[i] = rand() / (float)RAND_MAX;

    thrust::device_vector<float> d = h;       // cudaMalloc + cudaMemcpy in one line

    thrust::sort(d.begin(), d.end());          // GPU radix sort
    float sum = thrust::reduce(d.begin(), d.end(), 0.0f);   // GPU reduction, result on the host
    float mx  = d.back();                      // single element copy (device -> host)

    thrust::sequence(d.begin(), d.end());      // 0, 1, 2, ...
    h = d;                                     // copy back
}

STL을 써 본 사람이면 거의 설명이 필요 없다. 주요 구성 요소는 다음과 같다.

연산 넘기기 - functor와 device 람다

알고리즘에 넘기는 연산은 GPU에서 실행되므로 __device__로 컴파일되어야 한다. 방법은 두 가지다.

// 1) functor with __host__ __device__
struct Saxpy
{
    float a;
    __host__ __device__ float operator()(float x, float y) const { return a * x + y; }
};
thrust::transform(x.begin(), x.end(), y.begin(), y.begin(), Saxpy{2.0f});

// 2) extended device lambda (compile with: nvcc --extended-lambda)
float a = 2.0f;
thrust::transform(x.begin(), x.end(), y.begin(), y.begin(),
                  [=] __device__ (float xi, float yi) { return a * xi + yi; });
람다는 빌드 옵션이 필요 __device__ 람다는 nvcc의 --extended-lambda 옵션이 있어야 컴파일된다. Visual Studio 프로젝트라면 CUDA C/C++ → Command Line에 추가한다. 람다 캡처는 값 캡처([=])만 써야 한다. 참조 캡처([&])로 CPU 변수의 주소를 넘기면 GPU에서 그 주소를 읽다가 오류가 난다.

fancy iterator - 메모리 없이 값 만들기

Thrust의 강점 중 하나가 fancy iterator다. 실제 배열 없이 값을 계산해서 알고리즘에 넘겨 주므로, 중간 결과를 위한 임시 메모리와 그 메모리를 읽고 쓰는 시간이 사라진다. 메모리 대역폭이 한계인 GPU 연산에서는 이 차이가 크다.

iterator만들어 주는 값쓰는 곳
counting_iterator<int>(0)0, 1, 2, ...인덱스가 필요할 때 (좌표 계산, 위치 기록)
constant_iterator<T>(v)v, v, v, ...모두 같은 값으로 연산
transform_iterator(it, f)f(*it)를 읽을 때 계산변환 후 리덕션을 한 번에
zip_iterator(make_tuple(a, b))(a[i], b[i]) 묶음배열 여러 개를 함께 처리 (SoA)
permutation_iterator(v, idx)v[idx[i]]인덱스로 골라 읽기

예제 - 밝은 픽셀 좌표 모으기

14편의 stream compaction을 Thrust로 쓰면 다음과 같다. 인덱스 배열을 만들지 않고 counting_iterator를 입력으로 쓴다.

#include <thrust/copy.h>
#include <thrust/iterator/counting_iterator.h>

struct IsBright
{
    const unsigned char* img;
    unsigned char th;
    __host__ __device__ bool operator()(int i) const { return img[i] > th; }
};

// d_img: raw device pointer to a continuous 8-bit image of size w*h
thrust::device_vector<int> idx(w * h);                 // worst case size
auto first = thrust::counting_iterator<int>(0);
auto last  = first + w * h;
auto end   = thrust::copy_if(thrust::device, first, last, idx.begin(), IsBright{d_img, 200});
int count  = static_cast<int>(end - idx.begin());      // number of bright pixels
// idx[0..count) holds linear indices in increasing order: x = i % w, y = i / w

예제 - 평균과 표준편차 한 번에

평균과 분산을 구하려면 합과 제곱합이 필요하다. transform_reduce로 각 원소를 (x, x²) 쌍으로 바꾸면서 동시에 더하면, 영상을 한 번만 읽고 두 값을 얻는다.

#include <thrust/transform_reduce.h>
#include <thrust/tuple.h>

using Pair = thrust::tuple<double, double>;            // (sum, sum of squares)

struct ToPair
{
    __host__ __device__ Pair operator()(unsigned char v) const { double x = v; return Pair(x, x * x); }
};
struct AddPair
{
    __host__ __device__ Pair operator()(const Pair& a, const Pair& b) const
    { return Pair(thrust::get<0>(a) + thrust::get<0>(b), thrust::get<1>(a) + thrust::get<1>(b)); }
};

Pair s = thrust::transform_reduce(thrust::device, d_img, d_img + n, ToPair{}, Pair(0, 0), AddPair{});
double mean = thrust::get<0>(s) / n;
double var  = thrust::get<1>(s) / n - mean * mean;

기존 코드와 섞어 쓰기 - raw pointer와 스트림

실제 프로젝트에서는 이미 cudaMalloc으로 잡은 버퍼나 OpenCV GpuMat이 있다. Thrust 알고리즘은 raw pointer를 그대로 받을 수 있지만, 그 포인터가 GPU 메모리라는 것을 알려 줘야 한다.

#include <thrust/device_ptr.h>
#include <thrust/execution_policy.h>

float* d_raw;                                          // from cudaMalloc
cudaMalloc(&d_raw, n * sizeof(float));

// a) execution policy tells Thrust "these pointers are on the device"
thrust::sort(thrust::device, d_raw, d_raw + n);

// b) or wrap the pointer
thrust::device_ptr<float> p(d_raw);
thrust::sort(p, p + n);

// c) device_vector -> raw pointer for your own kernel
thrust::device_vector<float> v(n);
MyKernel<<<grid, block>>>(thrust::raw_pointer_cast(v.data()), n);

// d) run on a specific stream
thrust::sort(thrust::cuda::par.on(stream), d_raw, d_raw + n);

// e) do not block the host after the algorithm (Thrust 1.16+)
thrust::transform(thrust::cuda::par_nosync.on(stream), a, a + n, b, op);
GpuMat과 함께 쓸 때 cv::cuda::GpuMat은 보통 행마다 여백(pitch)이 있어서 메모리가 연속이 아니다. 전체를 1차원 배열처럼 다루려면 gm.isContinuous()를 확인하거나, cv::cuda::createContinuous로 연속 메모리를 할당한다. 행 단위로 처리해야 한다면 gm.ptr<T>(y)로 행마다 범위를 넘긴다.

Thrust의 숨은 비용

Thrust는 쓰기 편한 대신 보이지 않는 비용이 있다. 실시간 파이프라인에 넣기 전에 아래 항목을 확인한다.

비용원인대책
임시 메모리 할당sort, scan, copy_if 같은 알고리즘이 호출마다 내부 임시 버퍼를 cudaMalloc/cudaFree캐시 할당자를 실행 정책에 넘김 (thrust::cuda::par(alloc).on(s)) 또는 CUB 직접 사용
호스트 동기화값을 돌려주는 알고리즘(reduce, count_if)은 결과를 CPU로 가져오느라 반드시 기다림결과를 GPU 메모리에 남기는 CUB 사용
device_vector 원소 접근d[i] 한 번이 cudaMemcpy 한 번반복문에서 d[i] 금지. 통째로 복사 후 접근
device_vector 생성생성자가 메모리 할당 + 초기화 커널 실행프레임마다 새로 만들지 말고 재사용 (resize는 커질 때만 재할당)
반복문 안의 device_vector[i] for (int i = 0; i < d.size(); ++i) total += d[i];는 원소 수만큼 GPU→CPU 복사를 한다. 원소 100만 개면 복사 100만 번이다. 문법상 문제가 없어서 그대로 지나가기 쉬운 실수다.

CUB 장치 단위 알고리즘

CUB의 Device* 알고리즘은 Thrust와 같은 일을 하지만, 임시 메모리를 호출하는 쪽이 직접 준다. 그래서 호출이 두 번 필요하다. 첫 번째는 임시 메모리 크기를 묻고, 두 번째에 실제로 실행한다.

#include <cub/cub.cuh>

// one-time setup: ask for the temp size, allocate once
size_t tempBytes = 0;
cub::DeviceRadixSort::SortPairs(nullptr, tempBytes,
                                d_keysIn, d_keysOut, d_valsIn, d_valsOut, n, 0, 32, stream);
void* d_temp = nullptr;
cudaMalloc(&d_temp, tempBytes);

// every frame: no allocation, no host synchronization
cub::DeviceRadixSort::SortPairs(d_temp, tempBytes,
                                d_keysIn, d_keysOut, d_valsIn, d_valsOut, n, 0, 32, stream);

임시 메모리를 미리 잡아 두고 재사용할 수 있고, 모든 호출이 스트림 위에서 비동기로 실행되며, 결과도 GPU 메모리에 남는다. 그래서 17편의 CUDA Graph 캡처에도 그대로 들어간다. 실시간 파이프라인에서는 Thrust보다 CUB를 선호하는 이유다.

CUB 장치 알고리즘하는 일
DeviceReduce::Sum / Max / ArgMax / Reduce리덕션 (13편)
DeviceScan::InclusiveSum / ExclusiveSum스캔 (14편)
DeviceSelect::If / Flagged / Unique골라내기 (compaction)
DeviceRadixSort::SortKeys / SortPairs기수 정렬. begin_bit, end_bit로 정렬할 비트 범위를 줄이면 빨라짐

예제 - ROI마다 합계 구하기

검사 영상에서 ROI 여러 개의 밝기 합을 따로 구한다고 하자. ROI 픽셀을 한 배열에 이어 붙이고, 각 ROI가 시작하는 위치(offset)를 알려 주면 구간 리덕션 한 번으로 모든 ROI의 합이 나온다.

// d_vals:    pixels of ROI 0, then ROI 1, then ROI 2 ... (packed)
// d_offsets: [0, n0, n0+n1, n0+n1+n2, ...]  (numRoi + 1 entries)
size_t tempBytes = 0;
cub::DeviceSegmentedReduce::Sum(nullptr, tempBytes, d_vals, d_sums,
                                numRoi, d_offsets, d_offsets + 1, stream);
cudaMallocAsync(&d_temp, tempBytes, stream);
cub::DeviceSegmentedReduce::Sum(d_temp, tempBytes, d_vals, d_sums,
                                numRoi, d_offsets, d_offsets + 1, stream);
// d_sums[r] = sum of ROI r

CUB 블록, 워프 부품

직접 짜는 커널 안에서도 CUB를 쓸 수 있다. 13편의 BlockReduceSum을 손으로 짜는 대신 cub::BlockReduce를 쓰면, 블록 크기와 GPU에 맞는 구현을 CUB가 고른다.

#include <cub/block/block_reduce.cuh>
#include <cub/block/block_scan.cuh>

template <int BLOCK>
__global__ void RowStats(const float* img, int width, float* rowSum, float* rowMax)
{
    using BlockReduce = cub::BlockReduce<float, BLOCK>;
    __shared__ typename BlockReduce::TempStorage temp;    // CUB tells us how much shared memory

    const float* row = img + blockIdx.x * width;          // one block per row
    float s = 0.0f, m = -INFINITY;
    for (int x = threadIdx.x; x < width; x += BLOCK)
    {
        float v = row[x];
        s += v;
        m = fmaxf(m, v);
    }

    float total = BlockReduce(temp).Sum(s);
    __syncthreads();                                      // temp storage is reused below
    float maxv  = BlockReduce(temp).Reduce(m, cub::Max());

    if (threadIdx.x == 0) { rowSum[blockIdx.x] = total; rowMax[blockIdx.x] = maxv; }
}

RowStats<256><<<height, 256, 0, stream>>>(d_img, width, d_rowSum, d_rowMax);
부품하는 일
cub::WarpReduce, cub::WarpScan워프 안 리덕션, 스캔 (15편의 shuffle을 대신)
cub::BlockReduce, cub::BlockScan블록 안 리덕션, 스캔
cub::BlockLoad, cub::BlockStore스레드당 여러 원소를 결합된 접근(7편)으로 읽고 쓰기. 벡터 로드, 전치 방식 선택
cub::BlockRadixSort블록 안 정렬 (작은 배열 여러 개를 동시에 정렬)
cub::BlockHistogram블록 안 히스토그램
TempStorage를 다시 쓸 때는 동기화 위 예제처럼 같은 TempStorage로 두 번 연산하면, 그 사이에 __syncthreads()가 필요하다. 첫 연산의 shared memory 사용이 끝나기 전에 두 번째 연산이 덮어쓰면 결과가 틀린다. CUB 문서도 이 규칙을 명시하고 있다.

흔한 함정

예외 처리 Thrust는 CUDA 오류가 나면 thrust::system_error 예외를 던진다. 예외를 쓰지 않는 코드베이스라면 Thrust 호출을 try/catch로 감싸는 계층을 하나 둔다. CUB는 예외 대신 cudaError_t를 돌려준다.
CUB 첫 호출의 nullptr 크기를 묻는 첫 호출에서 임시 포인터를 nullptr로 넘겨야 크기만 계산하고 끝난다. 이미 할당한 포인터를 넘기면서 크기 변수가 0이면, 실제 실행으로 처리되어 오류가 난다.
Toolkit 버전과 헤더 버전 CUB, Thrust는 Toolkit에 포함된 버전을 쓰는 것이 기본이다. GitHub의 최신 CCCL을 따로 가져와 섞으면 Toolkit 내장 헤더와 충돌할 수 있다. 버전을 올려야 하면 include 경로 순서를 명확히 하고 한 가지 버전만 보이게 한다.
