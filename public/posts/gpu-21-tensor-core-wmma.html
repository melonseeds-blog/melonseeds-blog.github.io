Tensor Core란

지금까지 짠 커널의 덧셈, 곱셈은 모두 CUDA core가 처리했다. CUDA core는 스레드 하나가 명령 하나로 값 하나를 계산한다(FMA라면 a × b + c 하나). Tensor Core는 행렬 곱만 전문으로 하는 별도 연산기로, 명령 하나로 작은 행렬 곱 전체를 계산한다.

항목CUDA coreTensor Core
한 번에 하는 일스칼라 FMA 1개: d = a × b + c작은 행렬 곱 누적: D = A × B + C
실행 단위스레드워프 (32개 스레드가 함께 한 행렬 곱을 맡음)
주 데이터 형식FP32, FP64, INT32FP16, BF16, TF32, INT8, FP8 등 낮은 정밀도 입력 + 높은 정밀도 누적
처리량기준같은 GPU에서 행렬 곱 처리량이 수 배에서 수십 배
할 수 있는 일모든 계산행렬 곱(과 행렬 곱으로 바꿀 수 있는 계산)뿐

딥러닝 신경망의 계산은 대부분이 행렬 곱이다. 완전 연결 층은 그 자체로 행렬 곱이고, 컨볼루션 층도 행렬 곱으로 바꿔서 계산한다(아래 im2col). 그래서 TensorRT(11편)로 FP16, INT8 추론을 하면 속도가 크게 오르는 이유의 대부분이 Tensor Core다.

GTX 10xx(Pascal) 이전 GPU에는 Tensor Core가 없다. 사용하는 GPU의 compute capability는 deviceQuery나 cudaGetDeviceProperties로 확인한다(1편).

낮은 정밀도로 계산해도 되는 이유

Tensor Core는 입력을 FP16이나 INT8처럼 낮은 정밀도로 받는다. 그런데 결과를 더해 나가는 누적(accumulate)은 FP32 같은 높은 정밀도로 할 수 있다. 이것이 핵심이다.

형식비트 (부호/지수/가수)표현 범위특징
FP321 / 8 / 23약 ±3.4×1038기준
TF321 / 8 / 10 (19비트만 사용)FP32와 같음FP32 데이터를 그대로 넣으면 가수만 줄여 계산. 코드 변경 없이 Ampere+ Tensor Core 사용
FP161 / 5 / 10약 ±65504범위가 좁아서 큰 값은 넘침(overflow) 주의
BF161 / 8 / 7FP32와 같음정밀도는 낮지만 범위가 넓어 학습에서 안정적
INT8정수 8비트-128 ~ 127스케일 값과 함께 사용(양자화). 보정(calibration) 필요

신경망 가중치와 활성값은 원래 잡음이 섞인 근사값이라, 곱하는 입력의 정밀도를 낮춰도 최종 정확도가 거의 변하지 않는 경우가 많다. 반면 수천 개를 더하는 누적 단계는 오차가 쌓이므로 FP32로 한다. 이 조합이 "mixed precision"이다.

영상 계측 계산에 무조건 쓰지 않기 신경망과 달리 캘리브레이션, 정밀 계측처럼 값 자체가 결과인 계산은 FP16이나 TF32로 바꾸면 정밀도 손실이 그대로 결과 오차가 된다. Tensor Core는 정확도 영향을 측정해서 허용 범위일 때만 쓴다.

WMMA API

CUDA C++에서 Tensor Core를 직접 쓰는 가장 쉬운 방법이 WMMA(Warp Matrix Multiply-Accumulate) API다. 이름 그대로 워프 단위로 동작한다. 워프의 32개 스레드가 함께 16×16 같은 작은 행렬 조각(fragment)을 나눠 들고, 함께 곱한다.

#include <mma.h>
using namespace nvcuda;

// one warp computes one 16x16 tile:  C = A(16x16) * B(16x16) + C
__global__ void WmmaTile(const half* A, const half* B, float* C)
{
    // fragments: the warp holds the tiles in registers, spread over 32 threads
    wmma::fragment<wmma::matrix_a,    16, 16, 16, half, wmma::row_major> a;
    wmma::fragment<wmma::matrix_b,    16, 16, 16, half, wmma::col_major> b;
    wmma::fragment<wmma::accumulator, 16, 16, 16, float>                 c;

    wmma::fill_fragment(c, 0.0f);
    wmma::load_matrix_sync(a, A, 16);          // leading dimension = 16
    wmma::load_matrix_sync(b, B, 16);
    wmma::mma_sync(c, a, b, c);                // Tensor Core instruction(s)
    wmma::store_matrix_sync(C, c, 16, wmma::mem_row_major);
}

WmmaTile<<<1, 32>>>(d_A, d_B, d_C);           // exactly one warp; compile with -arch=sm_70 or newer
요소의미
fragment<역할, M, N, K, 타입, 배치>워프가 레지스터에 나눠 든 행렬 조각. 역할은 matrix_a, matrix_b, accumulator
M, N, KA는 M×K, B는 K×N, C는 M×N. FP16은 16×16×16이 기본
row_major / col_major메모리에 행 순서로 저장됐는지 열 순서로 저장됐는지
load_matrix_sync(frag, ptr, ldm)메모리에서 조각을 읽음. ldm은 한 행(또는 열)의 원소 간격
mma_sync(d, a, b, c)d = a × b + c
_sync워프의 32개 스레드가 모두 같이 호출해야 함 (15편의 shuffle과 같은 규칙)
fragment 안의 원소 배치는 알 수 없음 fragment의 어느 원소가 어느 스레드의 레지스터에 있는지는 공개된 규칙이 아니고 아키텍처마다 다를 수 있다. 원소별로 같은 연산(예: 모든 원소에 스케일 곱하기, ReLU)은 for (int i = 0; i < c.num_elements; ++i) c.x[i] *= s;처럼 할 수 있지만, 특정 행렬 위치의 값을 꺼내려면 메모리에 store한 뒤 읽는다.

WMMA로 행렬 곱 전체 계산하기

큰 행렬 곱 C(M×N) = A(M×K) × B(K×N)는 출력을 16×16 타일로 나누고, 워프 하나가 타일 하나를 맡는다. 각 워프는 K 방향으로 16씩 이동하며 A의 행 조각과 B의 열 조각을 곱해 누적한다. 6편 타일링 행렬 곱과 같은 구조이고, 안쪽 곱셈만 Tensor Core가 한다.

// C (M x N, float, row-major) = A (M x K, half, row-major) * B (K x N, half, col-major)
// M, N, K must be multiples of 16 in this simple version.
__global__ void WmmaGemm(const half* A, const half* B, float* C, int M, int N, int K)
{
    // which 16x16 tile of C does this warp own?
    int warpM = (blockIdx.x * blockDim.x + threadIdx.x) / 32;   // tile row
    int warpN =  blockIdx.y * blockDim.y + threadIdx.y;         // tile column
    if (warpM * 16 >= M || warpN * 16 >= N) return;             // whole warp exits together

    wmma::fragment<wmma::matrix_a, 16, 16, 16, half, wmma::row_major> a;
    wmma::fragment<wmma::matrix_b, 16, 16, 16, half, wmma::col_major> b;
    wmma::fragment<wmma::accumulator, 16, 16, 16, float> acc;
    wmma::fill_fragment(acc, 0.0f);

    for (int k = 0; k < K; k += 16)
    {
        const half* tileA = A + (warpM * 16) * K + k;     // row-major: row * K + col
        const half* tileB = B + (warpN * 16) * K + k;     // col-major: col * K + row
        wmma::load_matrix_sync(a, tileA, K);
        wmma::load_matrix_sync(b, tileB, K);
        wmma::mma_sync(acc, a, b, acc);                   // accumulate in FP32
    }

    float* tileC = C + (warpM * 16) * N + warpN * 16;
    wmma::store_matrix_sync(tileC, acc, N, wmma::mem_row_major);
}

// 128 threads in x = 4 warps -> 4 tile rows per block; 4 tile columns per block in y
dim3 block(128, 4);
dim3 grid((M / 16 + 3) / 4, (N / 16 + 3) / 4);
WmmaGemm<<<grid, block>>>(d_A, d_B, d_C, M, N, K);

이 커널은 원리를 보여 주는 최소 형태다. 실제로 빠른 GEMM은 여기에 다음을 더한다.

추가 기법효과
shared memory에 A, B 블록 타일을 올려 여러 워프가 공유 (6편)global 읽기 횟수 감소
워프 하나가 타일 여러 개(예: 2×4) 계산읽은 조각 재사용, 레지스터 활용
다음 K 조각을 미리 비동기로 읽기 (cp.async, Hopper TMA)메모리 대기 시간 숨기기
shared memory 배치 조정뱅크 충돌 제거

이것들을 모두 직접 하기는 어렵다. 그래서 실무에서는 다음 절의 라이브러리를 쓴다.

실무에서는 라이브러리가 Tensor Core를 쓴다

WMMA를 직접 쓰는 경우는 많지 않다. 대부분은 아래 라이브러리가 알아서 Tensor Core 커널을 고른다. 개발자가 할 일은 Tensor Core를 쓸 수 있는 조건을 맞춰 주는 것이다.

라이브러리역할
cuBLAS, cuBLASLt행렬 곱. cublasGemmEx로 입력, 출력, 계산 형식을 지정
cuDNN컨볼루션, 정규화 등 신경망 연산
TensorRT추론 엔진. FP16, INT8 모드에서 Tensor Core 커널을 자동 선택 (11편)
CUTLASSNVIDIA의 오픈소스 C++ 템플릿 라이브러리. 직접 GEMM, 컨볼루션 커널을 조립할 때. 최신 기능(Hopper wgmma, TMA)까지 다룸
// cuBLAS: FP16 inputs, FP32 accumulate and output -> Tensor Core path
// cuBLAS is column-major; this computes C(MxN) = A(MxK) * B(KxN)
float alpha = 1.0f, beta = 0.0f;
cublasGemmEx(handle, CUBLAS_OP_N, CUBLAS_OP_N, M, N, K,
             &alpha,
             d_A, CUDA_R_16F, M,
             d_B, CUDA_R_16F, K,
             &beta,
             d_C, CUDA_R_32F, M,
             CUBLAS_COMPUTE_32F,             // accumulate in FP32
             CUBLAS_GEMM_DEFAULT);

// FP32 data, allow TF32 Tensor Cores (Ampere+): faster, ~10-bit mantissa products
cublasSetMathMode(handle, CUBLAS_TF32_TENSOR_OP_MATH);

Tensor Core를 쓰게 하는 조건

조건설명
형식FP16, BF16, INT8 등 Tensor Core 형식이거나, FP32라면 TF32 허용 설정
차원이 배수NVIDIA 성능 가이드는 행렬 차원(신경망이면 채널 수, 배치 크기)을 FP16은 8의 배수, INT8은 16의 배수로 맞추길 권장. 어긋나면 덧붙이기(padding)나 다른 커널을 써서 효율이 떨어짐
메모리 정렬포인터와 leading dimension이 정렬되어 있어야 벡터 단위로 읽을 수 있음
TensorRT 설정빌드할 때 FP16 또는 INT8 플래그를 켜야 해당 정밀도 커널을 후보에 넣음

컨볼루션이 행렬 곱이 되는 원리

비전 신경망의 대부분은 컨볼루션 층인데, 어떻게 행렬 곱 전용 하드웨어를 쓸 수 있을까. 컨볼루션을 행렬 곱 형태로 펼치는 im2col 변환 덕분이다.

im2col. 컨볼루션 창마다 값을 한 열로 펼치면, 컨볼루션 전체가 (필터 행렬) × (펼친 입력 행렬)이라는 행렬 곱 하나가 된다

입력 채널 64, 출력 채널 128, 3×3 필터, 출력 크기 160×160이면 행렬 곱 크기는 (128 × 576) × (576 × 25,600)이다. Tensor Core가 좋아하는 크고 규칙적인 행렬 곱이다. 실제 cuDNN과 TensorRT는 펼친 행렬을 메모리에 다 만들지 않고, 행렬 곱 커널이 타일을 읽을 때 그 자리에서 펼치는 방식(implicit GEMM)을 쓴다. 채널 수를 8의 배수로 맞추라는 권장이 여기서 나온다. 채널 수가 행렬의 K 차원이 되기 때문이다.

Tensor Core를 실제로 쓰는지 확인

설정을 맞췄다고 해서 항상 Tensor Core 커널이 선택되는 것은 아니다. 프로파일러로 확인한다(8편).

도구보는 곳
Nsight Systems커널 이름. cuBLAS, cuDNN, TensorRT의 Tensor Core 커널은 이름에 hmma, imma, xmma, s16816, i8816 같은 말이 들어가는 경우가 많음
Nsight ComputeCompute Workload Analysis 섹션의 Tensor 파이프 사용률. 0%면 Tensor Core를 쓰지 않는 커널

nsys profile -o infer ./my_infer

# tensor pipe utilization of one kernel
ncu --section ComputeWorkloadAnalysis -k regex:gemm ./my_app

WMMA 아래의 단계

WMMA는 쓰기 쉬운 대신, 최신 GPU의 성능을 끝까지 끌어내지는 못한다. 그 아래에는 더 낮은 수준의 방법이 있다.

수준내용
WMMA (C++ API)워프 단위, fragment 배치 숨김. 쉬움
PTX mma.sync워프 단위, 레지스터 배치가 공개됨. 더 다양한 크기, 형식. 인라인 어셈블리로 사용
PTX wgmma (Hopper)워프 4개(warpgroup) 단위, shared memory에서 바로 읽음, 비동기 실행
CUTLASS / CuTe위 명령들을 C++ 템플릿으로 감싼 라이브러리. 직접 작성 대신 이것을 쓰는 것이 일반적

흔한 함정

FP16 넘침 FP16 최댓값은 65504다. 0~255 픽셀 값을 정규화 없이 FP16으로 바꾸고 큰 필터로 곱해 더하면 중간값이 쉽게 넘쳐 inf가 된다. 누적은 FP32로 하고, 입력은 0~1이나 평균 0 근처로 정규화한다.
WMMA의 크기, 정렬 조건 load_matrix_sync의 포인터는 256비트(32바이트) 정렬이어야 하고, leading dimension은 half라면 8의 배수, float라면 4의 배수여야 한다. 위 단순 커널은 M, N, K가 16의 배수라고 가정하므로, 그렇지 않으면 0으로 덧붙여 크기를 맞춘다.
워프 일부만 WMMA 호출 WMMA 함수는 워프의 32개 스레드가 모두 같이 호출해야 한다. 범위 검사로 일부 스레드만 return하면 결과가 정의되지 않는다. 위 커널처럼 워프 단위로 판단해서 워프 전체가 함께 빠지게 한다.
아키텍처 플래그 WMMA 코드는 -arch=sm_70 이상으로 컴파일해야 한다. 기본값이 더 낮은 아키텍처로 잡혀 있는 프로젝트에서는 mma.h의 기능이 비활성화되어 컴파일 오류가 난다. Visual Studio에서는 CUDA C/C++ → Device → Code Generation에서 설정한다.
