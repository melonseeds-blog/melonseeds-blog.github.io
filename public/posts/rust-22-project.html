작은 프로젝트 — 이미지 처리 맛보기

2026-06-25 약 8분 분량 Rust 시리즈
이 편에서 배우는 것 지금까지 익힌 문법을 손에 잡히는 결과물로 묶어 본다. image 크레이트로 실제 이미지 파일을 읽고, 픽셀을 만지고, 새 파일로 저장한다. 그레이스케일 변환을 직접 픽셀 단위로 구현해 보며 Rust의 소유권·빌림이 이미지 버퍼 같은 큰 데이터에서 어떻게 작동하는지 본다. C++에서 OpenCV를 래핑해 본 경험이 있다면, 같은 작업을 Rust 생태계에서는 어떻게 다루는지 비교하며 읽는다.

왜 이미지 처리를 골랐나

문법을 따로 배울 때는 추상적이지만, 결과가 눈으로 보이면 감각이 빨리 붙는다. 이미지 처리는 그 점에서 첫 프로젝트로 좋다. 입력과 출력이 모두 파일로 남아 무엇이 바뀌었는지 바로 확인할 수 있고, 픽셀 버퍼는 "큰 데이터를 누가 소유하고 누가 빌리는가"라는 Rust의 핵심 주제를 자연스럽게 건드린다.

이 시리즈에서 다룬 것 — 변수와 가변성, 함수, 소유권과 빌림, 그리고 크레이트 사용 — 이 한 프로그램 안에서 어떻게 맞물리는지 본다. 거창한 알고리즘은 없다. 이미지를 읽어 회색조로 바꾸고 다시 저장하는, 끝까지 완성되는 작은 프로그램 하나면 충분하다.

C++ 경험자라면 OpenCV를 직접 쓰거나 래핑해 본 적이 있다면 cv::imread → cv::cvtColor → cv::imwrite의 흐름이 익숙할 것이다. Rust의 image 크레이트도 같은 골격을 따른다. 큰 차이는 두 가지다. 첫째, 메모리 해제를 직접 신경 쓰지 않는다 — 버퍼는 소유자가 스코프를 벗어날 때 자동으로 정리된다. 둘째, 실패할 수 있는 호출은 예외가 아니라 Result로 돌아와, 컴파일러가 "에러 처리를 했는지"를 강제한다.

Cargo로 크레이트 추가하기

Rust의 외부 라이브러리는 크레이트(crate)라고 부르고, 패키지 관리는 Cargo가 맡는다. C++에서 vcpkg나 CMake로 OpenCV를 끌어오는 단계를, 여기서는 명령 한 줄로 끝낸다. 프로젝트 폴더에서 다음을 실행한다.

# 새 프로젝트를 만든다
cargo new image_demo
cd image_demo

# image 크레이트를 의존성으로 추가한다
cargo add image

cargo add는 Cargo.toml의 [dependencies]에 항목을 적어 준다. 직접 손으로 적어도 결과는 같다.

# Cargo.toml
[package]
name = "image_demo"
version = "0.1.0"
edition = "2021"

[dependencies]
image = "0.25"

버전 문자열 "0.25"는 "0.25 이상, 0.26 미만"을 뜻한다. 처음 cargo build를 돌리면 Cargo가 크레이트를 내려받아 빌드하고, 정확한 버전을 Cargo.lock에 고정한다. 협업할 때 같은 버전이 보장되는 구조다.

C++과 이렇게 다르다 — 의존성 추가 OpenCV를 붙이려면 보통 라이브러리 설치, include 경로와 link 라이브러리 설정, 플랫폼별 빌드 차이까지 손봐야 한다. Cargo에서는 cargo add image 한 줄이면 다운로드·빌드·링크가 한 번에 끝나고, 버전 잠금까지 자동이다. 헤더/라이브러리 경로를 수동으로 맞추는 작업이 사라진다.

이미지 읽기·변환·저장

먼저 가장 짧은 완성 프로그램을 본다. 이미지를 열고, 크레이트가 제공하는 변환을 써서 회색조로 바꾸고, 새 파일로 저장한다. 입력 파일 input.png이 프로젝트 폴더에 있다고 가정한다.

use image::ImageReader;

fn main() {
    // 파일을 열고 디코딩한다. 두 단계 모두 실패할 수 있어 ? 로 에러를 위로 넘긴다.
    let img = ImageReader::open("input.png")
        .expect("파일을 열 수 없다")
        .decode()
        .expect("이미지를 디코딩할 수 없다");

    // 크레이트가 제공하는 그레이스케일 변환. 새 버퍼를 돌려준다.
    let gray = img.grayscale();

    // 확장자(.png)를 보고 인코더를 알아서 고른다.
    gray.save("output_gray.png").expect("저장에 실패했다");

    println!("output_gray.png 로 저장했다");
}

여기서 img는 DynamicImage 타입이다. 어떤 픽셀 포맷(8비트 RGB, RGBA, 그레이스케일 등)이든 하나로 감싸 주는 열거형이라, 입력이 무엇이든 동일한 코드로 다룰 수 있다. grayscale()은 원본을 바꾸지 않고 새 이미지를 반환한다 — 원본 img는 그대로 살아 있다.

픽셀에 직접 접근하기

크레이트가 주는 변환만 쓰면 픽셀을 만질 일이 없다. 직접 처리하려면 RGB 버퍼로 바꿔 픽셀을 순회한다. 아래는 모든 픽셀의 빨강 채널 값만 출력하는 예다.

use image::{ImageReader, GenericImageView};

fn main() {
    let img = ImageReader::open("input.png")
        .expect("열기 실패")
        .decode()
        .expect("디코딩 실패");

    // 너비/높이는 (u32, u32) 튜플로 한 번에 받는다.
    let (width, height) = img.dimensions();
    println!("크기: {} x {}", width, height);

    // to_rgb8 은 8비트 RGB 버퍼(RgbImage)를 새로 만든다.
    let rgb = img.to_rgb8();

    // get_pixel 은 픽셀을 빌려서 읽는다. 채널은 [r, g, b] 배열이다.
    let first = rgb.get_pixel(0, 0);
    let [r, g, b] = first.0;
    println!("(0,0) 픽셀 = R:{} G:{} B:{}", r, g, b);
}

get_pixel(x, y)는 픽셀을 값으로 복사해 돌려준다. 좌표가 범위를 벗어나면 패닉이 나므로, 순회할 때는 0..width, 0..height 범위 안에서만 접근한다. 다음 절에서 이 패턴을 써서 직접 필터를 만든다.

그레이스케일 필터 직접 만들기

크레이트의 grayscale()에 의존하지 않고, 픽셀마다 직접 밝기를 계산해 본다. 사람 눈은 초록에 가장 민감하므로 채널마다 가중치를 다르게 주는 게 표준 방식이다. 여기서는 널리 쓰이는 가중치(R 0.299, G 0.587, B 0.114)를 따른다.

use image::{ImageReader, GenericImageView, GrayImage, Luma};

fn main() {
    let img = ImageReader::open("input.png")
        .expect("열기 실패")
        .decode()
        .expect("디코딩 실패");

    let (width, height) = img.dimensions();
    let rgb = img.to_rgb8();

    // 같은 크기의 1채널(그레이) 버퍼를 0으로 채워 새로 만든다.
    let mut gray = GrayImage::new(width, height);

    for y in 0..height {
        for x in 0..width {
            let [r, g, b] = rgb.get_pixel(x, y).0;

            // u8 끼리 곱하면 넘치므로 f32 로 올려 계산한다.
            let luma = 0.299 * r as f32
                     + 0.587 * g as f32
                     + 0.114 * b as f32;

            // 다시 u8 로 내린다. 0~255 안에 들어오는 값이라 안전하다.
            gray.put_pixel(x, y, Luma([luma as u8]));
        }
    }

    gray.save("output_manual.png").expect("저장 실패");
    println!("직접 만든 그레이스케일을 저장했다");
}

핵심은 두 버퍼의 역할이 다르다는 점이다. rgb는 읽기만 하므로 불변으로 두고, gray는 픽셀을 채워 넣어야 하므로 mut으로 선언했다. put_pixel이 gray를 가변으로 빌리는 동안에도 rgb는 따로 불변으로 빌려 읽을 수 있다 — 서로 다른 값이라 빌림 규칙이 충돌하지 않는다.

함수로 분리하기

변환 로직을 함수로 떼어 내면 재사용과 테스트가 쉬워진다. 입력 이미지는 빌려서(&) 받고, 결과는 새로 만들어 돌려준다. 원본을 건드리지 않는 설계다.

use image::{RgbImage, GrayImage, Luma};

// 입력을 불변으로 빌리고(&), 새 그레이 이미지를 소유권째 돌려준다.
fn to_grayscale(src: &RgbImage) -> GrayImage {
    let (width, height) = src.dimensions();
    let mut out = GrayImage::new(width, height);

    for y in 0..height {
        for x in 0..width {
            let [r, g, b] = src.get_pixel(x, y).0;
            let luma = 0.299 * r as f32
                     + 0.587 * g as f32
                     + 0.114 * b as f32;
            out.put_pixel(x, y, Luma([luma as u8]));
        }
    }

    out // 마지막 식이 반환값이다. out 의 소유권이 호출자에게 넘어간다.
}

호출하는 쪽에서는 let gray = to_grayscale(&rgb); 처럼 쓴다. &rgb로 빌려 줬으니 함수가 끝나도 rgb는 호출자 손에 그대로 남아 다른 처리에 또 쓸 수 있다. 반환된 out은 소유권이 통째로 넘어와 gray가 받는다. 복사가 아니라 이동(move)이라 큰 버퍼를 돌려줘도 비용이 들지 않는다.

C++ 대조 — 누가 버퍼를 책임지나 C++에서 cv::Mat을 함수가 반환하면 이동/복사·참조 카운트가 어떻게 도는지 머릿속으로 추적해야 한다. Rust에서는 시그니처만 봐도 결판이 난다. &RgbImage는 "빌려서 읽기만 한다", -> GrayImage는 "새 버퍼를 소유권째 넘긴다"는 약속이다. 댕글링 참조나 이중 해제는 컴파일 단계에서 막힌다.

시리즈 마무리와 다음 방향

이 작은 프로그램 하나에 시리즈에서 다룬 조각들이 모두 들어 있다. 변수의 가변성(let vs let mut), 함수로의 분리, 소유권과 빌림(&와 이동), 그리고 외부 크레이트를 Cargo로 끌어와 쓰는 흐름이다. 문법을 따로 외울 때와 달리, 끝까지 돌아가는 결과물 안에서 보면 각 규칙이 왜 그렇게 생겼는지 감이 잡힌다.

여기서 더 나아간다면

  • 다른 필터 추가 — 밝기 조절, 반전, 임계값(threshold) 이진화는 모두 픽셀 한 개씩 처리하는 같은 골격으로 만들 수 있다. 위 to_grayscale를 본떠 함수를 하나 더 써 본다.
  • 에러 처리 다듬기 — 예제는 expect로 단순화했지만, 실제 도구라면 main이 Result를 반환하게 바꾸고 ? 연산자로 에러를 위로 전파하는 방식이 깔끔하다.
  • 테스트 작성 — to_grayscale처럼 입력을 빌리고 결과를 돌려주는 순수 함수는 테스트하기 쉽다. 작은 이미지를 만들어 예상 픽셀 값과 비교해 본다.
  • 표준 라이브러리와 친해지기 — Option, Result, 이터레이터는 어떤 Rust 코드에서도 다시 만난다. The Book의 해당 장을 한 번 더 읽으면 다음 프로젝트가 수월해진다.
크레이트 버전과 API는 바뀐다 image 크레이트는 버전에 따라 타입 이름이나 함수 시그니처가 달라질 수 있다. 예제는 0.25 계열을 기준으로 작성했다. 다른 버전을 쓴다면 docs.rs의 해당 버전 문서에서 ImageReader·DynamicImage 같은 타입을 한 번 확인하고 맞춘다.

여기까지가 이 시리즈의 마무리다. 문법은 도구일 뿐이고, 손에 익는 건 결국 작은 프로젝트를 끝까지 완성해 보는 과정에서다. 이 이미지 변환기를 출발점 삼아, 마음에 걸리던 작은 도구 하나를 Rust로 직접 만들어 보길 권한다.
