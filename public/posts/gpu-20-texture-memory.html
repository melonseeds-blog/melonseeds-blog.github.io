Texture 하드웨어가 해 주는 일

GPU는 원래 3D 그래픽을 위해 만들어졌고, 그래픽에서는 물체 표면에 그림(texture)을 입힐 때 "좌표 (12.3, 45.7) 위치의 색"처럼 픽셀 사이 값을 끊임없이 읽는다. 이 일을 빠르게 하려고 GPU에는 texture unit이라는 전용 하드웨어가 있다. CUDA에서도 이 하드웨어를 쓸 수 있고, 영상 처리에서는 특히 쓸모가 많다.

기능설명영상 처리에서 쓰는 곳
하드웨어 보간소수 좌표를 주면 주변 4픽셀을 bilinear로 섞은 값을 돌려줌. 계산 명령이 거의 들지 않음리사이즈, 회전, 왜곡 보정(remap), 서브픽셀 샘플링
경계 처리영상 밖 좌표를 읽으면 clamp, wrap, mirror, border 규칙대로 값을 돌려줌필터 가장자리 처리를 코드 없이
2D 지역성 캐시위아래 이웃처럼 2차원으로 가까운 데이터를 잘 캐시함회전처럼 접근 방향이 행과 맞지 않는 처리
자동 형 변환8비트 정수 픽셀을 읽으면서 0.0~1.0 float로 바꿔 줌정규화 단계를 생략

요약하면 texture는 "읽기 전용 영상을 소수 좌표로 읽는 일"에 특화된 경로다. 일반 배열 읽기로 같은 일을 하려면 좌표 내림, 이웃 4개 읽기, 가중치 계산, 경계 검사를 모두 직접 써야 한다.

texture object 만들기

CUDA에서 texture는 cudaTextureObject_t라는 핸들로 다룬다. 만들 때 두 가지를 정한다. 무엇을 읽을지(resource)와 어떻게 읽을지(texture description)다.

texture reference는 쓰지 않음 오래된 자료에는 전역 변수로 texture<float, 2> texRef;를 선언하고 cudaBindTexture로 묶는 방식(texture reference)이 나온다. 이 방식은 오래전에 사용 중단되었고 CUDA 12에서 제거되었다. 지금은 texture object만 쓴다. 
// source image: 8-bit gray, width x height, stored with a pitch
unsigned char* d_img;
size_t pitch;
cudaMallocPitch(&d_img, &pitch, width, height);
cudaMemcpy2D(d_img, pitch, h_img, width, width, height, cudaMemcpyHostToDevice);

// 1) WHAT to read: a pitched 2D buffer
cudaResourceDesc res = {};
res.resType = cudaResourceTypePitch2D;
res.res.pitch2D.devPtr       = d_img;
res.res.pitch2D.desc         = cudaCreateChannelDesc<unsigned char>();
res.res.pitch2D.width        = width;
res.res.pitch2D.height       = height;
res.res.pitch2D.pitchInBytes = pitch;

// 2) HOW to read it
cudaTextureDesc td = {};
td.addressMode[0]   = cudaAddressModeClamp;        // x outside -> nearest edge pixel
td.addressMode[1]   = cudaAddressModeClamp;        // y outside -> nearest edge pixel
td.filterMode       = cudaFilterModeLinear;        // hardware bilinear interpolation
td.readMode         = cudaReadModeNormalizedFloat; // uchar 0..255 -> float 0.0..1.0
td.normalizedCoords = 0;                           // coordinates in pixels, not 0..1

cudaTextureObject_t tex = 0;
cudaCreateTextureObject(&tex, &res, &td, nullptr);

// ... use tex in kernels ...

cudaDestroyTextureObject(tex);                     // the buffer itself is still yours to free

메모리 종류 두 가지

resource 종류메모리장점단점
cudaResourceTypePitch2DcudaMallocPitch로 잡은 일반 메모리다른 커널이 쓴 결과를 복사 없이 바로 texture로 읽을 수 있음캐시 효율이 cudaArray보다 조금 떨어질 수 있음
cudaResourceTypeArraycudaMallocArray로 잡은 cudaArraytexture 접근에 맞게 내부 배치(타일 형태)가 최적화됨일반 포인터로 접근 불가. 채우려면 cudaMemcpy2DToArray 복사가 필요

카메라 영상을 받아 전처리 커널을 거친 뒤 그 결과를 보간해서 읽는 파이프라인이라면, 중간 결과를 그대로 쓸 수 있는 Pitch2D가 대개 편하다. 보정 맵, LUT처럼 한 번 올려 두고 계속 읽는 데이터는 cudaArray가 맞다.

좌표 규칙과 보간 계산

texture를 처음 쓸 때 가장 많이 틀리는 부분이 좌표다. texture에서 픽셀 (i, j)의 중심은 정수 좌표가 아니라 (i + 0.5, j + 0.5)다.

bilinear 보간. 좌표에서 0.5를 뺀 뒤 정수부로 왼쪽 위 픽셀을, 소수부로 가중치를 정한다

그래서 원본 픽셀 (x, y)를 그대로 읽고 싶으면 tex2D<float>(tex, x + 0.5f, y + 0.5f)로 읽어야 한다. +0.5를 빼먹으면 모든 픽셀이 반 픽셀씩 왼쪽 위로 밀린 값, 즉 이웃과 섞인 값이 나온다. 결과 영상이 살짝 흐리고 반 픽셀 이동한 것처럼 보이면 이 실수를 의심한다.

하드웨어 보간의 정밀도

texture 보간은 빠른 대신 정밀도에 한계가 있다. CUDA 프로그래밍 가이드에 따르면 보간 가중치(α, β)는 소수부 8비트의 고정소수점으로 계산된다. 즉 픽셀 사이를 256단계로만 나눈다. 1/256 픽셀보다 작은 위치 차이는 결과에 반영되지 않는다.

용도하드웨어 보간
표시용 리사이즈, 회전, 일반 전처리충분함
렌즈 왜곡 보정 remap대부분 충분함. 계측 정확도 요구가 높으면 비교 확인
서브픽셀 정밀 계측 (에지 위치, 정합)부족할 수 있음. 1/100 픽셀 단위 결과가 필요하면 point 모드로 4픽셀을 읽고 float로 직접 보간
// software bilinear with full float weights (texture in POINT mode, element type float)
__device__ float BilinearPrecise(cudaTextureObject_t texPoint, float x, float y)
{
    float xb = x - 0.5f, yb = y - 0.5f;
    float fx = floorf(xb), fy = floorf(yb);
    float a = xb - fx, b = yb - fy;                     // full 24-bit float weights
    float t00 = tex2D<float>(texPoint, fx + 0.5f, fy + 0.5f);
    float t10 = tex2D<float>(texPoint, fx + 1.5f, fy + 0.5f);
    float t01 = tex2D<float>(texPoint, fx + 0.5f, fy + 1.5f);
    float t11 = tex2D<float>(texPoint, fx + 1.5f, fy + 1.5f);
    return (1 - a) * (1 - b) * t00 + a * (1 - b) * t10 + (1 - a) * b * t01 + a * b * t11;
}

읽기 옵션 정리

경계 처리 (addressMode)

모드영상 밖 좌표를 읽으면비슷한 OpenCV 옵션
cudaAddressModeClamp가장 가까운 가장자리 픽셀 값BORDER_REPLICATE
cudaAddressModeBorder0BORDER_CONSTANT (값 0)
cudaAddressModeWrap반대쪽에서 이어짐 (반복)BORDER_WRAP
cudaAddressModeMirror경계에서 거울처럼 뒤집힘BORDER_REFLECT 계열

Wrap과 Mirror는 정규화 좌표(normalizedCoords = 1, 좌표 범위 0~1)에서만 동작한다. 픽셀 좌표를 쓸 때는 Clamp나 Border를 쓴다.

필터와 읽기 모드

옵션값결과
filterModecudaFilterModePoint가장 가까운 픽셀 하나 (보간 없음)
cudaFilterModeLinearbilinear 보간. float로 읽을 때만 가능
readModecudaReadModeElementType저장된 타입 그대로 (uchar면 uchar)
cudaReadModeNormalizedFloat8, 16비트 정수를 0.0~1.0 float로 (부호 있으면 -1.0~1.0)
8비트 영상에 Linear 필터를 쓰려면 unsigned char 영상에 cudaFilterModeLinear를 쓰려면 readMode를 cudaReadModeNormalizedFloat로 해야 한다. 결과가 0~1이므로 원래 범위가 필요하면 255를 곱한다. ElementType 모드로 정수 영상을 Linear로 읽으려 하면 texture 생성이 실패한다.

예제 - 리사이즈와 회전

texture를 쓰면 리사이즈 커널은 출력 픽셀마다 원본 좌표를 계산해서 한 번 읽는 것이 전부다.

__global__ void ResizeBilinear(cudaTextureObject_t src, unsigned char* dst, size_t dstPitch,
                               int dstW, int dstH, float scaleX, float scaleY)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x >= dstW || y >= dstH) return;

    // map the CENTER of the output pixel to the source image (same rule as cv::resize)
    float sx = (x + 0.5f) * scaleX;          // already includes the +0.5 texel offset
    float sy = (y + 0.5f) * scaleY;

    float v = tex2D<float>(src, sx, sy);     // 0..1 (normalized float read)
    dst[y * dstPitch + x] = (unsigned char)(v * 255.0f + 0.5f);
}

// scale = srcSize / dstSize
dim3 block(32, 8), grid((dstW + 31) / 32, (dstH + 7) / 8);
ResizeBilinear<<<grid, block, 0, stream>>>(tex, d_dst, dstPitch, dstW, dstH,
                                           (float)srcW / dstW, (float)srcH / dstH);

회전이나 어파인 변환도 같은 구조다. 출력 픽셀 좌표에 역변환 행렬을 곱해 원본 좌표를 얻고 tex2D로 읽는다. 원본 바깥 좌표는 addressMode가 알아서 처리한다.

// inverse affine: src = M * (dst + 0.5) ; M is 2x3, row-major, passed by value
struct Affine { float m00, m01, m02, m10, m11, m12; };

__global__ void WarpAffine(cudaTextureObject_t src, float* dst, int w, int h, Affine inv)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x >= w || y >= h) return;
    float px = x + 0.5f, py = y + 0.5f;
    float sx = inv.m00 * px + inv.m01 * py + inv.m02;
    float sy = inv.m10 * px + inv.m11 * py + inv.m12;
    dst[y * w + x] = tex2D<float>(src, sx, sy);   // outside -> Border mode gives 0
}

예제 - 렌즈 왜곡 보정 (remap)

렌즈 왜곡 보정은 미리 계산해 둔 좌표 맵(출력 픽셀마다 원본의 어느 소수 좌표를 읽을지)을 따라 원본을 읽는 처리다. OpenCV의 initUndistortRectifyMap으로 맵을 만들고 remap으로 적용하는 구조와 같다. 맵은 보정이 바뀌지 않는 한 고정이므로 GPU에 한 번 올려 두고, 영상만 texture로 매 프레임 바꿔 읽는다.

// mapX/mapY: float source coordinates for every output pixel (pixel units, like cv::remap)
__global__ void Remap(cudaTextureObject_t src, const float* mapX, const float* mapY,
                      unsigned char* dst, int w, int h)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x >= w || y >= h) return;
    int i = y * w + x;
    // cv::remap treats integer map values as pixel centers -> add 0.5 for texture space
    float v = tex2D<float>(src, mapX[i] + 0.5f, mapY[i] + 0.5f);
    dst[i] = (unsigned char)(v * 255.0f + 0.5f);
}

remap은 출력 픽셀마다 원본에서 읽는 위치가 불규칙하게 흩어진다. 왜곡이 큰 가장자리일수록 워프 안 스레드들이 읽는 위치가 행 방향으로 나란하지 않다. 이런 접근에서 texture의 2D 캐시와 하드웨어 보간이 가장 효과를 본다.

surface - cudaArray에 쓰기

texture는 읽기 전용이다. cudaArray에 커널이 직접 써야 하면 surface object를 쓴다. cudaArray를 만들 때 cudaArraySurfaceLoadStore 플래그가 필요하다.

cudaChannelFormatDesc fmt = cudaCreateChannelDesc<float>();
cudaArray_t arr;
cudaMallocArray(&arr, &fmt, width, height, cudaArraySurfaceLoadStore);

cudaResourceDesc res = {};
res.resType = cudaResourceTypeArray;
res.res.array.array = arr;
cudaSurfaceObject_t surf;
cudaCreateSurfaceObject(&surf, &res);

__global__ void Fill(cudaSurfaceObject_t s, int w, int h)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x < w && y < h)
        surf2Dwrite(float(x + y), s, x * sizeof(float), y);   // x is in BYTES
}
surface의 x 좌표는 바이트 단위 surf2Dwrite, surf2Dread의 x 좌표는 픽셀 번호가 아니라 바이트 오프셋이다. float 영상이면 x * 4를 넘겨야 한다. y는 행 번호 그대로다. 이 비대칭 때문에 자주 틀린다.

응용 - 3D texture로 색 보정 LUT

texture는 1D, 2D뿐 아니라 3D도 지원한다. 3D texture에 Linear 필터를 쓰면 하드웨어가 주변 8개 값을 섞는 trilinear 보간을 해 준다. 컬러 카메라의 색 보정에 쓰는 3D LUT(입력 RGB → 출력 RGB 표, 보통 17×17×17이나 33×33×33)에 딱 맞는다. 입력 RGB를 0~1 정규화 좌표로 그대로 넣으면 보정된 색이 나온다.

// lut3d: float4 cudaArray of size N x N x N, normalizedCoords = 1, Linear, Clamp
__global__ void ApplyLut3D(cudaTextureObject_t lut3d, const uchar4* in, uchar4* out, int n, int N)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i >= n) return;
    uchar4 p = in[i];
    // map 0..255 onto texel centers of an N-point grid: 0 -> 0.5/N, 255 -> (N-0.5)/N
    float s = (N - 1) / (255.0f * N), o = 0.5f / N;
    float4 c = tex3D<float4>(lut3d, p.x * s + o, p.y * s + o, p.z * s + o);
    out[i] = make_uchar4(__float2int_rn(c.x * 255.f), __float2int_rn(c.y * 255.f),
                         __float2int_rn(c.z * 255.f), p.w);
}

texture를 쓸 때와 안 쓸 때

예전 GPU(Kepler 이전)에서는 일반 global 읽기에 캐시가 약해서, 읽기 전용 데이터는 무조건 texture로 읽는 것이 이득이었다. 지금 GPU는 L1 캐시와 texture 캐시가 같은 하드웨어로 합쳐져 있어서, 단순히 읽기만 하는 경우에는 차이가 거의 없다. const __restrict__ 포인터로 읽으면 컴파일러가 읽기 전용 캐시 경로를 쓴다.

상황선택
정수 좌표로 행 방향 순서대로 읽음 (필터, 원소별 연산)일반 포인터 (const __restrict__)
소수 좌표 보간이 필요함 (리사이즈, 회전, remap)texture
영상 밖 좌표가 자주 나오고 경계 처리를 단순하게 하고 싶음texture
3D LUT 같은 다차원 표 보간3D texture
1/256 픽셀보다 정밀한 보간이 필요함texture point 모드 + 직접 보간, 또는 일반 포인터
같은 커널 안에서 읽고 쓰는 데이터일반 포인터 (texture는 같은 커널 안에서 쓴 값이 보인다는 보장이 없음)

흔한 함정

+0.5 누락 픽셀 중심은 (x + 0.5, y + 0.5)다. 빼먹으면 결과가 반 픽셀 밀리고 흐려진다. OpenCV 결과와 비교할 때 전체가 조금씩 다르면 가장 먼저 확인한다.
같은 커널에서 쓰고 texture로 읽기 texture 캐시는 커널 실행 중에 global memory가 바뀌어도 갱신을 보장하지 않는다. 커널 A가 쓴 결과는 커널 A가 끝난 뒤 다음 커널에서 texture로 읽는다.
texture object를 매 프레임 생성, 삭제 cudaCreateTextureObject는 가벼운 편이지만 매 프레임 호출할 필요는 없다. 입력 버퍼 주소가 고정이면(17편의 설계 원칙) texture object도 처음에 한 번 만들어 재사용한다.
Pitch2D의 정렬 조건 Pitch2D texture는 시작 주소와 pitch가 장치가 요구하는 정렬(cudaDevAttrTexturePitchAlignment)을 만족해야 한다. cudaMallocPitch로 잡은 메모리는 조건을 만족하지만, 큰 버퍼 중간을 잘라 ROI로 넘기면 정렬이 깨져 생성이 실패할 수 있다.
