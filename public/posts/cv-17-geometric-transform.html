기하 변환이란?

기하 변환(geometric transformation)은 이미지의 픽셀을 다른 위치로 옮기는 연산이다. 핵심은 픽셀 값이 아니라 좌표를 바꾼다는 점이다. 블러나 임계화는 픽셀이 머무는 자리는 그대로 두고 값만 바꾸지만, 기하 변환은 반대로 값은 그대로 둔 채 그 값이 놓이는 자리를 옮긴다. 이동·회전·크기 조절·기울임(전단)·원근 왜곡이 모두 여기에 속한다.

수학적으로는 입력 좌표 (x, y)를 출력 좌표 (x', y')로 보내는 함수다. 이 함수가 행렬 한 개로 표현되면 한 번의 행렬 곱으로 모든 픽셀을 한꺼번에 옮길 수 있다. OpenCV의 기하 변환 함수들이 전부 변환 행렬을 인자로 받는 이유다.

실제로는 출력에서 입력을 거꾸로 찾는다 입력 픽셀을 출력으로 보내면 출력 격자에 빈틈이 생긴다. 그래서 OpenCV는 출력 픽셀마다 "이 자리는 입력의 어디서 왔나"를 역으로 계산하고, 그 위치의 값을 보간해서 가져온다. 보간이 기하 변환과 한 묶음으로 따라붙는 이유다.

변환의 종류와 자유도

기하 변환은 무엇을 보존하느냐에 따라 등급이 나뉜다. 제약이 많을수록 자유도(degrees of freedom, 추정해야 할 미지수 개수)가 적고, 제약이 풀릴수록 자유도가 늘면서 더 일반적인 변형을 표현한다.

제약이 풀릴수록 도형이 더 자유롭게 변형된다. 강체는 모양을 그대로 옮기고, 투영은 평행선마저 한 점으로 모은다.
변환자유도허용되는 변형보존되는 성질
강체 (Rigid / Euclidean)3이동, 회전거리, 각도, 넓이, 평행
유사 (Similarity)4+ 균일 스케일각도, 길이 비율, 평행
어파인 (Affine)6+ 전단, 비균일 스케일평행, 직선, 길이 비율(같은 직선상)
투영 (Projective / Homography)8+ 원근 왜곡직선 (평행·각도·비율 모두 깨짐)

실무에서 가장 많이 쓰는 것은 어파인과 투영(원근) 두 가지다. 어파인은 2×3 행렬로, 투영은 3×3 행렬로 표현한다. 행렬이 한 줄 더 큰 만큼 투영이 더 일반적인 변형을 담는다.

기본 변환 — resize / 회전 / flip

변환 행렬을 직접 다루기 전에, 자주 쓰는 변환은 전용 함수로 제공된다. 크기 조절, 회전 행렬 생성, 뒤집기, 단순 이동을 차례로 본다.

resize — 크기 조절

cv::resize는 이미지를 목표 크기나 배율로 늘리거나 줄인다. 목표 cv::Size를 직접 주거나, Size()를 빈 값으로 두고 fx, fy 배율을 줄 수 있다.

cv::Mat src = cv::imread("part.png");

// 1) 목표 크기를 직접 지정
cv::Mat dstA;
cv::resize(src, dstA, cv::Size(640, 480));

// 2) 배율로 지정 — 가로세로 절반으로 축소
cv::Mat dstB;
cv::resize(src, dstB, cv::Size(), 0.5, 0.5, cv::INTER_AREA);

// 3) 확대 — 2배. 확대에는 CUBIC이 부드럽다
cv::Mat dstC;
cv::resize(src, dstC, cv::Size(), 2.0, 2.0, cv::INTER_CUBIC);
축소는 INTER_AREA, 확대는 INTER_CUBIC 축소할 때 INTER_AREA는 여러 픽셀을 평균 내 모아레와 계단 현상을 줄인다. 확대할 때는 INTER_CUBIC이나 INTER_LINEAR가 더 매끄럽다. 기본값 INTER_LINEAR는 무난하지만 최적은 아니다.

getRotationMatrix2D — 회전 행렬

임의 각도로 회전하려면 cv::getRotationMatrix2D로 2×3 회전 행렬을 만들고 warpAffine에 넘긴다. 인자는 회전 중심, 각도(도 단위, 반시계 방향이 양수), 스케일이다.

cv::Mat src = cv::imread("part.png");
cv::Point2f center(src.cols / 2.0f, src.rows / 2.0f);

// 중심 기준 30도 회전, 스케일 1.0
cv::Mat rotMat = cv::getRotationMatrix2D(center, 30.0, 1.0);

cv::Mat rotated;
cv::warpAffine(src, rotated, rotMat, src.size());

위 코드는 출력 크기를 원본과 같게 두어 모서리가 잘린다. 회전한 이미지 전체를 담으려면 회전 후 경계 상자를 계산해 출력 크기를 키우고, 행렬의 이동 성분을 보정한다.

double angle = 30.0;
cv::Point2f center(src.cols / 2.0f, src.rows / 2.0f);
cv::Mat rotMat = cv::getRotationMatrix2D(center, angle, 1.0);

// 회전된 경계 상자 크기를 구한다
cv::Rect2f bbox = cv::RotatedRect(center, src.size(), (float)angle).boundingRect2f();

// 이동 성분을 보정해 잘리지 않게 한다
rotMat.at<double>(0, 2) += bbox.width / 2.0 - center.x;
rotMat.at<double>(1, 2) += bbox.height / 2.0 - center.y;

cv::Mat rotated;
cv::warpAffine(src, rotated, rotMat, bbox.size());

flip — 뒤집기 / translate — 이동

cv::flip은 축을 기준으로 이미지를 반전한다. 단순 평행 이동은 이동 성분만 채운 2×3 행렬을 warpAffine에 넘기면 된다.

// flip: flipCode 0 = 상하, 1 = 좌우, -1 = 상하좌우
cv::Mat flipped;
cv::flip(src, flipped, 1);  // 좌우 반전

// 평행 이동 — x로 +50, y로 +30
double tx = 50, ty = 30;
cv::Mat transMat = (cv::Mat_<double>(2, 3) << 1, 0, tx,
                                               0, 1, ty);
cv::Mat translated;
cv::warpAffine(src, translated, transMat, src.size());

이동 행렬 [[1, 0, tx], [0, 1, ty]]에서 왼쪽 2×2가 단위 행렬이면 회전·스케일 없이 위치만 옮긴다. 이 형태가 어파인 행렬의 가장 단순한 사례다.

어파인 변환 (warpAffine)

어파인 변환은 2×3 행렬로 표현되며, 핵심 성질은 평행선이 변환 후에도 평행하게 유지된다는 것이다. 이동·회전·스케일·전단을 모두 담지만 원근 왜곡은 표현하지 못한다. 직사각형은 평행사변형까지만 변형된다 — 사다리꼴은 안 된다.

어파인 행렬은 다음 형태다. (x, y)를 (x', y')로 보낸다.

// 어파인 변환식
//  x' = a*x + b*y + c
//  y' = d*x + e*y + f
//
// 행렬 형태 (2x3):
//  | a  b  c |
//  | d  e  f |

getAffineTransform — 3점 대응으로 행렬 구하기

어파인 행렬의 미지수는 6개이므로, 변환 전후의 대응점 3쌍이면 행렬이 유일하게 정해진다. cv::getAffineTransform이 그 계산을 해 준다.

cv::Mat src = cv::imread("label.png");

// 변환 전 3점 (원본 좌표)
cv::Point2f srcPts[3] = {
    { 0.0f,           0.0f },
    { (float)src.cols, 0.0f },
    { 0.0f,           (float)src.rows }
};

// 변환 후 3점 — 대응되는 목표 좌표
cv::Point2f dstPts[3] = {
    { 60.0f,  30.0f },
    { (float)src.cols - 20.0f, 50.0f },
    { 40.0f, (float)src.rows - 10.0f }
};

// 3점 대응 → 2x3 어파인 행렬
cv::Mat affineMat = cv::getAffineTransform(srcPts, dstPts);

cv::Mat dst;
cv::warpAffine(src, dst, affineMat, src.size());

warpAffine의 마지막 인자는 출력 이미지 크기다. 그 외에 보간 방법과 경계 처리 방식도 지정할 수 있다.

cv::warpAffine(
    src, dst, affineMat, src.size(),
    cv::INTER_LINEAR,            // 보간 방법
    cv::BORDER_CONSTANT,         // 영역 밖 처리
    cv::Scalar(0, 0, 0)         // 영역 밖을 채울 색 (검은색)
);
역변환이 필요하면 invertAffineTransform 변환 행렬을 알 때 그 반대 변환을 얻으려면 cv::invertAffineTransform(affineMat, invMat)을 쓴다. 대상물 좌표계에서 검출한 결과를 원본 이미지 좌표로 되돌릴 때 자주 필요하다.

원근 변환 (warpPerspective)

원근 변환(perspective transform)은 3×3 행렬로 표현되며, 어파인이 못 하는 원근 왜곡을 담는다. 평행선이 변환 후 한 점(소실점)으로 모일 수 있어, 비스듬히 찍어 사다리꼴로 보이는 사각형을 똑바른 직사각형으로 펼 수 있다.

원근 행렬의 미지수는 8개(마지막 원소는 1로 고정)이므로, 대응점 4쌍이 필요하다. cv::getPerspectiveTransform이 4점 대응으로 행렬을 구한다.

비스듬히 찍은 문서·라벨 펴기

대표 사례는 기울어진 라벨이나 문서를 정면에서 본 모습으로 펴는 것이다. 원본에서 라벨의 네 꼭짓점을 찾고, 그 점들을 직사각형의 네 꼭짓점으로 보내는 변환을 만든다.

cv::Mat src = cv::imread("tilted_label.jpg");

// 원본에서 라벨의 네 꼭짓점 (좌상 → 우상 → 우하 → 좌하 순서)
cv::Point2f srcQuad[4] = {
    { 142.0f,  88.0f },   // 좌상
    { 510.0f, 130.0f },   // 우상
    { 470.0f, 410.0f },   // 우하
    {  98.0f, 360.0f }    // 좌하
};

// 펴진 결과의 목표 직사각형 (400 x 300)
int outW = 400, outH = 300;
cv::Point2f dstQuad[4] = {
    { 0.0f,         0.0f },
    { (float)outW,  0.0f },
    { (float)outW,  (float)outH },
    { 0.0f,         (float)outH }
};

// 4점 대응 → 3x3 원근 행렬
cv::Mat perspMat = cv::getPerspectiveTransform(srcQuad, dstQuad);

cv::Mat warped;
cv::warpPerspective(src, warped, perspMat, cv::Size(outW, outH));
결과
비스듬한 사다리꼴 라벨 → 400 x 300 정면 직사각형으로 펴짐 이후 OCR·검사 알고리즘은 똑바른 이미지를 입력으로 받는다

꼭짓점 순서는 srcQuad와 dstQuad가 일대일로 같은 순서여야 한다. 좌상-우상-우하-좌하로 맞췄으면 양쪽 모두 그 순서를 지켜야 한다. 순서가 어긋나면 이미지가 뒤집히거나 꼬인다.

어파인과 원근을 혼동하지 않는다 어파인은 평행선을 평행하게 유지한다. 원근은 평행선이 한 점으로 모인다. 비스듬히 찍힌 사각형을 펴려는데 getAffineTransform(3점)을 쓰면 사다리꼴 왜곡이 절대 펴지지 않는다. 원근 왜곡이 있으면 반드시 getPerspectiveTransform(4점)이다.

호모그래피 (findHomography)

getPerspectiveTransform은 대응점이 정확히 4쌍일 때만 쓴다. 그런데 특징점 매칭으로 얻은 대응점은 수십~수백 쌍이고 그중 일부는 잘못 매칭된 이상치(outlier)다. 이때는 cv::findHomography를 쓴다. 여러 대응점에서 가장 그럴듯한 3×3 투영 행렬(호모그래피)을 추정하며, RANSAC으로 이상치를 걸러낸다.

// srcPts, dstPts: 특징점 매칭(16편)으로 얻은 대응점 목록
std::vector<cv::Point2f> srcPts, dstPts;
// ... 매칭 결과를 채운다 ...

cv::Mat inlierMask;

// RANSAC으로 호모그래피 추정. 3.0은 인라이어 판정 임계(픽셀)
cv::Mat H = cv::findHomography(srcPts, dstPts, cv::RANSAC, 3.0, inlierMask);

if (H.empty())
{
    std::cerr << "호모그래피 추정 실패" << std::endl;
    return -1;
}

// inlierMask로 실제 사용된 대응점 개수를 확인할 수 있다
int inliers = cv::countNonZero(inlierMask);
std::cout << "인라이어: " << inliers << " / " << srcPts.size() << std::endl;

객체 정렬 · 이미지 정합

추정한 호모그래피 H는 warpPerspective에 그대로 넘긴다. 기준 템플릿 이미지를 현재 장면에 맞춰 정렬하거나, 두 장의 이미지를 같은 좌표계로 겹치는 이미지 정합(registration)에 쓴다.

// 템플릿(기준) 이미지를 장면 좌표계로 정렬
cv::Mat aligned;
cv::warpPerspective(templateImg, aligned, H, sceneImg.size());

// 템플릿의 네 모서리가 장면 어디에 놓이는지 투영
std::vector<cv::Point2f> corners = {
    { 0, 0 },
    { (float)templateImg.cols, 0 },
    { (float)templateImg.cols, (float)templateImg.rows },
    { 0, (float)templateImg.rows }
};
std::vector<cv::Point2f> projected;
cv::perspectiveTransform(corners, projected, H);
// projected: 장면 안에서 객체가 차지하는 사각형 영역
perspectiveTransform은 점만 변환한다 warpPerspective는 이미지 전체를 변환하지만, cv::perspectiveTransform은 좌표 목록만 변환한다. 검출한 좌표·ROI 꼭짓점을 변환된 좌표계로 옮길 때 가볍게 쓴다.

보간 (interpolation)

출력 픽셀의 원본 위치는 대개 정수 좌표가 아니라 소수점 자리에 떨어진다. (132.7, 88.3) 같은 위치의 값을 주변 정수 픽셀로부터 추정하는 것이 보간이다. OpenCV의 거의 모든 기하 변환 함수가 보간 방법 인자를 받는다.

방법동작품질 / 속도권장 용도
INTER_NEAREST가장 가까운 픽셀 값 그대로최저 품질 / 최고 속도마스크·라벨맵 (값이 섞이면 안 될 때)
INTER_LINEAR주변 2×2 픽셀 선형 보간무난 / 빠름 (기본값)일반 용도, 실시간 처리
INTER_CUBIC주변 4×4 픽셀 3차 보간높은 품질 / 느림확대, 화질이 중요한 경우
INTER_AREA영역 평균(픽셀 면적 관계)축소에 최적이미지 축소, 다운샘플링
INTER_LANCZOS4주변 8×8 Lanczos 보간최고 품질 / 가장 느림고품질 리샘플링
마스크나 라벨 이미지는 반드시 INTER_NEAREST 클래스 ID나 0/255 마스크는 픽셀 값 자체가 의미를 가진다. 선형 보간을 쓰면 클래스 1과 3 사이에 존재하지 않는 2가 생기고, 마스크 경계에 127 같은 어중간한 값이 생긴다. 이런 이미지는 값을 섞지 않는 INTER_NEAREST로만 변환한다.

remap — 임의 좌표 매핑

warpAffine·warpPerspective는 변환을 행렬 하나로 표현할 수 있을 때만 쓴다. 렌즈 왜곡처럼 위치마다 변형량이 다른 비선형 변환은 행렬로 담을 수 없다. 이때 cv::remap을 쓴다. 출력 픽셀마다 "원본 어디서 가져올지"를 좌표 맵 두 장(mapX, mapY)으로 직접 지정한다.

cv::Mat src = cv::imread("part.png");
int h = src.rows, w = src.cols;

// 출력 각 픽셀이 원본의 어느 좌표에서 올지 지정하는 맵
cv::Mat mapX(h, w, CV_32FC1);
cv::Mat mapY(h, w, CV_32FC1);

for (int y = 0; y < h; ++y)
{
    for (int x = 0; x < w; ++x)
    {
        // 예: 좌우 반전을 remap으로 표현
        mapX.at<float>(y, x) = (float)(w - 1 - x);
        mapY.at<float>(y, x) = (float)y;
    }
}

cv::Mat dst;
cv::remap(src, dst, mapX, mapY, cv::INTER_LINEAR, cv::BORDER_CONSTANT);

좌우 반전은 flip으로 충분하지만, 핵심은 맵을 어떻게 채우느냐에 따라 어떤 비선형 변형이든 표현할 수 있다는 점이다. 다음 글에서 다룰 카메라 캘리브레이션은 렌즈 왜곡 계수로 이 맵을 만들어(initUndistortRectifyMap) remap으로 왜곡을 펴낸다. remap은 그 왜곡 보정의 기반이다.

산업 검사 관점

산업 비전에서 기하 변환은 거의 항상 정렬을 위해 쓴다. 검사 알고리즘은 대상물이 매번 같은 위치·각도에 있다고 가정할 때 가장 안정적이다. 현실에서는 부품이 컨베이어 위에서 조금씩 틀어진다. 이 틀어짐을 기하 변환으로 보정하는 것이 핵심이다.

검사 ROI를 대상에 맞추기

두 가지 접근이 있다. 대상물을 기준 자세로 옮기거나(이미지를 변환), 검사 ROI를 대상물의 현재 자세로 옮기거나(좌표를 변환). 후자가 더 가볍다 — 이미지 전체를 다시 그리지 않고 ROI 꼭짓점만 변환하면 된다.

// 기준 이미지에서 정의해 둔 검사 ROI 꼭짓점
std::vector<cv::Point2f> templateRoi = {
    { 120, 80 }, { 260, 80 }, { 260, 200 }, { 120, 200 }
};

// 현재 부품 자세를 어파인 행렬로 추정했다고 하자 (정합 결과)
cv::Mat alignMat;  // 2x3, 기준 → 현재 자세

// ROI 꼭짓점을 현재 부품 위치로 옮긴다
std::vector<cv::Point2f> currentRoi;
cv::transform(templateRoi, currentRoi, alignMat);
// currentRoi 영역에서 검사를 수행한다

비스듬한 촬영 보정과 좌표계 정합

카메라를 대상물 정면에 두지 못하는 경우, 원근 변환으로 정면에서 본 모습으로 펴고 나서 측정한다. 이렇게 펴면 픽셀 좌표가 실제 평면 좌표와 선형 관계가 되어, 펴진 이미지 위의 거리 측정이 곧 실제 치수와 비례한다. 여러 카메라·여러 스테이션의 좌표를 하나의 기준 좌표계로 모으는 좌표계 정합도 호모그래피로 처리한다.

정렬은 검사의 전처리, 측정의 기준 대부분의 검사 파이프라인은 "대상 검출 → 자세 추정 → 기하 변환으로 정렬 → 검사·측정" 순서다. 정렬이 부정확하면 그 뒤 모든 단계가 흔들린다. 그래서 대응점 정확도와 변환 종류 선택이 검사 신뢰도를 좌우한다.

흔한 함정

기하 변환에서 반복적으로 나오는 실수들이다.

어파인과 원근 혼동

어파인은 평행을 유지, 원근은 안 한다 가장 잦은 실수다. 원근 왜곡(사다리꼴)이 있는데 어파인으로 펴려 하면 절대 펴지지 않는다. 반대로 단순히 회전·이동만 필요한데 원근(4점)을 쓰면 대응점 오차가 엉뚱한 사다리꼴 왜곡으로 증폭된다. 평행선이 평행으로 남으면 어파인, 한 점으로 모이면 원근으로 판단한다.

대응점 순서와 정확도

대응점은 순서가 맞아야 하고, 정밀할수록 좋다 srcPts[i]와 dstPts[i]는 같은 인덱스가 같은 물리적 지점이어야 한다. 순서가 어긋나면 이미지가 꼬인다. 또 대응점은 변환 행렬을 결정하는 입력이므로, 한두 픽셀의 오차도 변환 전체로 퍼진다. 점은 가능한 한 멀리 떨어뜨려 배치하고(가까우면 오차에 민감), 위치를 서브픽셀 정밀도로 잡는다.

보간 방법 부적절

축소에 INTER_LINEAR를 쓰면 모아레가 남고, 마스크에 선형 보간을 쓰면 경계가 흐려진다. 용도에 맞는 보간을 골라야 한다 — 축소는 AREA, 확대는 CUBIC, 마스크·라벨은 NEAREST.

변환 후 영역 밖은 검은색

회전이나 원근 변환을 하면 출력에 원본이 채우지 못하는 빈 영역이 생긴다. 기본값 BORDER_CONSTANT + Scalar(0,0,0)이라 그 영역은 검게 남는다. 검사 알고리즘이 그 검은 영역을 결함으로 오인할 수 있다.

// 빈 영역을 흰색으로 채우기
cv::warpAffine(src, dst, rotMat, dst.size(),
               cv::INTER_LINEAR, cv::BORDER_CONSTANT,
               cv::Scalar(255, 255, 255));

// 또는 가장자리 픽셀을 복제해 채우기
cv::warpAffine(src, dst, rotMat, dst.size(),
               cv::INTER_LINEAR, cv::BORDER_REPLICATE);

역변환이 필요할 때

변환된 좌표계의 결과는 원본으로 되돌려야 한다 정렬한 이미지에서 결함을 검출했다면 그 좌표는 변환된 좌표계의 값이다. 사용자에게 원본 이미지 위에 표시하려면 역변환을 적용해야 한다. 어파인은 cv::invertAffineTransform, 원근은 cv::invert(또는 warpPerspective에 WARP_INVERSE_MAP 플래그)로 되돌린다. 이 단계를 빼먹으면 결함 위치가 엉뚱한 곳에 찍힌다. 
// 어파인 역변환
cv::Mat invAffine;
cv::invertAffineTransform(affineMat, invAffine);

// 변환 좌표계의 검출점을 원본 좌표로 되돌린다
std::vector<cv::Point2f> detected, original;
cv::transform(detected, original, invAffine);
정리하면 변환 종류는 보존 성질로 고른다(평행 유지 → 어파인, 소실점 → 원근). 대응점은 순서를 맞추고 멀리 떨어뜨려 정밀하게 잡는다. 보간은 용도별로(축소 AREA, 확대 CUBIC, 마스크 NEAREST). 빈 영역은 borderMode로 처리하고, 검출 결과는 역변환으로 원본 좌표계에 되돌린다.
