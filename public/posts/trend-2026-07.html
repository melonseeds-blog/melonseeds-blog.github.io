월간 트렌드 브리핑 — 2026년 7월호

2026-07-15 약 10분 분량 월간 트렌드 브리핑
이번 호 안내 한 달 동안의 AI·개발 트렌드를 한 편으로 모아 두는 정기 기록의 두 번째 호다. 첫 호(6월호)가 6월 하순까지를 담았으므로, 이번 호는 그 뒤인 6월 말부터 7월 중순까지의 흐름을 정리한다. 공교롭게도 이 시기에 세 프런티어 랩의 모델 갱신이 몰려 어느 달보다 변화가 컸다. 목적은 여전히 하나다 — 이 글만 읽어도 큰 흐름을 놓치지 않는 것.
이달 한눈에
  • 모델 — Anthropic Claude Sonnet 5가 새 기본 모델로, Fable 5는 중단됐다 복귀. OpenAI GPT-5.6 패밀리 정식 공개, xAI Grok 4.5 등장
  • 모델 랩 — 보도에 따르면 세 프런티어 랩이 같은 날(7/9) 새 모델을 내놓은 첫 사례로 회자
  • 코딩 에이전트 — Claude Code가 브라우저 사용 격차를 메우기 시작(Claude in Chrome 정식 출시 + 데스크톱 인앱 브라우저)

이달의 헤드라인

  • Claude Sonnet 5, 새 기본 모델로. 6월 30일 출시돼 Pro·Team·Enterprise 구독의 기본 모델이 됐다. 네이티브 100만 토큰 컨텍스트와 기본 활성화된 적응형 사고(adaptive thinking)가 특징으로 보도된다.
  • 세 랩이 거의 동시에 모델을 갱신. OpenAI GPT-5.6 패밀리(Sol·Terra·Luna)가 7월 9일 정식 공개됐고, 같은 날 xAI Grok 4.5가 나왔으며, Anthropic Fable 5는 7월 1일 복귀했다. 보도에서는 세 프런티어 모델이 동시에 이용 가능해진 첫 날로 회자됐다.
  • 코딩 에이전트의 최대 격차가 좁혀졌다. 그동안 Codex 대비 Claude Code의 약점으로 꼽히던 "브라우저·컴퓨터 사용"이 Claude in Chrome 정식 출시와 데스크톱 인앱 브라우저로 메워지기 시작했다.

프런티어 모델 동향

6월 말부터 7월 중순 사이는 최근 몇 달 중 모델 갱신이 가장 몰린 구간이다. 랩별로 정리하면 이렇다.

Anthropic — Sonnet 5 기본화, Fable 5의 중단과 복귀

지난 호에서 등장을 다룬 Fable 5는 그 뒤 굴곡이 있었다. 6월 하순 일반 이용이 한때 중단(suspended)됐다가, 7월 1일 크레딧 기반으로 다시 열렸다. 보도 기준으로 Fable 5는 SWE-Bench Pro에서 80%대 초반으로 코딩 선두를 재탈환한 것으로 전해진다. 동시에 Claude Sonnet 5가 6월 30일 나와 다수 구독의 기본 모델로 올라섰다 — 최상위 성능은 Opus·Fable 계열에 두고, 일상 작업의 기본값을 한 단계 끌어올리는 배치다.

OpenAI — GPT-5.6 패밀리 정식 공개

GPT-5.6 패밀리가 7월 9일 정식 공개됐다. 세 티어로 나뉜 점이 특징이다 — Sol은 고난도 추론·코딩·과학, Terra는 이전 세대급 품질을 더 낮은 비용에, Luna는 빠르고 저렴한 대량 처리에 맞춘 구성으로 보도된다. 정식 공개 전 약 2주간은 안전 검토를 이유로 제한 공개 상태였던 것으로 전해진다.

xAI·Google — Grok 4.5 등장, Gemini 3.5 Pro는 대기

xAI는 7월 9일 Grok 4.5를 내놨다. 토큰 효율(같은 작업에 더 적은 출력 토큰)을 강조한 점이 보도에서 자주 언급된다. Google은 Gemini 3.5 Flash를 앞서 공개했으나, 상위 모델인 Gemini 3.5 Pro는 아직 기업용 프리뷰 단계로 정식 출시일이 확정되지 않은 것으로 전해진다.

벤치마크 수치는 그대로 믿지 않는다 이 글의 성능·순위 언급은 7월 중순 시점의 외부 보도와 서드파티 비교를 근거로 한 것이며, 측정 방식·버전·시점에 따라 출렁인다. 절대값보다 "어느 방향으로 움직였나"를 보는 게 안전하고, 정확한 사양은 각 랩의 공식 발표를 확인한다.

코딩 에이전트 — Claude Code vs Codex

지난 호의 결론("둘 다 쓴다")은 이번 달에도 유효하다. 다만 6월 대비 가장 큰 변화가 하나 생겼다 — Claude Code가 그동안의 최대 약점이던 브라우저·컴퓨터 사용을 갖추기 시작했다. 표를 6월 시점에서 갱신하면 이렇다.

벤치마크는 여전히 지표에 따라 엇갈려 "접전"으로 요약된다. 서드파티 설문·리뷰 보도를 보면 흥미로운 엇갈림도 있다 — 일상적으로는 Codex를 선호한다는 응답이 다수였지만, 코드 결과물을 블라인드로 비교하면 Claude Code 쪽을 더 깔끔하다고 평가하는 경우가 더 많았다는 보도가 있다. "빠르고 편한 쪽"과 "결과물 품질"이 반드시 일치하지는 않는다는 이야기다.

현장 컨센서스 — "둘 다 쓴다"는 구도는 그대로다. 다만 6월에 자주 지목되던 "Codex만 브라우저·컴퓨터를 쓴다"는 격차가 이번 달부터 흐려지기 시작했다. 도구 선택 기준이 "기능이 있느냐"에서 "어느 쪽 워크플로가 내 작업에 맞느냐"로 옮겨 가는 중이다.

도구·기능 업데이트

6월 하순부터 7월 중순까지 Claude Code 쪽 변경 이력에서 눈에 띄는 항목을 추린다.

브라우저 탑재 (Claude in Chrome 정식 + 데스크톱 인앱 브라우저)

Claude in Chrome이 직접 이용 플랜 전반에 정식 출시됐고(6월 말~7월 초), 뒤이어 데스크톱 앱에는 인앱 브라우저가 더해졌다(7월 초). 로컬 개발 서버 프리뷰를 다루던 방식 그대로 문서·디자인·일반 웹페이지를 열고 상호작용할 수 있게 됐다. 앞선 비교에서 언급한 "브라우저 격차"를 정면으로 메우는 변화다.

기본 모델 교체 + 서브에이전트 백그라운드 실행

같은 시기 Claude Sonnet 5가 Pro·Team·Enterprise 좌석의 기본 모델이 됐고, 서브에이전트가 기본적으로 백그라운드에서 실행되도록 바뀌었다. 서브에이전트가 도는 동안 메인 작업이 멈추지 않는다. Linux용 데스크톱 앱도 베타로 합류했다.

안전·점검 기능 강화

auto mode에는 트랜스크립트 변조 차단과, 값이 확정되지 않은 변수로 rm -rf가 실행되려 할 때 되묻는 안전장치가 추가됐다. 설정 상태를 한 번에 진단하고 일부는 자동 교정까지 해 주는 /doctor(별칭 /checkup)도 들어왔다. 지난 호의 키워드였던 "안전 점검의 자동화" 흐름이 이어지는 모습이다.

읽는 법 이번 달은 "모델 경쟁"과 "에이전트 기능 격차 해소"가 동시에 크게 움직였다. 모델은 세 랩이 몰아쳐 갱신됐고, 도구는 오래 지적되던 브라우저 격차를 메우는 쪽으로 갔다. 트렌드를 볼 때는 벤치 점수 몇 점보다 기본값이 무엇으로 바뀌었는지(기본 모델, 기본 실행 방식)를 확인하는 게 실무에 더 가깝다.
