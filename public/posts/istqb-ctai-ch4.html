ML 데이터의 중요성 — Garbage In, Garbage Out

머신러닝 모델의 품질은 모델 구조나 알고리즘보다 데이터의 품질에 의해 결정된다. 실러버스는 데이터 준비에 전체 ML 프로젝트 노력의 평균 43%가 들어가고, 모델 선택과 구현은 17%에 불과하다고 명시한다. 데이터가 "주연", 모델은 "조연"인 셈이다.

왜 CT-AI Ch4가 가장 큰 챕터(230분)인가? 실러버스 분량을 보면 4장은 9장(245분) 다음으로 비중이 크고, 4장과 9장이 합쳐 전체의 약 31%를 차지한다. 시험에서도 데이터 라벨링·편향·품질·분할 비율을 묻는 문제가 반복적으로 등장한다. 학습 계획에서 이 챕터를 2회독 권장한 이유다.

데이터가 결정하는 세 가지

  • 정확도(Accuracy) — 데이터가 누락되거나 잘못 라벨링되면 예측이 빗나간다.
  • 편향성(Bias) — 데이터가 한쪽으로 쏠리면 모델도 그대로 쏠린다.
  • 보안과 프라이버시 — 데이터 보호가 무너지면 모델 자체가 손상된다.

이 세 가지는 모두 Ch3 머신러닝 개요에서 다룬 "ML 모델의 한계"와 직결된다. 알고리즘이 아무리 정교해도 입력 데이터가 쓰레기면 결과도 쓰레기다(Garbage In, Garbage Out).

데이터 준비 (Data Preparation)

데이터 준비는 데이터 파이프라인에 속하는 작업으로, 원본 데이터를 입력받아 모델 훈련 또는 예측에 사용할 수 있는 형식으로 출력한다. 다음 세 단계로 구성된다.

1단계 — 데이터 수집 (Data Acquisition)

  • 식별(Identification): 훈련과 예측에 쓸 데이터 유형을 정한다. 예) 자율주행에는 레이더·비디오·LiDAR 데이터가 필요하다고 결정한다.
  • 수집(Gathering): 데이터 출처와 채널을 결정한다. 예) 금융 데이터는 IMF에서 받아 어떤 채널로 시스템에 넣을지 정한다.
  • 라벨링: 별도 절(4.5)로 분리할 만큼 비중이 크다. 뒤에서 다룬다.

수집한 데이터는 숫자·범주·이미지·표·텍스트·시계열·센서·지리공간·비디오·오디오 등 다양한 형식을 가진다.

2단계 — 데이터 전처리 (Data Pre-processing)

활동설명예시
정제(Cleaning)잘못된 값·중복·이상값을 제거하거나 수정한다. 누락값은 평균·중앙값·모드로 대체(imputation)한다.센서 노이즈 제거, 결측값 평균 대치, 개인정보 익명화
변환(Transformation)데이터 형식을 바꾼다. 범주형 → 숫자형, 문자열 분할, 크기 조정(표준화·정규화)을 포함한다.주소를 동·도로명으로 분리, 평균 0/표준편차 1로 표준화
증강(Augmentation)샘플 수를 늘린다. 적대적 공격에 대한 강건성을 위해 적대적 예제를 훈련 데이터에 포함시키기도 한다.이미지 회전·뒤집기·밝기 변화, 노이즈 추가
샘플링(Sampling)전체 데이터의 일부만 선택해 비용과 시간을 줄인다.1억 건 중 100만 건만 무작위 추출
전처리의 양날의 검 모든 전처리는 유용한 유효 데이터를 변경하거나 비유효 데이터를 새로 만들어 낼 위험이 있다. "이상값"이라고 지운 데이터가 사실은 중요한 신호였을 수도 있다.

3단계 — 특성 엔지니어링 (Feature Engineering)

  • 특성 선택(Feature Selection): 모델에 가장 기여하는 특성만 남기고 노이즈는 버린다. 효과는 훈련 시간 단축, 과적합 방지, 정확도 향상, 일반화 능력 증가다.
  • 특성 추출(Feature Extraction): 기존 특성을 조합해 새로운(더 유용하고 중복 없는) 특성을 만든다. 결과 데이터 세트가 작아지면서 동일한 정확도를 더 저렴·빠르게 얻을 수 있다.

탐색적 데이터 분석 (EDA)

위 세 단계와 병행해 탐색적 데이터 분석(Exploratory Data Analysis, EDA)을 수행한다. 데이터의 트렌드를 식별하고 도표로 시각화해 다음 단계의 의사결정을 돕는다. EDA는 데이터 준비 전체를 지원하는 보조 활동이다.

데이터 준비의 어려움

  • 애플리케이션 도메인·데이터 속성·전처리 기법 모두에 대한 지식이 필요하다.
  • 여러 출처에서 고품질 데이터를 확보하기 어렵다.
  • 파이프라인을 자동화하고 운영 환경에서 확장성과 성능 효율성을 보장해야 한다.
  • 데이터 준비 비용이 크다.
  • 파이프라인에 유입된 결함에 충분한 우선순위가 주어지지 않는다.
  • 표본 편향성이 유입될 수 있다.

훈련 · 검증 · 테스트 데이터 세트

ML 모델을 개발하려면 세 가지 동등한 데이터 세트가 필요하다. 모두 하나의 초기 데이터 세트에서 무작위로 분할한다.

세트목적훈련 중 노출 여부
훈련 데이터(Training Dataset)모델의 가중치·파라미터를 학습시킨다.학습에 직접 사용
검증 데이터(Validation Dataset)학습한 모델을 검증하고 하이퍼파라미터를 튜닝한다.튜닝에 사용 (학습엔 미사용)
테스트 데이터(Test Dataset)최종 튜닝된 모델의 성능을 평가한다. 홀드아웃(Holdout) 데이터라고도 부른다.훈련·튜닝 동안 절대 미사용
왜 테스트 세트는 끝까지 숨겨야 하는가 모델이 테스트 데이터의 영향을 한 번이라도 받으면 그 테스트 점수는 "모델의 실제 품질"이 아니라 "모델이 그 데이터에 얼마나 잘 맞춰졌나"를 측정하게 된다. 테스트 세트는 "한 번도 본 적 없는 미래 데이터"의 대용품이어야 한다.

분할 비율 — 60:20:20 ~ 80:10:10

최적의 비율은 없다. 일반적으로 훈련:검증:테스트 = 60:20:20에서 80:10:10 범위를 사용한다. 분할은 보통 무작위로 진행하지만, 데이터가 작거나 운영 데이터를 대표하지 못할 위험이 있는 경우 다른 방법을 쓴다.

데이터가 부족할 때 — 교차 검증

데이터가 제한적이면 3개 세트로 분할 시 훈련용 데이터가 부족해진다. 이를 극복하기 위해 훈련·검증 세트를 합친 뒤(테스트 세트는 별도 유지) 여러 분할 조합을 만들어 평균 성능을 계산한다. 대표적 기법은 다음과 같다.

  • 분할-테스트(Split-test)
  • 부트스트랩(Bootstrap)
  • k-폴드 교차 검증(k-Fold Cross Validation)
  • 리브-원-아웃 교차 검증(Leave-One-Out CV)

지도학습을 위한 데이터 라벨링

데이터 라벨링은 라벨이 없거나 잘못 지정된 데이터에 라벨을 부여해 지도학습에 쓸 수 있게 만드는 작업이다. 실러버스는 라벨링이 ML 프로젝트 전체 시간의 평균 25%를 차지한다고 보고한다.

가장 단순한 형태는 클래스별 폴더에 파일을 넣는 것이다. 예) 긍정 리뷰는 한 폴더, 부정 리뷰는 다른 폴더. 이미지에 사각형 박스를 그리는 방식은 주석(annotation, 어노테이션)이라 부른다. 3D 객체나 불규칙한 객체에는 더 복잡한 주석이 필요하며, 일반적으로 전용 도구를 사용한다.

라벨링 접근법 5가지

방법설명장단점
내부(Internal)개발자·테스터·전담팀이 직접 라벨링한다.도메인 통제 우수, 인력 비용 큼
아웃소싱(Outsourcing)외부 전문 기관에 위탁한다.전문성·확장성 우수, 도메인 이해 부족 가능
크라우드소싱(Crowdsourcing)다수의 익명 참여자가 라벨링한다. 품질 관리가 어려워 동일 데이터에 여러 사람의 라벨을 받아 다수결로 결정한다.빠르고 저렴, 품질 편차 큼
AI 지원(AI-assisted)AI 도구가 1차 라벨을 달면 사람이 확인·보완한다. 2단계 프로세스다.속도 향상, AI 오류 전파 위험
하이브리드(Hybrid)위 방법들을 조합한다. 예) AI 크라우드 관리 도구로 크라우드소싱을 운영한다.유연함, 관리 복잡
라벨링 비용을 아끼는 또 다른 길 이미 라벨링된 공개 데이터 세트를 재사용할 수 있다면 라벨링 자체가 불필요하다. Kaggle이 대표적이며, ImageNet·COCO 같은 표준 데이터 세트도 같은 맥락이다.

잘못 라벨링되는 이유

실제 데이터 세트에서 모든 항목이 올바르게 라벨링되는 경우는 드물다. 다음과 같은 이유로 라벨이 잘못 지정된다.

  • 주석자의 임의 오류 (예: 버튼을 잘못 누름)
  • 시스템 오류 (예: 라벨 담당자가 잘못된 지침을 받음, 훈련 부족)
  • 악의적인 주석자에 의한 의도적 오류
  • 번역 오류 (한 언어로 맞는 라벨이 다른 언어에서는 틀림)
  • 주관적 판단 차이 (해석 여지가 있는 경우 주석자마다 다름)
  • 도메인 지식 부족
  • 분류 작업이 너무 복잡함
  • 라벨링 도구의 결함
  • ML 기반 라벨링 자체가 확률적이라 일부 오라벨 발생

데이터 세트 품질 문제

실러버스는 데이터 세트의 품질 문제를 10가지 유형으로 정리한다. 시험에 그대로 출제되는 표라서 통째로 익혀 둔다.

품질 문제설명
잘못된 데이터수집한 데이터가 부정확하거나(예: 오류 있는 센서) 잘못 입력됨(예: 복사-붙여넣기 오류)
불완전한 데이터값이 누락됨. 원인은 보안 문제, 하드웨어 문제, 인적 오류 등
잘못 라벨링된 데이터4.5.2절 참조 — 주석자 오류, 시스템 오류, 도메인 지식 부족 등
데이터 부족학습 알고리즘이 패턴을 인식하기에 데이터가 부족함
전처리 되지 않은 데이터깨끗하고 일관된 형식이 아닌 채로 사용됨
오래된 데이터최신성이 떨어지는 데이터로 학습(예: 수년 전 재무 데이터)
불균형 데이터특정 클래스가 과대표상되거나 과소표상됨. 인종·성별·민족 차별로 이어질 수 있음
불공정한 데이터공정성을 위해 의도적으로 다양성을 강화한 데이터. "긍정적으로 편향"되어 불균형해질 수 있음
중복 데이터반복된 레코드가 모델 결과에 과도하게 영향을 미침
관련성 없는 데이터문제와 무관한 데이터가 결과를 악화시키고 자원을 낭비함
개인정보 보호 문제GDPR 등 데이터 보호법 위반
보안 문제의도적으로 주입된 허위 데이터가 모델 정확도를 떨어뜨림 (데이터 포이즈닝)

품질 문제 → 모델 결함 3가지

위 품질 이슈는 다음 세 가지 모델 결함으로 귀결된다.

  • 정확도 감소 — 잘못된·불완전·잘못 라벨링된·부족한·오래된·관련없는·미전처리 데이터로 인해 발생한다. 예) 단독주택 데이터가 거의 없는 학습 세트로 단독주택 가격을 예측하면 빗나간다.
  • 편향된 모델 — 불완전·불균형·불공정·다양성 부족·중복 데이터로 인해 발생한다. 예) 의료 데이터가 특정 성별 것만 수집되면 다른 성별 대상 예측이 부정확해진다.
  • 손상된 모델 — 개인정보·보안 제한 위반으로 인해 발생한다. 예) 보안 취약점을 통해 모델이 역설계되고 개인정보가 유출될 수 있다.
합성 데이터(Synthetic Data)의 함정 실제 데이터를 확보하기 어려울 때 합성 데이터를 만들기도 한다. 그러나 합성 데이터는 실제 데이터의 분포를 완벽히 재현하지 못해 모델이 운영 환경에서 무너지는 원인이 될 수 있다. 합성 데이터로 학습한 모델은 반드시 실제 데이터로 검증해야 한다.

데이터 편향(Data Bias)

편향은 CT-AI 전체를 관통하는 키워드다. 데이터 편향은 크게 네 가지 종류로 나뉜다.

편향의 4가지 유형

편향 유형설명예시
샘플 편향(Sample Bias)표본이 모집단을 대표하지 못함20대 남성 데이터로 전 연령 얼굴 인식 학습
라벨링 편향(Labelling Bias)주석자의 선입견이 라벨에 반영됨"성공한 사람" 라벨에 특정 인종을 더 많이 부여
측정 편향(Measurement Bias)측정 도구·환경이 한쪽에 유리하게 설정됨천장 높이에 설치한 얼굴 인식 카메라 — 키 큰 사람 위주 학습
알고리즘 편향(Algorithmic Bias)알고리즘 자체가 특정 결과를 선호하도록 설계됨최적화 목표 설정이 다수 클래스에 유리한 경우

이 중 처음 세 가지는 데이터 단계에서, 마지막은 모델 단계에서 발생한다. Ch2 품질 특성에서 다룬 공정성(Fairness)과 직결되며, Ch9 테스팅 기법의 페어와이즈·변성 테스팅으로 검출한다.

편향 완화 전략

  • 데이터 수집 단계에서 모집단의 다양성을 사전 정의한다.
  • 주석자 풀의 인구통계학적 다양성을 확보한다.
  • 측정 도구·환경에 대한 메타데이터를 함께 기록한다.
  • 편향 검출용 보조 데이터 세트(Fairness Test Set)를 별도 유지한다.
  • 주기적으로 편향 측정지표(예: Demographic Parity, Equalized Odds)를 모니터링한다.

데이터 파이프라인과 테스팅

데이터 파이프라인은 원본 데이터를 입력받아 모델 훈련용 또는 예측용 형식으로 변환·전달하는 일련의 자동화된 흐름이다. 실러버스가 강조하는 핵심은 두 가지다.

  • 일부 단계는 한 번만 수행되고 수동으로 처리된다. 예) 데이터 출처 식별.
  • 운영 데이터 파이프라인에 포함되는 단계는 라이브 데이터를 다루며 반드시 자동화되어야 한다. 예) 실시간 정제·변환·예측.

파이프라인에서 발생하는 결함

파이프라인 결함은 모델 결함보다 검출이 더 어렵다. 모델이 학습한 데이터가 이미 오염된 상태이기 때문이다.

  • 스키마 변경에 대한 무방비 (입력 형식이 바뀌면 무음 실패)
  • 스케일링 함수의 운영/학습 불일치 (Training-Serving Skew)
  • 버전 관리 부재 — 어느 시점의 데이터로 학습했는지 추적 불가
  • 피처 누출(Feature Leakage) — 미래 정보가 학습 데이터에 새어 들어옴
데이터 파이프라인 테스트 4종 (1) 스키마 검증, (2) 통계적 분포 모니터링(Data Drift), (3) 변환 함수 단위 테스트, (4) 엔드투엔드 회귀 테스트. 자세한 내용은 Ch9 테스팅 방법과 기법에서 다룬다.

데이터 익명화와 프라이버시

개인정보가 포함된 데이터는 GDPR·개인정보보호법 등 관련 법규를 준수해야 한다. 주요 기법은 다음과 같다.

  • 익명화(Anonymization) — 개인 식별자를 영구히 제거한다. 복원 불가능해야 한다.
  • 가명화(Pseudonymization) — 식별자를 가명으로 대체한다. 별도 키로 복원 가능하다.
  • 차분 프라이버시(Differential Privacy) — 통계 결과에 노이즈를 추가해 개인 식별을 어렵게 한다.
  • 연합 학습(Federated Learning) — 데이터를 중앙으로 옮기지 않고 각 단말에서 학습한다.

데이터 버전 관리와 재현성

ML 프로젝트에서 "같은 모델을 다시 학습시켜라"는 요청을 받았을 때, 코드만으로는 결과를 재현할 수 없다. 동일한 결과를 얻으려면 다음 세 가지가 같아야 한다.

  • 코드 버전 — Git 등 일반 SW와 동일하게 관리
  • 모델 가중치 버전 — 학습 결과물 저장(MLflow, DVC 등)
  • 데이터 버전 — 어느 시점의 어떤 데이터로 학습했는가

데이터 버전 관리가 빠진 채 모델만 배포하면, 동일 입력에 다른 결과가 나오는 원인을 추적할 수 없다. 데이터 버전 도구로는 DVC(Data Version Control), LakeFS, Pachyderm 등이 쓰인다.

재현성(Reproducibility)은 ML 테스팅의 전제 조건 같은 입력에 같은 출력이 나오지 않으면 결함을 발견해도 재현·디버깅이 불가능하다. 데이터·코드·시드(random seed)·환경(라이브러리 버전·GPU)을 모두 고정해야 진정한 재현이 가능하다.

데이터 드리프트 (Data Drift)

운영 환경에서 입력 데이터의 분포가 학습 시점과 달라지는 현상이다. 모델이 처음에는 잘 동작하다가 시간이 지나면서 성능이 떨어진다. 대표 유형은 다음과 같다.

드리프트 유형설명예시
공변량 드리프트(Covariate Drift)입력 X의 분포가 변함, 입력→출력 관계는 그대로제품 조명 환경 변화로 카메라 영상의 밝기 분포가 달라짐
레이블 드리프트(Label Drift)출력 Y의 분포가 변함결함 부품 비율이 1%에서 5%로 증가
개념 드리프트(Concept Drift)X와 Y의 관계 자체가 변함"좋은 리뷰"의 기준이 시대에 따라 달라짐

드리프트 대응을 위해 통계적 분포 모니터링(KS 검정·PSI), 주기적 재학습 파이프라인, 섀도우 배포(Shadow Deployment) 등이 사용된다.

빅데이터의 4V

ML이 다루는 데이터는 종종 빅데이터의 특성을 지닌다. 실러버스는 빅데이터를 다음 4V로 설명한다.

특성의미ML 관점에서 어려움
Volume (양)데이터 크기가 매우 큼저장·전송·처리 비용 증가
Velocity (속도)데이터 생성·수집 속도가 빠름실시간 처리 파이프라인 필요
Variety (다양성)구조화·반구조화·비구조화 데이터가 섞임통합·정제·변환의 복잡도 증가
Veracity (진실성)데이터의 신뢰도·정확성품질 검증·이상 탐지 필요

일부 자료는 여기에 Value(가치)를 더해 5V로 부르기도 하지만, ISTQB CT-AI 실러버스는 4V를 기준으로 한다.

현장 사례 — 머신비전 검사 시스템

실제 공장의 결함 검출 ML 시스템을 예로 들어 Ch4 개념이 어떻게 적용되는지 본다.

1. 데이터 수집 단계

  • 식별: 결함 유형 분류 — 스크래치, 찍힘, 이물질, 변색 4종
  • 수집: 생산 라인 카메라에서 결함품 5,000장, 정상품 50,000장 확보
  • 품질 이슈: 결함품이 정상품의 10%에 불과해 불균형 데이터 문제 발생

2. 전처리와 증강

  • 정제: 흐릿한 이미지·중복 프레임 제거
  • 증강: 결함 이미지 회전·뒤집기·밝기 변화로 5배 증강해 50,000장으로 균형 맞춤
  • 변환: 8비트 RGB로 통일, 224×224 리사이즈, 픽셀값 [0,1] 정규화

3. 라벨링

  • 1차: AI 지원 — 사전 학습된 모델이 박스 위치를 자동 제안
  • 2차: 내부 검수 — 도메인 전문가(QC 엔지니어)가 박스 위치·결함 클래스 확정
  • 품질 관리: 동일 이미지를 2명에게 라벨링시켜 일치율 95% 이상 유지

4. 분할과 학습

  • 비율 70:15:15로 분할
  • 주의: 같은 부품의 다른 각도 이미지가 학습/테스트에 함께 들어가지 않도록 부품 ID 단위로 분할 (피처 누출 방지)
  • k-폴드 교차 검증으로 모델 안정성 확인

5. 배포 후 모니터링

  • 월별 정확도·재현율 추적 — Ch5 측정지표
  • 입력 영상의 밝기·대비 분포 모니터링 — 데이터 드리프트 검출
  • 오탐 사례 자동 수집 → 재학습 파이프라인에 투입
현장에서 가장 자주 일어나는 사고 조명·렌즈·카메라를 교체했을 때 모델 성능이 갑자기 떨어진다. 측정 환경 자체가 바뀌면서 입력 분포가 학습 시점과 달라지는 공변량 드리프트의 전형적 사례다. 하드웨어 교체 시 반드시 모델을 재검증해야 한다.
공부 노트 — Ch4 한눈에 보기

1. 데이터 준비 = 전체 노력의 43%, 모델 구현은 17%.
2. 데이터 세트 3종: 훈련(학습) · 검증(튜닝) · 테스트(평가). 비율 60:20:20 ~ 80:10:10.
3. 테스트 세트는 학습·튜닝 동안 절대 노출 금지.
4. 라벨링 방법 5가지: 내부 · 아웃소싱 · 크라우드소싱 · AI 지원 · 하이브리드.
5. 품질 문제 → 모델 결함 3종: 정확도 감소 · 편향된 모델 · 손상된 모델.
6. 편향 4종: 샘플 · 라벨링 · 측정 · 알고리즘.
7. 빅데이터 4V: Volume · Velocity · Variety · Veracity.

연습 문제

Q1. 다음 중 데이터 준비 단계에 속하지 않는 것은?
  • 데이터 정제(Cleaning)
  • 특성 추출(Feature Extraction)
  • 하이퍼파라미터 튜닝
  • 데이터 증강(Augmentation)
정답: c — 하이퍼파라미터 튜닝은 모델 학습 단계의 활동이다. 데이터 준비는 수집 → 전처리 → 특성 엔지니어링으로 구성된다.
Q2. 다음 중 테스트 데이터 세트(Test Dataset)의 올바른 설명을 고르시오.
  • 모델 가중치를 학습시키는 데 사용한다.
  • 하이퍼파라미터를 튜닝하는 데 사용한다.
  • 훈련·튜닝 동안 모델에 노출되어서는 안 된다.
  • 일반적으로 전체 데이터의 50% 이상을 차지한다.
정답: c — 테스트 세트(홀드아웃 세트)는 최종 평가용이며, 학습·튜닝 동안 한 번이라도 노출되면 객관적 평가 기능을 잃는다. 권장 비율은 10~20% 수준이다.
Q3. 다음 시나리오에서 발생한 편향의 유형을 고르시오. "얼굴 인식 카메라를 천장 높이에 설치해 학습 데이터를 수집한 결과, 키 큰 사람의 얼굴이 과대표상되었다."
  • 샘플 편향(Sample Bias)
  • 라벨링 편향(Labelling Bias)
  • 측정 편향(Measurement Bias)
  • 알고리즘 편향(Algorithmic Bias)
정답: c — 측정 도구(카메라)의 설치 환경 자체가 한쪽에 유리하게 작용했으므로 측정 편향이다. 실러버스 4.3절 "불균형 데이터" 항목의 예시와 동일하다.
Q4. 라벨링 접근법 중 "AI 도구가 1차 라벨을 부여하고 사람이 확인·보완"하는 2단계 방식은?
  • 크라우드소싱(Crowdsourcing)
  • AI 지원(AI-assisted)
  • 아웃소싱(Outsourcing)
  • 내부(Internal)
정답: b — AI 지원 방식은 자동 라벨링 후 사람이 검수한다. 크라우드소싱은 다수 참여자의 라벨링을 모으는 방식이고, 하이브리드는 여러 방법을 조합한 방식이다.
