책 개요

Git for Teams: A User-Centered Approach to Creating Efficient Workflows in Git

저자Emma Jane Hogbin Westby
원서 출판O'Reilly Media (2015)

4.0 / 5.0

팀을 위한 git(원제 Git for Teams)은 흔한 Git 책과 결이 다르다. 대부분의 Git 책이 commit, branch, merge 같은 명령어 사용법에 집중하는 반면, 이 책은 "여러 사람이 함께 일할 때 Git을 어떻게 쓸 것인가"라는 질문에서 출발한다.

저자 Emma Jane Hogbin Westby는 1996년부터 웹 개발을 해 온 개발자이자 팀 리드로, 분산 버전 관리와 변경 관리를 오래 가르쳐 왔다. 그 경험을 바탕으로 도구가 아니라 사람과 팀을 중심에 둔 버전 관리 접근을 제시한다.

그래서 대상 독자가 둘로 나뉜다. 워크플로를 설계해야 하는 프로젝트 관리자·팀 리드·CTO, 그리고 Git 명령을 손에 익혀야 하는 개발자다. 책도 그에 맞춰 두 부분으로 구성된다.

왜 이 책인가

Git 명령어를 다 외워도 팀 협업이 매끄럽지 않은 경우가 많다. 브랜치를 언제 따고 언제 합칠지, 리뷰는 어느 시점에 할지, 릴리스는 어떻게 가져갈지 — 이런 약속(워크플로)이 없으면 도구가 아무리 좋아도 충돌과 혼선이 생긴다.

이 책은 그 약속을 어떻게 설계하는지를 다룬다. 팀이 어떻게 구성돼 있고, 소프트웨어가 어떻게 고객에게 전달되는지에 따라 브랜칭 전략이 달라져야 한다는 관점이 핵심이다.

"User-Centered" 의 의미 부제의 "사용자 중심(user-centered)"은 Git의 사용자, 즉 함께 일하는 팀원을 가리킨다. 명령어가 아니라 사람의 작업 흐름에서 출발해 워크플로를 거꾸로 설계한다는 뜻이다.

책의 구성

크게 "워크플로 설계"와 "Git 실습" 두 부분으로 나뉜다. 앞부분은 관리자·리드를 위한 전략, 뒷부분은 개발자를 위한 손에 익히는 실습이다.

부다루는 내용
워크플로 설계팀 구조와 권한, 브랜칭 전략 선택, 코드 리뷰·릴리스 흐름을 팀에 맞게 설계
Git 실습브랜치·병합·충돌 해결 등 핵심 명령을 시나리오로 익히는 hands-on 연습

핵심 내용 몇 가지

브랜칭 전략은 팀에 맞춰 고른다

정답인 단일 브랜칭 전략은 없다. 팀 규모, 릴리스 주기, 배포 방식에 따라 적절한 전략이 다르다. 책은 여러 전략의 장단점을 비교하고, "우리 팀에 맞는 것"을 고르는 기준을 제시한다.

코드 리뷰와 권한을 워크플로에 녹인다

누가 어떤 브랜치에 머지할 수 있는지, 리뷰는 어느 단계에서 강제할지 같은 권한·절차를 Git 워크플로 자체에 설계해 넣는다. 사람의 합의를 도구의 규칙으로 옮기는 셈이다.

충돌은 예방이 먼저다

병합 충돌을 해결하는 기술도 다루지만, 더 강조하는 건 충돌이 적게 나도록 워크플로를 설계하는 것이다. 작은 단위로 자주 합치고, 브랜치 수명을 짧게 가져가는 습관이 핵심이다.

인상 깊은 점

Git을 "기술"이 아니라 "협업의 언어"로 본다는 관점이 신선하다. 같은 명령이라도 팀의 약속이 다르면 의미가 달라진다는 걸 분명히 한다. 명령어만 가르치는 책에서는 못 얻는, "왜 이렇게 쓰기로 했는가"를 설계하는 시야를 준다.

핵심 교훈

팀의 Git을 정리하며 얻은 것 ① 브랜칭 전략에 정답은 없다 — 팀과 배포 방식에 맞춰 고른다. ② 충돌은 해결보다 예방이 먼저다(작게 자주 머지). ③ 권한·리뷰 같은 합의를 워크플로 규칙으로 명시한다. ④ Git은 도구이자 팀의 협업 약속이다.

누구에게 / 어떻게 읽나

팀의 Git 워크플로를 정해야 하는 리드·관리자라면 앞부분(워크플로 설계)이 특히 유용하다. Git이 아직 손에 안 익은 개발자라면 뒷부분 실습부터 봐도 된다. 두 부분이 독립적이라 역할에 맞게 골라 읽기 좋다.

이 블로그와의 연결

본 블로그의 Git 기본 명령어 가이드가 "명령을 어떻게 쓰는가"라면, 이 책은 "팀이 그 명령을 어떤 약속으로 쓰는가"를 다룬다. 또 배포 흐름 설계라는 점에서 신뢰할 수 있는 소프트웨어 출시(Continuous Delivery)와도 맞닿아 있다.

한 줄 평

"Git 명령어 책이 아니라, 팀이 Git을 쓰는 약속을 설계하는 책." 혼자 쓰는 Git과 여럿이 쓰는 Git은 다르다는 걸 일깨워 주는, 팀 리드에게 특히 유용한 안내서다.
