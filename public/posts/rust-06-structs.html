구조체(struct)와 메서드(impl)

2026-06-25 약 8분 분량 Rust 시리즈
이 편에서 배우는 것 Rust에서 여러 값을 하나로 묶는 struct를 정의하고, 그 데이터에 동작을 붙이는 impl 블록을 다룬다. 객체를 만드는 관례인 연관 함수 new, 그리고 #[derive(...)]로 출력·복제 같은 보일러플레이트를 자동 생성하는 법을 익힌다. 마지막으로 이름 없는 필드를 쓰는 튜플 구조체까지 본다. C++의 class를 알고 있다면 "데이터와 동작을 분리한다"는 한 가지 차이만 잡으면 나머지는 자연스럽게 따라온다.

구조체 정의와 필드

구조체(struct)는 서로 관련 있는 여러 값을 하나의 이름 있는 타입으로 묶는 도구다. C++의 struct/class에서 데이터 멤버를 모아 두던 것과 같은 역할이다. 각 필드는 이름과 타입을 가진다.

// 사각형을 나타내는 구조체. 필드마다 이름과 타입을 적는다.
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    // 필드 이름을 명시해 인스턴스를 만든다. 순서는 자유다.
    let rect = Rectangle {
        width: 30,
        height: 50,
    };

    // 점 표기법으로 필드에 접근한다.
    println!("width = {}, height = {}", rect.width, rect.height);
}

인스턴스를 만들 때는 구조체이름 { 필드: 값 } 형태로 모든 필드를 채운다. 값을 바꾸려면 변수 자체가 가변이어야 한다. Rust는 기본이 불변이므로 let mut로 선언한다.

fn main() {
    // 가변 인스턴스. mut가 없으면 필드 대입이 컴파일 오류다.
    let mut rect = Rectangle {
        width: 30,
        height: 50,
    };

    rect.width = 40; // mut라서 허용된다.
    println!("new width = {}", rect.width);
}

struct Rectangle {
    width: u32,
    height: u32,
}
C++과 이렇게 다르다 — 가변성은 필드가 아니라 변수에 붙는다 C++은 멤버마다 const를 붙여 개별 필드의 불변을 표현한다. Rust에는 필드 단위 const가 없다. 인스턴스 전체가 mut이면 모든 필드를 바꿀 수 있고, mut가 아니면 어느 필드도 못 바꾼다. 가변성의 단위가 "멤버"가 아니라 "바인딩(변수)"이라는 점이 첫 번째 차이다.

impl 블록과 메서드

구조체는 데이터만 담는다. 그 데이터에 동작을 붙이려면 별도의 impl 블록에 메서드를 작성한다. 첫 인자가 self 계열이면 메서드, 아니면 연관 함수다. self를 받는 방식은 세 가지이며 의미가 명확히 다르다.

  • &self — 인스턴스를 빌려서 읽기만 한다(불변 빌림).
  • &mut self — 인스턴스를 가변으로 빌려 필드를 수정한다.
  • self — 인스턴스의 소유권을 가져온다(보통 변환·소비용).
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    // &self: 필드를 읽어 넓이를 계산만 한다.
    fn area(&self) -> u32 {
        self.width * self.height
    }

    // &mut self: 인스턴스를 가변으로 빌려 폭을 키운다.
    fn scale_width(&mut self, factor: u32) {
        self.width *= factor;
    }

    // &self: 다른 인스턴스를 인자로 받아 비교한다.
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

fn main() {
    let mut rect = Rectangle { width: 30, height: 50 };
    println!("area = {}", rect.area()); // 1500

    rect.scale_width(2);
    println!("area = {}", rect.area()); // 3000

    let small = Rectangle { width: 10, height: 20 };
    println!("can hold = {}", rect.can_hold(&small)); // true
}

메서드는 인스턴스.메서드()로 호출한다. rect.area()는 컴파일러가 자동으로 (&rect)를 넘겨 주므로 호출 쪽에서 &를 직접 쓸 필요가 없다. 한 타입에 impl 블록을 여러 개 둘 수도 있다.

C++과 이렇게 다르다 — 데이터(struct)와 동작(impl)이 분리된다 C++ class는 데이터 멤버와 멤버 함수를 같은 중괄호 안에 함께 적는다. Rust는 데이터는 struct에, 동작은 impl에 따로 둔다. &self는 C++의 const 멤버 함수, &mut self는 일반(비-const) 멤버 함수, self(값으로 받기)는 호출 후 객체를 소비하는 경우에 대응한다고 보면 감이 잡힌다. 선언과 정의를 .h/.cpp로 나누지 않고, 동작을 데이터와 분리하는 것이 차이다.

연관 함수 new로 생성하기

self를 받지 않는 함수를 연관 함수(associated function)라고 한다. 인스턴스 없이 타입이름::함수()로 호출하며, 가장 흔한 용도가 생성자 역할의 new다. Rust에는 언어 차원의 생성자 문법이 없고, new는 강제 키워드가 아니라 커뮤니티가 합의한 관례다.

struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    // 연관 함수: self가 없고 Self를 반환한다. Self는 Rectangle의 별칭이다.
    fn new(width: u32, height: u32) -> Self {
        Self { width, height } // 인자 이름과 필드 이름이 같으면 축약 표기.
    }

    // 정사각형을 만드는 또 다른 연관 함수.
    fn square(size: u32) -> Self {
        Self { width: size, height: size }
    }

    fn area(&self) -> u32 {
        self.width * self.height
    }
}

fn main() {
    // :: 로 연관 함수를 호출한다(인스턴스가 아직 없으므로).
    let rect = Rectangle::new(30, 50);
    let sq = Rectangle::square(20);

    println!("rect area = {}", rect.area()); // 1500
    println!("sq area = {}", sq.area());      // 400
}

메서드는 점(.)으로, 연관 함수는 이중 콜론(::)으로 호출한다는 점이 다르다. 반환 타입의 Self는 그 impl이 대상으로 하는 타입을 가리키는 별칭이라, 타입 이름을 그대로 적어도 되고 Self로 적어도 된다.

derive 매크로로 보일러플레이트 줄이기

구조체를 그대로 println!("{}", rect)로 출력하려 하면 컴파일되지 않는다. 출력 방법을 컴파일러가 모르기 때문이다. 직접 구현할 수도 있지만, 표준적인 동작이라면 #[derive(...)] 한 줄로 자동 생성하는 게 관례다.

Debug — 디버그 출력

#[derive(Debug)]를 붙이면 {:?}(또는 보기 좋은 {:#?}) 형식 지정자로 구조체를 출력할 수 있다.

// Debug를 파생하면 {:?}로 출력 가능해진다.
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect = Rectangle { width: 30, height: 50 };

    println!("{:?}", rect);  // Rectangle { width: 30, height: 50 }
    println!("{:#?}", rect); // 여러 줄로 보기 좋게 출력
}

Clone — 명시적 복제

#[derive(Clone)]은 .clone() 메서드를 자동 생성한다. Rust는 소유권 때문에 한 값을 다른 변수에 대입하면 기본적으로 이동(move)이 일어나, 원래 변수를 더 못 쓰게 되는 경우가 있다. 원본을 그대로 두고 별도 복사본이 필요할 때 clone()을 쓴다.

// 두 매크로를 한 줄에 함께 파생할 수 있다.
#[derive(Debug, Clone)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let a = Rectangle { width: 30, height: 50 };

    // 명시적으로 복제한다. a는 그대로 살아 있다.
    let b = a.clone();

    println!("a = {:?}", a); // a를 계속 사용 가능
    println!("b = {:?}", b);
}
C++과 이렇게 다르다 — 보일러플레이트를 매크로가 대신 쓴다 C++에서는 출력 연산자(operator<<)나 복사 생성자를 손으로 작성하거나 컴파일러의 암묵 생성에 기대야 했다. Rust는 #[derive(Debug, Clone)] 한 줄로 그 코드를 컴파일 타임에 생성한다. 게다가 복제가 암묵적으로 일어나지 않고 .clone()을 명시해야 하므로, "여기서 복사가 일어난다"가 코드에 그대로 드러난다. 비용이 드는 복사가 숨지 않는 셈이다.

튜플 구조체

필드에 이름을 붙이는 대신 순서로만 구분하는 구조체를 튜플 구조체(tuple struct)라고 한다. 타입에는 이름이 필요하지만 각 필드 이름은 군더더기일 때 쓴다. 좌표나 색처럼 의미가 위치로 분명한 경우가 대표적이다.

// 이름 있는 타입이지만 필드는 위치(.0, .1, .2)로 접근한다.
struct Color(u8, u8, u8);
struct Point(i32, i32);

fn main() {
    let black = Color(0, 0, 0);
    let origin = Point(0, 0);

    // 인덱스로 필드에 접근한다.
    println!("R = {}", black.0);
    println!("x = {}, y = {}", origin.0, origin.1);
}

중요한 점은 같은 내부 구조라도 타입이 다르면 서로 호환되지 않는다는 것이다. Color와 둘 다 (u8, u8, u8)처럼 생긴 다른 튜플 구조체가 있어도, 한쪽을 기대하는 함수에 다른 쪽을 넘기면 컴파일 오류다. 이렇게 같은 표현을 별개 타입으로 구분하면, 의미가 다른 값을 실수로 섞는 버그를 컴파일러가 막아 준다. 인자가 하나뿐인 튜플 구조체는 이런 "뉴타입" 패턴에 특히 자주 쓰인다.

// 같은 u32라도 의미가 다른 두 단위를 별개 타입으로 만든다.
struct Meters(u32);
struct Millimeters(u32);

fn describe(distance: &Meters) {
    println!("{} m", distance.0);
}

fn main() {
    let d = Meters(5);
    describe(&d);

    // describe(&Millimeters(5)); // 타입이 달라 컴파일 오류.
}

정리

  • struct는 데이터 — 관련 값을 이름 있는 타입으로 묶는다. 가변성은 필드가 아니라 변수(let mut)에 붙는다.
  • impl은 동작 — 메서드는 &self(읽기)·&mut self(수정)·self(소비)로 인스턴스를 받고, 점(.)으로 호출한다.
  • new는 관례 — self 없는 연관 함수로 생성하며 ::로 호출한다. 언어 강제가 아니라 합의된 패턴이다.
  • derive는 자동 생성 — #[derive(Debug, Clone)] 한 줄로 출력·복제 코드를 컴파일러가 만든다. 복제는 .clone()으로 명시한다.
  • 튜플 구조체는 위치 기반 — 필드 이름 없이 .0으로 접근하고, 같은 표현이라도 타입이 다르면 섞이지 않아 뉴타입 패턴에 유용하다.
