OpenCV란?

OpenCV(Open Source Computer Vision Library)는 이미지·영상 처리와 컴퓨터 비전을 위한 오픈소스 라이브러리다. 1999년 인텔에서 시작되어 지금은 사실상 비전 분야의 표준 도구로 쓰인다. C++로 작성되었고 Python, Java 바인딩도 제공한다. 산업용 검사, 로보틱스, 의료 영상, 딥러닝 전처리까지 거의 모든 비전 작업의 바탕이 된다.

OpenCV는 거대한 단일 덩어리가 아니라 기능별 모듈로 나뉜다. 필요한 모듈만 골라 링크하면 된다.

모듈역할대표 기능
core기본 자료구조와 연산cv::Mat, 행렬 연산, 기본 타입
imgproc이미지 처리필터, 엣지, 색공간 변환, 기하 변환
imgcodecs이미지 파일 입출력imread, imwrite (PNG, JPG 등)
highgui간단한 GUIimshow, waitKey, 윈도우 생성
videoio영상·카메라 입출력VideoCapture, VideoWriter
features2d특징점 검출·매칭ORB, SIFT, 키포인트 매칭
calib3d카메라 캘리브레이션·3D왜곡 보정, 스테레오, PnP
dnn딥러닝 추론ONNX/Caffe 모델 추론
처음에는 core + imgproc + imgcodecs + highgui면 충분하다 이 네 모듈로 이미지를 읽고, 처리하고, 저장하고, 화면에 띄우는 기본 흐름을 모두 다룰 수 있다. 나머지는 필요할 때 추가한다.

개발 환경 구축

Windows + Visual Studio 2022 환경에서 vcpkg manifest 모드로 OpenCV를 설치한다. manifest 모드는 프로젝트 폴더에 vcpkg.json을 두면 빌드 시 의존성을 자동으로 받아 빌드하는 방식이다. 의존성이 프로젝트에 명시되므로 팀원 간 환경이 일치한다.

vcpkg.json 작성

프로젝트 루트에 vcpkg.json을 만든다.

{
  "name": "opencv-start",
  "version": "0.1.0",
  "dependencies": [
    {
      "name": "opencv4",
      "version>=": "4.10.0",
      "features": ["contrib"]
    }
  ]
}

features에 contrib를 넣으면 SIFT 같은 추가 모듈도 함께 받는다. CUDA가 필요하면 "cuda"를 추가한다. 처음에는 빼고 시작하는 편이 빌드가 빠르다.

CMake로 OpenCV 링크

CMakeLists.txt에서 find_package로 OpenCV를 찾고 타깃에 링크한다.

cmake_minimum_required(VERSION 3.20)
project(opencv_start)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# vcpkg가 설치한 OpenCV를 찾는다
find_package(OpenCV REQUIRED)

add_executable(opencv_start main.cpp)

# OpenCV 헤더 경로 + 라이브러리 연결
target_include_directories(opencv_start PRIVATE ${OpenCV_INCLUDE_DIRS})
target_link_libraries(opencv_start PRIVATE ${OpenCV_LIBS})

구성할 때 vcpkg toolchain 파일을 지정해야 manifest 모드가 동작한다.

cmake -B build -S . ^
  -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake

cmake --build build --config Release
Visual Studio에서 폴더 열기로 바로 쓸 수 있다 VS2022는 CMake 프로젝트를 기본 지원한다. toolchain 파일은 CMakeSettings.json 또는 CMakePresets.json에 한 번만 적어두면 된다.

첫 프로그램 — 이미지 읽고 표시하기

이미지를 디스크에서 읽어 창에 띄우는 가장 기본적인 프로그램이다. imread로 읽고, imshow로 그리고, waitKey로 키 입력을 기다린다.

#include <opencv2/opencv.hpp>
#include <iostream>

int main()
{
    // 이미지를 읽는다 (컬러로). 실패하면 빈 Mat 반환
    cv::Mat image = cv::imread("sample.jpg", cv::IMREAD_COLOR);

    if (image.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    std::cout << "크기: " << image.cols << " x " << image.rows
              << ", 채널: " << image.channels() << std::endl;

    cv::imshow("First Window", image);  // 창에 표시
    cv::waitKey(0);                     // 키 입력까지 대기
    cv::destroyAllWindows();
    return 0;
}
실행 결과 (콘솔)
크기: 1920 x 1080, 채널: 3

imread의 두 번째 인자는 읽기 모드다. IMREAD_COLOR는 3채널 컬러, IMREAD_GRAYSCALE는 1채널 흑백, IMREAD_UNCHANGED는 알파 채널까지 원본 그대로 읽는다. waitKey(0)은 키를 누를 때까지 무한 대기하고, waitKey(30)처럼 양수를 주면 그 밀리초만큼만 기다린다 — 영상 루프에서 자주 쓴다.

cv::Mat 핵심 구조

cv::Mat은 OpenCV의 심장이다. 이름은 Matrix(행렬)이지만 실질적으로는 이미지 컨테이너다. 이미지를 가로 × 세로 격자에 픽셀값이 채워진 행렬로 보기 때문이다.

핵심은 cv::Mat이 헤더(메타데이터)와 데이터(픽셀 버퍼)를 분리해서 관리한다는 점이다. 헤더는 작다 — 크기, 타입, 데이터 포인터 같은 정보만 담는다. 실제 픽셀값이 들어있는 데이터 버퍼는 따로 힙에 잡히고, 여러 Mat이 같은 버퍼를 공유할 수 있다.

cv::Mat은 가벼운 헤더와 무거운 데이터 버퍼로 나뉜다. 헤더의 data 포인터가 버퍼를 가리킨다.

이 구조 덕분에 Mat을 함수 인자로 넘기거나 대입해도 거대한 픽셀 버퍼를 통째로 복사하지 않는다. 헤더만 가볍게 복사되고 데이터 버퍼는 공유된다. 이 동작이 다음 절의 얕은 복사다.

cv::Mat 생성 방법

Mat을 만드는 방법은 여러 가지다. 상황에 맞게 고른다.

생성자로 만들기

// 비어 있는 Mat
cv::Mat empty;

// 행 480, 열 640, 8비트 3채널 — 값은 미초기화
cv::Mat a(480, 640, CV_8UC3);

// 크기를 cv::Size로 지정 (주의: Size는 width, height 순서)
cv::Mat b(cv::Size(640, 480), CV_8UC3);

// 모든 픽셀을 특정 값으로 초기화 (BGR = 회색)
cv::Mat gray(480, 640, CV_8UC3, cv::Scalar(128, 128, 128));
생성자 인자 순서가 헷갈린다 Mat(rows, cols, ...)는 행(height) 먼저지만, cv::Size(width, height)는 너비 먼저다. 둘을 섞어 쓰면 가로세로가 뒤바뀐다.

정적 팩토리 — zeros / ones / eye

// 모든 값 0 (검은 이미지)
cv::Mat z = cv::Mat::zeros(480, 640, CV_8UC1);

// 모든 값 1
cv::Mat o = cv::Mat::ones(3, 3, CV_32FC1);

// 단위 행렬 (대각선만 1)
cv::Mat i = cv::Mat::eye(3, 3, CV_32FC1);

기존 데이터 래핑

카메라 SDK가 넘겨준 버퍼처럼 이미 존재하는 메모리를 Mat으로 감쌀 수 있다. 이때 Mat은 그 버퍼를 소유하지 않는다 — 복사 없이 가리키기만 한다.

unsigned char* sdkBuffer = grabber.GetFrameData();
int w = 1920, h = 1080;

// 외부 버퍼를 가리키는 Mat (데이터 복사 없음)
cv::Mat frame(h, w, CV_8UC1, sdkBuffer);

// 안전하게 보관하려면 깊은 복사로 소유권을 가져온다
cv::Mat owned = frame.clone();
래핑한 Mat은 원본 버퍼가 살아있어야 유효하다 외부 버퍼를 감싼 Mat은 버퍼가 해제되거나 다음 프레임으로 덮어쓰이면 곧바로 깨진 데이터를 가리킨다. 데이터를 오래 들고 있어야 하면 clone()으로 복사하자.

얕은 복사 vs 깊은 복사

cv::Mat을 다룰 때 가장 많이 실수하는 지점이다. 헤더와 데이터가 분리되어 있다는 사실이 여기서 직접 드러난다.

얕은 복사 — 헤더만 복사, 데이터 공유

Mat b = a;나 함수 인자 전달은 헤더만 복사한다. 두 Mat이 같은 픽셀 버퍼를 가리키므로, 한쪽을 수정하면 다른 쪽도 바뀐다.

cv::Mat a = cv::imread("sample.jpg");

cv::Mat b = a;        // 얕은 복사 — b와 a는 같은 데이터 공유
cv::Mat c(a);         // 이것도 얕은 복사

b.setTo(cv::Scalar(0, 0, 0));  // b를 검게 칠하면...
// → a도 검게 변한다! 같은 버퍼이기 때문

깊은 복사 — 데이터까지 복제

원본과 독립된 사본이 필요하면 clone() 또는 copyTo()를 쓴다. 픽셀 버퍼가 통째로 복제된다.

cv::Mat a = cv::imread("sample.jpg");

cv::Mat d = a.clone();   // 깊은 복사 — 완전히 독립된 버퍼

cv::Mat e;
a.copyTo(e);             // 깊은 복사 — e에 새 버퍼 할당 후 복제

d.setTo(cv::Scalar(0, 0, 0));  // d를 검게 칠해도
// → a는 그대로. 서로 다른 버퍼

참조 카운트 기반 메모리 관리

그렇다면 얕은 복사된 Mat 중 하나가 사라지면 데이터는 누가 해제할까? cv::Mat은 데이터 버퍼마다 참조 카운트를 둔다. 같은 버퍼를 가리키는 Mat이 늘면 카운트가 증가하고, 소멸하면 감소한다. 카운트가 0이 되는 순간 버퍼가 자동 해제된다.

std::shared_ptr와 같은 원리다 cv::Mat의 데이터 관리는 std::shared_ptr의 참조 카운트와 동일한 발상이다 — 마지막 소유자가 사라질 때 해제. 그래서 Mat을 값으로 주고받아도 메모리 누수나 이중 해제가 없다. C++ 시리즈의 스마트 포인터 글을 떠올리면 정확히 같은 그림이다. 
cv::Mat a = cv::imread("sample.jpg");  // 버퍼 참조 카운트 = 1
{
    cv::Mat b = a;   // 얕은 복사 → 카운트 = 2
    cv::Mat c = a;   // 얕은 복사 → 카운트 = 3
}                    // b, c 소멸 → 카운트 = 1
// a가 여전히 버퍼를 안전하게 소유
구분코드동작비용
얕은 복사Mat b = a;헤더만 복사, 데이터 공유매우 저렴
얕은 복사Mat c(a);헤더만 복사, 데이터 공유매우 저렴
깊은 복사a.clone()새 버퍼 할당 + 픽셀 복제버퍼 크기에 비례
깊은 복사a.copyTo(b)대상에 복제 (필요 시 재할당)버퍼 크기에 비례

cv::Mat 주요 멤버

Mat을 다룰 때 자주 들여다보는 멤버와 메서드들이다.

cv::Mat img = cv::imread("sample.jpg");  // 1920x1080 컬러

img.rows;          // 1080 — 세로 픽셀 수 (height)
img.cols;          // 1920 — 가로 픽셀 수 (width)
img.channels();    // 3 — 채널 수 (BGR)
img.type();        // 16 — 타입 (CV_8UC3의 정수값)
img.depth();       // 0 — 픽셀 한 개의 비트 깊이 (CV_8U)
img.step;          // 5760 — 한 행의 바이트 수 (1920 * 3)
img.total();       // 2073600 — 전체 픽셀 수 (rows * cols)
img.data;          // unsigned char* — 픽셀 버퍼 시작 주소
img.empty();       // false — 데이터가 없으면 true
멤버의미비고
rows / cols세로 / 가로 픽셀 수멤버 변수 (괄호 없음)
channels()채널 수흑백 1, 컬러 3, 알파 포함 4
type()타입 정수값깊이 + 채널이 합쳐진 코드
depth()픽셀 한 개의 비트 깊이CV_8U, CV_16U, CV_32F 등
step한 행의 바이트 수패딩이 있으면 cols×채널보다 큼
data픽셀 버퍼 포인터직접 접근 시 사용, 위험
total()전체 픽셀 수rows × cols
empty()데이터 유무imread 실패 검사에 필수
step은 cols × 채널과 다를 수 있다 OpenCV는 메모리 정렬을 위해 행 끝에 패딩을 넣기도 한다. 픽셀을 포인터로 직접 순회할 때는 cols * channels()가 아니라 반드시 step을 기준으로 다음 행을 찾아야 한다.

타입 시스템 (CV_8UC3 등)

OpenCV의 타입 코드는 CV_<비트깊이><자료형>C<채널수> 형태다. 예를 들어 CV_8UC3은 8비트 unsigned, 3채널 — 가장 흔한 컬러 이미지 포맷이다.

구성 요소표기의미
비트 깊이8, 16, 32, 64픽셀값 한 개의 비트 수
자료형U / S / FUnsigned / Signed / Float
채널 수C1, C2, C3, C4채널 개수

실무에서 마주치는 조합은 사실 몇 개로 좁혀진다.

타입구성대표 용도
CV_8UC18비트 unsigned, 1채널흑백(그레이스케일) 이미지, 마스크
CV_8UC38비트 unsigned, 3채널일반 컬러 이미지 (BGR)
CV_8UC48비트 unsigned, 4채널알파 채널 포함 (BGRA)
CV_16UC116비트 unsigned, 1채널고비트 산업 카메라, 깊이 영상
CV_32FC132비트 float, 1채널연산 중간 결과, 정밀 계산
CV_32FC332비트 float, 3채널HDR, 정규화된 컬러 처리
// 흑백 마스크
cv::Mat mask(480, 640, CV_8UC1, cv::Scalar(0));

// 16비트 산업 카메라 프레임
cv::Mat frame16(1080, 1920, CV_16UC1);

// float 연산용 버퍼로 변환
cv::Mat colorImg = cv::imread("sample.jpg");  // CV_8UC3
cv::Mat floatImg;
colorImg.convertTo(floatImg, CV_32FC3, 1.0 / 255.0);  // 0~1 정규화
depth는 자료형, type은 자료형 + 채널 depth()는 CV_8U처럼 채널을 뺀 값을, type()은 CV_8UC3처럼 채널까지 포함한 값을 돌려준다. 함수가 특정 타입을 요구할 때 이 차이를 알아야 한다.

흔한 함정

입문 단계에서 거의 모두가 한 번씩 밟는 함정들이다.

빈 Mat 접근

imread가 실패하면 예외를 던지지 않고 빈 Mat을 반환한다. 검사 없이 픽셀에 접근하면 크래시한다.

cv::Mat img = cv::imread("없는파일.jpg");

// 나쁨 — 경로가 틀리면 여기서 크래시
// int v = img.at<uchar>(0, 0);

// 좋음 — 항상 empty() 먼저 검사
if (img.empty())
{
    std::cerr << "로드 실패" << std::endl;
    return -1;
}

얕은 복사를 깊은 복사로 착각

Mat b = a; 는 사본이 아니다 원본을 보존하면서 처리하려고 Mat b = a;로 "복사"한 뒤 b를 수정하면 a까지 망가진다. 두 Mat이 같은 버퍼를 공유하기 때문이다. 독립된 사본이 필요하면 반드시 a.clone()을 써야 한다. 
cv::Mat original = cv::imread("sample.jpg");

// 의도: original은 그대로 두고 result만 흐리게
cv::Mat result = original;            // 함정! 얕은 복사
cv::GaussianBlur(result, result, cv::Size(15, 15), 0);
// → original도 흐려진다

// 올바른 방법
cv::Mat result2 = original.clone();   // 깊은 복사
cv::GaussianBlur(result2, result2, cv::Size(15, 15), 0);
// → original은 안전

채널 순서는 RGB가 아니라 BGR

OpenCV의 컬러 이미지는 BGR 순서다 역사적 이유로 OpenCV는 채널을 Blue, Green, Red 순으로 저장한다. cv::Scalar(255, 0, 0)은 빨강이 아니라 파랑이다. matplotlib나 Qt 등 RGB를 기대하는 라이브러리로 넘길 때는 cv::cvtColor(img, rgb, cv::COLOR_BGR2RGB)로 변환해야 색이 안 뒤집힌다. 
cv::Mat img(100, 100, CV_8UC3, cv::Scalar(255, 0, 0));
// → 파란색 이미지 (B=255). 빨강을 원했다면 Scalar(0, 0, 255)

// 다른 라이브러리에 넘기기 전 RGB로 변환
cv::Mat rgb;
cv::cvtColor(img, rgb, cv::COLOR_BGR2RGB);

imshow 후 waitKey 누락

imshow는 창에 그릴 내용을 예약만 한다. 실제 렌더링과 이벤트 처리는 waitKey가 호출될 때 일어난다. waitKey를 빼면 창이 안 뜨거나 회색으로 멈춘 것처럼 보인다.

cv::imshow("Window", img);
// cv::waitKey 가 없으면 창이 제대로 안 뜬다

cv::waitKey(0);  // 이 줄이 있어야 창이 그려지고 키 입력을 받는다
정리하면 빈 Mat은 empty()로 검사하고, 사본이 필요하면 clone()을 쓰고, 색은 BGR임을 기억하고, imshow 뒤엔 waitKey를 붙인다. 이 네 가지만 몸에 익히면 입문 단계의 버그 대부분을 피한다.
