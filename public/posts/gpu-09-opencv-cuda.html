cv::cuda 모듈 개요

cv::cuda는 OpenCV에 내장된 CUDA 가속 모듈이다. 시리즈 앞부분에서 살펴본 그리드·블록·스레드·shared memory를 직접 다루지 않아도, 친숙한 OpenCV API로 GPU 가속을 그대로 받을 수 있다.

핵심 아이디어는 두 가지다. 첫째, 데이터를 cv::Mat이 아니라 cv::cuda::GpuMat에 담아 GPU 메모리에 올린다. 둘째, cv::resize 대신 cv::cuda::resize를 호출한다. 함수 시그니처와 동작은 거의 동일하다.

화살표가 그려진 대로 업로드 → GPU 처리 → 다운로드 흐름만 잘 지키면 된다. CUDA 커널을 한 줄도 쓰지 않고도 GPU 가속을 받는다.

빌드 요건과 환경 확인

가장 큰 진입 장벽은 빌드다. NuGet이나 OS 패키지 매니저로 받는 일반 OpenCV는 CUDA 지원이 꺼져 있다. cv::cuda 헤더는 있지만 호출하면 예외가 난다. CUDA를 쓰려면 다음 셋 중 하나가 필요하다.

  • vcpkg에서 opencv4[cuda,contrib] 피처로 직접 빌드
  • OpenCV 소스에서 WITH_CUDA=ON, OPENCV_DNN_CUDA=ON으로 CMake 빌드
  • NVIDIA에서 제공하는 CUDA-enabled 빌드 사용

전제 조건은 다음과 같다.

항목요구 사항비고

런타임에서는 이렇게 환경을 확인한다.

#include <opencv2/core/cuda.hpp>
#include <iostream>

int main()
{
	int deviceCount = cv::cuda::getCudaEnabledDeviceCount();
	if (deviceCount == 0)
	{
		std::cerr << "CUDA-enabled OpenCV not available." << std::endl;
		return -1;
	}

	cv::cuda::printShortCudaDeviceInfo(cv::cuda::getDevice());

	cv::cuda::DeviceInfo info(0);
	std::cout << "Name: " << info.name() << "\n"
	          << "Major.Minor: " << info.majorVersion() << "."
	          << info.minorVersion() << "\n"
	          << "Total memory: " << info.totalMemory() / (1024 * 1024) << " MB\n";
	return 0;
}

getCudaEnabledDeviceCount()가 0이면 빌드부터 다시 봐야 한다 OpenCV 자체가 CUDA 없이 빌드되었다는 뜻이다. 헤더는 보이는데 링크가 안 되거나, 실행 시 OpenCV(4.x) Error: No CUDA support 예외가 난다.

cv::cuda::GpuMat

cv::cuda::GpuMat은 한 줄로 정리하면 GPU 메모리에 있는 cv::Mat이다. 인터페이스가 거의 똑같이 생겼다. 호스트 메모리와의 데이터 교환은 upload()와 download()로 한다.

#include <opencv2/opencv.hpp>
#include <opencv2/cudaimgproc.hpp>
#include <opencv2/cudaarithm.hpp>

cv::Mat hostImage = cv::imread("input.png", cv::IMREAD_COLOR);

// 1) 호스트 → 디바이스 업로드
cv::cuda::GpuMat dSrc;
dSrc.upload(hostImage);

// 2) GPU에서 처리
cv::cuda::GpuMat dGray;
cv::cuda::cvtColor(dSrc, dGray, cv::COLOR_BGR2GRAY);

// 3) 디바이스 → 호스트 다운로드
cv::Mat result;
dGray.download(result);

cv::imwrite("gray.png", result);

GpuMat 멤버

대부분의 멤버 이름이 cv::Mat과 같다. 따라서 기존 OpenCV 코드를 옮길 때 학습 부담이 적다.

GpuMat 재사용

GPU 메모리 할당은 비용이 크다. 매 프레임 새로 만들지 말고, 한 번 만들어 두고 재사용한다.

class FrameProcessor
{
public:
	void Process(const cv::Mat& hostFrame, cv::Mat& hostResult)
	{
		// 동일 크기·타입이면 메모리를 재사용한다.
		m_dSrc.upload(hostFrame);
		cv::cuda::cvtColor(m_dSrc, m_dGray, cv::COLOR_BGR2GRAY);
		cv::cuda::threshold(m_dGray, m_dBin, 128, 255, cv::THRESH_BINARY);
		m_dBin.download(hostResult);
	}

private:
	cv::cuda::GpuMat m_dSrc;
	cv::cuda::GpuMat m_dGray;
	cv::cuda::GpuMat m_dBin;
};

간단한 함수 호출 예시다.

#include <opencv2/cudaarithm.hpp>
#include <opencv2/cudaimgproc.hpp>
#include <opencv2/cudawarping.hpp>

cv::cuda::GpuMat dSrc;
dSrc.upload(hostImage);

// 색 변환
cv::cuda::GpuMat dGray;
cv::cuda::cvtColor(dSrc, dGray, cv::COLOR_BGR2GRAY);

// 리사이즈 (1/2 축소)
cv::cuda::GpuMat dSmall;
cv::cuda::resize(dGray, dSmall, cv::Size(), 0.5, 0.5, cv::INTER_LINEAR);

// 임계화
cv::cuda::GpuMat dBin;
cv::cuda::threshold(dSmall, dBin, 128, 255, cv::THRESH_BINARY);

// minMaxLoc — 결과는 호스트 값으로 받는다
double minVal, maxVal;
cv::Point minLoc, maxLoc;
cv::cuda::minMaxLoc(dGray, &minVal, &maxVal, &minLoc, &maxLoc);
입력 타입을 잘 확인하자 GPU 함수는 CPU 버전보다 지원 타입이 좁은 경우가 많다. 예를 들어 cv::cuda::threshold는 CV_8UC1, CV_32FC1 같은 일부 타입만 받는다. 입력 타입이 안 맞으면 예외가 난다.

Filter 객체 — 반복 호출 최적화

가우시안 블러처럼 커널 자체가 매번 재사용되는 연산은, 호출할 때마다 커널을 새로 만드는 비용이 아깝다. 그래서 cv::cuda는 필터를 Ptr<Filter> 객체로 미리 만들어 두고 apply()로 반복 적용하는 패턴을 쓴다.

#include <opencv2/cudafilters.hpp>

// 한 번만 만든다 — 5x5 커널, sigma 1.5
cv::Ptr<cv::cuda::Filter> gaussian =
	cv::cuda::createGaussianFilter(CV_8UC1, CV_8UC1, cv::Size(5, 5), 1.5);

cv::cuda::GpuMat dSrc, dBlur;
for (int i = 0; i < 1000; ++i)
{
	GrabFrameToGpu(dSrc);          // 카메라에서 GPU로 직접 업로드(가상 예시)
	gaussian->apply(dSrc, dBlur);  // 반복 호출 — 빠르다
	UseResult(dBlur);
}

다른 필터들도 같은 패턴이다.

// Canny 엣지 — 임계값을 고정해 두고 반복 호출
cv::Ptr<cv::cuda::CannyEdgeDetector> canny =
	cv::cuda::createCannyEdgeDetector(50.0, 150.0);
canny->detect(dGray, dEdge);

// 모폴로지 — 열림 연산
cv::Mat kernel = cv::getStructuringElement(cv::MORPH_RECT, cv::Size(3, 3));
cv::Ptr<cv::cuda::Filter> opening =
	cv::cuda::createMorphologyFilter(cv::MORPH_OPEN, CV_8UC1, kernel);
opening->apply(dBin, dOpen);

// 박스 필터 (평균)
cv::Ptr<cv::cuda::Filter> box =
	cv::cuda::createBoxFilter(CV_8UC1, CV_8UC1, cv::Size(7, 7));
box->apply(dGray, dMean);
Filter 객체는 멤버 변수로 보관하자 매 프레임 createGaussianFilter를 다시 호출하면 GPU 상수 메모리 셋업 비용이 매번 든다. 클래스 멤버 cv::Ptr<cv::cuda::Filter>로 한 번 만들고, 파라미터가 바뀔 때만 다시 만들자.

특징점 GPU 가속

특징점 검출과 매칭은 CPU에서 무거운 연산이라 GPU 효과가 크다. cv::cuda는 ORB와 FAST를 기본으로 제공한다.

#include <opencv2/cudafeatures2d.hpp>

// ORB 검출기 — 최대 1000개 특징점
cv::Ptr<cv::cuda::ORB> orb = cv::cuda::ORB::create(1000);

cv::cuda::GpuMat dGray;
dGray.upload(hostGray);

cv::cuda::GpuMat dKeypoints;   // 키포인트 (GPU 표현)
cv::cuda::GpuMat dDescriptors; // 디스크립터
orb->detectAndCompute(dGray, cv::cuda::GpuMat(), dKeypoints, dDescriptors);

// 호스트에서 해석 가능한 KeyPoint 벡터로 변환
std::vector<cv::KeyPoint> keypoints;
orb->convert(dKeypoints, keypoints);

// 디스크립터 매칭도 GPU에서
cv::Ptr<cv::cuda::DescriptorMatcher> matcher =
	cv::cuda::DescriptorMatcher::createBFMatcher(cv::NORM_HAMMING);
std::vector<cv::DMatch> matches;
matcher->match(dDescriptors1, dDescriptors2, matches);

FAST 검출기도 비슷한 방식이다.

cv::Ptr<cv::cuda::FastFeatureDetector> fast =
	cv::cuda::FastFeatureDetector::create(40, true);

std::vector<cv::KeyPoint> kp;
fast->detect(dGray, kp);

cv::cuda::Stream — 비동기 실행

시리즈 #5에서 다룬 CUDA Stream의 OpenCV 래퍼다. cv::cuda::Stream 객체를 만들어 GPU 함수의 마지막 인자로 넘기면, 그 호출이 비동기로 큐잉된다.

cv::cuda::Stream stream;

cv::cuda::GpuMat dSrc, dGray, dBlur, dEdge;

// 비동기 업로드 — 핀드 메모리에서 출발해야 진짜 비동기다
dSrc.upload(hostImage, stream);

// 비동기 처리
cv::cuda::cvtColor(dSrc, dGray, cv::COLOR_BGR2GRAY, 0, stream);

cv::Ptr<cv::cuda::Filter> gauss =
	cv::cuda::createGaussianFilter(CV_8UC1, CV_8UC1, cv::Size(5,5), 1.2);
gauss->apply(dGray, dBlur, stream);

cv::Ptr<cv::cuda::CannyEdgeDetector> canny =
	cv::cuda::createCannyEdgeDetector(50, 150);
canny->detect(dBlur, dEdge, stream);

// 비동기 다운로드
cv::Mat hostEdge;
dEdge.download(hostEdge, stream);

// 여기까지는 즉시 반환됨. 결과를 쓰기 전 동기화 필수.
stream.waitForCompletion();
UseResult(hostEdge);

Stream을 두 개 이상 만들면 GPU 처리와 PCIe 전송을 겹쳐 처리량을 높일 수 있다. 시리즈 #5의 더블 버퍼링 패턴이 그대로 적용된다.

호스트 메모리는 pinned여야 진짜 비동기다 일반 cv::Mat의 메모리는 pageable이라 upload/download가 내부적으로 동기 동작이 된다. 진짜 오버랩이 필요하면 cv::cuda::HostMem (page-locked)을 써서 호스트 버퍼를 잡아야 한다.

cv::dnn으로 GPU 추론

OpenCV DNN 모듈도 CUDA 백엔드를 지원한다. AI 시리즈 #12에서 다룬 OpenCV DNN을 GPU로 돌리려면 두 줄만 추가하면 된다.

#include <opencv2/dnn.hpp>

cv::dnn::Net net = cv::dnn::readNetFromONNX("yolov8n.onnx");

// 핵심 — 백엔드와 타깃을 CUDA로 지정
net.setPreferableBackend(cv::dnn::DNN_BACKEND_CUDA);
net.setPreferableTarget(cv::dnn::DNN_TARGET_CUDA);          // FP32
// net.setPreferableTarget(cv::dnn::DNN_TARGET_CUDA_FP16);  // FP16, 더 빠르다

cv::Mat blob = cv::dnn::blobFromImage(image, 1.0/255, cv::Size(640, 640),
                                      cv::Scalar(), true, false);
net.setInput(blob);
cv::Mat output = net.forward();

전제 조건은 OpenCV가 WITH_CUDA=ON + OPENCV_DNN_CUDA=ON + cuDNN으로 빌드되었을 것이다. DNN_TARGET_CUDA_FP16은 Compute Capability 5.3 이상에서 의미가 있다.

백엔드 / 타깃 조합설명전제
DNN_BACKEND_OPENCV + DNN_TARGET_CPU기본 CPU 추론없음
DNN_BACKEND_OPENCV + DNN_TARGET_OPENCLOpenCL GPU (NV/AMD/Intel)OpenCL 드라이버
DNN_BACKEND_CUDA + DNN_TARGET_CUDANVIDIA GPU, FP32CUDA + cuDNN 빌드
DNN_BACKEND_CUDA + DNN_TARGET_CUDA_FP16NVIDIA GPU, FP16 (가장 빠름)CC 5.3+, cuDNN
cv::dnn CUDA vs TensorRT cv::dnn CUDA 백엔드는 셋업이 쉽지만, 모델 그래프를 풀로 최적화하지는 않는다. 같은 모델·같은 GPU에서 TensorRT(시리즈 #11)가 2~4배 빠른 경우가 흔하다. 빠른 프로토타이핑은 cv::dnn, 양산은 TensorRT 식의 분기가 자연스럽다.

언제 cv::cuda를 쓸까

cv::cuda는 만능이 아니다. 직접 CUDA 커널을 짜는 것과 비교했을 때 다음과 같은 트레이드오프가 있다.

상황권장이유
표준적인 이미지 처리 파이프라인(블러·엣지·임계화)cv::cudaOpenCV 함수가 이미 잘 튜닝됨. 작성 비용 거의 0
이미 CPU OpenCV로 짜여 있는 코드를 GPU로 옮길 때cv::cuda함수 이름이 거의 같아 마이그레이션이 쉽다
여러 연산을 한 커널에 융합(fusion)해야 할 때직접 커널cv::cuda는 함수마다 별도 커널 → 메모리 트래픽 손해
알고리즘이 OpenCV에 없는 경우(특수 측정·전용 검사)직접 커널cv::cuda 자체가 없다
딥러닝 추론cv::dnn (CUDA) or TensorRTcv::cuda는 추론용이 아니다
여러 GPU 라이브러리(NPP, cuFFT, TensorRT)와 혼용직접 커널 + GpuMatGpuMat의 data 포인터를 다른 라이브러리에 넘길 수 있다

현실적인 패턴은 cv::cuda를 베이스라인으로 깔고, 병목 단계만 커스텀 커널로 교체하는 것이다. 시리즈 #10에서 이 커스텀 커널 작성을 다룬다.

산업 비전 파이프라인 관점

산업 비전에서 cv::cuda의 가치는 명확하다. 카메라가 GenICam으로 매초 수십~수백 프레임을 쏘는 환경에서, CPU 한 코어로 다 처리하기 어렵다. GPU로 옮기되 직접 커널 짤 인력은 부족하다. cv::cuda는 이 간극을 메운다.

이상적인 흐름은 다음과 같다.

  1. 카메라 프레임을 핀드 호스트 메모리로 grab한다 (PCIe DMA 효율을 위해)
  2. GpuMat::upload(stream)으로 비동기 업로드
  3. GPU 위에서 cvtColor → blur → threshold → 모폴로지 → 측정 등 모든 처리
  4. 결과는 최소한만 download — 마스크 이미지 전체가 아니라 측정값(double, int) 위주로
  5. UI에 띄울 미리보기는 다운샘플링해서 작은 이미지만 다운로드
class VisionPipeline
{
public:
	VisionPipeline()
	{
		m_gaussian = cv::cuda::createGaussianFilter(
			CV_8UC1, CV_8UC1, cv::Size(5, 5), 1.5);
		m_canny = cv::cuda::createCannyEdgeDetector(50, 150);
	}

	// 측정값만 호스트로 돌려준다.
	ErrorCode ProcessFrame(const cv::Mat& hostFrame, double& outDefectArea)
	{
		if (hostFrame.empty())
		{
			return ErrorCode::InvalidInput;
		}

		m_dColor.upload(hostFrame, m_stream);
		cv::cuda::cvtColor(m_dColor, m_dGray, cv::COLOR_BGR2GRAY, 0, m_stream);
		m_gaussian->apply(m_dGray, m_dBlur, m_stream);
		cv::cuda::threshold(m_dBlur, m_dBin, 128, 255, cv::THRESH_BINARY, m_stream);
		m_canny->detect(m_dBlur, m_dEdge, m_stream);

		// 면적은 countNonZero — 결과는 작은 정수
		int defectPixels = cv::cuda::countNonZero(m_dBin);
		outDefectArea = static_cast<double>(defectPixels);

		m_stream.waitForCompletion();
		return ErrorCode::Ok;
	}

private:
	cv::cuda::Stream m_stream;
	cv::cuda::GpuMat m_dColor, m_dGray, m_dBlur, m_dBin, m_dEdge;
	cv::Ptr<cv::cuda::Filter> m_gaussian;
	cv::Ptr<cv::cuda::CannyEdgeDetector> m_canny;
};

핵심은 GpuMat 재사용 + Filter 객체 보관 + Stream으로 비동기 + 다운로드 최소화의 네 가지다. 이 패턴만 지켜도 OpenCV CPU 구현보다 수 배 빠른 파이프라인을 얻을 수 있다.

흔한 함정

CUDA 미빌드 OpenCV에서 cv::cuda 호출

가장 흔한 사고다. 헤더와 링크는 되지만 첫 호출에서 CUDA support is not available 예외가 난다. 시작할 때 항상 getCudaEnabledDeviceCount()를 확인해 빠르게 실패시키자.

upload/download를 자주 하면 가속 효과가 사라진다

PCIe 전송 대역폭은 GPU 연산 대역폭보다 훨씬 좁다. 업로드 → 한 함수 처리 → 다운로드를 반복하는 코드는 CPU보다도 느릴 수 있다. GPU 안에서 가능한 한 많은 단계를 처리한 뒤 마지막에 한 번만 내려받자.

안티 패턴 upload → cuda::resize → download → 다음 함수 → upload → cuda::threshold → download ... 같은 코드는 PCIe 왕복만 잔뜩 발생한다. 결과적으로 CPU 단일 함수만 부르는 것보다 느려진다.

작은 이미지에선 CPU가 더 빠를 수 있다

GPU는 데이터 병렬성으로 이긴다. 320x240 그레이스케일 같은 작은 이미지에선 커널 런치 오버헤드와 전송 비용이 연산 시간을 압도해 CPU가 이긴다. 벤치마크해서 손익분기점을 알아 두자. 보통 1~2 MP 이상부터 GPU가 유리하다.

GpuMat 메모리 누수와 단편화

GpuMat은 RAII로 자동 해제되지만, 매 프레임 새로 cv::cuda::GpuMat tmp; 식으로 만들면 GPU 메모리 단편화가 일어난다. 멤버 변수로 잡아 두고 재사용하자. 또 같은 크기·타입이면 OpenCV 내부적으로 메모리를 재사용한다.

지원 타입이 좁다

cv::cuda 함수는 CPU 버전보다 받는 타입이 좁다. 컴파일은 되는데 런타임에 Unsupported format 예외가 난다면 입력의 type()을 출력해서 확인하자.

Stream 결과를 동기화 없이 사용

비동기 호출 직후 결과 GpuMat을 download하지 않고 호스트에서 바로 쓰면 데이터가 비어 있거나 이전 프레임 결과가 보인다. 결과를 쓰기 전에 반드시 stream.waitForCompletion() 또는 동기 download를 호출하자.

CUDA Toolkit과 OpenCV 버전 호환

최신 CUDA 12.x로 구버전 OpenCV(4.5 이하)를 빌드하면 곳곳에서 컴파일 에러가 난다. OpenCV 릴리스 노트에서 권장 CUDA 버전을 확인하고, 가능하면 OpenCV도 최신을 쓰자.
