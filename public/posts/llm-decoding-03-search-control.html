Beam search — likelihood의 함정

beam search는 매 스텝 상위 b개 후보 시퀀스를 동시에 유지하며 전체 확률(likelihood)이 가장 높은 시퀀스를 찾는 탐색이다. 기계번역·요약처럼 "정답이 대체로 하나"인 태스크에서는 강력하다.

그런데 자유 창작·대화에서는 오히려 품질을 떨어뜨린다. 이유는 "가장 그럴듯한(likely) 텍스트"가 "가장 좋은 텍스트"가 아니기 때문이다. likelihood를 극대화하면 모델은 안전하고 반복적이며 김빠진 문장으로 수렴한다 — 같은 구절을 되풀이하거나, 뻔한 결말로 빠진다. 이를 "likelihood trap" 또는 neural text degeneration이라 부른다(1편에서 언급한 nucleus sampling 논문의 출발점이기도 하다).

핵심 직관 사람이 쓴 글은 의외로 "확률이 들쭉날쭉한" 토큰의 연속이다. 늘 최고 확률만 이으면 사람 글의 자연스러운 변동성이 사라진다. 그래서 창작·대화에는 beam search 대신 sampling(top-p/min-p)이, 번역·요약처럼 정답이 좁은 태스크에는 beam이 어울린다.

Best-of-n과 다중 생성

n은 한 번의 요청으로 여러 개를 독립 샘플링하는 것이고, best-of-n은 n개를 생성한 뒤 점수가 가장 높은 하나만 고르는 것이다. 차이가 중요하다 — best-of-n은 n개를 다 생성하므로 비용·지연이 n배인데 결과는 1개만 받는다.

  • 잘 쓰는 곳: 검증 가능한 태스크(코드 → 테스트 통과 여부, 수학 → 정답 일치)에서 n개 뽑아 자동 채점 후 최고를 고르면 정확도가 크게 오른다. self-consistency도 같은 계열.
  • 오해: best-of-n은 "더 좋은 모델"이 아니라 "더 많이 시도"다. 좋은 답이 분포 안에 있을 때만 효과가 있다. 분포 자체가 틀리면 n을 늘려도 소용없다.

Logit bias — 토큰 강제와 금지

logit bias는 특정 토큰의 logit에 상수를 더하거나 빼서 등장 확률을 직접 조작한다. 디코딩 파라미터 중 가장 외과적인 도구다.

z_token ← z_token + bias      # bias: -100 ~ +100 (구현마다)
bias = -100  → 사실상 완전 금지
bias = +5    → 강하게 선호
  • 금지 용도: 특정 단어·기호가 절대 나오면 안 될 때 해당 토큰에 큰 음수. 단, 토큰 단위라 "단어"가 여러 토큰으로 쪼개지면 일부만 막혀 우회된다 — 토크나이저를 확인해야 한다.
  • 강제 용도: 분류기처럼 답을 " Yes"/" No" 토큰으로만 받고 싶을 때, 그 토큰들에 +bias를 주고 나머지를 억제하면 출력 공간을 좁힐 수 있다.
  • 함정: bias는 logit 절대값에 더해지므로, 모델이 원래 강하게 확신하는 자리에서는 작은 bias가 무력하고, 애매한 자리에서는 같은 bias가 과하게 작동한다. 맥락마다 효과가 다르다.

구조적 디코딩 (constrained decoding)

"JSON으로 답해줘"라고 프롬프트로 부탁하는 것과, 디코딩 단계에서 문법을 강제하는 것은 차원이 다르다. 구조적 디코딩은 매 스텝 문법(grammar)·스키마에 맞지 않는 토큰의 logit을 −∞로 만들어 애초에 뽑힐 수 없게 한다.

매 스텝:
  허용 토큰 집합 = 문법상 지금 올 수 있는 토큰들
  그 외 모든 토큰 logit ← -inf
  → 남은 것 중에서만 샘플링

그래서 JSON 스키마·정규식·문맥자유문법(CFG)을 100% 보장할 수 있다(GBNF, JSON mode, structured output 등). 프롬프트로 "제발 JSON만"이라고 비는 것과 달리 형식 위반이 구조적으로 불가능해진다.

알아둘 트레이드오프 구조적 디코딩은 형식은 보장하지만, 강한 제약이 모델을 "부자연스러운 경로"로 밀어 내용 품질이 떨어질 수 있다. 스키마를 너무 빡빡하게 잡으면 모델이 좋은 답을 못 내는 자리로 몰린다. 형식 보장과 내용 자유 사이의 균형이 필요하다.

태스크별 튜닝 레시피

위 도구들을 종합한 실전 출발점이다. 절대값이 아니라 "어디서 시작해 어느 방향으로 움직일지"의 지도로 쓰면 된다.

태스크권장 출발점이유
코드 생성T 0.0~0.2, penalty 0, 구조적 디코딩(가능하면)정답이 좁고 반복이 정상 — penalty가 독
사실 QA / 추출T 0~0.3, top-p 1.0일관성·재현성 우선
창작 / 브레인스토밍T 0.9~1.2 + min-p 0.05~0.1다양성 확보, min-p로 붕괴 방지
대화 / 어시스턴트T 0.6~0.8, top-p 0.9자연스러움과 안정성의 균형
번역 / 요약beam search(b=4~8) 또는 낮은 T정답이 좁아 likelihood 탐색이 유효
JSON / 구조 출력구조적 디코딩 + 낮은 T형식 보장이 최우선

정리

핵심 요약 ① beam search는 정답이 좁은 태스크용 — 창작에선 likelihood trap. ② best-of-n은 "더 많이 시도", 검증 가능한 태스크에서 강력하지만 비용 n배. ③ logit bias는 외과적이지만 토큰 단위·맥락 의존. ④ 구조적 디코딩은 형식을 100% 보장하되 내용 품질과 트레이드오프. ⑤ 파라미터엔 절대 정답이 없다 — 태스크의 "정답 폭"에 맞춘다.
