정렬과 탐색이 기본인 이유

정렬(sorting)은 데이터를 일정한 순서로 나열하는 것이고, 탐색(searching)은 데이터 더미에서 원하는 값을 찾는 것이다. 이 두 가지는 거의 모든 프로그램이 끊임없이 반복하는 작업이다. 검색 결과를 순위대로 보여주고, 로그를 시간순으로 정리하고, 사용자 목록에서 특정 ID를 찾고, 측정값 배열에서 중앙값을 구한다 — 전부 정렬과 탐색이다.

두 작업은 깊게 얽혀 있다. 정렬된 데이터에서는 이진 탐색으로 O(log n)에 값을 찾을 수 있지만, 정렬되지 않은 데이터에서는 처음부터 끝까지 훑는 O(n) 선형 탐색밖에 쓸 수 없다. 즉 한 번 정렬해 두면 이후의 모든 탐색이 빨라진다. "먼저 정렬하고, 그다음 탐색한다"는 패턴이 알고리즘 설계의 기본기인 이유다.

정렬 알고리즘은 또한 알고리즘을 배우는 교과서적 소재다. 같은 문제를 푸는 여러 방법이 시간 복잡도, 메모리 사용량, 안정성에서 어떻게 다른지를 가장 선명하게 보여준다. 버블 정렬에서 인트로 정렬까지의 흐름을 따라가면 "더 나은 알고리즘이란 무엇인가"에 대한 감각이 생긴다.

이 글의 코드 표기 예제는 C++17 기준이며, 설명을 위해 int 배열을 정렬한다. 멤버 변수는 m_ 접두사, 메서드는 PascalCase, 중괄호는 Allman 스타일을 따른다. 비교 함수와 제네릭 처리는 STL 절에서 별도로 다룬다.

버블 정렬

버블 정렬(bubble sort)은 인접한 두 원소를 비교해 순서가 어긋나면 교환하는 과정을 반복한다. 한 번 훑을 때마다 가장 큰 값이 거품처럼 끝으로 떠오른다고 해서 이런 이름이 붙었다. 가장 단순하지만 가장 느린 정렬 중 하나로, 거의 교육용으로만 쓰인다.

동작 원리

배열을 왼쪽부터 훑으면서 arr[i]와 arr[i+1]을 비교한다. 앞이 더 크면 둘을 맞바꾼다. 한 바퀴를 다 돌면 가장 큰 값이 맨 끝에 자리 잡는다. 다음 바퀴는 그 끝을 제외하고 다시 훑는다. 이를 n−1번 반복하면 정렬이 끝난다.

// 인접한 두 원소를 비교·교환하며 가장 큰 값을 끝으로 보낸다.
void BubbleSort(std::vector<int>& arr)
{
    const size_t n = arr.size();
    for (size_t i = 0; i < n - 1; ++i)
    {
        bool swapped = false;
        // 매 패스마다 마지막 i개는 이미 정렬되어 있다.
        for (size_t j = 0; j < n - 1 - i; ++j)
        {
            if (arr[j] > arr[j + 1])
            {
                std::swap(arr[j], arr[j + 1]);
                swapped = true;
            }
        }
        // 한 패스에서 교환이 없었다면 이미 정렬된 상태다.
        if (!swapped)
        {
            break;
        }
    }
}
[5, 2, 4, 1] 정렬 과정
패스 1: [2, 4, 1, 5] (5가 끝으로 이동) 패스 2: [2, 1, 4, 5] (4가 자리잡음) 패스 3: [1, 2, 4, 5] (정렬 완료)

swapped 플래그는 작은 최적화다. 한 패스 동안 한 번도 교환이 없었다면 이미 정렬된 것이므로 일찍 종료한다. 그래도 최악·평균 시간 복잡도는 O(n²)이며, 데이터가 조금만 커져도 실용성이 없다. 버블 정렬은 "정렬이 왜 어려운 문제인지"를 보여주는 출발점일 뿐이다.

선택 정렬 / 삽입 정렬

선택 정렬과 삽입 정렬도 O(n²) 정렬이지만, 버블 정렬보다 동작이 직관적이고 삽입 정렬은 특정 상황에서 매우 빠르다.

선택 정렬

선택 정렬(selection sort)은 매번 남은 부분에서 가장 작은 값을 찾아 맨 앞에 놓는다. "최솟값을 골라(select) 앞으로 보낸다"는 단순한 전략이다. 교환 횟수가 최대 n−1번으로 적다는 점이 특징이지만, 비교 횟수는 항상 O(n²)이다.

// 남은 구간에서 최솟값을 찾아 앞으로 보낸다.
void SelectionSort(std::vector<int>& arr)
{
    const size_t n = arr.size();
    for (size_t i = 0; i < n - 1; ++i)
    {
        size_t minIndex = i;
        for (size_t j = i + 1; j < n; ++j)
        {
            if (arr[j] < arr[minIndex])
            {
                minIndex = j;
            }
        }
        // 찾은 최솟값을 현재 위치로 교환한다.
        if (minIndex != i)
        {
            std::swap(arr[i], arr[minIndex]);
        }
    }
}

삽입 정렬

삽입 정렬(insertion sort)은 카드를 정렬하는 방식과 같다. 왼쪽 구간을 "이미 정렬된 영역"으로 두고, 다음 원소를 그 안의 올바른 위치에 끼워 넣는다. 끼워 넣을 자리를 찾으려고 큰 값들을 오른쪽으로 한 칸씩 민다.

// 정렬된 왼쪽 구간에 다음 원소를 올바른 자리에 끼워 넣는다.
void InsertionSort(std::vector<int>& arr)
{
    const size_t n = arr.size();
    for (size_t i = 1; i < n; ++i)
    {
        int key = arr[i];
        size_t j = i;
        // key보다 큰 값들을 오른쪽으로 한 칸씩 민다.
        while (j > 0 && arr[j - 1] > key)
        {
            arr[j] = arr[j - 1];
            --j;
        }
        arr[j] = key;
    }
}

삽입 정렬의 진짜 가치는 거의 정렬된 데이터에서 드러난다. 이미 정렬되어 있다면 while 조건이 매번 거짓이 되어 한 바퀴만 돌고 끝난다 — 이 경우 시간 복잡도가 O(n)이다. 데이터가 작거나 거의 정렬된 상황에서는 삽입 정렬이 퀵 정렬보다도 빠르다. 이 때문에 실무의 고성능 정렬은 작은 구간을 삽입 정렬로 마무리한다.

O(n²) 정렬이 무가치한 것은 아니다 삽입 정렬은 원소 수가 수십 개 이하로 작을 때 분할정복 정렬보다 오버헤드가 적어 더 빠르다. 그래서 std::sort 같은 인트로 정렬도 재귀가 작은 구간에 도달하면 삽입 정렬로 전환한다. "느린 알고리즘"이라는 꼬리표는 입력 크기를 전제로 한 말이다.

병합 정렬 (Merge Sort)

병합 정렬(merge sort)은 분할정복(divide and conquer) 전략의 대표 예다. 배열을 절반으로 계속 쪼개 더 이상 쪼갤 수 없을 때까지 내려간 뒤, 정렬된 두 조각을 병합(merge)하며 다시 올라온다. 어떤 입력에서도 O(n log n)을 보장하고, 안정 정렬이다.

분할과 병합

핵심은 "정렬된 두 배열을 합치는 것은 쉽다"는 사실이다. 두 배열의 맨 앞을 비교해 작은 쪽을 결과에 넣고 그쪽 포인터만 전진시키면, 한 번 훑는 것만으로 병합이 끝난다. 분할은 단순히 중간 지점에서 둘로 나누는 것뿐이다.

병합 정렬 — 절반으로 분할해 내려간 뒤, 정렬된 조각을 병합하며 올라온다
// 정렬된 두 구간 [lo, mid], [mid+1, hi]를 하나로 병합한다.
void Merge(std::vector<int>& arr, int lo, int mid, int hi)
{
    std::vector<int> buffer;
    buffer.reserve(hi - lo + 1);

    int i = lo;
    int j = mid + 1;
    // 두 구간의 앞쪽을 비교해 작은 값을 먼저 담는다.
    while (i <= mid && j <= hi)
    {
        if (arr[i] <= arr[j])   // <= 이므로 안정 정렬이 유지된다.
        {
            buffer.push_back(arr[i++]);
        }
        else
        {
            buffer.push_back(arr[j++]);
        }
    }
    while (i <= mid) { buffer.push_back(arr[i++]); }
    while (j <= hi)  { buffer.push_back(arr[j++]); }

    // 병합 결과를 원본 구간에 되돌린다.
    for (int k = 0; k < static_cast<int>(buffer.size()); ++k)
    {
        arr[lo + k] = buffer[k];
    }
}

// 배열을 절반으로 나눠 재귀 정렬한 뒤 병합한다.
void MergeSort(std::vector<int>& arr, int lo, int hi)
{
    if (lo >= hi)
    {
        return;
    }
    const int mid = lo + (hi - lo) / 2;   // 오버플로우를 피하는 중간값 계산.
    MergeSort(arr, lo, mid);
    MergeSort(arr, mid + 1, hi);
    Merge(arr, lo, mid, hi);
}

병합 정렬은 분할 깊이가 log n이고 각 깊이에서 전체 n개를 병합하므로 항상 O(n log n)이다. 단점은 병합용 보조 배열이 필요해 O(n)의 추가 메모리를 쓴다는 점이다. 그 대신 arr[i] <= arr[j] 비교 덕분에 같은 값의 순서가 보존되는 안정 정렬이며, 연결 리스트 정렬이나 외부 정렬(메모리에 다 안 들어가는 데이터)에 강하다.

퀵 정렬 (Quick Sort)

퀵 정렬(quick sort) 역시 분할정복이지만 접근이 반대다. 병합 정렬은 "단순 분할 → 어려운 병합"인 반면, 퀵 정렬은 "어려운 분할 → 병합 불필요"다. 평균 O(n log n)에 in-place로 동작해 실무에서 가장 널리 쓰인다.

피벗과 분할

퀵 정렬은 피벗(pivot) 한 개를 고른 뒤, 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 모은다(partition). 이 과정이 끝나면 피벗은 최종 위치에 확정되고, 왼쪽과 오른쪽을 각각 재귀로 정렬한다. 양쪽이 정렬되면 이어 붙일 필요 없이 그대로 끝난다.

// 마지막 원소를 피벗으로 삼아 작은 값을 왼쪽으로 모은다.
int Partition(std::vector<int>& arr, int lo, int hi)
{
    const int pivot = arr[hi];
    int i = lo - 1;   // 작은 값 구간의 마지막 인덱스.
    for (int j = lo; j < hi; ++j)
    {
        if (arr[j] < pivot)
        {
            ++i;
            std::swap(arr[i], arr[j]);
        }
    }
    // 피벗을 작은 값 구간 바로 뒤에 놓는다.
    std::swap(arr[i + 1], arr[hi]);
    return i + 1;
}

// 피벗 기준으로 분할한 뒤 양쪽을 재귀 정렬한다.
void QuickSort(std::vector<int>& arr, int lo, int hi)
{
    if (lo >= hi)
    {
        return;
    }
    const int p = Partition(arr, lo, hi);
    QuickSort(arr, lo, p - 1);
    QuickSort(arr, p + 1, hi);
}

피벗 선택과 최악의 경우

퀵 정렬의 성능은 피벗을 얼마나 잘 고르느냐에 달려 있다. 피벗이 매번 구간을 절반으로 나누면 O(n log n)이지만, 매번 최솟값이나 최댓값이 피벗으로 잡히면 한쪽이 비고 다른 쪽에 n−1개가 몰린다 — 이때 시간 복잡도가 O(n²)으로 떨어진다. 위 코드처럼 "마지막 원소"를 피벗으로 쓰면, 이미 정렬된 입력이 바로 이 최악의 경우가 된다.

고정 피벗은 정렬된 입력에서 O(n²)이 된다 항상 첫 번째나 마지막 원소를 피벗으로 고르면, 이미 정렬됐거나 역순인 데이터에서 분할이 완전히 한쪽으로 쏠려 O(n²)이 된다. 실무 구현은 이를 피하려고 3개 중앙값(median-of-three)이나 무작위 피벗을 쓴다. 직접 퀵 정렬을 구현한다면 고정 피벗은 피해야 한다.

퀵 정렬은 추가 메모리가 재귀 스택뿐이라 사실상 in-place이고, 캐시 지역성이 좋아 같은 O(n log n)인 병합 정렬·힙 정렬보다 상수 계수가 작다 — 실측 속도가 빠른 이유다. 단점은 최악 O(n²)과 불안정 정렬이라는 점이다.

힙 정렬 (Heap Sort)

힙 정렬(heap sort)은 힙(heap)이라는 자료구조를 이용한다. 힙은 "부모가 자식보다 항상 크거나 같은(최대 힙)" 완전 이진 트리이며, 배열로 표현할 수 있다. 인덱스 i의 자식은 2i+1, 2i+2다. 최악에도 O(n log n)을 보장하고 in-place로 동작한다.

동작 원리

전략은 두 단계다. 먼저 배열 전체를 최대 힙으로 만든다(build heap). 그러면 최댓값이 맨 앞(루트)에 온다. 그 루트를 배열 맨 끝과 교환하면 최댓값이 제자리를 찾는다. 끝 원소를 제외한 나머지를 다시 힙으로 정리(sift down)하면 그다음 최댓값이 루트로 올라온다. 이를 반복한다.

// 인덱스 root를 뿌리로 하는 부분 트리를 최대 힙으로 정리한다.
void SiftDown(std::vector<int>& arr, int root, int size)
{
    while (true)
    {
        int largest = root;
        const int left = 2 * root + 1;
        const int right = 2 * root + 2;

        if (left < size && arr[left] > arr[largest])
        {
            largest = left;
        }
        if (right < size && arr[right] > arr[largest])
        {
            largest = right;
        }
        // 부모가 이미 가장 크면 정리가 끝났다.
        if (largest == root)
        {
            break;
        }
        std::swap(arr[root], arr[largest]);
        root = largest;
    }
}

// 배열을 최대 힙으로 만든 뒤 루트를 끝으로 빼며 정렬한다.
void HeapSort(std::vector<int>& arr)
{
    const int n = static_cast<int>(arr.size());

    // 1단계: 마지막 내부 노드부터 거꾸로 힙을 구성한다.
    for (int i = n / 2 - 1; i >= 0; --i)
    {
        SiftDown(arr, i, n);
    }
    // 2단계: 루트(최댓값)를 끝으로 보내고 힙 크기를 줄인다.
    for (int end = n - 1; end > 0; --end)
    {
        std::swap(arr[0], arr[end]);
        SiftDown(arr, 0, end);
    }
}

힙 정렬은 퀵 정렬과 달리 입력에 상관없이 O(n log n)을 보장하고, 병합 정렬과 달리 추가 메모리가 거의 없다. 그래서 "최악의 경우 보장"이 중요한 곳에 쓰인다. 다만 메모리 접근이 트리를 따라 멀리 점프해 캐시 효율이 떨어지므로, 평균 실측 속도는 퀵 정렬보다 느린 편이고 불안정 정렬이다.

힙은 정렬만의 도구가 아니다 힙 자료구조 자체는 우선순위 큐(priority queue)의 기반이다. "가장 큰(작은) 값을 빠르게 꺼낸다"가 필요한 작업 스케줄러, 다익스트라 최단 경로, 이벤트 시뮬레이션 등에 쓰인다. C++ 표준 라이브러리의 std::priority_queue가 바로 힙으로 구현되어 있다.

정렬 알고리즘 비교

지금까지의 정렬을 시간·공간 복잡도, 안정성, 실측 속도 관점에서 정리한다. "어떤 정렬이 제일 좋은가"라는 질문에는 단일한 답이 없다 — 입력의 크기와 성질, 메모리 제약, 안정성 요구가 선택을 좌우한다.

알고리즘평균최악추가 메모리안정성비고
버블 정렬O(n²)O(n²)O(1)안정교육용
선택 정렬O(n²)O(n²)O(1)불안정교환 횟수 최소
삽입 정렬O(n²)O(n²)O(1)안정거의 정렬된 입력에 O(n)
병합 정렬O(n log n)O(n log n)O(n)안정외부 정렬·연결 리스트에 강함
퀵 정렬O(n log n)O(n²)O(log n)불안정평균 실측 가장 빠름
힙 정렬O(n log n)O(n log n)O(1)불안정최악 보장 + in-place

주목할 점은 복잡도가 같다고 실측 속도가 같지는 않다는 사실이다. 퀵·병합·힙 정렬은 모두 평균 O(n log n)이지만, 캐시 지역성과 상수 계수 차이로 퀵 정렬이 보통 가장 빠르다. 또 O(n²)인 삽입 정렬이 작은 입력에서는 O(n log n) 정렬들을 이긴다. 빅오는 입력이 충분히 클 때의 증가율일 뿐, 실제 성능의 전부가 아니다.

안정 정렬 (Stable Sort)

안정 정렬(stable sort)은 값이 같은 원소들의 원래 상대 순서를 보존하는 정렬이다. 정렬 키가 같은 두 원소 A, B가 입력에서 A가 앞이었다면, 정렬 후에도 A가 앞에 온다.

왜 중요한가

단일 키로 한 번만 정렬할 때는 안정성이 의미 없다. 중요해지는 것은 다중 키 정렬이다. 예를 들어 직원 목록을 "부서별로 정렬하되, 같은 부서 안에서는 이름순"으로 만들고 싶다고 하자. 안정 정렬을 쓰면 이름으로 먼저 정렬한 뒤 부서로 정렬하기만 하면 된다. 부서 정렬이 같은 부서 원소들의 (이미 이름순인) 순서를 흩뜨리지 않기 때문이다.

struct Employee
{
    std::string m_name;
    std::string m_department;
};

// 1단계: 이름순으로 정렬한다.
std::stable_sort(employees.begin(), employees.end(),
    [](const Employee& a, const Employee& b)
    {
        return a.m_name < b.m_name;
    });

// 2단계: 부서순으로 정렬한다. 같은 부서 안의 이름순은 보존된다.
std::stable_sort(employees.begin(), employees.end(),
    [](const Employee& a, const Employee& b)
    {
        return a.m_department < b.m_department;
    });
// 결과: 부서순 + 같은 부서 안에서 이름순
안정 정렬 vs 불안정 정렬 (부서 기준)
입력 : (영업,박) (개발,김) (영업,이) (개발,최) 불안정 정렬: (개발,최) (개발,김) (영업,이) (영업,박) ← 이름 순서 깨짐 안정 정렬 : (개발,김) (개발,최) (영업,박) (영업,이) ← 입력 순서 보존

만약 불안정 정렬을 썼다면 부서 정렬이 같은 부서 안의 이름 순서를 임의로 섞어 버려, 이 2단계 기법이 통하지 않는다. 병합 정렬과 삽입 정렬은 안정적이고, 퀵 정렬과 힙 정렬은 불안정하다. 안정성이 필요하면 알고리즘 선택이 곧 정답의 정확성 문제가 된다.

선형 탐색

선형 탐색(linear search)은 가장 단순한 탐색이다. 데이터를 처음부터 끝까지 하나씩 비교하며 원하는 값을 찾는다. 시간 복잡도는 O(n)이고, 데이터가 정렬되어 있을 필요가 없다는 것이 가장 큰 장점이다.

// 배열을 앞에서부터 훑어 target을 찾는다. 없으면 -1을 반환한다.
int LinearSearch(const std::vector<int>& arr, int target)
{
    for (int i = 0; i < static_cast<int>(arr.size()); ++i)
    {
        if (arr[i] == target)
        {
            return i;
        }
    }
    return -1;   // 찾지 못함.
}

선형 탐색은 정렬 비용이 없으므로, 데이터가 작거나·한 번만 찾거나·정렬이 불가능한 구조(단방향 연결 리스트 등)에서는 오히려 합리적인 선택이다. "정렬해서 이진 탐색"이 항상 이기는 것은 아니다 — 정렬 비용 O(n log n)을 한 번의 탐색으로 회수할 수 없다면 그냥 O(n)으로 훑는 편이 낫다.

이진 탐색 (Binary Search)

이진 탐색(binary search)은 정렬된 데이터에서 중간값을 보고 탐색 범위를 절반씩 줄여 나간다. 매 단계마다 후보가 반으로 줄므로 시간 복잡도는 O(log n)이다. 100만 개 데이터에서도 약 20번의 비교면 충분하다.

동작 원리

탐색 범위를 [lo, hi]로 두고 중간 인덱스 mid를 본다. arr[mid]가 목표값이면 끝이다. 목표가 더 크면 왼쪽 절반은 버리고 lo = mid + 1, 더 작으면 오른쪽 절반을 버리고 hi = mid - 1. 범위가 사라질 때까지 반복한다.

// 정렬된 배열에서 target을 찾는다. 없으면 -1을 반환한다.
int BinarySearch(const std::vector<int>& arr, int target)
{
    int lo = 0;
    int hi = static_cast<int>(arr.size()) - 1;   // 닫힌 구간 [lo, hi].

    while (lo <= hi)   // 구간이 비면 종료한다.
    {
        const int mid = lo + (hi - lo) / 2;   // (lo + hi) / 2는 오버플로우 위험.
        if (arr[mid] == target)
        {
            return mid;
        }
        else if (arr[mid] < target)
        {
            lo = mid + 1;   // 오른쪽 절반만 남긴다.
        }
        else
        {
            hi = mid - 1;   // 왼쪽 절반만 남긴다.
        }
    }
    return -1;   // 찾지 못함.
}

경계 처리의 함정

이진 탐색은 개념이 단순한데도 정확히 구현하기가 의외로 까다롭다. 함정은 거의 항상 경계 조건에 있다.

  • 구간 정의의 일관성 — 닫힌 구간 [lo, hi]로 시작했다면 종료 조건은 lo <= hi여야 하고, hi는 mid - 1로 갱신해야 한다. 반개구간 [lo, hi)를 쓴다면 종료 조건은 lo < hi다. 둘을 섞으면 원소를 놓치거나 무한 루프에 빠진다.
  • 무한 루프 — lo = mid처럼 범위를 줄이지 않는 갱신을 쓰면, lo와 hi가 붙었을 때 mid가 계속 같은 값이 되어 영원히 끝나지 않는다. 갱신은 반드시 mid ± 1로 범위를 실제로 좁혀야 한다.
  • mid 계산 오버플로우 — (lo + hi) / 2는 lo + hi가 int 최대값을 넘으면 음수로 뒤집힌다. lo + (hi - lo) / 2로 계산하면 안전하다.
정렬되지 않은 데이터에 이진 탐색을 쓰면 조용히 틀린다 이진 탐색은 "arr[mid]보다 크면 무조건 오른쪽에 있다"는 전제 위에서 동작한다. 데이터가 정렬되어 있지 않으면 이 전제가 깨지지만, 코드는 예외를 던지지 않고 그냥 잘못된 -1이나 엉뚱한 인덱스를 반환한다. 컴파일 에러도 런타임 에러도 없이 결과만 틀리므로 디버깅이 가장 어려운 종류의 버그다. 이진 탐색 호출 전에 데이터가 정말 정렬되어 있는지 반드시 확인해야 한다.

STL의 정렬·탐색

실무에서는 정렬·탐색을 직접 구현하지 않고 C++ 표준 라이브러리를 쓴다. 표준 구현은 수많은 입력에 대해 검증되었고, 함정들이 이미 처리되어 있다.

std::sort와 std::stable_sort

std::sort는 인트로 정렬(introsort)로 구현된다. 기본은 퀵 정렬로 시작하되, 재귀 깊이가 너무 깊어지면(최악의 경우 조짐) 힙 정렬로 전환하고, 구간이 작아지면 삽입 정렬로 마무리한다. 이렇게 퀵 정렬의 평균 속도와 힙 정렬의 최악 보장 O(n log n)을 모두 얻는다. 단 불안정 정렬이다. 안정성이 필요하면 std::stable_sort를 쓴다.

std::vector<int> data = { 5, 2, 8, 1, 9, 3 };

// 인트로 정렬 — 평균 O(n log n), 최악도 O(n log n) 보장, 불안정.
std::sort(data.begin(), data.end());

// 비교 함수(람다)로 정렬 기준을 바꾼다 — 내림차순.
std::sort(data.begin(), data.end(),
    [](int a, int b) { return a > b; });

// 같은 값의 상대 순서가 중요하면 stable_sort를 쓴다.
std::stable_sort(data.begin(), data.end());

binary_search와 lower_bound / upper_bound

탐색 쪽도 표준 함수가 있다. 모두 정렬된 범위를 전제로 한다.

함수반환용도
std::binary_searchbool값의 존재 여부만 확인
std::lower_bound반복자target 이상이 처음 나오는 위치
std::upper_bound반복자target 초과가 처음 나오는 위치
std::vector<int> sorted = { 1, 2, 2, 2, 5, 8, 9 };

// 존재 여부만 필요할 때.
bool found = std::binary_search(sorted.begin(), sorted.end(), 5);   // true

// target 이상이 시작되는 위치 — 삽입 위치를 찾을 때 유용하다.
auto lo = std::lower_bound(sorted.begin(), sorted.end(), 2);
// target 초과가 시작되는 위치.
auto hi = std::upper_bound(sorted.begin(), sorted.end(), 2);

// [lo, hi) 구간이 곧 값 2의 모든 출현 — 개수는 hi - lo.
const auto count = std::distance(lo, hi);   // 3

lower_bound와 upper_bound를 함께 쓰면 "정렬된 배열에서 특정 값이 몇 개 있는가"를 O(log n)에 구할 수 있다. 직접 이진 탐색을 변형해 같은 일을 하려다 경계 처리에서 실수하는 경우가 많은데, 표준 함수는 이를 정확히 보장한다.

C++ 시리즈와 연결 std::sort에 넘기는 비교 함수는 엄격한 약순서(strict weak ordering)를 만족해야 한다 — a < b와 b < a가 동시에 참이 되면 정의되지 않은 동작이다. 람다·함수 객체와 비교자 설계는 C++ 시리즈에서 더 자세히 다룬다.

실무 관점 — 무엇을 선택할까

실무 결론은 명확하다 — 정렬·탐색을 직접 구현하지 말고 표준 라이브러리를 쓴다. std::sort는 인트로 정렬로 평균 속도와 최악 보장을 모두 갖췄고, 수십 년간 검증되었으며, 직접 짠 퀵 정렬보다 거의 항상 빠르고 안전하다.

그렇다면 원리를 왜 알아야 하는가. 선택과 디버깅을 위해서다.

  • 안정성 요구 — 다중 키 정렬처럼 같은 값의 순서가 의미 있으면 std::stable_sort를, 아니면 std::sort를 쓴다. 안정성 개념을 모르면 이 선택 자체를 못 한다.
  • 데이터의 성질 — 거의 정렬된 데이터가 반복적으로 들어온다면 삽입 정렬 계열이 유리할 수 있고, 데이터가 메모리에 다 안 들어가면 외부 병합 정렬을 고려한다.
  • 탐색 빈도 — 한 번만 찾는다면 정렬 없이 선형 탐색이, 같은 데이터를 여러 번 탐색한다면 한 번 정렬 후 이진 탐색이 유리하다. 정렬 비용을 탐색 횟수로 나눠 따져야 한다.
  • 디버깅 — 정렬 결과가 이상하거나 탐색이 엉뚱한 값을 줄 때, 내부 동작을 알아야 "비교 함수가 약순서를 어겼나", "데이터가 정렬 안 됐나"를 짚을 수 있다.
"바퀴를 다시 발명하지 말되, 바퀴의 원리는 알라" 표준 라이브러리를 쓰는 것과 그 안에서 무슨 일이 일어나는지 아는 것은 충돌하지 않는다. 알고리즘 원리는 코드를 짜기 위한 것이 아니라, 올바른 도구를 고르고 잘못된 결과를 진단하기 위한 지식이다.

흔한 함정

함정 1 — 정렬 안 된 데이터에 이진 탐색

가장 흔하고 가장 잡기 어려운 버그다. 이진 탐색과 std::binary_search·lower_bound는 모두 입력이 정렬되었다고 가정할 뿐 검증하지 않는다. 정렬되지 않은 데이터를 넘기면 에러 없이 그냥 틀린 결과가 나온다. 데이터 출처가 정렬을 보장하는지 확실하지 않다면, 탐색 전에 정렬하거나 최소한 디버그 빌드에서 정렬 여부를 assert로 확인한다.

함정 2 — 이진 탐색 경계와 오버플로우

직접 구현한 이진 탐색의 버그는 거의 다 경계에 있다. 종료 조건(lo <= hi vs lo < hi)과 갱신 방식(mid - 1 vs mid)을 구간 정의와 일관되게 맞춰야 한다. 또 mid = (lo + hi) / 2는 큰 인덱스에서 정수 오버플로우를 일으키므로 항상 mid = lo + (hi - lo) / 2로 쓴다. 가능하면 직접 구현 대신 std::lower_bound를 쓰는 것이 안전하다.

함정 3 — 퀵 정렬 최악 케이스

직접 구현한 퀵 정렬에서 첫/마지막 원소를 고정 피벗으로 쓰면, 이미 정렬됐거나 역순인 입력에서 O(n²)으로 떨어진다. 산업 데이터는 의외로 "거의 정렬된" 경우가 많아 이 함정에 잘 빠진다. 무작위 피벗이나 3개 중앙값을 쓰거나, 애초에 인트로 정렬인 std::sort를 쓰면 이 문제가 없다.

함정 4 — 안정성이 필요한데 std::sort 사용

std::sort는 불안정 정렬이다. 다중 키 정렬을 단계적으로 수행하면서 std::sort를 쓰면, 앞 단계에서 맞춰 둔 순서가 뒤 단계에서 임의로 흐트러진다. 결과는 컴파일도 되고 실행도 되지만 틀린 순서다. 같은 값의 상대 순서가 의미를 가지는 순간 반드시 std::stable_sort를 써야 한다.
