스캔(prefix sum)이란

스캔은 배열의 각 위치에 "처음부터 그 위치까지의 합"을 넣는 연산이다. 리덕션이 배열을 값 하나로 줄인다면, 스캔은 중간 합계를 모두 남긴다. 자기 자신을 포함하느냐에 따라 두 종류로 나눈다.

종류i번째 결과입력 [3, 1, 7, 0, 4, 1, 6, 3]의 결과
inclusive scana[0] + ... + a[i] (자기 포함)[3, 4, 11, 11, 15, 16, 22, 25]
exclusive scana[0] + ... + a[i-1] (자기 제외, 첫 값은 0)[0, 3, 4, 11, 11, 15, 16, 22]

exclusive 결과는 inclusive 결과를 오른쪽으로 한 칸 민 것과 같다. 쓰임새가 생각보다 넓어서, GPU 병렬 알고리즘의 기본 부품으로 취급한다.

쓰는 곳스캔이 하는 역할
조건에 맞는 원소만 모으기 (stream compaction)각 원소가 결과 배열의 몇 번째 자리에 들어갈지 계산
히스토그램 평활화히스토그램을 누적해서 CDF(누적 분포)를 만듦
적분 영상 (integral image, SAT)행 방향 스캔 후 열 방향 스캔. 박스 필터를 영역 크기와 상관없이 4번 읽기로 계산
기수 정렬 (radix sort)각 비트 값별로 원소가 갈 위치를 계산
가변 길이 출력 할당스레드마다 출력 개수가 다를 때, 각자 쓸 시작 위치를 계산

스캔도 CPU에서는 반복문 하나지만 매 단계가 앞 단계 결과에 의존한다. 리덕션처럼 트리 구조로 바꿔야 병렬화할 수 있는데, 중간 합계를 모두 남겨야 하므로 리덕션보다 조금 복잡하다. 대표적인 방법이 두 가지 있다.

Hillis-Steele 스캔 - 단순하지만 일이 많은 방식

단계마다 offset을 1, 2, 4, ...로 키우면서, 모든 원소가 자기보다 offset만큼 앞의 원소를 더한다. log2n 단계가 지나면 각 원소에 처음부터 자기까지의 합이 모인다.

Hillis-Steele 스캔. 단계마다 offset만큼 앞의 값을 더한다. 마지막 줄이 inclusive scan 결과

같은 단계 안에서 읽기와 쓰기가 섞이면 안 되므로, 버퍼 두 개를 번갈아 쓴다(double buffering).

// inclusive scan of one block (n == blockDim.x), Hillis-Steele
__global__ void ScanHillisSteele(const float* in, float* out, int n)
{
    extern __shared__ float buf[];          // 2 * n floats
    float* src = buf;
    float* dst = buf + n;
    int tid = threadIdx.x;

    src[tid] = (tid < n) ? in[tid] : 0.0f;
    __syncthreads();

    for (int offset = 1; offset < n; offset <<= 1)
    {
        dst[tid] = (tid >= offset) ? src[tid] + src[tid - offset] : src[tid];
        __syncthreads();
        float* t = src; src = dst; dst = t;  // swap buffers
    }
    if (tid < n) out[tid] = src[tid];
}

코드는 짧고 단계 수도 log2n으로 적다. 대신 단계마다 거의 모든 원소가 덧셈을 하므로 전체 덧셈 횟수가 n log2n이다. CPU 순차 스캔은 n번이면 되므로, 원소가 많아지면 일을 훨씬 더 많이 하는 셈이다. 이런 성질을 work-efficient하지 않다고 한다. 다만 워프 하나(32개)처럼 원소가 적고 스레드가 어차피 놀고 있는 경우에는 단계 수가 적은 이 방식이 유리하다. 뒤에서 볼 워프 스캔이 바로 이 방식이다.

Blelloch 스캔 - 일을 줄인 방식

Blelloch 방식은 두 단계로 나눈다. 전체 덧셈 횟수가 약 2n으로, 순차 스캔과 같은 수준이다.

단계하는 일
up-sweep (리덕션)13편의 트리 리덕션과 같다. 단, 중간 합을 지우지 않고 그 자리에 남겨 둔다. 끝나면 마지막 칸에 전체 합이 있다
down-sweep마지막 칸을 0으로 바꾸고 트리를 거꾸로 내려온다. 각 단계에서 왼쪽 자식에는 부모 값을, 오른쪽 자식에는 "부모 값 + 원래 왼쪽 자식 값"을 넣는다. 끝나면 exclusive scan 결과가 남는다
// exclusive scan of 2 * blockDim.x elements in one block, Blelloch
__global__ void ScanBlelloch(const float* in, float* out, int n)   // n == 2 * blockDim.x
{
    extern __shared__ float t[];
    int tid = threadIdx.x;

    t[2 * tid]     = in[2 * tid];
    t[2 * tid + 1] = in[2 * tid + 1];

    // up-sweep: build partial sums in place
    int offset = 1;
    for (int d = n >> 1; d > 0; d >>= 1)
    {
        __syncthreads();
        if (tid < d)
        {
            int ai = offset * (2 * tid + 1) - 1;
            int bi = offset * (2 * tid + 2) - 1;
            t[bi] += t[ai];
        }
        offset <<= 1;
    }

    // clear the last element (it holds the total)
    if (tid == 0) t[n - 1] = 0.0f;

    // down-sweep: walk back down the tree
    for (int d = 1; d < n; d <<= 1)
    {
        offset >>= 1;
        __syncthreads();
        if (tid < d)
        {
            int ai = offset * (2 * tid + 1) - 1;
            int bi = offset * (2 * tid + 2) - 1;
            float left = t[ai];
            t[ai]  = t[bi];          // left child  <- parent
            t[bi] += left;           // right child <- parent + old left
        }
    }
    __syncthreads();

    out[2 * tid]     = t[2 * tid];
    out[2 * tid + 1] = t[2 * tid + 1];
}

입력 [3, 1, 7, 0, 4, 1, 6, 3]으로 직접 계산해 보면 다음과 같다.

단계배열 상태
입력[3, 1, 7, 0, 4, 1, 6, 3]
up-sweep offset 1[3, 4, 7, 7, 4, 5, 6, 9]
up-sweep offset 2[3, 4, 7, 11, 4, 5, 6, 14]
up-sweep offset 4[3, 4, 7, 11, 4, 5, 6, 25] (마지막 칸 = 전체 합)
마지막 칸을 0으로[3, 4, 7, 11, 4, 5, 6, 0]
down-sweep offset 4[3, 4, 7, 0, 4, 5, 6, 11]
down-sweep offset 2[3, 0, 7, 4, 4, 11, 6, 16]
down-sweep offset 1[0, 3, 4, 11, 11, 15, 16, 22] = exclusive scan
Blelloch 방식의 뱅크 충돌 up-sweep 후반부에는 ai, bi의 간격이 16, 32, ...로 벌어져 13편 버전 2와 같은 뱅크 충돌이 생긴다. GPU Gems 3 39장은 인덱스 32개마다 빈칸 하나를 끼워 넣는 CONFLICT_FREE_OFFSET(n) = n >> 5 기법을 소개한다. 6편의 패딩([32][33])과 같은 원리다.

워프 스캔 - shuffle로 32개 한 번에

지금 GPU에서는 블록 스캔도 리덕션처럼 워프 단위로 먼저 계산한다. 워프 안에서는 shared memory 없이 레지스터끼리 값을 주고받는 __shfl_up_sync를 쓴다. 구조는 Hillis-Steele와 같지만, 32개뿐이고 스레드가 어차피 32개 모두 실행 중이라 일이 많다는 단점이 문제가 되지 않는다.

// inclusive scan across the 32 lanes of a warp
__device__ __forceinline__ float WarpInclusiveScan(float x)
{
    int lane = threadIdx.x & 31;
    for (int offset = 1; offset < 32; offset <<= 1)
    {
        float y = __shfl_up_sync(0xffffffff, x, offset);   // value from lane - offset
        if (lane >= offset) x += y;                        // lanes 0..offset-1 keep x
    }
    return x;
}

// block scan = warp scan + scan of warp totals + add back
__device__ float BlockInclusiveScan(float x)
{
    __shared__ float warpTotals[32];
    int lane = threadIdx.x & 31;
    int warp = threadIdx.x >> 5;

    x = WarpInclusiveScan(x);                    // 1) scan inside each warp
    if (lane == 31) warpTotals[warp] = x;        // 2) last lane holds the warp total
    __syncthreads();

    if (warp == 0)                               // 3) scan the warp totals
    {
        int numWarps = (blockDim.x + 31) >> 5;
        float t = (lane < numWarps) ? warpTotals[lane] : 0.0f;
        warpTotals[lane] = WarpInclusiveScan(t);
    }
    __syncthreads();

    if (warp > 0) x += warpTotals[warp - 1];     // 4) add totals of earlier warps
    return x;
}

블록 크기 256이면 워프 8개가 각자 스캔하고, 워프 합계 8개를 첫 워프가 다시 스캔한 뒤, 각 워프가 자기 앞 워프들의 합계를 더한다. 동기화는 두 번뿐이다.

블록보다 큰 배열 스캔

배열이 블록 하나보다 크면 세 단계로 나눈다.

큰 배열 스캔. 블록 합계 배열이 여전히 크면 2단계를 같은 방법으로 다시 나눈다
// step 1: scan each block, save its total
__global__ void ScanBlocks(const float* in, float* out, float* blockSums, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    float x = (i < n) ? in[i] : 0.0f;
    x = BlockInclusiveScan(x);
    if (i < n) out[i] = x;
    if (threadIdx.x == blockDim.x - 1) blockSums[blockIdx.x] = x;
}

// step 3: add the offset of all earlier blocks
__global__ void AddBlockOffsets(float* out, const float* scannedSums, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (blockIdx.x > 0 && i < n)
        out[i] += scannedSums[blockIdx.x - 1];   // inclusive scan of block sums
}

// host
ScanBlocks<<<numBlocks, 256>>>(d_in, d_out, d_sums, n);
ScanBlocks<<<1, 1024>>>(d_sums, d_sums, d_dummy, numBlocks);   // step 2 (numBlocks <= 1024)
AddBlockOffsets<<<numBlocks, 256>>>(d_out, d_sums, n);

이 방식은 global memory를 대략 입력 두 번 읽기, 출력 두 번 쓰기만큼 오간다. CUB의 DeviceScan은 "decoupled look-back"이라는 기법으로 이 왕복을 한 번으로 줄여, 거의 memcpy 수준 속도를 낸다. 직접 짠 3단계 스캔은 원리를 익히는 용도로 보고, 실무에서는 CUB를 쓴다.

#include <cub/cub.cuh>

size_t tempBytes = 0;
cub::DeviceScan::ExclusiveSum(nullptr, tempBytes, d_in, d_out, n, stream);  // size query
cudaMallocAsync(&d_temp, tempBytes, stream);
cub::DeviceScan::ExclusiveSum(d_temp, tempBytes, d_in, d_out, n, stream);

응용 - 조건에 맞는 원소만 모으기

스캔을 가장 많이 쓰는 곳이 stream compaction이다. 예를 들어 영상에서 밝기가 임계값을 넘는 픽셀의 좌표만 뽑아 배열에 모으고 싶다고 하자. 스레드마다 "내가 결과의 몇 번째 칸에 써야 하는가"를 알아야 하는데, 이것이 바로 "나보다 앞에서 조건을 만족한 원소 수", 즉 플래그 배열의 exclusive scan이다.

단계값
입력 픽셀[12, 250, 30, 240, 255, 8, 200, 15]
플래그 (값 > 128)[0, 1, 0, 1, 1, 0, 1, 0]
플래그의 exclusive scan[0, 0, 1, 1, 2, 3, 3, 4]
플래그가 1인 원소를 scan 값 위치에 씀out[0]=1번, out[1]=3번, out[2]=4번, out[3]=6번 위치
결과 개수마지막 scan 값 + 마지막 플래그 = 4 + 0 = 4
__global__ void Scatter(const unsigned char* img, const int* flags, const int* pos,
                        int* outIdx, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n && flags[i])
        outIdx[pos[i]] = i;      // no collisions: every survivor has a unique slot
}

// flags -> exclusive scan -> scatter.  CUB does all three in one call:
cub::DeviceSelect::If(d_temp, tempBytes, d_in, d_out, d_numSelected, n, IsBright{}, stream);

atomicAdd로 결과 위치를 하나씩 받아 가는 방법(pos = atomicAdd(&count, 1))도 있다. 코드는 더 짧지만 결과 순서가 실행할 때마다 바뀌고, 조건을 만족하는 원소가 많으면 카운터 하나에 경합이 몰린다. 순서가 유지되어야 하면 스캔 방식을 쓴다.

atomic 연산

여러 스레드가 같은 주소의 값을 동시에 고치면 결과가 깨진다. count++는 실제로는 "읽기 → 1 더하기 → 쓰기" 세 단계라, 두 스레드가 같은 값을 읽고 각자 1을 더해 쓰면 2가 늘어야 할 값이 1만 는다. atomic 연산은 이 세 단계를 다른 스레드가 끼어들 수 없는 하나의 동작으로 처리한다.

함수동작참고
atomicAdd(addr, v)*addr += vint, unsigned, unsigned long long, float, double(cc 6.0+), half 계열
atomicSub(addr, v)*addr -= vint, unsigned만
atomicMax / atomicMin더 큰(작은) 값으로 교체정수형만. float은 직접 구현
atomicExch(addr, v)v로 바꾸고 이전 값 반환float 지원
atomicCAS(addr, cmp, v)*addr == cmp일 때만 v로 바꿈모든 atomic의 기본 부품
atomicAnd / Or / Xor비트 연산플래그 비트 세우기
atomicInc(addr, max)1 증가, max를 넘으면 0으로링 버퍼 인덱스

모든 atomic 함수는 바뀌기 전 값을 돌려준다. compaction에서 int slot = atomicAdd(&count, 1);로 자기 자리를 받을 수 있는 이유가 이것이다.

atomicCAS로 없는 연산 만들기

float 최댓값처럼 기본 제공되지 않는 연산은 CAS(compare-and-swap) 반복문으로 만든다. "내가 읽은 값이 아직 그대로면 새 값으로 바꾸고, 그 사이 누가 바꿨으면 다시 시도"하는 방식이다.

__device__ float AtomicMaxFloat(float* addr, float value)
{
    int* addrAsInt = reinterpret_cast<int*>(addr);
    int  old = *addrAsInt;
    int  assumed;
    do
    {
        assumed = old;
        if (__int_as_float(assumed) >= value) break;          // already larger, nothing to do
        old = atomicCAS(addrAsInt, assumed, __float_as_int(value));
    } while (assumed != old);                                  // someone else changed it: retry
    return __int_as_float(old);
}
양수 float는 정수 비교로 충분 IEEE 754 float는 양수끼리는 비트 패턴을 정수로 봤을 때도 크기 순서가 같다. 값이 항상 0 이상이라면 atomicMax((int*)addr, __float_as_int(v)) 한 줄로 끝난다. 음수가 섞이면 이 방법은 틀리므로 위 CAS 반복문을 쓴다.

atomic이 비싼 경우

atomic 자체는 최신 GPU에서 L2 캐시에서 처리되어 꽤 빠르다. 느려지는 원인은 경합(contention)이다. 같은 주소에 몰린 atomic은 하드웨어가 하나씩 순서대로 처리하므로, 스레드 1만 개가 카운터 하나에 atomicAdd를 하면 사실상 1만 번 순차 실행이 된다. 반대로 주소가 고르게 흩어져 있으면 거의 일반 쓰기만큼 빠르다. 다음 절의 히스토그램이 이 차이를 잘 보여 준다.

히스토그램 - atomic 경합 줄이기

8비트 영상의 밝기 히스토그램은 값 0~255 각각이 몇 번 나오는지 세는 것이다. 픽셀마다 스레드 하나를 두면, 스레드들이 bin 256개 중 하나에 1을 더한다.

버전 1 - global memory atomic

__global__ void HistGlobal(const unsigned char* img, unsigned int* hist, size_t n)
{
    for (size_t i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += (size_t)blockDim.x * gridDim.x)
        atomicAdd(&hist[img[i]], 1u);
}

짧고 정확하다. 문제는 영상 내용에 따라 속도가 크게 달라진다는 점이다. 밝기가 고르게 퍼진 영상은 빠르지만, 검사 영상처럼 배경이 대부분 같은 밝기면 한두 개 bin에 atomic이 몰린다. 극단적으로 전체가 검은 영상(모든 픽셀 0)이면 모든 스레드가 hist[0] 하나를 놓고 줄을 선다.

버전 2 - 블록마다 shared memory 히스토그램

블록마다 자기만의 히스토그램을 shared memory에 두고(privatization), 블록 안에서 먼저 센 뒤 마지막에 global 히스토그램에 한 번씩 더한다.

__global__ void HistShared(const unsigned char* img, unsigned int* hist, size_t n)
{
    __shared__ unsigned int local[256];

    // 1) clear the block-private histogram
    for (int b = threadIdx.x; b < 256; b += blockDim.x)
        local[b] = 0;
    __syncthreads();

    // 2) count into shared memory (fast atomics, contention only inside the block)
    for (size_t i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += (size_t)blockDim.x * gridDim.x)
        atomicAdd(&local[img[i]], 1u);
    __syncthreads();

    // 3) merge: at most 256 global atomics per block
    for (int b = threadIdx.x; b < 256; b += blockDim.x)
        if (local[b] > 0)
            atomicAdd(&hist[b], local[b]);
}

cudaMemsetAsync(d_hist, 0, 256 * sizeof(unsigned int), stream);
HistShared<<<numSMs * 4, 256, 0, stream>>>(d_img, d_hist, width * height);

방법설명

묶어 쓰기 - 히스토그램 평활화

지금까지의 패턴 세 개(히스토그램, 스캔, 맵)를 이어 붙이면 히스토그램 평활화가 된다. 어두운 영상의 밝기를 0~255 전체로 넓게 펴는 처리다.

단계패턴계산
1히스토그램 (atomic)hist[v] = 밝기 v인 픽셀 수
2스캔cdf[v] = hist[0] + ... + hist[v]
3LUT 계산 (원소별)lut[v] = round((cdf[v] - cdfmin) / (N - cdfmin) × 255)
4맵 (원소별)out[i] = lut[img[i]]
// steps 2 + 3 in one tiny kernel: 256 bins fit in a single block
__global__ void BuildEqualizeLut(const unsigned int* hist, unsigned char* lut, unsigned int total)
{
    __shared__ unsigned int cdfMin;
    unsigned int c = BlockInclusiveScanUInt(hist[threadIdx.x]);   // blockDim.x == 256

    // smallest non-zero cdf value = cdf of the first non-empty bin
    if (threadIdx.x == 0) cdfMin = 0xFFFFFFFFu;
    __syncthreads();
    if (c > 0) atomicMin(&cdfMin, c);
    __syncthreads();

    float denom = (float)(total - cdfMin);
    float v = (c <= cdfMin || denom <= 0.0f) ? 0.0f : (c - cdfMin) / denom * 255.0f;
    lut[threadIdx.x] = (unsigned char)fminf(255.0f, roundf(v));
}

// step 4: one read + one table lookup per pixel (keep lut in __constant__ or shared)
__global__ void ApplyLut(const unsigned char* in, unsigned char* out, const unsigned char* lut, size_t n)
{
    __shared__ unsigned char s[256];
    if (threadIdx.x < 256) s[threadIdx.x] = lut[threadIdx.x];
    __syncthreads();
    for (size_t i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += (size_t)blockDim.x * gridDim.x)
        out[i] = s[in[i]];
}

BlockInclusiveScanUInt는 앞의 BlockInclusiveScan을 unsigned int로 바꾼 것이다. 이렇게 커널 세 개(히스토그램, LUT, 적용)로 나누면 각 커널이 단순해지고, 17편에서 다룰 CUDA Graph로 묶어 프레임마다 한 번에 실행하기도 좋다. OpenCV의 cv::cuda::equalizeHist도 내부적으로 같은 순서로 동작한다.

흔한 함정

스캔 중간의 동기화 누락 Blelloch 스캔은 단계마다 다른 스레드가 쓴 값을 읽는다. __syncthreads()를 하나라도 빠뜨리면 원소 수가 적을 때는 우연히 맞다가 블록 크기를 키우면 틀린다. 결과를 반드시 CPU 순차 스캔과 비교해서 검증한다.
정수 카운터 넘침 unsigned int는 약 42억까지 셀 수 있다. 4K 영상 한 장은 문제없지만, 영상 수천 장의 히스토그램을 한 버퍼에 누적하면 넘칠 수 있다. 누적 개수가 커질 수 있으면 unsigned long long을 쓴다. 스캔 결과(인덱스)도 원소가 20억 개를 넘으면 int로는 부족하다.
모든 것을 atomic으로 풀기 atomic은 정확하지만 같은 주소에 몰리면 순차 실행이 된다. 출력 위치가 많은 스레드에서 겹친다면 먼저 블록이나 워프 안에서 모은 뒤(privatization, aggregation) 대표만 atomic을 쓴다. 출력 순서가 중요하면 atomic 대신 스캔을 쓴다.
float atomicAdd 결과가 매번 다름 atomic의 실행 순서는 정해지지 않으므로 float 합계는 마지막 자리가 실행마다 달라질 수 있다. 정수 연산(히스토그램, 카운터)은 순서와 상관없이 항상 같은 결과가 나온다.
