모의고사 개요

부록 27문제의 후반부 13문제는 실러버스 후반 챕터에 집중되어 있다. 5장(ML 기능 성능 지표), 7장(블랙박스/화이트박스 테스팅), 8장(AI 품질 특성 테스팅), 9장(테스트 기법), 10장(테스트 환경), 11장(테스트 자동화)에서 골고루 출제된다.

특히 후반부는 "비결정적·자율적·자가학습" 같은 AI 고유 특성과 "테스트 오라클·A/B·시각적 테스팅·메타모픽" 같은 기법 용어가 중심이다. 단순 암기보다 각 용어가 어떤 상황에서 쓰이는지를 사례와 함께 떠올릴 수 있어야 한다.

아래 13문제는 부록 해설을 바탕으로 다시 풀이를 정리한 것이다. 시간을 재고 풀어 본 뒤 정답표로 채점하면 약 30분 분량의 미니 모의고사가 된다.

Q15. ML 성능 지표의 한계

문제: 기계학습(ML) 팀은 기계학습 모델 훈련의 일환으로 수집한 검증 데이터 기반의 기계학습 기능 성능 지표(ML functional performance metrics)가 시스템 품질을 판단하는 데 충분하다고 주장한다. 다음 중 이 주장이 맞지 않을 수 있음을 보여주는 타당한 이유를 설명한 것은?
  • a) 실제 정보가 정확하지 않으면 기계학습 기능 성능 지표가 제대로 동작하지 않을 수 있다.
  • b) 도구들이 독립적이기 때문에 기계학습 기능 성능 지표를 품질 측정에 사용할 수 없다.
  • c) 유효성 검증 데이터가 편향되어 기능 성능 측정값이 왜곡된다.
  • d) 기능 성능 측정이 모델 품질을 반영하지 않도록 모델 훈련 전에 데이터 변형이 이뤄져야 한다.

정답: a)

ML 성능 지표(accuracy, precision, recall 등)는 모두 정답 라벨(ground truth)을 전제로 계산된다. 그 정답 자체가 잘못 붙어 있다면 모델이 아무리 그것을 잘 맞춰도 실제로는 틀린 답을 잘 맞추는 셈이라 품질을 보장하지 못한다.

b) ML 지표는 측정 도구 종류에 의존하지 않는다.
c) 검증 데이터가 편향될 수 있다는 것은 가능성이지 단정할 수 없다. 보기 a가 더 본질적인 이유다.
d) 데이터 변환이 항상 모델 품질에 부정적이지는 않다.

관련 학습 목표: AI-5.3.1 (K2) — ML 기능 성능 지표의 한계

Q16. 벤치마크 스위트

문제: 다음 중 벤치마크 스위트(benchmark suites)에 대한 설명으로 가장 적절한 것은?
  • a) 기계학습 벤치마크 스위트는 훈련에 들어가는 시간을 알려주어 특정 모델 선택에 도움을 준다.
  • b) 기계학습 벤치마크 스위트는 테스트에 들어가는 시간을 알려주어 특정 모델 선택에 도움을 준다.
  • c) 기계학습 벤치마크 스위트는 검증에 들어가는 시간을 알려주어 특정 모델 선택에 도움을 준다.
  • d) 기계학습 벤치마크 스위트는 배포에 들어가는 시간을 알려주어 특정 모델 선택에 도움을 준다.

정답: a)

ML 벤치마크 스위트(MLPerf 등)는 표준 데이터셋·모델·과제로 훈련 시간을 측정해 다양한 알고리즘·하드웨어 조합을 비교할 수 있게 해 준다. 테스트·검증·배포 시간은 벤치마크의 주된 대상이 아니다.

Q17. 편향 테스팅 레벨

문제: 다음 중 편향 관련(bias-related) 테스팅을 수행하기에 가장 적절한 테스트 레벨은?
  • a) 컴포넌트 테스팅
  • b) 입력 데이터 테스팅
  • c) 시스템 테스팅
  • d) 모델 테스팅

정답: b)

편향은 본질적으로 훈련 데이터에서 시작된다. 모델을 훈련하기 전에 입력 데이터 단계에서 인구통계학적 편향, 표본 편향 등을 검사하는 것이 가장 효과적이다. 모델 훈련 후에 발견되면 재훈련 비용이 크다.

a) 컴포넌트 테스팅은 비ML 컴포넌트에 적용되는 전통적 테스팅이다.
c) 시스템 테스팅에서도 편향 확인은 가능하지만 이상적인 시점은 아니다.
d) 모델 테스팅은 성능 기준 충족 확인이 주 목적이다.

Q18. AI 컴포넌트 문서화

문제: 다음 중 AI 컴포넌트 문서화에 대한 설명으로 옳은 것은?
  • a) 비기능 요구사항은 AI 컴포넌트 문서의 일부가 아니므로, 비기능 테스팅은 수행할 수 없다.
  • b) 인터페이스가 문서의 일부라면 AI와 비-AI 컴포넌트 간 상호작용에 대한 화이트박스 테스팅은 불가능하다.
  • c) 문서에 데이터 출처를 포함하면 데이터 편향 확인이 가능하다.
  • d) 자가-적응(self-adapting) AI 시스템 사용을 위해선 시스템에서 일어난 각 변경사항을 충분히 문서화해야 한다.

정답: c)

데이터 출처(provenance)와 메타데이터를 문서에 포함하면 어떤 인구·지역·시기의 데이터가 얼마나 들어 있는지 추적할 수 있고, 그 자체가 편향 검토의 기초가 된다.

a) 비기능 요구사항은 문서의 일부이며 비기능 테스팅도 수행한다.
b) 오히려 인터페이스 문서화는 화이트박스 테스팅을 지원한다.
d) 자가적응 시스템은 매 변경 사항을 모두 문서화하지 못하는 것이 현실적 한계다. "충분히 문서화해야 한다"라는 당위만으로는 옳다고 볼 수 없다.

Q19. 변환율 변화의 원인

문제: 고객의 구매 이력과 해당 사이트를 이용한 다른 사람들의 구매 내용을 기반으로 고객에게 구매할 제품을 추천해 주는 이커머스 애플리케이션이 있다. 테스터는 추천 항목의 현재 변환율(conversion rate)을 측정해 원래 필요한 변환율과 비교할 것을 요청 받았다. 다음 중 이런 요청을 하는 근본적인 이유로 가장 적절한 것은?
  • a) AI 효과 (AI effect)
  • b) 적대적 공격 (Adversarial attacks)
  • c) 컨셉 드리프트 (Concept drift)
  • d) 공정성 결여 (Lack of fairness)

정답: c)

컨셉 드리프트(concept drift)는 시간이 지나면서 입력 데이터의 분포나 사용자 행동 패턴이 변해 한때 잘 작동하던 모델의 성능이 점차 떨어지는 현상이다. 추천 시스템의 변환율을 주기적으로 측정해 기준치와 비교하는 것은 컨셉 드리프트 모니터링의 전형이다.

a) AI 효과는 "AI라고 부르던 것이 익숙해지면 더는 AI로 보지 않는다"는 인식 변화에 관한 용어다.
b) 적대적 공격은 입력을 의도적으로 교란해 잘못된 예측을 유도하는 공격이다. 일상적인 구매 데이터에서 발생할 일이 아니다.
d) 공정성 결여는 학습 데이터의 편향에서 비롯되며, 이미 운영 중인 시스템의 점진적 변환율 저하 원인으로는 약하다.

관련 학습 목표: AI-7.6.1 (K2) — 컨셉 드리프트의 식별

Q20. 자율성 테스팅

문제: 다음 중 시스템 자율성 테스팅과 가장 관련성이 높은 것은?
  • a) 일정하게 지속되는 기간 동안의 테스팅
  • b) 시스템 예측의 정확도에 대한 테스팅
  • c) 시스템 적응 속도 테스팅
  • d) 훈련 데이터에 대한 정적 분석

정답: a)

자율성(autonomy)은 사람의 개입 없이 얼마나 오래 스스로 작동할 수 있는가로 측정된다. 따라서 일정 기간을 두고 시스템을 운영하면서 개입 빈도와 시점을 관찰하는 장기간 테스팅이 자율성 평가의 핵심이다.

b) 정확도와 자율성은 다른 차원이다. 자율적이지만 부정확할 수도 있다.
c) 적응 속도는 적응성(adaptability)의 측정이지 자율성이 아니다.
d) 훈련 데이터의 정적 분석은 데이터 품질·편향과 관련된다.

Q21. 비결정적 시스템

문제: 다음 설명 중 테스팅에서 비결정적(non-deterministic) 시스템이 어떻게 문제를 일으킬 수 있는지를 가장 잘 나타내는 것은?
  • a) 비결정적 시스템은 매번 다른 결과를 생성함으로써, 보통 기대한 결과를 만들지 못하게 한다.
  • b) 비결정적 시스템은 설명할 수 없기 때문에 테스트하기 어렵고 결함의 조사나 수정도 어렵다.
  • c) 입력과 초기상태가 동일한 시스템이 다른 결과를 도출할 수 있으므로 테스트를 여러 번 실행해야 한다.
  • d) 비결정적 시스템은 보통 편향되어 있으며 결과에서 이러한 편향을 배제하기 위해 추가 테스트가 필요하다.

정답: c)

비결정적 시스템의 정의가 정확히 c)다. 같은 입력과 같은 초기 상태에서도 결과가 달라질 수 있으므로 단일 실행의 결과만으로 통과/실패를 판단할 수 없다. 통계적으로 유의미한 결론을 얻으려면 같은 테스트를 여러 번 반복해 분포를 봐야 한다.

a) "보통 기대한 결과를 만들지 못한다"는 과장이다. 허용 오차 안에서 기댓값을 정의할 수 있다.
b) 비결정성과 설명가능성은 별개의 속성이다.
d) 편향과 비결정성은 직접적 인과 관계가 없다.

관련 학습 목표: AI-8.2.1 (K2) — 비결정적 시스템 테스팅의 어려움

Q22. 동적 테스팅 없이 평가

문제: 다음 중 딥러닝 신경망(deep neural network)을 테스트할 때 동적 테스팅(dynamic testing) 없이 평가할 수 있는 속성은?
  • a) 설명 가능성 (Explainability)
  • b) 투명성 (Transparency)
  • c) 자동화 편향 (Automation bias)
  • d) 정확도 (Accuracy)

정답: b)

투명성(transparency)은 시스템이 어떤 원리·구조·데이터로 만들어졌는지가 사용자에게 공개되어 있는가를 묻는다. 따라서 시스템을 실제로 돌려보지 않고 문서와 코드·구성 자료를 비교하는 정적 검토만으로 평가할 수 있다.

a) 설명가능성은 개별 예측에 대한 근거를 봐야 하므로 시스템 실행이 필요하다.
c) 자동화 편향은 사용자가 시스템 결과를 어떻게 받아들이는지 봐야 하므로 실행이 필요하다.
d) 정확도는 당연히 실행 결과를 측정해야 한다.

관련 학습 목표: AI-8.6.1 (K2) — 정적 vs 동적 테스팅 대상

Q23. 테스트 오라클 문제

문제: 다음 중 AI 기반 시스템이 테스트 오라클 문제를 일으키는 예를 설명하는 것은?
  • a) 훈련 데이터의 출처를 모른다.
  • b) 시스템의 결과값은 알려지지 않은 실제값에 대한 예측이다.
  • c) 사람의 개입없이 시스템이 동작해 자율적이라고 여겨진다.
  • d) 시스템이 어떻게 구현됐는지에 대한 투명성이 부족하다.

정답: b)

테스트 오라클 문제는 "기대 결과를 어떻게 알 수 있는가"의 문제다. 미래 주가 예측, 신약 효능 예측처럼 정답이 아직 존재하지 않는(unknown ground truth) 분야는 그 자체가 오라클 문제의 전형적 예시다.

a) 데이터 출처를 모르는 것은 데이터 품질 문제이지 오라클 문제가 아니다.
c) 자율성은 오라클과 무관하다.
d) 투명성 부족은 화이트박스 테스팅을 어렵게 하지만 오라클 문제와 다른 차원이다.

관련 학습 목표: AI-8.7.1 (K2) — 테스트 오라클 문제의 사례

Q24. A/B 테스팅

문제: 다음 중 A/B 테스팅에 대한 설명으로 올바른 것은?
  • a) A/B 테스팅에 두 가지 다른 프로그램을 사용하기 때문에 차등 테스팅(differential testing)이라고도 한다.
  • b) A/B 테스팅은 복잡한 모델에 대한 정확한 결과를 가져오지 않기 때문에 간단한 기계학습(ML) 모델을 테스트하는 데 주로 유용하다.
  • c) A/B 테스팅에서는 테스트한 모델의 주요 차이점 식별을 위해 같은 입력에 대해 여러 예상 결과를 비교해야 한다.
  • d) A/B 테스팅은 다양한 기계학습(ML) 모델, 특히 자가학습 시스템을 위한 테스트 케이스 작성에 좋은 기법이다.

정답: c)

A/B 테스팅은 같은 입력(또는 같은 사용자 집단의 일부)에 대해 모델 A의 결과와 모델 B의 결과를 비교해 어느 쪽이 더 나은지 판단하는 기법이다. 따라서 잘 정의된 비교 기준(예: 클릭률, 변환율)이 필수다.

a) 차등 테스팅이라고도 불리는 것은 백투백 테스팅이다.
b) A/B 테스팅은 단순/복잡 모델 가리지 않고 사용한다.
d) A/B 테스팅은 모델 비교용이지 테스트 케이스 작성 기법이 아니다.

관련 학습 목표: AI-9.4.1 (K2) — A/B 테스팅의 정의

Q25. 가상 테스트 환경의 이점

문제: 다음 설명 중 AI 기반 시스템 테스팅에서 가상 테스트 환경이 제공하는 이점과 가장 거리가 먼 것은?
  • a) 매우 드물게 발생하는 시나리오(예: 설 연휴 혼잡 제어)를 테스트할 수 있도록 스마트 시티 애플리케이션을 가상 테스트 환경에서 테스트한다.
  • b) 잠재적인 비용발생 때문에 실제 금융시장에서 테스트하는 것이 비현실적이므로 AI 기반 금융시장 거래 시스템을 가상 테스트 환경에서 테스트한다.
  • c) 과일이 상하지 않았는지 확인할 수 있도록 빠른 기간내에 다양한 수확 시나리오를 실행하기 위해 스마트 과일 수확기(smart fruit picker)를 가상 테스트 환경에서 테스트한다.
  • d) 잠재적으로 위험한 테스트 시나리오를 안전하게 실행할 수 있도록 자율주행차를 가상 테스트 환경에서 테스트한다.

정답: c)

가상 환경은 희귀 시나리오 재현, 위험 회피, 비용 절감에 유리하다. 그러나 "과일이 실제로 상하지 않았는지" 같은 물리적·생물학적 결과는 시뮬레이션에서 정확히 모델링하기가 훨씬 어렵다. 이런 검증은 오히려 실제 환경에서 해야 한다.

a) 희귀 시나리오는 가상 환경의 대표 용도다.
b) 실제 거래에서 손실이 발생하기 때문에 가상 환경이 합리적이다.
d) 안전을 위한 가상 환경 사용은 자율주행 테스트의 표준이다.

관련 학습 목표: AI-10.2.1 (K2) — 가상 테스트 환경의 한계와 장점

Q26. AI 소프트웨어 엔지니어링 기법

문제: AI 지원 테스트 자동화 도구(AI-assisted test automation tool)를 사용해 위치 참조를 사용하는 대신에 이미지 처리를 통해 개체를 인식하는 것이 가능하다. 다음 중 위에서 언급하고 있는 AI 소프트웨어 엔지니어링 기술 유형은?
  • a) 분류, 학습 및 예측
  • b) 확률적 소프트웨어 엔지니어링
  • c) 검색 기반 소프트웨어 엔지니어링
  • d) 클러스터링

정답: a)

GUI 자동화 도구가 좌표 대신 화면 캡처에서 버튼·아이콘을 찾아내는 방식은 이미지 분류 모델로 구현된다. 분류·학습·예측 범주에 속한다.

b) 확률적 SW 엔지니어링은 특정 사건의 발생 확률을 추정하는 기법이다.
c) 검색 기반 SW 엔지니어링은 큰 탐색 공간을 줄이는 기법이다.
d) 클러스터링은 알고리즘 한 형태이지 SW 엔지니어링 기법 분류가 아니다.

관련 학습 목표: AI-11.1.1 (K2) — AI 소프트웨어 엔지니어링 기법 분류

Q27. 시각적 테스팅

문제: 다음 중 시각적 테스팅(visual testing)을 올바르게 설명하고 있는 것은?
  • a) 시각적 테스팅은 객체 ID를 사용해 변경사항을 결정한다.
  • b) 시각적 테스팅은 픽셀 단위 비교를 위해 이미지를 사용한다.
  • c) 시각적 테스팅은 중복되는 사용자 인터페이스 요소를 찾도록 해준다.
  • d) 시각적 테스팅은 스크린 레이아웃을 변경하면 실패한다.

정답: c)

현대적 시각적 테스팅 도구는 사람 테스터가 화면을 보는 것처럼 UI 요소의 의미·중복·정렬 같은 시각적 품질을 검사한다. 픽셀 단위 비교의 한계를 AI가 보완하기 때문에 작은 레이아웃 변경에도 강건하다.

a) 객체 ID 기반은 전통적 GUI 자동화의 방식이다.
b) 단순 픽셀 비교는 옛날 방식이다. AI 기반 시각적 테스팅은 픽셀이 아닌 의미 단위로 비교한다.
d) 오히려 레이아웃 변경에도 잘 동작하는 것이 시각적 테스팅의 장점이다.

시험 마무리 종합 팁

CT-AI 시리즈의 마지막 글이므로, 시험 직전에 한 번 더 떠올리면 좋을 점들을 정리한다. 학습 계획, 챕터 정리, 샘플 풀이를 모두 거친 사람을 기준으로 한다.

60분 시간 배분 전략

CT-AI는 40문항·60분이라 문제당 평균 90초다. 다음 3단계로 풀면 시간이 거의 부족하지 않는다.

3단계 풀이 흐름
  • 1차 (30분) — 모든 문제를 처음부터 끝까지 훑으며 K1·K2 짧은 문제는 즉답한다. K3 시나리오 문제는 답이 떠오르면 표시하고, 막히면 표시만 남기고 넘긴다.
  • 2차 (20분) — 미루어 둔 K3 시나리오 문제와 헷갈리는 문제를 푼다. 보기 4개 중 명백히 틀린 것 2개를 먼저 제거하고 남은 2개에서 판단한다.
  • 3차 (10분) — 전체 검토. "두 개 고르시오" 문제는 답을 정확히 2개 표시했는지, 부정 표현("아닌 것"·"거리가 먼")을 놓치지 않았는지 확인한다.

"두 개 고르시오" 문제 대응

CT-AI에서는 보기 5개 중 두 개를 고르는 문제가 평균 2~3문항 출제된다. 다음 원칙을 지킨다.

복수 정답 문제 원칙
  • 정확히 2개를 골라야 점수가 인정된다. 1개만 골라도 0점, 3개를 골라도 0점이다.
  • 보기 중 "절반은 맞고 절반은 틀린" 형태가 자주 함정이다. 부분적으로 옳더라도 한 부분이 틀리면 제외한다.
  • 두 정답은 보통 같은 범주의 다른 측면이다. 예를 들어 테스터의 역량을 묻는다면 "도메인 지식"과 "비판적 사고"처럼 성격이 비슷한 두 항목이 짝지어진다.

자주 헷갈리는 영문 용어 마지막 점검

한글 번역만으로는 구분이 어려운 용어들을 영문과 함께 마지막으로 외운다.

Transparency 투명성
시스템이 AI라는 사실과 작동 원리·데이터가 공개되어 있는가
Interpretability 해석가능성
시스템이 어떻게 작동하는지(메커니즘)를 이해할 수 있는가
Explainability 설명가능성
시스템이 특정 결정을 왜 그렇게 내렸는지 설명할 수 있는가
Flexibility 유연성
설계 범위 밖 상황에서도 사용 가능한가 (사용 범위의 너비)
Adaptability 적응성
환경 변화에 따라 스스로 변하는 능력
Autonomy 자율성
사람 개입 없이 얼마나 오래 스스로 작동하는가
Concept Drift 컨셉 드리프트
시간이 지나며 데이터 분포·행동 변화로 성능 저하
Adversarial Attack 적대적 공격
의도적으로 입력을 교란해 잘못된 예측 유도
Bias 편향
훈련 데이터에서 시작되어 입력 데이터 단계에서 검사
A/B Testing
두 모델의 결과를 같은 입력에 대해 비교 (≠ 백투백)
Back-to-back Testing
차등 테스팅(differential testing)이라고도 불림
Metamorphic Testing
오라클이 없을 때 입력 변환과 결과 관계로 검증
Test Oracle Problem
기대 결과를 알 수 없는 예측 시스템의 본질적 문제
Model Evaluation vs Testing
평가=검증 데이터, 테스팅=테스트 데이터로 별개 단계

시험장 들어가기 전 마지막 5분 체크리스트

학습 유형 3가지 — 지도/비지도/강화. 각각 라벨·패턴·보상으로 한 단어 매칭.
ML 워크플로우 7단계 — 목표 정의 → 데이터 준비 → 모델 선택 → 모델 빌드/컴파일 → 모델 훈련 → 모델 평가 → 모델 튜닝 → 모델 테스팅 → 배포 순.
혼동행렬과 지표 — 정확도, 정밀도, 재현율, F1의 공식을 머릿속에 그릴 수 있어야 한다.
데이터 분할 — 훈련/검증/테스트의 역할 차이. 테스트 데이터는 끝까지 격리.
AI 윤리 4원칙 — 자율성 존중, 피해 방지, 공정성, 설명가능성.
표준 매칭 — GDPR=개인 정보, ISO 26262=자동차 결정적 시스템, SOTIF=의도된 기능 안전, ISO/IEC 23053·22989=AI 일반 표준.
적대적 공격 vs 데이터 중독 — 운영 시 입력 교란이 적대적 공격, 훈련 데이터 오염이 데이터 중독(data poisoning).
K-레벨 감각 — K1은 정의, K2는 설명/사례 판별, K3은 시나리오에 기법 적용. 시간 배분 시 참고.
마지막 한마디
  • CT-AI는 코드 구현이 아니라 "AI 시스템을 어떻게 테스트할 것인가"를 묻는 시험이다. 항상 테스터의 관점에서 답을 고른다.
  • 긴 시나리오 문제에서 헷갈리면 보기 4개 중 어느 것이 "테스터가 실제로 할 일"에 가장 가까운지 떠올린다.
  • 시험은 합격선만 넘기면 된다. 모든 문제를 100% 알 필요는 없다. 확실한 것부터 챙기고 모르는 문제는 표시 후 넘어간다.
