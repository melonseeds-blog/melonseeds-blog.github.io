열거형(enum)과 패턴 매칭(match)

2026-06-25 약 8분 분량 Rust 시리즈
이 편에서 배우는 것 Rust의 enum은 단순한 상수 묶음이 아니라 변형마다 서로 다른 데이터를 담는 합타입(sum type)이다. 이 글에서는 데이터를 보유하는 enum 변형을 정의하고, match로 그 값을 안전하게 분해하는 법을 다룬다. 컴파일러가 모든 변형을 강제로 처리하게 만드는 완전성(exhaustiveness) 검사, 한 가지 경우만 볼 때 쓰는 if let, 그리고 패턴 안에서 값을 꺼내 묶는 패턴 바인딩까지 순서대로 본다. C++의 enum·std::variant와 어떻게 다른지도 짚는다.

enum이 왜 필요한가

프로그램은 "여러 경우 중 하나"인 값을 자주 다룬다. 신호등은 빨강·노랑·초록 중 하나이고, 도형은 원이거나 사각형이다. C++에서는 이런 경우를 보통 enum으로 표현하지만, C++의 전통적 enum은 정수에 이름을 붙인 것에 가깝다. 각 경우에 딸린 데이터를 함께 담지는 못한다.

Rust의 enum은 한 걸음 더 나아간다. 각 변형(variant)이 서로 다른 형태의 데이터를 보유할 수 있다. 즉 "이 값은 A이거나 B이거나 C이고, 각 경우마다 들고 다니는 정보가 다르다"를 타입 하나로 표현한다. 타입 이론에서 말하는 합타입(sum type)이며, 이것이 Rust enum의 핵심이다.

가장 단순한 형태는 C 스타일과 같다.

// 데이터 없는 단순 변형 — C 스타일 enum과 유사하다.
enum Direction {
    North,
    East,
    South,
    West,
}

fn main() {
    let heading = Direction::North;

    // match로 각 변형을 처리한다.
    let degrees = match heading {
        Direction::North => 0,
        Direction::East => 90,
        Direction::South => 180,
        Direction::West => 270,
    };

    println!("heading = {} degrees", degrees);
}

여기까지는 C++ enum과 큰 차이가 없어 보인다. 차이는 변형이 데이터를 들고 다니기 시작할 때 드러난다.

데이터를 보유하는 변형

각 변형은 튜플처럼 값을 묶거나, 구조체처럼 이름 붙은 필드를 가질 수 있다. 하나의 enum 안에서 변형마다 형태가 달라도 된다.

// 변형마다 다른 데이터를 보유한다.
enum Shape {
    Circle { radius: f64 },              // 구조체형 변형
    Rectangle { width: f64, height: f64 },
    Point,                               // 데이터 없는 변형
}

// 면적을 계산한다. 모든 변형을 분해해 값을 꺼낸다.
fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle { radius } => std::f64::consts::PI * radius * radius,
        Shape::Rectangle { width, height } => width * height,
        Shape::Point => 0.0,
    }
}

fn main() {
    let shapes = [
        Shape::Circle { radius: 2.0 },
        Shape::Rectangle { width: 3.0, height: 4.0 },
        Shape::Point,
    ];

    // 참조로 순회하므로 배열의 소유권은 그대로 둔다.
    for s in &shapes {
        println!("area = {:.2}", area(s));
    }
}

area는 &Shape를 받아 빌림(borrow)만 한다. 따라서 호출한 쪽의 shapes는 소유권을 잃지 않고, 함수가 끝난 뒤에도 그대로 쓸 수 있다. match 안의 radius·width 같은 이름은 변형 내부 값을 가리키는 참조로 묶이며, 곱셈에서 자동 역참조되어 그대로 계산에 쓰인다.

패턴 바인딩 — 값을 꺼내 묶기

match의 각 가지(arm)에서 변형 내부 데이터를 변수로 묶는 것을 패턴 바인딩이라 한다. C++에서 std::get<T>로 꺼낸 뒤 직접 변수에 대입하던 과정이, Rust에서는 패턴을 쓰는 순간 한 번에 일어난다. 표준 라이브러리의 Option<T>가 대표적인 예다.

// Option은 표준 라이브러리 enum이다: Some(값) 또는 None.
fn first_char(text: &str) -> Option<char> {
    text.chars().next()
}

fn main() {
    let label = String::from("Rust");

    // Some(c)에서 c로 내부 char를 바인딩한다.
    match first_char(&label) {
        Some(c) => println!("first char: {}", c),
        None => println!("empty string"),
    }

    // label은 &label로 빌려줬을 뿐이라 여기서도 유효하다.
    println!("label is still usable: {}", label);
}

Some(c)에서 c는 Some 안의 char 값으로 묶인다. 변형을 확인하는 동작과 그 안의 데이터를 꺼내는 동작이 한 문법으로 합쳐져, 잘못된 변형의 데이터에 손대는 실수를 원천적으로 막는다.

match와 완전성 검사

Rust match의 가장 중요한 성질은 완전성(exhaustiveness)이다. enum의 모든 변형을 빠짐없이 다루지 않으면 컴파일이 거부된다. 변형 하나라도 처리하지 않은 채로 두면, 그건 깜빡 잊은 버그일 가능성이 높다고 컴파일러가 보는 것이다.

enum Event {
    Click { x: i32, y: i32 },
    KeyPress(char),
    Close,
}

fn describe(event: &Event) -> String {
    match event {
        Event::Click { x, y } => format!("click at ({}, {})", x, y),
        Event::KeyPress(key) => format!("key: {}", key),
        Event::Close => String::from("window closed"),
    }
    // 세 변형 중 하나라도 빠지면 컴파일 에러가 난다.
}

fn main() {
    let events = [
        Event::Click { x: 10, y: 20 },
        Event::KeyPress('a'),
        Event::Close,
    ];

    for e in &events {
        println!("{}", describe(e));
    }
}

여기서 만약 Event::Close 가지를 지우면, 컴파일러는 "Close 변형이 처리되지 않았다"며 빌드를 멈춘다. 나중에 enum에 새 변형을 추가했을 때도 마찬가지다. 그 변형을 처리하지 않은 모든 match가 즉시 컴파일 에러로 드러나므로, 어디를 고쳐야 하는지 컴파일러가 빠짐없이 알려 준다.

모든 경우를 일일이 적기 싫고 나머지를 한꺼번에 묶고 싶다면, 와일드카드 _나 포괄 변수 패턴을 마지막 가지에 둔다.

fn http_label(code: u16) -> &'static str {
    match code {
        200 => "OK",
        404 => "Not Found",
        500 => "Server Error",
        _ => "Other",   // 나머지 모든 경우를 포괄한다.
    }
}

fn main() {
    println!("{}", http_label(200));
    println!("{}", http_label(403));
}

다만 _를 enum에 습관적으로 붙이면, 새 변형을 추가했을 때 완전성 검사가 그걸 잡아 주지 못한다. 새 변형을 일부러 별도 처리하고 싶은 게 아니라면, enum match에서는 _를 아껴 쓰는 편이 컴파일러의 안전망을 더 잘 활용한다.

C++과 이렇게 다르다 — 합타입과 완전성 C++에서 "여러 타입 중 하나"를 담으려면 std::variant<Circle, Rectangle>을 쓰고, 분기는 std::visit에 오버로드된 호출 가능 객체를 넘겨 처리한다. 표준 라이브러리가 제공하는 기능이고, 문법도 다소 번잡하다. 더 중요한 차이는 누락 처리다. C++에서 어떤 대안(alternative)의 처리를 빠뜨려도 컴파일은 대체로 통과하고(잡힌다면 런타임 또는 별도 정적 분석 도구의 몫이다), Rust는 변형을 빠뜨린 match를 언어 차원에서 컴파일 에러로 막는다. Rust에서는 합타입(enum)과 그것을 분해하는 match·완전성 검사가 모두 언어에 내장되어 있다.

if let — 한 경우만 보기

변형이 여럿이어도 실제로는 한 가지 경우에만 관심이 있을 때가 있다. 이때 match로 모든 가지를 적는 것은 장황하다. if let은 패턴 하나가 맞을 때만 본문을 실행하는 간결한 문법이다.

fn main() {
    let maybe_port: Option<u16> = Some(8080);

    // Some일 때만 내부 값을 꺼내 쓴다. None이면 아무 일도 안 한다.
    if let Some(port) = maybe_port {
        println!("listening on port {}", port);
    }

    // else 가지로 나머지 경우도 처리할 수 있다.
    let config: Option<&str> = None;
    if let Some(path) = config {
        println!("config path: {}", path);
    } else {
        println!("using default config");
    }
}

if let Some(port) = maybe_port는 "maybe_port가 Some 변형이면 그 안의 값을 port로 묶고 본문을 실행하라"는 뜻이다. 같은 일을 match로 쓰면 관심 없는 None 가지까지 적어야 한다. if let은 그 match를 한 줄로 줄인 문법 설탕(syntactic sugar)이라고 보면 된다.

한 가지만 주의할 점은, if let은 완전성을 강제하지 않는다는 것이다. 나머지 경우를 침묵 속에 흘려보내도 컴파일러가 막지 않는다. 그러므로 "이 한 경우만 처리하면 충분하다"가 확실할 때 쓰고, 모든 변형을 반드시 다뤄야 하는 로직에는 match를 쓰는 편이 안전하다.

match와 if let, 언제 무엇을 모든 변형을 빠짐없이 처리해야 하고 컴파일러의 완전성 검사로 보호받고 싶으면 match를 쓴다. 관심 있는 변형이 하나뿐이고 나머지는 무시해도 안전하면 if let을 쓴다. 둘 다 같은 패턴 문법을 공유하므로, 패턴 바인딩으로 값을 꺼내는 방식은 어느 쪽이든 동일하다.

정리

  • enum은 합타입 — 각 변형이 서로 다른 데이터를 보유할 수 있다. C 스타일 상수 묶음을 넘어선다.
  • match는 완전하다 — 모든 변형을 다루지 않으면 컴파일 에러다. 새 변형을 추가하면 손볼 곳을 컴파일러가 짚어 준다.
  • 패턴 바인딩 — 변형 확인과 내부 값 꺼내기가 한 문법으로 합쳐져, 잘못된 변형의 데이터에 손대는 실수를 막는다.
  • if let — 한 변형만 관심 있을 때 match를 간결하게 줄이는 문법. 단, 완전성은 보장하지 않는다.
  • C++ 대비 — std::variant + visit가 라이브러리로 푸는 일을, Rust는 enum·match·완전성 검사로 언어 차원에서 제공한다.
