색공간이란?

색공간(color space)은 색을 수치로 표현하는 좌표계다. 우리가 눈으로 보는 색은 연속적인 물리량이지만, 컴퓨터가 다루려면 몇 개의 숫자로 바꿔야 한다. 그 숫자를 어떤 축으로 나눌지 정한 것이 색공간이다.

같은 색이라도 표현 방식은 여럿이다. 예를 들어 순수한 빨강은 RGB에서 (255, 0, 0)이지만, HSV에서는 (0, 255, 255)로 적힌다. 좌표계만 다를 뿐 가리키는 색은 같다. 중요한 점은 작업에 따라 편한 좌표계가 다르다는 것이다. 색상으로 물체를 골라내려면 HSV가 편하고, 색끼리 얼마나 다른지 재려면 Lab이 편하다.

색공간 변환은 데이터를 바꾸는 게 아니라 보는 각도를 바꾸는 것 같은 픽셀을 RGB로 보느냐 HSV로 보느냐의 차이다. 변환 자체가 정보를 만들어내지는 않지만, 원하는 정보를 다루기 쉬운 형태로 재배치한다. 그래서 전처리 단계에서 색공간 선택이 알고리즘 난이도를 크게 좌우한다.

BGR / RGB

RGB는 빛의 삼원색인 Red·Green·Blue를 축으로 삼는 색공간이다. 각 채널값을 0~255로 두면 256³ ≈ 1670만 가지 색을 표현한다. 모니터·카메라 센서가 물리적으로 이 세 가지 빛을 다루기 때문에 가장 직관적인 좌표계다.

OpenCV는 같은 데이터를 BGR 순서로 저장한다. Blue가 먼저, Red가 마지막이다. 라이브러리 초창기 Windows 비트맵 포맷을 따른 역사적 이유이며, 지금도 그대로 유지된다. 색 자체는 RGB와 동일하고 채널 배열 순서만 거꾸로다.

// OpenCV의 컬러 이미지는 BGR 순서로 저장된다
cv::Mat img(100, 100, CV_8UC3, cv::Scalar(255, 0, 0));
// → 파란색. Scalar의 첫 값이 Blue 채널이기 때문

// 빨간색을 원했다면 R 채널을 마지막에
cv::Mat red(100, 100, CV_8UC3, cv::Scalar(0, 0, 255));

// 채널을 분리해 보면 순서가 드러난다
std::vector<cv::Mat> channels;
cv::split(img, channels);
// channels[0] = Blue, channels[1] = Green, channels[2] = Red
OpenCV는 BGR, 대부분의 다른 라이브러리는 RGB matplotlib, Qt, PIL 등은 RGB를 기대한다. OpenCV가 읽은 이미지를 그대로 넘기면 빨강과 파랑이 뒤바뀐 채 표시된다. 라이브러리 경계를 넘을 때는 cv::cvtColor(img, rgb, cv::COLOR_BGR2RGB)로 변환해야 한다.

RGB(또는 BGR) 좌표계의 약점은 밝기와 색이 세 축에 뒤섞여 있다는 점이다. 조명이 어두워지면 R·G·B 세 값이 동시에 줄어든다. 같은 빨간 물체라도 그늘에 들어가면 (200, 30, 30)이 (90, 15, 15)처럼 변한다. "빨강"이라는 속성만 떼어내고 싶어도 세 채널 모두를 봐야 하므로, 단순 임계값으로 색을 골라내기 어렵다. 이 한계가 HSV·Lab·YCrCb 같은 색공간이 존재하는 이유다.

그레이스케일

그레이스케일은 색을 버리고 밝기 하나만 남긴 1채널 이미지다. 엣지 검출, 임계값 처리, 특징점 검출 같은 작업은 색이 필요 없으므로 그레이스케일로 변환해 연산량을 1/3로 줄인다.

BGR을 그레이스케일로 바꿀 때 단순 평균 (B+G+R)/3을 쓰지 않는다. 사람 눈은 초록에 가장 민감하고 파랑에 둔하기 때문에, 사람이 느끼는 밝기에 맞춰 가중 평균을 쓴다.

사람 눈의 채널별 민감도를 반영한 가중 평균. 초록의 비중이 가장 크다.
cv::Mat color = cv::imread("sample.jpg");  // CV_8UC3 (BGR)

// 방법 1 — 읽을 때 바로 그레이스케일로
cv::Mat gray1 = cv::imread("sample.jpg", cv::IMREAD_GRAYSCALE);

// 방법 2 — 이미 읽은 컬러 이미지를 변환
cv::Mat gray2;
cv::cvtColor(color, gray2, cv::COLOR_BGR2GRAY);

// 결과는 1채널
std::cout << gray2.channels() << std::endl;  // 1
// 내부적으로 적용되는 공식: Y = 0.299R + 0.587G + 0.114B
실행 결과 (콘솔)
1
0.299 / 0.587 / 0.114는 어디서 왔나 이 계수는 ITU-R BT.601 표준에서 정의한 휘도 가중치다. 뒤에 나오는 YCrCb의 Y 채널도 같은 공식을 쓴다. 즉 그레이스케일 변환은 사실상 YCrCb의 휘도 채널만 뽑아낸 것과 같다.

HSV / HSL

HSV는 색을 사람이 말로 설명하는 방식에 가깝게 나눈 색공간이다. 세 축은 다음과 같다.

채널의미OpenCV 범위 (CV_8U)
H (Hue)색상 — 빨강·노랑·초록 같은 색의 종류, 색상환의 각도0~179
S (Saturation)채도 — 색의 선명함. 0이면 무채색(회색)0~255
V (Value)명도 — 밝기. 0이면 검정0~255

핵심 장점은 색상(H)이 한 축에 독립적으로 분리되어 있다는 점이다. RGB에서는 "빨강"을 표현하려면 세 채널을 모두 봐야 하지만, HSV에서는 H 하나만 보면 된다. 조명이 바뀌어 어두워지면 주로 V가 줄고 H는 비교적 안정적으로 유지된다. 그래서 색상 기반 물체 분할에 HSV가 압도적으로 유리하다.

RGB는 세 빛이 정육면체를 이루고, HSV는 색상을 각도·채도를 반지름·명도를 높이로 둔 원뿔이다.
OpenCV의 H는 0~179다 (0~360 아님) 색상환의 각도는 원래 0~360°지만, 8비트 채널에 360을 담으면 255를 넘어 잘린다. 그래서 OpenCV는 각도를 절반으로 줄여 0~179로 저장한다. 다른 도구(웹 컬러 피커 등)에서 본 Hue 값을 그대로 쓰면 색이 어긋난다 — 2로 나눠야 한다.

HSL은 HSV와 사촌 관계인 색공간이다. H·S까지는 같고 마지막 축이 Value 대신 Lightness(밝기)다. HSV의 V는 가장 밝은 채널값을, HSL의 L은 가장 밝은 값과 어두운 값의 중간을 쓴다. CSS 색 지정 등에서 자주 보이지만, OpenCV 비전 작업에서는 HSV가 더 일반적이다.

cv::Mat bgr = cv::imread("sample.jpg");

cv::Mat hsv;
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);

// 특정 픽셀의 HSV 값 확인
cv::Vec3b pixel = hsv.at<cv::Vec3b>(100, 100);
std::cout << "H=" << (int)pixel[0]   // 0~179
          << " S=" << (int)pixel[1]   // 0~255
          << " V=" << (int)pixel[2]   // 0~255
          << std::endl;

// HSL이 필요하면 COLOR_BGR2HLS 사용
cv::Mat hls;
cv::cvtColor(bgr, hls, cv::COLOR_BGR2HLS);

Lab

Lab(정확히는 CIELAB)은 지각 균일(perceptually uniform)을 목표로 설계된 색공간이다. 지각 균일이란 색공간에서 두 점 사이의 거리가 사람이 느끼는 색 차이와 비례한다는 뜻이다. RGB에서는 좌표상 같은 거리라도 어떤 영역은 차이가 확 느껴지고 어떤 영역은 거의 안 느껴진다. Lab은 이 불균형을 줄였다.

채널의미비고
L밝기 (Lightness)0(검정) ~ 100, 색 정보 없음
a초록 ↔ 빨강 축음수는 초록, 양수는 빨강
b파랑 ↔ 노랑 축음수는 파랑, 양수는 노랑

가장 큰 실용 가치는 색차(ΔE) 계산이다. 두 색의 Lab 좌표 사이 유클리드 거리가 곧 사람이 느끼는 색 차이의 척도가 된다. 산업용 색 검사 — 인쇄물 색 일치 여부, 도장 색 편차 측정 등 — 에서 Lab이 표준으로 쓰이는 이유다. HSV로는 "이 두 색이 얼마나 다른가"를 일관되게 재기 어렵다.

cv::Mat bgr1 = cv::imread("ref.png");
cv::Mat bgr2 = cv::imread("sample.png");

cv::Mat lab1, lab2;
cv::cvtColor(bgr1, lab1, cv::COLOR_BGR2Lab);
cv::cvtColor(bgr2, lab2, cv::COLOR_BGR2Lab);

// 두 이미지의 평균 색차(ΔE)를 구한다
cv::Scalar mean1 = cv::mean(lab1);
cv::Scalar mean2 = cv::mean(lab2);

double deltaE = std::sqrt(
    std::pow(mean1[0] - mean2[0], 2) +   // L 차이
    std::pow(mean1[1] - mean2[1], 2) +   // a 차이
    std::pow(mean1[2] - mean2[2], 2));   // b 차이

std::cout << "delta E = " << deltaE << std::endl;
// ΔE 가 작을수록 두 색이 가깝다 (보통 2.3 이하면 육안 구별 어려움)
8비트 Lab은 값이 압축되어 저장된다 Lab의 L은 본래 0~100, a·b는 약 -128~127 범위다. 하지만 CV_8U 이미지로 변환하면 OpenCV가 L에 255/100을 곱하고 a·b에는 128을 더해 0~255로 욱여넣는다. 정밀한 ΔE 계산이 필요하면 CV_32F로 변환해 원래 스케일을 유지하는 편이 안전하다.

YCrCb

YCrCb는 영상을 휘도(Y)와 색차(Cr, Cb)로 분리하는 색공간이다. 방송·영상 압축 분야에서 출발했다.

채널의미비고
Y휘도 (Luma) — 밝기그레이스케일과 동일한 가중치
Cr빨강 색차 (R - Y 계열)빨강 성분의 치우침
Cb파랑 색차 (B - Y 계열)파랑 성분의 치우침

밝기와 색을 분리하면 두 가지 이점이 생긴다. 첫째, 압축: 사람 눈은 밝기 변화에는 예민하고 색 변화에는 둔하므로, Y는 그대로 두고 Cr·Cb만 해상도를 낮춰도 티가 잘 안 난다. JPEG·MPEG의 크로마 서브샘플링이 이 원리다. 둘째, 피부색 검출: 사람 피부색은 밝기가 제각각이어도 Cr·Cb 평면에서는 좁은 타원 영역에 모인다. 그래서 조명에 강건한 피부 검출기를 만들 수 있다.

cv::Mat bgr = cv::imread("face.jpg");

cv::Mat ycrcb;
cv::cvtColor(bgr, ycrcb, cv::COLOR_BGR2YCrCb);

// 피부색 범위로 마스킹 (Y는 넓게, Cr/Cb는 좁게)
cv::Mat skinMask;
cv::inRange(ycrcb,
            cv::Scalar(0, 133, 77),     // Y_min, Cr_min, Cb_min
            cv::Scalar(255, 173, 127),  // Y_max, Cr_max, Cb_max
            skinMask);

// Y 채널만 따로 뽑으면 그레이스케일과 거의 같다
std::vector<cv::Mat> ch;
cv::split(ycrcb, ch);
cv::Mat luma = ch[0];  // ≈ COLOR_BGR2GRAY 결과
밝기만 손대고 싶을 때도 유용하다 대비 보정(예: 히스토그램 평활화)을 컬러 이미지에 적용할 때, BGR 세 채널에 각각 적용하면 색이 틀어진다. YCrCb로 바꿔 Y 채널에만 평활화를 걸고 다시 합치면 색은 유지한 채 명암만 개선된다.

cvtColor 사용법

모든 색공간 변환은 cv::cvtColor(src, dst, code) 하나로 처리한다. 세 번째 인자 code가 어디에서 어디로 변환할지 지정하는 상수다. 형식은 COLOR_<출발>2<도착>이다.

변환 코드방향대표 용도
COLOR_BGR2GRAYBGR → 그레이스케일엣지·임계값·특징점 전처리
COLOR_GRAY2BGR그레이스케일 → BGR흑백 위에 컬러로 그리기
COLOR_BGR2RGBBGR → RGB다른 라이브러리로 전달
COLOR_BGR2HSVBGR → HSV색상 기반 분할
COLOR_HSV2BGRHSV → BGRHSV에서 만든 결과를 표시
COLOR_BGR2LabBGR → Lab색차 계산, 색 검사
COLOR_BGR2YCrCbBGR → YCrCb피부색 검출, 밝기 보정
COLOR_BayerBG2BGRBayer → BGR산업 카메라 디모자이킹
cv::Mat bgr = cv::imread("sample.jpg");

// 한 번 변환
cv::Mat hsv;
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);

// 왕복 변환 — HSV에서 작업한 결과를 다시 BGR로
cv::Mat back;
cv::cvtColor(hsv, back, cv::COLOR_HSV2BGR);

// 그레이스케일은 1채널이므로 다시 BGR로 올려야
// 컬러 도형을 그릴 수 있다
cv::Mat gray, grayBgr;
cv::cvtColor(bgr, gray, cv::COLOR_BGR2GRAY);
cv::cvtColor(gray, grayBgr, cv::COLOR_GRAY2BGR);
cv::circle(grayBgr, {50, 50}, 20, cv::Scalar(0, 0, 255), 2);  // 빨간 원
왕복 변환은 완벽하게 원본으로 돌아오지 않는다 BGR → HSV → BGR을 거치면 부동소수 연산을 8비트 정수로 반올림하는 과정에서 미세한 오차가 쌓인다. 한두 번은 눈에 안 띄지만 반복 변환을 누적하면 색이 조금씩 흐려진다. 색공간 변환은 손실이 있을 수 있다는 점을 전제로 설계해야 한다.

실전 — HSV 색 기반 분할

가장 흔한 색공간 활용 사례다. 영상에서 특정 색의 물체만 골라내는 작업을 단계별로 본다. 흐름은 아래와 같다.

HSV 색 분할 파이프라인 — 변환 후 색 범위로 마스킹하고 모폴로지로 잡음을 정리한다.

inRange로 색 범위 마스킹

cv::inRange는 각 픽셀이 지정한 하한·상한 사이에 있으면 255, 아니면 0인 마스크를 만든다. HSV로 변환한 뒤 H 범위로 색을 지정하면 조명 변화에 비교적 강건한 마스크를 얻는다.

cv::Mat bgr = cv::imread("objects.jpg");

cv::Mat hsv;
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);

// 파란색 물체 마스킹 — H는 약 100~130 부근
cv::Mat blueMask;
cv::inRange(hsv,
            cv::Scalar(100,  80,  50),   // H_min, S_min, V_min
            cv::Scalar(130, 255, 255),   // H_max, S_max, V_max
            blueMask);

// 마스크로 원본에서 파란 물체만 추출
cv::Mat result;
cv::bitwise_and(bgr, bgr, result, blueMask);

S와 V에도 최소값을 둔 점이 중요하다. S가 너무 낮으면 거의 회색인 픽셀까지 잡히고, V가 너무 낮으면 검정에 가까운 픽셀이 섞인다. 채도·명도 하한으로 "충분히 선명하고 충분히 밝은" 픽셀만 남긴다.

빨강 — H가 양 끝에 걸친 색

빨강은 색상환에서 0°(= H 0) 근처에 있는데, 0을 기준으로 양쪽으로 펼쳐진다. OpenCV의 H 범위로 보면 빨강은 0 근처와 179 근처 양 끝에 동시에 걸린다. 한 번의 inRange로는 잡을 수 없으므로 두 구간을 따로 만들어 합친다.

cv::Mat hsv;
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);

// 빨강 하단 구간 (H: 0~10)
cv::Mat lowerRed;
cv::inRange(hsv, cv::Scalar(0,   100, 80),
                 cv::Scalar(10,  255, 255), lowerRed);

// 빨강 상단 구간 (H: 170~179)
cv::Mat upperRed;
cv::inRange(hsv, cv::Scalar(170, 100, 80),
                 cv::Scalar(179, 255, 255), upperRed);

// 두 마스크를 OR로 합쳐 빨강 전체를 얻는다
cv::Mat redMask;
cv::bitwise_or(lowerRed, upperRed, redMask);
색상환이 원형이라 생기는 일 H는 각도이므로 179 다음은 다시 0으로 이어진다. 빨강처럼 0°에 걸친 색만 이 처리가 필요하고, 파랑·초록·노랑처럼 중간에 있는 색은 한 구간으로 충분하다.

모폴로지로 마스크 정리

inRange가 만든 마스크는 보통 자잘한 잡음 점과 구멍이 섞여 있다. 모폴로지 연산으로 다듬는다. MORPH_OPEN(침식 후 팽창)은 작은 잡음 점을 지우고, MORPH_CLOSE(팽창 후 침식)는 물체 내부의 작은 구멍을 메운다.

// 5x5 사각 커널
cv::Mat kernel = cv::getStructuringElement(
    cv::MORPH_RECT, cv::Size(5, 5));

cv::Mat cleaned;
// 1) 잡음 점 제거
cv::morphologyEx(redMask, cleaned, cv::MORPH_OPEN, kernel);
// 2) 내부 구멍 메우기
cv::morphologyEx(cleaned, cleaned, cv::MORPH_CLOSE, kernel);

// 정리된 마스크로 윤곽선을 찾으면 깔끔한 물체 영역을 얻는다
std::vector<std::vector<cv::Point>> contours;
cv::findContours(cleaned, contours,
                 cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
std::cout << "검출된 물체 수: " << contours.size() << std::endl;

색공간별 용도 비교

어떤 작업에 어떤 색공간을 고를지는 거의 정해진 패턴이 있다.

색공간구조강점대표 용도
BGR / RGB빛의 삼원색 3축센서·디스플레이와 직접 대응, 직관적입출력, 표시, 저장
Gray밝기 1축연산량 1/3, 색 무관 알고리즘에 적합엣지·임계값·특징점 검출
HSV / HSL색상·채도·명도색상이 한 축에 분리, 조명에 비교적 강건색 기반 물체 분할·추적
Lab밝기 + 색 대립 2축지각 균일, 색차(ΔE)가 사람 감각과 비례색차 측정, 산업 색 검사
YCrCb휘도 + 색차 2축밝기·색 완전 분리피부색 검출, 압축, 밝기 보정
한 줄 요약 읽고 쓰는 건 BGR, 모양만 보면 Gray, 색으로 고르면 HSV, 색 차이를 재면 Lab, 밝기와 색을 떼어내려면 YCrCb다.

흔한 함정

색공간을 다룰 때 반복해서 나오는 실수들이다.

BGR을 RGB로 착각

OpenCV가 읽은 이미지는 BGR이다 cv::Scalar(255, 0, 0)은 빨강이 아니라 파랑이고, OpenCV 이미지를 RGB 기대 라이브러리에 그대로 넘기면 색이 뒤집힌다. 채널 순서를 항상 의식하고, 경계를 넘을 때는 COLOR_BGR2RGB로 명시적으로 변환한다.

HSV의 H 범위 (0~179 vs 0~360)

웹에서 본 Hue 값을 그대로 쓰면 안 된다 포토샵·CSS·온라인 컬러 피커는 보통 H를 0~360으로 표시한다. OpenCV의 8비트 H는 0~179다. "Hue 240인 파랑"을 OpenCV에서 쓰려면 120으로 환산해야 한다. 2로 나누는 것을 잊으면 엉뚱한 색을 마스킹한다.

단일 threshold로 색 분할

고정된 임계값은 조명이 바뀌면 무너진다 실험실에서 맞춘 inRange 범위가 현장의 다른 조명에서는 물체를 놓치거나 배경을 잡는다. HSV가 RGB보다 조명에 강건한 것은 사실이지만 면역은 아니다. 가능하면 조명을 통제하고, 어렵다면 S·V 범위를 넉넉히 두거나 화이트 밸런스 보정을 전처리에 넣는다.

색공간 변환은 손실이 있을 수 있다

8비트 이미지의 색공간 변환은 부동소수 계산 결과를 정수로 반올림한다. 한 번 변환은 거의 무손실에 가깝지만, BGR↔HSV를 여러 번 왕복하면 오차가 누적된다. 변환된 색공간에서 작업을 끝낸 뒤 마지막에 한 번만 되돌리는 방식으로 변환 횟수를 최소화한다.

// 나쁨 — 단계마다 왕복 변환, 오차 누적
cv::Mat hsv, tmp;
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);
cv::cvtColor(hsv, tmp, cv::COLOR_HSV2BGR);   // 되돌렸다가
cv::cvtColor(tmp, hsv, cv::COLOR_BGR2HSV);   // 다시 변환...

// 좋음 — HSV로 한 번 변환, 작업 끝낸 뒤 한 번만 복귀
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);
// ... HSV 공간에서 필요한 작업 모두 수행 ...
cv::Mat finalBgr;
cv::cvtColor(hsv, finalBgr, cv::COLOR_HSV2BGR);
정리하면 OpenCV는 BGR임을 기억하고, HSV의 H는 0~179로 환산하고, 고정 임계값은 조명에 약하다는 점을 전제하고, 변환은 손실이 있으니 횟수를 최소화한다. 이 네 가지를 의식하면 색공간 관련 버그 대부분을 피한다.
