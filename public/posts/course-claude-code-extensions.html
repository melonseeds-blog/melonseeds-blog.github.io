Introduction to Subagents

Subagent는 "메인 Claude 세션이 필요할 때 호출하는 별도 에이전트"다. 컨텍스트가 분리되고, 자기 도구 세트와 자기 시스템 프롬프트를 가진다. 강의는 네 차시로 이를 풀어 간다.

L1Subagent란 무엇인가 (What are subagents?)

핵심 개념은 "컨텍스트 윈도우의 분리"다. 메인 에이전트가 직접 큰 작업을 다 끌어안으면 윈도우가 빠르게 차고 판단력이 떨어진다. Subagent에게 위임하면 작업을 그쪽 윈도우에서 수행하고, 메인은 요약 결과만 받아 간다. 일종의 함수 호출과 비슷한 추상이다.

L2Subagent 만들기 (Creating a subagent)

/agents 명령으로 인터랙티브하게 만든다. 이름·역할·시스템 프롬프트·허용 도구를 정의하고, .claude/agents/ 디렉터리에 Markdown 파일로 저장된다. 프로젝트 단위로도 사용자 글로벌로도 만들 수 있다.

L3좋은 Subagent 설계 (Designing effective subagents)

강의의 핵심 차시다. 좋은 Subagent는 다음 세 가지를 가진다.

  • 좁은 책임 — "모든 일을 잘 한다"가 아니라 "이 한 가지를 잘 한다"
  • 명시적 출력 형식 — 메인 에이전트가 받아서 쓸 구조를 미리 정의
  • 실패 보고 — 못 한 경우 무엇을 못 했는지 분명히 돌려보냄

L4효과적으로 쓰기 (Using subagents effectively)

안티패턴이 같이 나온다. 가장 흔한 실수는 "한 작업을 1초 단축하려고 Subagent를 부르는 것"이다. 호출/요약 자체에 오버헤드가 있어서 작은 일에는 오히려 손해다. 또한 같은 컨텍스트를 봐야 하는 작업(예: 메인 세션의 대화 흐름에 깊이 얽힌 결정)은 위임이 잘 안 된다.

Subagent를 쓸 만한 신호 (1) 컨텍스트가 크고 따로 분리해도 무관한 조사형 작업, (2) 결과만 받으면 되는 변환 작업(코드 리뷰, 테스트 작성, 데이터 추출), (3) 여러 번 같은 형태로 반복되는 위임. 이 셋이 아닐 때는 메인이 직접 하는 게 보통 더 빠르다.

Introduction to Agent Skills

Skill은 "절차를 Markdown으로 적어 두면 트리거 조건에 맞을 때 자동 로드되는 모듈"이다. Anthropic이 표어로 쓰는 표현이 "stop repeating yourself and start teaching Claude once"인데 정확히 이 의미다.

L1Skill이란 (What are skills?)

Skill은 디렉터리 단위로 구성된 Markdown 패키지다. 기본 구조는 SKILL.md 한 장이고, 그 안의 frontmatter에 "이 Skill은 언제 트리거되는가"를 자연어로 적는다. 모델이 그 설명을 읽고 매 턴 "지금 이걸 써야 하나?"를 자율 판단한다.

L2첫 Skill 만들기 (Creating your first skill)

가장 단순한 형태는 SKILL.md 하나만 가지는 디렉터리다. 예: "PR 머지 직전에 항상 변경 로그를 업데이트하라"를 적어 두면, 모델이 PR 머지 흐름을 감지했을 때 자동으로 그 절차를 따른다. 실행은 모델이 직접 한다.

L3설정과 다중 파일 (Configuration and multi-file skills)

Skill 디렉터리에 추가 파일을 둘 수 있다. 예시 입력·출력 샘플, 스크립트, 보조 Markdown 등을 함께 포함한다. 모델은 SKILL.md를 먼저 읽고 필요할 때 추가 파일을 자율적으로 로드한다. 컨텍스트 윈도우를 절약하는 "지연 로드" 구조다.

L4다른 기능과의 차이 (Skills vs. other Claude Code features)

강의에서 가장 자주 헷갈리는 부분을 정리해 준다. Skill은 "절차적 지식의 패키지"이고, Subagent는 "별도 실행 컨텍스트"이고, MCP는 "외부 도구 연결"이고, Hook은 "라이프사이클 자동화"다. 본 글의 다음 절에서 더 자세히 본다.

L5공유와 배포 (Sharing skills)

Skill은 그냥 디렉터리이므로 git에 같이 커밋해서 팀 전체가 쓸 수 있다. 글로벌 사용자 디렉터리에도 둘 수 있고, 플러그인으로 배포해서 다른 팀이 받아 가게 할 수도 있다. 일종의 "조직 차원의 지식 베이스"로 진화할 가능성이 있다.

L6트러블슈팅 (Troubleshooting skills)

가장 흔한 문제는 "Skill이 트리거되지 않는 것"이다. 원인은 거의 항상 frontmatter의 트리거 설명이 모호하거나 너무 좁기 때문이다. 강의는 "트리거 문장은 사용자가 어떤 말을 했을 때 발동해야 하는지를 구체적으로 적어라"라고 안내한다.

Subagent vs Skill — 언제 무엇을

두 강의를 함께 듣고 나서 가장 자주 받는 질문이 "그래서 둘 중 뭘 쓰지?"다. 정리하면 다음과 같다.

구분SubagentSkill
본질별도 실행 컨텍스트절차적 지식의 패키지
실행 방식독립된 에이전트 인스턴스 호출메인 에이전트가 그 자리에서 따름
컨텍스트분리됨(메인 윈도우 절약)메인 윈도우 안에서 동작
전형적 용도큰 조사·변환·리뷰의 위임반복 절차·체크리스트·코딩 컨벤션
비유전문 외주 업체에 의뢰회사 사내 매뉴얼
두 개를 같이 쓸 수도 있다 강의는 둘이 배타적이 아님을 강조한다. Skill에 "이 작업은 review-subagent에 위임하라"고 적어 두면, Skill이 트리거되고 그 안에서 Subagent를 호출하는 합성이 가능하다.

실무 적용 포인트

Skill부터 시작한다

둘 다 강력하지만 진입 비용은 Skill이 훨씬 낮다. Markdown 한 장이면 끝이고, 실패해도 동작에 큰 영향이 없다. "이 작업을 매번 다시 설명하고 있다"고 느끼는 절차가 있다면 그것부터 Skill로 옮긴다.

Subagent는 컨텍스트 무게로 판단

"이 작업을 메인에서 직접 시켰을 때 컨텍스트 윈도우가 부담되는가"를 기준으로 본다. 부담되면 Subagent 후보, 아니면 그냥 메인이 한다. 코드 리뷰·대형 문서 요약·여러 파일의 일관성 검사 같은 게 전형적인 후보다.

트리거 문장을 사용자 발화 기준으로

Skill의 trigger 설명을 쓸 때는 "사용자가 어떤 말을 했을 때 발동해야 하는가"를 1인칭 발화 예시로 적는다. "PR을 만들 때"보다 "사용자가 'PR 올려줘'·'pull request 만들어줘'라고 말할 때"가 훨씬 잘 잡힌다.

Subagent에는 출력 스키마를 강제

"결과를 자유 텍스트로 줘"보다 "다음 형식의 JSON 또는 표로 결과를 돌려줘"가 훨씬 안정적이다. 메인 에이전트가 그 결과를 파싱해서 후속 작업에 쓸 때 차이가 크다.

한계와 더 알아볼 것

  • 강의 자체가 짧다 — Subagent 20분, Skill 30분이라 깊이 있는 사례 연구는 부족하다. 자기 프로젝트에서 직접 만들어 보는 게 강의보다 훨씬 빠르다.
  • 버전·API 변동 — Subagent와 Skill 모두 비교적 새로운 메커니즘이라 명령어·파일 구조가 바뀔 수 있다. 공식 문서를 주기적으로 다시 확인한다.
  • 실전 통합 흐름은 별도 강의 "Claude Code in Action"에서 다룬다. Hooks·MCP·SDK까지 함께 묶어 본다.
