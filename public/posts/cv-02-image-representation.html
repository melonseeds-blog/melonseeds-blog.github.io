디지털 이미지란?

디지털 이미지는 결국 숫자가 채워진 2차원 배열이다. 각 칸이 하나의 픽셀(pixel)이고, 픽셀에 담긴 숫자가 그 위치의 밝기나 색을 나타낸다. 화면에 보이는 사진도 메모리 안에서는 정수 또는 실수의 격자일 뿐이다.

OpenCV에서 이 격자를 담는 그릇이 cv::Mat이다. 행(row) 개수가 rows, 열(column) 개수가 cols다.

좌표계 — 원점은 좌상단

이미지 좌표계는 수학 시간에 배운 것과 다르다. 원점 (0, 0)은 왼쪽 위에 있고, x는 오른쪽(열, column)으로, y는 아래쪽(행, row)으로 증가한다.

이미지 좌표계 — 원점은 좌상단, x는 열 방향, y는 행 방향으로 증가

그래서 픽셀에 접근할 때 인덱스 순서가 헷갈리기 쉽다. at<T>(y, x)는 행 먼저, 열 나중 순서다.

cv::Mat img = cv::imread("sample.png", cv::IMREAD_GRAYSCALE);

int w = img.cols;   // 너비 (열 개수)
int h = img.rows;   // 높이 (행 개수)

// 픽셀 접근 — 인자 순서는 (y, x), 즉 (row, col)
uchar v = img.at<uchar>(10, 20);   // y=10행, x=20열의 밝기값

// cv::Point는 반대로 (x, y) 순서 — 혼동 주의
cv::Point pt(20, 10);              // x=20, y=10
uchar v2 = img.at<uchar>(pt);      // 위와 같은 픽셀
at()은 (행, 열), Point는 (x, y) at<T>(row, col)은 y가 먼저인데 cv::Point(x, y)는 x가 먼저다. 둘을 섞어 쓰면 좌표가 뒤집힌 채로 동작하므로 항상 의식하고 쓴다.

채널 (Channel)

채널은 한 픽셀이 몇 개의 숫자로 표현되는가를 뜻한다. 흑백 사진은 픽셀당 밝기값 하나면 충분하지만, 컬러 사진은 색을 표현하려고 여러 개의 숫자를 쓴다.

채널 수구성픽셀당 데이터용도
1채널Grayscale밝기값 1개측정, 엣지 검출, 이진화
3채널BGRBlue, Green, Red일반 컬러 이미지
4채널BGRABGR + Alpha(투명도)오버레이, PNG 합성

OpenCV는 컬러를 RGB가 아니라 BGR 순서로 저장한다는 점을 반드시 기억한다. 역사적인 이유(초기 윈도우 비트맵 호환)로 굳어진 관례다.

cv::Mat gray = cv::imread("img.png", cv::IMREAD_GRAYSCALE);
cv::Mat color = cv::imread("img.png", cv::IMREAD_COLOR);   // BGR 3채널

std::cout << gray.channels()  << "\n";   // 1
std::cout << color.channels() << "\n";   // 3

// 3채널 픽셀 접근 — Vec3b = uchar 3개 묶음
cv::Vec3b bgr = color.at<cv::Vec3b>(10, 20);
uchar blue  = bgr[0];
uchar green = bgr[1];
uchar red   = bgr[2];

채널 분리와 병합 — split / merge

컬러 이미지를 채널별 단일 채널 이미지로 쪼개거나, 반대로 합칠 수 있다. 특정 채널만 따로 처리해야 할 때 자주 쓴다.

cv::Mat color = cv::imread("img.png", cv::IMREAD_COLOR);

// 분리 — 3개의 1채널 Mat으로
std::vector<cv::Mat> ch;
cv::split(color, ch);
// ch[0] = Blue, ch[1] = Green, ch[2] = Red (각각 1채널)

// Red 채널만 밝게 한 뒤 다시 병합
ch[2] = ch[2] * 1.3;

cv::Mat merged;
cv::merge(ch, merged);   // 다시 3채널 BGR로

// 컬러 → 그레이 변환은 split이 아니라 cvtColor 사용
cv::Mat gray;
cv::cvtColor(color, gray, cv::COLOR_BGR2GRAY);
그레이 변환 = 채널 평균이 아니다 cvtColor(BGR2GRAY)는 단순 평균이 아니라 사람 눈의 민감도를 반영한 가중치(0.299R + 0.587G + 0.114B)로 계산한다. 초록색에 가장 민감하기 때문이다.

비트 깊이 (Bit Depth)

비트 깊이는 한 채널의 값을 몇 비트로 저장하는가이다. 비트가 많을수록 표현할 수 있는 단계(계조)가 많아진다.

OpenCV 깊이C++ 타입비트값 범위주 용도
CV_8Uuchar8비트 부호 없음0 ~ 255일반 이미지, 디스플레이
CV_16Uushort16비트 부호 없음0 ~ 65535산업 카메라 10/12/16비트
CV_16Sshort16비트 부호 있음-32768 ~ 32767미분/엣지 중간 결과
CV_32Ffloat32비트 실수임의 (보통 0.0~1.0)연산 정밀도, 정규화
CV_64Fdouble64비트 실수임의고정밀 행렬 연산

산업 카메라의 10/12비트 데이터

산업용 카메라는 8비트보다 미세한 명암 차이를 잡으려고 10비트(0~1023)나 12비트(0~4095)로 출력하는 경우가 많다. 하지만 메모리는 8비트 단위로 다뤄지므로, 10/12비트 데이터는 보통 16비트 컨테이너(CV_16U)에 담아 처리한다.

// 12비트 카메라 raw 버퍼를 16비트 Mat으로 감쌌다고 가정
cv::Mat raw12(h, w, CV_16U, cameraBuffer);   // 값 범위 0~4095

// 12비트 → 8비트 표시용으로 줄이기 (4095 / 255 ≈ 16.06)
cv::Mat display8;
raw12.convertTo(display8, CV_8U, 255.0 / 4095.0);

// 또는 실제 사용 비트수가 16비트의 어디에 정렬됐는지 확인 필요
// MSB 정렬(상위 비트 정렬)이면 우측 시프트가 필요할 수 있다
double minV, maxV;
cv::minMaxLoc(raw12, &minV, &maxV);
std::cout << "actual range: " << minV << " ~ " << maxV << "\n";
10/12비트는 "16비트 안의 어디에" 들어있는지 확인 카메라마다 12비트 값을 16비트의 하위 비트(LSB 정렬)에 두기도, 상위 비트(MSB 정렬)에 두기도 한다. 정렬 방식을 모르고 스케일링하면 영상이 어둡거나 깨져 보인다. 카메라 SDK의 픽셀 포맷 문서를 먼저 확인한다.

타입 표기 완전 정복

OpenCV의 타입 상수는 CV_8UC3 처럼 생겼다. 처음 보면 암호 같지만 규칙만 알면 한눈에 읽힌다.

CV_<bit><U|S|F>C<channels> — 비트 깊이 + 자료형 + 채널 수
  • U = Unsigned(부호 없는 정수), S = Signed(부호 있는 정수), F = Float(실수)
  • C<n> = 채널 수. C1은 생략 가능 — CV_8U와 CV_8UC1은 같다.
타입 상수읽는 법대표 용도
CV_8UC18비트 부호없음, 1채널그레이스케일 이미지
CV_8UC38비트 부호없음, 3채널BGR 컬러 이미지
CV_8UC48비트 부호없음, 4채널BGRA 이미지
CV_16UC116비트 부호없음, 1채널산업 카메라 12/16비트
CV_32FC132비트 실수, 1채널정규화된 그레이, 거리맵
CV_32FC332비트 실수, 3채널HDR, 정밀 색 연산

type() 반환값 해석

Mat::type()은 정수 하나를 돌려준다. 그 값에서 깊이와 채널을 분리해 읽을 수 있다.

cv::Mat img = cv::imread("img.png", cv::IMREAD_COLOR);

int t = img.type();              // 예: CV_8UC3 == 16
int depth = img.depth();         // CV_8U == 0
int ch = img.channels();         // 3

// 사람이 읽을 수 있는 문자열로 바꾸는 헬퍼
std::string typeToString(int type)
{
    int depth = type & CV_MAT_DEPTH_MASK;   // 하위 비트 = 깊이
    int chans = 1 + (type >> CV_CN_SHIFT);   // 상위 비트 = 채널 수

    const char* d = nullptr;
    switch (depth)
    {
        case CV_8U:  d = "8U";  break;
        case CV_8S:  d = "8S";  break;
        case CV_16U: d = "16U"; break;
        case CV_16S: d = "16S"; break;
        case CV_32S: d = "32S"; break;
        case CV_32F: d = "32F"; break;
        case CV_64F: d = "64F"; break;
        default:     d = "?";   break;
    }
    return "CV_" + std::string(d) + "C" + std::to_string(chans);
}

std::cout << typeToString(img.type()) << "\n";

CV_8UC3

메모리 레이아웃

2차원 이미지지만 메모리는 1차원이다. OpenCV는 픽셀을 행 우선(row-major)으로 저장한다. 즉 첫 행의 모든 픽셀이 먼저 나열되고, 그다음 둘째 행이 이어진다.

인터리브드 vs 플래너

컬러 이미지를 메모리에 늘어놓는 방식은 두 가지다.

  • 인터리브드(interleaved): 한 픽셀의 모든 채널을 모아 둔다 — BGR BGR BGR .... OpenCV의 기본 방식.
  • 플래너(planar): 채널별로 따로 모은다 — BBB... GGG... RRR.... split()한 결과가 이 형태.
인터리브드 BGR 레이아웃 — 행 끝에 정렬용 패딩이 붙으면 step이 실제 픽셀 폭보다 커진다

step / stride 와 패딩

step(또는 stride)은 한 행에서 다음 행으로 건너뛰는 바이트 수다. 직관적으로는 cols × channels × 1바이트일 것 같지만, 메모리 정렬(alignment)을 위해 행 끝에 패딩(padding)이 붙으면 step이 그보다 커진다.

cv::Mat img(480, 641, CV_8UC3);   // 일부러 폭을 641로 (정렬 안 맞게)

std::cout << "cols        : " << img.cols          << "\n";  // 641
std::cout << "channels    : " << img.channels()     << "\n";  // 3
std::cout << "elemSize1   : " << img.elemSize1()    << "\n";  // 1 (채널 1개 바이트)
std::cout << "elemSize    : " << img.elemSize()     << "\n";  // 3 (픽셀 1개 바이트)
std::cout << "실제 픽셀 폭 : " << img.cols * img.elemSize() << "\n";  // 1923
std::cout << "step[0]     : " << img.step[0]        << "\n";  // 1923 또는 그 이상(패딩)
std::cout << "step[1]     : " << img.step[1]        << "\n";  // 3 (한 픽셀)

// y행 x열 픽셀의 메모리 주소 계산 공식
// addr = data + y * step[0] + x * elemSize()
uchar* rowPtr = img.ptr<uchar>(10);          // 10행의 시작 포인터 (권장)
uchar* px = img.data + 10 * img.step[0] + 20 * img.elemSize();  // 수동 계산
행 단위 접근은 항상 ptr()로 img.ptr<T>(y)는 패딩을 자동으로 고려해 y행의 시작 주소를 정확히 돌려준다. 직접 data + y * cols 식으로 계산하면 패딩을 빠뜨려 행이 어긋난다.

연속 메모리 (isContinuous)

모든 행이 패딩 없이 빈틈없이 이어져 있으면 그 Mat은 연속(continuous)이다. imread로 막 읽은 이미지는 보통 연속이다. 하지만 ROI(관심 영역)를 떼어내면 비연속이 된다 — 원본의 일부 행 조각만 가리키므로 행 사이에 원본의 나머지 부분이 끼어 있기 때문이다.

cv::Mat full = cv::imread("img.png", cv::IMREAD_GRAYSCALE);
std::cout << full.isContinuous() << "\n";   // 보통 1 (true)

// ROI 추출 — 데이터는 복사되지 않고 원본을 공유
cv::Mat roi = full(cv::Rect(100, 50, 200, 150));
std::cout << roi.isContinuous() << "\n";    // 0 (false) — 비연속

// ROI를 연속으로 만들려면 명시적으로 복사
cv::Mat roiCopy = roi.clone();
std::cout << roiCopy.isContinuous() << "\n"; // 1 (true)

연속일 때의 빠른 일괄 처리

연속이면 2차원 이미지를 1차원 배열처럼 한 번에 훑을 수 있어 빠르다. reshape로 1행짜리로 바꾸거나, 연속 여부를 보고 루프 범위를 합치는 패턴을 쓴다.

// 모든 픽셀에 +10을 더하는 함수 — 연속/비연속 모두 안전
void addBrightness(cv::Mat& img, int delta)
{
    CV_Assert(img.type() == CV_8UC1);

    int rows = img.rows;
    int cols = img.cols;

    // 연속이면 전체를 한 행으로 펼쳐서 루프 횟수를 줄인다
    if (img.isContinuous())
    {
        cols = rows * cols;
        rows = 1;
    }

    for (int y = 0; y < rows; ++y)
    {
        uchar* p = img.ptr<uchar>(y);   // 행 시작 포인터
        for (int x = 0; x < cols; ++x)
        {
            p[x] = cv::saturate_cast<uchar>(p[x] + delta);
        }
    }
}

// reshape — 연속 Mat을 1행 N열로 (데이터 복사 없음)
cv::Mat flat = img.reshape(1, 1);   // (채널 수, 행 수) → 1채널 1행
reshape는 연속 Mat에서만 안전하다 비연속 Mat에 reshape(1, 1)을 호출하면 예외가 나거나, 패딩까지 포함된 잘못된 데이터를 가리킨다. 비연속이면 먼저 clone()으로 연속화한 뒤 reshape 한다.

픽셀 값의 의미

같은 숫자라도 이미지 타입에 따라 뜻이 다르다.

이미지 종류픽셀 값해석
그레이스케일 8U0완전한 검정
그레이스케일 8U255완전한 흰색
그레이스케일 8U128중간 회색
BGR 8U(255, 0, 0)순수한 파랑 (B=255)
BGR 8U(0, 0, 255)순수한 빨강 (R=255)
정규화 32F0.0 ~ 1.00=검정, 1=흰색 (실수 비율)

딥러닝 입력이나 정밀한 연산에서는 0~255 정수 대신 0.0~1.0 범위의 float로 정규화해 쓰는 경우가 많다. 곱셈·나눗셈에서 자릿수가 잘리지 않고, 여러 연산을 누적해도 정밀도가 유지되기 때문이다.

cv::Mat img8 = cv::imread("img.png", cv::IMREAD_GRAYSCALE);  // 0~255

// 8U → 32F 정규화 (0.0 ~ 1.0)
cv::Mat imgF;
img8.convertTo(imgF, CV_32F, 1.0 / 255.0);

float v = imgF.at<float>(10, 20);   // 예: 0.5019...  (원래 128)

// 다시 표시용 8U로 되돌리기
cv::Mat back8;
imgF.convertTo(back8, CV_8U, 255.0);

데이터 변환

convertTo — 비트 깊이 변환과 스케일링

convertTo(dst, type, alpha, beta)는 각 픽셀에 dst = src × alpha + beta를 적용하면서 타입을 바꾼다. 비트 깊이 변환과 밝기/대비 조정을 한 번에 한다.

cv::Mat src = cv::imread("img.png", cv::IMREAD_GRAYSCALE);

// 1) 단순 타입 변환 (값 그대로)
cv::Mat f32;
src.convertTo(f32, CV_32F);

// 2) 16비트(0~4095) → 8비트(0~255) 스케일 다운
cv::Mat raw16 = cv::imread("12bit.tif", cv::IMREAD_UNCHANGED);  // CV_16U
cv::Mat disp8;
raw16.convertTo(disp8, CV_8U, 255.0 / 4095.0);

// 3) 밝기 +30, 대비 1.2배 (alpha=대비, beta=밝기)
cv::Mat adjusted;
src.convertTo(adjusted, CV_8U, 1.2, 30);
// 결과가 255를 넘으면 자동으로 saturate(포화) 처리됨

normalize — 범위 맞추기

normalize는 픽셀 값을 지정한 범위로 다시 펼쳐준다. 실제 값 범위를 모를 때(필터 결과, 거리맵 등)나, 어두운 이미지를 화면 전체 명암으로 펼칠 때 유용하다.

cv::Mat src = cv::imread("dark.png", cv::IMREAD_GRAYSCALE);

// MIN-MAX 정규화 — 실제 최솟값→0, 최댓값→255 로 펼침 (콘트라스트 스트레칭)
cv::Mat stretched;
cv::normalize(src, stretched, 0, 255, cv::NORM_MINMAX, CV_8U);

// 0.0 ~ 1.0 float 범위로 정규화
cv::Mat norm01;
cv::normalize(src, norm01, 0.0, 1.0, cv::NORM_MINMAX, CV_32F);

// 필터 결과처럼 음수가 섞인 Mat도 안전하게 표시용으로 변환 가능
cv::Mat sobel;
cv::Sobel(src, sobel, CV_32F, 1, 0);          // 음수 포함
cv::Mat sobelDisp;
cv::normalize(sobel, sobelDisp, 0, 255, cv::NORM_MINMAX, CV_8U);
convertTo vs normalize 스케일 비율을 내가 정확히 알 때는 convertTo(예: 4095→255). 실제 데이터의 min/max에 맞춰 펼치고 싶을 때는 normalize(NORM_MINMAX). 둘은 목적이 다르다.

흔한 함정

1. 채널 순서는 RGB가 아니라 BGR

OpenCV로 읽은 컬러 이미지는 BGR 순서다. 이를 RGB로 가정하고 다른 라이브러리(matplotlib, Qt, 딥러닝 프레임워크 등)에 넘기면 빨강과 파랑이 뒤바뀐다.

cv::Mat bgr = cv::imread("img.png", cv::IMREAD_COLOR);   // BGR

// 빨간색 픽셀을 만들고 싶다면 — R은 인덱스 2
bgr.at<cv::Vec3b>(0, 0) = cv::Vec3b(0, 0, 255);   // (B,G,R) = 빨강

// RGB를 기대하는 외부 라이브러리에 넘기기 전 변환
cv::Mat rgb;
cv::cvtColor(bgr, rgb, cv::COLOR_BGR2RGB);
BGR ↔ RGB 혼동 영상이 "푸르딩딩"하거나 "불그스름"하게 나오면 십중팔구 채널 순서 문제다. OpenCV 내부에서만 다룰 때는 BGR 그대로 두고, 외부와 주고받을 때만 cvtColor로 변환한다.

2. 8비트 오버플로우 — saturate_cast

uchar는 0~255만 담는다. 200 + 100 = 300은 8비트에 들어가지 않아 래핑(wrap-around)되어 44가 된다. 밝게 만들려다 오히려 어두워지는 버그가 여기서 나온다.

uchar a = 200, b = 100;

// 잘못된 코드 — 오버플로우
uchar wrong = a + b;                       // 300 → 44 (래핑!)

// 올바른 코드 — saturate_cast로 255에서 잘림(포화)
uchar safe = cv::saturate_cast<uchar>(a + b);   // 255

// OpenCV 내장 연산자는 자동으로 saturate 처리한다
cv::Mat img = cv::imread("img.png", cv::IMREAD_GRAYSCALE);
cv::Mat bright = img + 100;                 // 안전 — 자동 포화
// 직접 포인터로 픽셀을 순회할 때만 saturate_cast가 필요

3. step과 cols 혼동

cols는 "픽셀 개수", step[0]은 "한 행의 바이트 수"다. 패딩이 있거나 다채널이면 둘은 다르다. 포인터 산술에 cols를 쓰면 행이 어긋난다.

cv::Mat img(100, 100, CV_8UC3);

// 틀린 가정: 다음 행 = data + cols
// 실제로는 cols(100) ≠ step[0](300 또는 그 이상)

uchar* row5_wrong = img.data + 5 * img.cols;       // 어긋남
uchar* row5_right = img.data + 5 * img.step[0];    // 정확
uchar* row5_best  = img.ptr<uchar>(5);             // 가장 안전

4. 비연속 Mat에서 data 포인터 직접 순회

ROI 같은 비연속 Mat을 img.data부터 rows*cols 만큼 일직선으로 순회하면, 행 사이의 패딩(원본의 다른 부분)까지 건드리게 된다.

cv::Mat full = cv::imread("img.png", cv::IMREAD_GRAYSCALE);
cv::Mat roi = full(cv::Rect(10, 10, 50, 50));   // 비연속

// 위험한 코드 — 비연속인데 일직선 순회
uchar* p = roi.data;
for (int i = 0; i < roi.rows * roi.cols; ++i)
    p[i] = 0;            // 행을 넘어가면 원본의 엉뚱한 픽셀을 침범!

// 안전한 코드 — 행 단위로 ptr() 사용
for (int y = 0; y < roi.rows; ++y)
{
    uchar* row = roi.ptr<uchar>(y);
    for (int x = 0; x < roi.cols; ++x)
        row[x] = 0;
}

// 또는 처음부터 연속화
cv::Mat safeRoi = roi.clone();   // 연속 보장
"한 줄 순회"는 isContinuous()를 먼저 확인 data 포인터로 전체를 한 번에 도는 최적화는 isContinuous()가 true일 때만 유효하다. 비연속이면 반드시 행 단위 ptr() 순회로 바꾸거나 clone()한다.
