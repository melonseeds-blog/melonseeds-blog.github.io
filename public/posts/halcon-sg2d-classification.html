분류(Classification)란

분류는 객체(pixel 또는 region)를 미리 정의된 여러 class 중 하나에 할당하는 작업이다. HALCON에서 객체는 보통 region이나 pixel이며, 각 객체는 color, texture, shape, size 같은 feature로 기술된다.

분류가 적합한 상황은 객체가 비슷하지만 정확한 규칙으로 정의하기 어려운 경우다. 모양이 고정되어 있다면 template matching이 더 빠르고 쉽지만, 객체들의 유사성을 명시적 규칙으로 표현하기 어렵다면 분류기에게 sample을 보여주고 class 경계를 학습시키는 편이 효율적이다.

HALCON 분류의 주요 응용
  • image segmentation — color/texture가 유사한 region으로 영상을 분할
  • object recognition — 여러 객체 타입 중 특정 타입을 식별
  • quality control — 양품/불량 판정
  • novelty detection — 학습된 class에 속하지 않는 이상 객체 탐지
  • OCR — 문자 region을 글자 class로 분류

1.1 Feature Vector와 Feature Space

각 객체에서 추출한 feature 값들을 모은 배열을 feature vector라 하고, 이 vector가 차지하는 공간을 feature space라 한다. 같은 class에 속한 객체들은 feature space에서 cluster를 형성하며, 분류기의 목표는 cluster 사이를 가르는 경계(line, plane, hypersurface)를 찾는 것이다.

예를 들어 오렌지와 레몬을 구분할 때 area와 circularity 두 feature만으로도 두 class는 2D feature space 위에서 충분히 분리된다. 분리 경계가 직선이면 linear classifier, 곡면이면 non-linear classifier라 한다.

분류 워크플로우

HALCON 분류는 크게 두 그룹으로 나뉜다. MLP/SVM/GMM/k-NN은 사용자가 feature를 명시적으로 정의해야 하고, Deep Learning은 라벨링된 이미지만 주면 network가 feature를 자동으로 학습한다.

전통 분류기와 딥러닝 분류기의 워크플로우 차이

HALCON 분류기 5종

3.1 MLP — Multi-Layer Perceptron

단일 hidden layer를 가진 신경망으로 비선형 분류 경계를 직접 만든다. Hidden unit에서는 hyperbolic tangent, 출력층에서는 softmax 활성화 함수를 사용해 class별 확률로 변환한다. HALCON의 MLP는 hidden layer가 하나뿐이라 엄밀히는 deep learning이 아니다.

  • 적합: 빠른 분류 속도가 필요한 응용, 라인 적용용
  • 약점: training이 느리고, 전체 데이터가 한 번에 있어야 함
  • novelty detection 지원 안 함

3.2 SVM — Support Vector Machine

feature space를 kernel(예: Gaussian RBF, polynomial)로 고차원에 mapping해 linear separator를 찾는다. 두 class 간 margin을 최대화하는 hyperplane을 선택하며, hyperplane에 가장 가까운 sample이 support vector다. 다중 class는 one-vs-one 또는 one-vs-rest로 확장된다.

  • 적합: 약간 더 높은 정확도가 필요한 경우
  • 약점: 분류 속도가 MLP보다 느리고, sample이 많아지면 메모리가 큼
  • reduce_class_svm으로 support vector 수를 줄일 수 있음

3.3 GMM — Gaussian Mixture Model

Bayes decision rule 기반으로 각 class의 확률 밀도를 여러 Gaussian 분포의 선형 결합으로 모델링한다. class 중심 주위에 covariance ellipsoid를 그리고, sample의 a posteriori probability가 가장 큰 class로 할당한다.

  • 적합: 학습/분류 모두 빠르고, class 수가 적을 때
  • novelty detection에 가장 적합 — 어느 class에도 속하지 않는 sample을 reject 가능
  • 약점: feature 차원이 약 15를 넘으면 신뢰성 저하 (curse of dimensionality)
  • OCR에는 부적합 (HALCON이 미제공)

3.4 k-NN — K-Nearest Neighbors

training data를 그대로 저장한 뒤, 새 sample에 대해 가장 가까운 k개의 이웃 class를 majority vote(또는 distance-weighted vote)로 결정한다. 학습은 사실상 데이터 저장에 불과해 매우 빠르다.

  • 적합: feature/training set 구성을 빠르게 실험할 때, 추가 데이터를 점진적으로 넣을 때
  • 약점: 분류 속도가 MLP보다 느리고, training data 전부를 보관하므로 메모리 사용량이 큼
  • feature 차원 제한 없음

3.5 Deep Learning — CNN 기반

Convolutional / Pooling / ReLU / Fully Connected layer로 구성된 CNN을 사용한다. HALCON은 처음부터 network를 만들지 못하게 하고, 대신 pretrained network에 출력층만 교체해 hidden layer를 재학습하는 transfer learning만 허용한다.

  • 적합: 매우 높은 정확도가 필요하거나, feature 정의가 어려운 경우
  • 약점: 라벨 이미지 다량 필요, 학습 시간 길고 GPU 거의 필수
  • OCR의 경우 pretrained font Universal만 사용 가능 (자체 학습 불가)
Euclidean / Hyperbox 단순한 분류기로 image segmentation에 한정해 제공된다. 저차원 feature에서만 안정적이며 일반 분류·OCR에서는 거의 쓰지 않는다.

특징(Feature) 선택

딥러닝을 제외한 모든 HALCON 분류기는 사용자가 feature를 선택해야 한다. 어떤 feature가 좋은지에 대한 고정 규칙은 없고, 객체 특성에 따라 다르게 결정해야 한다.

5.1 작업별 feature

작업 사용 가능한 feature
general classification region feature, color, texture, shape, size 등 자유롭게 조합
image segmentation multi-channel color/texture 이미지의 pixel 값 (자동 추출)
OCR 제한된 region feature 집합 (operator가 내부적으로 계산)

5.2 HALCON이 돕는 도구

  • texture_laws + compose6 — multi-channel texture 이미지 생성
  • cooc_feature_image — energy, correlation, homogeneity, contrast 등 텍스처 feature
  • HDevelop의 calculate_features procedure — 회전 불변 등 속성을 묶어 계산
  • select_feature_set_mlp/svm/gmm/knn — 자동 feature 선택 operator
feature가 많을수록 좋은 것은 아니다 무관한 feature를 늘리면 noise가 추가되고 GMM은 차원 저주에 빠진다. 자동 selection을 출발점으로 삼고, class 간 분리도가 높은 feature만 남기는 편이 안전하다.

학습 데이터(Training Samples) 관리

분류 결과가 만족스럽지 않다면 그 원인은 보통 알고리즘이 아니라 데이터다. sample은 다음 두 가지를 모두 보여줘야 한다.

  • 객체의 핵심 특징(class 사이의 차이)
  • 같은 class 내부에서 허용되는 변동 범위 — 조명, 노이즈, 크기, 회전, 제품 편차 등

6.1 데이터가 부족할 때의 trick

인공 sample 증강

몇 안 되는 sample을 복사해 약간씩 변형한다. texture라면 noise를 추가하고, 크기/회전이 영향이면 erosion·dilation 또는 작은 회전을 가해 허용 변동 방향마다 여러 변형본을 만든다.

두 단계 분류로 분할

class 불균형이 심하면 우선 모든 결함 class를 하나의 "불량" class로 합쳐 양품/불량 2-class 문제로 학습한다. 이후 불량으로 reject된 sample만 대상으로 결함 종류를 분류하는 두 번째 모델을 학습한다.

6.2 라벨링 원칙

  • 라벨 일관성 — 같은 객체는 같은 사람이 같은 기준으로
  • 경계 sample 확보 — class 사이 애매한 경우도 일부 포함
  • train / validation / test set 분리
  • 현장 조명·광학 편차를 sample에 반영

평가 — Confusion Matrix와 클래스 불균형

HALCON은 evaluate_class_mlp / gmm 등으로 sample이 어느 class에 얼마의 confidence로 할당되었는지 반환한다. 이 결과를 confusion matrix로 정리하면 단순 정확도(accuracy) 너머의 정보가 보인다.

지표 의미 주의점
Accuracy 전체 sample 중 맞춘 비율 class 불균형 시 함정 — 다수 class 정답률에 가려짐
Precision "불량" 판정 중 진짜 불량의 비율 false reject 비용이 크면 핵심 지표
Recall 실제 불량 중 잡아낸 비율 유출(escape) 비용이 크면 핵심 지표
Confusion Matrix class별 오인 패턴 특정 class 쌍이 자주 헷갈리면 feature·sample 보강
Confidence 분류기가 자신 있다고 판단하는 정도 낮으면 reject 또는 재검사로 분기 가능
class 불균형은 평가까지 왜곡한다 양품 99% 불량 1% 라인에서 모든 sample을 양품이라 답해도 accuracy 99%다. 항상 confusion matrix와 class별 precision/recall을 함께 본다.

딥러닝 분류기로의 전환

전통 분류기로 한계가 보일 때, 또는 다음 조건에 해당하면 deep learning을 검토할 만하다.

  • 사람 눈으로는 구분되지만 명시적 rule/feature로 표현하기 어려운 경우
  • 결함 형태가 다양해 region feature로 일반화가 어려운 경우
  • texture·외관 검사처럼 high-level 추상이 필요한 경우

8.1 Transfer Learning이 표준 진입점

HALCON은 처음부터 network를 짜는 것을 허용하지 않는다. 대신 ImageNet급 데이터로 미리 학습된 backbone에 사용자 class용 출력층을 붙여 hidden layer를 재학습한다. 이 방식은 데이터·연산·시간 요구를 크게 줄여준다.

8.2 출력 해석

딥러닝 분류기는 단일 class를 반환하는 대신 class별 confidence(예: apple: 0.97, lemon: 0.03)를 돌려준다. 임계값을 두어 신뢰도가 낮은 sample은 재검사 또는 manual review로 보내는 것이 실무 패턴이다.

흔한 함정

데이터 부족 sample이 적으면 어떤 분류기도 일반화하지 못한다. 특히 DL은 class당 수백~수천 장이 출발점이다. 양 부족 → 증강 또는 전통 분류기로 회귀.
과적합(Overfitting) train set만 잘 맞추고 현장에서 무너지는 경우. 별도의 validation/test set으로 항상 검증하고, DL에서는 pooling·dropout·data augmentation으로 완화한다.
라벨 오류 잘못 라벨된 sample 몇 개가 class 경계를 흐트러뜨린다. confusion matrix에서 특정 쌍이 반복적으로 헷갈리면 sample 라벨 자체를 의심한다.
feature 선택 실패 class 간 분리도가 낮은 feature 조합으로는 어떤 분류기도 좋은 결과를 내지 못한다. feature space 시각화(2D/3D)와 자동 선택 operator를 적극 활용한다.
훈련 후 데이터 분포 변화(Drift) 제품 lot 변경, 조명 노화, 카메라 교체로 feature 분포가 이동하면 정확도가 서서히 떨어진다. 주기적 재검증 + 추가 학습 절차를 운영 단계에 포함한다.

핵심 정리

HALCON 분류 설계 핵심
  • 분류는 "feature 정의 + sample 수집 + 학습 + 검증 + 적용"의 반복이다.
  • HALCON 주요 분류기 5종(MLP/SVM/GMM/k-NN/DL) 중 라인 속도는 MLP, 정확도는 SVM, novelty는 GMM, 실험은 k-NN, feature 정의 어려움은 DL.
  • 알고리즘보다 feature·sample 품질이 결과의 대부분을 결정한다.
  • accuracy 하나가 아니라 confusion matrix·precision·recall을 함께 봐야 한다.
  • DL 분류기는 transfer learning이 표준 진입점이며, confidence 기반 reject 흐름과 결합한다.
  • 운영 단계 drift를 가정해 재검증·재학습 절차를 설계에 포함한다.
