트레이트(Trait) — Rust의 다형성

2026-06-25 약 8분 분량 Rust 시리즈
이 편에서 배우는 것 트레이트는 Rust가 다형성을 표현하는 핵심 도구다. 이 글에서는 trait를 정의하고 타입에 impl로 구현하는 법, 구현 없이도 쓰는 기본 메서드, 그리고 같은 추상을 두 가지 방식으로 푸는 정적 디스패치(impl Trait·제네릭)와 동적 디스패치(dyn Trait)를 다룬다. C++의 추상 인터페이스·concept과 어떻게 같고 다른지도 짚는다. 모든 예제는 컴파일되는 안전한 코드만 쓴다.

트레이트란 무엇인가

트레이트는 "어떤 타입이 제공해야 하는 동작의 집합"을 정의한다. C++로 치면 순수 가상 함수만 모은 추상 인터페이스에 가깝지만, 클래스 상속 계층에 묶이지 않는다. 트레이트는 나중에, 외부에서 기존 타입에 구현을 붙일 수 있다.

먼저 트레이트를 선언하고, 두 개의 서로 다른 타입에 각각 구현해 본다.

// 동작 집합을 트레이트로 정의한다.
trait Area {
    fn area(&self) -> f64;
}

struct Circle {
    radius: f64,
}

struct Rectangle {
    width: f64,
    height: f64,
}

// 각 타입에 트레이트를 구현한다.
impl Area for Circle {
    fn area(&self) -> f64 {
        std::f64::consts::PI * self.radius * self.radius
    }
}

impl Area for Rectangle {
    fn area(&self) -> f64 {
        self.width * self.height
    }
}

fn main() {
    let c = Circle { radius: 2.0 };
    let r = Rectangle { width: 3.0, height: 4.0 };
    println!("{:.2}", c.area()); // 12.57
    println!("{:.2}", r.area()); // 12.00
}

&self는 메서드가 값을 빌려서(빌림) 읽기만 한다는 뜻이다. 소유권을 가져가지 않으므로 호출 뒤에도 c와 r은 그대로 쓸 수 있다.

고아 규칙(orphan rule) 트레이트를 구현하려면 트레이트나 대상 타입 중 하나는 내 크레이트 소유여야 한다. 둘 다 외부 것이면 구현할 수 없다. 덕분에 같은 타입에 대한 충돌 구현이 라이브러리 간에 생기지 않는다. C++에는 이런 강제 규칙이 없다.

기본 메서드

트레이트 메서드에 본문을 직접 적어 두면 그것이 기본 구현이 된다. 구현 타입이 따로 재정의하지 않으면 기본 구현을 그대로 쓴다. 기본 메서드는 같은 트레이트의 다른(추상) 메서드를 호출할 수도 있다.

trait Greet {
    // 구현체가 반드시 채워야 하는 메서드.
    fn name(&self) -> String;

    // 기본 구현 — name()을 활용한다.
    fn hello(&self) -> String {
        format!("Hello, {}!", self.name())
    }
}

struct Dog;
struct Robot;

impl Greet for Dog {
    fn name(&self) -> String {
        String::from("Dog")
    }
    // hello()는 기본 구현을 그대로 사용한다.
}

impl Greet for Robot {
    fn name(&self) -> String {
        String::from("Robot")
    }
    // 기본 동작을 재정의한다.
    fn hello(&self) -> String {
        format!("BEEP. I am {}.", self.name())
    }
}

fn main() {
    println!("{}", Dog.hello());   // Hello, Dog!
    println!("{}", Robot.hello()); // BEEP. I am Robot.
}

이 패턴은 표준 라이브러리 전반에서 쓰인다. 예를 들어 Iterator 트레이트는 next 하나만 구현하면 map·filter·collect 같은 수십 개 메서드를 기본 구현으로 공짜로 얻는다.

정적 디스패치 — 제네릭과 impl Trait

"이 트레이트를 구현한 어떤 타입이든 받는다"를 표현하는 첫 번째 방법은 정적 디스패치다. 컴파일러가 호출 지점마다 구체 타입을 알고 있으므로, 타입별로 함수를 따로 찍어 낸다(단형화, monomorphization). 런타임 분기 비용이 없고 인라인도 잘 된다.

제네릭의 트레이트 경계(T: Area)와, 그 축약형인 impl Trait는 같은 정적 디스패치를 만든다.

// 앞서 정의한 Area 트레이트를 그대로 쓴다.

// 제네릭 + 트레이트 경계 — 가장 일반적인 형태.
fn print_area<T: Area>(shape: &T) {
    println!("area = {:.2}", shape.area());
}

// impl Trait — 위와 동등한 축약 표기.
fn print_area_impl(shape: &impl Area) {
    println!("area = {:.2}", shape.area());
}

// 반환 위치의 impl Trait — 구체 타입을 숨기고 반환한다.
fn make_circle(radius: f64) -> impl Area {
    Circle { radius }
}

fn main() {
    let c = make_circle(1.5);
    print_area(&c);
    print_area_impl(&c);
}

핵심 한 가지를 짚는다. 단형화는 호출되는 구체 타입의 수만큼 코드가 복제된다는 뜻이다. 타입이 많으면 바이너리가 커질 수 있다. 그 대신 실행은 빠르다. 이 트레이드오프가 다음 절의 동적 디스패치를 고르는 기준이 된다.

동적 디스패치 — 트레이트 객체 dyn

두 번째 방법은 트레이트 객체 dyn Trait다. 서로 다른 구체 타입을 하나의 컬렉션에 섞어 담거나, 호출할 타입을 컴파일 시점에 고정하고 싶지 않을 때 쓴다. 트레이트 객체는 크기가 컴파일 시점에 정해지지 않으므로 항상 포인터 뒤에 둔다 — &dyn Area 또는 Box<dyn Area>.

// 서로 다른 타입을 한 Vec에 담는다.
fn total_area(shapes: &[Box<dyn Area>]) -> f64 {
    let mut sum = 0.0;
    for shape in shapes {
        sum += shape.area(); // vtable을 통해 런타임에 디스패치
    }
    sum
}

fn main() {
    // Circle과 Rectangle을 같은 벡터에 섞어 담는다.
    let shapes: Vec<Box<dyn Area>> = vec![
        Box::new(Circle { radius: 1.0 }),
        Box::new(Rectangle { width: 2.0, height: 3.0 }),
    ];
    println!("total = {:.2}", total_area(&shapes));
}

각 Box<dyn Area>는 "데이터 포인터 + vtable 포인터"의 한 쌍(fat pointer)이다. shape.area()를 부르면 vtable을 거쳐 올바른 구현으로 점프한다. 정적 디스패치와 달리 코드는 한 벌만 존재하지만, 호출마다 간접 분기가 생기고 인라인이 어렵다.

구분정적 디스패치동적 디스패치
표기T: Trait · impl Trait&dyn Trait · Box<dyn Trait>

한 컬렉션에 여러 타입불가(타입 하나로 고정)가능

고를 때 한 줄 기준 타입이 컴파일 시점에 하나로 정해지면 정적 디스패치(impl Trait·제네릭)가 기본값이다. 서로 다른 타입을 한 자료구조에 섞어야 하거나 플러그인처럼 타입을 미리 알 수 없을 때만 dyn으로 간다. 의심스러우면 정적으로 시작하고, 필요해질 때 dyn으로 바꾼다.

C++과 이렇게 다르다

C++ 경험자에게 트레이트는 익숙하면서도 미묘하게 다르다. 가장 또렷한 대응은 다음과 같다.

관점C++Rust 트레이트
추상 인터페이스순수 가상 함수를 가진 추상 클래스 + 상속trait + impl (상속 계층 불필요)
제네릭 제약concept (C++20)트레이트 경계 T: Trait
정적 다형성템플릿(단형화)제네릭 · impl Trait(단형화)
동적 다형성가상 함수 + vtable(객체 내부 포인터)dyn Trait + vtable(fat pointer)
기존 타입 확장외부 타입에 멤버 추가 불가외부 타입에 트레이트 구현 가능(고아 규칙 내)

요약하면 트레이트는 C++의 추상 인터페이스와 concept을 하나로 합친 도구다. 같은 트레이트가 제네릭의 제약(concept 역할)도 되고, 동적 다형성의 인터페이스(추상 클래스 역할)도 된다.

vtable이 어디 있느냐가 다르다 C++의 가상 함수는 vtable 포인터를 객체 안에 박아 둔다 — 가상 함수가 있는 클래스의 모든 인스턴스는 그 포인터만큼 커진다. Rust는 다르다. Circle 값 자체에는 vtable 포인터가 없고, &dyn Area로 만드는 그 순간에만 "데이터 포인터 + vtable 포인터" 쌍(fat pointer)이 생긴다. 그래서 같은 타입을 비용 없이 정적으로 쓰다가 필요할 때만 dyn으로 전환할 수 있다. C++에서는 가상 여부가 클래스 정의에 고정된다.
