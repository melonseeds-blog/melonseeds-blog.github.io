픽셀 접근이 왜 중요한가

OpenCV의 내장 함수만으로 처리되는 작업은 픽셀을 직접 만질 일이 없다. 하지만 실무에서는 그렇지 않은 경우가 많다.

  • 커스텀 알고리즘 — 내장 함수로 표현되지 않는 처리(특수한 결함 검출 규칙, 좌표 기반 보정 등)는 픽셀을 직접 다뤄야 한다.
  • 디버깅 — 특정 좌표의 픽셀 값이 기대와 다를 때, 그 값을 찍어 보는 것이 가장 빠른 확인 방법이다.
  • 성능 — 픽셀 루프는 잘못 짜면 수십 배 느려진다. 접근 방식의 차이를 알아야 병목을 피한다.

cv::Mat은 같은 픽셀에 접근하는 방법을 여러 개 제공한다. 안전하지만 느린 것부터, 빠르지만 위험한 것까지 단계가 있다. 이 글은 그 단계를 하나씩 짚고, 마지막으로 부분 영역만 다루는 ROI를 다룬다.

전제: 좌표 순서는 (행, 열) = (y, x) cv::Mat의 픽셀 접근은 항상 (y, x) 순서다. cv::Point가 (x, y)인 것과 반대라서 자주 헷갈린다. 이 글의 모든 예제는 (y, x) 순서를 따른다.

at<T>() — 안전한 접근

at<T>(y, x)는 가장 직관적인 픽셀 접근 방법이다. 디버그 빌드에서는 범위 체크를 하므로 잘못된 좌표에 접근하면 바로 잡힌다. 대신 매 호출마다 검사가 들어가서 느리다.

#include <opencv2/opencv.hpp>

cv::Mat gray = cv::imread("input.png", cv::IMREAD_GRAYSCALE);

// 단일 채널(Mono8) — uchar
uchar v = gray.at<uchar>(10, 20);   // (y=10, x=20)의 밝기
gray.at<uchar>(10, 20) = 255;       // 흰색으로 변경

// 3채널 컬러(BGR) — cv::Vec3b
cv::Mat color = cv::imread("input.png", cv::IMREAD_COLOR);
cv::Vec3b px = color.at<cv::Vec3b>(10, 20);
uchar b = px[0];   // Blue
uchar g = px[1];   // Green
uchar r = px[2];   // Red

color.at<cv::Vec3b>(10, 20) = cv::Vec3b(0, 0, 255);  // 빨강으로

전체 픽셀을 순회할 때도 쓸 수 있지만, 이중 루프 안에서 at을 호출하면 매번 행 시작 위치를 다시 계산한다.

// at()으로 전체 순회 — 동작은 하지만 느리다
for (int y = 0; y < gray.rows; ++y)
{
    for (int x = 0; x < gray.cols; ++x)
    {
        uchar v = gray.at<uchar>(y, x);
        gray.at<uchar>(y, x) = cv::saturate_cast<uchar>(v + 30);  // 밝기 +30
    }
}
at<T>()의 타입은 반드시 정확히 맞춰야 한다 cv::Vec3b 이미지에 at<uchar>()로 접근하면 컴파일은 되지만 엉뚱한 메모리를 읽는다. 채널 수와 깊이에 맞는 타입(Mono8 → uchar, BGR8 → cv::Vec3b, float 1채널 → float)을 써야 한다. 릴리즈 빌드에서는 범위 체크도 빠지므로 잘못된 타입은 조용히 깨진 결과를 만든다.

ptr<T>() — 행 포인터 순회

ptr<T>(y)는 y행의 시작 주소를 포인터로 반환한다. 한 행 안에서는 포인터를 인덱싱해 픽셀에 접근하므로, 행마다 한 번만 주소를 계산하면 된다. 가장 흔하게 쓰는 고성능 순회 패턴이다.

// 단일 채널 — 행 포인터로 순회
for (int y = 0; y < gray.rows; ++y)
{
    uchar* row = gray.ptr<uchar>(y);   // y행 시작 주소
    for (int x = 0; x < gray.cols; ++x)
    {
        row[x] = cv::saturate_cast<uchar>(row[x] + 30);
    }
}

// 3채널 — Vec3b 포인터
for (int y = 0; y < color.rows; ++y)
{
    cv::Vec3b* row = color.ptr<cv::Vec3b>(y);
    for (int x = 0; x < color.cols; ++x)
    {
        row[x][2] = 255;   // R 채널만 최대로
    }
}

읽기 전용이라면 const 포인터를 받는다. 의도를 명확히 하고 컴파일러 최적화에도 도움이 된다.

// 읽기 전용 순회 — 평균 밝기 계산
double sum = 0.0;
for (int y = 0; y < gray.rows; ++y)
{
    const uchar* row = gray.ptr<uchar>(y);
    for (int x = 0; x < gray.cols; ++x)
    {
        sum += row[x];
    }
}
double mean = sum / (gray.rows * gray.cols);
대부분의 픽셀 루프는 ptr<T>()로 충분하다 at보다 빠르면서 data 포인터 직접 접근만큼 위험하지 않다. 행 단위로 끊어 처리하므로 비연속 Mat(ROI 등)에서도 안전하다. 성능이 필요한데 어떤 방법을 쓸지 고민된다면 ptr이 기본값이다.

data 포인터 직접 접근

Mat::data는 픽셀 버퍼의 맨 앞 주소(uchar*)다. 행 사이의 간격은 Mat::step으로 직접 계산해야 한다. 가장 빠르지만, 인덱스 계산을 손으로 하므로 실수가 곧 메모리 손상으로 이어진다.

// data 포인터 + step으로 직접 인덱싱
uchar* base = gray.data;
size_t step = gray.step;   // 한 행의 바이트 수 (패딩 포함)

for (int y = 0; y < gray.rows; ++y)
{
    uchar* row = base + y * step;
    for (int x = 0; x < gray.cols; ++x)
    {
        row[x] = cv::saturate_cast<uchar>(row[x] + 30);
    }
}

메모리가 연속(continuous)이라면 2차원 이미지를 1차원 배열처럼 한 번에 훑을 수 있다. 행 경계를 무시하고 전체를 한 루프로 처리하므로 가장 빠르다. 단, 연속일 때만 안전하다.

// 연속 메모리일 때만 — 전체를 1차원으로 순회
if (gray.isContinuous())
{
    uchar* p = gray.data;
    size_t total = gray.total();   // rows * cols
    for (size_t i = 0; i < total; ++i)
    {
        p[i] = cv::saturate_cast<uchar>(p[i] + 30);
    }
}
else
{
    // 비연속 — 행 단위 ptr 순회로 폴백
    for (int y = 0; y < gray.rows; ++y)
    {
        uchar* row = gray.ptr<uchar>(y);
        for (int x = 0; x < gray.cols; ++x)
            row[x] = cv::saturate_cast<uchar>(row[x] + 30);
    }
}
ROI는 보통 비연속이다 원본에서 잘라낸 ROI는 행 끝에 원본의 나머지 픽셀이 패딩처럼 남아 있어 isContinuous()가 false다. isContinuous() 확인 없이 data를 1차원으로 훑으면 ROI 바깥 픽셀까지 건드린다. data 직접 접근은 항상 연속성 검사를 동반해야 한다.

forEach / LUT / 벡터화 연산

픽셀 루프를 직접 짜기 전에, 같은 일을 하는 OpenCV 내장 연산이 있는지 먼저 확인한다. 내장 연산은 SIMD와 멀티스레드로 최적화돼 있어 손으로 짠 루프보다 훨씬 빠르다.

내장 연산 — 루프 자체를 없앤다

// "밝기 +30"은 루프 없이 한 줄
gray += 30;                       // 또는 cv::add(gray, 30, gray);

// 스케일 + 오프셋 (대비/밝기 조정)
gray.convertTo(gray, -1, 1.2, 10);   // dst = 1.2 * src + 10

// 임계화, 정규화 등도 모두 내장
cv::threshold(gray, gray, 128, 255, cv::THRESH_BINARY);

LUT — 값 매핑 테이블

"입력 픽셀 값 → 출력 픽셀 값"이 고정된 변환이라면 cv::LUT가 가장 빠르다. 256칸짜리 룩업 테이블을 미리 만들어 두면 픽셀마다 계산 대신 테이블 참조만 한다. 감마 보정이 대표적인 예다.

// 감마 보정 LUT 만들기
cv::Mat lut(1, 256, CV_8U);
uchar* p = lut.ptr<uchar>();
double gamma = 0.5;
for (int i = 0; i < 256; ++i)
{
    p[i] = cv::saturate_cast<uchar>(std::pow(i / 255.0, gamma) * 255.0);
}

cv::Mat result;
cv::LUT(gray, lut, result);   // 전체 픽셀에 테이블 적용

forEach — 병렬 픽셀 루프

내장 연산으로 표현이 안 되는 커스텀 처리라면 Mat::forEach를 쓴다. 람다를 받아 픽셀을 여러 스레드로 나눠 처리하므로, 같은 로직의 직접 루프보다 빠르다.

// forEach — 픽셀별 커스텀 처리를 병렬로
gray.forEach<uchar>([](uchar& pixel, const int* pos) -> void
{
    // pos[0] = y, pos[1] = x
    pixel = cv::saturate_cast<uchar>(pixel + 30);
});

// 3채널도 동일
color.forEach<cv::Vec3b>([](cv::Vec3b& px, const int*) -> void
{
    std::swap(px[0], px[2]);   // B와 R 교환
});
우선순위: 내장 연산 > LUT > forEach > ptr 루프 같은 결과를 낼 수 있다면 위쪽을 먼저 고른다. 직접 루프는 "내장으로 표현이 안 될 때"의 마지막 선택지다. 픽셀 루프를 짜기 전에 항상 한 번 더 생각해 본다.

픽셀 접근 방법 비교

방법속도안전성특징언제 쓰나
at<T>(y,x) 느림 높음 (디버그 범위 체크) 호출마다 주소 재계산 몇 개 픽셀만 읽기/쓰기, 디버깅
ptr<T>(y) 빠름 중간 (행 단위 안전) 행마다 한 번 주소 계산 대부분의 픽셀 루프 (기본값)
data + step 가장 빠름 낮음 (수동 계산) 연속일 때 1차원 순회 가능 연속 메모리 확인 후 최고 성능 필요 시
forEach<T> 매우 빠름 (병렬) 높음 멀티스레드 자동 분할 커스텀 픽셀 처리를 빠르게
LUT / 내장 연산 매우 빠름 높음 루프 자체가 없음 표현 가능하면 항상 우선
"느림/빠름"은 상대적이다 at도 픽셀 몇 개를 읽는 정도라면 전혀 문제 없다. 차이가 드러나는 건 수백만 픽셀을 매 프레임 순회할 때다. 산업용 라인스캔 카메라처럼 해상도가 크면 접근 방식 하나로 처리 시간이 프레임 예산을 넘기기도 한다.

ROI — Region of Interest

이미지 전체가 아니라 일부 영역만 처리하고 싶을 때 ROI(관심 영역)를 쓴다. cv::Rect로 사각형 영역을 지정하고, 그 Rect로 Mat을 인덱싱하면 부분 영역을 가리키는 새 Mat이 나온다.

cv::Mat image = cv::imread("board.png");

// cv::Rect(x, y, width, height)
cv::Rect roiRect(100, 50, 200, 150);   // (100,50)에서 200x150 영역

cv::Mat roi = image(roiRect);          // ROI Mat — 데이터는 원본과 공유
// 또는 동일: cv::Mat roi = image(cv::Range(50, 200), cv::Range(100, 300));

여기서 핵심은 image(roiRect)가 픽셀 데이터를 복사하지 않는다는 점이다. ROI Mat은 헤더만 새로 만들고(크기·시작 위치·step 정보), 실제 픽셀 버퍼는 원본과 같은 메모리를 가리킨다. 이른바 얕은 복사다.

원본 Mat과 ROI Mat은 서로 다른 헤더를 갖지만 같은 픽셀 데이터 버퍼를 가리킨다. ROI 헤더는 그 버퍼의 일부 사각형만 보도록 좌표·크기·step이 설정될 뿐이다.

그래서 ROI Mat을 수정하면 그 변경이 원본에 그대로 반영된다.

cv::Mat image = cv::imread("board.png");
cv::Rect roiRect(100, 50, 200, 150);

cv::Mat roi = image(roiRect);
roi.setTo(cv::Scalar(0, 0, 255));   // ROI를 빨강으로 채움

// image의 (100,50)~(300,200) 영역도 빨강으로 바뀐다 — 같은 메모리이므로
ROI는 독립 사본이 아니다 image(roiRect)로 얻은 Mat을 "원본과 별개인 잘라낸 이미지"로 착각하면 안 된다. ROI에 한 처리는 원본을 건드린다. 원본을 보존한 채 부분 영역만 따로 다루려면 다음처럼 명시적으로 복사한다.
// 원본과 완전히 분리된 독립 사본이 필요하면 .clone()
cv::Mat roiCopy = image(roiRect).clone();
roiCopy.setTo(cv::Scalar(0, 0, 255));   // image는 그대로, roiCopy만 변경

물론 "원본에 반영된다"는 성질이 유용할 때도 많다. 큰 이미지의 한 영역에만 필터를 적용하고 싶을 때 ROI에 처리하면 그 자리에 바로 결과가 쓰인다.

// 특정 영역에만 블러 적용 — 결과가 원본 image에 바로 반영됨
cv::Mat region = image(cv::Rect(100, 50, 200, 150));
cv::GaussianBlur(region, region, cv::Size(7, 7), 0);

cv::Rect 연산

cv::Rect는 단순한 좌표 묶음이 아니라 집합 연산을 지원한다. 두 영역의 겹침을 구하거나, ROI가 이미지 경계를 넘지 않도록 잘라낼 때 유용하다.

cv::Rect a(50, 50, 100, 100);    // (50,50)~(150,150)
cv::Rect b(100, 100, 100, 100);  // (100,100)~(200,200)

// 교집합 (&) — 두 사각형이 겹치는 영역
cv::Rect inter = a & b;          // (100,100, 50,50)
if (inter.area() == 0)
{
    // 겹치지 않음
}

// 합집합 (|) — 두 사각형을 모두 포함하는 최소 사각형
cv::Rect uni = a | b;            // (50,50, 150,150)

// 이동, 크기 조정
cv::Rect moved = a + cv::Point(10, 10);   // 위치 이동
cv::Rect sized = a + cv::Size(20, 20);    // 크기 확대

실무에서 가장 많이 쓰는 패턴은 이미지 경계 클리핑이다. 사용자가 지정한 ROI나 계산으로 나온 ROI가 이미지 밖으로 삐져나갈 수 있는데, 이미지 전체를 나타내는 Rect와 교집합을 구하면 안전한 범위로 잘린다.

// 경계를 넘을 수 있는 ROI를 안전하게 클리핑
cv::Rect requested(-20, -10, 300, 300);   // 음수 좌표 — 위험
cv::Rect bounds(0, 0, image.cols, image.rows);

cv::Rect safe = requested & bounds;       // 이미지 안으로 클리핑됨
if (safe.area() > 0)
{
    cv::Mat roi = image(safe);            // 이제 예외 없이 안전
}
ROI를 만들기 전에 항상 클리핑한다 외부에서 들어온 좌표(사용자 입력, 검출 결과, 설정 파일)로 ROI를 만들 때는 rect & cv::Rect(0,0,cols,rows)를 습관처럼 거친다. 한 줄로 경계 초과 예외를 막을 수 있다.

clone() vs copyTo()

ROI나 다른 Mat을 실제로 복사할 때 쓰는 두 함수다. 둘 다 픽셀 데이터를 깊은 복사하지만 쓰임이 다르다.

// clone() — 새 Mat을 만들어 반환. 메모리도 새로 할당
cv::Mat dst1 = src.clone();

// copyTo() — 이미 있는 Mat에 내용을 쓴다. 필요하면 크기를 자동 재할당
cv::Mat dst2;
src.copyTo(dst2);

// copyTo()는 마스크를 받을 수 있다 — clone()은 불가능
cv::Mat mask;   // 8비트 1채널, 0이 아닌 픽셀만 복사 대상
src.copyTo(dst3, mask);

루프 안에서는 copyTo()가 유리하다 매 프레임 clone()을 호출하면 매번 메모리를 새로 할당한다. copyTo()는 대상 Mat의 크기·타입이 맞으면 기존 버퍼를 재사용하므로 할당 비용이 없다. 반복 처리에서는 대상 Mat을 한 번 만들어 두고 copyTo()로 채운다.

마스크를 이용한 선택적 복사

copyTo(dst, mask)는 마스크에서 0이 아닌 픽셀 위치만 복사한다. 검출된 영역만 합성하거나, 특정 색 범위만 다른 이미지에 옮길 때 쓴다.

cv::Mat src = cv::imread("foreground.png");
cv::Mat dst = cv::imread("background.png");   // src와 같은 크기

// 마스크 만들기 — 밝은 영역만 1로
cv::Mat gray, mask;
cv::cvtColor(src, gray, cv::COLOR_BGR2GRAY);
cv::threshold(gray, mask, 100, 255, cv::THRESH_BINARY);

// mask가 0이 아닌 픽셀만 src에서 dst로 복사
src.copyTo(dst, mask);   // dst의 해당 위치만 src 픽셀로 덮임

ROI와 마스크를 함께 쓰면 "이미지의 특정 사각 영역 안에서, 마스크에 걸린 픽셀만" 복사하는 것도 가능하다.

// ROI + 마스크 조합
cv::Rect r(100, 50, 200, 150);
cv::Mat srcRoi = src(r);
cv::Mat dstRoi = dst(r);          // 둘 다 원본과 데이터 공유
cv::Mat maskRoi = mask(r);

srcRoi.copyTo(dstRoi, maskRoi);   // dst의 r 영역 중 마스크 픽셀만 갱신

흔한 함정

at<T>() 타입 불일치

BGR 이미지에 at<uchar>()로 접근하면 한 픽셀의 첫 바이트(Blue)만 읽는다. 컴파일러는 막지 못한다. 채널 수와 깊이에 정확히 맞는 타입을 써야 한다.

cv::Mat color = cv::imread("input.png", cv::IMREAD_COLOR);  // 3채널

uchar wrong = color.at<uchar>(10, 20);          // 잘못됨 — B 바이트만
cv::Vec3b right = color.at<cv::Vec3b>(10, 20);  // 올바름 — BGR 한 픽셀

ROI 경계 초과

이미지 밖으로 나가는 cv::Rect로 image(rect)를 호출하면 cv::Exception이 발생한다. 앞서 본 경계 클리핑(rect & bounds)을 거치면 막을 수 있다.

음수 좌표·과대 크기 Rect는 즉시 예외 cv::Rect(-10, 0, 100, 100)이나 이미지보다 큰 width는 ROI 생성 시점에 바로 던진다. 외부 입력으로 만든 Rect는 반드시 image 크기와 교집합을 취한 뒤 사용한다.

ROI를 독립 사본으로 착각

가장 흔한 실수다. ROI에 한 처리가 원본을 망가뜨리는 줄 모르고 디버깅에 시간을 쏟는다. 원본을 지켜야 하면 .clone()으로 끊는다.

// 흔한 실수 — 원본이 같이 바뀐다
cv::Mat roi = image(rect);
cv::GaussianBlur(roi, roi, cv::Size(15, 15), 0);   // image도 흐려짐!

// 의도가 "원본 보존"이면 clone으로 분리
cv::Mat roi = image(rect).clone();
cv::GaussianBlur(roi, roi, cv::Size(15, 15), 0);   // image는 그대로

비연속 Mat을 일괄 순회

ROI나 한 행 건너 만든 Mat은 비연속이다. isContinuous() 확인 없이 data를 rows * cols만큼 1차원으로 훑으면 의도한 영역 밖을 건드린다.

cv::Mat roi = image(cv::Rect(100, 50, 200, 150));

// 위험 — roi는 비연속인데 1차원으로 훑음
uchar* p = roi.data;
for (size_t i = 0; i < roi.total(); ++i)
    p[i] = 0;            // ROI 바깥 픽셀까지 0으로!

// 안전 — 행 단위 ptr 순회는 비연속이어도 정확
for (int y = 0; y < roi.rows; ++y)
{
    uchar* row = roi.ptr<uchar>(y);
    for (int x = 0; x < roi.cols; ++x)
        row[x] = 0;
}
정리 픽셀 접근은 ptr<T>()를 기본으로 하고, 표현 가능하면 내장 연산·LUT·forEach를 먼저 쓴다. ROI는 헤더만 새로 만들고 데이터는 원본과 공유한다는 점을 항상 기억하고, 원본 보존이 필요하면 .clone(), 경계 안전이 필요하면 rect & bounds를 거친다.
