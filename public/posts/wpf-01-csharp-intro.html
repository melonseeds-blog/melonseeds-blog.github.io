C#이란?

C#은 Microsoft가 2000년 발표한 .NET 기반 멀티 패러다임 언어다. 객체지향을 중심에 두면서 제네릭, 함수형(LINQ, 람다), 비동기(async/await) 기능을 두루 지원한다. 소스는 IL(Intermediate Language)로 컴파일된 뒤 런타임이 JIT(Just-In-Time)로 네이티브 코드로 변환한다. 메모리는 GC(가비지 컬렉터)가 관리한다.

Hello World

.NET 6부터는 최상위 문(top-level statements)을 지원한다. Main 메서드 없이 바로 코드를 적을 수 있다.

// Program.cs — .NET 6+ 최상위 문 스타일
Console.WriteLine("Hello, World!");

// 인자 사용
foreach (var arg in args)
{
    Console.WriteLine($"arg: {arg}");
}

전통적인 Main 메서드 방식은 다음과 같다. 내부 동작은 동일하다.

using System;

namespace HelloApp
{
    public class Program
    {
        public static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}

switch expression (C# 8+)

전통적인 switch 문 외에, 값을 반환하는 switch expression이 추가됐다. 패턴 매칭과 결합하면 매우 간결하다.

string day = "Mon";

// 전통 switch
switch (day)
{
    case "Mon":
        Console.WriteLine("월요일");
        break;
    case "Tue":
        Console.WriteLine("화요일");
        break;
    default:
        Console.WriteLine("기타");
        break;
}

// switch expression
string label = day switch
{
    "Mon" => "월요일",
    "Tue" => "화요일",
    "Wed" or "Thu" => "주중",
    _ => "기타"                  // default
};

// 타입 패턴
object obj = 42;
string desc = obj switch
{
    int n when n > 0 => $"양수 {n}",
    int n => $"정수 {n}",
    string s => $"문자열 {s}",
    null => "null",
    _ => "기타"
};

타입 시스템 맛보기

C# 타입은 크게 값 타입(value type)과 참조 타입(reference type)으로 나뉜다. 자세한 내용은 2편에서 다룬다. 여기서는 핵심만 짚는다.

분류예시저장 위치대입 시
값 타입int, double, bool, struct, enum스택(또는 인라인)복사
참조 타입class, string, 배열, interface, delegate힙참조 복사
// var — 타입 추론. 우변이 명확할 때만 가능
var i = 10;            // int
var s = "hello";       // string
var list = new List<int>();

// nullable 값 타입
int? maybe = null;
maybe = 5;
if (maybe.HasValue) Console.WriteLine(maybe.Value);

// nullable reference types (C# 8+) — 프로젝트에서 활성화 시
string? nullableName = null;     // 명시적으로 null 허용
string requiredName = "Foo";     // null 허용 안 함 (경고로 보호)
nullable reference types .csproj에 <Nullable>enable</Nullable>을 넣으면 활성화된다. string?은 null 가능, string은 null 금지로 컴파일러가 경고를 띄운다. NullReferenceException 예방에 강력하다.

클래스 기본

public class Person
{
    // 필드
    private readonly string _id;

    // 자동 구현 속성 (auto-property)
    public string Name { get; set; }
    public int Age { get; private set; }            // 외부에선 읽기만
    public string Country { get; init; } = "KR";    // 생성 시에만 할당 (C# 9+)

    // 생성자
    public Person(string id, string name, int age)
    {
        _id = id;
        Name = name;
        Age = age;
    }

    // 메서드
    public void Greet()
    {
        Console.WriteLine($"안녕하세요, {Name}입니다.");
    }

    // 표현식 본문(expression-bodied) 메서드
    public bool IsAdult() => Age >= 18;
}

// 사용
var p = new Person("u001", "Melon", 30);
p.Greet();
p.Name = "Seed";       // OK
// p.Age = 31;         // 컴파일 에러: private set
자동 구현 속성(auto-property) get; set;만 적으면 컴파일러가 백킹 필드를 자동 생성한다. C++/Java처럼 getter/setter를 직접 쓰지 않는다.

StringBuilder — 반복 연결

using System.Text;

// 나쁜 예 — 매 반복마다 새 string 객체 생성 (O(n^2))
string bad = "";
for (int i = 0; i < 10000; i++) bad += i.ToString();

// 좋은 예 — StringBuilder는 가변 버퍼
var sb = new StringBuilder();
for (int i = 0; i < 10000; i++) sb.Append(i);
string result = sb.ToString();
string은 불변(immutable)이다 +=로 반복 연결하면 매번 새 객체가 만들어진다. 큰 루프에서는 반드시 StringBuilder를 쓴다.

컬렉션

C#의 표준 컬렉션은 System.Collections.Generic 네임스페이스에 있다. C++ STL과 1:1 대응이 자연스럽다.

using System.Collections.Generic;

// List<T> — C++의 std::vector
var list = new List<int> { 1, 2, 3 };
list.Add(4);
list.Insert(0, 0);
list.Remove(2);            // 값으로 첫 항목 제거
list.RemoveAt(0);          // 인덱스
int first = list[0];
int count = list.Count;
bool has = list.Contains(3);

foreach (var x in list) Console.WriteLine(x);

// Dictionary<TKey, TValue> — std::unordered_map
var dict = new Dictionary<string, int>
{
    ["apple"] = 3,
    ["banana"] = 5
};
dict["cherry"] = 7;

if (dict.TryGetValue("apple", out int v))
{
    Console.WriteLine($"apple = {v}");
}

foreach (var (key, val) in dict)
{
    Console.WriteLine($"{key}: {val}");
}

// HashSet<T> — std::unordered_set
var set = new HashSet<int> { 1, 2, 3 };
set.Add(3);                // 무시 (이미 존재)
bool exists = set.Contains(2);

// Queue<T>, Stack<T>도 같은 네임스페이스에 있다

IEnumerable — 모든 컬렉션의 공통 인터페이스

List, Dictionary, 배열 모두 IEnumerable<T>를 구현한다. foreach와 LINQ는 이 인터페이스 위에서 동작한다.

using System.Linq;

IEnumerable<int> nums = new List<int> { 1, 2, 3, 4, 5 };

var evens = nums.Where(n => n % 2 == 0);   // 2, 4
var sum = nums.Sum();                       // 15
var max = nums.Max();                       // 5
var doubled = nums.Select(n => n * 2).ToList();

try
{
    int n = int.Parse("not a number");
}
catch (FormatException ex)
{
    Console.WriteLine($"형식 오류: {ex.Message}");

{
    // exception filter (C# 6+)

finally
{
    // 성공/실패 무관 항상 실행

}

// 예외 던지기
void Validate(int age)
{
    if (age < 0)
        throw new ArgumentOutOfRangeException(nameof(age), "음수는 허용 안 됨");
}

// using — IDisposable 자원의 자동 해제 (C#의 RAII 대응)
using (var stream = File.OpenRead("a.txt"))
{
    // 사용
}   // 블록 종료 시 자동 Dispose

C++ 개발자가 알아두면 좋은 점

C++을 익힌 사람이 C#으로 넘어올 때 마주치는 차이를 정리한다. 자세한 내용은 시리즈 다음 편들에서 다룬다.

  • GC가 있다 — delete 없고 소멸자가 결정적으로 호출되지 않는다. 자원은 IDisposable + using으로 해제한다.
  • 참조 의미가 기본 — class는 자동으로 참조 타입이다. 값 의미가 필요하면 struct를 쓴다.
  • 다중 상속이 없다 — 클래스는 단일 상속, 다중 상속은 interface로만 가능하다.
  • 속성(Property)이 언어 기능 — obj.Name = "x"처럼 보이지만 실제로는 setter 호출이다.
  • 델리게이트(delegate)와 이벤트 — 함수 포인터 + 멤버 함수 묶음. 람다와 결합해 콜백 시스템을 만든다.
  • 제네릭은 런타임 보존 — C++ 템플릿과 다르게 IL에 정보가 남는다. typeof(T)가 동작한다.
  • async/await — 비동기 코드를 동기 코드처럼 작성 가능하다. (별도 편에서)

흔한 함정

string 반복 연결의 O(n²) 함정 루프 안에서 s += token을 반복하면 매 반복마다 새 string이 생성된다. 1만 번 돌면 5천만 회의 복사가 일어난다. 반드시 StringBuilder를 쓴다.
struct vs class 혼동 struct는 값 타입이라 대입/인자 전달 시 복사된다. list[0].X = 10은 컴파일 에러거나 사본을 수정하는 셈이라 원본이 안 바뀐다. 가변 struct는 피하고, 큰 객체나 다형성이 필요하면 class를 쓴다.
NullReferenceException 참조 타입의 기본값은 null이다. 점 접근 전에 null을 확인하거나 ?. (null-conditional) / ?? (null-coalescing) 연산자를 활용한다. <Nullable>enable</Nullable>로 컴파일러 경고를 켜 두는 게 좋다.
GC 인지 부족 매 프레임 수천 개의 임시 객체를 만들면 Gen0 GC가 자주 일어나 프레임 드랍을 유발한다. 이미지 처리 같은 핫패스에서는 struct, ArrayPool<T>, Span<T>를 활용해 할당을 줄인다.
== 연산자가 타입마다 다름 string은 값 비교, 일반 class는 참조 비교가 기본이다. 의미가 헷갈리면 Equals나 EqualityComparer<T>.Default.Equals를 명시적으로 쓴다.
