결과 표시의 숨은 왕복

GPU로 영상을 처리한 뒤 화면에 보여 주는 가장 흔한 방법은, 결과를 CPU 메모리로 복사하고 그것을 화면 라이브러리(Qt, WPF, OpenCV imshow)에 넘기는 것이다. 그런데 화면 라이브러리는 그 영상을 그리기 위해 다시 GPU로 올린다. 결국 영상이 GPU → CPU → GPU로 PCIe를 두 번 오간다.

그래픽스 연동을 쓰면 결과 버퍼를 화면용 텍스처로 바로 쓰거나 GPU 안에서만 복사한다

2,000만 화소 컬러 영상(약 80 MB, RGBA)을 초당 30장 보여 주면 왕복 이동량이 초당 약 4.8 GB다. PCIe 대역폭을 크게 차지해 카메라 영상을 GPU로 올리는 일(4편)과 부딪친다. CUDA는 OpenGL, Direct3D, Vulkan과 메모리를 공유하는 그래픽스 연동(graphics interop) 기능을 제공한다.

연동의 기본 흐름

API는 그래픽스 종류마다 이름이 조금씩 다르지만 흐름은 같다. 그래픽스 쪽에서 만든 버퍼나 텍스처를 CUDA에 등록해 두고, 프레임마다 CUDA가 쓸 때만 잠깐 빌렸다가 돌려준다.

단계함수시점
1. 등록cudaGraphicsGLRegisterBuffer, cudaGraphicsGLRegisterImage, cudaGraphicsD3D11RegisterResource시작할 때 한 번 (크기가 바뀌면 다시)
2. 빌리기 (map)cudaGraphicsMapResources매 프레임, CUDA가 쓰기 전
3. 주소 얻기버퍼: cudaGraphicsResourceGetMappedPointer
텍스처: cudaGraphicsSubResourceGetMappedArray		매 프레임
4. CUDA 커널로 쓰기보통 커널, 또는 surface 쓰기(20편), cudaMemcpy2DToArrayAsync매 프레임
5. 돌려주기 (unmap)cudaGraphicsUnmapResources매 프레임, 그래픽스가 그리기 전
6. 해제cudaGraphicsUnregisterResource끝날 때

map과 unmap 사이에는 CUDA만, 그 밖에서는 그래픽스 API만 그 메모리를 쓴다. map, unmap이 두 쪽의 순서를 맞춰 주는 동기화 역할을 한다.

OpenGL - 픽셀 버퍼로 연동

가장 많이 쓰는 방법은 OpenGL 픽셀 버퍼 객체(PBO)를 CUDA에 등록하는 것이다. CUDA 커널이 PBO에 RGBA 픽셀을 쓰고, OpenGL은 PBO에서 텍스처로 GPU 안에서만 복사해 화면에 그린다.

// ---- once, with the GL context current on this thread ----
GLuint pbo, tex;
glGenBuffers(1, &pbo);
glBindBuffer(GL_PIXEL_UNPACK_BUFFER, pbo);
glBufferData(GL_PIXEL_UNPACK_BUFFER, w * h * 4, nullptr, GL_STREAM_DRAW);
glBindBuffer(GL_PIXEL_UNPACK_BUFFER, 0);

glGenTextures(1, &tex);
glBindTexture(GL_TEXTURE_2D, tex);
glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA8, w, h, 0, GL_RGBA, GL_UNSIGNED_BYTE, nullptr);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);

cudaGraphicsResource_t pboRes;
cudaGraphicsGLRegisterBuffer(&pboRes, pbo, cudaGraphicsRegisterFlagsWriteDiscard);  // CUDA only writes

// ---- every frame ----
cudaGraphicsMapResources(1, &pboRes, stream);
uchar4* d_rgba = nullptr; size_t size = 0;
cudaGraphicsResourceGetMappedPointer((void**)&d_rgba, &size, pboRes);

GrayToRgba<<<grid, block, 0, stream>>>(d_result, d_rgba, w, h);   // write display pixels
DrawOverlay<<<grid2, block2, 0, stream>>>(d_rgba, d_defects, numDefects, w, h);

cudaGraphicsUnmapResources(1, &pboRes, stream);   // hand the buffer back to OpenGL

// PBO -> texture copy stays on the GPU, then draw a full-screen quad
glBindBuffer(GL_PIXEL_UNPACK_BUFFER, pbo);
glBindTexture(GL_TEXTURE_2D, tex);
glTexSubImage2D(GL_TEXTURE_2D, 0, 0, 0, w, h, GL_RGBA, GL_UNSIGNED_BYTE, nullptr);  // offset 0 in PBO
glBindBuffer(GL_PIXEL_UNPACK_BUFFER, 0);
DrawTexturedQuad(tex);
등록 플래그뜻
cudaGraphicsRegisterFlagsNoneCUDA가 읽고 쓰기
cudaGraphicsRegisterFlagsReadOnlyCUDA는 읽기만 (그래픽스가 만든 영상을 CUDA로 분석)
cudaGraphicsRegisterFlagsWriteDiscardCUDA가 매번 전체를 새로 씀. 이전 내용을 보존할 필요가 없어 가장 빠름

텍스처를 직접 등록하는 방법

PBO 없이 텍스처를 바로 등록할 수도 있다. 이 경우 CUDA 쪽에서는 일반 포인터가 아니라 cudaArray로 보이므로, surface 쓰기(20편)나 배열 복사로 채운다.

cudaGraphicsResource_t texRes;
cudaGraphicsGLRegisterImage(&texRes, tex, GL_TEXTURE_2D, cudaGraphicsRegisterFlagsSurfaceLoadStore);

// every frame
cudaGraphicsMapResources(1, &texRes, stream);
cudaArray_t arr;
cudaGraphicsSubResourceGetMappedArray(&arr, texRes, 0, 0);   // array index 0, mip level 0
cudaMemcpy2DToArrayAsync(arr, 0, 0, d_rgba, pitch, w * 4, h, cudaMemcpyDeviceToDevice, stream);
cudaGraphicsUnmapResources(1, &texRes, stream);

Direct3D와 Vulkan

그래픽스 APICUDA 연동 방법참고
Direct3D 11cudaGraphicsD3D11RegisterResource + 위와 같은 map/unmapWindows 화면 프로그램에서 흔히 사용
Direct3D 12외부 메모리 API: cudaImportExternalMemory, cudaImportExternalSemaphore공유 핸들(shared handle)로 메모리와 펜스를 넘김
Vulkan같은 외부 메모리 API메모리는 Win32 핸들(Windows) 또는 파일 디스크립터(리눅스)로 넘김

D3D12와 Vulkan은 map/unmap 대신 외부 메모리와 외부 세마포어로 연동한다. 그래픽스 쪽에서 메모리를 "공유 가능"으로 만들어 핸들을 얻고, CUDA가 그 핸들로 같은 메모리를 가져온다. 동기화도 map/unmap이 아니라 세마포어(펜스)를 CUDA 스트림에서 신호하고 기다리는 방식이다. 코드는 길지만, 한 번 설정하면 프레임마다 하는 일은 세마포어 대기, 커널 실행, 세마포어 신호뿐이다.

// outline: import a D3D12/Vulkan buffer and a fence into CUDA (handles come from the graphics side)
cudaExternalMemoryHandleDesc memDesc = {};
memDesc.type = cudaExternalMemoryHandleTypeD3D12Resource;   // or ...OpaqueWin32 for Vulkan
memDesc.handle.win32.handle = sharedHandle;
memDesc.size = bytes;
memDesc.flags = cudaExternalMemoryDedicated;
cudaExternalMemory_t extMem;
cudaImportExternalMemory(&extMem, &memDesc);

cudaExternalMemoryBufferDesc bufDesc = {};
bufDesc.size = bytes;
void* d_shared = nullptr;
cudaExternalMemoryGetMappedBuffer(&d_shared, extMem, &bufDesc);   // a normal device pointer now

// per frame: wait graphics fence -> CUDA work -> signal fence for graphics
cudaWaitExternalSemaphoresAsync(&extSem, &waitParams, 1, stream);
Render<<<grid, block, 0, stream>>>((uchar4*)d_shared, w, h);
cudaSignalExternalSemaphoresAsync(&extSem, &signalParams, 1, stream);

화면 프레임워크와 연결

검사 장비 프로그램은 대부분 Qt나 WPF 같은 화면 프레임워크 위에서 돈다. 프레임워크가 내부에서 쓰는 그래픽스 API에 맞춰 연결한다.

프레임워크연결 지점메모
QtQOpenGLWidget(또는 QOpenGLWindow)의 initializeGL에서 등록, paintGL에서 map → 커널 → unmap → 그리기GL 컨텍스트가 현재인 스레드에서 호출해야 함. Qt 6의 기본 렌더링은 Direct3D일 수 있으니 OpenGL 위젯을 명시적으로 사용
WPFD3DImage로 Direct3D 표면을 표시. 표면을 공유 텍스처로 만들어 CUDA(D3D11 연동)로 채움설정이 복잡함. C++/CLI(이 시리즈의 C++ 편)로 CUDA 코드와 이어 붙이는 구조가 흔함
OpenCVcv::ogl::Texture2D, cv::cuda::GpuMat과 OpenGL 연동 모듈OpenCV를 OpenGL 지원으로 빌드해야 함
화면 해상도만큼만 보내기 5000만 화소 영상을 1920×1080 창에 보여 준다면, 연동을 쓰더라도 원본 크기를 화면으로 넘길 필요가 없다. CUDA에서 화면 크기로 줄인 표시용 영상(20편의 texture 리사이즈)을 만들어 그것만 연동 버퍼에 쓰면 메모리와 시간이 크게 준다. 연동을 쓸 수 없는 환경에서도 이 방법만으로 CPU 왕복량이 수십 분의 일로 준다.

같은 GPU 조건

연동은 CUDA 커널을 돌리는 GPU와 화면을 그리는 GPU가 같을 때 의미가 있다. 다르면 드라이버가 내부에서 복사를 하게 되어, 연동을 써도 PCIe 왕복이 생긴다.

환경주의
노트북 (내장 그래픽 + 외장 GPU)창이 내장 그래픽에서 그려질 수 있음. 그래픽 설정에서 프로그램을 고성능 GPU로 지정
멀티 GPU (24편)모니터가 연결된 GPU에서 표시용 처리를 함. 다른 GPU의 결과는 표시용으로 줄인 영상만 P2P나 CPU 경유로 넘김
계산 전용 GPU (TCC 모드, 데이터센터 GPU)화면 출력이 없어 그래픽스 연동 불가. 결과를 CPU로 가져와 표시
// pick the CUDA device that drives the current OpenGL context
unsigned int count = 0;
int glDevices[4];
cudaGLGetDevices(&count, glDevices, 4, cudaGLDeviceListAll);
if (count > 0)
    cudaSetDevice(glDevices[0]);       // do the display work on the same GPU

흔한 함정

매 프레임 등록, 해제 cudaGraphicsGLRegisterBuffer는 무거운 호출이다. 매 프레임 등록하면 연동을 쓰지 않는 것보다 느려질 수 있다. 등록은 시작할 때와 창 크기가 바뀔 때만 하고, 프레임마다는 map/unmap만 한다.
GL 컨텍스트가 없는 스레드에서 호출 OpenGL 연동 함수는 해당 GL 컨텍스트가 "현재"인 스레드에서 불러야 한다. CUDA 처리 스레드와 화면 스레드가 다르면, 처리 스레드는 결과를 일반 CUDA 버퍼에 쓰고, 화면 스레드가 map → GPU 안 복사(cudaMemcpyAsync device to device) → unmap을 하는 구조가 안전하다.
unmap 전에 그리기 map된 상태의 버퍼를 OpenGL이 쓰면 결과가 정의되지 않는다. 그리기 전에 반드시 unmap한다. 반대로 unmap 뒤에 CUDA가 그 포인터를 쓰는 것도 금지다. map할 때마다 포인터를 새로 받는다.
RGBA 4바이트 정렬 표시용 버퍼는 픽셀당 4바이트(RGBA)로 잡는 것이 좋다. RGB 3바이트는 행 정렬과 메모리 결합(7편)이 어긋나기 쉽고, OpenGL 기본 행 정렬(GL_UNPACK_ALIGNMENT = 4)과 맞지 않아 영상이 비스듬히 밀려 보이는 문제가 생긴다.

정리

요점내용
푸는 문제결과 표시를 위한 GPU → CPU → GPU 왕복
흐름등록(한 번) → map → 주소 얻기 → 커널로 쓰기 → unmap → 그리기
APIOpenGL, D3D11은 register + map/unmap. D3D12, Vulkan은 외부 메모리와 세마포어
조건CUDA GPU와 화면 GPU가 같아야 효과가 있음
함께 쓸 것표시용으로 줄인 영상만 연동 버퍼에 쓰기

22~25편으로 성능 분석(Roofline과 커널 융합), 수치 정밀도, 멀티 GPU, 화면 연동까지 다뤘다. 영상 처리 프로그램을 GPU로 옮길 때 처리 속도뿐 아니라 결과의 정확도, 장비 구성, 화면 표시까지 함께 설계할 수 있게 된다.
