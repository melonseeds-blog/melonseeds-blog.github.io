히스토그램이란?

히스토그램은 이미지 안에서 각 밝기 값이 몇 번 나타나는지를 센 분포 그래프다. 가로축은 픽셀 밝기 값(8비트 이미지면 0~255), 세로축은 그 값을 가진 픽셀의 개수다. 이미지를 한 장 한 장 눈으로 보지 않아도 히스토그램만 보면 밝기·대비·노출 상태를 한눈에 파악할 수 있다.

예를 들어 히스토그램이 왼쪽(0 근처)에 몰려 있으면 어두운 이미지, 오른쪽(255 근처)에 몰려 있으면 밝은 이미지다. 좁은 범위에 봉우리가 솟아 있으면 대비가 낮고, 0~255 전 구간에 고르게 퍼져 있으면 대비가 풍부하다. 산업 검사에서 조명이 바뀌었는지, 카메라 노출이 흔들렸는지를 픽셀 단위로 따지지 않고 히스토그램 형태 하나로 감지할 수 있다.

히스토그램은 공간 정보를 버린다 히스토그램은 "어떤 밝기가 몇 개"만 셀 뿐, "어디에 있는지"는 기록하지 않는다. 그래서 완전히 다른 두 이미지가 같은 히스토그램을 가질 수도 있다. 위치가 중요하면 히스토그램만으로는 부족하다 — 다른 특징과 함께 써야 한다.

calcHist — 히스토그램 계산과 시각화

OpenCV에서 히스토그램은 cv::calcHist로 계산한다. 인자가 많아 보이지만 핵심은 세 가지다 — 어떤 채널을, 몇 개의 bin으로, 어떤 범위에서 셀 것인가.

인자의미예시
채널 인덱스몇 번 채널의 값을 셀지그레이스케일은 {0}, BGR의 G는 {1}
bin 수 (histSize)밝기 구간을 몇 칸으로 나눌지256이면 값마다 한 칸, 64면 4개씩 묶음
범위 (ranges)셀 값의 최소~최대8비트는 {0, 256}
마스크특정 영역만 셀 때 사용비우면 전체 이미지

그레이스케일 히스토그램 계산

가장 단순한 형태다. 1채널 이미지의 0~255 분포를 256개 bin으로 센다.

#include <opencv2/opencv.hpp>
#include <iostream>

int main()
{
    cv::Mat gray = cv::imread("sample.jpg", cv::IMREAD_GRAYSCALE);
    if (gray.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    int channels[] = { 0 };          // 0번 채널
    int histSize[] = { 256 };        // bin 256개
    float range[] = { 0, 256 };      // 값 범위 0~255
    const float* ranges[] = { range };

    cv::Mat hist;                    // 결과는 CV_32F, 256x1 행렬
    cv::calcHist(&gray, 1, channels, cv::Mat(),
                 hist, 1, histSize, ranges);

    // 가장 픽셀이 많은 밝기 값 찾기
    double maxVal; int maxIdx[2];
    cv::minMaxIdx(hist, nullptr, &maxVal, nullptr, maxIdx);
    std::cout << "최빈 밝기 = " << maxIdx[0]
              << " (" << static_cast<int>(maxVal) << " 픽셀)" << std::endl;
    return 0;
}
실행 결과 (콘솔)
최빈 밝기 = 47 (28310 픽셀)

calcHist의 결과 hist는 CV_32F 타입의 256×1 행렬이다. hist.at<float>(i)로 i번 밝기의 픽셀 수를 읽는다. 위 결과는 밝기 47이 가장 많다는 뜻 — 이미지가 어두운 쪽으로 치우쳐 있음을 짐작할 수 있다.

히스토그램 직접 그리기

OpenCV에는 히스토그램을 그려주는 함수가 없다. hist 행렬을 받아 막대 그래프 이미지를 직접 만든다. 핵심은 정규화로 막대 높이를 캔버스 안에 맞추는 것이다.

// hist: calcHist 결과 (256x1, CV_32F)
cv::Mat drawHistogram(const cv::Mat& hist)
{
    const int kHistW = 512;   // 캔버스 너비
    const int kHistH = 400;   // 캔버스 높이
    const int binW = kHistW / 256;

    cv::Mat canvas(kHistH, kHistW, CV_8UC3, cv::Scalar(20, 20, 20));

    // 막대 높이를 캔버스 높이에 맞게 정규화
    cv::Mat normHist;
    cv::normalize(hist, normHist, 0, kHistH, cv::NORM_MINMAX);

    for (int i = 1; i < 256; i++)
    {
        int y1 = kHistH - static_cast<int>(normHist.at<float>(i - 1));
        int y2 = kHistH - static_cast<int>(normHist.at<float>(i));
        cv::line(canvas,
                 cv::Point(binW * (i - 1), y1),
                 cv::Point(binW * i, y2),
                 cv::Scalar(120, 220, 120), 2);
    }
    return canvas;
}

컬러 이미지 — 채널별 히스토그램

컬러 이미지는 B, G, R 채널을 따로 분리해 각각 히스토그램을 구한다. 세 곡선을 한 캔버스에 겹쳐 그리면 색 균형을 볼 수 있다.

cv::Mat color = cv::imread("sample.jpg", cv::IMREAD_COLOR);

std::vector<cv::Mat> bgr;
cv::split(color, bgr);   // B, G, R 채널로 분리

int histSize[] = { 256 };
float range[] = { 0, 256 };
const float* ranges[] = { range };
int channels[] = { 0 };

cv::Mat histB, histG, histR;
cv::calcHist(&bgr[0], 1, channels, cv::Mat(), histB, 1, histSize, ranges);
cv::calcHist(&bgr[1], 1, channels, cv::Mat(), histG, 1, histSize, ranges);
cv::calcHist(&bgr[2], 1, channels, cv::Mat(), histR, 1, histSize, ranges);
// 이후 histB/histG/histR을 각각 파랑/초록/빨강 선으로 겹쳐 그린다
bin 수는 목적에 맞춘다 시각화나 정밀 분석은 256 bin이 자연스럽다. 하지만 히스토그램 비교나 역투영처럼 잡음에 민감한 작업은 bin을 16~64로 줄이면 작은 밝기 차이에 둔감해져 더 안정적이다.

히스토그램 읽기 — 밝기·대비 진단

히스토그램의 형태를 보면 이미지 상태를 진단할 수 있다. 네 가지 전형적인 패턴을 알아두면 카메라 설정이나 조명 문제를 빠르게 짚어낸다.

히스토그램 형태이미지 상태진단
왼쪽(0 근처)에 몰림어두운 이미지노출 부족, 조명 약함
오른쪽(255 근처)에 몰림밝은 이미지노출 과다, 조명 강함
가운데 좁은 범위에 봉우리저대비 이미지명암 차이 부족, 흐릿함
0 또는 255에 막대가 솟음 (클리핑)노출 과다·부족 한계정보 손실 — 복구 불가
0~255 전 구간에 고르게 분포대비 풍부한 정상 이미지양호
0이나 255에 솟은 막대는 클리핑 신호다 히스토그램의 양 끝(0 또는 255)에 막대가 비정상적으로 높으면 픽셀이 그 한계로 잘려나갔다는 뜻이다. 이미 손실된 정보는 평활화로도 복구되지 않는다. 클리핑이 보이면 후처리가 아니라 촬영 단계의 노출·조명을 고쳐야 한다.

코드로 간단히 진단할 수도 있다. 어두운 영역(0~84)과 밝은 영역(170~255)의 픽셀 비율을 비교하면 노출 편향을 수치로 잡는다.

// hist: 그레이스케일 256 bin 히스토그램
double darkSum = 0, brightSum = 0, total = 0;
for (int i = 0; i < 256; i++)
{
    float c = hist.at<float>(i);
    total += c;
    if (i < 85)        darkSum += c;     // 어두운 영역
    else if (i >= 170) brightSum += c;   // 밝은 영역
}

double darkRatio = darkSum / total;
double brightRatio = brightSum / total;

if (darkRatio > 0.7)
    std::cout << "노출 부족 의심 (어두운 픽셀 "
              << static_cast<int>(darkRatio * 100) << "%)" << std::endl;
else if (brightRatio > 0.7)
    std::cout << "노출 과다 의심 (밝은 픽셀 "
              << static_cast<int>(brightRatio * 100) << "%)" << std::endl;

히스토그램 평활화 (equalizeHist)

히스토그램 평활화(equalization)는 좁은 범위에 몰려 있는 밝기 분포를 0~255 전 구간으로 펼쳐 대비를 끌어올리는 기법이다. 저대비 이미지의 디테일을 살리는 가장 기본적인 전처리다.

원리 — 누적분포함수(CDF)

평활화의 핵심은 누적분포함수(CDF, Cumulative Distribution Function)다. 각 밝기 값까지의 픽셀 수를 누적한 곡선을 만들고, 그 곡선을 0~255로 정규화한 값을 새 밝기 값으로 매핑한다. 픽셀이 많이 몰린 구간은 CDF가 가파르게 올라가므로 넓게 펼쳐지고, 픽셀이 적은 구간은 압축된다. 결과적으로 출력 히스토그램이 거의 평평해진다.

평활화는 누적분포함수를 통해 좁게 뭉친 밝기 분포를 0~255 전 구간으로 펼쳐 대비를 높인다.

그레이스케일 평활화

cv::equalizeHist는 1채널 8비트 이미지 전용이다. 입력과 출력 모두 CV_8UC1이어야 한다.

cv::Mat gray = cv::imread("low_contrast.jpg", cv::IMREAD_GRAYSCALE);
if (gray.empty())
{
    std::cerr << "이미지를 열 수 없습니다." << std::endl;
    return -1;
}

cv::Mat equalized;
cv::equalizeHist(gray, equalized);   // CDF 기반 평활화

cv::imshow("Original", gray);
cv::imshow("Equalized", equalized);
cv::waitKey(0);

컬러 이미지 평활화 — YCrCb의 Y만

컬러 이미지를 평활화하려면 밝기 채널만 평활화해야 한다. BGR 채널을 각각 평활화하면 채널 간 균형이 깨져 색이 틀어진다. 올바른 방법은 YCrCb나 HSV로 변환해 밝기 채널(Y 또는 V)만 평활화하고 다시 합치는 것이다.

cv::Mat color = cv::imread("low_contrast.jpg", cv::IMREAD_COLOR);

// BGR -> YCrCb 변환 (Y = 밝기, Cr/Cb = 색차)
cv::Mat ycrcb;
cv::cvtColor(color, ycrcb, cv::COLOR_BGR2YCrCb);

std::vector<cv::Mat> ch;
cv::split(ycrcb, ch);          // ch[0] = Y, ch[1] = Cr, ch[2] = Cb

cv::equalizeHist(ch[0], ch[0]);   // 밝기 채널만 평활화

cv::merge(ch, ycrcb);
cv::Mat result;
cv::cvtColor(ycrcb, result, cv::COLOR_YCrCb2BGR);   // 다시 BGR로
BGR 채널을 따로따로 평활화하면 색이 망가진다 B, G, R을 각각 equalizeHist에 넣으면 각 채널의 분포가 독립적으로 펼쳐지면서 채널 비율이 깨진다. 결과는 원본과 색조가 전혀 다른 이미지다. 컬러 평활화는 반드시 밝기 채널만 건드린다 — 색차 채널은 그대로 둔다.

CLAHE — 지역 적응형 평활화

equalizeHist는 이미지 전체에 하나의 CDF를 적용한다. 그래서 이미지의 일부만 어둡거나 밝은 경우, 전역 평활화는 그 지역 대비를 제대로 살리지 못하고 평탄한 배경의 노이즈를 과도하게 증폭시킨다.

CLAHE(Contrast Limited Adaptive Histogram Equalization)는 이미지를 작은 타일로 나눠 각 타일마다 따로 평활화하고, 타일 경계는 보간으로 매끄럽게 잇는다. 여기에 대비 제한(clip limit)을 두어 히스토그램의 특정 bin이 너무 높으면 잘라내 다른 bin에 재분배한다 — 이것이 노이즈 과증폭을 막는 핵심이다.

항목equalizeHistCLAHE
적용 범위이미지 전체에 단일 CDF타일별 지역 CDF + 경계 보간
지역 대비일부 영역은 살리지 못함어두운/밝은 영역 모두 개선
노이즈평탄한 영역에서 과증폭clipLimit로 증폭 억제
파라미터없음clipLimit, tileGridSize
속도매우 빠름약간 느림 (여전히 실용적)
적합 상황전체적으로 저대비조명 불균일, 부분 그림자

CLAHE 기본 사용

CLAHE는 cv::createCLAHE로 객체를 만들고 apply로 적용한다.

cv::Mat gray = cv::imread("uneven_light.jpg", cv::IMREAD_GRAYSCALE);

// clipLimit = 2.0, 타일 8x8 그리드
cv::Ptr<cv::CLAHE> clahe = cv::createCLAHE(2.0, cv::Size(8, 8));

cv::Mat result;
clahe->apply(gray, result);

cv::imshow("Original", gray);
cv::imshow("CLAHE", result);
cv::waitKey(0);

파라미터 — clipLimit와 tileGridSize

두 파라미터가 결과를 좌우한다.

파라미터의미값을 키우면
clipLimit히스토그램 막대 높이 제한대비 강해짐 + 노이즈도 증폭. 보통 2.0~4.0
tileGridSize이미지를 나누는 타일 격자 수더 지역적 — 작은 디테일 살아남, 부자연스러워질 수 있음. 보통 8×8
// 파라미터를 나중에 바꿔가며 튜닝할 수도 있다
cv::Ptr<cv::CLAHE> clahe = cv::createCLAHE();
clahe->setClipLimit(3.0);
clahe->setTilesGridSize(cv::Size(16, 16));

cv::Mat result;
clahe->apply(gray, result);

컬러 이미지에 CLAHE 적용

컬러도 마찬가지로 밝기 채널에만 적용한다.

cv::Mat color = cv::imread("uneven_light.jpg", cv::IMREAD_COLOR);

cv::Mat lab;
cv::cvtColor(color, lab, cv::COLOR_BGR2Lab);   // L = 밝기

std::vector<cv::Mat> ch;
cv::split(lab, ch);

cv::Ptr<cv::CLAHE> clahe = cv::createCLAHE(2.0, cv::Size(8, 8));
clahe->apply(ch[0], ch[0]);   // L 채널만

cv::merge(ch, lab);
cv::Mat result;
cv::cvtColor(lab, result, cv::COLOR_Lab2BGR);
clipLimit를 과도하게 키우면 CLAHE의 장점이 사라진다 clipLimit를 10, 20처럼 크게 주면 대비 제한이 사실상 풀려 CLAHE가 전역 평활화처럼 행동한다. 평탄한 배경의 미세한 센서 노이즈까지 거친 얼룩으로 증폭된다. 산업 검사 이미지라면 2.0~4.0 범위에서 시작해 결함이 보일 만큼만 천천히 올린다.

히스토그램 비교 (compareHist)

cv::compareHist는 두 히스토그램이 얼마나 닮았는지를 하나의 숫자로 돌려준다. 색 분포가 비슷한 이미지를 찾거나, 기준 이미지와 검사 이미지의 밝기 분포 차이를 감지할 때 쓴다.

비교 방법상수특징값 해석
상관 (Correlation)HISTCMP_CORREL두 분포의 선형 상관1에 가까울수록 유사, 0은 무관
카이제곱 (Chi-Square)HISTCMP_CHISQR차이를 제곱해 강조0에 가까울수록 유사, 클수록 다름
교차 (Intersection)HISTCMP_INTERSECT겹치는 부분의 합클수록 유사 (정규화 필요)
Bhattacharyya 거리HISTCMP_BHATTACHARYYA분포 간 거리0에 가까울수록 유사, 1은 완전 불일치
cv::Mat img1 = cv::imread("ref.jpg", cv::IMREAD_GRAYSCALE);
cv::Mat img2 = cv::imread("test.jpg", cv::IMREAD_GRAYSCALE);

int histSize[] = { 64 };          // 비교는 bin을 줄이는 편이 안정적
float range[] = { 0, 256 };
const float* ranges[] = { range };
int channels[] = { 0 };

cv::Mat h1, h2;
cv::calcHist(&img1, 1, channels, cv::Mat(), h1, 1, histSize, ranges);
cv::calcHist(&img2, 1, channels, cv::Mat(), h2, 1, histSize, ranges);

// 반드시 같은 기준으로 정규화한 뒤 비교한다
cv::normalize(h1, h1, 0, 1, cv::NORM_MINMAX);
cv::normalize(h2, h2, 0, 1, cv::NORM_MINMAX);

double correl = cv::compareHist(h1, h2, cv::HISTCMP_CORREL);
double chisqr = cv::compareHist(h1, h2, cv::HISTCMP_CHISQR);
double bhatta = cv::compareHist(h1, h2, cv::HISTCMP_BHATTACHARYYA);

std::cout << "상관 = "        << correl << std::endl;
std::cout << "카이제곱 = "    << chisqr << std::endl;
std::cout << "Bhattacharyya = " << bhatta << std::endl;
실행 결과 (콘솔)
상관 = 0.9214
카이제곱 = 3.187
Bhattacharyya = 0.1903
어떤 방법을 쓸까 빠른 유사도 판정은 HISTCMP_CORREL이 직관적이다. 작은 차이까지 민감하게 잡아야 하면 HISTCMP_CHISQR, 두 분포를 거리로 다뤄야 하면 HISTCMP_BHATTACHARYYA가 적합하다. 결과 스케일이 방법마다 다르므로 임계값도 방법별로 따로 정한다.

역투영 (calcBackProject)

역투영(back projection)은 "이 색 분포를 가진 영역이 이미지 어디에 있는가"를 찾는 기법이다. 먼저 찾고 싶은 객체의 히스토그램을 만들고, cv::calcBackProject로 입력 이미지의 각 픽셀이 그 분포에 속할 확률을 계산한다. 결과는 그레이스케일 확률 맵 — 밝을수록 그 색일 가능성이 높다.

색 기반 객체 추적이나 피부색 검출 등에 쓰인다. 보통 색상 정보가 밝기와 분리되는 HSV 색공간의 Hue 채널을 쓴다.

// 1단계: 찾고 싶은 객체 영역(ROI)의 색 히스토그램 만들기
cv::Mat objectRoi = cv::imread("object_sample.jpg");   // 추적할 색 샘플
cv::Mat roiHsv;
cv::cvtColor(objectRoi, roiHsv, cv::COLOR_BGR2HSV);

int hbins = 30;
int histSize[] = { hbins };
float hrange[] = { 0, 180 };           // Hue 범위 0~179
const float* ranges[] = { hrange };
int channels[] = { 0 };                // Hue 채널

cv::Mat roiHist;
cv::calcHist(&roiHsv, 1, channels, cv::Mat(), roiHist, 1, histSize, ranges);
cv::normalize(roiHist, roiHist, 0, 255, cv::NORM_MINMAX);

// 2단계: 전체 이미지에서 그 색 분포를 역투영
cv::Mat scene = cv::imread("scene.jpg");
cv::Mat sceneHsv;
cv::cvtColor(scene, sceneHsv, cv::COLOR_BGR2HSV);

cv::Mat backProj;
cv::calcBackProject(&sceneHsv, 1, channels, roiHist, backProj, ranges);
// backProj: 밝은 픽셀일수록 객체 색일 확률이 높다

// 3단계: 임계값으로 마스크화하면 객체 영역만 남는다
cv::Mat mask;
cv::threshold(backProj, mask, 50, 255, cv::THRESH_BINARY);
역투영 결과는 거칠다 — 후처리가 필요하다 calcBackProject의 출력은 픽셀 단위 확률이라 점잡음이 많다. 실무에서는 GaussianBlur로 부드럽게 만든 뒤 threshold, 그리고 모폴로지 연산(morphologyEx)으로 작은 구멍을 메우고 노이즈를 제거한 다음에야 깔끔한 객체 마스크를 얻는다.

산업 검사 관점

히스토그램은 산업 머신비전에서 이미지 품질을 감시하는 가장 값싼 센서다. 검사 알고리즘을 돌리기 전에 입력 이미지가 정상 범위 안에 있는지 빠르게 확인할 수 있다.

조명·노출 모니터링

생산 라인은 시간이 지나며 조명이 어두워지거나 외란광이 들어온다. 기준 이미지의 히스토그램을 저장해 두고, 매 프레임 compareHist로 비교하면 조명 드리프트를 즉시 감지한다. 평균 밝기나 표준편차만 추적해도 효과적이다.

// 매 프레임 평균 밝기를 추적해 조명 이상 감지
cv::Mat gray;
cv::cvtColor(frame, gray, cv::COLOR_BGR2GRAY);

cv::Scalar meanVal, stddevVal;
cv::meanStdDev(gray, meanVal, stddevVal);

const double kRefMean = 128.0;     // 기준 밝기
const double kTolerance = 20.0;    // 허용 오차

if (std::abs(meanVal[0] - kRefMean) > kTolerance)
{
    std::cout << "[경고] 조명 변화 감지 — 평균 밝기 "
              << meanVal[0] << std::endl;
    // 검사 보류 또는 조명 보정 트리거
}

평활화를 전처리로 활용

조명이 균일하지 않은 표면 검사에서는 CLAHE가 결함의 미세한 대비를 끌어올려 후속 임계처리나 엣지 검출의 신뢰도를 높인다. 다만 평활화는 밝기 절댓값을 바꾸므로, 절대 밝기를 기준으로 판정하는 알고리즘 앞에서는 쓰면 안 된다. 형태나 상대 대비를 보는 검사에만 적용한다.

전처리는 일관성이 생명이다 평활화나 CLAHE를 검사 파이프라인에 넣었다면 모든 프레임에 동일한 파라미터로 적용해야 한다. 프레임마다 파라미터가 달라지면 같은 결함이 어떤 날은 검출되고 어떤 날은 놓쳐진다. 파라미터는 한 번 정해 고정하고 버전 관리한다.

흔한 함정

히스토그램 작업에서 반복적으로 나오는 실수들이다.

equalizeHist를 컬러 이미지에 잘못 적용

equalizeHist는 1채널 전용이다 3채널 BGR 이미지를 그대로 equalizeHist에 넣으면 에러가 나거나, split 후 채널별로 평활화하면 색이 완전히 틀어진다. 컬러는 반드시 YCrCb/Lab/HSV로 변환해 밝기 채널만 평활화하고 다시 합쳐야 한다. 
cv::Mat color = cv::imread("sample.jpg");   // CV_8UC3

// 나쁨 — 3채널을 그대로 넣으면 동작하지 않거나 의도와 다름
// cv::equalizeHist(color, color);

// 나쁨 — 채널별 평활화는 색을 망가뜨린다
// std::vector<cv::Mat> bgr; cv::split(color, bgr);
// for (auto& c : bgr) cv::equalizeHist(c, c);   // 색조 붕괴

// 좋음 — 밝기 채널만 (4절의 YCrCb 방식 사용)

CLAHE clipLimit 과도 설정

clipLimit를 무작정 키우면 대비 제한이 풀려 CLAHE가 전역 평활화처럼 변하고 노이즈가 거칠게 증폭된다. 2.0~4.0에서 시작해 필요한 만큼만 조금씩 올린다. tileGridSize도 너무 작게(예: 2×2) 잡으면 타일 경계가 부자연스럽게 드러난다.

정규화 없이 히스토그램 비교

크기가 다른 이미지의 히스토그램은 그대로 비교할 수 없다 히스토그램의 막대 높이는 픽셀 수의 절댓값이다. 해상도가 다른 두 이미지는 전체 픽셀 수가 달라 같은 분포라도 막대 높이가 다르다. compareHist 전에 반드시 normalize로 두 히스토그램을 같은 기준에 맞춰야 한다.

bin 수 선택 실수

bin 수는 작업 목적에 맞춰야 한다. 256 bin은 시각화·정밀 분석에 좋지만 비교나 역투영에서는 작은 잡음에 과민하게 반응한다. 반대로 bin을 너무 적게(예: 8) 잡으면 서로 다른 이미지가 같은 히스토그램으로 뭉뚱그려진다. 비교·역투영은 보통 16~64 bin이 균형점이다.

정리하면 컬러 평활화는 밝기 채널만 건드리고, CLAHE clipLimit는 2.0~4.0에서 시작하고, compareHist 전에는 반드시 정규화하고, bin 수는 목적(시각화 256 / 비교·역투영 16~64)에 맞춘다. 이 네 가지가 히스토그램 작업의 90%를 좌우한다.
