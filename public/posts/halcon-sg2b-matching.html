Matching 개요와 공통 워크플로우

HALCON에서 matching은 prototype object(template)로부터 model을 만들고 다른 이미지에서 같은 model을 다시 찾는 일련의 연산을 가리킨다. 별도의 segmentation 없이 객체의 position, orientation, scale, pose 정보를 돌려준다는 점이 핵심이다.

모든 matching 접근법은 동일한 두 단계로 환원된다.

  1. Create model — reference image 또는 synthetic data로 model을 생성하고, 필요 시 train을 수행한다.
  2. Find model — search image에서 model instance를 찾아 위치·자세·score를 돌려받는다.
그림 1. HALCON matching 공통 파이프라인 — 접근법이 달라도 단계 구조는 동일하다.

접근법 선택 기준

Solution Guide II-B는 접근법 선택을 두 단계 결정으로 정리한다. 먼저 객체가 2D인지 3D인지, 평면 객체라면 직교 시점인지 원근 시점인지를 묻는다.

2.1 결정 트리

  • 직교 시점 2D 평면 객체: NCC, Shape-Based, Local Deformable 중 선택
  • 원근 시점 2D 평면 객체: Perspective Deformable, Descriptor-Based
  • 3D 객체(여러 면이 보이는 입체): 3D Matching

그 다음 객체의 외형 특성으로 좁힌다. gray pattern이 안정적이면 NCC, contour가 안정적이면 Shape-Based, 부분 휨이 있으면 Local Deformable, 평면 텍스처가 풍부하면 Descriptor-Based가 후보다.

2.2 접근법 비교표

접근법 모델 단서 대응 변환 속도 적합 상황
NCC gray value pattern 2D pos (+회전 제한) 매우 빠름 조명 안정, texture 일정한 부품
Shape-Based edge contour 2D pos + angle + scale 빠름 산업 부품, 인쇄, 형상 안정
Local Deformable edge contour + vector field 2D pos + 국소 변형 중간 label 휨, 유연 재질, 인쇄물 굴곡
Perspective Deformable edge contour Homography 또는 3D pose 중간~느림 비스듬한 카메라, 평면 마크
Descriptor-Based interest point + descriptor Homography 또는 3D pose 느림 texture 풍부한 평면 객체
3D Matching CAD 또는 surface model 3D pose (6DoF) 느림 다면 입체 부품, bin picking

Shape-Based Matching 심화

Shape-Based Matching은 객체를 edge contour와 그 gradient 방향으로 표현한다. 산업 현장에서 가장 범용적으로 쓰이는 방식이며, 조명 밝기 변화·부분 occlusion·clutter에 비교적 강하다.

3.1 generic interface 흐름

HALCON 24.11의 generic interface는 4단계로 정리된다.

gen_rectangle1 / draw_region        // 1. ROI 선택
create_generic_shape_model          // 2. 빈 model 생성
set_generic_shape_model_param       //    parameter 지정
train_generic_shape_model           // 3. template으로 학습
find_generic_shape_model            // 4. search image에서 찾기
get_generic_shape_model_result      //    score / pose 조회
get_generic_shape_model_result_object //  contour 조회

3.2 핵심 model parameter

parameter역할튜닝 원칙
contrast_low / contrast_highedge 포함 임계값 (hysteresis)단일값으로 깨끗하지 않으면 hysteresis로 약한 contour만 살리기
min_size최소 contour component 크기점·짧은 조각 형태의 clutter 제거
num_levelsimage pyramid 단계 수최상 level에서 model이 10~15픽셀 유지되도록
angle / scale range탐색 회전·축척 범위기구적으로 가능한 만큼만 열기
metricpolarity 비교 방식밝기 반전·배경 변화가 있으면 ignore_global_polarity
optimizationmodel point 개수 축소점이 많아 느릴 때 사용, 너무 줄이면 강건성 손실
min_contrastsearch 시 최소 contrastnoise 양에 맞춰 조정

3.3 ROI 정제 팁

reference image에 clutter가 있을 때 inspect_shape_model로 후보 contour를 미리 확인하고, fill_up + opening_circle 같은 morphology로 region 자체를 정제한 뒤 model을 만드는 방식이 권장된다. ROI 폭은 2^(NumLevels-1) 픽셀 이상이어야 상위 pyramid level에서 contour가 사라지지 않는다.

auto 값 활용 대부분 parameter는 'auto'로 두면 HALCON이 추정한다. 처음에는 auto로 시작해 determine_shape_model_params·inspect_shape_model로 값과 model 외형을 확인한 뒤, 속도/정확도 이슈가 있는 항목만 수동으로 좁힌다.

3.4 다중 모델 동시 검색

find_generic_shape_model은 ModelID tuple을 입력 받아 여러 모델을 한 번에 탐색할 수 있다. 다품종 라인에서 부품 종류와 위치를 동시에 식별할 때 유용하며, 결과의 model 필드로 어떤 model이 매칭됐는지 구분한다.

Correlation-Based Matching (NCC)

Normalized Cross Correlation은 ROI 내 gray value pattern과 search image의 윈도우 사이 정규화된 상관계수를 score로 사용한다. edge가 약하지만 gray pattern이 또렷한 대상(인쇄된 로고, frosted 표면 위 코드 등)에서 강하다.

4.1 기본 연산자

create_ncc_model       // ROI + reference image → model
find_ncc_model         // search image에서 NCC 기반 검색
set_ncc_model_param    // 'timeout' 등 부가 옵션
clear_ncc_model

4.2 주요 parameter

  • NumLevels — pyramid 단계. search 시 model 생성 시점보다 더 좁게 둘 수 있어 속도를 더 줄일 수 있다.
  • AngleStart / AngleExtent — 회전 범위. 회전을 열수록 model copy가 늘어나 메모리·시간이 증가한다.
  • Metric — use_polarity는 폴라리티 보존, ignore_global_polarity는 배경 명도 반전 허용.
  • SubPixel — true가 거의 같은 속도에 더 정밀한 위치를 주므로 기본 권장.
  • Greediness — 후보 가지치기 공격성. 0이면 안전·느림, 1이면 빠름·miss 가능.
NCC의 한계 부분 가림이 생기면 score가 빠르게 무너진다. Occlusion·clutter가 있는 산업 환경이라면 Shape-Based가 더 안전한 기본값이다.

Local Deformable Matching

Local Deformable Matching은 edge contour를 사용해 model을 만든다는 점에서 Shape-Based와 같지만, 결과로 vector field를 함께 돌려준다는 점이 다르다. 객체가 국소적으로 휘어진 경우 그 변형을 정량적으로 파악할 수 있다.

5.1 결과 산출물

  • image_rectified — 검출 영역을 model 좌표계로 펴서 normalize한 이미지. 후속 OCR/검사에 바로 투입할 수 있다.
  • vector_field — 각 픽셀의 변위. vector_field_to_real로 row/col 두 채널 실수 이미지로 분리해 사용한다.
  • deformed_contours — model contour를 변형 결과에 맞춰 펴서 표시용으로 받는 contour.

5.2 주요 parameter

  • NumLevels·Optimization·Contrast — Shape-Based와 동일 의미.
  • deformation_smoothness — 변형장의 매끄러움. 낮을수록 자유롭지만 false match 증가.
  • expand_border — rectified image의 외곽 여유.
회전·축척의 의미가 바뀐다 Local Deformable에서는 회전과 scale이 별도 결과로 나오지 않고 vector field 안의 변형으로 흡수된다. 후속 측정 좌표계를 만들 때는 단순 affine이 아니라 vector field를 함께 보정해야 한다.

Perspective Deformable Matching

카메라가 평면 객체를 비스듬히 보면 객체는 사다리꼴로 왜곡되고 위치마다 왜곡 정도가 달라진다. 이런 경우 Shape-Based는 실패하지만 Perspective Deformable Matching은 model 자체가 perspective 왜곡을 허용하도록 구성되어 있다.

6.1 uncalibrated vs calibrated

  • Uncalibrated — 결과로 2D homography(3×3 projective transform)를 돌려준다. 후속 ROI/contour를 projective_trans_*로 변환하면 된다.
  • Calibrated — camera calibration을 적용한 모델로, 결과로 객체의 3D pose를 돌려준다. 동일 평면 위에 있는 객체의 실제 위치·자세가 필요할 때 사용한다.

6.2 image rectify 대안과의 비교

카메라 시점이 한 가지로 고정되어 있다면 gen_image_to_world_plane_map + map_image로 이미지를 먼저 펴고 Shape-Based를 쓰는 쪽이 더 빠르고 정확하다. Perspective Deformable이 필요한 경우는 한 카메라가 여러 자세의 평면 객체를 보거나, 카메라가 움직이는 환경이다.

Descriptor-Based Matching

객체 위에 texture가 풍부한 경우에는 contour보다 interest point가 더 안정적인 단서가 된다. Descriptor-Based Matching은 reference image에서 interest point를 뽑고 그 주변 패치로 descriptor를 만든 뒤, search image의 점들과 매칭해 homography 또는 3D pose를 추정한다.

7.1 흐름

create_uncalib_descriptor_model    // ROI에서 interest point 추출 + descriptor 학습
find_uncalib_descriptor_model      // search image에서 대응점 찾고 homography 추정

calibrated 버전은 create_calib_descriptor_model / find_calib_descriptor_model이며 3D pose를 돌려준다.

7.2 적합·부적합

  • 적합: 책 표지, 인쇄 라벨, 다양한 texture가 있는 평면 마크
  • 부적합: 단순 금속 부품, 반복 패턴(체커보드·격자) — descriptor가 서로 구별되지 않아 ambiguity 발생

Component-Based / 3D Matching

8.1 Component-Based Matching

객체가 여러 부품(component)으로 이뤄지고 부품 사이 상대 위치가 약간씩 달라질 수 있을 때 사용한다. 각 component는 개별 shape model이고, component 간의 허용 관계(거리·각도 변동)를 함께 학습한다. 책 본 가이드의 주된 주제는 아니며, training 단계가 별도로 필요하다는 점만 알고 넘어가도 된다.

8.2 3D Matching

2D 이미지나 3D point cloud에서 입체 객체를 찾는 방식이다. Solution Guide II-B는 위치만 언급하고 자세한 절차는 Solution Guide III-C로 미룬다. 종류는 크게 두 가지다.

  • Shape-Based 3D — DXF/STL 같은 CAD 모델로 model을 만들고 2D image에서 객체의 3D pose를 찾는다.
  • Surface-Based 3D — 3D point cloud 사이의 정합. bin picking 시나리오의 표준이다.

평면 부품의 한 면만 안정적으로 보인다면 calibrated perspective deformable이나 calibrated descriptor가 더 간단하고 빠르다. 진짜 3D matching은 여러 면을 동시에 봐야 객체를 구분할 수 있을 때 필요하다.

모델 학습·검증 워크플로우

실무에서 matching이 안정적으로 동작하려면 model 생성 한 번으로 끝나는 게 아니라 sample 수집·검증·튜닝 사이클이 필요하다.

  1. 대표 reference image 확보 — 정상 조명·정상 자세·전형적인 contrast로 촬영한 이미지를 골라야 한다. 불량 sample을 reference로 쓰면 안 된다.
  2. ROI 정제 — 배경 edge, 가변 문자, 반사 highlight를 제거한다. 필요하면 synthetic model로 대체한다.
  3. parameter는 auto부터 — Shape-Based는 'auto'로 시작하고 inspect_shape_model·determine_shape_model_params로 확인한다.
  4. positive/negative sample로 score 분포 기록 — 양품·불량·오검출 후보의 score를 모아 threshold를 정한다.
  5. 속도 측정 후 단계적 축소 — search ROI → angle/scale range → num_levels → greediness 순으로 좁힌다. greediness를 먼저 올리는 것은 마지막 수단이다.
  6. recipe로 저장 — model file과 함께 ROI·tolerance·measure parameter도 묶어 저장한다. 다품종 라인에서 recipe load만으로 전환할 수 있어야 한다.

흔한 함정

함정 1 — 배경 edge가 model에 섞임

ROI를 객체에 딱 맞추지 않으면 배경 contour가 model에 포함되어, 다른 frame에서는 그 배경이 사라지자마자 score가 떨어진다. 대응: ROI를 좁히거나 morphology로 정제하거나 synthetic model로 전환.

함정 2 — 과대한 angle/scale 범위

"혹시 모르니" -180°~+180°를 열어 두면 search 시간이 폭증하고 대칭 형상에서 false match가 생긴다. 기구적으로 가능한 범위만 열어야 한다.

함정 3 — score threshold 오용

score는 절대 품질 지표가 아니다. 양품/불량 sample 분포가 겹치는 영역에서 threshold를 잡아야 하며, 단일 image로 정한 값을 그대로 라인에 올리면 거의 항상 실패한다.

함정 4 — pyramid level 과다

num_levels를 늘리면 빨라지지만 작은 feature는 상위 level에서 사라진다. 가장 작은 model feature 두께가 상위 level에서 살아남는지 inspect_shape_model로 확인한다.

함정 5 — Local Deformable 결과를 affine처럼 사용

Local Deformable의 위치를 단순 affine으로 후속 ROI 변환에 쓰면 휨이 반영되지 않는다. rectified image나 vector field 기반 변환을 써야 한다.

함정 6 — Descriptor를 반복 패턴에 적용

같은 무늬가 반복되는 객체(체크무늬, 격자)에서는 descriptor 사이 ambiguity가 커 잘못된 대응이 많아진다. Shape-Based로 전환하는 게 낫다.

핵심 정리

Solution Guide II-B 요점
  • HALCON matching은 5가지 2D 접근법 + 3D matching으로 구성되며, 모두 동일한 create → (train) → find 흐름이다.
  • 접근법 선택은 객체의 차원·시점·외형 단서(gray pattern vs contour vs interest point)로 결정한다.
  • Shape-Based는 산업 현장 기본값이고, 나머지는 그 한계(perspective, 휨, texture, 입체)에서 출발해 선택한다.
  • parameter는 'auto'로 시작하고 inspect_*·determine_*로 검증한 뒤 좁힌다.
  • 속도는 search ROI → 회전·축척 → pyramid → greediness 순으로 절약한다.
  • score threshold는 sample 분포 기반으로만 결정해야 하며 절대값으로 다루지 않는다.
