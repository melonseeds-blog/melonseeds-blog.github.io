왜 자기회귀 디코딩은 느린가

LLM은 토큰을 하나 만들 때마다 모델 전체를 한 번씩 forward한다. 100토큰을 만들려면 forward를 100번 해야 한다. 이전 토큰이 나와야 다음 토큰을 계산할 수 있으니 순차적(autoregressive)이라 병렬화도 안 된다.

더 중요한 건 이 과정이 메모리 바운드(memory-bound)라는 점이다. 토큰 1개를 만드는 데 필요한 연산량은 적은데, 그 1개를 위해 수십 GB의 모델 가중치를 GPU 메모리에서 다 읽어와야 한다. 즉 계산이 부족한 게 아니라 "가중치를 메모리에서 옮기는 시간"이 병목이다.

핵심 통찰 한 번 forward에서 토큰 1개를 만들든 여러 개를 검증하든, 가중치를 읽는 비용은 거의 같다(메모리 바운드라). 그렇다면 "한 번의 forward로 여러 토큰을 처리"할 수만 있으면 공짜에 가깝게 빨라진다. 가속 기법 대부분이 이 빈틈을 노린다.

Speculative decoding — 추측하고 검증한다

핵심 아이디어: 작고 빠른 draft 모델이 다음 토큰 여러 개를 추측하고, 크고 정확한 target 모델이 그 추측들을 한 번의 forward로 동시에 검증한다.

1. draft 모델이 다음 k개 토큰을 빠르게 생성:  t1, t2, ..., tk
2. target 모델이 그 k개를 한 번에 forward → 각 위치의 진짜 분포 확인
3. 앞에서부터 맞는 토큰은 수락(accept), 처음 틀린 곳에서 거절(reject)
4. 거절된 자리는 target 분포로 다시 1개 샘플 → 다음 라운드

draft가 잘 맞히면 한 번의 target forward로 여러 토큰이 통과한다. draft가 다 틀려도 최소 1토큰은 target이 직접 만들어내므로 느려지지는 않는다(최악이 일반 디코딩과 비슷). 보통 2~3배 속도 향상을 본다.

왜 품질이 손상되지 않는가

여기가 speculative decoding의 정수다. "작은 모델이 만든 토큰을 쓰는데 왜 품질이 안 떨어지나?"

답은 검증 단계가 수정된 거절 샘플링(modified rejection sampling)이라는 데 있다. draft가 제안한 토큰 x를 target 분포 p와 draft 분포 q로 이렇게 판정한다.

수락 확률 = min(1, p(x) / q(x))
거절 시  = (p - q)의 양수 부분으로 재정규화한 분포에서 샘플

이 규칙의 수학적 보장이 핵심이다 — 최종적으로 뽑히는 토큰의 분포는 정확히 target 모델 p와 같다. draft 모델이 무엇이든(아무리 나빠도) 결과 분포는 변하지 않는다. draft의 품질은 속도에만 영향을 주고 출력 분포에는 전혀 영향이 없다. 그래서 "무손실 가속(lossless acceleration)"이라 부른다.

자주 하는 오해 "speculative decoding은 품질을 약간 희생해 속도를 얻는다"는 틀렸다. greedy든 sampling이든, 거절 샘플링이 분포를 보존하므로 출력은 통계적으로 동일하다. 단, 부동소수점 오차나 구현 차이로 토큰이 미세하게 갈릴 수는 있다.

Self-speculative · Medusa · EAGLE

별도 draft 모델을 두는 건 번거롭다(두 모델을 메모리에 올려야 함). 그래서 "draft를 모델 안에서 만들자"는 변형들이 나왔다.

Self-speculative decoding

같은 모델의 일부 층만 써서(층 건너뛰기) draft를 만들고, 전체 층으로 검증한다. 별도 모델이 필요 없다.

Medusa — 다중 디코딩 헤드

모델 위에 추가 예측 헤드(head)를 여러 개 붙여, "다음 토큰", "다다음 토큰", "그 다음"을 한 번에 추측하게 한다. 이 헤드들의 추측을 트리로 묶어 target이 한 번에 검증한다. 별도 draft 모델 없이 헤드만 추가 학습하면 된다.

EAGLE — feature 수준 자기회귀

토큰이 아니라 모델 내부 표현(feature) 수준에서 다음을 예측해 draft를 만든다. 토큰 수준 추측보다 정확도가 높아 수락률이 올라가고, 그만큼 더 빠르다. 현재 speculative 계열 중 가속비가 높은 축에 속한다.

Lookahead와 n-gram speculation

Lookahead decoding (Jacobi)

draft 모델 자체가 없는 접근. 여러 위치의 토큰을 동시에 추측하고 반복적으로 수렴시키는 Jacobi 반복을 쓴다. 추측한 n-gram을 캐시에 모아 재활용한다. 별도 모델·추가 학습이 필요 없다는 게 장점이다.

Prompt lookup / n-gram speculation

가장 단순하면서 특정 상황에 강력하다. 출력에 입력의 텍스트가 그대로 다시 나올 법한 작업(요약·편집·RAG·코드 수정)에서는, draft를 입력 텍스트에서 n-gram 매칭으로 가져온다. 모델 호출 없이 "방금 본 구절"을 추측으로 제안하니, 인용·반복이 많은 작업에서 큰 가속을 낸다.

실무 선택 기준 ① 입력 재사용이 많은 작업(요약·편집·RAG) → prompt lookup이 거의 공짜. ② 범용 가속 + 추가 학습 가능 → Medusa/EAGLE. ③ 좋은 소형 동족 모델이 있음 → draft 모델 speculative. ④ 아무것도 추가 못 함 → lookahead.

배치·KV 캐시와의 관계

가속을 이야기할 때 디코딩 알고리즘만 보면 절반만 보는 것이다. 실제 처리량(throughput)은 서빙 계층이 좌우한다.

  • KV 캐시 — 이미 계산한 토큰의 key/value를 저장해 매 스텝 재계산을 피한다. 디코딩 속도의 기본 전제. 길이가 길수록 KV 캐시 메모리가 병목이 된다.
  • 연속 배치(continuous batching) — 여러 요청을 동적으로 묶어 GPU를 항상 채운다. vLLM·TGI 등이 쓰는 핵심 기법으로, 단일 요청 지연보다 전체 처리량을 끌어올린다.
  • PagedAttention — KV 캐시를 페이지 단위로 관리해 메모리 단편화를 줄인다(vLLM).
  • speculative decoding은 이들과 함께 작동한다. 단, 배치가 클 때는 GPU가 이미 꽉 차서(연산 바운드로 전환) speculative의 이득이 줄어들 수 있다 — 메모리 바운드일 때 가장 효과적이다.

정리

핵심 요약 ① 디코딩은 메모리 바운드라 "한 forward에 여러 토큰 검증"이 거의 공짜다. ② speculative decoding은 거절 샘플링으로 분포를 정확히 보존 — 무손실 가속. ③ Medusa·EAGLE·self-spec은 draft를 모델 안에서 해결. ④ prompt lookup은 입력 재사용 작업에서 모델 호출 없이 가속. ⑤ 실제 처리량은 KV 캐시·연속 배치 같은 서빙 계층과 함께 결정된다.
