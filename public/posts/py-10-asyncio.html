동시성·병렬성·비동기

비슷해 보이지만 서로 다른 개념이다. 한 줄로 구분하면 다음과 같다.

개념의미비유
동시성 (Concurrency)여러 작업을 잘게 쪼개 번갈아 진행한다. 한 시점에 진행 중인 작업이 여러 개다.한 명의 요리사가 여러 요리를 번갈아 만든다
병렬성 (Parallelism)여러 작업을 물리적으로 동시에 수행한다. 코어가 여러 개 필요하다.여러 명의 요리사가 각자 요리를 만든다
비동기 (Asynchronous)호출과 결과 수신을 분리한다. 결과를 기다리는 동안 다른 일을 한다.주문 후 진동벨을 받고 자리에서 다른 일을 한다

Python의 GIL과 그 한계

CPython은 GIL (Global Interpreter Lock) 때문에 같은 프로세스 안에서 한 번에 한 스레드만 파이썬 바이트코드를 실행한다. 즉 멀티스레드를 써도 CPU 바운드 작업은 진짜 병렬로 돌지 않는다.

방식병렬 실행GIL 영향적합한 작업
threading아니오(번갈아)받음 (I/O 대기 중에는 풀림)I/O 바운드
multiprocessing예 (프로세스별 인터프리터)없음CPU 바운드
asyncio아니오(단일 스레드 협력적)없음 (어차피 1스레드)대량 I/O 바운드
asyncio는 "더 가벼운 동시성"이다 스레드는 OS가 강제로 전환(선점형)하지만, asyncio는 코루틴이 await 지점에서 스스로 양보(협력형)한다. 컨텍스트 스위칭 비용이 작아 수천~수만 개의 동시 연결도 가볍게 다룬다.

asyncio 개요

asyncio는 Python 표준 라이브러리의 비동기 I/O 프레임워크다. 세 가지 축이 있다.

  • 이벤트 루프 (Event Loop) — 실행 가능한 코루틴을 골라 돌리는 스케줄러
  • 코루틴 (Coroutine) — async def로 정의된, 중간에 멈췄다 재개할 수 있는 함수
  • await — 다른 코루틴이나 awaitable이 끝날 때까지 자기 자리를 양보하는 키워드
이벤트 루프의 동작 — Ready Queue에서 코루틴을 꺼내 돌리다, await를 만나면 I/O 대기열로 보내고 다음을 실행한다. OS Selector가 완료를 알리면 다시 Ready Queue로 복귀한다.

async def와 await

async def로 정의하면 일반 함수가 아니라 코루틴 함수가 된다. 호출해도 바로 실행되지 않고 코루틴 객체를 반환한다. 실제 실행은 이벤트 루프가 한다.

import asyncio

async def hello():
    print("hello")
    await asyncio.sleep(1)   # 1초 동안 자리를 양보
    print("world")

# 그냥 호출하면 실행되지 않는다
coro = hello()
print(type(coro))            # <class 'coroutine'>

# 이벤트 루프에서 실행
asyncio.run(hello())
실행 결과
<class 'coroutine'> hello world

await는 awaitable(코루틴·Task·Future)이 완료될 때까지 현재 코루틴을 일시 중지한다. 그동안 이벤트 루프는 다른 코루틴을 돌린다.

async def fetch(name, delay):
    print(f"[{name}] 시작")
    await asyncio.sleep(delay)     # 다른 코루틴에 자리 양보
    print(f"[{name}] 완료 ({delay}s)")
    return f"{name} 결과"

async def main():
    # 순차 await — 총 3초
    r1 = await fetch("A", 1)
    r2 = await fetch("B", 2)
    print(r1, r2)

asyncio.run(main())
실행 결과 (총 ~3초)
[A] 시작 [A] 완료 (1s) [B] 시작 [B] 완료 (2s) A 결과 B 결과
await만으로는 동시 실행이 아니다 위 예제는 A가 끝난 뒤에야 B가 시작한다. 진짜 동시에 돌리려면 뒤에서 다룰 asyncio.gather나 create_task를 써야 한다.

이벤트 루프

이벤트 루프는 코루틴을 실제로 돌리는 엔진이다. 보통 asyncio.run()이 알아서 만들고 닫아 준다.

import asyncio

async def main():
    loop = asyncio.get_running_loop()   # 현재 실행 중인 루프 얻기
    print(loop)
    print("실행 중?", loop.is_running())

asyncio.run(main())

asyncio.run의 역할

asyncio.run(coro)는 다음 세 가지를 자동으로 처리한다.

  1. 새 이벤트 루프를 만든다
  2. coro를 끝까지 돌린다
  3. 루프를 닫는다 (모든 비동기 자원 정리 포함)
asyncio.run을 중첩하지 말 것 이미 이벤트 루프가 도는 안에서 asyncio.run()을 또 부르면 RuntimeError: asyncio.run() cannot be called from a running event loop가 난다. Jupyter처럼 루프가 미리 도는 환경에선 await를 직접 쓰거나 nest_asyncio 같은 도구를 쓴다.

Task와 동시 실행

코루틴을 Task로 감싸면 이벤트 루프가 즉시 스케줄에 올린다. 여러 Task를 만들고 모두 기다리는 것이 asyncio의 핵심 패턴이다.

asyncio.create_task

async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f"{name}({delay}s)"

async def main():
    # 즉시 백그라운드로 스케줄
    t1 = asyncio.create_task(fetch("A", 1))
    t2 = asyncio.create_task(fetch("B", 2))

    # 다른 일도 하고
    print("작업 시작 직후 — 아직 끝나지 않음")

    # 필요할 때 await로 결과 회수
    r1 = await t1
    r2 = await t2
    print(r1, r2)

asyncio.run(main())
실행 결과 (총 ~2초)
작업 시작 직후 — 아직 끝나지 않음 A(1s) B(2s)

asyncio.gather — 여러 코루틴 동시에

가장 자주 쓰는 함수. 여러 awaitable을 동시에 돌리고 결과를 순서대로 모은다.

async def main():
    results = await asyncio.gather(
        fetch("A", 1),
        fetch("B", 2),
        fetch("C", 1.5),
    )
    print(results)   # ['A(1s)', 'B(2s)', 'C(1.5s)']  ← 입력 순서

asyncio.run(main())
실행 결과 (총 ~2초)
['A(1s)', 'B(2s)', 'C(1.5s)']

return_exceptions=True를 주면 한 작업이 실패해도 나머지를 계속하고 예외를 결과 리스트에 담아 돌려준다.

async def maybe_fail(x):
    await asyncio.sleep(0.5)
    if x == 0:
        raise ValueError("zero!")
    return 1 / x

async def main():
    results = await asyncio.gather(
        maybe_fail(2), maybe_fail(0), maybe_fail(4),
        return_exceptions=True,
    )
    for r in results:
        print(r)

asyncio.run(main())
실행 결과
0.5 zero! 0.25

asyncio.wait — 더 세밀한 제어

wait는 gather보다 저수준이다. 완료된 것·아직인 것을 분리해 돌려주며, "하나라도 끝나면 깨우기" 같은 패턴이 가능하다.

async def main():
    tasks = [asyncio.create_task(fetch(name, d))
             for name, d in [("A", 1), ("B", 3), ("C", 2)]]

    done, pending = await asyncio.wait(
        tasks, return_when=asyncio.FIRST_COMPLETED
    )
    print("먼저 끝남:", [t.result() for t in done])
    print("남은 작업:", len(pending))

    # 나머지도 마저 대기
    await asyncio.gather(*pending)

asyncio.run(main())

타임아웃과 취소

asyncio.wait_for로 타임아웃 걸기

async def slow():
    await asyncio.sleep(5)
    return "done"

async def main():
    try:
        result = await asyncio.wait_for(slow(), timeout=2)
        print(result)
    except asyncio.TimeoutError:
        print("타임아웃! 작업은 취소됨")

asyncio.run(main())
실행 결과 (2초 후)
타임아웃! 작업은 취소됨

Task.cancel()로 명시적 취소

async def worker():
    try:
        while True:
            print("작업 중...")
            await asyncio.sleep(1)
    except asyncio.CancelledError:
        print("정리 작업 수행")
        raise            # 반드시 다시 던져야 cancel이 정상 전파됨

async def main():
    task = asyncio.create_task(worker())
    await asyncio.sleep(3)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("worker 취소 완료")

asyncio.run(main())
CancelledError는 잡되, 반드시 다시 던지자 취소 신호를 삼키면 cancel 의미가 사라진다. finally로 자원 정리만 하고 다시 raise하는 것이 표준 패턴이다.

asyncio.Queue로 생산자/소비자

스레드의 queue.Queue와 비슷한 인터페이스를 가진 비동기 큐다. put·get이 모두 await를 지원해 자연스럽게 생산자/소비자 파이프라인을 만들 수 있다.

import asyncio
import random

async def producer(queue, n):
    for i in range(n):
        item = f"item-{i}"
        await asyncio.sleep(random.uniform(0.1, 0.3))
        await queue.put(item)
        print(f"  생산: {item}")
    await queue.put(None)   # 종료 신호 (Sentinel)

async def consumer(queue, name):
    while True:
        item = await queue.get()
        if item is None:
            await queue.put(None)   # 다른 소비자에게도 전달
            break
        print(f"[{name}] 소비: {item}")
        await asyncio.sleep(random.uniform(0.2, 0.5))
        queue.task_done()

async def main():
    queue = asyncio.Queue(maxsize=5)
    await asyncio.gather(
        producer(queue, 5),
        consumer(queue, "C1"),
        consumer(queue, "C2"),
    )

asyncio.run(main())
maxsize로 자연스러운 배압(Backpressure) maxsize를 두면 큐가 가득 찼을 때 put이 자동으로 대기한다. 생산자가 소비자보다 너무 빠를 때 메모리 폭증을 막는 핵심 메커니즘이다.

async with와 async for

8편(컨텍스트 매니저)에서 봤던 with·for의 비동기 버전이다. I/O가 끼는 컨텍스트 진입·반복을 await로 처리한다.

async with — 비동기 컨텍스트 매니저

# 예: aiohttp로 HTTP 요청
import aiohttp
import asyncio

async def fetch_url(url):
    async with aiohttp.ClientSession() as session:   # __aenter__ / __aexit__
        async with session.get(url) as resp:
            return await resp.text()

async def main():
    html = await fetch_url("https://example.com")
    print(len(html), "bytes")

asyncio.run(main())

직접 구현할 때는 __aenter__·__aexit__ 또는 @asynccontextmanager 데코레이터를 쓴다.

from contextlib import asynccontextmanager

@asynccontextmanager
async def db_connection(url):
    print(f"연결 시작: {url}")
    await asyncio.sleep(0.1)        # 가상 연결
    try:
        yield {"url": url}
    finally:
        await asyncio.sleep(0.1)
        print("연결 해제")

async def main():
    async with db_connection("postgres://...") as conn:
        print("사용:", conn)

asyncio.run(main())

async for — 비동기 이터레이터

async def stream(n):
    for i in range(n):
        await asyncio.sleep(0.5)
        yield i                     # 비동기 제너레이터

async def main():
    async for value in stream(3):   # await가 내장된 for
        print("받음:", value)

asyncio.run(main())
실행 결과
받음: 0 받음: 1 받음: 2

언제 asyncio를 쓸까

asyncio는 대기 시간이 긴 I/O가 많을 때 빛난다. CPU를 쓰는 작업에는 도움이 되지 않는다.

작업 유형예시적합한 도구
I/O 바운드 (적은 수)파일 한두 개 읽기, 단일 HTTP동기 코드로 충분
I/O 바운드 (대량 동시)웹 크롤러, 채팅 서버, API gateway, DB 다중 쿼리asyncio
I/O 바운드 + 동기 라이브러리레거시 ORM, 동기 HTTP 라이브러리threading 또는 asyncio.to_thread
CPU 바운드이미지 처리, 행렬 연산, 압축multiprocessing / numpy / C 확장
# CPU 바운드는 멀티프로세스로
from concurrent.futures import ProcessPoolExecutor
import asyncio

def heavy(n):
    return sum(i * i for i in range(n))   # CPU만 씀

async def main():
    loop = asyncio.get_running_loop()
    with ProcessPoolExecutor() as pool:
        results = await asyncio.gather(*[
            loop.run_in_executor(pool, heavy, 10_000_000)
            for _ in range(4)
        ])
    print(results[0])

asyncio.run(main())

asyncio 안에서 동기 블로킹 함수를 안전하게 부르려면 asyncio.to_thread를 쓴다.

import time
import asyncio

def sync_blocking():
    time.sleep(2)            # 진짜로 멈춤
    return "done"

async def main():
    # 별도 스레드에서 실행 → 이벤트 루프는 안 막힘
    result = await asyncio.to_thread(sync_blocking)
    print(result)

asyncio.run(main())

흔한 함정

① await 누락 — 코루틴이 그냥 버려진다

async def save(data):
    await asyncio.sleep(0.1)
    print("저장:", data)

async def main():
    save("hello")            # ← await가 빠짐! 코루틴 객체만 만들고 끝
    print("끝")

asyncio.run(main())
실행 결과
끝 sys:1: RuntimeWarning: coroutine 'save' was never awaited
"never awaited" 경고는 곧 버그다 코루틴 함수를 호출만 하면 실행되지 않는다. 반드시 await 또는 asyncio.create_task()로 감싸야 한다.

② 동기 블로킹 호출 — 이벤트 루프 정지

import time

async def bad():
    time.sleep(2)            # ← 이벤트 루프 전체가 2초간 멈춤!
    return "done"

async def good():
    await asyncio.sleep(2)   # ← 자리를 양보, 다른 코루틴은 계속 진행
    return "done"
asyncio 안에선 time.sleep·requests.get 금지 파일·네트워크·DB는 비동기 라이브러리를 쓰거나 (aiofiles·aiohttp·asyncpg), 어쩔 수 없으면 asyncio.to_thread·run_in_executor로 별도 스레드에서 돌린다.

③ asyncio.run 중첩

async def inner():
    return 1

async def outer():
    # 잘못된 예
    return asyncio.run(inner())   # RuntimeError!

# 올바른 예
async def outer_ok():
    return await inner()

④ 너무 잘게 쪼개기

코루틴 스위칭이 가볍긴 해도 0은 아니다. CPU만 쓰는 짧은 함수를 굳이 async로 만들면 오버헤드만 늘고 이득이 없다. 실제로 I/O 대기가 있는 경계에서만 비동기로 만들자.

⑤ Task 참조를 놓치기

# 위험 — Task가 가비지 컬렉트되어 도중에 사라질 수 있음
asyncio.create_task(some_coro())

# 안전 — 참조를 보관
tasks = set()
task = asyncio.create_task(some_coro())
tasks.add(task)
task.add_done_callback(tasks.discard)
create_task 결과는 반드시 어딘가 보관 파이썬 공식 문서에도 명시된 권고다. 약한 참조만 남은 Task는 GC 대상이 되어 경고 없이 사라질 수 있다.
