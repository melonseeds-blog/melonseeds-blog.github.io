2D 데이터 코드 개요

2D 데이터 코드는 가로·세로 두 방향에 정보를 채워 같은 면적에 1D 바코드보다 훨씬 많은 데이터를 담는다. 어두운 모듈과 밝은 모듈로 이뤄진 셀의 격자가 기본 단위이고, 모듈의 개수가 곧 심볼의 크기다.

HALCON이 지원하는 2D 코드는 6종이다.

  • PDF417 — stacked code. 여러 줄의 1D 바코드가 행과 열로 쌓인다.
  • Data Matrix ECC 200 — 산업에서 가장 많이 쓰이는 매트릭스 코드. L자 finder 패턴.
  • QR Code — 세 모서리에 position detection 사각형이 있다.
  • Micro QR Code — finder 패턴이 좌상단에 하나뿐이다.
  • Aztec Code — 중앙의 동심 사각형이 finder 패턴이다.
  • DotCode — finder 패턴이 없는 점 패턴 코드.

심볼의 크기는 인코딩할 메시지 길이와 적용된 error correction 레벨에 따라 결정된다. 일부 모듈이 손상되어도 디코딩이 가능한 이유가 바로 이 error correction 때문이다.

코드 종류와 구조

심볼은 세 가지 구성요소로 나뉜다. finder pattern, data module, quiet zone이다. DotCode만 finder pattern이 없다.

심볼 분류 Finder 위치 특징
PDF417 stacked start/stop bar (좌·우) 3~90행, 1~30열, truncated 변형 지원
Data Matrix ECC 200 matrix L-shape + alternating 정사각 또는 직사각, 산업 표준
QR Code matrix 세 모서리 사각형 버전 번호가 크기를 결정
Micro QR matrix 좌상단 한 개 작은 면적용
Aztec matrix 중앙 nested square compact / full-range / rune
DotCode matrix(dot) 없음 잉크젯·고속 마킹용
주요 매트릭스 코드의 finder 패턴 차이

검출 워크플로우

HALCON의 모든 2D 코드 검출은 사실상 두 단계의 함수로 끝난다.

create_data_code_2d_model
→ (선택) set_data_code_2d_param
→ find_data_code_2d
→ get_data_code_2d_results / get_data_code_2d_objects

3.1 모델 생성

create_data_code_2d_model은 심볼 타입과 기본 파라미터 세트를 받아 핸들을 만든다.

create_data_code_2d_model ('Data Matrix ECC 200', [], [], DataCodeHandle)

3.2 검출과 디코딩

find_data_code_2d는 하나의 호출로 검출·읽기·디코드를 모두 수행한다.

find_data_code_2d (Image, SymbolXLDs, DataCodeHandle, [], [], \
                   ResultHandles, DecodedDataStrings)

출력은 심볼 외곽 XLD 컨투어, 디코드된 문자열, 그리고 후속 분석에 쓰는 result handle이다. 한 이미지에 코드가 여러 개라면 stop_after_result_num 파라미터를 같이 지정한다.

표준 2D 코드 검출 파이프라인

모델 파라미터

HALCON은 미리 정의된 세 단계의 인식 모드를 제공한다. 강도가 올라갈수록 더 어려운 심볼을 잡아내지만 그만큼 느리고 메모리도 많이 쓴다.

모드 특징 상대 속도
standard 좁은 파라미터 범위, dark-on-light, contrast ≥ 30 1×
enhanced light-on-dark 허용, contrast 10까지, slant 30°, module gap 허용 약 2×
maximum finder 일부 손상·왜곡 허용, 작은 모듈, local contrast 변동 약 5×
maximum 모드는 최후의 카드다 실행 시간과 메모리 부담이 크다. 가능하면 standard에서 시작해 training이나 specific parameter로 좁히는 편이 현장에서 더 안정적이다.

모듈 외관 polarity, contrast_min, module_size_min/max 극성, 명암차, 모듈 크기

학습 기반 모델 튜닝

대상 심볼들이 비슷한 특성을 공유한다면 일부 샘플로 모델을 자동 학습할 수 있다. 학습은 별도 함수가 아니라 find_data_code_2d 호출에 'train' 옵션을 넘기는 방식이다.

find_data_code_2d (Image, SymbolXLDs, DataCodeHandle, \
                   'train', 'all', ResultHandles, DecodedDataStrings)

학습 옵션 값은 'all', 'symbol_size', 'module_size', 'contrast' 등을 튜플로 조합할 수 있다. 첫 학습 이미지에서 모델 범위가 한 번 좁아지고, 그 뒤 이미지마다 필요한 만큼 다시 확장된다.

학습 샘플이 변동을 대표해야 한다 밝은 이미지와 어두운 이미지처럼 가장 차이가 큰 샘플을 의도적으로 골라야 한다. 비슷한 이미지만 모아 학습하면 현장의 변동을 못 잡는다.

학습 전후 차이는 query_data_code_2d_params와 get_data_code_2d_param으로 직접 비교할 수 있다.

검출 실패 원인 진단

find_data_code_2d는 내부적으로 후보(candidate)들을 단계별로 통과시키며 통과한 후보만 디코딩한다. 실패 진단은 결국 후보들이 어느 단계에서 떨어졌는지를 보는 것이다.

6.1 두 가지 실패 유형

  • aborted candidates — 심볼 후보로 인정되지 못한 영역. finder 패턴이 안 잡혔거나 quiet zone이 망가진 경우.
  • undecoded candidates — 심볼로 인정됐지만 디코드 실패. 모듈 손상·왜곡·노이즈가 주원인.

두 후보 그룹은 각각 'all_aborted', 'all_undecoded'로 접근한다.

set_data_code_2d_param (DataCodeHandle, 'persistence', 1)
find_data_code_2d (Image, ..., ResultHandles, DecodedDataStrings)

get_data_code_2d_results (DataCodeHandle, 'all_undecoded', \
                          'handle', HandlesUndecoded)
get_data_code_2d_results (DataCodeHandle, HandlesUndecoded[J], \
                          'status', StatusValue)

6.2 증상별 원인

증상 가능 원인 대응
candidate 자체가 안 잡힘 quiet zone 침범, contrast 부족, finder 손상 조명·ROI·enhanced 모드
candidate는 잡히는데 디코드 실패 모듈 손상, blur, print growth, 격자 왜곡 전처리·module 파라미터 조정
방향에 따라 결과가 달라짐 조명 반사, perspective 왜곡 조명각 변경, rectification
작은 모듈이 인식 안 됨 module_size_min이 너무 큼 small_modules_robustness=high
속도가 느림 maximum 모드, search 범위 넓음 training, ROI 제한, symbol_size 고정

디버깅 시각화에는 'search_image'(피라미드의 저해상도 검색 영상)와 'process_image'(고해상도 후속 처리 영상), 그리고 'module_1_rois'(전경 모듈)·'module_0_rois'(배경 모듈) 영역이 큰 도움이 된다.

전처리

모델 파라미터로 해결되지 않을 때는 이미지 쪽을 손본다. Solution Guide II-C가 직접 다루는 세 가지 시나리오가 있다.

7.1 Perspective 왜곡

심볼이 사선으로 찍혔다면 네 점을 표시해 hom_mat2d_..._4points로 변환 행렬을 구하고 projective_trans_image로 정면 영상을 만든다. 한 장씩 손으로 처리하는 단순 방법이지만 ECC 200이 정상적인 격자로 돌아오면 디코드 성공률이 크게 올라간다.

7.2 모듈 간격이 너무 큰 경우

매트릭스 코드는 모듈 사이의 간격이 모듈 크기의 50%를 넘어가면 기본 reader가 실패한다. 이때 그레이값 erosion으로 전경 모듈을 키워 간격을 좁힌다.

gray_erosion_shape (Image, ImageMin, 15, 15, 'rectangle')

이 방법은 매트릭스 코드 전용이다. PDF417은 모듈 간격 자체를 허용하지 않으므로 별도로 정교한 closing이 필요하다.

7.3 노이즈

quiet zone에 줄무늬가 끼거나 텍스처 노이즈가 심한 경우는 gray opening 또는 median filter로 부드럽게 만든다.

gray_opening_shape (Image, ImageOpening, 7, 7, 'octagon')
median_image (Image, ImageMedian, 'circle', 3, 'continued')

품질 평가 (ISO/IEC 15415)

코드가 지금 읽힌다고 해서 품질이 좋은 것은 아니다. 다른 reader, 다른 조명, 다른 카메라에서는 실패할 수 있기 때문이다. ISO/IEC 15415:2011은 2D 코드의 출력 품질을 객관 등급으로 매기는 표준이다.

HALCON에서는 get_data_code_2d_results의 파라미터 'quality_isoiec15415'로 등급을 가져온다. 등급은 4(최상)에서 0(최하)까지의 정수다.

8.1 매트릭스 코드 11개 항목

항목 의미
Overall Quality나머지 항목 중 최저 등급
Contrastdark/light의 최대 진폭
Modulation모듈별 진폭 균일도
Fixed Pattern Damagefinder·quiet zone 손상
Decode읽혔는지 여부(0 또는 4)
Axial Non-Uniformity가로/세로 모듈 간격 일치
Grid Non-Uniformity이상 격자에서의 편차
Unused Error Correction남은 error correction 여유
Reflectance Margin모듈 식별 마진
Print Growth잉크 번짐 정도(등급 아님)
Contrast Uniformity모듈별 modulation 최솟값(등급 아님)

PDF417은 7개 항목(Start/Stop Pattern, Codeword Yield, Unused Error Correction, Modulation, Decodability, Defects, Overall Quality)으로 평가한다. PDF417의 일부 항목은 1D 바코드 표준인 ISO/IEC 15416:2016의 기법과 겹친다.

"읽힘"과 "양호한 품질"은 다르다 HALCON은 ISO 등급이 낮은 심볼도 무리 없이 읽는다. 그래서 출하 검사에서는 "현재 읽힘 여부"가 아니라 ISO/IEC 15415 등급을 기준으로 합격선을 잡아야 한다. 라인에서 읽혀도 고객사 reader에서는 실패할 수 있다.

8.2 사용 예

find_data_code_2d (Image, SymbolXLDs, DataCodeHandle, [], [], \
                   ResultHandles, DecodedDataStrings)
get_data_code_2d_results (DataCodeHandle, ResultHandles[0], \
                          'quality_isoiec15415', Grades)

최근 HALCON에서는 절차 grade_data_code_2d를 사용하면 결과가 dictionary 형태로 반환되어 다루기가 더 편하다.

DPM과 AIM DPM-1-2006

DPM(Direct Part Marking)은 부품 표면에 직접 마킹된 코드를 말한다. 레이저 각인, 도트 핀, 잉크젯 등이 흔하다. 표면 재질의 반사가 균일하지 않고 마킹과 배경의 대비가 일반 인쇄보다 약해 ISO/IEC 15415만으로는 평가가 어렵다.

AIM DPM-1-2006은 ISO/IEC 15415의 확장으로, DPM 환경을 가정한다. HALCON은 ECC 200, QR, Micro QR, Aztec에 한해 이 표준을 지원한다.

9.1 AIM DPM의 12개 항목

ISO/IEC 15415와 거의 같지만 두 가지가 다르다.

  • Cell Contrast, Cell Modulation — 기존 Contrast / Modulation을 DPM 환경에 맞게 다시 정의한다.
  • Mean Light — 등급이 아니라 처리된 영상의 평균 밝기(0.0~1.0). 시스템 간 일관성을 확보하기 위한 보정 지표다.

9.2 절차 — Reflectance Calibration 필요

AIM DPM은 단발 호출로 끝나지 않는다. 사전 단계로 reflectance calibration이 필수이고, 결과를 저장한 뒤 본 검사에 사용한다. HALCON 예제 두 개가 제공된다.

  • calibration_aimdpm_1_2006.hdev — calibration 수행 및 저장
  • print_quality_aimdpm_1_2006.hdev — 저장된 calibration 기반 등급 산출
DPM은 조명 환경 자체가 표준의 일부다 AIM DPM-1-2006은 diffuse on-axis(90), diffuse off-axis(D), 30Q/30T/30S directional 같은 특정 조명을 권장한다. 조명을 바꾸면 calibration부터 다시 해야 한다. SW 튜닝으로 해결될 문제가 아니다.

산업 적용 — 추적성

2D 데이터 코드는 단순한 정보 표시가 아니라 스마트 공장의 추적성(traceability)을 떠받치는 기둥이다. 시리얼·로트·공정 이력이 부품 표면의 ECC 200 하나에 묶이는 구조다.

  • 부품 단위 시리얼 관리 — 입고부터 출하까지의 이력 연결
  • 공정 인터록 — 코드를 못 읽으면 다음 공정으로 못 넘어가게
  • 리콜 대응 — 결함 부품의 동일 로트 추적
  • 품질 데이터 누적 — 코드별 검사 결과의 시계열 분석
스마트 공장 시리즈 #9와의 연결 스마트 공장의 추적성은 결국 "어떤 코드를 어떤 품질로 마킹하고, 어느 공정에서 다시 읽는지"의 문제다. 마킹 품질은 ISO/IEC 15415·AIM DPM-1-2006으로 정량화하고, 읽기는 HALCON의 find_data_code_2d로 통일하면 라인 전체를 같은 기준으로 묶을 수 있다.

흔한 함정

알고리즘보다 영상·마킹 품질이 먼저다 검출률이 안 나올 때 가장 먼저 의심해야 할 것은 SW 파라미터가 아니라 조명·초점·노출·마킹 품질이다. enhanced/maximum 모드는 응급 처방이지 정답이 아니다.
training 샘플 부족 한두 장으로 학습하면 현장 변동을 못 잡는다. 가장 어두운 이미지와 가장 밝은 이미지처럼 양극단 샘플을 의도적으로 포함해야 한다.
DPM은 조명을 표준에 맞추지 않으면 grading 자체가 무효 AIM DPM-1-2006은 권장 조명 환경을 명시한다. 임의 조명에서 측정한 등급은 표준 등급이 아니다.
"읽힘" 기준으로 합격선을 잡지 말 것 라인에서 통과한 코드도 ISO 등급이 1~2점이면 고객사 reader에서 떨어진다. 출하 합격선은 등급 기준으로 정의한다.
속도가 안 나오면 search 범위부터 좁힌다 symbol_size, module_size, polarity를 고정하고 ROI를 한정하면 maximum 모드에서도 속도가 크게 나아진다. 모드를 낮추기 전에 먼저 해야 할 일이다.

핵심 정리

2D 데이터 코드 설계 핵심
  • HALCON의 2D 코드 검출은 create_data_code_2d_model + find_data_code_2d 두 호출이 전부다.
  • standard → training → specific parameter 순으로 좁히는 것이 enhanced/maximum 모드를 켜는 것보다 안정적이다.
  • 실패는 후보 단계(aborted/undecoded)와 status 메시지로 진단한다.
  • 전처리는 perspective 보정, gray morphology, median filter 세 가지가 핵심이다.
  • "읽힘"이 아닌 ISO/IEC 15415 등급으로 출하 합격선을 정의한다.
  • DPM은 AIM DPM-1-2006을 쓰되 reflectance calibration과 권장 조명이 필수다.
  • 2D 코드는 스마트 공장 추적성의 데이터 매개체이므로 마킹 품질이 전체 시스템 품질을 결정한다.
