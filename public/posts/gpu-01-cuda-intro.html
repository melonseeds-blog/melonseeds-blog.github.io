GPU란?

Graphics Processing Unit. 원래는 픽셀과 정점(vertex)을 동시에 그리기 위해 태어난 그래픽 전용 칩이다. 화면의 모든 픽셀이 본질적으로 같은 연산("이 색을 이 위치에 그려라")을 반복한다는 점에서, GPU는 처음부터 같은 연산을 수천 개의 데이터에 동시에 적용하는 방향으로 진화했다.

2007년 NVIDIA가 CUDA를 발표하면서 GPU는 그래픽을 벗어나 범용 컴퓨팅(GPGPU, General-Purpose computing on GPU)으로 확장된다. 지금은 딥러닝, 시뮬레이션, 영상처리, 암호 해시까지 "데이터가 많고 연산이 규칙적인" 모든 분야의 표준 가속기다.

SIMD와 SIMT

GPU의 병렬성은 SIMT(Single Instruction, Multiple Threads) 모델로 표현된다. CPU의 SIMD(Single Instruction, Multiple Data — 예: AVX-512)와 비슷하지만, GPU는 한 명령을 수십~수천 개의 "스레드" 단위로 동시에 흘려보낸다. NVIDIA에서는 32개 스레드가 한 묶음(warp)으로 같은 명령을 실행한다.

모델의미예시
SISD한 명령, 한 데이터전통적 스칼라 CPU
SIMD한 명령, 여러 데이터 (벡터 레지스터)SSE, AVX, NEON
SIMT한 명령, 여러 스레드 (분기 허용)NVIDIA CUDA, AMD ROCm

CPU vs GPU

한 줄 요약: CPU는 레이턴시(latency) 최적화, GPU는 처리량(throughput) 최적화다. CPU는 한 스레드를 최대한 빨리 끝내는 데 자원을 쓰고, GPU는 한 스레드가 느리더라도 수만 개를 굴려서 단위 시간당 처리량을 끌어올린다.

CPU는 코어가 크고 캐시·제어 로직이 두껍다. GPU는 코어가 작고 많으며, 한 명령을 warp 단위로 동시에 흘린다.

대표적인 데스크탑급 칩을 기준으로 비교한다(수치는 세대마다 다르므로 자릿수로 보자).

"GPU가 1000배 빠르다"는 어디서 나오나 스칼라 한 줄이 빠르다는 게 아니다. 같은 시간에 GPU는 수천 개 연산을 동시에 수행한다. 즉 처리량(throughput) 측면의 비율이며, 데이터가 충분히 클 때만 의미가 있다.

CUDA란?

CUDA(Compute Unified Device Architecture)는 NVIDIA가 만든 GPU 컴퓨팅 플랫폼이다. 단순한 API가 아니라 드라이버 + 런타임 + 컴파일러(nvcc) + 표준 라이브러리(cuBLAS, cuDNN, Thrust 등) + 도구(Nsight)의 묶음이다.

산업 현장에서 NVIDIA GPU + Windows + Visual Studio 조합이 사실상 표준이므로, 이 시리즈는 CUDA를 기준으로 진행한다.

CUDA 프로그래밍 모델

CUDA 코드는 두 세계로 나뉜다. 호스트(Host) = CPU + 시스템 메모리, 디바이스(Device) = GPU + GPU 메모리. 호스트가 데이터를 디바이스로 복사하고, 커널을 실행시키고, 결과를 받아온다.

호스트는 디바이스로 데이터를 복사하고 커널을 띄운 뒤, 결과를 다시 호스트로 복사한다.

스레드 계층: grid / block / thread

커널을 실행할 때 두 개의 차원을 정한다. 한 grid는 여러 개의 block으로 이루어지고, 한 block은 여러 개의 thread로 이루어진다.

// 1D 예시: N개의 데이터를 처리한다.
// block 당 256 thread, block 개수는 ceil(N/256).
int threadsPerBlock = 256;
int blocks = (N + threadsPerBlock - 1) / threadsPerBlock;
myKernel<<<blocks, threadsPerBlock>>>(d_data, N);

커널 내부에서는 인덱싱이 핵심이다.

__global__ void myKernel(float* data, int N)
{
    // 전역 1D 인덱스 계산.
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx >= N) return;          // 경계 가드 필수.

    data[idx] = data[idx] * 2.0f;
}
지정자실행 위치호출 위치
__global__DeviceHost (커널 진입점)
__device__DeviceDevice (디바이스 보조 함수)
__host__HostHost (기본값)

Compute Capability

GPU 세대마다 지원하는 명령어 집합이 다르다. 이를 compute capability (sm_XX)로 표현한다. 컴파일 시 본인 GPU에 맞춰 지정해야 PTX → SASS 변환이 효율적이다.

아키텍처대표 GPUsm_XX
PascalGTX 1080sm_61
TuringRTX 2080sm_75
AmpereRTX 3090, A100sm_86 / sm_80
Ada LovelaceRTX 4090sm_89
HopperH100sm_90
드라이버 버전과 Toolkit 버전이 안 맞으면 끝장이다 Toolkit은 "최소 드라이버 버전" 요구사항이 있다. 회사 PC처럼 드라이버 업데이트가 막힌 환경에서 최신 Toolkit을 설치하면 cudaErrorInsufficientDriver가 뜬다. nvidia-smi가 보여주는 드라이버의 "CUDA Version"은 그 드라이버가 지원하는 최대 Toolkit 버전이다 — 설치된 Toolkit 버전이 아니라는 점에 주의.

Visual Studio 2022 + CUDA 빌드

두 가지 방법이 있다. (A) VS의 CUDA 프로젝트 템플릿은 가장 빠른 시작 방법이고, (B) CMake 통합은 ImagingLib처럼 멀티 모듈 프로젝트에 적합하다.

(A) VS CUDA 프로젝트

VS 2022 → 새 프로젝트 → CUDA 12.x Runtime 템플릿. .cu 파일이 자동으로 nvcc로 라우팅된다. 프로젝트 속성 → CUDA C/C++ → Device → Code Generation에서 sm_XX를 지정한다.

(B) CMake 통합 (권장)

# CMakeLists.txt
cmake_minimum_required(VERSION 3.18)
project(ImagingCuda LANGUAGES CXX CUDA)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CUDA_STANDARD 17)

# 빌드 대상 아키텍처. 본인 GPU에 맞춘다.
# 75 = Turing, 86 = Ampere, 89 = Ada
set(CMAKE_CUDA_ARCHITECTURES 75 86 89)

add_executable(hello_cuda
    src/main.cpp
    src/kernel.cu
)

# .cu 파일에 별도 옵션이 필요하면
target_compile_options(hello_cuda PRIVATE
    $<$<COMPILE_LANGUAGE:CUDA>:--use_fast_math>
)
vcpkg + CMake 환경이라면 ImagingLib는 vcpkg manifest 모드를 쓴다. opencv4[cuda,contrib] 기능을 켜두면 cv::cuda 헤더가 자동으로 연결된다. CUDA Toolkit 자체는 vcpkg가 설치하지 않으므로 시스템에 별도로 설치해야 한다.

첫 실행 — deviceQuery와 CUDA Hello

deviceQuery로 GPU 정보 확인

Toolkit 샘플에 포함된 deviceQuery는 GPU 스펙을 한눈에 보여준다. 직접 짜도 어렵지 않다.

// device_query.cu — 디바이스 정보를 출력한다.
#include <cuda_runtime.h>
#include <cstdio>

int main()
{
    int deviceCount = 0;
    cudaGetDeviceCount(&deviceCount);

    if (deviceCount == 0)
    {
        printf("CUDA-capable device not found.\n");
        return 1;
    }

    for (int i = 0; i < deviceCount; ++i)
    {
        cudaDeviceProp prop{};
        cudaGetDeviceProperties(&prop, i);

        printf("Device %d: %s\n", i, prop.name);
        printf("  Compute Capability : %d.%d\n", prop.major, prop.minor);
        printf("  SM count           : %d\n", prop.multiProcessorCount);
        printf("  Global memory      : %.2f GB\n",
               prop.totalGlobalMem / (1024.0 * 1024.0 * 1024.0));
        printf("  Memory bus width   : %d-bit\n", prop.memoryBusWidth);
        printf("  Memory clock       : %d MHz\n", prop.memoryClockRate / 1000);
        printf("  Max threads/block  : %d\n", prop.maxThreadsPerBlock);
        printf("  Warp size          : %d\n", prop.warpSize);
    }
    return 0;
}
실행 결과 (예: RTX 3060 기준)
Device 0: NVIDIA GeForce RTX 3060 Compute Capability : 8.6 SM count : 28 Global memory : 11.99 GB Memory bus width : 192-bit Memory clock : 7501 MHz Max threads/block : 1024 Warp size : 32

CUDA Hello — 벡터 덧셈

"Hello, World" 격인 벡터 덧셈 예제. CUDA의 전체 사이클(할당 → 복사 → 커널 → 복사 → 해제)이 다 들어있다.

// vector_add.cu
#include <cuda_runtime.h>
#include <cstdio>
#include <vector>

// Device kernel: c[i] = a[i] + b[i].
__global__ void VectorAdd(const float* a, const float* b, float* c, int n)
{
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n)
    {
        c[idx] = a[idx] + b[idx];
    }
}

int main()
{
    constexpr int kN = 1 << 20;            // 약 100만개.
    constexpr int kBytes = kN * sizeof(float);

    // Host buffer.
    std::vector<float> hA(kN, 1.0f);
    std::vector<float> hB(kN, 2.0f);
    std::vector<float> hC(kN, 0.0f);

    // Device buffer.
    float* dA = nullptr;
    float* dB = nullptr;
    float* dC = nullptr;
    cudaMalloc(&dA, kBytes);
    cudaMalloc(&dB, kBytes);
    cudaMalloc(&dC, kBytes);

    // H2D copy.
    cudaMemcpy(dA, hA.data(), kBytes, cudaMemcpyHostToDevice);
    cudaMemcpy(dB, hB.data(), kBytes, cudaMemcpyHostToDevice);

    // Launch kernel.
    constexpr int kThreadsPerBlock = 256;
    int blocks = (kN + kThreadsPerBlock - 1) / kThreadsPerBlock;
    VectorAdd<<<blocks, kThreadsPerBlock>>>(dA, dB, dC, kN);

    // D2H copy.
    cudaMemcpy(hC.data(), dC, kBytes, cudaMemcpyDeviceToHost);

    // Verify.
    printf("hC[0] = %f, hC[N-1] = %f\n", hC[0], hC[kN - 1]);

    cudaFree(dA);
    cudaFree(dB);
    cudaFree(dC);
    return 0;
}
실행 결과
hC[0] = 3.000000, hC[N-1] = 3.000000

에러 체크는 매크로로 묶자

위 예제는 깔끔한 흐름을 보여주려고 에러 체크를 생략했지만, 실제 코드에서는 모든 CUDA API 호출의 반환값을 확인해야 한다.

// Common CUDA error-check macro.
#define CUDA_CHECK(call)                                                      \
    do                                                                        \
    {                                                                         \
        cudaError_t err = (call);                                             \
        if (err != cudaSuccess)                                               \
        {                                                                     \
            fprintf(stderr, "CUDA error %s at %s:%d\n",                       \
                    cudaGetErrorString(err), __FILE__, __LINE__);             \
            std::abort();                                                     \
        }                                                                     \
    } while (0)

CUDA_CHECK(cudaMalloc(&dA, kBytes));
CUDA_CHECK(cudaMemcpy(dA, hA.data(), kBytes, cudaMemcpyHostToDevice));

// 커널 실행 직후에는 별도로 체크해야 한다.
VectorAdd<<<blocks, kThreadsPerBlock>>>(dA, dB, dC, kN);
CUDA_CHECK(cudaGetLastError());           // launch 실패 여부.
CUDA_CHECK(cudaDeviceSynchronize());      // 실행 중 에러 여부.

산업 비전 관점

산업 비전(머신 비전) 시스템은 한 줄 요약하면 "고속 카메라 + 실시간 검사"다. 다음과 같은 상황에서 GPU는 선택이 아니라 필수가 된다.

  • 고해상도 라인스캔 카메라 — 8K × 라인레이트 100kHz면 초당 수백 MB의 픽셀. CPU 한 스레드로는 컬러 보간조차 따라가지 못한다.
  • 딥러닝 기반 결함 검출 — UNet, YOLO 같은 모델은 GPU 없이는 ms 단위 추론이 불가능하다. cuDNN/TensorRT 사용이 사실상 강제된다.
  • 대면적 매칭 / 서브픽셀 측정 — 정규화 상관(NCC), Hough, 모폴로지 등을 풀 해상도에서 수십 fps로 돌려야 할 때.

ImagingLib에서는 핵심 이미지 컨테이너가 CPU/GPU 메모리를 모두 들고 있다가 EnsureCpu() / EnsureGpu()로 필요한 쪽에 데이터를 보장한다. 처리 블록은 가능하면 GPU 위에 데이터를 머무르게 해서 H2D/D2H 왕복 비용을 없앤다. 다음 편들에서 이 컨테이너 설계와 cv::cuda 래핑, 그리고 TensorRT 통합을 차례로 다룬다.

시리즈 미리보기 9편에서는 cv::cuda를 ImagingLib의 Filter 블록에 연결하는 방법을, 11편에서는 학습된 모델을 TensorRT 엔진으로 변환해 실시간 검사 파이프라인에 끼우는 방법을 다룬다. 둘 다 결국은 본 글의 host-device 모델 위에서 동작한다.

흔한 함정

1. 드라이버 / Toolkit / cuDNN 버전 불일치 가장 흔한 삽질. Toolkit 12.4면 드라이버 R550 이상이 필요한 식이다. cuDNN은 또 Toolkit 버전에 묶인다. 새 PC에서 환경을 잡을 때는 드라이버 → Toolkit → cuDNN → 프레임워크 순으로, 각 단계에서 호환 표를 확인하고 진행한다.
2. compute capability 미지원으로 인한 런타임 실패 sm_89로 빌드한 바이너리를 sm_61 GPU에 가져가면 JIT 컴파일이 시도되지만 실패하는 경우가 많다. 배포용 빌드는 CMAKE_CUDA_ARCHITECTURES에 여러 SM을 같이 넣어 fat binary로 만든다.
3. "GPU는 무조건 빠르다"라는 착각 데이터 크기가 작으면 cudaMemcpy 왕복 비용이 커널 실행 시간보다 크다. 100 × 100 이미지 한 장에 단순 임계 처리하려고 GPU를 쓰는 건 손해다. 일반적으로 수 MB 이상 + 픽셀당 충분한 연산량이 있을 때부터 GPU가 이긴다.
4. 비동기 커널을 동기로 착각 커널 런치(kernel<<<...>>>)는 즉시 리턴한다. 결과를 측정하려면 반드시 cudaDeviceSynchronize()를 부르거나 cudaEvent를 써야 한다. 그냥 std::chrono로 둘러싸면 커널 시간이 0에 가깝게 나온다.
5. 커널 안에서 예외 / 동적 할당 / iostream 사용 디바이스 코드는 C++의 표준 예외, std::cout, 호스트 std::vector 등을 쓰지 못한다. 디버깅 출력은 printf(디바이스용)나 호스트로 복사 후 출력으로 우회한다.
