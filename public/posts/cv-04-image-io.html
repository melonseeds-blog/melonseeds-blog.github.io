이미지 처리 코드는 결국 어딘가에서 이미지를 읽어와 처리하고, 어딘가에 결과를 내보낸다. OpenCV의 입출력 모듈은 파일, 메모리 버퍼, 비디오, 카메라를 모두 같은 cv::Mat으로 다루게 해 준다. 이 글은 그 입출력 경로 전체를 코드 중심으로 정리한다.

입력 소스 → 입력 API → cv::Mat → 출력 API. 어떤 소스든 중간 표현은 항상 cv::Mat이다.

이미지 파일 읽기 — imread

cv::imread(path, flags)는 디스크의 이미지 파일을 읽어 cv::Mat으로 반환한다. 두 번째 인자 flags로 어떤 형태로 디코딩할지 지정한다.

#include <opencv2/opencv.hpp>
using namespace cv;

// 기본 — 3채널 BGR 컬러로 읽기
Mat color = imread("sample.png", IMREAD_COLOR);

// 1채널 그레이스케일로 읽기
Mat gray = imread("sample.png", IMREAD_GRAYSCALE);

// 파일에 저장된 그대로 (알파 채널·비트 깊이 보존)
Mat raw = imread("sample.png", IMREAD_UNCHANGED);

// 16비트/32비트 등 원본 비트 깊이 유지 (TIFF, PNG 16bit 등)
Mat depth16 = imread("height_map.tif", IMREAD_ANYDEPTH);

주요 flag 정리

Flag결과 Mat용도
IMREAD_COLOR3채널 8비트 BGR기본값. 컬러 처리 일반
IMREAD_GRAYSCALE1채널 8비트엣지·이진화 등 흑백 처리
IMREAD_UNCHANGED파일 그대로 (알파 포함)PNG 투명도, 원본 비트 깊이 보존
IMREAD_ANYDEPTH원본 비트 깊이 유지16/32비트 TIFF, 깊이맵
IMREAD_ANYCOLOR원본 채널 수 유지채널 수를 강제하지 않을 때
IMREAD_REDUCED_COLOR_21/2 축소 컬러썸네일·빠른 미리보기
imread는 실패해도 예외를 던지지 않는다 파일이 없거나 깨졌으면 빈 Mat을 조용히 반환한다. 읽은 직후 반드시 empty()로 확인하지 않으면, 다음 처리 단계에서 엉뚱한 곳에서 크래시가 난다. 
Mat img = imread("input.png", IMREAD_COLOR);
if (img.empty())
{
    std::cerr << "이미지를 읽지 못했다: input.png" << std::endl;
    return -1;
}
// 여기서부터는 img가 유효함이 보장된다
std::cout << "크기: " << img.cols << "x" << img.rows
          << ", 채널: " << img.channels() << std::endl;
실행 결과
크기: 1920x1080, 채널: 3

이미지 파일 쓰기 — imwrite

cv::imwrite(path, img, params)는 cv::Mat을 파일로 저장한다. 저장 포맷은 파일 확장자로 결정된다. 세 번째 인자 params로 포맷별 압축 옵션을 준다.

Mat img = imread("input.png");

// 확장자만 보고 포맷 결정 — 별도 옵션 없음
imwrite("output.png", img);
imwrite("output.jpg", img);
imwrite("output.bmp", img);

// JPEG 품질 지정 (0~100, 높을수록 고품질·큰 용량)
std::vector<int> jpegParams = { IMWRITE_JPEG_QUALITY, 95 };
imwrite("high_quality.jpg", img, jpegParams);

// PNG 압축 레벨 지정 (0~9, 높을수록 작은 용량·느린 저장, 무손실)
std::vector<int> pngParams = { IMWRITE_PNG_COMPRESSION, 3 };
imwrite("compressed.png", img, pngParams);

imwrite는 성공 시 true, 실패 시 false를 반환한다. 디렉터리가 없거나 권한이 없으면 실패하므로 반환값을 확인한다.

if (!imwrite("result/output.png", img))
{
    std::cerr << "저장 실패 — 디렉터리/권한 확인" << std::endl;
}
파라미터범위의미
IMWRITE_JPEG_QUALITY0~100 (기본 95)JPEG 품질. 낮을수록 손실 큼
IMWRITE_PNG_COMPRESSION0~9 (기본 1)PNG 압축 강도. 무손실 유지
IMWRITE_TIFF_COMPRESSION코덱 코드TIFF 압축 방식 (LZW 등)
IMWRITE_WEBP_QUALITY1~100WebP 품질
PNG 압축 레벨은 화질과 무관하다 PNG는 무손실이라 압축 레벨 0이든 9든 픽셀 값은 동일하다. 레벨이 높을수록 파일이 작아지고 저장이 느려질 뿐이다. JPEG의 품질 인자와는 성격이 완전히 다르다.

지원 포맷과 손실/무손실

OpenCV는 JPG, PNG, BMP, TIFF, WebP, PPM 등 대부분의 일반 이미지 포맷을 지원한다. 산업 검사에서 포맷 선택은 곧 정밀도와 직결되므로 손실/무손실 구분이 중요하다.

포맷손실 여부특징산업 검사 적합도
BMP무손실 (무압축)용량 큼, 저장/로드 빠름적합 — 원본 보존
PNG무손실 (압축)용량 절감, 16비트·알파 지원적합 — 가장 추천
TIFF무손실 (옵션)16/32비트, 멀티페이지적합 — 고비트 영상
JPG손실용량 매우 작음, 블록 노이즈부적합 — 검사 금지
WebP손실/무손실 선택웹 전송용제한적
검사 대상 이미지는 손실 압축으로 저장하지 않는다 JPEG는 8x8 블록 단위 DCT로 고주파 성분을 버린다. 그 결과 미세 결함의 엣지가 뭉개지고, 없던 블록 경계 패턴이 생긴다. 측정·결함 검출 정밀도가 직접 떨어지므로, 검사 파이프라인에서는 PNG·BMP·TIFF 같은 무손실 포맷만 쓴다. JPEG는 사람이 눈으로 확인하는 리포트 썸네일 정도로만 제한한다.

메모리 버퍼 입출력 — imdecode / imencode

파일 경로 대신 메모리상의 바이트 배열과 직접 주고받아야 할 때가 있다. 네트워크로 이미지를 전송하거나, 데이터베이스 BLOB 컬럼에 저장하는 경우다. 이때 imdecode와 imencode를 쓴다.

imencode — Mat을 인코딩된 바이트로

Mat img = imread("input.png");

// Mat → PNG 바이트 배열 (파일로 쓰지 않고 메모리에만)
std::vector<uchar> buffer;
bool ok = imencode(".png", img, buffer);
if (ok)
{
    std::cout << "인코딩 크기: " << buffer.size() << " bytes" << std::endl;
    // 이 buffer를 소켓으로 전송하거나 DB에 INSERT
}

// JPEG 품질을 주면서 인코딩
std::vector<int> params = { IMWRITE_JPEG_QUALITY, 80 };
std::vector<uchar> jpgBuf;
imencode(".jpg", img, jpgBuf, params);

imdecode — 바이트를 Mat으로

// 네트워크/DB에서 받은 바이트 배열이 buffer에 있다고 가정
std::vector<uchar> buffer = receiveFromNetwork();

// 바이트 배열 → Mat
Mat decoded = imdecode(buffer, IMREAD_COLOR);
if (decoded.empty())
{
    std::cerr << "디코딩 실패 — 손상된 데이터" << std::endl;
    return -1;
}
// decoded를 일반 Mat처럼 처리
imdecode도 빈 Mat을 반환한다 imread와 마찬가지로 디코딩 실패 시 예외 없이 빈 Mat을 돌려준다. 외부에서 받은 데이터일수록 손상 가능성이 크므로 empty() 확인은 필수다.

비디오 읽기 — VideoCapture

cv::VideoCapture는 비디오 파일, 카메라, 네트워크 스트림을 모두 같은 인터페이스로 연다. 생성자나 open()에 무엇을 넘기느냐로 소스가 결정된다.

// 비디오 파일 열기
VideoCapture cap("video.mp4");

// USB 카메라 열기 (장치 인덱스 0번)
VideoCapture camCap(0);

// RTSP 네트워크 스트림 열기
VideoCapture stream("rtsp://192.168.0.10/stream1");

// 열기 성공 여부 확인 — 반드시 체크
if (!cap.isOpened())
{
    std::cerr << "비디오를 열 수 없다" << std::endl;
    return -1;
}

프레임 루프

프레임은 cap >> frame 또는 cap.read(frame)으로 한 장씩 꺼낸다. 더 이상 읽을 프레임이 없으면 빈 Mat이 반환되므로 그것을 루프 종료 조건으로 쓴다.

VideoCapture cap("video.mp4");
if (!cap.isOpened()) return -1;

Mat frame;
int frameCount = 0;
while (true)
{
    cap >> frame;            // cap.read(frame) 과 동일
    if (frame.empty())      // 마지막 프레임 이후엔 빈 Mat
        break;

    // 여기서 frame 처리 (예: 그레이 변환)
    Mat gray;
    cvtColor(frame, gray, COLOR_BGR2GRAY);
    frameCount++;
}
std::cout << "총 " << frameCount << " 프레임 처리" << std::endl;
cap.release();              // 명시적 해제 (소멸자에서도 자동 해제)

비디오 속성 조회

double fps    = cap.get(CAP_PROP_FPS);
double width  = cap.get(CAP_PROP_FRAME_WIDTH);
double height = cap.get(CAP_PROP_FRAME_HEIGHT);
double total  = cap.get(CAP_PROP_FRAME_COUNT);   // 파일에서만 유효

std::cout << width << "x" << height
          << " @ " << fps << "fps, "
          << total << " frames" << std::endl;

카메라 캡처

USB 웹캠은 VideoCapture(0)처럼 장치 인덱스로 연다. 카메라가 여러 대면 0, 1, 2... 순으로 늘려가며 시도한다. 해상도와 FPS는 set()으로 요청한다.

VideoCapture cam(0);
if (!cam.isOpened())
{
    std::cerr << "카메라를 열 수 없다" << std::endl;
    return -1;
}

// 해상도·FPS 설정 요청 (드라이버가 지원해야 적용됨)
cam.set(CAP_PROP_FRAME_WIDTH, 1280);
cam.set(CAP_PROP_FRAME_HEIGHT, 720);
cam.set(CAP_PROP_FPS, 30);

// 실제 적용된 값 확인 — 요청대로 안 될 수 있다
std::cout << "실제 해상도: "
          << cam.get(CAP_PROP_FRAME_WIDTH) << "x"
          << cam.get(CAP_PROP_FRAME_HEIGHT) << std::endl;

Mat frame;
while (true)
{
    cam >> frame;
    if (frame.empty()) break;

    imshow("Camera", frame);
    if (waitKey(1) == 27)   // ESC 키로 종료
        break;
}
cam.release();
destroyAllWindows();
속성의미
CAP_PROP_FRAME_WIDTH프레임 가로 픽셀 수
CAP_PROP_FRAME_HEIGHT프레임 세로 픽셀 수
CAP_PROP_FPS초당 프레임 수
CAP_PROP_BRIGHTNESS밝기 (드라이버 지원 시)
CAP_PROP_EXPOSURE노출 (드라이버 지원 시)
CAP_PROP_BUFFERSIZE내부 프레임 버퍼 크기
산업 카메라는 보통 전용 SDK를 쓴다 Vieworks 같은 산업용 카메라/그래버는 트리거 동기화, 정밀 노출 제어, GenICam 포맷 등이 필요해서 제조사 전용 SDK로 다룬다. 다만 USB UVC 웹캠은 VideoCapture로 충분히 캡처되므로, 프로토타입이나 간단한 테스트 환경에는 그대로 쓸 수 있다.

비디오 쓰기 — VideoWriter

cv::VideoWriter는 프레임들을 모아 비디오 파일로 저장한다. 생성 시 코덱(fourcc), FPS, 프레임 크기를 지정해야 한다.

// 코덱 지정 — 4글자 코드 (fourcc)
int fourcc = VideoWriter::fourcc('m', 'p', '4', 'v');  // MPEG-4
// 다른 예: 'X','V','I','D' (Xvid), 'M','J','P','G' (Motion JPEG)

double fps = 30.0;
Size frameSize(1280, 720);

VideoWriter writer("output.mp4", fourcc, fps, frameSize);
if (!writer.isOpened())
{
    std::cerr << "VideoWriter 열기 실패 — 코덱 확인" << std::endl;
    return -1;
}

VideoCapture cap(0);
Mat frame;
while (cap.read(frame))
{
    if (frame.empty()) break;

    // writer에 넣는 프레임 크기는 frameSize와 정확히 일치해야 한다
    if (frame.size() != frameSize)
        resize(frame, frame, frameSize);

    writer.write(frame);    // writer << frame; 과 동일
    if (waitKey(1) == 27) break;
}
writer.release();
cap.release();
프레임 크기·채널 수가 어긋나면 영상이 비거나 깨진다 VideoWriter에 넘기는 모든 프레임은 생성 시 지정한 frameSize와 크기가 같아야 하고, 기본적으로 3채널 BGR이어야 한다. 그레이스케일을 저장하려면 cvtColor로 BGR로 변환하거나 생성자의 isColor 인자를 false로 준다. 크기가 어긋나면 에러 없이 빈 파일이 만들어지는 경우가 많아 디버깅이 까다롭다.

디스플레이 — imshow / waitKey

처리 결과를 화면에 띄울 때는 imshow로 그리고 waitKey로 이벤트를 처리한다. 이 둘은 거의 항상 짝으로 쓰인다.

Mat img = imread("input.png");
if (img.empty()) return -1;

// 창에 이미지 표시
imshow("Result", img);

// 키 입력 대기 — 이게 없으면 창이 그려지지 않는다!
waitKey(0);             // 0: 키 누를 때까지 무한 대기
// waitKey(30);         // 30ms 대기 후 진행 (영상 루프용)

destroyWindow("Result");    // 특정 창 닫기
// destroyAllWindows();     // 모든 창 닫기

namedWindow — 창 속성 제어

imshow는 창이 없으면 자동 생성하지만, namedWindow로 미리 만들면 창 속성을 지정할 수 있다.

// 사용자가 창 크기를 자유롭게 조절할 수 있게
namedWindow("Preview", WINDOW_NORMAL);
resizeWindow("Preview", 800, 600);
imshow("Preview", img);

// 이미지 크기에 창을 고정 (기본값)
namedWindow("Fixed", WINDOW_AUTOSIZE);

waitKey(0);

키 입력 처리

VideoCapture cap(0);
Mat frame;
while (cap.read(frame))
{
    imshow("Live", frame);

    int key = waitKey(1);        // 1ms 대기, 반환값은 ASCII 코드
    if (key == 27)               // ESC
        break;
    else if (key == 's' || key == 'S')
        imwrite("snapshot.png", frame);   // 's' 키로 스냅샷 저장
}
waitKey는 디스플레이의 일부다 imshow는 GUI 이벤트 큐에 그리기 요청만 넣는다. 실제 렌더링은 waitKey가 이벤트 루프를 돌릴 때 일어난다. 그래서 waitKey를 빼면 창이 회색으로 멈추거나 아예 안 뜬다. 영상 루프에서는 waitKey(1)처럼 짧게라도 반드시 호출한다.

흔한 함정

imread 실패를 체크하지 않음

가장 빈번한 실수다. imread는 실패해도 빈 Mat을 반환할 뿐 예외를 던지지 않는다. 체크를 빠뜨리면 한참 뒤 처리 단계에서 원인 불명의 크래시가 난다. 읽기·디코딩 직후 항상 empty() 확인한다.

경로 문제 — 상대경로와 한글 경로

상대경로는 실행 시점의 작업 디렉터리 기준이다. IDE에서 실행할 때와 더블클릭으로 실행할 때 작업 디렉터리가 달라 "분명 있는 파일"을 못 읽는 일이 흔하다. 가능하면 절대경로를 쓴다. 또한 OpenCV의 파일 입출력은 환경에 따라 유니코드(한글) 경로를 제대로 못 다룰 수 있다. 한글 경로가 불가피하면 imread 대신 파일을 직접 읽어 imdecode로 디코딩하는 우회법을 쓴다.

// 한글 경로 우회 — 파일을 바이트로 읽어 imdecode
#include <fstream>

Mat imreadUnicode(const std::string& path)
{
    std::ifstream file(path, std::ios::binary);
    if (!file)
        return Mat();   // 빈 Mat 반환

    std::vector<uchar> data((std::istreambuf_iterator<char>(file)),
                            std::istreambuf_iterator<char>());
    return imdecode(data, IMREAD_COLOR);
}

waitKey 누락으로 창이 안 뜸

imshow만 호출하고 waitKey를 빼면 창이 그려지지 않거나 회색으로 멈춘다. 디스플레이 코드 뒤에는 반드시 waitKey를 둔다.

VideoWriter 프레임 크기 불일치

VideoWriter 생성 시 지정한 크기와 다른 크기의 프레임을 write하면 에러 없이 빈 파일이 만들어진다. 매 프레임 크기를 보장하거나 resize로 맞춘다.

손실 압축으로 검사 정밀도 저하

검사 이미지를 JPEG로 저장하면 결함이 사라진다 "용량 절감"을 이유로 검사 대상 이미지를 JPEG로 저장하면, DCT 압축이 미세 결함의 엣지와 텍스처를 뭉갠다. 한 번 손실된 정보는 복구되지 않으므로, 저장 단계에서 PNG·BMP·TIFF 같은 무손실 포맷을 강제한다. 손실 압축은 사람이 보는 리포트용 썸네일에만 허용한다.
