레이아웃 시스템 — Measure / Arrange

WPF는 모든 컨트롤을 2단계 패스로 배치한다. 부모 패널이 자식을 측정하고, 자식이 원하는 크기를 보고 실제 위치를 결정한다. 이 두 단계를 이해해야 커스텀 컨트롤이나 복잡한 레이아웃에서 막히지 않는다.

단계호출 메서드역할
MeasureMeasureOverride(Size availableSize)부모가 주는 가용 공간을 받아 자식이 원하는 DesiredSize를 계산
ArrangeArrangeOverride(Size finalSize)부모가 실제로 할당한 영역에 자식을 위치·크기 확정
// 커스텀 패널 예시 — Measure / Arrange 직접 구현
public class SimpleStackPanel : Panel
{
    protected override Size MeasureOverride(Size availableSize)
    {
        double totalHeight = 0;
        double maxWidth = 0;
        foreach (UIElement child in InternalChildren)
        {
            // 자식에게 가용 공간을 알려주고, 원하는 크기를 묻는다.
            child.Measure(new Size(availableSize.Width, double.PositiveInfinity));
            totalHeight += child.DesiredSize.Height;
            maxWidth = Math.Max(maxWidth, child.DesiredSize.Width);
        }
        return new Size(maxWidth, totalHeight);
    }

    protected override Size ArrangeOverride(Size finalSize)
    {
        double y = 0;
        foreach (UIElement child in InternalChildren)
        {
            child.Arrange(new Rect(0, y, finalSize.Width, child.DesiredSize.Height));
            y += child.DesiredSize.Height;
        }
        return finalSize;
    }
}
왜 2단계인가? Measure는 "자식이 얼마나 필요한지" 묻고, Arrange는 "그래서 어디에 놓을지" 정한다. 분리되어 있어서 Auto 크기처럼 자식의 요구에 맞춰 부모가 줄어드는 동작이 가능하다.

레이아웃 패널 5종 개요

WPF가 기본으로 제공하는 주요 패널은 다음 다섯이다. 각각의 용도를 먼저 비교한다.

패널용도대표 속성전형적 쓰임
Grid행·열 분할 표RowDefinitions, ColumnDefinitions전체 화면 골격
StackPanel한 방향 일렬Orientation버튼 묶음, 폼 항목
DockPanel가장자리 도킹DockPanel.Dock, LastChildFill툴바·상태바 레이아웃
WrapPanel자동 줄바꿈ItemWidth, ItemHeight썸네일 갤러리
Canvas절대 좌표Canvas.Left, Canvas.Top다이어그램, 블록 에디터
5종 패널의 배치 특성

Grid — 행·열 분할

가장 자주 쓰는 패널이다. 행·열로 영역을 나누고 자식을 셀에 배치한다. RowDefinition·ColumnDefinition의 크기 단위 세 가지를 먼저 익혀야 한다.

크기 단위의미예시
Auto자식이 원하는 만큼제목줄 높이
* (스타)남은 공간을 비율로 분배*, 2*
절대값고정 픽셀(DIP)200

기본 Grid

<Grid>
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>   <!-- 0: 제목줄, 내용에 맞춤 -->
        <RowDefinition Height="*"/>      <!-- 1: 본문, 남는 공간 차지 -->
        <RowDefinition Height="30"/>     <!-- 2: 상태바, 고정 30 -->
    </Grid.RowDefinitions>
    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="200"/> <!-- 0: 사이드바 200 -->
        <ColumnDefinition Width="*"/>   <!-- 1: 영상 영역 -->
    </Grid.ColumnDefinitions>

    <TextBlock Grid.Row="0" Grid.ColumnSpan="2" Text="검사 도구"/>
    <ListBox   Grid.Row="1" Grid.Column="0"/>
    <Image     Grid.Row="1" Grid.Column="1" Source="frame.png"/>
    <StatusBar Grid.Row="2" Grid.ColumnSpan="2"/>
</Grid>
Grid.Row·Grid.Column attached property로 셀을 지정한다

스타(*) 비율 분배

<!-- 1 : 2 : 1 비율로 3등분 -->
<Grid.ColumnDefinitions>
    <ColumnDefinition Width="*"/>
    <ColumnDefinition Width="2*"/>
    <ColumnDefinition Width="*"/>
</Grid.ColumnDefinitions>

<!-- 최소·최대 폭 제한도 가능 -->
<ColumnDefinition Width="*" MinWidth="100" MaxWidth="400"/>

셀 병합 — RowSpan / ColumnSpan

<Border Grid.Row="0" Grid.Column="0"
        Grid.RowSpan="2" Grid.ColumnSpan="3"
        Background="LightYellow"/>

SharedSizeGroup — 폼 정렬 팁

여러 Grid의 같은 열을 같은 폭으로 맞출 때 쓴다. 폼에서 라벨 폭을 통일할 때 유용하다.

<StackPanel Grid.IsSharedSizeScope="True">
    <Grid>
        <Grid.ColumnDefinitions>
            <ColumnDefinition Width="Auto" SharedSizeGroup="LabelCol"/>
            <ColumnDefinition Width="*"/>
        </Grid.ColumnDefinitions>
        <TextBlock Text="Exposure (us):"/>
        <TextBox Grid.Column="1"/>
    </Grid>
    <Grid>
        <Grid.ColumnDefinitions>
            <ColumnDefinition Width="Auto" SharedSizeGroup="LabelCol"/>
            <ColumnDefinition Width="*"/>
        </Grid.ColumnDefinitions>
        <TextBlock Text="Gain:"/>
        <TextBox Grid.Column="1"/>
    </Grid>
</StackPanel>
Auto vs * 혼동 주의 Auto는 자식 크기에 맞춰 줄어들지만, *는 부모가 주는 공간을 모두 차지한다. ScrollViewer 안에서 * 행을 쓰면 무한 공간이 되어 스크롤이 동작하지 않는 사고가 자주 난다.

StackPanel — 일렬 배치

자식을 한 방향으로 일렬 배치한다. Orientation이 Vertical(기본) 또는 Horizontal이다.

<!-- 수직(기본) — 버튼이 위에서 아래로 쌓인다 -->
<StackPanel Margin="8">
    <Button Content="Load Image" Margin="0,0,0,4"/>
    <Button Content="Run Inspection" Margin="0,0,0,4"/>
    <Button Content="Save Result"/>
</StackPanel>

<!-- 수평 — 도구바처럼 좌에서 우로 -->
<StackPanel Orientation="Horizontal">
    <Button Content="Zoom +"/>
    <Button Content="Zoom -"/>
    <Button Content="Fit"/>
</StackPanel>
StackPanel은 한 축으로 무한 공간을 준다 수직 StackPanel은 자식의 세로 크기에 제약을 두지 않는다. 자식의 Height="*"나 VerticalAlignment="Stretch"가 먹지 않는다. 영역을 비율로 나눠야 한다면 Grid를 써야 한다.

DockPanel — 가장자리 도킹

자식을 상·하·좌·우 가장자리에 차례로 붙인다. DockPanel.Dock attached property로 도킹 변을 지정하고, 마지막 자식은 기본적으로 남은 영역을 채운다.

<DockPanel LastChildFill="True">
    <Menu       DockPanel.Dock="Top"/>
    <ToolBar    DockPanel.Dock="Top"/>
    <StatusBar  DockPanel.Dock="Bottom"/>
    <TreeView   DockPanel.Dock="Left" Width="220"/>
    <Border     DockPanel.Dock="Right" Width="280"/>
    <!-- LastChildFill=true 이므로 마지막 자식이 가운데를 채운다 -->
    <Image Source="frame.png"/>
</DockPanel>
도킹 순서가 중요하다 먼저 선언된 자식이 먼저 가장자리를 차지한다. Top을 먼저 선언하면 좌·우는 그 아래에만 도킹된다. 헤더가 좌측 패널 위까지 덮길 원하면 순서를 바꿔야 한다.

WrapPanel — 자동 줄바꿈

자식을 한 줄에 채우다가 폭이 부족하면 다음 줄로 넘긴다. 썸네일 갤러리, 태그 묶음 같은 곳에 쓴다.

<WrapPanel Orientation="Horizontal" ItemWidth="120" ItemHeight="90">
    <Image Source="img1.png"/>
    <Image Source="img2.png"/>
    <Image Source="img3.png"/>
    <!-- 폭이 부족하면 자동으로 다음 줄로 넘어간다 -->
</WrapPanel>

Canvas — 절대 좌표

좌상단 (0, 0) 기준의 절대 좌표로 자식을 배치한다. Canvas.Left·Canvas.Top attached property를 쓴다. 자유 배치가 필요한 다이어그램이나 데이터 플로우 블록 에디터에 적합하다.

<Canvas Background="#F8F9FB">
    <Rectangle Canvas.Left="50"  Canvas.Top="40"
               Width="120" Height="60" Fill="#BFDBFE"/>
    <Rectangle Canvas.Left="240" Canvas.Top="120"
               Width="120" Height="60" Fill="#A7F3D0"/>
    <Line X1="170" Y1="70" X2="240" Y2="150"
          Stroke="Black" StrokeThickness="2"/>
</Canvas>

코드 비하인드에서 동적으로 노드를 추가할 때도 같은 패턴이다.

// 블록 에디터에서 노드를 동적으로 추가
var node = new BlockNodeView { DataContext = blockVm };
Canvas.SetLeft(node, blockVm.X);
Canvas.SetTop(node, blockVm.Y);
canvas.Children.Add(node);
블록 에디터에서 본격적으로 다룬다 Canvas + ItemsControl + DataTemplate 조합으로 데이터 플로우 노드를 그리는 패턴은 시리즈 11편에서 다룬다.

Alignment·Margin·Padding

패널이 자식에게 영역을 할당한 뒤, 자식이 그 영역 안에서 어떻게 자리잡을지를 결정하는 속성이다.

속성대상값의미
HorizontalAlignment모든 FrameworkElementLeft, Center, Right, Stretch할당된 셀 안에서 가로 정렬
VerticalAlignment모든 FrameworkElementTop, Center, Bottom, Stretch할당된 셀 안에서 세로 정렬
Margin모든 FrameworkElementThickness (외부 여백)자기 외곽과 부모 사이 간격
PaddingControl / Border / BlockThickness (내부 여백)경계와 내용 사이 간격
<Button Content="OK"
        HorizontalAlignment="Right"
        VerticalAlignment="Bottom"
        Margin="0,0,16,16"
        Padding="20,8"/>

<!-- Margin / Padding Thickness 표기 -->
<!-- Margin="10"            : 사방 10 -->
<!-- Margin="10,5"          : 좌우 10, 상하 5 -->
<!-- Margin="L,T,R,B"  →    : 좌, 상, 우, 하 -->
<Border Margin="10,5,10,20" Padding="12"/>
Stretch가 기본값이다 HorizontalAlignment·VerticalAlignment의 기본은 Stretch다. 명시하지 않으면 셀을 가득 채운다. 가운데 정렬이 필요하면 명시해야 한다.

Border·ScrollViewer·Viewbox

레이아웃 패널은 아니지만 거의 항상 함께 쓰는 컨테이너 3종이다.

Border — 테두리·배경·둥근 모서리

<Border BorderBrush="#CBD5E1" BorderThickness="1"
        CornerRadius="8" Background="White" Padding="16">
    <TextBlock Text="검사 결과: OK"/>
</Border>

ScrollViewer — 스크롤

<ScrollViewer HorizontalScrollBarVisibility="Auto"
              VerticalScrollBarVisibility="Auto">
    <Image Source="huge_image.png" Stretch="None"/>
</ScrollViewer>
ScrollViewer 안에서 Grid Height="*"는 사고를 부른다 ScrollViewer는 자식에게 무한 공간을 준다. 그 안의 * 행은 0이 되거나 무한이 되어 의도와 다르게 동작한다. 스크롤이 필요한 영역은 Auto 행에 넣어야 한다.

Viewbox — 자식 전체를 등비 확대/축소

<!-- 자식 트리 전체를 부모 크기에 맞춰 비례 스케일 -->
<Viewbox Stretch="Uniform">
    <Canvas Width="800" Height="600">
        <!-- 800x600 가상 캔버스에 그려도 윈도우 크기에 맞춰 줄어든다 -->
    </Canvas>
</Viewbox>

패널 중첩

패널은 중첩해서 복잡한 레이아웃을 만든다. 실무 화면은 거의 항상 DockPanel 안에 Grid, Grid 안에 StackPanel이 들어가는 식이다.

<DockPanel>
    <Menu DockPanel.Dock="Top">
        <MenuItem Header="File"/>
        <MenuItem Header="View"/>
    </Menu>
    <StatusBar DockPanel.Dock="Bottom">
        <TextBlock Text="Ready"/>
    </StatusBar>

    <Grid>
        <Grid.ColumnDefinitions>
            <ColumnDefinition Width="240"/>
            <ColumnDefinition Width="*"/>
            <ColumnDefinition Width="280"/>
        </Grid.ColumnDefinitions>

        <!-- 좌: 도구 목록 (StackPanel) -->
        <StackPanel Grid.Column="0" Margin="8">
            <TextBlock Text="Tools" FontWeight="Bold"/>
            <ListBox ItemsSource="{Binding Tools}"/>
        </StackPanel>

        <!-- 중: 영상 (Border + ScrollViewer + Image) -->
        <Border Grid.Column="1" BorderBrush="#CBD5E1" BorderThickness="1">
            <ScrollViewer>
                <Image Source="{Binding CurrentFrame}" Stretch="None"/>
            </ScrollViewer>
        </Border>

        <!-- 우: 파라미터 (Grid + SharedSizeGroup) -->
        <StackPanel Grid.Column="2" Grid.IsSharedSizeScope="True" Margin="8">
            <TextBlock Text="Parameters" FontWeight="Bold"/>
            <!-- 라벨/값 행들이 여기 들어간다 -->
        </StackPanel>
    </Grid>
</DockPanel>

성능과 가상화

WPF의 시각 트리(Visual Tree)는 깊을수록 Measure/Arrange 비용이 커진다. 수천 개 항목을 화면에 한 번에 띄우면 프레임이 떨어진다. 해법은 두 가지다.

1) 트리 깊이를 낮춘다

의미 없는 중첩 패널을 줄인다. Border 안 Grid 안 StackPanel 안 TextBlock처럼 한 줄을 위해 네 단계를 쌓지 않는다.

2) 가상화 — VirtualizingStackPanel

ItemsControl·ListBox·DataGrid 등은 기본적으로 화면에 보이는 항목만 만들고 스크롤될 때 재활용한다. 단, ScrollViewer 안에 넣거나 ItemsPanel을 직접 바꾸면 가상화가 깨질 수 있다.

<ListBox ItemsSource="{Binding LogEntries}"
         VirtualizingPanel.IsVirtualizing="True"
         VirtualizingPanel.VirtualizationMode="Recycling"
         ScrollViewer.CanContentScroll="True">
    <ListBox.ItemsPanel>
        <ItemsPanelTemplate>
            <VirtualizingStackPanel/>
        </ItemsPanelTemplate>
    </ListBox.ItemsPanel>
</ListBox>
가상화를 깨는 흔한 패턴 ItemsPanel을 StackPanel(가상화 없는 버전)이나 WrapPanel로 바꾸면 모든 항목이 생성된다. ScrollViewer.CanContentScroll="False"(픽셀 단위 스크롤)도 가상화를 깬다.

산업 비전 UI 적용

검사 SW의 메인 화면은 거의 동일한 골격이다. 좌측 사이드바(도구·검사 트리), 중앙 영상, 우측 파라미터 패널, 상단 메뉴, 하단 상태바. 이 구성은 DockPanel로 골격을 잡고 가운데를 Grid로 3분할하는 것이 표준이다.

전형적 검사 SW 화면 골격
<Window x:Class="Inspector.MainWindow"
        Title="Inspector" Width="1280" Height="800">
    <DockPanel>
        <Menu DockPanel.Dock="Top">
            <MenuItem Header="File">
                <MenuItem Header="Open Recipe..."/>
                <MenuItem Header="Save Recipe"/>
            </MenuItem>
            <MenuItem Header="Run"/>
        </Menu>

        <StatusBar DockPanel.Dock="Bottom">
            <TextBlock Text="{Binding StatusText}"/>
            <Separator/>
            <TextBlock Text="{Binding Fps, StringFormat='FPS: {0:F1}'}"/>
        </StatusBar>

        <Grid>
            <Grid.ColumnDefinitions>
                <ColumnDefinition Width="240" MinWidth="180"/>
                <ColumnDefinition Width="*"/>
                <ColumnDefinition Width="280" MinWidth="220"/>
            </Grid.ColumnDefinitions>

            <!-- 좌: 검사 도구 트리 -->
            <Border Grid.Column="0" BorderBrush="#CBD5E1" BorderThickness="0,0,1,0">
                <TreeView ItemsSource="{Binding InspectionTools}"/>
            </Border>

            <!-- 중: 영상 영역. Canvas 위에 ROI/오버레이 노드 -->
            <Border Grid.Column="1" Background="#1E293B">
                <Grid>
                    <Image Source="{Binding CurrentFrame}" Stretch="Uniform"/>
                    <ItemsControl ItemsSource="{Binding Overlays}">
                        <ItemsControl.ItemsPanel>
                            <ItemsPanelTemplate>
                                <Canvas/>
                            </ItemsPanelTemplate>
                        </ItemsControl.ItemsPanel>
                    </ItemsControl>
                </Grid>
            </Border>

            <!-- 우: 파라미터 -->
            <Border Grid.Column="2" BorderBrush="#CBD5E1" BorderThickness="1,0,0,0">
                <ScrollViewer>
                    <StackPanel Margin="8" Grid.IsSharedSizeScope="True">
                        <TextBlock Text="Camera" FontWeight="Bold" Margin="0,0,0,6"/>
                        <!-- 파라미터 행들 ... -->
                    </StackPanel>
                </ScrollViewer>
            </Border>
        </Grid>
    </DockPanel>
</Window>

중앙 영상 위에 Canvas를 겹쳐 ROI 박스, 결과 라벨, 측정 선을 오버레이한다. 데이터 플로우 블록 에디터도 같은 구조에서 Canvas 위에 노드와 연결선을 얹는 형태로 확장된다.

흔한 함정

증상원인해결
스크롤이 안 된다ScrollViewer 안 Grid * 행스크롤 대상은 Auto 행
StackPanel 자식 Height가 무시StackPanel은 무한 공간Grid로 교체
DockPanel 마지막 자식이 안 채워짐LastChildFill 미설정 / 마지막에 Dock 명시LastChildFill="True", 마지막 자식엔 Dock 빼기
Canvas 자식이 보이지 않음Canvas.Left/Top 미설정둘 다 명시 (기본 0)
리스트가 수천 개에서 끊긴다가상화 깨짐VirtualizingStackPanel 유지, ItemsPanel 변경 주의
요소가 겹친다Margin 음수 사용음수 Margin은 피하고 패널 구조 재검토
Canvas로 모든 레이아웃을 짜지 말 것 Canvas는 절대 좌표라 창 크기가 바뀌면 깨진다. 자유 배치가 본질적으로 필요한 영역(블록 에디터, ROI 오버레이)에서만 쓰고, 일반 화면 골격은 Grid·DockPanel로 짜야 한다.
Margin 음수는 마지막 수단 Margin="-4,0,0,0"은 임시방편으로 작동하지만 부모의 클립 영역을 벗어나 그려져 다른 패널과 충돌한다. 보통은 잘못 짜인 중첩의 신호다.
