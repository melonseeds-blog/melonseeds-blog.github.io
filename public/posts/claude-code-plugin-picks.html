플러그인과 마켓플레이스

Claude Code 플러그인은 슬래시 명령·스킬·서브에이전트·훅·MCP 서버를 하나로 묶어 배포하는 패키지다. 예전에는 이런 확장을 손으로 하나씩 설정해야 했지만, 2026년 정식 마켓플레이스가 열리면서 명령 한 줄로 설치하고 관리할 수 있게 됐다.

Anthropic이 관리하는 공식 마켓플레이스에는 백 개가 넘는 플러그인이 있다. 크게 두 갈래다 — Anthropic이 직접 만든 공식 플러그인(디자인·개발 워크플로·언어 서버 등)과, 여러 회사가 제공하는 파트너 플러그인(GitHub·Playwright·Figma·Vercel·Sentry·Supabase 등)이다.

플러그인 ≠ MCP 서버 헷갈리기 쉬운데, MCP 서버는 "외부 도구·데이터에 연결"하는 한 조각이고,
플러그인은 그 MCP를 포함해 스킬·명령·훅까지 묶은 더 큰 단위다.
구조가 궁금하면 Claude Code를 구조로 이해하기를 함께 보면 좋다.

설치·관리하는 법

플러그인은 슬래시 명령으로 설치·관리한다. 대략 이런 흐름이다(명령 문법은 버전에 따라 다를 수 있으니 공식 문서를 함께 확인한다).

# 마켓플레이스 추가(공식 디렉터리)
/plugin marketplace add anthropics/claude-plugins-official

# 플러그인 설치
/plugin install frontend-design

# 설치된 플러그인 관리(켜기/끄기/삭제)
/plugin

설치하면 그 플러그인이 제공하는 스킬·명령이 바로 쓸 수 있는 상태가 된다. 예를 들어 frontend-design을 깔면 UI를 만들 때 그 스킬이 자동으로 개입한다.

디자인 — frontend-design

frontend-design 공식

가장 널리 설치된 축에 드는 대표 플러그인이다. Claude가 UI를 만들 때 "어디서 본 듯한 밋밋한 결과(AI slop)"에 머무르지 않고, 또렷한 타이포그래피·과감한 색·분위기 있는 디테일로 밀어붙이게 유도한다. React·Vue·Svelte는 물론 순수 HTML/CSS까지 다룬다.

언제 좋은가 — 새 화면·랜딩·대시보드처럼 "그럴듯함"을 넘어 인상을 남기고 싶을 때. 디자이너 없이 프런트를 빠르게 뽑아야 할 때.

왜 이게 인기인가 AI로 만든 UI가 다 비슷비슷해 보이는 문제를 정면으로 겨냥했기 때문이다. 같은 프롬프트라도 이 플러그인이 있으면 기본값스럽지 않은 선택(폰트·팔레트·모션)을 하도록 방향을 잡아 준다.

개발 워크플로 플러그인

Anthropic이 공식으로 내놓은 개발 흐름 도우미들이다. 대부분 무난하게 신뢰할 수 있어 먼저 깔아 볼 만하다.

feature-dev 공식

요구사항에서 구현까지 이어지는 기능 개발 흐름을 정형화한다. 계획 → 구현 → 점검의 단계를 잡아 주어, 큰 작업을 덩어리로 몰아치지 않게 한다.

code-review 공식

변경분(diff)을 대상으로 버그·개선점을 리뷰한다. 커밋·PR 전에 한 번 돌려 보면 놓친 부분을 잡아낸다.

security-guidance 공식

코드 편집·커밋을 실시간으로 보며 SQL 인젝션·명령 주입·하드코딩된 키 같은 위험 패턴을 자동으로 짚어 준다. 보안 감이 부족한 팀에 특히 유용하다.

commit-commands 공식

커밋 메시지 작성·정리 같은 반복 커밋 작업을 명령으로 묶어 준다. 컨벤션을 지키기 쉬워진다.

Chrome DevTools 연동

다소 저평가된 유용템. 로그인된 크롬 세션으로 네트워크 요청·콘솔 에러를 들여다보며 라이브 페이지를 디버깅한다. 프런트 문제 추적에 강하다.

외부 연동 플러그인

여러 회사가 제공하는 파트너 플러그인은 Claude를 자기 서비스에 붙여 준다. 쓰는 도구가 있으면 그에 맞춰 골라 깐다.

플러그인무엇을 이어 주나
GitHub이슈·PR·리포 조작
Playwright브라우저 자동화·E2E 테스트
Figma디자인 파일·컴포넌트 참조
Vercel배포·프리뷰 관리
Sentry에러·이슈 추적 연동
SupabaseDB·인증 백엔드 조작

이 외에도 Linear·Stripe·Firebase 등 파트너 목록은 계속 늘고 있다. 목록·최신 현황은 공식 마켓플레이스에서 확인한다.

고르는 법

  • 필요한 것만 — 많이 깐다고 좋아지지 않는다. 스킬·명령이 늘수록 모델이 판단할 게 많아진다. 실제 반복되는 마찰이 있는 영역부터 하나씩 깐다.
  • 공식·파트너 우선 — 플러그인은 내 코드·계정에 접근할 수 있다. 출처가 분명한 공식/파트너 플러그인을 먼저 고르고, 서드파티는 게시자·인기도를 확인한다.
  • 먼저 깔 만한 것 — 프런트가 잦으면 frontend-design, 리뷰 습관을 들이려면 code-review, 보안이 걱정이면 security-guidance. 여기서 시작해 넓혀 간다.
  • 버전 변동에 유의 — 마켓플레이스·플러그인·명령 문법은 빠르게 바뀐다. 이름·설치법은 공식 문서와 마켓플레이스에서 최신을 확인한다.
