워프 복습과 lane 번호

7편에서 본 것처럼 GPU는 스레드 32개를 묶은 워프(warp) 단위로 명령을 실행한다. 워프 안에서 각 스레드의 위치를 lane이라고 부르며, 0~31 값을 갖는다. 1차원 블록에서는 다음처럼 계산한다.

int lane   = threadIdx.x & 31;   // same as threadIdx.x % 32
int warpId = threadIdx.x >> 5;   // same as threadIdx.x / 32

// 2D block: flatten first
int linear = threadIdx.y * blockDim.x + threadIdx.x;
int lane2d = linear & 31;

13편과 14편에서 리덕션과 스캔의 마지막 단계를 shuffle로 처리했다. shuffle은 워프 안의 스레드끼리 레지스터 값을 직접 주고받는 명령이다. shared memory를 거치지 않으므로 다음 장점이 있다.

항목shared memory로 교환shuffle로 교환
명령 수쓰기 + 동기화 + 읽기명령 1개
동기화__syncthreads() 또는 __syncwarp() 필요명령 자체에 포함 (_sync)
shared memory 사용량배열 크기만큼0 (점유율에 유리)
뱅크 충돌접근 방식에 따라 생김없음
교환 범위블록 전체워프 안 (32개)

shuffle 함수 4종

모든 shuffle 함수는 "각 lane이 어느 lane의 값을 읽을지"만 다르다. 값을 보내는 쪽이 아니라 받는 쪽 기준으로 생각하면 헷갈리지 않는다.

함수lane i가 읽는 값주로 쓰는 곳
__shfl_sync(mask, v, src)lane src의 v방송(broadcast), 임의 순서 교환
__shfl_up_sync(mask, v, d)lane i - d의 v (i < d면 자기 값 그대로)스캔, 왼쪽 이웃 읽기
__shfl_down_sync(mask, v, d)lane i + d의 v (범위를 넘으면 자기 값 그대로)리덕션, 오른쪽 이웃 읽기
__shfl_xor_sync(mask, v, m)lane i ^ m의 v모든 lane이 결과를 갖는 리덕션 (butterfly)
shuffle은 받는 쪽 기준으로 "누구의 값을 읽는가"가 다르다

인자 정리

인자의미
mask이 명령에 참여하는 lane의 비트 마스크. 워프 전체면 0xffffffff
v주고받을 값. int, unsigned, long long, float, double, half 등. 구조체는 멤버마다 따로 shuffle
src / d / m읽을 lane 번호, 거리, XOR 마스크
width (선택)워프를 width개씩 나눠 그 안에서만 교환. 2의 거듭제곱, 기본값 32
_sync 없는 옛 함수 CUDA 9 이전 자료에는 __shfl_down(v, d)처럼 mask가 없는 함수가 나온다. 이 함수들은 CUDA 9에서 사용 중단되었고 Volta(compute capability 7.0) 이상에서는 쓸 수 없다. 옛 코드를 가져올 때는 반드시 _sync 버전으로 바꾼다.

mask의 의미와 분기 안에서 쓰기

mask는 "이 명령을 함께 실행하는 lane 목록"이다. Volta 이후 GPU는 워프 안의 스레드도 분기마다 따로 진행할 수 있어서(independent thread scheduling), shuffle을 실행하기 전에 mask에 적힌 lane들이 모두 그 지점에 도착할 때까지 맞춰 준다. mask에 적힌 lane이 실제로 그 명령에 도착하지 않으면 결과가 정의되지 않는다.

// OK: every lane of the warp reaches this line
float total = WarpReduceSum(v);            // uses 0xffffffff inside

// WRONG: only some lanes enter the branch but mask says "all 32"
if (v > 0.0f)
    v += __shfl_down_sync(0xffffffff, v, 1);   // undefined result

// OK: compute the mask of lanes that take the branch, before branching
unsigned m = __ballot_sync(0xffffffff, v > 0.0f);
if (v > 0.0f)
    v += __shfl_down_sync(m, v, 1);        // only participating lanes in the mask
                                           // (source lane must also be in m)

가장 안전한 방법은 shuffle을 분기 밖에서 모든 lane이 실행하게 하고, 결과를 쓸지 말지만 분기로 정하는 것이다. 배열 끝을 넘는 스레드도 return하지 말고 0 같은 항등원을 들고 shuffle에 참여시킨다.

__global__ void SumKernel(const float* in, float* out, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    // do NOT "if (i >= n) return;" here - those lanes are needed by the shuffle
    float v = (i < n) ? in[i] : 0.0f;
    v = WarpReduceSum(v);
    if ((threadIdx.x & 31) == 0) atomicAdd(out, v);
}

워프 리덕션 두 가지 - down과 xor

13편에서 쓴 __shfl_down_sync 리덕션은 결과가 lane 0에만 남는다. 모든 lane이 결과를 알아야 하면(예: 평균을 구한 뒤 각자 자기 값에서 빼기) __shfl_xor_sync를 쓴다.

// result only in lane 0
__device__ __forceinline__ float WarpSumToLane0(float v)
{
    for (int o = 16; o > 0; o >>= 1)
        v += __shfl_down_sync(0xffffffff, v, o);
    return v;
}

// result in all 32 lanes (butterfly / all-reduce)
__device__ __forceinline__ float WarpSumAll(float v)
{
    for (int m = 16; m > 0; m >>= 1)
        v += __shfl_xor_sync(0xffffffff, v, m);
    return v;
}

// example: subtract the warp mean from each value, no shared memory at all
__global__ void CenterPerWarp(float* data)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    float v = data[i];
    float mean = WarpSumAll(v) / 32.0f;
    data[i] = v - mean;
}

xor 방식에서 lane 0의 값 변화를 따라가 보면, m=16일 때 lane 16의 값을, m=8일 때 lane 8(이 시점에 lane 8+24 합을 가진)의 값을 더하는 식으로 5단계 만에 32개 전체 합을 갖게 된다. 모든 lane이 대칭으로 같은 일을 하므로 마지막에 모두 같은 값을 갖는다.

방송과 이웃 값 읽기

방송 (broadcast)

한 lane만 계산한 값을 워프 전체에 나눠 줄 때 쓴다. 대표 lane 하나가 atomicAdd로 출력 위치를 받아 오고 나머지에게 알려 주는 경우가 대표적이다.

int lane = threadIdx.x & 31;
int base = 0;
if (lane == 0)
    base = atomicAdd(&globalCounter, 32);        // reserve 32 slots for the whole warp
base = __shfl_sync(0xffffffff, base, 0);         // everyone gets lane 0's value
output[base + lane] = myValue;

1차원 필터 - shared memory 없이 이웃 읽기

가로 방향 3탭 필터처럼 바로 옆 픽셀만 필요하면 shuffle로 이웃 값을 받아 올 수 있다. 워프 경계에 있는 lane 0과 lane 31은 이웃이 다른 워프에 있으므로 global memory에서 직접 읽는다.

// out[x] = 0.25*in[x-1] + 0.5*in[x] + 0.25*in[x+1]   (one row, clamp at borders)
__global__ void Blur3Row(const float* in, float* out, int width)
{
    int x    = blockIdx.x * blockDim.x + threadIdx.x;
    int lane = threadIdx.x & 31;
    int xc   = min(x, width - 1);                     // keep all lanes alive for shuffles

    float c = in[xc];
    float l = __shfl_up_sync(0xffffffff, c, 1);       // value of lane-1
    float r = __shfl_down_sync(0xffffffff, c, 1);     // value of lane+1

    if (lane == 0)  l = in[max(xc - 1, 0)];           // neighbour lives in another warp
    if (lane == 31) r = in[min(xc + 1, width - 1)];
    if (x == 0)         l = c;                        // image borders
    if (x == width - 1) r = c;

    if (x < width)
        out[x] = 0.25f * l + 0.5f * c + 0.25f * r;
}

이 방식은 32개 중 2개 lane만 global 메모리를 추가로 읽고, 나머지 이웃은 레지스터 교환으로 끝난다. 필터 반경이 커지면 경계 처리가 복잡해지므로, 반경이 2~3을 넘으면 6편의 shared memory 타일 방식이 더 깔끔하다.

투표 함수 - ballot, any, all

투표 함수는 워프의 각 lane이 낸 참/거짓을 모아 준다. shuffle이 값을 주고받는다면, 투표는 조건 결과를 32비트로 압축해서 돌려준다.

함수반환값
__ballot_sync(mask, pred)pred가 참인 lane의 비트가 1인 32비트 정수
__any_sync(mask, pred)하나라도 참이면 1
__all_sync(mask, pred)모두 참이면 1
__activemask()지금 이 코드를 실행 중인 lane의 마스크 (동기화는 하지 않음)
__popc(x)x에서 1인 비트 수
__ffs(x)가장 낮은 1 비트의 위치 + 1 (없으면 0)

워프 집계 atomic

임계값을 넘는 픽셀 수를 세는 커널을 생각해 보자. 픽셀마다 atomicAdd(&count, 1)을 하면 카운터 하나에 경합이 몰린다(14편). ballot으로 워프 안에서 먼저 세면 atomic이 워프당 1번으로 줄어든다.

__global__ void CountBright(const unsigned char* img, int n, unsigned char th, unsigned int* count)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    bool bright = (i < n) && (img[i] > th);

    unsigned int votes = __ballot_sync(0xffffffff, bright);   // bit k = lane k is bright
    if ((threadIdx.x & 31) == 0 && votes != 0)
        atomicAdd(count, __popc(votes));                       // one atomic per warp
}

compaction에도 쓸 수 있다. 각 lane은 "나보다 낮은 번호 lane 중 조건을 만족한 수"를 알면 워프 안에서 자기 출력 위치를 정할 수 있다. 이것은 ballot 결과에서 자기보다 아래 비트만 남기고 세면 된다.

unsigned int votes = __ballot_sync(0xffffffff, keep);
int lane = threadIdx.x & 31;
unsigned int lowerMask = (1u << lane) - 1u;          // bits of lanes below me
int myOffset = __popc(votes & lowerMask);            // warp-level exclusive scan of flags
int warpCount = __popc(votes);

int base = 0;
if (lane == 0 && warpCount > 0) base = atomicAdd(&outCount, warpCount);
base = __shfl_sync(0xffffffff, base, 0);
if (keep) out[base + myOffset] = value;

같은 값끼리 묶기 - __match_any_sync

compute capability 7.0 이상에서는 __match_any_sync(mask, value)가 "나와 같은 값을 가진 lane들의 마스크"를 돌려준다. 히스토그램에서 같은 bin을 가진 lane끼리 묶고 대표 lane 하나만 atomic을 실행하면 경합이 크게 준다.

unsigned int bin    = img[i];
unsigned int peers  = __match_any_sync(0xffffffff, bin);   // lanes with the same bin
int leader = __ffs(peers) - 1;                              // lowest lane in the group
if ((threadIdx.x & 31) == leader)
    atomicAdd(&localHist[bin], __popc(peers));              // one atomic per distinct bin

Cooperative Groups 기본

지금까지는 "워프는 32개", "lane은 threadIdx.x & 31", "mask는 0xffffffff"를 손으로 계산했다. Cooperative Groups(CUDA 9부터)는 스레드 묶음을 객체로 다루게 해서, 이런 계산과 동기화를 명시적으로 쓰게 해 준다.

#include <cooperative_groups.h>
#include <cooperative_groups/reduce.h>     // cg::reduce (CUDA 11+)
namespace cg = cooperative_groups;

__global__ void SumCg(const float* in, float* out, int n)
{
    cg::thread_block block = cg::this_thread_block();             // whole block
    cg::thread_block_tile<32> warp = cg::tiled_partition<32>(block); // one warp

    int i = block.group_index().x * block.size() + block.thread_rank();
    float v = (i < n) ? in[i] : 0.0f;

    v = cg::reduce(warp, v, cg::plus<float>());   // warp reduction in one call
    if (warp.thread_rank() == 0)
        atomicAdd(out, v);
}
Cooperative Groups예전 방식
block.sync()__syncthreads()
block.thread_rank()threadIdx를 1차원으로 편 값
warp.thread_rank()threadIdx.x & 31
warp.meta_group_rank()threadIdx.x >> 5 (블록 안 워프 번호)
warp.shfl_down(v, o)__shfl_down_sync(0xffffffff, v, o)
warp.ballot(p), warp.any(p)__ballot_sync, __any_sync
cg::reduce(warp, v, op)shuffle 반복문
cg::inclusive_scan(warp, v) (cooperative_groups/scan.h)14편의 WarpInclusiveScan

워프보다 작은 묶음

tiled_partition<16>, <8>, <4>처럼 워프를 더 작게 나눌 수 있다. 예를 들어 픽셀 하나의 RGBA 4채널을 lane 4개가 나눠 처리하거나, 3×3 같은 작은 단위 계산에 lane 8~16개를 묶을 때 유용하다. 타일 안에서의 shuffle, 리덕션이 그 타일 범위로 자동 제한된다.

auto tile4 = cg::tiled_partition<4>(cg::this_thread_block());
float channelSum = cg::reduce(tile4, myChannelValue, cg::plus<float>());  // sum over 4 lanes

분기 안의 묶음 - coalesced_threads

분기 안에서 지금 함께 실행 중인 스레드만 묶고 싶으면 cg::coalesced_threads()를 쓴다. mask를 직접 계산하지 않아도 되므로 앞의 "분기 안 shuffle" 문제를 깔끔하게 풀 수 있다.

if (bright)
{
    cg::coalesced_group active = cg::coalesced_threads();   // lanes that took this branch
    unsigned int base = 0;
    if (active.thread_rank() == 0)
        base = atomicAdd(&outCount, active.size());          // reserve slots for the group
    base = active.shfl(base, 0);                             // broadcast inside the group
    out[base + active.thread_rank()] = i;
}

그리드 전체 동기화

Cooperative Groups의 가장 큰 기능은 그리드 전체 동기화다. 원래 CUDA에서 블록끼리 맞추는 유일한 방법은 커널을 끝내고 새로 실행하는 것이었다. cg::this_grid().sync()를 쓰면 커널 하나 안에서 "모든 블록이 여기까지 왔다"를 보장할 수 있다. 13편의 두 번 실행 리덕션을 커널 하나로 만들 수 있다.

__global__ void ReduceOneKernel(const float* in, float* partial, float* out, int n)
{
    cg::grid_group grid = cg::this_grid();

    float sum = 0.0f;
    for (int i = grid.thread_rank(); i < n; i += grid.size())
        sum += in[i];
    sum = BlockReduceSum(sum);                     // from part 13
    if (threadIdx.x == 0) partial[blockIdx.x] = sum;

    grid.sync();                                   // every block has written its partial

    if (blockIdx.x == 0)
    {
        float v = 0.0f;
        for (int b = threadIdx.x; b < gridDim.x; b += blockDim.x)
            v += partial[b];
        v = BlockReduceSum(v);
        if (threadIdx.x == 0) *out = v;
    }
}

대신 실행 방법과 조건이 까다롭다.

// 1) the device must support cooperative launch
int supported = 0;
cudaDeviceGetAttribute(&supported, cudaDevAttrCooperativeLaunch, dev);

// 2) all blocks must be resident at the same time -> limit the grid size
int blocksPerSM = 0, numSMs = 0;
cudaOccupancyMaxActiveBlocksPerMultiprocessor(&blocksPerSM, ReduceOneKernel, 256, 0);
cudaDeviceGetAttribute(&numSMs, cudaDevAttrMultiProcessorCount, dev);
dim3 grid(blocksPerSM * numSMs), block(256);

// 3) launch with the cooperative API, not <<< >>>
void* args[] = { &d_in, &d_partial, &d_out, &n };
cudaLaunchCooperativeKernel((void*)ReduceOneKernel, grid, block, args, 0, stream);
조건이유
모든 블록이 동시에 GPU에 올라가 있어야 함먼저 끝난 블록이 아직 시작도 못 한 블록을 기다리면 영원히 멈춤. 그래서 그리드 크기를 점유율 계산으로 제한
cudaLaunchCooperativeKernel로 실행<<< >>>로 실행하면 grid.sync()가 동작하지 않음 (오류 또는 멈춤)
장치가 지원해야 함Pascal 이후 GPU 대부분이 지원하지만 드라이버 모드나 환경에 따라 다를 수 있으므로 위 속성 값으로 확인
언제 쓰는가 반복 계산(예: 반복 솔버, 여러 단계를 거치는 작은 그래프 알고리즘)처럼 단계마다 커널을 다시 실행하는 비용이 계산보다 클 때 효과가 있다. 일반 영상 처리처럼 커널 하나가 충분히 큰 일을 하면 커널을 나눠 실행해도 손해가 적고 코드가 단순하다. 오래된 CUDA 버전에서는 grid.sync()에 -rdc=true 빌드 옵션이 필요했으므로, 예전 자료를 볼 때 참고한다.

흔한 함정

shuffle 전에 return if (i >= n) return; 뒤에 0xffffffff mask로 shuffle을 하면, 마지막 워프에서 빠진 lane 때문에 결과가 정의되지 않는다. 범위 밖 스레드도 항등원을 들고 shuffle에 참여시킨다.
블록 크기가 32의 배수가 아님 블록 크기가 100이면 마지막 워프는 lane 4개뿐이다. 이 워프에서 0xffffffff mask를 쓰면 없는 lane을 기다리게 된다. 블록 크기는 항상 32의 배수로 잡는다.
source lane이 mask에 없음 부분 mask를 쓸 때, 값을 읽어 올 lane도 mask에 포함되어 있어야 한다. 읽어 올 lane이 빠져 있으면 그 값은 정의되지 않는다.
grid.sync()를 일반 실행으로 호출 <<<grid, block>>>로 실행한 커널에서 grid.sync()를 부르면 동작하지 않는다. 또 그리드 크기를 점유율 한도보다 크게 잡으면 cooperative 실행 자체가 실패한다(cudaErrorCooperativeLaunchTooLarge). 반환값을 반드시 확인한다.

정리

하고 싶은 일쓸 함수
워프 합계 (lane 0에만)__shfl_down_sync 반복, 또는 cg::reduce
워프 합계 (모든 lane에)__shfl_xor_sync 반복
워프 스캔__shfl_up_sync 반복, 또는 cg::inclusive_scan
한 lane 값을 모두에게__shfl_sync(mask, v, src)
조건 만족 개수, 위치__ballot_sync + __popc
같은 값끼리 묶기__match_any_sync (cc 7.0+)
분기 안 협력cg::coalesced_threads()
블록 사이 동기화cg::this_grid().sync() + cooperative 실행

13~15편은 커널 안의 계산 패턴을 다뤘다. 다음 편부터는 커널 바깥, 즉 메모리 관리와 실행 방식으로 넘어간다. 16편은 CPU와 GPU가 포인터 하나를 같이 쓰는 Unified Memory를 깊이 본다.
