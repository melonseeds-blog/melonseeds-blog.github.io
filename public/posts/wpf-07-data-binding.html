데이터 바인딩이란?

데이터 바인딩은 UI 요소(Target)와 데이터 객체(Source)를 연결해 한쪽이 바뀌면 다른 쪽이 자동으로 갱신되도록 하는 메커니즘이다. 코드 비하인드에서 textBox.Text = model.Name; 같은 동기화 코드를 직접 작성할 필요가 없어진다.

Source ↔ Binding ↔ Target — 바인딩은 두 객체를 잇는 다리

MVVM 패턴(9편)에서 ViewModel과 View를 분리할 수 있는 것도 결국 이 바인딩 덕분이다. View는 ViewModel의 속성에 바인딩만 걸어두고, 비즈니스 로직은 ViewModel에 둔다.

Binding 기본 문법

XAML에서는 마크업 확장 {Binding ...}으로 바인딩을 선언한다.

<!-- Path는 생략 가능 (기본 인자) -->
<TextBlock Text="{Binding Path=UserName}" />
<TextBlock Text="{Binding UserName}" />

<!-- 중첩 속성 -->
<TextBlock Text="{Binding Person.Address.City}" />

<!-- 컬렉션 인덱스 -->
<TextBlock Text="{Binding Items[0].Name}" />

<!-- 현재 DataContext 자체에 바인딩 -->
<TextBlock Text="{Binding}" />

Source가 명시되지 않으면 WPF는 자동으로 그 요소의 DataContext를 Source로 사용한다.

DataContext 흐름

DataContext는 비주얼 트리를 따라 상속된다. 부모에 한 번 설정하면 자식들은 모두 같은 DataContext를 사용한다.

<Window x:Class="App.MainWindow">
    <Window.DataContext>
        <local:MainViewModel />
    </Window.DataContext>

    <StackPanel>
        <!-- 모두 MainViewModel을 Source로 사용 -->
        <TextBlock Text="{Binding Title}" />
        <TextBox  Text="{Binding UserName}" />
        <Button   Content="{Binding ButtonLabel}" />
    </StackPanel>
</Window>

다른 Source 지정 방법

<!-- ElementName: x:Name으로 이름 붙인 다른 요소 참조 -->
<Slider x:Name="zoomSlider" Minimum="0.1" Maximum="4" Value="1" />
<TextBlock Text="{Binding ElementName=zoomSlider, Path=Value}" />

<!-- RelativeSource: 비주얼 트리 상대 참조 -->
<TextBlock Text="{Binding RelativeSource={RelativeSource Self}, Path=Tag}" />
<TextBlock Text="{Binding RelativeSource={RelativeSource AncestorType=Window}, Path=Title}" />

<!-- StaticResource: 리소스 객체 참조 -->
<Window.Resources>
    <local:Settings x:Key="settings" />
</Window.Resources>
<TextBlock Text="{Binding Source={StaticResource settings}, Path=Theme}" />
우선순위 Binding은 Source → ElementName → RelativeSource → DataContext 순으로 Source를 결정한다. 위 3개가 모두 없으면 DataContext가 쓰인다.

바인딩 모드 (Mode)

Source와 Target 사이의 데이터 흐름 방향을 결정한다.

Mode흐름대표 사용처
OneWaySource → TargetTextBlock처럼 표시만 하는 컨트롤
TwoWaySource ↔ TargetTextBox, CheckBox, Slider 등 입력 컨트롤
OneTimeSource → Target (한 번만)한 번 표시 후 변하지 않는 값(로고 텍스트 등)
OneWayToSourceTarget → Source드물게 사용 — Target 값을 Source에 역으로 기록할 때
Default컨트롤 기본값지정하지 않으면 이 값. TextBox.Text는 TwoWay, TextBlock.Text는 OneWay가 기본
<TextBox Text="{Binding UserName, Mode=TwoWay}" />
<TextBlock Text="{Binding UserName, Mode=OneWay}" />
<TextBlock Text="{Binding Version, Mode=OneTime}" />
대부분 Mode는 생략해도 된다 컨트롤마다 합리적인 기본값이 설정돼 있다. Slider.Value, CheckBox.IsChecked는 기본 TwoWay, TextBlock.Text는 기본 OneWay다.

INotifyPropertyChanged

Source 객체가 값이 바뀐 사실을 UI에 알리려면 INotifyPropertyChanged(이하 INPC)를 구현해야 한다. PropertyChanged 이벤트를 발생시키면 바인딩 시스템이 이를 감지하고 Target을 갱신한다.

using System.ComponentModel;
using System.Runtime.CompilerServices;

public class UserViewModel : INotifyPropertyChanged
{
    private string _userName;

    public string UserName
    {
        get => _userName;
        set
        {
            if (_userName == value) return;  // 동일 값이면 무시
            _userName = value;
            OnPropertyChanged();             // UI에 변경 알림
        }
    }

    public event PropertyChangedEventHandler PropertyChanged;

    // CallerMemberName으로 호출자 이름 자동 전달
    protected void OnPropertyChanged([CallerMemberName] string propertyName = null)
    {
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
    }
}

베이스 클래스로 추출

실무에서는 매번 위 보일러플레이트를 작성하지 않고, 베이스 클래스를 두고 상속한다.

public abstract class ObservableObject : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler PropertyChanged;

    protected void OnPropertyChanged([CallerMemberName] string name = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(name));

    // 값 비교 + set + 알림을 한 번에
    protected bool SetField<T>(ref T field, T value, [CallerMemberName] string name = null)
    {
        if (EqualityComparer<T>.Default.Equals(field, value)) return false;
        field = value;
        OnPropertyChanged(name);
        return true;
    }
}

public class InspectionViewModel : ObservableObject
{
    private int _passCount;
    public int PassCount
    {
        get => _passCount;
        set => SetField(ref _passCount, value);  // 한 줄!
    }
}
INPC를 구현하지 않으면 UI가 갱신되지 않는다 단순 public string Name { get; set; } 자동 속성은 값이 바뀌어도 PropertyChanged 이벤트를 발생시키지 않는다. 바인딩이 "안 먹는" 가장 흔한 원인 1순위다.

ObservableCollection<T>

일반 List<T>는 항목 추가/삭제를 UI에 알릴 수 없다. 컬렉션 변경을 자동으로 통지하려면 ObservableCollection<T>를 사용한다. 내부적으로 INotifyCollectionChanged를 구현하고 있다.

using System.Collections.ObjectModel;

public class InspectionListViewModel : ObservableObject
{
    public ObservableCollection<InspectionResult> Results { get; }
        = new ObservableCollection<InspectionResult>();

    public void AddResult(InspectionResult r)
    {
        Results.Add(r);   // ListView가 자동으로 새 행 추가
    }

    public void Clear()
    {
        Results.Clear();  // UI도 즉시 비워짐
    }
}
<ListView ItemsSource="{Binding Results}" />
UI 스레드 밖에서 수정하면 예외 발생 카메라 캡처 스레드처럼 백그라운드 스레드에서 Results.Add(...)를 호출하면 InvalidOperationException이 터진다. 반드시 Application.Current.Dispatcher.Invoke(...)로 UI 스레드에 마샬링하거나, .NET의 BindingOperations.EnableCollectionSynchronization으로 동기화 객체를 등록해야 한다.

컨버터 (IValueConverter)

Source 값을 Target 타입으로 변환할 때 사용한다. 가장 흔한 패턴은 bool → Visibility다.

using System.Globalization;
using System.Windows;
using System.Windows.Data;

public class BoolToVisibilityConverter : IValueConverter
{
    public object Convert(object value, Type targetType, object parameter, CultureInfo culture)
    {
        bool b = value is bool v && v;
        // parameter="Invert"면 반대로
        if ("Invert".Equals(parameter)) b = !b;
        return b ? Visibility.Visible : Visibility.Collapsed;
    }

    public object ConvertBack(object value, Type targetType, object parameter, CultureInfo culture)
        => value is Visibility vis && vis == Visibility.Visible;
}
<Window.Resources>
    <local:BoolToVisibilityConverter x:Key="BoolToVis" />
</Window.Resources>

<ProgressBar Visibility="{Binding IsBusy, Converter={StaticResource BoolToVis}}" />

<!-- ConverterParameter 사용 -->
<Button Content="시작"
        Visibility="{Binding IsBusy,
                     Converter={StaticResource BoolToVis},
                     ConverterParameter=Invert}" />
대표 컨버터 패턴변환용도
BoolToVisibilityConverterbool → Visibility로딩 인디케이터 표시·숨김
NullToVisibilityConverterobject → Visibilitynull이면 숨기기
InverseBoolConverterbool → boolIsEnabled 반전
EnumToStringConverterenum → string한글 라벨 표시
StatusToBrushConverterenum → BrushPass=초록 / Fail=빨강
.NET Core 3.0+ 내장 컨버터 BooleanToVisibilityConverter는 WPF 표준 제공이라 별도 구현 없이 바로 쓸 수 있다. 다만 Invert 옵션이 없어 커스텀이 자주 필요하다.

UpdateSourceTrigger · StringFormat

UpdateSourceTrigger

TwoWay/OneWayToSource 바인딩에서 언제 Source를 갱신할지 결정한다.

값갱신 시점비고
PropertyChangedTarget이 바뀔 때마다 즉시타이핑마다 ViewModel 갱신 (실시간 검증)
LostFocus포커스가 빠질 때TextBox.Text의 기본값
Explicit코드에서 UpdateSource() 호출 시저장 버튼 누를 때만 갱신
Default속성마다 정의된 기본값대부분 PropertyChanged
<!-- 한 글자 입력할 때마다 ViewModel 갱신 (검색창에 유용) -->
<TextBox Text="{Binding SearchKeyword,
                UpdateSourceTrigger=PropertyChanged}" />

<!-- 코드에서 명시적 호출 -->
<TextBox x:Name="amountBox"
         Text="{Binding Amount, UpdateSourceTrigger=Explicit}" />
// Explicit 모드일 때 직접 호출
var be = amountBox.GetBindingExpression(TextBox.TextProperty);
be?.UpdateSource();

StringFormat

숫자·날짜를 표시 형식으로 변환할 때 컨버터 없이 처리할 수 있다.

<!-- 통화 형식 -->
<TextBlock Text="{Binding Amount, StringFormat={}{0:C}}" />
<!-- → ￦1,234,567 -->

<!-- 소수점 자리수 -->
<TextBlock Text="{Binding Accuracy, StringFormat={}{0:F2}}" />
<!-- → 0.97 -->

<!-- 퍼센트 -->
<TextBlock Text="{Binding PassRate, StringFormat={}{0:P1}}" />
<!-- → 98.5% -->

<!-- 날짜 -->
<TextBlock Text="{Binding StartTime, StringFormat=yyyy-MM-dd HH:mm:ss}" />

<!-- 라벨 결합 -->
<TextBlock Text="{Binding ItemCount, StringFormat=총 {0}건}" />
{}{0:C} 앞의 빈 중괄호 XAML 마크업 확장 파서가 {0}을 다른 확장으로 오해하지 않도록 이스케이프하는 용도다. {로 시작하는 StringFormat에는 항상 {}를 앞에 붙여야 한다.

DataTemplate

객체 컬렉션을 화면에 표시할 때 각 객체를 어떤 UI로 렌더링할지 정의한다. ItemsControl, ListView, ListBox, ContentControl에서 사용한다.

<ListView ItemsSource="{Binding Results}">
    <ListView.ItemTemplate>
        <DataTemplate>
            <Border Padding="8" Margin="2" BorderBrush="#ccc" BorderThickness="1">
                <StackPanel Orientation="Horizontal">
                    <Ellipse Width="12" Height="12" Margin="0,0,8,0"
                             Fill="{Binding Status, Converter={StaticResource StatusToBrush}}" />
                    <TextBlock Text="{Binding Id}" FontWeight="Bold" Margin="0,0,12,0" />
                    <TextBlock Text="{Binding Defect}" Foreground="#555" Margin="0,0,12,0" />
                    <TextBlock Text="{Binding Score, StringFormat={}{0:F2}}" />
                </StackPanel>
            </Border>
        </DataTemplate>
    </ListView.ItemTemplate>
</ListView>

DataTemplate 내부에서 {Binding}은 컬렉션의 각 항목 객체를 가리킨다. 즉 DataContext가 항목 단위로 자동 설정된다.

바인딩 디버깅

바인딩은 컴파일 타임 검증이 안 된다. 오타로 잘못된 속성 이름을 쓰면 그냥 조용히 실패할 뿐 예외도 안 난다. 진단은 Visual Studio의 출력 창으로 한다.

// 디버그: 출력 → 출력 위치를 "디버그"로
// 다음과 같은 메시지 확인
//
// System.Windows.Data Error: 40 : BindingExpression path error:
//   'UserNmae' property not found on 'object' ''MainViewModel'
//   (HashCode=12345)'. BindingExpression:Path=UserNmae; DataItem='MainViewModel'
//   (HashCode=12345); target element is 'TextBlock' (Name=''); target property
//   is 'Text' (type 'String')

PresentationTraceSources로 특정 바인딩 추적

의심되는 바인딩 하나만 자세히 추적할 수 있다.

<Window xmlns:diag="clr-namespace:System.Diagnostics;assembly=WindowsBase">
    ...
    <TextBlock Text="{Binding UserName,
                       diag:PresentationTraceSources.TraceLevel=High}" />
</Window>

TraceLevel=High로 지정하면 해당 바인딩의 생성·Source 결정·값 변환 등 모든 단계가 출력 창에 찍힌다. 어디서 끊겼는지 단계별로 보인다.

Visual Studio의 라이브 시각적 트리 디버깅 중 디버그 → Windows → 라이브 시각적 트리를 켜면 실행 중인 UI 요소를 클릭해 그 요소의 DataContext와 바인딩 현황을 직접 볼 수 있다.

검사 UI 예시 — 실시간 결과 표시

지금까지 다룬 요소를 모은 검사 결과 ListView 예제다. 카메라가 한 장 찍을 때마다 InspectionResult가 한 줄 추가된다.

모델 (POCO + INPC)

public enum InspectionStatus { Pass, Fail, Pending }

public class InspectionResult : ObservableObject
{
    private InspectionStatus _status;
    public InspectionStatus Status
    {
        get => _status;
        set => SetField(ref _status, value);
    }

    public int Id { get; init; }
    public string Defect { get; init; }
    public double Score { get; init; }
    public DateTime Timestamp { get; init; }
}

ViewModel

public class InspectionViewModel : ObservableObject
{
    public ObservableCollection<InspectionResult> Results { get; }
        = new ObservableCollection<InspectionResult>();

    private int _passCount;
    public int PassCount
    {
        get => _passCount;
        private set => SetField(ref _passCount, value);
    }

    private int _failCount;
    public int FailCount
    {
        get => _failCount;
        private set => SetField(ref _failCount, value);
    }

    public double PassRate =>
        (PassCount + FailCount) == 0 ? 0.0
        : (double)PassCount / (PassCount + FailCount);

    public bool IsBusy { get; private set; }

    // 카메라 콜백에서 호출 — UI 스레드로 마샬링
    public void AddResult(InspectionResult r)
    {
        Application.Current.Dispatcher.Invoke(() =>
        {
            Results.Add(r);
            if (r.Status == InspectionStatus.Pass) PassCount++;
            else if (r.Status == InspectionStatus.Fail) FailCount++;
            OnPropertyChanged(nameof(PassRate));  // 파생 속성도 알림
        });
    }
}

View (XAML)

<Window x:Class="App.InspectionView"
        xmlns:local="clr-namespace:App">
    <Window.DataContext>
        <local:InspectionViewModel />
    </Window.DataContext>
    <Window.Resources>
        <local:StatusToBrushConverter   x:Key="StatusToBrush" />
        <local:BoolToVisibilityConverter x:Key="BoolToVis" />
    </Window.Resources>

    <DockPanel Margin="12">
        <!-- 상단 통계 -->
        <StackPanel DockPanel.Dock="Top" Orientation="Horizontal" Margin="0,0,0,10">
            <TextBlock Text="{Binding PassCount, StringFormat=Pass {0}}"
                       Foreground="Green" FontWeight="Bold" Margin="0,0,16,0" />
            <TextBlock Text="{Binding FailCount, StringFormat=Fail {0}}"
                       Foreground="Red"  FontWeight="Bold" Margin="0,0,16,0" />
            <TextBlock Text="{Binding PassRate, StringFormat=양품률 {0:P1}}" />
            <ProgressBar Width="80" Height="14" IsIndeterminate="True"
                         Margin="20,0,0,0"
                         Visibility="{Binding IsBusy, Converter={StaticResource BoolToVis}}" />
        </StackPanel>

        <!-- 결과 리스트 -->
        <ListView ItemsSource="{Binding Results}">
            <ListView.ItemTemplate>
                <DataTemplate>
                    <Border Padding="6" Margin="2"
                            BorderBrush="#ddd" BorderThickness="1">
                        <StackPanel Orientation="Horizontal">
                            <Ellipse Width="10" Height="10"
                                     Margin="0,0,8,0"
                                     Fill="{Binding Status,
                                            Converter={StaticResource StatusToBrush}}" />
                            <TextBlock Text="{Binding Id, StringFormat=#{0:D4}}"
                                       FontWeight="Bold" Width="60" />
                            <TextBlock Text="{Binding Defect}" Width="120" />
                            <TextBlock Text="{Binding Score, StringFormat={}{0:F3}}"
                                       Width="70" />
                            <TextBlock Text="{Binding Timestamp,
                                              StringFormat=HH:mm:ss.fff}"
                                       Foreground="#888" />
                        </StackPanel>
                    </Border>
                </DataTemplate>
            </ListView.ItemTemplate>
        </ListView>
    </DockPanel>
</Window>
동작 흐름
1. 카메라 콜백 스레드 → ViewModel.AddResult() 호출 2. Dispatcher.Invoke로 UI 스레드 진입 3. Results.Add() → ObservableCollection이 CollectionChanged 발생 4. ListView가 새 행 자동 추가, DataTemplate으로 렌더링 5. PassCount/FailCount setter → PropertyChanged 발생 → 상단 라벨 갱신 6. OnPropertyChanged("PassRate") → 양품률 라벨도 함께 갱신

흔한 함정

1. INPC 미구현으로 UI가 안 갱신된다 자동 속성 public string Name { get; set; }은 변경 알림을 보내지 않는다. 첫 화면 표시는 되지만 그 후 ViewModel에서 값을 바꿔도 UI는 그대로다. 항상 INPC + 베이스 클래스의 SetField를 쓰자.
2. UI 스레드 외에서 ObservableCollection 수정 백그라운드 스레드에서 Results.Add(...) 호출 시 NotSupportedException 또는 InvalidOperationException이 발생한다. Dispatcher.Invoke로 마샬링하거나 BindingOperations.EnableCollectionSynchronization으로 동기화 객체를 등록하자.
3. DataContext 누락 {Binding Name}이라고 썼는데 부모 어디에도 DataContext가 설정되어 있지 않으면 출력 창에 "Cannot find source" 같은 에러가 뜬다. 일반적으로 Window/UserControl 생성자에서 DataContext를 ViewModel로 지정한다.
4. OneTime인데 변경을 기대 Mode=OneTime은 첫 평가 후 바인딩을 끊어버린다. Source가 나중에 바뀌어도 Target은 그대로다. 변경을 반영하려면 OneWay로 바꾸고 Source에 INPC를 구현하자.
5. 정적(static) 속성 바인딩 WPF는 인스턴스 속성 중심이라 정적 속성 바인딩이 어색하다. x:Static이나 {Binding Source={x:Static ...}}로 가능하지만 정적 속성은 INPC를 구현하기 까다롭다. 가능하면 ViewModel 인스턴스 속성으로 노출하자.
6. 파생 속성 알림 누락 PassRate처럼 다른 속성에서 계산되는 값은 의존 속성이 바뀔 때 OnPropertyChanged(nameof(PassRate))를 명시적으로 호출해야 UI에 반영된다.
7. TextBox 입력 후 즉시 ViewModel 반영이 안 됨 TextBox.Text의 기본 UpdateSourceTrigger는 LostFocus다. 포커스를 잃기 전엔 ViewModel이 갱신되지 않는다. 실시간 반영이 필요하면 UpdateSourceTrigger=PropertyChanged를 명시하자.
