OpenCV DNN 모듈이란

11편에서 학습한 모델을 ONNX로 내보냈다. 그렇다면 그 모델을 실제 검사 소프트웨어에서 어떻게 실행하는가. 가장 손쉬운 답 하나가 OpenCV DNN 모듈이다. OpenCV 4.x에 기본 포함된 딥러닝 추론 전용 엔진으로, 별도의 딥러닝 프레임워크를 설치하지 않고도 C++ 코드에서 바로 모델을 돌릴 수 있다.

핵심 단어는 추론 전용이다. OpenCV DNN은 모델을 학습하지 못한다. 역전파도, 옵티마이저도, 손실 함수도 없다. 학습은 PyTorch나 TensorFlow에서 끝내고, 그 결과 가중치를 받아 순전파(forward pass)만 수행한다. 즉 "이미 다 만들어진 함수를 실행하는 도구"다.

왜 검사 SW에서 OpenCV DNN을 쓰는가

산업 검사 소프트웨어는 이미 OpenCV로 짜여 있는 경우가 대부분이다. 이미지 로딩, 전처리, 필터, 블롭 분석, 측정이 전부 cv::Mat 위에서 돈다. 여기에 딥러닝 판정을 끼워 넣으려는데, ONNX Runtime이나 TensorRT를 별도로 붙이려면 의존성·빌드·메모리 변환이 모두 새 일이 된다.

OpenCV DNN은 이미 있는 OpenCV 안의 한 모듈이다. 입력도 출력도 cv::Mat이라 전처리 파이프라인과 자연스럽게 이어진다. "전통 비전으로 정렬하고 딥러닝으로 판정"하는 하이브리드 구조를 한 라이브러리 안에서 끝낼 수 있다는 점이 가장 큰 장점이다.

대신 대가도 있다. 전용 런타임만큼 빠르지는 않고, 최신 모델 구조나 특이한 연산자(operator)는 지원이 늦거나 빠질 수 있다. 이 트레이드오프는 10장에서 다시 정리한다. 우선은 "OpenCV 파이프라인에 딥러닝을 가장 적은 마찰로 끼워 넣는 도구"라고 이해하면 된다.

지원 포맷

OpenCV DNN은 여러 프레임워크의 모델 포맷을 읽을 수 있다. 하지만 실무에서 권장되는 답은 하나다 — ONNX. ONNX는 프레임워크 중립 포맷이라 PyTorch, TensorFlow, scikit-learn 등 어디서 학습했든 같은 형태로 받을 수 있고, OpenCV의 ONNX 파서가 가장 활발히 관리된다.

포맷 로딩 함수 필요 파일 비고
ONNX readNetFromONNX / readNet .onnx 1개 권장 — 프레임워크 중립, 범용성 최고
Caffe readNetFromCaffe .prototxt + .caffemodel 구형 모델에 많음, 신규 학습엔 비권장
TensorFlow readNetFromTensorflow .pb (+ .pbtxt) frozen graph 형태, 변환이 까다로움
Darknet readNetFromDarknet .cfg + .weights YOLOv3/v4 원본 가중치
TF Lite readNetFromTFLite .tflite OpenCV 4.8+ 지원
고민하지 말고 ONNX로 통일한다 어떤 프레임워크로 학습하든 마지막에 ONNX로 export 하면 OpenCV DNN 쪽 코드는 항상 동일해진다. 11편에서 ONNX export를 다룬 이유가 여기 있다. 이 글의 모든 예제도 ONNX 모델을 가정한다.

모델 로딩

모델을 메모리에 올리는 것은 한 줄이다. cv::dnn::readNet은 파일 확장자를 보고 알아서 적절한 파서를 고르는 범용 함수다. 포맷이 확실하면 readNetFromONNX처럼 전용 함수를 써도 된다.

#include <opencv2/dnn.hpp>
#include <opencv2/opencv.hpp>
#include <iostream>

using namespace cv;
using namespace cv::dnn;

int main()
{
    // 방법 1: 확장자로 포맷 자동 판별 (가장 무난)
    Net net = readNet("model.onnx");

    // 방법 2: ONNX 전용 함수
    // Net net = readNetFromONNX("model.onnx");

    // 로딩 실패는 빈 Net으로 돌아온다 — 반드시 확인한다
    if (net.empty())
    {
        std::cerr << "모델 로딩 실패: model.onnx" << std::endl;
        return -1;
    }

    std::cout << "모델 로딩 성공" << std::endl;
    return 0;
}

Net 객체는 모델 그래프 전체를 담는 핵심 자료구조다. 한 번 로딩하면 같은 Net으로 이미지를 계속 추론할 수 있으니, 루프 안에서 매번 로딩하지 않는다. 로딩은 비싼 작업이라 프로그램 초기화 때 한 번만 한다.

readNet은 예외 대신 빈 Net을 줄 수도 있다 파일이 없거나 파서가 지원하지 않는 연산자를 만나면 경우에 따라 예외를 던지기도 하고, 비어 있는 Net을 반환하기도 한다. 두 경우 모두 대비하려면 try/catch로 감싸고 net.empty()도 확인한다. ImagingLib 규칙대로라면 이 지점에서 예외를 잡아 ErrorCode로 변환하는 것이 맞다.

백엔드와 타깃

같은 모델이라도 어떤 연산 엔진으로, 어떤 장치 위에서 돌릴지 고를 수 있다. 이것이 백엔드(backend)와 타깃(target)이다. 백엔드는 연산을 수행하는 구현체(OpenCV 내장, CUDA 등)이고, 타깃은 그 연산이 실행되는 하드웨어(CPU, GPU)다.

Net net = readNet("model.onnx");

// 기본값: OpenCV 내장 백엔드 + CPU
net.setPreferableBackend(DNN_BACKEND_OPENCV);
net.setPreferableTarget(DNN_TARGET_CPU);

// CUDA 가속 (CUDA 지원으로 빌드된 OpenCV 필요)
net.setPreferableBackend(DNN_BACKEND_CUDA);
net.setPreferableTarget(DNN_TARGET_CUDA);       // FP32
// net.setPreferableTarget(DNN_TARGET_CUDA_FP16);  // 더 빠름, 정밀도 약간 손해

// OpenCL (내장 GPU 등) — 효과는 환경마다 편차가 크다
net.setPreferableBackend(DNN_BACKEND_OPENCV);
net.setPreferableTarget(DNN_TARGET_OPENCL);
타깃 실행 장치 전제 조건 특징
DNN_TARGET_CPU CPU 없음 (기본) 어디서나 동작, 가장 안전한 기본값
DNN_TARGET_CUDA NVIDIA GPU CUDA 빌드 OpenCV + NVIDIA GPU CPU 대비 수 배~수십 배 빠름 (FP32)
DNN_TARGET_CUDA_FP16 NVIDIA GPU 위와 동일 + FP16 지원 GPU CUDA보다 더 빠름, 정밀도 약간 손해
DNN_TARGET_OPENCL GPU (벤더 무관) OpenCL 드라이버 효과 편차 큼, CPU보다 느릴 때도 있음
CUDA 빌드가 안 된 OpenCV에 CUDA 타깃을 걸면 조용히 CPU로 떨어진다 패키지 매니저로 받은 OpenCV는 대개 CUDA 없이 빌드돼 있다. 이때 DNN_BACKEND_CUDA를 설정해도 에러가 나지 않고 CPU 폴백이 일어나는 경우가 많다. "GPU를 켰는데 왜 안 빨라지지?"의 단골 원인이다. cv::getBuildInformation()을 출력해 CUDA 항목이 YES인지 먼저 확인한다. 
// OpenCV가 CUDA 지원으로 빌드됐는지 확인
std::cout << cv::getBuildInformation() << std::endl;
// 출력에서 "NVIDIA CUDA: YES" 같은 줄을 찾는다

// CUDA 디바이스 개수로도 간단히 확인 가능
int cudaCount = cv::cuda::getCudaEnabledDeviceCount();
std::cout << "CUDA devices: " << cudaCount << std::endl;  // 0이면 CUDA 없음

전처리 — blobFromImage

모델은 cv::Mat 이미지를 그대로 먹지 않는다. 모델이 기대하는 형태의 4차원 텐서(blob)로 바꿔 줘야 한다. 이 변환을 담당하는 함수가 cv::dnn::blobFromImage다. blob의 형태는 NCHW — (배치 N, 채널 C, 높이 H, 너비 W) 순서다.

blobFromImage가 한 번에 하는 일

① 리사이즈 — 모델 입력 크기(예: 224×224, 640×640)로 크기 조정
② 스케일 — 픽셀값에 scalefactor를 곱함 (예: 1/255.0으로 0~1 정규화)
③ 평균 빼기 — mean 값을 빼서 중심을 0 근처로 (ImageNet 계열에서 흔함)
④ 채널 순서 — swapRB로 BGR↔RGB 교환 (OpenCV는 BGR, 대부분 모델은 RGB 학습)
⑤ 레이아웃 변환 — HWC 이미지를 NCHW 텐서로 재배치

Mat image = imread("input.jpg");

// 분류 모델 예시 (ImageNet 계열, 224x224 입력)
Mat blob = blobFromImage(
    image,                       // 입력 이미지
    1.0 / 255.0,                 // scalefactor: 0~255 -> 0~1
    Size(224, 224),              // 모델 입력 크기
    Scalar(0.485, 0.456, 0.406), // mean (채널별로 뺄 값)
    true,                        // swapRB: BGR -> RGB
    false                        // crop: 리사이즈만, 크롭 안 함
);

// blob.size = [1, 3, 224, 224]  (N, C, H, W)
std::cout << "blob shape: " << blob.size << std::endl;

여기서 가장 중요한 원칙은 이것이다 — blobFromImage의 모든 인자는 학습 시 전처리와 정확히 일치해야 한다. 학습할 때 0~1로 정규화하고 RGB로 넣었다면, 추론에서도 똑같이 해야 한다. 하나라도 어긋나면 모델은 엉뚱한 입력을 받고 결과가 무의미해진다. 이 함정은 11장에서 다시 강조한다.

mean과 scalefactor의 적용 순서를 헷갈리지 않는다 OpenCV는 출력 = scalefactor × (입력 − mean) 순서로 계산한다. 즉 평균을 먼저 빼고 스케일을 곱한다. PyTorch의 Normalize(mean, std)는 (입력/255 − mean) / std 형태라 식이 다르다. PyTorch 전처리를 OpenCV로 옮길 때는 이 식 차이를 계산해서 인자를 맞춰야 한다.

여러 장을 한 번에 처리하려면 blobFromImages(복수형)를 쓴다. 배치 차원 N이 1보다 커진다.

std::vector<Mat> images = { img1, img2, img3, img4 };

Mat batchBlob = blobFromImages(
    images, 1.0 / 255.0, Size(224, 224),
    Scalar(), true, false
);
// batchBlob.size = [4, 3, 224, 224]  (배치 4장)

추론 — setInput과 forward

blob이 준비되면 추론은 두 줄이다. setInput으로 blob을 모델 입력에 꽂고, forward로 순전파를 실행해 출력을 받는다.

net.setInput(blob);          // 입력 텐서 설정
Mat output = net.forward();  // 순전파 실행, 출력 Mat 반환

// 출력 형태 확인 — 모델마다 다르다
std::cout << "output dims: " << output.dims << std::endl;
std::cout << "output size: " << output.size << std::endl;

출력의 형태(shape)는 모델 종류에 따라 완전히 다르다. 이걸 모르면 후처리를 짤 수 없다. 대표적인 출력 형태는 다음과 같다.

모델 종류 대표 출력 형태 의미
분류 [1, 1000] 클래스별 점수(logit) 1000개
검출 (YOLOv5/v7) [1, 25200, 85] 박스 25200개 × (x,y,w,h,obj + 클래스 80)
검출 (YOLOv8) [1, 84, 8400] (x,y,w,h + 클래스 80) × 박스 8400개 — 축이 전치됨
세그멘테이션 [1, C, H, W] 픽셀별 클래스 C개 점수 맵
YOLOv5와 YOLOv8은 출력 축 순서가 다르다 YOLOv5/v7은 [1, 박스수, 속성수]인데 YOLOv8은 [1, 속성수, 박스수]로 축이 전치돼 있다. 같은 "YOLO 후처리 코드"를 그대로 쓰면 한쪽은 박스가 전부 깨진다. 모델 버전에 맞춰 output을 reshape·transpose 해야 한다. 출력 형태를 먼저 찍어 보는 습관이 중요하다.

출력 노드가 여러 개인 모델(예: 마스크와 박스를 따로 내보내는 검출기)은 이름으로 특정 출력을 받거나, 여러 출력을 한 번에 받을 수 있다.

// 특정 출력 노드를 이름으로 지정
Mat out = net.forward("output0");

// 여러 출력을 한 번에 받기
std::vector<Mat> outputs;
std::vector<String> outNames = net.getUnconnectedOutLayersNames();
net.forward(outputs, outNames);
// outputs[0], outputs[1], ... 각 출력 노드 결과

후처리

모델의 raw 출력은 사람이 바로 쓸 수 없다. 분류는 점수에서 클래스를 뽑아야 하고, 검출은 수만 개 박스를 걸러야 하고, 세그멘테이션은 점수 맵을 마스크로 바꿔야 한다. 이것이 후처리다.

분류 — softmax와 argmax

분류 출력 [1, N]은 클래스별 점수(logit)다. argmax로 가장 높은 클래스를 고르고, 확률이 필요하면 softmax로 변환한다.

// output: [1, 1000] 형태의 분류 점수
Mat scores = output.reshape(1, 1);  // [1, 1000]로 평탄화

// argmax — 가장 높은 점수의 클래스
Point classIdPoint;
double maxScore;
minMaxLoc(scores, nullptr, &maxScore, nullptr, &classIdPoint);
int classId = classIdPoint.x;

// softmax — 점수를 확률로 변환
Mat probs;
exp(scores - maxScore, probs);          // 오버플로 방지로 max를 뺀다
probs /= cv::sum(probs)[0];
float confidence = probs.at<float>(0, classId);

std::cout << "class " << classId
          << ", confidence " << confidence << std::endl;

검출 — 박스 디코딩과 NMS

검출 모델은 후보 박스를 수만 개 쏟아낸다. 같은 물체에 박스가 여러 개 겹쳐 나오기 때문에, NMS(Non-Maximum Suppression, 비최대 억제)로 가장 신뢰도 높은 박스만 남기고 겹치는 것을 지운다. OpenCV는 cv::dnn::NMSBoxes를 제공한다.

// confidence threshold 이상인 박스만 모은다
std::vector<Rect> boxes;
std::vector<float> confidences;
std::vector<int> classIds;

// ... (모델 출력을 파싱해 boxes/confidences/classIds 채움) ...

// NMS: 겹치는 박스 제거
float confThreshold = 0.25f;
float nmsThreshold  = 0.45f;   // IoU 임계값
std::vector<int> keepIndices;
NMSBoxes(boxes, confidences, confThreshold, nmsThreshold, keepIndices);

// keepIndices에 살아남은 박스 인덱스만 들어 있다
for (int idx : keepIndices)
{
    rectangle(image, boxes[idx], Scalar(0, 255, 0), 2);
}

세그멘테이션 — 마스크

세그멘테이션 출력 [1, C, H, W]는 픽셀마다 클래스 C개의 점수를 가진다. 각 픽셀에서 argmax를 취하면 클래스 라벨 맵(마스크)이 된다.

// output: [1, C, H, W]  — C개 클래스, H x W 점수 맵
int numClasses = output.size[1];
int h = output.size[2];
int w = output.size[3];

Mat maxClass(h, w, CV_8UC1, Scalar(0));
Mat maxScore(h, w, CV_32FC1, Scalar(-FLT_MAX));

for (int c = 0; c < numClasses; ++c)
{
    // c번째 클래스의 H x W 점수 평면
    Mat scorePlane(h, w, CV_32FC1, output.ptr<float>(0, c));
    for (int y = 0; y < h; ++y)
    {
        for (int x = 0; x < w; ++x)
        {
            float s = scorePlane.at<float>(y, x);
            if (s > maxScore.at<float>(y, x))
            {
                maxScore.at<float>(y, x) = s;
                maxClass.at<uchar>(y, x) = static_cast<uchar>(c);
            }
        }
    }
}
// maxClass: 픽셀별 클래스 라벨 마스크 — 원본 크기로 resize 해서 사용

전체 추론 파이프라인 예제

지금까지의 단계를 하나로 이으면 추론 파이프라인이 된다. 흐름은 항상 같다 — 모델 로딩 → blobFromImage 전처리 → forward 추론 → 후처리.

그림 1. OpenCV DNN 추론 파이프라인 — 모델 로딩에서 후처리까지. 로딩은 한 번, 나머지는 이미지마다 반복된다

이미지 분류 전체 코드

ONNX 분류 모델로 이미지 한 장을 판정하는 전체 흐름이다. 로딩 → 전처리 → 추론 → 후처리가 모두 들어 있다.

#include <opencv2/opencv.hpp>
#include <opencv2/dnn.hpp>
#include <fstream>
#include <iostream>

using namespace cv;
using namespace cv::dnn;

int main()
{
    // --- 1. 모델 로딩 (초기화 때 1회) ---
    Net net = readNet("classifier.onnx");
    if (net.empty())
    {
        std::cerr << "모델 로딩 실패" << std::endl;
        return -1;
    }
    net.setPreferableBackend(DNN_BACKEND_OPENCV);
    net.setPreferableTarget(DNN_TARGET_CPU);

    // 클래스 이름 목록 로딩
    std::vector<std::string> classNames;
    std::ifstream ifs("labels.txt");
    std::string line;
    while (std::getline(ifs, line)) classNames.push_back(line);

    // --- 2. 입력 이미지와 전처리 ---
    Mat image = imread("sample.jpg");
    if (image.empty())
    {
        std::cerr << "이미지 로딩 실패" << std::endl;
        return -1;
    }

    Mat blob = blobFromImage(
        image, 1.0 / 255.0, Size(224, 224),
        Scalar(0.485, 0.456, 0.406), true, false);

    // --- 3. 추론 ---
    net.setInput(blob);
    Mat output = net.forward();   // [1, numClasses]

    // --- 4. 후처리: argmax + softmax ---
    Mat scores = output.reshape(1, 1);

    Point classIdPoint;
    double maxScore;
    minMaxLoc(scores, nullptr, &maxScore, nullptr, &classIdPoint);
    int classId = classIdPoint.x;

    Mat probs;
    exp(scores - maxScore, probs);
    probs /= cv::sum(probs)[0];
    float confidence = probs.at<float>(0, classId);

    // --- 5. 결과 출력 ---
    std::cout << "예측: " << classNames[classId]
              << " (" << confidence * 100.0f << "%)" << std::endl;

    putText(image, classNames[classId], Point(10, 30),
            FONT_HERSHEY_SIMPLEX, 0.9, Scalar(0, 255, 0), 2);
    imwrite("result.jpg", image);
    return 0;
}

객체 검출(YOLO ONNX) 전체 코드

YOLOv5/v7 계열 ONNX 모델로 객체를 검출하고 NMS로 박스를 정리한 뒤 그려 주는 전체 코드다. 출력 형태는 [1, 25200, 85]를 가정한다 — 박스 25200개, 각 박스가 (cx, cy, w, h, objectness, 클래스 80개).

#include <opencv2/opencv.hpp>
#include <opencv2/dnn.hpp>
#include <iostream>

using namespace cv;
using namespace cv::dnn;

// YOLO 입력 크기 (학습 설정과 일치해야 함)
const int   kInputW       = 640;
const int   kInputH       = 640;
const float kConfThresh   = 0.25f;   // objectness 임계값
const float kScoreThresh  = 0.25f;   // 클래스 점수 임계값
const float kNmsThresh    = 0.45f;   // NMS IoU 임계값

int main()
{
    // --- 1. 모델 로딩 ---
    Net net = readNet("yolov5s.onnx");
    if (net.empty())
    {
        std::cerr << "모델 로딩 실패" << std::endl;
        return -1;
    }
    net.setPreferableBackend(DNN_BACKEND_OPENCV);
    net.setPreferableTarget(DNN_TARGET_CPU);

    Mat image = imread("street.jpg");
    if (image.empty()) return -1;

    // --- 2. 전처리 ---
    Mat blob = blobFromImage(
        image, 1.0 / 255.0, Size(kInputW, kInputH),
        Scalar(), true, false);

    // --- 3. 추론 ---
    net.setInput(blob);
    Mat output = net.forward();   // [1, 25200, 85]

    // 출력을 2차원 [25200, 85]로 재배치
    int numBoxes = output.size[1];
    int numAttrs = output.size[2];   // 85 = 4(box) + 1(obj) + 80(class)
    output = output.reshape(1, numBoxes);

    // 원본 좌표로 되돌리기 위한 스케일 계수
    float xFactor = static_cast<float>(image.cols) / kInputW;
    float yFactor = static_cast<float>(image.rows) / kInputH;

    // --- 4. 박스 디코딩 ---
    std::vector<Rect>  boxes;
    std::vector<float> confidences;
    std::vector<int>   classIds;

    for (int i = 0; i < numBoxes; ++i)
    {
        float* row = output.ptr<float>(i);
        float objectness = row[4];
        if (objectness < kConfThresh) continue;

        // 클래스 점수 중 최댓값 찾기
        Mat classScores(1, numAttrs - 5, CV_32FC1, row + 5);
        Point classIdPoint;
        double maxClassScore;
        minMaxLoc(classScores, nullptr, &maxClassScore,
                  nullptr, &classIdPoint);

        float score = objectness * static_cast<float>(maxClassScore);
        if (score < kScoreThresh) continue;

        // 중심 좌표(cx, cy, w, h) -> 좌상단 기준 Rect
        float cx = row[0], cy = row[1];
        float w  = row[2], h  = row[3];
        int left = static_cast<int>((cx - w / 2) * xFactor);
        int top  = static_cast<int>((cy - h / 2) * yFactor);
        int bw   = static_cast<int>(w * xFactor);
        int bh   = static_cast<int>(h * yFactor);

        boxes.emplace_back(left, top, bw, bh);
        confidences.push_back(score);
        classIds.push_back(classIdPoint.x);
    }

    // --- 5. NMS: 겹치는 박스 제거 ---
    std::vector<int> keep;
    NMSBoxes(boxes, confidences, kScoreThresh, kNmsThresh, keep);

    // --- 6. 결과 그리기 ---
    for (int idx : keep)
    {
        rectangle(image, boxes[idx], Scalar(0, 255, 0), 2);
        std::string label = format("id %d: %.2f",
                                   classIds[idx], confidences[idx]);
        putText(image, label, boxes[idx].tl() + Point(0, -5),
                FONT_HERSHEY_SIMPLEX, 0.5, Scalar(0, 255, 0), 1);
    }

    std::cout << "검출된 객체: " << keep.size() << "개" << std::endl;
    imwrite("detected.jpg", image);
    return 0;
}

성능

검사 소프트웨어에서는 정확도만큼 속도(택트 타임)가 중요하다. OpenCV DNN의 추론 속도를 좌우하는 요소는 크게 백엔드/타깃, 입력 크기, 배치다.

백엔드별 속도 차이

같은 모델이라도 CPU와 CUDA의 차이는 크다. 모델·하드웨어마다 다르지만, 무거운 검출 모델에서 CUDA는 CPU 대비 수 배에서 수십 배까지 빨라지는 경우가 흔하다. net.getPerfProfile로 실제 추론 시간을 측정할 수 있다.

net.setInput(blob);
Mat output = net.forward();

// 레이어별 누적 추론 시간 측정
std::vector<double> layerTimes;
double freq = getTickFrequency() / 1000.0;   // ms 단위
double totalTime = net.getPerfProfile(layerTimes) / freq;

std::cout << "추론 시간: " << totalTime << " ms" << std::endl;
설정 상대 속도(경향) 적합한 상황
CPU 기준 (1×) 가벼운 모델, GPU 없는 환경, 개발·디버깅
CUDA (FP32) 수 배~수십 배 무거운 검출/세그멘테이션, 고속 라인
CUDA (FP16) CUDA보다 추가로 빠름 FP16 지원 GPU, 약간의 정밀도 손해 허용
OpenCL 편차 큼 NVIDIA GPU가 없을 때 차선책 (효과는 검증 필요)

입력 크기와 배치

추론 비용은 입력 크기에 거의 제곱으로 비례한다. 640×640과 320×320은 픽셀 수가 4배 차이라 추론 시간도 그만큼 벌어진다. 정확도가 허용하는 선에서 입력을 가장 작게 잡는 것이 가장 쉬운 최적화다.

여러 장을 처리할 때는 blobFromImages로 배치를 묶으면 장당 오버헤드가 줄어 처리량이 올라간다. 다만 모델이 동적 배치 차원을 지원하도록 export 돼 있어야 한다.

첫 forward는 항상 느리다 — 워밍업을 한다 모델 로딩 직후 첫 forward는 메모리 할당과 커널 초기화 때문에 유난히 느리다. 성능을 측정하거나 실가동에 들어가기 전, 더미 이미지로 forward를 한두 번 미리 돌려 워밍업하면 실제 추론부터는 안정적인 속도가 나온다.

OpenCV DNN vs 전용 런타임

OpenCV DNN이 유일한 선택지는 아니다. ONNX Runtime, TensorRT 같은 전용 추론 런타임은 더 빠르고 더 많은 모델을 지원한다. 그렇다면 언제 무엇을 쓰는가.

항목 OpenCV DNN ONNX Runtime TensorRT
속도 보통 빠름 가장 빠름 (NVIDIA 전용)
모델 호환성 제한적 — 최신 연산자 지원 늦음 넓음 넓으나 변환·튜닝 필요
OpenCV 통합 매우 쉬움 — 같은 라이브러리 Mat↔Tensor 변환 필요 변환 + 빌드 부담 큼
의존성·설치 OpenCV만 있으면 끝 런타임 추가 설치 CUDA/cuDNN/TensorRT 스택
하드웨어 CPU·CUDA·OpenCL CPU·CUDA·기타 EP 다양 NVIDIA GPU 전용
잘 맞는 경우 OpenCV 파이프라인에 끼워 넣기, 빠른 프로토타입 속도와 호환성의 균형 최고 속도가 필요한 NVIDIA 양산 장비
판단 기준 — 마찰이냐 속도냐

이미 OpenCV로 짜인 검사 SW에 딥러닝을 가장 적은 마찰로 넣고 싶다면 OpenCV DNN이 정답이다. 같은 cv::Mat으로 입출력이 흐르고, 추가 의존성이 없다.

반대로 택트 타임이 빠듯해서 마지막 한 방울의 속도까지 짜내야 하고 하드웨어가 NVIDIA로 고정돼 있다면 TensorRT가 맞다. CPU 환경에서 속도와 호환성의 균형을 원하면 ONNX Runtime이 무난하다.

실무에서 흔한 전략은 OpenCV DNN으로 먼저 만들어 검증하고, 속도가 부족할 때만 전용 런타임으로 옮기는 것이다. 전처리·후처리 코드는 거의 그대로 재사용되므로 옮기는 비용이 크지 않다.

흔한 함정

OpenCV DNN에서 "모델은 정상인데 결과가 이상한" 문제는 거의 다 정해진 몇 가지 함정에서 나온다. 미리 알면 디버깅 시간을 크게 줄일 수 있다.

전처리 불일치 — 가장 흔하고 가장 조용한 버그 scalefactor, mean, swapRB가 학습 때와 다르면 모델은 에러 없이 그냥 틀린 답을 낸다. 0~1 정규화로 학습한 모델에 0~255를 넣거나, RGB로 학습한 모델에 BGR을 넣는 식이다. 학습 코드의 전처리 설정을 그대로 베껴 와 한 줄씩 대조한다. 디버깅 1순위로 의심할 곳이다.
NMS 누락 — 박스가 한 물체에 잔뜩 겹쳐 나온다 검출 후처리에서 NMSBoxes를 빼먹으면 같은 물체에 박스가 수십 개씩 중복으로 그려진다. "검출은 되는데 박스가 지저분하다"면 NMS가 빠졌거나 nmsThreshold가 잘못된 것이다. confidence 필터링과 NMS는 검출 후처리의 필수 짝이다.
입력 크기 불일치 blobFromImage의 Size가 모델이 기대하는 입력과 다르면, 운이 좋으면 에러가 나고 운이 나쁘면 깨진 결과가 나온다. 고정 입력 모델은 정확히 그 크기를, 동적 입력 모델도 학습 해상도 근처를 써야 정확도가 유지된다.
출력 형태 오해 앞서 봤듯 YOLOv5와 YOLOv8은 출력 축 순서가 다르고, 모델마다 [배치, 박스, 속성]인지 [배치, 속성, 박스]인지 제각각이다. 후처리 코드를 짜기 전에 output.size를 반드시 출력해 형태를 확인한다. 형태를 모르고 짠 인덱싱은 조용히 틀린다.
CUDA 빌드 안 된 OpenCV에 CUDA 타깃 설정 4장에서 말한 그 함정이다. DNN_BACKEND_CUDA를 걸어도 OpenCV가 CUDA 없이 빌드됐으면 조용히 CPU로 폴백되어 "GPU를 켰는데 안 빨라진다". getBuildInformation()으로 CUDA 항목을 먼저 확인하는 것이 유일한 확실한 방법이다.
다음 편 예고 이번 편에서는 학습한 모델을 OpenCV DNN으로 검사 SW에 끼워 넣는 실전 방법을 봤다. 마지막 13편에서는 시리즈를 마무리하며 산업 비전에서의 딥러닝 — 전통 비전과 딥러닝을 한 시스템 안에서 어떻게 역할을 나눠 공존시키는가, 그 하이브리드 전략을 정리한다.
