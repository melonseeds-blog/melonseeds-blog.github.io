검사 파이프라인 개요

지난 19편에 걸쳐 OpenCV의 요소 기술을 하나씩 익혔다. cv::Mat으로 이미지를 담고, 색공간을 바꾸고, 필터로 노이즈를 줄이고, 엣지를 찾고, 임계화로 객체를 분리하고, 모폴로지로 형태를 다듬고, 윤곽과 블롭으로 객체를 세고, 측정으로 치수를 뽑았다. 하지만 실제 산업 현장의 머신 비전은 이 기술들을 하나씩 따로 쓰지 않는다. 정해진 순서로 엮어 검사 파이프라인(inspection pipeline)을 만든다.

검사 파이프라인이란 한 장의 입력 이미지가 들어오면 OK / NG 판정이 나올 때까지 거치는 처리 단계의 사슬이다. 각 단계는 앞 단계의 출력을 입력으로 받는다. 전처리가 깨끗한 영상을 만들면 검출 단계가 그 위에서 객체를 찾고, 측정 단계가 그 객체의 수치를 뽑고, 판정 단계가 그 수치를 기준과 비교한다. 마지막 글인 이번 편은 이 사슬을 실제로 동작하는 코드로 조립한다.

요소 기술과 파이프라인은 다른 능력이다 cv::Canny를 호출할 줄 아는 것과, 어떤 순서로 무엇을 호출해야 안정적인 검사기가 되는지 아는 것은 다른 문제다. 이번 편의 핵심은 함수 사용법이 아니라 조립 순서와 구조다.

전체 파이프라인 8단계

대부분의 2D 검사기는 다음 8단계로 정리된다. 검사 종류가 달라도 뼈대는 거의 같고, 어느 단계를 어떤 기법으로 채우느냐만 바뀐다.

검사 파이프라인의 표준 8단계. 파란 단계는 영상 정리, 초록 단계는 객체 분석, 노란 단계는 판정과 출력이다.

각 단계가 시리즈의 어느 편과 연결되는지, 어떤 OpenCV 기법을 쓰는지 정리하면 다음과 같다.

단계역할주요 기법 / 함수관련 편
① 이미지 획득카메라·파일에서 프레임 입력imread, VideoCapture, 그래버 SDK04편 입출력
② 전처리그레이 변환, 노이즈 제거, 조명 보정cvtColor, GaussianBlur, medianBlur05·08편
③ 정렬대상의 위치·각도 기준점 찾기템플릿 매칭, 윤곽 기반 기준점13편 윤곽
④ 검사 영역(ROI)처리할 범위를 사각형으로 한정cv::Rect, ROI 슬라이싱03편 ROI
⑤ 검출객체·엣지를 영상에서 분리Canny, threshold, findContours, connectedComponents10·11·13·14편
⑥ 측정·특징객체의 수치(치수·면적·위치) 산출contourArea, minAreaRect, moments13·14편 + 측정
⑦ 판정수치를 기준·공차와 비교해 OK/NG 결정비교 로직 (라이브러리 아님)—
⑧ 결과 출력·기록화면 표시, 로그, 통계 누적drawContours, putText, 파일 로그13편 + spdlog

아래 세 예제는 모두 이 8단계를 따른다. 다만 ①은 설명을 위해 imread로 단순화하고, ③ 정렬은 예제마다 필요한 만큼만 다룬다.

예제 1 — 부품 유무·개수 검사

트레이 위에 부품이 정해진 개수만큼 놓였는지 확인하는 검사다. 가장 기본적인 카운팅 검사이며, 파이프라인은 임계화 → 모폴로지 → connectedComponents → 면적 필터 → 개수 판정으로 흐른다.

핵심 아이디어는 이렇다. 부품과 배경의 밝기 차이로 객체를 이진화하고, 모폴로지로 작은 구멍·돌기를 정리한 뒤, 연결 요소로 덩어리를 센다. 이때 노이즈가 만든 작은 덩어리를 빼기 위해 면적 필터를 건다. 살아남은 덩어리 수가 곧 부품 개수다.

#include <opencv2/opencv.hpp>
#include <iostream>

// 부품 개수 검사 파라미터 (한곳에 모은다)
struct CountParams
{
    int    threshValue   = 110;     // 이진화 임계값
    int    morphKernel   = 5;       // 모폴로지 커널 크기
    double minPartArea   = 800.0;   // 부품으로 인정할 최소 면적 (px)
    double maxPartArea   = 60000.0; // 부품으로 인정할 최대 면적 (px)
    int    expectedCount = 12;      // 기대 부품 개수
};

// 부품 개수를 세어 OK/NG를 판정한다.
bool InspectPartCount(const cv::Mat& input, const CountParams& p, int& outCount)
{
    // ② 전처리 — 그레이 변환 + 블러로 노이즈 억제
    cv::Mat gray;
    if (input.channels() == 3)
        cv::cvtColor(input, gray, cv::COLOR_BGR2GRAY);
    else
        gray = input;

    cv::Mat blurred;
    cv::GaussianBlur(gray, blurred, cv::Size(5, 5), 0);

    // ⑤ 검출 — 임계화로 부품과 배경 분리
    cv::Mat binary;
    cv::threshold(blurred, binary, p.threshValue, 255, cv::THRESH_BINARY);

    // ⑤ 검출 — 모폴로지로 작은 구멍·돌기 정리 (열기 + 닫기)
    cv::Mat kernel = cv::getStructuringElement(
        cv::MORPH_ELLIPSE, cv::Size(p.morphKernel, p.morphKernel));
    cv::morphologyEx(binary, binary, cv::MORPH_OPEN,  kernel);
    cv::morphologyEx(binary, binary, cv::MORPH_CLOSE, kernel);

    // ⑤ 검출 — 연결 요소로 덩어리 라벨링
    cv::Mat labels, stats, centroids;
    int total = cv::connectedComponentsWithStats(
        binary, labels, stats, centroids, 8, CV_32S);

    // ⑥ 측정 + ⑦ 판정용 카운트 — 면적 필터로 노이즈 제거
    outCount = 0;
    for (int i = 1; i < total; ++i)  // 0은 배경이므로 제외
    {
        double area = stats.at<int>(i, cv::CC_STAT_AREA);
        if (area >= p.minPartArea && area <= p.maxPartArea)
            ++outCount;
    }

    // ⑦ 판정 — 기대 개수와 일치하면 OK
    return outCount == p.expectedCount;
}

int main()
{
    cv::Mat input = cv::imread("tray.jpg", cv::IMREAD_COLOR);
    if (input.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    CountParams params;
    int count = 0;
    bool ok = InspectPartCount(input, params, count);

    // ⑧ 결과 출력
    std::cout << "검출 개수: " << count
              << " / 기대 개수: " << params.expectedCount << std::endl;
    std::cout << "판정: " << (ok ? "OK" : "NG") << std::endl;
    return 0;
}
실행 결과 (콘솔)
검출 개수: 11 / 기대 개수: 12 판정: NG

면적 필터의 상한·하한이 검사의 신뢰도를 좌우한다. 하한이 너무 낮으면 노이즈를 부품으로 세고, 너무 높으면 작은 부품을 놓친다. 실제로는 정상 부품 면적의 분포를 측정해 여유를 두고 정한다.

이진화 한 번에 의존하지 않는다 고정 임계값은 조명이 흔들리면 바로 무너진다. 조명이 일정하지 않은 라인이면 THRESH_OTSU나 adaptiveThreshold로 바꾸고, 그래도 부족하면 ② 전처리에서 조명 보정(탑햇·나눗셈 보정)을 먼저 넣는다.

예제 2 — 치수 측정 검사

부품의 가로·세로 치수가 공차 안에 드는지 확인하는 검사다. 파이프라인은 그레이 → 블러 → Canny → findContours → minAreaRect → 픽셀→실측 변환 → 공차 판정으로 흐른다.

여기서 새로 등장하는 개념이 픽셀-실측 변환이다. OpenCV가 돌려주는 치수는 픽셀 단위다. 이를 mm로 바꾸려면 1픽셀이 몇 mm인지를 나타내는 보정 계수(mm/pixel)가 필요하다. 이 계수는 크기를 아는 기준물을 한 번 촬영해 미리 구해둔다.

#include <opencv2/opencv.hpp>
#include <iostream>

// 치수 측정 검사 파라미터
struct SizeParams
{
    double cannyLow      = 50.0;    // Canny 하한
    double cannyHigh     = 150.0;   // Canny 상한
    double minObjectArea = 5000.0;  // 측정 대상 최소 윤곽 면적
    double mmPerPixel    = 0.0254;  // 보정 계수: 1픽셀 = 0.0254 mm
    double targetWidth   = 20.0;    // 목표 가로 (mm)
    double targetHeight  = 12.0;    // 목표 세로 (mm)
    double tolerance     = 0.15;    // 허용 공차 (±mm)
};

struct SizeResult
{
    double widthMm  = 0.0;
    double heightMm = 0.0;
    bool   ok       = false;
};

// 가장 큰 윤곽의 외접 사각형으로 치수를 측정하고 공차를 판정한다.
bool MeasureObjectSize(const cv::Mat& input, const SizeParams& p, SizeResult& outResult)
{
    // ② 전처리
    cv::Mat gray;
    cv::cvtColor(input, gray, cv::COLOR_BGR2GRAY);
    cv::Mat blurred;
    cv::GaussianBlur(gray, blurred, cv::Size(5, 5), 0);

    // ⑤ 검출 — Canny 엣지 후 윤곽 추출
    cv::Mat edges;
    cv::Canny(blurred, edges, p.cannyLow, p.cannyHigh);

    std::vector<std::vector<cv::Point>> contours;
    cv::findContours(edges, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
    if (contours.empty())
        return false;  // 대상을 찾지 못함

    // ⑥ 측정 — 면적이 가장 큰 윤곽을 측정 대상으로 선택
    int bestIdx = -1;
    double bestArea = p.minObjectArea;
    for (int i = 0; i < static_cast<int>(contours.size()); ++i)
    {
        double area = cv::contourArea(contours[i]);
        if (area > bestArea)
        {
            bestArea = area;
            bestIdx = i;
        }
    }
    if (bestIdx < 0)
        return false;  // 충분히 큰 대상이 없음

    // ⑥ 측정 — 회전을 고려한 최소 외접 사각형
    cv::RotatedRect box = cv::minAreaRect(contours[bestIdx]);
    double longSide  = std::max(box.size.width, box.size.height);
    double shortSide = std::min(box.size.width, box.size.height);

    // ⑥ 픽셀 → 실측 변환
    outResult.widthMm  = longSide  * p.mmPerPixel;
    outResult.heightMm = shortSide * p.mmPerPixel;

    // ⑦ 판정 — 가로·세로가 모두 공차 안인지 확인
    bool widthOk  = std::abs(outResult.widthMm  - p.targetWidth)  <= p.tolerance;
    bool heightOk = std::abs(outResult.heightMm - p.targetHeight) <= p.tolerance;
    outResult.ok = widthOk && heightOk;
    return true;
}

int main()
{
    cv::Mat input = cv::imread("part.jpg", cv::IMREAD_COLOR);
    if (input.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    SizeParams params;
    SizeResult result;
    if (!MeasureObjectSize(input, params, result))
    {
        std::cout << "판정: NG (측정 대상 없음)" << std::endl;
        return 0;
    }

    // ⑧ 결과 출력
    std::cout.precision(3);
    std::cout << "가로: " << result.widthMm  << " mm (목표 "
              << params.targetWidth  << ")" << std::endl;
    std::cout << "세로: " << result.heightMm << " mm (목표 "
              << params.targetHeight << ")" << std::endl;
    std::cout << "판정: " << (result.ok ? "OK" : "NG") << std::endl;
    return 0;
}
실행 결과 (콘솔)
가로: 20.041 mm (목표 20) 세로: 11.913 mm (목표 12) 판정: NG

minAreaRect는 회전을 허용하는 외접 사각형을 돌려주므로, 부품이 비스듬히 놓여도 실제 치수를 잡는다. 다만 RotatedRect의 width·height는 회전 각도에 따라 의미가 바뀌므로, 위 코드처럼 max·min으로 긴 변·짧은 변을 명시적으로 구분하는 편이 안전하다.

보정 계수가 틀리면 모든 측정이 틀린다 mmPerPixel은 카메라·렌즈·작업 거리가 바뀌면 다시 구해야 한다. 측정 검사에서 가장 먼저 의심할 값이며, 렌즈 왜곡이 큰 경우 calib3d로 왜곡 보정을 거친 뒤 측정해야 정확하다.

예제 3 — 표면 결함(이물) 검출

매끈해야 할 표면에 이물·스크래치·얼룩이 있는지 검출하는 검사다. 결함은 모양이 일정하지 않아 "무엇을 찾을지" 정의하기 어렵다. 그래서 "정상이 아닌 것"을 찾는 전략을 쓴다.

두 가지 접근이 흔하다. 첫째, 기준 영상 차영상 — 정상 샘플 영상과 검사 영상의 차이를 본다. 정렬이 정확해야 해서 까다롭다. 둘째, 탑햇(top-hat) 변환 — 모폴로지로 배경의 완만한 밝기 변화를 제거하고, 배경보다 도드라지는 작은 밝은 결함만 남긴다. 정렬이 필요 없어 단일 영상 검사에 실용적이다. 아래는 탑햇 방식이다.

#include <opencv2/opencv.hpp>
#include <iostream>

// 표면 결함 검출 파라미터
struct DefectParams
{
    int    tophatKernel = 25;      // 탑햇 커널 크기 (결함보다 충분히 큼)
    int    threshValue  = 30;      // 결함 강조 후 이진화 임계값
    double minDefectArea = 15.0;   // 결함으로 인정할 최소 면적 (px)
    int    maxDefectCount = 0;     // 허용 결함 개수 (0 = 무결함만 OK)
};

struct DefectInfo
{
    cv::Point2f center;  // 결함 위치
    double      area;    // 결함 면적
};

// 탑햇 변환으로 표면 결함을 검출한다.
bool InspectSurfaceDefect(const cv::Mat& input, const DefectParams& p,
                          std::vector<DefectInfo>& outDefects)
{
    outDefects.clear();

    // ② 전처리
    cv::Mat gray;
    if (input.channels() == 3)
        cv::cvtColor(input, gray, cv::COLOR_BGR2GRAY);
    else
        gray = input;

    // ⑤ 검출 — 탑햇 변환으로 배경 밝기를 제거하고 밝은 결함만 강조
    cv::Mat kernel = cv::getStructuringElement(
        cv::MORPH_ELLIPSE, cv::Size(p.tophatKernel, p.tophatKernel));
    cv::Mat tophat;
    cv::morphologyEx(gray, tophat, cv::MORPH_TOPHAT, kernel);

    // ⑤ 검출 — 강조된 결함을 이진화
    cv::Mat binary;
    cv::threshold(tophat, binary, p.threshValue, 255, cv::THRESH_BINARY);

    // ⑤ 검출 — 블롭(연결 요소)으로 결함 후보 라벨링
    cv::Mat labels, stats, centroids;
    int total = cv::connectedComponentsWithStats(
        binary, labels, stats, centroids, 8, CV_32S);

    // ⑥ 측정 — 면적 필터로 진짜 결함만 추린다
    for (int i = 1; i < total; ++i)  // 0은 배경
    {
        double area = stats.at<int>(i, cv::CC_STAT_AREA);
        if (area < p.minDefectArea)
            continue;  // 너무 작으면 노이즈로 간주

        DefectInfo d;
        d.area = area;
        d.center = cv::Point2f(
            static_cast<float>(centroids.at<double>(i, 0)),
            static_cast<float>(centroids.at<double>(i, 1)));
        outDefects.push_back(d);
    }

    // ⑦ 판정 — 허용 개수 이하이면 OK
    return static_cast<int>(outDefects.size()) <= p.maxDefectCount;
}

int main()
{
    cv::Mat input = cv::imread("surface.jpg", cv::IMREAD_COLOR);
    if (input.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    DefectParams params;
    std::vector<DefectInfo> defects;
    bool ok = InspectSurfaceDefect(input, params, defects);

    // ⑧ 결과 출력
    std::cout << "검출 결함 수: " << defects.size() << std::endl;
    for (size_t i = 0; i < defects.size(); ++i)
    {
        std::cout << "  결함 " << (i + 1) << " — 위치 ("
                  << defects[i].center.x << ", " << defects[i].center.y
                  << "), 면적 " << defects[i].area << " px" << std::endl;
    }
    std::cout << "판정: " << (ok ? "OK" : "NG") << std::endl;
    return 0;
}
실행 결과 (콘솔)
검출 결함 수: 2 결함 1 — 위치 (412, 188), 면적 47 px 결함 2 — 위치 (905, 533), 면적 21 px 판정: NG

탑햇 커널 크기는 결함보다 크고 배경 무늬보다 작게 잡는다. 너무 작으면 결함 자체가 배경으로 흡수되고, 너무 크면 배경 보정 효과가 사라진다. 어두운 결함(움푹 팬 자국)을 찾을 때는 MORPH_TOPHAT 대신 MORPH_BLACKHAT을 쓴다.

예제 1부품 유무·개수threshold → morphologyEx → connectedComponentsWithStats → 면적 필터
예제 2치수 측정·공차GaussianBlur → Canny → findContours → minAreaRect → 픽셀 변환
예제 3표면 결함·이물morphologyEx(TOPHAT) → threshold → connectedComponentsWithStats → 면적 필터

파이프라인 설계 원칙

세 예제가 다른 검사를 하지만 코드 구조는 닮았다. 이는 우연이 아니라 좋은 파이프라인이 따르는 공통 원칙 때문이다.

각 단계는 함수로 모듈화한다

전처리·검출·측정·판정을 한 함수에 몰아넣으면 어디서 무엇이 잘못됐는지 알 수 없다. 단계마다 입력과 출력이 명확한 함수로 쪼개면 단계별로 따로 테스트하고 교체할 수 있다. 위 예제들은 설명을 위해 한 함수에 담았지만, 실제로는 단계별 함수로 나누는 편이 낫다.

중간 결과를 저장한다

검사가 NG인데 부품이 멀쩡해 보일 때, 이진화 결과가 깨졌는지 모폴로지가 과했는지는 중간 영상을 봐야 안다. 디버그 모드에서 각 단계의 결과를 파일로 떨군다.

// 디버그 모드에서 중간 결과를 단계별로 저장한다.
void SaveDebugStage(const cv::Mat& img, const std::string& stageName, bool debugEnabled)
{
    if (!debugEnabled)
        return;
    // 단계 이름을 파일명에 넣어 처리 순서를 추적 가능하게 한다
    cv::imwrite("debug_" + stageName + ".png", img);
}

// 사용 예 — 각 단계 직후에 호출
SaveDebugStage(gray,    "01_gray",   debug);
SaveDebugStage(binary,  "02_binary", debug);
SaveDebugStage(binary,  "03_morph",  debug);

파라미터를 한곳에 모은다

예제마다 struct ...Params를 만든 이유다. 임계값·커널 크기·면적 한계가 코드 곳곳에 흩어져 있으면 튜닝할 때마다 함수 본문을 헤집어야 한다. 파라미터를 구조체 하나에 모으면 설정 파일(JSON 등)에서 읽어오기도 쉽다.

매직 넘버를 코드에 박지 않는다 cv::threshold(img, out, 110, ...)처럼 숫자를 직접 쓰면 그 110이 무엇인지, 바꿔도 되는지 알 수 없다. 이름 있는 파라미터(p.threshValue)로 빼면 의미가 드러나고 한곳에서 관리된다.

실패 시 어느 단계인지 추적 가능하게 한다

"검사 실패"만으로는 대응할 수 없다. 윤곽을 못 찾았는지, 측정 대상이 너무 작았는지, 공차를 벗어났는지 — 실패 지점을 구분해야 한다. 단계마다 결과를 로그로 남기고, 실패를 종류별로 분리한다.

"NG"와 "검사 불가"는 다르다 부품이 불량이라 NG인 것과, 영상이 흐려 측정 자체를 못 한 것은 전혀 다른 상황이다. 전자는 부품을 버리면 되지만 후자는 설비를 점검해야 한다. 판정 결과에 이 둘을 반드시 구분해 담는다.

C++ 코드 구조화

예제처럼 자유 함수로 시작해도 좋지만, 검사기가 커지면 클래스로 묶는 편이 관리하기 좋다. C++ 시리즈에서 다룬 인터페이스 설계와 RAII가 여기서 그대로 쓰인다.

설계는 이렇다. 검사 단계를 메서드로 나누고, 파라미터는 멤버로 한 번만 설정하며, 모든 처리 메서드는 성공·실패를 ErrorCode로 돌려준다. 생성자에서 리소스를 잡고 소멸자에서 정리하는 RAII로 자원 누수를 막는다.

#include <opencv2/opencv.hpp>

// 검사 결과를 종류별로 구분하는 코드
enum class ErrorCode
{
    Ok = 0,
    EmptyInput,        // 입력 이미지가 비어 있음
    NoTargetFound,     // 검사 대상을 찾지 못함 (검사 불가)
    OutOfTolerance,    // 측정값이 공차를 벗어남 (NG)
};

// 치수 측정 검사기 — 단계별 메서드 + ErrorCode 반환
class SizeInspector
{
public:
    // 생성자에서 파라미터를 한 번만 받아 보관한다 (RAII)
    explicit SizeInspector(const SizeParams& params)
        : m_params(params)
    {
    }

    // 검사 진입점 — 단계 메서드를 순서대로 호출한다.
    ErrorCode Inspect(const cv::Mat& input, SizeResult& outResult)
    {
        if (input.empty())
            return ErrorCode::EmptyInput;

        cv::Mat pre;
        preprocess(input, pre);          // ② 전처리

        std::vector<cv::Point> target;
        ErrorCode ec = detectTarget(pre, target);  // ⑤ 검출
        if (ec != ErrorCode::Ok)
            return ec;

        measure(target, outResult);      // ⑥ 측정
        return judge(outResult);         // ⑦ 판정
    }

private:
    // ② 전처리 — 그레이 변환 + 블러
    void preprocess(const cv::Mat& src, cv::Mat& dst)
    {
        cv::Mat gray;
        cv::cvtColor(src, gray, cv::COLOR_BGR2GRAY);
        cv::GaussianBlur(gray, dst, cv::Size(5, 5), 0);
    }

    // ⑤ 검출 — Canny + 윤곽에서 가장 큰 대상 선택
    ErrorCode detectTarget(const cv::Mat& pre, std::vector<cv::Point>& outTarget)
    {
        cv::Mat edges;
        cv::Canny(pre, edges, m_params.cannyLow, m_params.cannyHigh);

        std::vector<std::vector<cv::Point>> contours;
        cv::findContours(edges, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

        double bestArea = m_params.minObjectArea;
        int bestIdx = -1;
        for (int i = 0; i < static_cast<int>(contours.size()); ++i)
        {
            double area = cv::contourArea(contours[i]);
            if (area > bestArea) { bestArea = area; bestIdx = i; }
        }
        if (bestIdx < 0)
            return ErrorCode::NoTargetFound;

        outTarget = contours[bestIdx];
        return ErrorCode::Ok;
    }

    // ⑥ 측정 — 외접 사각형에서 실측 치수 산출
    void measure(const std::vector<cv::Point>& target, SizeResult& outResult)
    {
        cv::RotatedRect box = cv::minAreaRect(target);
        double longSide  = std::max(box.size.width, box.size.height);
        double shortSide = std::min(box.size.width, box.size.height);
        outResult.widthMm  = longSide  * m_params.mmPerPixel;
        outResult.heightMm = shortSide * m_params.mmPerPixel;
    }

    // ⑦ 판정 — 공차 비교
    ErrorCode judge(SizeResult& outResult)
    {
        bool wOk = std::abs(outResult.widthMm  - m_params.targetWidth)  <= m_params.tolerance;
        bool hOk = std::abs(outResult.heightMm - m_params.targetHeight) <= m_params.tolerance;
        outResult.ok = wOk && hOk;
        return outResult.ok ? ErrorCode::Ok : ErrorCode::OutOfTolerance;
    }

    SizeParams m_params;  // 파라미터를 멤버로 한곳에 보관
};

이 구조의 이점은 명확하다. Inspect만 보면 파이프라인 흐름이 한눈에 읽히고, 각 단계는 private 메서드라 따로 손볼 수 있으며, ErrorCode가 실패를 종류별로 알려준다. 검사 종류가 늘면 공통 인터페이스(IInspector)를 두고 검사기마다 구현하는 식으로 확장한다 — C++ 시리즈에서 다룬 다형성이 그대로 적용된다.

cv::Mat 자체가 RAII다 멤버로 들고 있는 cv::Mat은 소멸자에서 참조 카운트를 내리고 마지막 소유자일 때 버퍼를 자동 해제한다. 1편에서 본 참조 카운트 메모리 관리가 검사기 클래스 안에서도 그대로 동작하므로, 버퍼 해제를 수동으로 챙길 필요가 없다.

성능 고려

인라인 검사는 택트 타임(tact time) 안에 끝나야 한다. 알고리즘을 바꾸기 전에, 다음 세 가지 기본기만 지켜도 상당한 시간을 아낀다.

불필요한 복사를 줄인다

1편에서 본 대로 cv::Mat을 값으로 넘겨도 픽셀 버퍼는 복사되지 않는다. 하지만 함수가 원본을 수정하지 않는다면 const cv::Mat&로 받아 의도를 분명히 한다. 그리고 clone()은 정말 독립 사본이 필요할 때만 쓴다 — 습관적인 clone()은 매 프레임 큰 버퍼를 새로 할당한다.

ROI로 처리 영역을 한정한다

파이프라인 4단계가 ROI인 이유다. 전체 4K 영상을 다 처리할 필요 없이, 검사 대상이 있는 영역만 잘라서 처리하면 처리량이 그만큼 줄어든다. ROI 슬라이싱은 복사 없이 헤더만 만드는 연산이라 공짜에 가깝다.

// 전체 영상이 아니라 검사 영역만 처리한다 (복사 없음)
cv::Rect inspectRegion(320, 180, 640, 480);  // x, y, w, h
cv::Mat roi = fullFrame(inspectRegion);      // 헤더만 생성, 데이터 공유

// 이후 무거운 처리는 roi에만 적용된다
cv::GaussianBlur(roi, roi, cv::Size(5, 5), 0);
cv::Canny(roi, edges, 50, 150);

적절한 자료형을 쓴다

8비트로 충분한 처리에 굳이 CV_32F를 쓰면 메모리와 연산량이 4배가 된다. float 변환은 정밀도가 필요한 단계에서만 하고, 검출·판정처럼 8비트로 충분한 곳은 CV_8U를 유지한다.

최적화 전에 측정부터 한다 어느 단계가 느린지는 추측하지 말고 cv::getTickCount로 단계별 시간을 재서 확인한다. 대개 병목은 한두 단계에 몰려 있고, 거기만 손봐도 충분하다. 그래도 부족하면 CUDA 가속(cv::cuda)을 검토하지만, 그건 병목을 정확히 안 다음의 이야기다.

OpenCV의 한계와 그 다음

OpenCV는 강력하고 무료이며 어디서나 돌아간다. 하지만 모든 검사를 OpenCV만으로 푸는 것은 아니다. 한계를 아는 것도 실력이다.

회전·변형 매칭과 정밀 shape 매칭이 대표적이다. 부품이 임의 각도로 놓이고 약간씩 변형되는 상황에서 위치를 견고하게 찾는 일은 OpenCV의 기본 템플릿 매칭으로는 한계가 있다. 이 영역은 HALCON, Cognex VisionPro 같은 상용 머신 비전 라이브러리가 훨씬 강하다. 서브픽셀 정밀도의 형상 기반 매칭, 검증된 측정 도구, GUI 기반 개발 환경을 제공한다. 정밀도와 안정성이 사업적으로 중요하고 예산이 허락한다면 상용 도구가 합리적인 선택이다.

딥러닝이 필요한 경우도 있다. 결함의 형태가 너무 다양해 규칙으로 정의할 수 없거나, 정상/불량의 경계가 사람도 설명하기 애매한 검사는 전통적 영상 처리로 한계에 부딪힌다. 이럴 때는 학습 기반 분류·세그멘테이션·이상 탐지가 답이 된다. OpenCV의 dnn 모듈로 학습된 모델을 추론에 쓸 수 있고, 그 자체로 전처리·후처리 도구로도 계속 유용하다.

OpenCV는 출발점이자 기반이다 상용 도구를 쓰든 딥러닝을 쓰든, 이미지를 읽고·자르고·전처리하고·결과를 그리는 일은 여전히 OpenCV로 한다. OpenCV에서 비전을 시작하는 것은 그래서 낭비가 아니다 — 어떤 방향으로 가든 바탕이 되는 공통 언어다.

시리즈 마무리

1편에서 cv::Mat의 헤더와 데이터가 어떻게 나뉘는지부터 시작했다. 그 뒤로 픽셀에 접근하고, 이미지를 읽고 쓰고, 색공간을 다루고, 산술·논리 연산을 하고, 히스토그램을 보고, 공간 필터링과 샤프닝으로 영상을 다듬고, 엣지를 찾고, 임계화로 객체를 분리하고, 모폴로지로 형태를 정리하고, 윤곽과 블롭으로 객체를 분석하고, 측정으로 수치를 뽑았다. 그리고 이번 편에서 그 모든 조각을 하나의 검사 파이프라인으로 조립했다. 요소 기술을 따로 보면 단순한 함수 호출이지만, 정해진 순서로 엮고 단계마다 추적 가능하게 구조화하면 그것이 곧 산업용 검사기가 된다.

이 CV 시리즈는 혼자 떨어져 있지 않다. C++ 시리즈에서 다진 인터페이스·RAII·스마트 포인터는 이번 편의 검사기 클래스 설계에 그대로 쓰였다. HALCON 시리즈는 OpenCV의 한계 너머 — 정밀 매칭과 측정 — 를 상용 도구로 어떻게 푸는지 이어서 보여준다. 그리고 스마트 공장 시리즈는 이렇게 만든 검사기가 설비·MES·데이터와 어떻게 연결되어 라인 위에서 돌아가는지를 다룬다. 20편으로 비전의 기초 체력을 만들었으니, 이제 그 위에 무엇을 쌓을지는 각자의 현장이 정한다. 여기까지 함께한 모든 독자에게 고맙다는 말을 전한다.
