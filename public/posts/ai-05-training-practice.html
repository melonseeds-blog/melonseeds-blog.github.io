데이터가 모델보다 중요하다

딥러닝 비전을 처음 배우면 모델 구조에 가장 큰 관심이 간다. ResNet이냐 EfficientNet이냐, 레이어를 몇 개 쌓을 것이냐 같은 질문이다. 하지만 산업 현장에서 검사 시스템을 만들어 보면 곧 깨닫는다. 성패를 가르는 것은 거의 항상 데이터다. 모델은 공개된 검증된 구조를 가져다 쓰면 되지만, 데이터는 누구도 대신 만들어 주지 않는다.

같은 모델, 같은 학습 코드라도 데이터가 깨끗하고 현장을 잘 대표하면 잘 동작하고, 데이터가 편향되거나 라벨이 엉성하면 아무리 좋은 모델도 무너진다. 그래서 최근의 흐름을 데이터 중심 AI(data-centric AI)라고 부른다. 모델 코드를 고치는 대신 데이터를 체계적으로 개선하는 접근이다.

모델 중심 vs 데이터 중심

모델 중심 접근은 데이터를 고정해 놓고 모델 구조와 하이퍼파라미터를 바꿔 가며 성능을 올린다. 연구 논문의 벤치마크 경쟁이 이 방식이다.
데이터 중심 접근은 모델을 고정해 놓고 데이터의 라벨 오류를 고치고, 부족한 케이스를 채우고, 일관성을 높여 성능을 올린다. 현장 검사 시스템은 데이터셋이 작고 지저분하기 때문에 이쪽에서 얻는 이득이 훨씬 크다.

"좋은 모델"은 출발점, "좋은 데이터"는 승부처 검증된 모델 구조는 이미 공개되어 있다. 진짜 일은 그 모델에 무엇을 먹일지 정하는 데 있다. 이 글은 모델 코드보다 데이터셋을 만들고 학습을 운영하는 실전 감각에 초점을 둔다.

데이터셋 구성 — 분할과 누수

모은 이미지를 그대로 학습에 다 넣으면 안 된다. 데이터는 학습(train)·검증(validation)·테스트(test) 세 묶음으로 나눈다. 각자 역할이 다르고, 이 역할이 섞이는 순간 모델 성능을 잘못 판단하게 된다.

세 묶음의 역할

학습셋 모델이 가중치를 실제로 학습하는 데이터다. 가장 많은 양을 차지한다. 모델은 이 데이터를 직접 보면서 파라미터를 조정한다.
검증셋 학습 도중 모델 상태를 점검하는 데이터다. 하이퍼파라미터를 고르고, Early Stopping 시점을 정하고, 과적합 여부를 본다. 모델이 직접 학습하지는 않지만 사람이 이 결과를 보고 결정을 내리므로 간접적으로 영향을 받는다.
테스트셋 모든 학습과 튜닝이 끝난 뒤 단 한 번, 최종 성능을 측정하는 데이터다. 학습 과정 어디에도 개입하지 않는다. 현장 배포 후의 성능을 가늠하는 마지막 잣대다.
그림 1. 데이터 분할과 학습 사이클 — 학습·검증은 반복 루프 안에서 돌고, 테스트셋은 루프 바깥에서 단 한 번만 쓰인다

분할 비율과 클래스 균형

분할 비율은 절대 공식이 없지만 데이터가 수천~수만 장 규모면 대략 70 / 15 / 15 또는 80 / 10 / 10이 흔한 출발점이다. 데이터가 수십만 장 이상으로 아주 많으면 검증·테스트는 각각 1~2%만 떼어도 충분하다. 반대로 데이터가 수백 장뿐이면 한 번의 분할로는 운에 좌우되므로 교차검증(k-fold)을 쓰는 편이 안전하다.

비율보다 더 중요한 것이 클래스 균형이다. 각 묶음에 클래스별 비율이 비슷하게 들어가야 한다. 전체의 결함 비율이 5%인데 테스트셋에 결함이 한 장도 안 들어가면 그 평가는 의미가 없다. 클래스 비율을 유지하며 나누는 것을 층화 분할(stratified split)이라고 한다.

데이터 누수 — 가장 무서운 함정

데이터 누수(data leakage)는 테스트셋의 정보가 어떤 경로로든 학습 과정에 새어 들어가는 것이다. 누수가 있으면 평가 점수는 화려하게 잘 나오지만, 실제 현장에 배포하면 성능이 폭락한다. 점수를 믿고 배포했다가 뒤통수를 맞는 전형적인 원인이다.

산업 비전에서 흔한 누수 패턴 같은 제품을 여러 각도로 찍은 이미지가 학습셋과 테스트셋에 나뉘어 들어가는 경우다. 모델은 사실상 "본 적 있는 물체"를 다시 보는 셈이라 점수가 부풀려진다. 또 증강으로 만든 이미지의 원본과 변형본이 서로 다른 묶음에 들어가는 것, 같은 생산 로트·같은 웨이퍼의 이미지가 분할을 가로지르는 것도 모두 누수다. 분할은 이미지 단위가 아니라 "독립된 대상" 단위로 해야 한다.

라벨링 — 형태·도구·품질

지도학습은 정답표가 있어야 한다. 이미지마다 "이것이 정답"이라고 붙여 주는 작업이 라벨링이다. 태스크에 따라 라벨의 형태가 완전히 다르고, 형태가 복잡할수록 라벨링 비용이 가파르게 오른다.

태스크별 라벨 형태

태스크 라벨 형태 예시 라벨링 비용
이미지 분류 이미지당 클래스 1개 "이 이미지 = 양품" / "불량" 낮음 — 클릭 한 번
객체 검출 경계 상자 + 클래스 스크래치 위치를 사각형으로 표시 중간 — 상자마다 드래그
세그멘테이션 픽셀 단위 마스크 결함 영역을 픽셀 경계까지 칠하기 높음 — 한 장에 수 분~수십 분

같은 1,000장이라도 분류 라벨은 하루면 끝나지만 세그멘테이션 마스크는 한 주가 걸릴 수 있다. 그래서 태스크를 정할 때 "꼭 픽셀 단위가 필요한가, 위치 상자로 충분한가, 합격/불합격만 알면 되는가"를 먼저 따져야 한다. 필요 이상으로 정밀한 라벨을 고르면 데이터셋이 작아지고 결국 성능이 나빠진다.

라벨링 도구

라벨링은 전용 도구로 한다. 대표적으로 CVAT, Label Studio, Roboflow, LabelImg 같은 것이 있다. 도구를 고를 때는 지원 태스크(분류·검출·세그멘테이션), 내보내기 포맷(COCO, YOLO, Pascal VOC 등), 여러 사람이 함께 작업하는 협업 기능, 모델이 미리 라벨을 제안하는 보조 기능 같은 것을 본다.

라벨 품질과 일관성

라벨링에서 진짜 어려운 것은 도구가 아니라 일관성이다. "이 정도 흠집을 결함으로 볼 것인가" 같은 경계 사례에서, 작업자 A와 B가 다르게 판단하면 모델은 모순된 정답을 학습하게 된다. 모델이 혼란스러워하기 전에 사람이 먼저 기준을 합의해야 한다.

라벨 가이드를 문서로 만든다 결함의 정의, 경계 사례 판정 기준, 상자를 얼마나 타이트하게 그릴지 등을 예시 이미지와 함께 문서로 남긴다. 여러 명이 라벨링할 때는 같은 이미지 묶음을 두 사람이 라벨링해 일치율을 확인하는 것도 좋다. 라벨이 흔들리면 그 위의 어떤 학습도 흔들린다.
라벨링 비용은 프로젝트의 숨은 큰 비용 딥러닝 검사 프로젝트에서 모델 학습보다 라벨링에 더 많은 시간과 인건비가 드는 경우가 흔하다. 데이터를 모으기는 쉬워도 라벨을 붙이는 것은 사람 손이 필요하다. 그래서 라벨이 적게 드는 태스크 설계, 전이학습, 이상탐지처럼 라벨 부담을 줄이는 전략이 중요해진다.

데이터 증강

데이터 증강(augmentation)은 가진 이미지에 변형을 가해 새로운 학습 샘플을 만들어 내는 기법이다. 한 장의 원본을 회전·반전·밝기 조정해서 여러 장처럼 쓴다. 데이터를 새로 수집하지 않고도 데이터의 다양성을 늘려 모델이 더 잘 일반화하도록 돕는다.

주요 증강 기법

기법 변형 내용 모사하는 현장 변동
회전·반전 이미지를 돌리거나 좌우·상하 뒤집기 부품이 놓이는 방향의 변동
크롭·이동 일부를 잘라내거나 위치를 옮기기 대상이 화면에 들어오는 위치의 변동
밝기·대비 밝기, 대비, 감마를 조정 조명 세기·노출 차이
색상 변형 색조·채도 조정 조명 색온도, 카메라 화이트밸런스 차이
노이즈 추가 가우시안 노이즈 등을 주입 센서 노이즈, 고감도 촬영 환경
블러 이미지를 흐리게 초점 흔들림, 미세한 모션 블러
스케일 확대·축소 카메라-대상 거리, 렌즈 배율 변동

산업 비전에서 증강이 특히 강력한 이유는, 현장의 변동 요인이 대부분 예측 가능하기 때문이다. 조명이 밝아지거나 어두워지는 것, 부품이 살짝 기울어 들어오는 것, 카메라 거리가 미세하게 달라지는 것 — 이런 변동을 증강으로 미리 모사해 학습시키면, 모델이 실제 그런 상황을 만났을 때 흔들리지 않는다.

과한 증강은 데이터를 망친다 증강은 "현장에서 실제로 일어날 법한" 변형이어야 한다. 글자가 항상 똑바로 들어오는 OCR 검사에 상하 반전을 넣으면 존재하지 않는 상황을 학습하게 된다. 결함 판정에서 색이 중요한데 색상을 심하게 흔들면 결함 신호 자체가 사라진다. 증강 후 이미지를 사람이 직접 눈으로 확인해서 "이게 현장에서 나올 수 있는 이미지인가"를 점검해야 한다.
증강은 학습셋에만 적용한다 증강은 학습 데이터를 늘리는 도구이지 평가 데이터를 늘리는 도구가 아니다. 검증셋·테스트셋에 증강을 적용하면 평가가 실제 현장 분포와 어긋나고, 같은 원본의 변형본이 학습·평가에 동시에 들어가는 누수까지 생긴다. 평가 데이터는 손대지 않은 원본 그대로 둔다.

과적합 — 정체와 진단

과적합(overfitting)은 모델이 학습 데이터는 거의 완벽하게 맞추지만 처음 보는 새 데이터에는 약한 상태다. 모델이 데이터의 일반적인 패턴이 아니라 학습셋에만 있는 우연한 특징, 심지어 노이즈까지 외워 버린 것이다. 학습셋이라는 시험지의 답을 통째로 암기했지만 원리는 모르는 학생과 같다.

학습 곡선으로 진단한다

과적합은 학습 손실과 검증 손실을 함께 그린 곡선으로 진단한다. 정상적인 학습이라면 두 손실이 함께 내려간다. 과적합이 시작되면 학습 손실은 계속 내려가는데 검증 손실이 어느 순간부터 다시 올라간다. 이 두 곡선이 벌어지는 지점이 과적합이 시작되는 지점이다.

그림 2. 과적합 학습 곡선 — 학습 손실은 계속 내려가지만 검증 손실이 다시 올라가는 지점부터 과적합이다. 두 곡선 사이의 벌어진 간격이 일반화 격차다
과적합과 과소적합

과적합은 학습 손실은 매우 낮은데 검증 손실이 높은 상태다 — 모델이 너무 복잡하거나 데이터가 너무 적다.
과소적합(underfitting)은 학습 손실 자체가 안 내려가는 상태다 — 모델이 너무 단순하거나 학습이 부족하다. 이때는 정규화를 줄이거나, 모델을 키우거나, 더 오래 학습해야 한다.
좋은 학습은 이 둘 사이의 균형점에서 멈춘다.

과적합에 대응하는 방법

과적합이 보이면 손쓸 방법이 여럿 있다. 하나만 쓰는 게 아니라 보통 여러 개를 함께 적용한다.

대응법 작동 원리 비고
데이터 늘리기 학습 데이터를 더 모으거나 증강으로 다양성을 키운다 가장 근본적인 해결책 — 효과가 가장 확실하다
L2 정규화 / Weight Decay 가중치가 과하게 커지지 않도록 손실에 페널티를 더한다 모델이 단순한 해를 선호하게 만든다
Dropout 학습 중 일부 뉴런을 무작위로 끈다 특정 뉴런에 과도하게 의존하지 못하게 한다
Early Stopping 검증 손실이 올라가기 시작하면 학습을 멈춘다 과적합 구간에 들어가기 전에 중단
Batch Normalization 층마다 출력 분포를 정규화한다 학습 안정화가 주목적이며 약한 정규화 효과도 있다
모델 단순화 레이어·파라미터 수를 줄인다 데이터 양에 비해 모델이 과하게 클 때
순서를 정하자면 데이터 → 정규화 → 모델 크기 과적합이 보이면 먼저 데이터를 늘릴 수 있는지 본다(증강 포함). 그다음 Dropout과 Weight Decay 같은 정규화를 켠다. Early Stopping은 거의 항상 기본으로 켜 둔다. 그래도 안 되면 모델 크기를 줄인다. 데이터가 충분히 많으면 과적합 자체가 잘 생기지 않는다.

전이학습

전이학습(transfer learning)은 다른 큰 데이터셋으로 미리 학습된 모델을 가져와, 내 데이터로 일부만 다시 학습하는 방식이다. 가장 흔한 형태는 ImageNet(약 1,400만 장, 1,000개 클래스)으로 사전학습된 모델을 출발점으로 쓰는 것이다.

왜 효과가 있는가. CNN의 앞쪽 층은 에지·코너·질감 같은 범용 시각 특징을 학습한다. 이런 특징은 강아지 사진이든 산업 부품 사진이든 공통으로 쓸모가 있다. 그래서 앞쪽 층은 이미 학습된 것을 그대로 쓰고, 내 데이터에 특화된 뒤쪽 층만 새로 학습하면 된다. 처음부터 학습하는 것보다 훨씬 적은 데이터로, 훨씬 빠르게 좋은 성능에 도달한다.

백본 동결 vs 전체 미세조정

전략 방식 적합한 상황
백본 동결 (Feature Extraction) 사전학습 층은 그대로 고정하고, 새로 붙인 분류 헤드만 학습한다 내 데이터가 매우 적을 때, 대상이 일반 사진과 비슷할 때
부분 미세조정 앞쪽 층은 동결하고 뒤쪽 일부 층 + 헤드를 학습한다 데이터가 어느 정도 있고, 대상이 일반 사진과 다소 다를 때
전체 미세조정 (Fine-tuning) 모든 층을 작은 학습률로 함께 다시 학습한다 데이터가 충분하고, 대상이 일반 사진과 많이 다를 때 (X선·현미경 영상 등)
전이학습은 데이터가 적은 산업 현장의 필수 무기 현장에서 결함 이미지를 수만 장 모으는 것은 비현실적이다. 수백~수천 장 규모에서 처음부터 학습하면 십중팔구 과적합한다. 사전학습 모델에서 출발하면 그 정도 데이터로도 쓸 만한 성능이 나온다. 산업 비전 딥러닝에서 전이학습은 선택이 아니라 기본 전제에 가깝다.
전체 미세조정은 학습률을 작게 전체 층을 미세조정할 때 학습률이 크면, 애써 학습된 사전학습 가중치가 초반 몇 스텝 만에 망가진다. 사전학습 모델을 미세조정할 때는 처음부터 학습할 때보다 훨씬 작은 학습률을 쓰는 것이 정석이다.

하이퍼파라미터 튜닝

하이퍼파라미터는 모델이 학습으로 알아내는 값(가중치)이 아니라, 학습을 시작하기 전에 사람이 정해 주는 설정값이다. 같은 모델·같은 데이터라도 하이퍼파라미터에 따라 결과가 크게 달라진다.

학습률 한 스텝마다 가중치를 얼마나 크게 움직일지를 정한다. 가장 영향이 큰 하이퍼파라미터다. 너무 크면 손실이 발산하거나 출렁이고, 너무 작으면 학습이 한없이 느리다.
배치 크기 한 번에 몇 장을 묶어 처리할지를 정한다. 크면 학습이 안정적이고 빠르지만 GPU 메모리를 많이 쓰고, 작으면 노이즈가 많아 일반화에 도움이 되기도 한다.
에폭 수 전체 학습 데이터를 몇 번 반복해서 볼지를 정한다. 너무 적으면 과소적합, 너무 많으면 과적합이다. 고정하기보다 Early Stopping에 맡기는 편이 낫다.
옵티마이저 손실을 줄이는 방향으로 가중치를 갱신하는 알고리즘이다. SGD, Adam, AdamW 등이 있다. 무엇을 쓸지, 그 안의 모멘텀 같은 값도 하이퍼파라미터다.

튜닝 전략

하이퍼파라미터를 다 동시에 흔들면 무엇이 효과가 있었는지 알 수 없다. 보통 학습률부터 잡는다. 영향이 가장 크기 때문이다. 학습률은 0.1, 0.01, 0.001처럼 자릿수 단위로 훑어 대략의 범위를 먼저 찾는다. 그다음 배치 크기, 정규화 강도 순으로 좁혀 간다.

탐색 방식은 가능한 값을 격자로 모두 도는 그리드 서치, 무작위로 뽑아 보는 랜덤 서치, 이전 결과를 보고 다음 후보를 똑똑하게 고르는 베이지안 최적화가 있다. 후보가 많을 때는 그리드 서치보다 랜덤 서치가 효율적인 경우가 많다. 무엇을 쓰든 평가는 반드시 검증셋으로 하고, 테스트셋은 건드리지 않는다.

학습 모니터링

학습은 돌려 놓고 끝나기를 기다리는 것이 아니라 지켜보는 것이다. 학습이 잘 가고 있는지, 망가지고 있는지를 곡선으로 읽는다.

무엇을 보는가

손실 곡선

학습 손실과 검증 손실을 함께 본다. 둘 다 내려가면 정상, 검증 손실이 올라가면 과적합, 학습 손실도 안 내려가면 과소적합이거나 학습률 문제다.

정확도 곡선

학습·검증 정확도를 함께 본다. 손실과 방향이 보통 반대다. 검증 정확도가 정체되거나 떨어지면 멈출 때가 가까운 것이다.

학습/검증 격차

두 곡선 사이의 벌어진 간격이 일반화 격차다. 격차가 점점 커지면 과적합이 진행 중이라는 신호다.

조기 종료 시점

검증 손실이 일정 에폭 동안 더 좋아지지 않으면 멈춘다. 그때까지의 가장 좋았던 가중치를 최종 모델로 쓴다.

이런 모니터링은 보통 TensorBoard, Weights & Biases 같은 도구로 실시간 그래프를 보면서 한다. 곡선이 이상하면(손실이 튀거나, NaN이 뜨거나, 전혀 안 내려가거나) 학습이 끝나기를 기다릴 필요 없이 바로 멈추고 원인을 찾는 것이 시간을 아끼는 길이다.

곡선은 거짓말을 하지 않는다 학습이 잘 안 될 때 모델 구조를 의심하기 전에 곡선부터 본다. 학습 손실이 안 내려가면 학습률·데이터·라벨 문제이고, 학습 손실은 내려가는데 검증 손실이 올라가면 과적합이다. 곡선의 모양만 봐도 다음에 무엇을 해야 할지 대부분 답이 나온다.

산업 비전 관점의 학습

지금까지의 내용은 딥러닝 학습 일반론이지만, 산업 비전에는 일반적인 분류 문제와 다른 결정적 제약이 있다. 결함 데이터가 극도로 적다는 것이다.

정상은 넘치고 결함은 귀하다

잘 관리되는 생산 라인일수록 불량률이 낮다. 불량률이 0.1%라면, 결함 이미지 1,000장을 모으려면 정상 이미지 100만 장을 찍어야 한다는 뜻이다. 게다가 결함의 종류는 다양한데 각 종류별로는 더더욱 샘플이 적다. 처음 보는 새로운 결함은 아예 학습 데이터에 없을 수도 있다. 이것이 산업 비전 딥러닝의 근본 난제다.

적은 데이터에 대응하는 전략

결함 데이터 부족에 대응하는 네 가지 축

1. 데이터 증강 — 가진 결함 이미지를 조명·각도·노이즈 변형으로 최대한 다양화한다. 단, 현장에서 일어날 법한 변형만.
2. 전이학습 — 사전학습 모델에서 출발해 적은 데이터로도 학습이 되게 한다. 산업 비전에서는 거의 기본이다.
3. 이상탐지 접근 — 결함을 분류로 학습하는 대신, 정상 이미지만 잔뜩 학습시켜 "정상에서 벗어난 것"을 결함으로 본다. 결함 샘플이 거의 없어도 동작하며, 이 시리즈 9편에서 다룬다.
4. 라벨 효율적 태스크 설계 — 픽셀 마스크가 꼭 필요한 게 아니라면 분류나 검출로 낮춰 라벨 부담을 줄인다.

"정상 위주 데이터"는 약점이자 기회 결함이 적은 것은 분류 학습 입장에서는 약점이지만, 정상이 풍부한 것은 이상탐지 입장에서는 강점이다. 풀려는 문제를 "결함을 분류한다"에서 "정상이 아닌 것을 찾는다"로 바꾸면, 데이터의 불균형이 오히려 유리하게 작동한다. 산업 비전 딥러닝은 이 발상의 전환을 자주 활용한다.

흔한 실수 정리

마지막으로, 학습 실전에서 반복적으로 나오는 실수를 모았다. 대부분 "점수는 잘 나왔는데 현장에서 안 된다"로 이어지는 것들이다.

실수 무슨 일이 벌어지는가 올바른 방법
테스트셋으로 튜닝 테스트셋 점수를 보고 하이퍼파라미터를 고른다 — 데이터 누수다. 점수는 부풀려지고 현장 성능은 낮다. 튜닝은 검증셋으로만. 테스트셋은 끝나고 단 한 번.
검증 없이 학습 검증셋을 안 만들면 과적합을 감지할 수단이 없다. 언제 멈출지도 모른다. 학습·검증·테스트 세 묶음을 처음부터 나눈다.
증강을 테스트셋에도 적용 평가가 실제 분포와 어긋나고, 원본·변형본이 섞이는 누수가 생긴다. 증강은 학습셋에만. 검증·테스트는 원본 그대로.
클래스 불균형 무시 결함 5%인 데이터에서 "전부 정상"이라 찍어도 정확도 95%다. 정확도만 보면 속는다. 층화 분할 + 정밀도·재현율 등 불균형에 강한 지표 사용.
학습 곡선 안 보고 에폭 고정 "100 에폭"으로 고정해 두면 과소적합이거나 과적합이거나 둘 중 하나다. 곡선을 보며 Early Stopping에 종료를 맡긴다.
같은 대상이 분할을 가로지름 같은 부품·로트의 이미지가 학습·테스트에 나뉘면 누수다. 분할은 이미지가 아니라 독립된 대상 단위로.
모든 누수는 같은 증상을 보인다 데이터 누수의 종류는 다양하지만 결과는 똑같다 — 학습·검증 점수는 훌륭한데 현장에서 무너진다. 학습 결과가 "너무 좋아 보일 때"는 기뻐하기 전에 누수를 의심하는 습관이 필요하다. 점수가 의심스러울 만큼 높으면 대개 어딘가에서 정답을 미리 본 것이다.
다음 편 예고 이 글에서는 데이터셋을 만들고 학습을 운영하는 실전 감각을 다뤘다. 다음 6편에서는 그렇게 학습한 모델의 성능을 어떻게 측정하는지 — 이미지 분류 태스크의 정의와 정확도·정밀도·재현율·혼동행렬 같은 평가지표를 살펴본다.
