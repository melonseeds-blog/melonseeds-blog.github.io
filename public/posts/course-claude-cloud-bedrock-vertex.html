왜 Claude를 클라우드로 배포하는가

두 강의 모두 첫 모듈에서 같은 질문에 답한다. "Anthropic Direct API가 있는데 왜 Bedrock/Vertex AI를 쓰나?" 답은 거의 동일하다.

  • 이미 AWS/GCP를 쓰고 있다면 동일 청구·동일 권한 체계로 통합
  • 데이터 거주(Data Residency) 요건 충족 — 지정 리전에서만 데이터 처리
  • VPC/Private 네트워크 안에서만 호출 가능
  • 엔터프라이즈 컴플라이언스(HIPAA, GDPR, FedRAMP 등)를 클라우드 인증으로 흡수
  • IAM/감사 로그가 기존 클라우드 도구(CloudTrail, Cloud Audit Logs)와 일원화됨
핵심 메시지 강의 결론은 일관된다 — Claude 모델 자체와 사용법(시스템 프롬프트, Tool Use, 캐싱, RAG)은 어느 플랫폼에서나 동일하다. 다른 건 인증·청구·네트워크 경계뿐이다.

Amazon Bedrock의 Claude

Amazon Bedrock 한 줄 요약

AWS의 관리형 파운데이션 모델 서비스. Claude, Titan, Llama 등 여러 모델을 통일된 API(boto3)로 호출하고, IAM/리전/VPC 통합을 그대로 활용한다.

시작 절차

  1. AWS 콘솔 → Bedrock → Model access에서 사용할 Claude 모델 활성화 요청
  2. IAM 사용자/역할에 bedrock:InvokeModel, bedrock:InvokeModelWithResponseStream 권한 부여
  3. 리전 선택 — Claude 모델이 제공되는 리전이 한정적(us-east-1, us-west-2 등 위주)
  4. boto3 또는 anthropic[bedrock] 패키지 설치

두 가지 호출 방법

Bedrock에서 Claude를 부르는 SDK는 두 가지가 있다.

# 방법 A: boto3로 직접 호출 import boto3, json client = boto3.client("bedrock-runtime", region_name="us-east-1") resp = client.invoke_model( modelId="anthropic.claude-opus-4-5-20251101-v1:0", body=json.dumps({ "anthropic_version": "bedrock-2023-05-31", "max_tokens": 1024, "messages": [{"role": "user", "content": "Hello"}], }), )
# 방법 B: anthropic SDK + Bedrock 백엔드 (강의 권장) from anthropic import AnthropicBedrock client = AnthropicBedrock(aws_region="us-east-1") resp = client.messages.create( model="anthropic.claude-opus-4-5-20251101-v1:0", max_tokens=1024, messages=[{"role": "user", "content": "Hello"}], )

강의는 방법 B를 강력히 권장한다. Anthropic Direct API에서 쓰던 코드를 거의 그대로 옮길 수 있고, Tool Use·Streaming·캐싱 같은 기능을 동일한 인터페이스로 쓴다.

Bedrock 특유 개념

  • Model ID는 anthropic.claude-{name}-{date}-v1:0 형식이다. 날짜가 포함된 명시적 버전.
  • Inference Profile — 크로스 리전 추론을 묶어주는 ID. 한 리전에서 capacity가 부족하면 자동 분산.
  • Provisioned Throughput — 고정 처리량 예약. 비싸지만 SLA가 확실.
  • Guardrails — AWS가 제공하는 콘텐츠 필터. Bedrock 레벨에서 입출력 검사.

Google Vertex AI의 Claude

Google Vertex AI 한 줄 요약

GCP의 통합 ML 플랫폼. Model Garden을 통해 Anthropic Claude를 GCP 프로젝트 안의 1급 모델로 호출하고, IAM/리전/VPC Service Controls 통합을 그대로 활용한다.

시작 절차

  1. GCP 콘솔 → Vertex AI → Model Garden에서 사용할 Claude 모델 카드 → "Enable"
  2. 서비스 계정에 roles/aiplatform.user 권한 부여
  3. 리전 선택 — Claude 제공 리전(예: us-east5, europe-west1) 한정
  4. gcloud auth application-default login 또는 서비스 계정 키로 인증
  5. anthropic[vertex] 패키지 설치

호출 방법

from anthropic import AnthropicVertex client = AnthropicVertex(region="us-east5", project_id="my-gcp-project") resp = client.messages.create( model="claude-opus-4-5@20251101", max_tokens=1024, messages=[{"role": "user", "content": "Hello"}], )

Vertex AI 특유 개념

  • Model ID는 claude-{name}@{date} 형식. Bedrock과 다른 표기.
  • Application Default Credentials(ADC) — 명시적 키 없이 환경의 자격증명을 자동 사용.
  • Model Garden — 1·3자 모델을 한 곳에 모아 발견·활성화·평가하는 GCP 마켓.
  • VPC Service Controls — 프로젝트 외부로 데이터가 나가지 못하도록 경계 설정.
  • Quota는 프로젝트+리전 단위. 사전 증액 신청 필요한 경우 많음.

SDK 호환성이 핵심 장점 Anthropic SDK는 세 백엔드 모두에서 client.messages.create(...) 호출 인터페이스가 동일하다. 백엔드 전환이 클래스 한 줄 교체로 끝나기 때문에, Direct API로 프로토타입하고 운영은 Bedrock/Vertex로 옮기는 패턴이 자연스럽다.

선택 가이드

Bedrock을 고르는 경우

  • 이미 AWS 위에 인프라가 있다
  • IAM 정책으로 권한을 통제하고 싶다
  • S3·Lambda·Step Functions와 자연스럽게 연결
  • Guardrails로 입출력 필터를 강제하고 싶다
  • 크로스 리전 분산(Inference Profile)이 필요하다

Vertex AI를 고르는 경우

  • 이미 GCP 위에 인프라가 있다
  • BigQuery 데이터와 직접 연동
  • VPC Service Controls로 강한 경계가 필요
  • Model Garden에서 다른 모델과 함께 비교/평가
  • GKE·Cloud Run 기반 서비스에 통합
그럼 Anthropic Direct는 언제?
  • 최신 기능을 가장 빨리 써보고 싶을 때
  • 특정 클라우드에 묶이고 싶지 않을 때
  • 프로토타입·연구·소규모 SaaS
  • Claude Code, Claude Desktop의 기본 백엔드로 쓸 때

실무 적용 포인트

1. SDK 추상화로 백엔드 갈아끼우기 가능하게 두기

코드에서 클라이언트 생성을 한 곳에 모아두면, 환경변수 한 줄로 Direct ↔ Bedrock ↔ Vertex 전환이 가능하다. 프로토타입은 Direct, 운영은 사내 정책에 맞는 클라우드로 옮기는 흐름이 자연스럽다.

def make_client(): backend = os.environ.get("CLAUDE_BACKEND", "direct") if backend == "bedrock": return AnthropicBedrock(aws_region=os.environ["AWS_REGION"]) if backend == "vertex": return AnthropicVertex(region=..., project_id=...) return Anthropic() # direct

2. 모델 ID는 환경변수/설정 파일로

모델 ID 형식이 세 군데 다 다르기 때문에, 코드에 하드코딩하면 백엔드 전환이 어려워진다. 항상 설정으로 빼두는 게 안전하다.

3. 리전과 데이터 거주 요건 확인

제품이 한국 고객을 대상으로 한다면 데이터가 어느 리전을 거치는지가 컴플라이언스 이슈가 된다. Bedrock/Vertex 모두 Claude 제공 리전이 한정적이라, 도입 전에 리전 매트릭스를 확인해야 한다.

4. 신기능 의존성 점검

Citations, Files API, Code Execution 같은 비교적 새 기능은 클라우드 백엔드에서 늦거나 일부만 지원될 수 있다. 운영을 Bedrock/Vertex로 옮기기 전에 사용 중인 기능이 그쪽에서 동작하는지 미리 확인해야 한다.

5. 평가(eval) 데이터셋은 백엔드 독립으로

메인 강의에서 다룬 프롬프트 평가 워크플로우는 백엔드와 무관하다. eval 코드를 잘 만들어두면 백엔드를 옮길 때 회귀 검증을 그대로 돌릴 수 있다.

한 줄 결론 Bedrock과 Vertex AI는 Claude의 또 다른 출입구다. 모델·SDK·기능은 거의 같고, 차이는 인증/청구/네트워크 경계뿐이다. 본격적인 학습은 메인 강의 정리에서, 운영 환경 선택은 이 글에서 참고하면 된다.
