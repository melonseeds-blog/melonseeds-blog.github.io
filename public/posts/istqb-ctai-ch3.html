CT-AI 3장은 머신러닝 자체를 다루는 유일한 장이다. 분량 145분으로 1, 2장보다 무겁고, 이후 Ch4 ML 데이터(230분), Ch5 측정지표, Ch6 신경망의 모든 기반이 여기서 깔린다. 모델을 직접 만들지 않는 테스터라도, 워크플로우의 어느 단계에서 무엇이 잘못될 수 있는지 알아야 한다.

3.1 머신러닝의 네 가지 형태

실러버스는 ML을 학습 신호의 형태에 따라 네 가지로 분류한다.

형태입력학습 신호대표 작업
지도 학습
(Supervised)		입력 X + 라벨 YX→Y 매핑분류, 회귀
비지도 학습
(Unsupervised)		입력 X만데이터 내재 구조클러스터링, 차원 축소, 이상 탐지
강화 학습
(Reinforcement)		상태 + 행동 + 보상누적 보상 최대화게임 플레이, 로봇 제어, 자율주행 정책
자가 학습
(Self-supervised)		입력 X에서 자체 생성한 의사 라벨입력 일부로 다른 일부 예측대형 언어 모델 사전훈련, 이미지 표현 학습

산업 적용 관점

  • 비전 결함 분류 — 지도 학습 (라벨링이 가장 큰 비용)
  • 설비 이상 탐지 — 비지도 학습 또는 준지도 학습
  • 로봇 픽업 정책 — 강화학습 (시뮬레이션 활용)
  • 비전 사전훈련 백본 — 자가 학습 (SimCLR, MAE 등)
준지도 학습(Semi-supervised) 라벨 데이터 소수 + 라벨 없는 데이터 다수를 함께 활용한다. 실러버스의 네 카테고리에는 별도 항목이 없지만 시험 보기에 등장할 수 있다.

3.2 분류와 회귀

지도 학습의 두 핵심 작업이다. 출력 변수의 성격으로 구분한다.

분류 (Classification)

출력이 이산적 클래스인 작업이다.

  • 이진 분류 — 합/불, 정상/불량, 스팸/정상
  • 다중 분류 — 결함 유형 10종 분류, 손글씨 숫자 0~9
  • 다중 라벨 분류 — 한 이미지에 여러 라벨 동시 할당 (사람+자전거+나무)

대표 지표: 정확도, 정밀도, 재현율, F1, AUC. Ch5 ML 측정지표에서 상세히 다룬다.

회귀 (Regression)

출력이 연속 수치인 작업이다.

  • 치수 측정값 예측 (mm 단위)
  • 주가/수요 예측
  • 장비 잔여 수명(RUL) 추정

대표 지표: MAE, MSE, RMSE, R².

시험 함정 '확률 출력 = 회귀'가 아니다. 이진 분류기가 0~1의 확률을 출력해도 본질은 분류다. 출력값 자체가 '의미 있는 연속 수치(치수, 시간, 가격)'일 때만 회귀로 본다.

3.3 클러스터링과 차원 축소

비지도 학습의 두 대표 작업이다.

클러스터링 (Clustering)

유사한 데이터끼리 그룹으로 묶는다. 라벨 없이도 데이터 구조를 파악할 수 있다.

  • 대표 알고리즘: K-Means, DBSCAN, 계층적 클러스터링
  • 활용: 고객 세분화, 결함 패턴 발견, 이상 탐지의 사전 단계

차원 축소 (Dimensionality Reduction)

고차원 데이터를 더 적은 수의 의미 있는 특성으로 축약한다.

  • 대표 알고리즘: PCA, t-SNE, UMAP, 오토인코더
  • 활용: 시각화, 노이즈 제거, 다음 단계 모델의 입력 차원 축소

3.4 강화학습 보상 시스템

강화학습(RL)의 핵심 구성요소는 다음과 같다.

  • 에이전트(Agent) — 행동을 선택하는 주체
  • 환경(Environment) — 에이전트가 상호작용하는 세계
  • 상태(State) — 현재 환경 정보
  • 행동(Action) — 에이전트의 선택
  • 보상(Reward) — 행동 결과에 대한 스칼라 평가
  • 정책(Policy) — 상태→행동 매핑

보상 설계의 어려움

보상은 RL 시스템의 '목적 함수'다. 설계가 잘못되면 2.6 보상 해킹으로 직결된다.

  • 희소 보상 — 보상이 너무 드물면 학습이 어렵다 (보상 셰이핑 필요)
  • 대리 보상의 오정렬 — "결승선 통과" 대신 "점수 획득"을 보상하면 에이전트는 점수만 모은다
  • 안전 보상 — 위험 행동에 큰 음의 보상을 주지 않으면 학습 과정에서 사고 발생
테스팅 관점

RL 시스템의 테스트는 '정책이 모든 가능 상태에서 안전한가'를 묻는다. 정상 시나리오만이 아니라 적대적/희귀 시나리오를 생성해 정책의 거동을 관찰해야 한다. 시뮬레이션 환경에서 대규모 시나리오 커버리지를 만드는 것이 일반적이다.

3.5 ML 워크플로우

실러버스가 제시하는 ML 워크플로우는 다음 7단계 흐름이다. 각 단계는 독립된 테스팅 대상이다.

단계내용테스팅 포인트
1. 목표 이해비즈니스 문제를 ML 문제로 변환지표가 실제 목적을 반영하는가
2. 데이터 수집학습/검증/테스트 데이터 확보대표성, 충분성, 라이선스
3. 데이터 준비/전처리정제, 라벨링, 특성 공학, 분할누수(leakage), 라벨 품질
4. 알고리즘 선택모델 종류와 구조 결정요구 성능/지연/메모리 충족 가능성
5. 학습/튜닝훈련 + 하이퍼파라미터 탐색과적합/과소적합 진단
6. 평가테스트 세트로 최종 평가편향, 강건성, 공정성 평가
7. 배포/모니터링운영 환경에 배포 후 지속 관측컨셉 드리프트, 성능 저하

워크플로우의 반복성

이 흐름은 일직선이 아니라 반복 루프다. 평가 결과가 만족스럽지 않으면 데이터 준비 또는 알고리즘 선택으로 돌아간다. 배포 후 모니터링에서 성능 저하가 감지되면 데이터 수집부터 다시 시작한다.

3.6 훈련/검증/테스트 데이터 세트

ML에서 데이터는 세 갈래로 분할된다. 각 세트는 명확한 역할이 있다.

세트역할비고
훈련 세트
(Training Set)		모델 파라미터(가중치) 학습가장 큰 비중. 보통 60~80%
검증 세트
(Validation Set)		하이퍼파라미터 튜닝, 모델 선택, 조기 종료학습 과정에서 반복 사용. 10~20%
테스트 세트
(Test Set)		최종 성능 평가. 단 한 번만 사용운영 분포를 반영해야 함. 10~20%

분리 원칙

  • 세트 간 중복 금지 — 같은 샘플이 두 세트에 들어가면 평가가 부풀려진다
  • 그룹 단위 분리 — 동일 환자의 다른 영상, 동일 부품의 다른 시점 사진은 같은 세트로 묶어야 한다
  • 시간순 분리 — 시계열 데이터는 미래로 테스트, 과거로 훈련 (반대 금지)
  • 테스트 세트는 진짜 마지막에 — 하이퍼파라미터 결정에 사용하면 정보 누수가 발생
데이터 누수 (Data Leakage) 검증/테스트 세트의 정보가 어떤 형태로든 학습 과정에 들어가는 현상. '훈련 정확도 99%, 테스트 정확도 60%' 같은 비정상적 격차로 드러나기 쉽다. 특성 공학에서 전체 데이터의 평균/분산을 사용하는 것도 누수다(훈련 세트로만 통계를 잡아야 함).

교차 검증 (Cross-validation)

데이터가 적을 때 검증 세트를 따로 떼지 않고, k개 폴드로 나눠 돌아가며 검증한다. K-Fold, Stratified K-Fold, Leave-One-Out 등이 있다.

3.7 과적합과 과소적합

모델 일반화 실패의 두 모드다. CT-AI에서 자주 출제되며 진단과 대응을 같이 묻는다.

과적합 (Overfitting)

모델이 학습 데이터에 너무 잘 맞아, 훈련 성능은 높지만 테스트/운영 성능은 낮은 상태다. 학습 데이터의 노이즈까지 외워버린 상황이다.

  • 원인: 모델 용량 과다, 데이터 부족, 학습 너무 길게, 정규화 부족
  • 대응: 데이터 추가, 데이터 증강, 정규화(L1/L2/Dropout), 조기 종료, 단순한 모델, 교차 검증

과소적합 (Underfitting)

모델이 학습 데이터의 패턴조차 충분히 잡지 못한 상태다. 훈련 성능도 낮고 테스트 성능도 낮다.

  • 원인: 모델 용량 부족, 특성 부족, 학습 부족, 과도한 정규화
  • 대응: 더 큰/복잡한 모델, 특성 추가, 학습 시간 연장, 정규화 약화
증상훈련 성능검증 성능진단
낮음 + 낮음낮음낮음과소적합
높음 + 낮음높음낮음 (격차 큼)과적합
높음 + 높음높음높음 (격차 작음)적정
편향-분산 트레이드오프 과소적합은 모델 편향(bias)이 큰 상태, 과적합은 모델 분산(variance)이 큰 상태로도 표현된다. 여기서 '편향'은 2.4의 사회적 편향과 다른 통계 개념이다.

3.8 컨셉 드리프트 (Concept Drift)

컨셉 드리프트는 시간이 지나면서 입력 데이터의 분포 또는 입력-출력 관계가 변하는 현상이다. 학습 시점에는 정확했던 모델이 운영 중 점점 무뎌진다.

드리프트의 종류

  • 점진적 드리프트 — 천천히 변화. 카메라 렌즈 오염, 계절 변화
  • 급격한 드리프트 — 한 시점에 갑자기 변화. 신규 제품 라인 도입, 조명 교체
  • 반복적 드리프트 — 주기적으로 돌아옴. 주야 차이, 계절성
  • 가상 드리프트(virtual drift) — 입력 분포만 변하고 결정 경계는 동일

대응

  • 운영 중 입력 분포와 출력 분포를 지속 모니터링
  • 성능 지표 임계치 이탈 시 알람
  • 주기적 재학습 또는 온라인 학습
  • 안전 시스템은 드리프트 감지 시 안전 모드로 fallback
실무 사례 — 산업 비전의 컨셉 드리프트

금속 표면 결함 분류기를 6개월 운영하니 정확도가 92%→78%로 떨어졌다. 원인은 공급사가 원재료 표면 처리 공정을 바꾼 것. 입력 영상의 텍스처 통계가 변했고(공변량 시프트), 학습 데이터가 그 분포를 포함하지 않았다. 대응은 새 공정 샘플 1,000장 추가 + 재학습.

연습 문제

Q1 (AI-3.1 K2)
다음 중 비지도 학습(Unsupervised Learning) 작업에 해당하는 것은?
  • a) 라벨링된 X선 이미지로 폐렴 유무를 분류
  • b) 가격이 라벨된 부동산 데이터로 시세를 예측
  • c) 라벨 없는 고객 거래 데이터에서 유사 고객을 K-Means로 묶음
  • d) 게임에서 보상을 최대화하는 행동 정책을 학습
정답: c)
라벨 없는 데이터에서 구조(클러스터)를 찾는 K-Means는 전형적인 비지도 학습이다. a, b는 지도 학습, d는 강화 학습이다.
Q2 (AI-3.7 K2)
학습된 분류기의 훈련 정확도가 99%, 검증 정확도가 65%로 큰 격차가 나타났다. 가장 가능성 높은 진단과 대응 조합은?
  • a) 과소적합 — 더 단순한 모델로 교체한다
  • b) 과적합 — 정규화 강화, 데이터 증강, 조기 종료를 검토한다
  • c) 데이터 누수 — 더 큰 모델로 교체한다
  • d) 컨셉 드리프트 — 학습 epoch를 늘린다
정답: b)
훈련↑/검증↓ 격차는 과적합의 전형이다. 모델 용량 축소, 정규화, 데이터 증강, 조기 종료가 표준 대응이다. 데이터 누수도 비슷한 패턴을 만들 수 있지만 그 경우 더 큰 모델은 해결책이 아니다.
Q3 (AI-3.6 K2)
훈련/검증/테스트 데이터 세트의 사용 원칙에 대한 설명으로 옳은 것을 두 가지 고르시오.
  • a) 테스트 세트로 하이퍼파라미터를 튜닝해야 한다
  • b) 동일 환자의 여러 영상은 같은 세트로 묶어야 한다
  • c) 시계열 데이터는 무작위 분할이 가장 안전하다
  • d) 검증 세트는 모델 선택 및 조기 종료에 사용한다
정답: b), d)
b는 그룹 단위 분리(group-aware split)의 원칙. d는 검증 세트의 정확한 역할. a는 테스트 정보 누수, c는 시간 누수(미래 정보로 과거 예측)를 일으키는 잘못된 선택이다.
Q4 (AI-3.8 K2)
'컨셉 드리프트(Concept Drift)'에 대한 설명으로 가장 적절한 것은?
  • a) 모델 학습 중 그래디언트가 발산하는 현상
  • b) 학습 데이터에 과도하게 적합되어 일반화가 실패하는 현상
  • c) 시간이 지나면서 입력 데이터 분포 또는 입력-출력 관계가 변하는 현상
  • d) 강화학습 보상 함수의 허점을 에이전트가 파고드는 현상
정답: c)
컨셉 드리프트는 운영 환경의 통계적 변화로 인해 모델 성능이 시간에 따라 저하되는 현상이다. b는 과적합, d는 보상 해킹에 대한 설명이다.
