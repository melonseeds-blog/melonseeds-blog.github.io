블롭(Blob)이란?

블롭(Blob, Binary Large OBject)은 이진 영상에서 서로 연결된 픽셀들이 이루는 하나의 덩어리다. 쉽게 말해 배경과 구분되는 객체 하나다. 검사 영상에서 부품 한 개, 구멍 한 개, 이물 한 점이 각각 하나의 블롭이 된다.

블롭 분석(Blob Analysis)은 이렇게 찾아낸 각 덩어리의 특징 — 면적, 위치, 모양 — 을 측정하고, 그 수치로 객체를 분류하거나 판정하는 작업이다. 산업 비전에서 "부품이 몇 개 있는가", "이 점은 정상 구멍인가 이물인가", "찍혀야 할 마크가 빠지지 않았는가" 같은 질문은 모두 블롭 분석으로 답한다.

전체 흐름은 단순하다. 원본 영상을 이진화해서 객체와 배경을 가르고 → 연결된 픽셀을 묶어 블롭을 식별하고 → 각 블롭의 특징을 측정하고 → 그 특징으로 걸러내거나 판정한다.

블롭 분석 파이프라인 — 이진화로 객체를 분리하고, 라벨링으로 덩어리를 식별하고, 특징으로 판정한다.
블롭 분석의 입력은 항상 이진 영상이다 블롭 분석은 픽셀이 객체(보통 255)인지 배경(0)인지가 이미 정해진 상태에서 시작한다. 그래서 이진화(threshold) 품질이 블롭 분석 결과를 사실상 결정한다. 이 글은 이진 영상이 준비되었다고 가정하고 진행한다.

연결성 — 4-연결 vs 8-연결

"픽셀이 연결되어 있다"를 정의하려면 어느 이웃까지 연결로 볼 것인가를 정해야 한다. 이것이 연결성(connectivity)이다. 두 가지 기준이 쓰인다.

  • 4-연결 — 상하좌우 4개 이웃만 연결로 본다. 대각선은 연결로 치지 않는다.
  • 8-연결 — 상하좌우 + 대각선 4개까지 8개 이웃 전부를 연결로 본다.
같은 픽셀 P라도 4-연결은 상하좌우만, 8-연결은 대각선까지 이웃으로 본다.

연결성을 어떻게 잡느냐에 따라 블롭 개수가 달라진다. 대각선으로만 닿아 있는 두 영역은 4-연결에서는 별개의 블롭 2개, 8-연결에서는 하나로 합쳐진 블롭 1개가 된다. 산업 검사에서는 객체가 대각선으로 살짝 이어진 경우를 한 덩어리로 보고 싶을 때가 많아 8-연결을 기본으로 쓴다.

4-연결과 8-연결을 혼동하면 개수가 어긋난다 같은 영상에서 4-연결로 세면 5개, 8-연결로 세면 3개가 나올 수 있다. 검사 스펙에 "개수 N개"가 박혀 있다면 어떤 연결성으로 센 N인지 반드시 통일해야 한다. 코드 곳곳에서 연결성 값을 제각각 쓰면 디버깅이 지옥이 된다.

connectedComponents — 라벨링

OpenCV의 cv::connectedComponents는 이진 영상을 받아 연결된 픽셀 덩어리마다 고유한 정수 라벨을 부여한다. 결과는 원본과 같은 크기의 라벨 영상(CV_32S)이다. 배경은 라벨 0, 첫 번째 블롭은 1, 두 번째는 2 ... 식으로 번호가 매겨진다.

#include <opencv2/opencv.hpp>
#include <iostream>

int main()
{
    // 그레이스케일로 읽어서 이진화한다
    cv::Mat src = cv::imread("parts.png", cv::IMREAD_GRAYSCALE);
    if (src.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    cv::Mat binary;
    cv::threshold(src, binary, 0, 255, cv::THRESH_BINARY | cv::THRESH_OTSU);

    // 8-연결로 라벨링. labels는 CV_32S 라벨 영상
    cv::Mat labels;
    int count = cv::connectedComponents(binary, labels, 8, CV_32S);

    // count는 배경(0)을 포함한 라벨 개수 → 실제 블롭 수는 count - 1
    std::cout << "라벨 개수(배경 포함): " << count << std::endl;
    std::cout << "블롭 개수: " << count - 1 << std::endl;
    return 0;
}
실행 결과 (콘솔)
라벨 개수(배경 포함): 4 블롭 개수: 3

반환값 count는 배경 라벨 0을 포함한 총 라벨 수다. 그래서 실제 객체 개수는 항상 count - 1이다. 이 한 칸 차이를 놓치면 개수가 하나씩 어긋난다.

라벨 영상을 눈으로 확인하려면 라벨마다 다른 색을 입혀 컬러 맵으로 만든다.

// 라벨 영상을 색상으로 시각화한다
cv::Mat ColorizeLabels(const cv::Mat& labels, int count)
{
    // 라벨별 임의 색상 테이블 — 배경(0)은 검정
    std::vector<cv::Vec3b> colors(count);
    colors[0] = cv::Vec3b(0, 0, 0);
    cv::RNG rng(12345);
    for (int i = 1; i < count; ++i)
    {
        colors[i] = cv::Vec3b(rng.uniform(50, 255),
                              rng.uniform(50, 255),
                              rng.uniform(50, 255));
    }

    cv::Mat colored(labels.size(), CV_8UC3);
    for (int y = 0; y < labels.rows; ++y)
    {
        for (int x = 0; x < labels.cols; ++x)
        {
            int label = labels.at<int>(y, x);
            colored.at<cv::Vec3b>(y, x) = colors[label];
        }
    }
    return colored;
}
라벨 영상은 CV_32S다 — imshow로 바로 못 본다 라벨 영상은 정수 라벨이 담긴 32비트 행렬이라 그대로 imshow하면 거의 검은 화면처럼 보인다. 라벨 1, 2, 3은 255단계 밝기에서 거의 0에 가깝기 때문이다. 항상 색을 입히거나 정규화해서 확인한다.

connectedComponentsWithStats — 통계까지

실무에서는 라벨만으로는 부족하다. 각 블롭이 어디에 얼마나 크게 있는지 알아야 한다. cv::connectedComponentsWithStats는 라벨링과 동시에 블롭마다 통계 행렬과 중심 좌표를 한 번에 돌려준다.

cv::Mat labels, stats, centroids;
int count = cv::connectedComponentsWithStats(
    binary, labels, stats, centroids, 8, CV_32S);

// 라벨 0은 배경이므로 1부터 순회한다
for (int i = 1; i < count; ++i)
{
    int x      = stats.at<int>(i, cv::CC_STAT_LEFT);    // 바운딩박스 좌측 x
    int y      = stats.at<int>(i, cv::CC_STAT_TOP);     // 바운딩박스 상단 y
    int w      = stats.at<int>(i, cv::CC_STAT_WIDTH);   // 바운딩박스 너비
    int h      = stats.at<int>(i, cv::CC_STAT_HEIGHT);  // 바운딩박스 높이
    int area   = stats.at<int>(i, cv::CC_STAT_AREA);    // 면적(픽셀 수)

    double cx  = centroids.at<double>(i, 0);            // 중심 x
    double cy  = centroids.at<double>(i, 1);            // 중심 y

    std::cout << "블롭 #" << i
              << "  area=" << area
              << "  bbox=(" << x << "," << y << "," << w << "," << h << ")"
              << "  centroid=(" << cx << "," << cy << ")"
              << std::endl;
}
실행 결과 (콘솔)
블롭 #1 area=1017 bbox=(42,30,38,36) centroid=(60.9,48.2) 블롭 #2 area=615 bbox=(91,106,29,28) centroid=(105.1,119.8) 블롭 #3 area=476 bbox=(70,130,34,14) centroid=(86.4,136.7)

stats는 count × 5 크기의 CV_32S 행렬이다. 행 인덱스가 라벨 번호이고, 5개 열이 각각 좌측 x, 상단 y, 너비, 높이, 면적을 담는다. 열은 인덱스 숫자 대신 아래 상수로 접근하는 게 안전하다.

상수열 인덱스의미
CC_STAT_LEFT0바운딩박스 좌측 x 좌표
CC_STAT_TOP1바운딩박스 상단 y 좌표
CC_STAT_WIDTH2바운딩박스 너비
CC_STAT_HEIGHT3바운딩박스 높이
CC_STAT_AREA4블롭 면적 (실제 픽셀 수)

centroids는 count × 2 크기의 CV_64F 행렬이다. 열 0이 중심 x, 열 1이 중심 y다. 면적 가중 평균 위치라서 소수점을 가진다 — at<double>로 읽어야 하며, stats처럼 at<int>로 읽으면 깨진 값이 나온다.

0번 행은 배경이다 — 무심코 포함하면 안 된다 stats와 centroids의 0번 행은 배경의 통계다. 배경 면적은 보통 영상 전체에서 객체를 뺀 거대한 값이라, 루프를 i=0부터 돌리면 "면적이 가장 큰 블롭"이 항상 배경으로 잡힌다. 반드시 i=1부터 순회한다.

블롭 특징 — 면적·중심·원형도

connectedComponentsWithStats가 직접 주는 건 면적·바운딩박스·중심뿐이다. 둘레, 원형도, 종횡비, 채움률 같은 모양 특징은 직접 계산해야 한다. 둘레처럼 윤곽이 필요한 특징은 해당 블롭 마스크에서 윤곽을 뽑아 구한다.

특징정의용도
면적 (Area)블롭을 이루는 픽셀 수크기 검사, 노이즈 제거
중심 (Centroid)블롭 픽셀 좌표의 평균 위치위치 측정, 정렬 검사
바운딩박스 (Bounding Box)블롭을 감싸는 최소 직사각형크롭, 위치/크기 1차 판정
둘레 (Perimeter)윤곽선의 길이원형도 계산의 입력
원형도 (Circularity)4π·면적 / 둘레² — 1에 가까울수록 원원/비원 구분
종횡비 (Aspect Ratio)바운딩박스 너비 / 높이길쭉한 객체 골라내기
채움률 (Extent)면적 / 바운딩박스 넓이채워진 정도, 빈 모양 판별
볼록성 (Solidity)면적 / 볼록껍질 면적 — 1에 가까울수록 매끈요철/오목 결함 검출
방향 (Orientation)장축이 향하는 각도회전 검사, 자세 측정

여러 특징을 한 구조체에 모아 계산하면 이후 판정 로직이 깔끔해진다. 다음은 라벨 하나에 대해 특징을 추출하는 예다.

#include <opencv2/opencv.hpp>

struct BlobFeature
{
    int    label = 0;
    int    area = 0;
    cv::Point2d centroid;
    cv::Rect bbox;
    double perimeter = 0.0;
    double circularity = 0.0;   // 1.0에 가까우면 원
    double aspectRatio = 0.0;   // 너비 / 높이
    double extent = 0.0;        // 면적 / bbox 넓이
    double solidity = 0.0;      // 면적 / 볼록껍질 면적
};

// 라벨 i 블롭의 특징을 추출한다
BlobFeature ExtractFeature(const cv::Mat& labels,
                           const cv::Mat& stats,
                           const cv::Mat& centroids,
                           int i)
{
    BlobFeature f;
    f.label = i;
    f.area  = stats.at<int>(i, cv::CC_STAT_AREA);
    f.bbox  = cv::Rect(stats.at<int>(i, cv::CC_STAT_LEFT),
                       stats.at<int>(i, cv::CC_STAT_TOP),
                       stats.at<int>(i, cv::CC_STAT_WIDTH),
                       stats.at<int>(i, cv::CC_STAT_HEIGHT));
    f.centroid = cv::Point2d(centroids.at<double>(i, 0),
                             centroids.at<double>(i, 1));

    // 해당 라벨만 흰색인 마스크를 만든다
    cv::Mat mask = (labels == i);

    // 마스크에서 외곽 윤곽을 뽑아 둘레와 모양 특징을 계산한다
    std::vector<std::vector<cv::Point>> contours;
    cv::findContours(mask, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
    if (!contours.empty())
    {
        const auto& c = contours[0];
        f.perimeter = cv::arcLength(c, true);

        // 원형도 — 둘레가 0이면 0으로 둔다
        if (f.perimeter > 0.0)
        {
            f.circularity = 4.0 * CV_PI * f.area / (f.perimeter * f.perimeter);
        }

        // 볼록성 — 볼록껍질 면적 대비 실제 면적
        std::vector<cv::Point> hull;
        cv::convexHull(c, hull);
        double hullArea = cv::contourArea(hull);
        if (hullArea > 0.0)
        {
            f.solidity = f.area / hullArea;
        }
    }

    // 종횡비와 채움률은 바운딩박스로 계산한다
    if (f.bbox.height > 0)
    {
        f.aspectRatio = static_cast<double>(f.bbox.width) / f.bbox.height;
    }
    int bboxArea = f.bbox.width * f.bbox.height;
    if (bboxArea > 0)
    {
        f.extent = static_cast<double>(f.area) / bboxArea;
    }
    return f;
}
원형도는 스케일에 무관한 특징이다 면적이나 둘레는 객체가 카메라에 가까워지면 값이 커진다. 하지만 원형도(4πA/P²), 종횡비, 채움률, 볼록성은 비율이라 크기가 변해도 거의 일정하다. 그래서 거리나 배율이 조금씩 변하는 환경에서는 면적 같은 절대값보다 비율 특징이 더 안정적인 판정 기준이 된다.

특징 기반 필터링

특징을 뽑았으면 이제 걸러낸다. 블롭 분석의 핵심은 "찾은 블롭 전부"가 아니라 "조건에 맞는 블롭만" 남기는 것이다. 대표적인 세 가지 필터링 시나리오를 본다.

면적으로 노이즈 제거

이진화 과정에서 생긴 작은 점들은 진짜 객체가 아니다. 면적이 일정 값보다 작은 블롭을 버린다.

// 면적이 너무 작거나 너무 큰 블롭을 제거한 마스크를 만든다
const int kMinArea = 200;     // 이보다 작으면 노이즈
const int kMaxArea = 100000;  // 이보다 크면 배경 덩어리 등

cv::Mat cleaned = cv::Mat::zeros(labels.size(), CV_8UC1);
for (int i = 1; i < count; ++i)
{
    int area = stats.at<int>(i, cv::CC_STAT_AREA);
    if (area >= kMinArea && area <= kMaxArea)
    {
        // 유효한 블롭만 마스크에 다시 그린다
        cleaned.setTo(255, labels == i);
    }
}

원형도로 원/비원 구분

둥근 구멍만 통과시키고 찌그러진 것은 불량으로 빼낸다. 원형도가 기준 이상인 블롭만 OK로 본다.

const double kMinCircularity = 0.80;  // 0.8 이상이면 원으로 인정

std::vector<BlobFeature> roundBlobs;
for (int i = 1; i < count; ++i)
{
    BlobFeature f = ExtractFeature(labels, stats, centroids, i);
    if (f.circularity >= kMinCircularity)
    {
        roundBlobs.push_back(f);  // 둥근 블롭만 수집
    }
}
std::cout << "둥근 블롭: " << roundBlobs.size() << "개" << std::endl;

종횡비로 길쭉한 것 골라내기

스크래치나 머리카락 같은 가늘고 긴 이물은 종횡비가 크다. 종횡비로 길쭉한 결함만 추려낸다.

const double kElongatedRatio = 4.0;  // 가로:세로가 4:1 이상이면 길쭉함

for (int i = 1; i < count; ++i)
{
    BlobFeature f = ExtractFeature(labels, stats, centroids, i);
    // 종횡비는 가로/세로라 세로로 긴 경우도 잡으려면 역수도 본다
    double ratio = std::max(f.aspectRatio, 1.0 / f.aspectRatio);
    if (ratio >= kElongatedRatio)
    {
        std::cout << "길쭉한 이물 의심 — 블롭 #" << i
                  << " ratio=" << ratio << std::endl;
    }
}

복수 특징 조합 판정

실전 판정은 특징 하나로 끝나지 않는다. "면적이 정상 범위이고, 충분히 둥글고, 꽉 차 있어야" 양품으로 본다. 조건을 AND로 묶는다.

// 양품 조건 — 면적·원형도·채움률을 모두 만족해야 OK
bool IsGoodBlob(const BlobFeature& f)
{
    const int    kMinArea       = 800;
    const int    kMaxArea       = 1500;
    const double kMinCirc       = 0.85;
    const double kMinExtent     = 0.70;

    return f.area >= kMinArea
        && f.area <= kMaxArea
        && f.circularity >= kMinCirc
        && f.extent >= kMinExtent;
}

// 전체 블롭을 양품/불량으로 분류한다
int good = 0, bad = 0;
for (int i = 1; i < count; ++i)
{
    BlobFeature f = ExtractFeature(labels, stats, centroids, i);
    if (IsGoodBlob(f)) { ++good; }
    else               { ++bad; }
}
std::cout << "양품 " << good << " / 불량 " << bad << std::endl;

SimpleBlobDetector

OpenCV는 라벨링을 직접 다루지 않고도 블롭을 찾을 수 있는 내장 검출기 cv::SimpleBlobDetector를 제공한다. 내부적으로 여러 임계값으로 이진화한 뒤 공통으로 검출되는 영역을 블롭으로 잡고, 파라미터로 면적·원형도·볼록도·관성비를 한 번에 필터링한다. 직접 라벨링+특징추출 코드를 짜기 전에 빠르게 프로토타이핑할 때 유용하다.

#include <opencv2/opencv.hpp>

int main()
{
    cv::Mat src = cv::imread("dots.png", cv::IMREAD_GRAYSCALE);
    if (src.empty()) { return -1; }

    // 검출기 파라미터를 설정한다
    cv::SimpleBlobDetector::Params params;

    // 면적 필터 — 너무 작거나 큰 블롭 제외
    params.filterByArea = true;
    params.minArea = 100.0f;
    params.maxArea = 5000.0f;

    // 원형도 필터 — 1.0에 가까울수록 완전한 원
    params.filterByCircularity = true;
    params.minCircularity = 0.80f;

    // 볼록도 필터 — 오목한 부분이 적을수록 1.0에 가까움
    params.filterByConvexity = true;
    params.minConvexity = 0.90f;

    // 관성비 필터 — 1.0이면 원, 0에 가까우면 길쭉함
    params.filterByInertia = true;
    params.minInertiaRatio = 0.50f;

    // 검출기를 만들고 블롭을 검출한다
    cv::Ptr<cv::SimpleBlobDetector> detector =
        cv::SimpleBlobDetector::create(params);

    std::vector<cv::KeyPoint> keypoints;
    detector->detect(src, keypoints);

    std::cout << "검출된 블롭: " << keypoints.size() << "개" << std::endl;

    // 검출 결과를 빨간 원으로 그린다
    cv::Mat output;
    cv::drawKeypoints(src, keypoints, output, cv::Scalar(0, 0, 255),
                      cv::DrawMatchesFlags::DRAW_RICH_KEYPOINTS);
    cv::imwrite("blobs_detected.png", output);
    return 0;
}

minConvexityfilterByConvexity볼록도 하한 — 면적/볼록껍질 면적

SimpleBlobDetector는 위치와 지름만 준다 검출 결과는 cv::KeyPoint의 벡터다 — 각 블롭의 중심 좌표(pt)와 대략적인 지름(size)만 담긴다. 바운딩박스, 정확한 면적, 윤곽, 종횡비가 필요하면 결국 connectedComponentsWithStats나 윤곽 분석으로 가야 한다. SimpleBlobDetector는 "둥근 점 찾기"에 강하고 정밀 측정에는 한계가 있다.

윤곽 기반 vs 연결 요소 기반

객체를 찾는 방법은 크게 두 갈래다. 이전 글에서 다룬 윤곽(contour) 기반(findContours)과 이번 글의 연결 요소(connected component) 기반(connectedComponents)이다. 둘은 경쟁 관계가 아니라 용도가 다르다.

  • 연결 요소는 영상 전체를 한 번에 훑어 라벨 영상과 통계를 만든다. 각 블롭이 픽셀 단위로 채워진 영역으로 표현된다.
  • 윤곽은 각 객체의 경계선 좌표 목록을 만든다. 계층 구조(구멍 안의 구멍)를 다룰 수 있다.

면적정확한 픽셀 수 (stats에 바로)contourArea — 다각형 근사값

픽셀 단위 마스크labels == i로 즉시 추출drawContours로 다시 그려야 함

속도한 번 스캔 — 블롭 많아도 빠름객체 수·복잡도에 따라 변동
잘 맞는 작업개수 세기, 면적 필터링, 마스크 생성모양 근사, 둘레/곡률, 계층 분석
둘을 섞어 쓰는 게 정석이다 실무에서는 connectedComponentsWithStats로 블롭을 빠르게 세고 면적으로 1차 거른 다음, 살아남은 블롭만 labels == i 마스크로 떼어내 findContours로 둘레·원형도 같은 모양 특징을 정밀 측정한다. 이 글의 ExtractFeature가 정확히 그 조합이다.

실전 — 개수 세기·결함 검출

지금까지의 조각을 모아 실제 검사 시나리오를 구성한다.

부품 개수 세기

트레이 위 부품 개수를 센다. 단순히 블롭 수를 세는 게 아니라 면적 필터로 노이즈를 먼저 걸러야 정확하다.

// 면적이 유효 범위인 블롭만 부품으로 센다
int CountParts(const cv::Mat& binary, int minArea, int maxArea)
{
    cv::Mat labels, stats, centroids;
    int count = cv::connectedComponentsWithStats(
        binary, labels, stats, centroids, 8, CV_32S);

    int parts = 0;
    for (int i = 1; i < count; ++i)  // 배경(0) 제외
    {
        int area = stats.at<int>(i, cv::CC_STAT_AREA);
        if (area >= minArea && area <= maxArea)
        {
            ++parts;
        }
    }
    return parts;
}

결함(이물) 검출

깨끗해야 할 영역에 나타난 블롭은 전부 이물 후보다. 면적과 종횡비를 함께 봐서 점 이물과 선 이물을 구분한다.

enum class DefectType { None, Spot, Scratch };

// 이물 블롭을 종류별로 분류한다
DefectType ClassifyDefect(const BlobFeature& f)
{
    const int    kIgnoreArea   = 30;    // 이보다 작으면 무시(센서 노이즈)
    const double kScratchRatio = 5.0;   // 종횡비 5 이상이면 스크래치

    if (f.area < kIgnoreArea)
    {
        return DefectType::None;
    }

    double ratio = std::max(f.aspectRatio, 1.0 / f.aspectRatio);
    if (ratio >= kScratchRatio)
    {
        return DefectType::Scratch;  // 가늘고 긴 결함
    }
    return DefectType::Spot;         // 점 형태 결함
}

누락 검사

찍혀 있어야 할 마크나 부품이 빠지지 않았는지 본다. 기대 위치마다 ROI를 잡고 그 안에 충분한 면적의 블롭이 있는지 확인한다.

// 기대 위치 ROI 안에 유효 블롭이 있는지 검사한다
bool IsPresent(const cv::Mat& binary, const cv::Rect& roi, int minArea)
{
    // ROI를 영상 경계 안으로 자른다
    cv::Rect safe = roi & cv::Rect(0, 0, binary.cols, binary.rows);
    if (safe.area() == 0) { return false; }

    cv::Mat region = binary(safe);
    cv::Mat labels, stats, centroids;
    int count = cv::connectedComponentsWithStats(
        region, labels, stats, centroids, 8, CV_32S);

    for (int i = 1; i < count; ++i)
    {
        if (stats.at<int>(i, cv::CC_STAT_AREA) >= minArea)
        {
            return true;  // 충분한 크기의 블롭 발견 → 정상
        }
    }
    return false;  // 비어 있음 → 누락
}
판정은 단일 특징보다 복수 특징 조합이 안정적이다 면적 하나로만 양품을 가르면, 면적은 맞는데 모양이 찌그러진 불량을 놓친다. 면적 + 원형도 + 채움률처럼 서로 독립적인 특징 두세 개를 조합하면 한 특징이 흔들려도 다른 특징이 잡아준다. 실전 검사 로직은 거의 항상 다중 조건 AND다.

흔한 함정

블롭 분석에서 거의 모두가 한 번씩 밟는 함정들이다.

이진화 품질이 블롭 분석 품질을 결정한다

블롭 분석의 정확도는 이진화에서 이미 정해진다 라벨링 알고리즘은 입력 이진 영상을 그대로 믿는다. 이진화가 조명 얼룩 때문에 객체를 두 조각으로 끊으면 블롭이 2개로 세어지고, 객체와 노이즈가 붙으면 1개로 합쳐진다. 블롭 개수가 이상하면 라벨링 코드보다 먼저 이진 영상을 띄워서 눈으로 확인하는 게 빠르다. 필요하면 모폴로지 연산(open/close)으로 이진 영상을 먼저 정리한다.

단일 면적 임계값의 취약성

"면적 > N" 하나로 판정하면 쉽게 무너진다 카메라 거리가 조금 바뀌거나 조명이 변하면 같은 객체의 면적도 출렁인다. 면적 하한 하나에 의존한 판정은 경계에 걸친 객체에서 양품/불량이 뒤집힌다. 면적은 범위(min~max)로 잡고, 가능하면 스케일에 무관한 원형도·종횡비를 함께 본다.

4-연결 / 8-연결 혼동

연결성을 함수마다 다르게 주면 결과가 어긋난다 connectedComponents의 connectivity 인자를 어떤 호출에서는 4, 어떤 호출에서는 8로 주면 같은 영상에서 블롭 개수가 달라진다. 프로젝트 전체에서 연결성을 하나(보통 8)로 고정하고, 상수로 빼서 한 곳에서 관리한다.

배경 라벨(0) 포함 주의

가장 흔한 실수다. stats·centroids의 0번 행은 배경이다. 루프를 i=0부터 돌리면 배경이 블롭으로 섞여 개수가 +1 되고, "최대 면적 블롭"이 배경으로 잡힌다.

// 나쁨 — i=0이 배경이라 개수가 하나 더 세어진다
// for (int i = 0; i < count; ++i) { ... }

// 좋음 — 항상 i=1부터 순회한다
for (int i = 1; i < count; ++i)
{
    int area = stats.at<int>(i, cv::CC_STAT_AREA);
    // ...
}

블롭이 붙으면 분리가 필요하다

맞닿은 두 객체는 하나의 블롭으로 세어진다 나란히 붙어 있는 부품 2개는 픽셀이 이어져 있어 라벨링이 블롭 1개로 본다. 개수가 모자라게 나온다면 객체들이 붙은 것이다. 이때는 거리 변환 + watershed나 침식(erode)으로 먼저 떼어낸 뒤 라벨링해야 한다. 라벨링 자체는 붙은 객체를 나눠주지 않는다.
정리하면 블롭 분석은 좋은 이진 영상에서 시작하고, 연결성은 8로 고정하고, 루프는 i=1부터 돌리고, 판정은 면적 범위 + 비율 특징 조합으로 한다. 붙은 객체는 라벨링 전에 분리한다. 이 다섯 가지만 지켜도 현장에서 만나는 블롭 분석 버그 대부분을 피한다.
