1. AI 기초 개념

비교 1: 약인공지능 vs 강인공지능 vs 초인공지능

3가지 비교

약인공지능 (Narrow AI)

  • 특정 작업 하나만 잘 수행
  • 예: 체스 엔진, 음성 인식, 이미지 분류기
  • 현재 우리가 쓰는 모든 AI가 여기에 속함
  • 학습된 영역 밖에선 작동 불가

강인공지능 (General AI)

  • 인간 수준의 범용 지능
  • 여러 영역의 문제를 스스로 학습·해결
  • 아직 구현된 사례 없음 (이론적 단계)
  • AGI(Artificial General Intelligence)

초인공지능 (Super AI)

  • 인간을 능가하는 모든 지적 능력
  • 강인공지능 이후 단계로 가정
  • 기술적 특이점(Singularity) 이후 등장 가정
  • 완전히 사변적인 개념
핵심: 시험에서 "현재의 AI"는 모두 약인공지능이다. 자율주행도 영상 인식·경로 계획 등 각 모듈이 따로 학습된 약인공지능의 조합이다.

비교 2: AI 효과 vs 기술적 특이점

VS

AI 효과 (AI Effect)

  • "AI가 풀면 그건 더 이상 AI가 아니다"
  • OCR·체스 엔진·내비게이션이 모두 한때는 AI였음
  • 대중·전문가의 인식 문제
  • AI의 정의가 시간에 따라 좁아지는 현상

기술적 특이점 (Singularity)

  • AI가 자신을 개선해 인간 지능을 초월하는 시점
  • 이후 인간이 예측·통제 불가
  • 미래의 가정적 사건
  • 초인공지능 등장과 직결
구분법: AI 효과는 "과거를 잊는다"는 인식 현상, 특이점은 "미래에 일어날 수도 있는" 사건이다. 시험에선 둘을 섞어서 묻는 함정 선지가 자주 나온다.
시험 함정: "AI 효과 때문에 AI는 인간 지능을 초월한다" -> 거짓. AI 효과는 단지 "예전 AI를 더 이상 AI로 부르지 않는" 인식 현상이고, 초월은 특이점 개념이다.

2. ML 학습 유형과 작업

비교 3: 지도 vs 비지도 vs 강화 vs 자가학습

4가지 비교
구분지도 학습비지도 학습강화 학습자가학습
입력 데이터레이블이 달린 데이터레이블 없는 데이터환경에서 얻는 상태레이블 없는 데이터 + 모델 스스로 레이블 생성
학습 신호정답(레이블)데이터 내부 패턴보상/벌점대리(pretext) 작업의 정답
대표 작업분류, 회귀군집화, 차원 축소, 연관 규칙게임 AI, 로봇 제어대규모 언어/비전 사전훈련
예시스팸 분류, 가격 예측고객 세분화, 이상 탐지알파고, 자율주행 정책BERT, SimCLR
구분 포인트: "레이블 누가 만들었나"가 핵심이다. 지도=사람, 비지도=없음, 강화=환경, 자가=모델 자신.
시험 함정: 자가학습(self-supervised)은 비지도 학습의 한 갈래로 묶이기도 하지만, CT-AI에서는 별도 항목으로 분리해서 묻는다. "사람이 레이블링하지 않는다"는 점은 같으나, 자가학습은 모델이 데이터 일부를 가리고 맞히는 식의 인공적 정답을 만든다.

비교 4: 분류 vs 회귀

VS

분류 (Classification)

  • 출력이 이산적인 클래스
  • 예: 스팸/정상, 고양이/개/말
  • 주요 지표: 정확도, 정밀도, 재현율, F1
  • 출력을 평가하는 도구: 혼동행렬

회귀 (Regression)

  • 출력이 연속적인 수치
  • 예: 집값 예측, 온도 예측
  • 주요 지표: MAE, MSE, RMSE, R²
  • 혼동행렬은 사용하지 않음
판별법: 출력이 카테고리 -> 분류, 출력이 숫자(범위) -> 회귀. "확률"이 나와도 그것을 임계값으로 라벨로 바꾸면 분류이다.

3. ML 워크플로우

비교 5: 과적합 vs 과소적합

VS

과적합 (Overfitting)

  • 훈련 데이터를 너무 잘 외움
  • 훈련 정확도 높음, 테스트 정확도 낮음
  • 모델이 잡음까지 학습
  • 일반화 실패

과소적합 (Underfitting)

  • 모델이 너무 단순해서 패턴을 못 잡음
  • 훈련 정확도도, 테스트 정확도도 낮음
  • 모델 용량 부족, 학습 부족
  • 아예 학습이 안 된 상태
대응책:
• 과적합 -> 규제(L1/L2), 드롭아웃, 데이터 증강, 모델 단순화, 조기 종료
• 과소적합 -> 모델 복잡도 증가, 더 많은 특성, 학습 시간 증가
시험 함정: 훈련 정확도가 99%인데 테스트 정확도가 60%라면 과소적합이 아니라 과적합이다. "테스트 정확도가 낮다"만 보고 무조건 과소적합이라고 답하면 안 된다.

비교 6: 훈련 vs 검증 vs 테스트 데이터

3가지 비교

훈련 데이터 (Training Set)

  • 모델 가중치 학습에 사용
  • 가장 큰 비중 (약 60~80%)
  • 모델이 직접 본 데이터

검증 데이터 (Validation Set)

  • 하이퍼파라미터 조정에 사용
  • 훈련 중 성능 모니터링
  • 모델 선택·조기 종료 기준
  • 약 10~20%

테스트 데이터 (Test Set)

  • 최종 모델의 일반화 성능 평가
  • 학습·조정에 절대 사용 안 함
  • 한 번만 사용 권장
  • 약 10~20%
핵심 원칙: 세 데이터셋은 서로 겹치지 않아야 한다. 테스트 데이터가 훈련에 섞이는 것을 데이터 누수(data leakage)라 하고, 성능이 부풀려 보이는 대표적 함정이다.

비교 7: 사전훈련 모델 vs 전이학습

VS

사전훈련 모델 (Pre-trained Model)

  • 대규모 데이터로 이미 학습된 모델
  • 예: ResNet, BERT, GPT
  • 제공 형태이지 사용 방법은 아님
  • "무엇" — 학습된 가중치 묶음

전이학습 (Transfer Learning)

  • 사전훈련 모델을 새 작업에 재사용하는 기법
  • 일부 레이어 동결 + 일부 재학습 (파인튜닝)
  • "어떻게" — 활용 방법론
  • 적은 데이터로도 좋은 성능
관계: 사전훈련 모델은 도구, 전이학습은 그 도구를 쓰는 방법이다. 둘은 짝으로 등장한다.

비교 8: 결정적 vs 비결정적 vs 확률적

3가지 비교

결정적 (Deterministic)

  • 같은 입력 -> 항상 같은 출력
  • 전통적 소프트웨어의 기본 가정
  • 예: 정렬 알고리즘, 사칙연산

비결정적 (Non-deterministic)

  • 같은 입력에도 다른 출력 가능
  • 원인이 명확하지 않을 수 있음
  • 예: 멀티스레드 race condition

확률적 (Probabilistic)

  • 출력이 확률 분포를 따름
  • 비결정성을 모델링한 것
  • 예: 분류 확률 출력, 베이지안 모델
관계: 대다수 ML 모델은 학습된 후엔 같은 입력에 같은 출력을 내므로 결정적이지만, 출력 자체가 확률이라는 점에서 확률적이다. 비결정적인 모델은 dropout이 활성화된 추론, 강화학습의 일부 정책 등이다.

지표공식의미언제 중요한가
정확도 (Accuracy)(TP+TN) / 전체전체 중 맞춘 비율클래스가 균형 잡힌 경우
정밀도 (Precision)TP / (TP+FP)Positive로 예측한 것 중 진짜 Positive 비율FP가 비싼 경우 (스팸 분류, 추천)
재현율 (Recall)TP / (TP+FN)실제 Positive 중 잡아낸 비율FN이 치명적인 경우 (암 진단, 보안)
F1 점수2 · (P·R) / (P+R)정밀도와 재현율의 조화 평균둘 다 균형 있게 보고 싶을 때
기억법:
• 정밀도(Precision) = "내가 positive라 외친 것 중 맞은 것" — 신중함
• 재현율(Recall) = "실제 positive 중 놓치지 않은 것" — 빠짐없음
• 둘은 일반적으로 트레이드오프 관계 (한쪽 올리면 다른 쪽 떨어짐)
시험 함정: "정확도가 95%니까 좋은 모델이다" -> 오답 가능. 100명 중 양성이 5명뿐인 불균형 데이터에서 모두 "음성"으로 찍어도 정확도 95%다. 이런 경우 재현율이 0이라 무의미하다.

비교 10: 정밀도 vs 재현율 — 어떤 걸 우선해야 하나

VS

정밀도 우선 시나리오

  • FP 비용이 큰 경우
  • 스팸 메일 차단 (정상 메일을 스팸으로 분류하면 큰일)
  • 유튜브 추천 (관련 없는 콘텐츠 추천은 사용자 이탈)
  • 법적 결정 (무고한 사람 처벌 방지)

재현율 우선 시나리오

  • FN 비용이 큰 경우
  • 암 진단 (놓치면 환자 사망)
  • 침입 탐지 (놓친 공격은 큰 피해)
  • 리콜 대상 부품 검사 (놓치면 사고)
판단법: "놓치면 죽나, 잘못 잡으면 죽나?" — 놓치면 죽으면 재현율, 잘못 잡으면 죽으면 정밀도.

5. 데이터와 편향

비교 11: 데이터 편향의 3가지 종류

3가지 비교

샘플 편향 (Sample Bias)

  • 데이터가 전체 모집단을 대표하지 못함
  • 예: 백인 얼굴 위주로 학습된 안면 인식 -> 다른 인종 성능 저하
  • 수집 단계의 문제

알고리즘 편향 (Algorithmic Bias)

  • 알고리즘 자체의 설계가 특정 결과로 치우침
  • 특성 선택, 손실 함수, 최적화 방식에서 기인
  • 같은 데이터라도 알고리즘에 따라 결과가 다름

부적절한 편향 (Inappropriate Bias)

  • 사회적·윤리적으로 받아들일 수 없는 편향
  • 예: 성별·인종으로 채용 점수 깎는 모델
  • 샘플/알고리즘 편향의 결과일 수 있음
관계: 샘플 편향 + 알고리즘 편향이 결합하면 부적절한 편향으로 드러난다. 모든 편향이 부적절한 것은 아니지만(예: 고양이 데이터가 많은 건 고양이 분류엔 적절), 부적절한 편향은 반드시 제거해야 한다.

비교 12: 적대적 공격 vs 데이터 오염

VS

적대적 공격 (Adversarial Attack)

  • 운영 단계에서 입력을 미세 조작
  • 사람 눈엔 같아 보이는 노이즈 추가
  • 모델이 완전히 다른 클래스로 오분류
  • 예: 도로 표지판에 스티커 -> 정지를 속도 제한으로 오인

데이터 오염 (Data Poisoning)

  • 학습 단계에서 훈련 데이터 변조
  • 오염된 샘플을 데이터셋에 끼워 넣음
  • 모델 자체가 잘못된 패턴을 학습
  • 백도어 트리거가 대표적 (특정 패턴 입력 시 의도된 오답)
구분 시점: 공격 시점이 핵심이다. 학습 전이면 데이터 오염, 추론 시점이면 적대적 공격. 데이터 오염은 발견·제거가 더 어렵다.

6. AI 품질 특성

비교 13: 투명성 vs 해석가능성 vs 설명가능성

3가지 비교

투명성 (Transparency)

  • 모델·데이터·프로세스가 공개되어 있는가
  • 아키텍처, 학습 데이터, 의도가 드러남
  • 조직·문서 차원의 속성

해석가능성 (Interpretability)

  • 모델의 내부 동작을 사람이 이해할 수 있는가
  • "이 가중치가 왜 이 값인가"
  • 선형 회귀·결정 트리는 본질적으로 해석 가능

설명가능성 (Explainability)

  • 모델의 특정 예측을 설명할 수 있는가
  • "왜 이 이미지를 고양이로 분류했나"
  • 블랙박스 모델에 LIME, SHAP 등으로 사후 설명
구분법: 투명성은 "공개", 해석가능성은 "모델 전체", 설명가능성은 "개별 예측". 딥러닝은 보통 투명할 순 있어도(코드/가중치 공개) 해석은 어렵고, 설명은 별도 기법으로 가능하다.

비교 14: 부작용 vs 보상 해킹

VS

부작용 (Side Effects)

  • 주 목표는 달성하지만 의도치 않은 다른 결과 발생
  • 예: 청소 로봇이 청소를 위해 화병을 깨뜨림
  • 보상 함수에 부작용이 명시되지 않아서 생김

보상 해킹 (Reward Hacking)

  • 보상 함수의 허점을 이용해 의도와 다른 방식으로 점수만 챙김
  • 예: 청소 로봇이 카메라를 가려 "더러움 0"으로 만들기
  • 목표 자체를 우회
차이: 부작용은 "목표는 했는데 부수 피해", 보상 해킹은 "목표를 안 하고 점수만 챙김". 둘 다 보상 설계 결함에서 나온다.

비교 15: AI 특유 품질 — 유연성·적응성·자율성·진화

4가지 비교
특성한 줄 정의예시
유연성 (Flexibility)학습된 외 영역에서도 어느 정도 작동하는 능력고양이 분류기가 비슷한 동물도 그럴듯하게 처리
적응성 (Adaptability)새로운 환경·데이터에 맞춰 모델이 변하는 능력온라인 학습으로 사용자 패턴에 적응
자율성 (Autonomy)사람 개입 없이 결정·행동하는 정도자율주행 차량이 신호 없이 운행
진화 (Evolution)시간이 지나며 모델이 지속적으로 변화지속적 학습, 모델 재학습 파이프라인
구분: 유연성은 "범위 밖 대응", 적응성은 "환경 변화에 맞춤", 자율성은 "스스로 결정", 진화는 "시간에 따른 변화". 진화하는 모델은 컨셉 드리프트 감시가 필수다.

7. 테스팅 기법

비교 16: 페어와이즈 vs 조합 vs 백투백 vs A/B vs 변성 테스팅

5가지 비교
기법핵심 아이디어언제 쓰나오라클
페어와이즈 (Pairwise)모든 2개 파라미터 쌍의 조합을 1회 이상 커버입력 파라미터가 많을 때 테스트 수 절감일반 오라클 필요
조합 테스팅 (Combinatorial)t-way 조합 커버 (t=2면 페어와이즈)복잡한 상호작용 결함 탐색일반 오라클 필요
백투백 (Back-to-Back)두 개 이상의 구현을 같은 입력으로 돌려 결과 비교레퍼런스 모델·기존 모델과 비교의사 오라클 (다른 구현)
A/B 테스팅운영 환경에서 두 버전을 사용자에게 노출, 통계적 비교모델 업데이트 효과 검증비즈니스 지표
변성 테스팅 (Metamorphic)입력 변형에 따른 출력의 관계(변성 관계)를 검증정답을 모르지만 입출력 관계는 알 때변성 관계 자체가 오라클
오라클 관점: AI는 정답이 모호한 경우가 많아 "오라클 문제"가 큰데, 백투백·변성 테스팅·A/B는 모두 오라클 문제를 우회하는 기법이다.
• 변성 예시: 이미지를 좌우 반전해도 분류 결과가 같아야 한다 — 정답을 몰라도 일관성 검증 가능
시험 함정: "백투백 테스팅은 사용자 그룹을 둘로 나눠 비교한다" -> 거짓. 그건 A/B 테스팅이다. 백투백은 같은 입력을 서로 다른 구현에 넣어 출력을 비교한다.

비교 17: 의사 오라클 vs 테스트 오라클 문제

VS

테스트 오라클 문제 (Oracle Problem)

  • 주어진 입력에 대한 정답을 알 수 없는 상황
  • AI에서 특히 심각 (이미지 분류, 추천 등)
  • "이 답이 맞는지 어떻게 검증하나"라는 본질적 문제

의사 오라클 (Pseudo-oracle)

  • 오라클 문제를 우회하기 위한 대체 정답
  • 다른 구현 결과, 변성 관계, 통계적 기준 등
  • 완벽한 정답은 아니지만 비교 기준 역할
관계: 오라클 문제는 문제, 의사 오라클은 해결책 중 하나다. 백투백, 변성 테스팅, 메타몰픽 등이 의사 오라클을 활용한 기법이다.

8. AI 구축 방식

비교 18: AIaaS vs 자체 구축 AI

VS

AIaaS (AI as a Service)

  • 클라우드 사업자의 완성된 AI API 사용
  • 예: AWS Rekognition, Azure Cognitive Services, GCP Vision
  • 구축 시간 짧음, 운영 부담 낮음
  • 모델 내부 통제 불가, 데이터가 외부로 나감

자체 구축 AI

  • 조직이 직접 학습·운영하는 모델
  • 도메인 데이터로 맞춤화 가능
  • 인프라·인력·시간 비용 큼
  • 완전한 통제와 IP 보호
선택 기준: 일반적 작업이고 빠르게 가야 한다 -> AIaaS. 도메인 특수성이 크고 데이터 보안이 중요하다(예: 산업·의료) -> 자체 구축.
시험 함정: "AIaaS는 항상 비용이 저렴하다" -> 거짓. 호출량이 폭증하면 API 종량 과금이 자체 구축보다 비싸질 수 있다. 또한 데이터 주권·규제 요구사항이 있으면 AIaaS를 못 쓰는 경우도 많다.
마무리 학습 팁 CT-AI 샘플문제는 시나리오 기반 문제가 많다. 각 개념을 단순 정의로 외우지 말고 "이 상황이면 어떤 개념이 적용되나"를 함께 떠올리는 연습을 해라. 특히 정밀도/재현율, 페어와이즈/백투백/변성, 부작용/보상해킹은 항상 셋트로 출제된다.
