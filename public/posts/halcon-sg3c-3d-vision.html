3D Vision 개요

HALCON의 3D Vision은 크게 두 가지 응용을 다룬다.

  • 3D position recognition — 알려진 객체의 3D 위치·자세 추정. pick-and-place와 bin picking의 핵심.
  • 3D inspection — 표면 형상·높이·체적 검사. 평면 검사로 환원할 수 없는 경우 사용.

두 응용 모두 출발점은 camera calibration이다. 1/40 pixel 정밀도로 edge를 뽑아도 렌즈 왜곡이 몇 pixel 수준이면 의미가 없다. 그래서 어떤 3D 방법을 쓰든 calibration이 먼저 온다.

3D 정보를 만드는 두 흐름

하나는 표면 재구성(reconstruction)으로 point cloud를 만드는 길이고, 다른 하나는 알려진 객체의 자세 추정(pose estimation)으로 6D pose를 얻는 길이다. 재구성 결과를 matching 입력으로 다시 사용하는 조합이 가장 강력하다.

3D 정보 획득 방법 비교

HALCON은 표면 재구성을 위해 다음 접근들을 제공한다. 각 방법은 하드웨어 요구사항과 대상 크기, 결과 형태가 다르다.

방법 하드웨어 대상 크기 결과

Multi-View Stereo카메라 다수 + calibration object약 10cm 이상3D object model 또는 X, Y, Z
Sheet of Light카메라 + 라인 레이저 + 이동축이동축에 올릴 수 있는 크기disparity image 또는 Z image

선택 기준 대상이 작고 정밀할수록 DFF나 photometric, 보통 산업 측정은 Sheet of Light, 자유 형상이나 bin picking은 Stereo·ToF·Structured Light. 정해진 정답이 아니라 표면 특성·이동 가능성·정밀도 요구가 동시에 결정한다.

Stereo Vision

Stereo는 서로 다른 시점에서 같은 점을 관찰했을 때 생기는 disparity를 이용해 깊이를 계산한다. 두 카메라(binocular)면 정면 표면, 여러 대(multi-view)면 다면 재구성까지 가능하다.

스테레오 삼각측량 원리: baseline B, 초점거리 f, disparity로부터 depth Z 계산

3.1 기본 흐름

create_calib_data
→ 두 카메라를 같은 calibration plate로 동시 캘리브레이션
→ calibrate_cameras
→ gen_binocular_rectification_map  // epipolar line이 수평이 되도록 재투영
→ map_image (좌·우 둘 다)
→ binocular_disparity 또는 binocular_disparity_ms / _mg
→ disparity_image_to_xyz

3.2 정합(matching) 방식

HALCON은 disparity 계산을 위해 세 가지 방식을 제공한다.

  • Correlation-based — 윈도우 상관 기반. 빠르고 텍스처 풍부한 면에 강하다.
  • Multigrid — 다중 해상도. 부드러운 표면도 보간으로 매끄럽게 나오나 가장자리가 무뎌질 수 있다.
  • Multi-Scanline — semi-global 계열. 균형 잡힌 결과로 일반 산업 환경 기본값으로 자주 쓰인다.

3.3 Uncalibrated Stereo

calibration plate를 둘 수 없는 환경에서는 특징점 대응에서 fundamental matrix를 추정해 epipolar 기하만 복원하는 방식도 있다. metric depth가 아니라 상대 형상까지만 얻는다.

스테레오의 약점 반사·투명·텍스처 없는 표면에서 correspondence가 깨진다. baseline을 늘리면 depth 정밀도는 좋아지지만 occlusion이 증가한다. 트레이드오프를 calibration 단계에서 결정해야 한다.

Sheet of Light / Laser Triangulation

레이저로 라인을 투사하고, 다른 각도의 카메라가 그 라인의 굴곡을 본다. 라인이 움직이는 객체 위를 스쳐가면 라인마다 한 줄의 높이 프로파일이 얻어지고, 이를 쌓아 Z image가 된다. 산업용 inline 측정에서 가장 흔하게 쓰이는 방식이다.

Sheet of Light 원리: 레이저 평면이 객체와 만나는 선의 굴곡을 다른 시점 카메라로 측정

4.1 캘리브레이션

HALCON은 두 가지 방법을 지원한다.

  • 표준 calibration plate를 여러 자세로 놓고 plate 평면들이 laser sheet와 만나는 선을 누적해서 laser plane을 결정한다.
  • 전용 3D calibration object(계단/홈 구조)를 한 번에 촬영하는 방식. 셋업이 고정되어 있고 정밀도가 중요한 경우 적합하다.

4.2 측정 흐름

create_sheet_of_light_model
→ set_sheet_of_light_param (calibration · 이동 step 등)
→ for each profile image:
     measure_profile_sheet_of_light
→ get_sheet_of_light_result   // disparity / x / y / z / score

encoder와 동기되면 X 좌표가 ticks로 정해진다. 그래서 인코더 분해능 자체가 측정 X 분해능의 상한이 된다.

표면 광학 함정 검은 흡수면·고광택 반사면·반투명면은 sheet of light의 단골 실패 케이스이다. 노출 부족, saturation, multipath 모두 만들어진다. 시운전 단계에서 score image를 함께 확인해 어느 픽셀이 믿을 만한지 추적해야 한다.

Structured Light

프로젝터가 알려진 패턴(스트라이프, gray code, phase shift, speckle 등)을 객체에 쏘고, calibrated 카메라가 그 패턴이 어떻게 변형되었는지 본다. 패턴이 각 픽셀에 고유한 부호를 입혀주므로 stereo의 텍스처 부족 문제를 우회한다.

  • 한 번에 면 전체를 얻을 수 있어 정지 대상에 빠르다.
  • 광택·반사에는 여전히 약하다.
  • 외부 광이 강한 환경에서는 패턴이 묻힌다.

Depth 카메라 (ToF 등)

Time-of-Flight 카메라는 변조된 적외선을 쏘고 돌아오는 위상 차이로 거리를 직접 측정한다. HALCON 입장에서는 결과로 X·Y·Z image가 들어오는 "이미 측정된 깊이"이고, 그 뒤의 처리는 stereo 결과와 동일하게 xyz_to_object_model_3d로 3D object model을 만들어 이어진다.

  • 장점 — 단일 카메라, 큰 작업 거리, 텍스처 무관.
  • 단점 — 깊이 정밀도가 stereo·sheet of light보다 떨어지고 가장자리 잡음이 크다. 객체 경계에서 "flying pixel"이 자주 발생한다.

3D Object Model

HALCON의 3D 처리의 공통 컨테이너가 3D object model이다. 어떤 방법으로 깊이를 얻었든 이 형식으로 모이고, 이 형식 위에서 visualization·matching·정합·feature 추출이 동작한다.

7.1 포함되는 내용

  • 3D point (point cloud)
  • normal vector
  • triangle 또는 polygon mesh
  • primitive (plane, cylinder, sphere 등)
  • 좌표계(pose) 정보
  • 2D mapping (X·Y·Z image 형태일 때)

7.2 어디서 들어오는가

  • CAD 파일 — read_object_model_3d (DXF, OFF, PLY, STL, OM3 등)
  • XYZ image — xyz_to_object_model_3d
  • stereo·sheet of light·ToF 결과
  • 여러 모델을 합치는 union

7.3 자주 쓰는 처리

  • 샘플링 — sample_object_model_3d
  • 변환 — rigid_trans_object_model_3d, affine_trans_object_model_3d
  • 법선 — surface_normals_object_model_3d
  • feature 추출 — get_object_model_3d_params로 bounding box·diameter·area 조회
  • visualization — visualize_object_model_3d

3D Matching

알려진 3D 객체를 scene에서 찾아 6D pose를 돌려주는 작업이다. HALCON은 입력의 형태와 객체 특성에 따라 여러 갈래를 제공한다.

8.1 Surface-Based 3D Matching 흐름

실무에서 bin picking·로봇 정렬에 가장 자주 쓰이는 흐름이다.

Surface-Based 3D Matching의 데이터 흐름
// 1. 모델 측 3D object model 준비 (CAD 또는 재구성 결과)
read_object_model_3d(...) 또는 xyz_to_object_model_3d(...)

// 2. surface model 생성 (sampling distance 가 정밀도/속도 균형)
create_surface_model(ObjectModel3D, 0.03, [], [], SFM)

// 3. scene 측 3D object model 준비
xyz_to_object_model_3d(X, Y, Z, Scene3D)

// 4. 탐색
find_surface_model(SFM, Scene3D, 0.05, 0.3, 0.2,
                   'true', 'num_matches', 10,
                   Pose, Score, ResultID)
샘플링 거리의 의미 create_surface_model의 RelSamplingDistance는 작을수록 robust·느림, 클수록 빠름·취약. 한쪽 끝에서 시작해 score와 시간을 둘 다 만족하는 지점을 찾는 식으로 튜닝한다.

8.2 Shape-Based 3D Matching과의 차이

Shape-based는 CAD에서 각 시점별 윤곽선을 미리 렌더링해 2D 이미지에서 자세를 찾는다. Surface-based는 point cloud 자체에서 매칭한다. 그래서 cuts:

  • 이미지만 있고 3D 센서가 없으면 shape-based가 적합하다.
  • 3D 센서가 이미 있고 객체가 겹쳐 쌓여 있으면 surface-based가 압도적으로 안정적이다.
  • CAD가 너무 복잡하면 fast_pose_refinement·pose range 제약·rotational symmetry 활용 같은 최적화가 필수이다.

8.3 Primitive Fitting

대상이 평면·원통·구 같은 단순 형상이면 매칭 대신 fit_primitives_object_model_3d로 직접 fitting하는 것이 압도적으로 빠르고 안정적이다. bin picking 전 단계에서 캐리어 트레이의 평면을 빼낸다든지, 파이프 부품의 원통축을 추정한다든지 하는 데 쓰인다.

Point Cloud 처리

3D 재구성과 matching 사이에는 거의 항상 point cloud 정리 단계가 들어간다. 잡음·배경·outlier를 정리하지 않으면 matching이 느려지거나 false positive가 늘어난다.

  • 샘플링 — sample_object_model_3d으로 균일 다운샘플링. 보통 'fast'나 'accurate' 모드.
  • 평면 제거 — primitive fitting으로 작업 평면을 찾아 그 위 점들만 남기기.
  • 세그멘테이션 — segment_object_model_3d로 공간적으로 끊어진 cluster 분리.
  • 이상치 제거 — k-NN 기반 outlier 제거나 normal 일관성 검사.
  • 법선 계산 — surface_normals_object_model_3d (matching·렌더링 전 필수).
법선 방향 모호성 XYZ image에서 만든 point cloud는 법선 방향이 카메라 쪽인지 반대쪽인지 모호하다. surface matching에서는 model과 scene 양쪽의 법선 방향이 일치해야 한다. 안되면 model_invert_normals를 'true'/'false' 양쪽으로 모델을 두 개 만들어 score 높은 쪽을 채택한다.

Robot Vision 심화

시리즈 I 08편에서 다룬 hand-eye calibration을 3D 입력으로 확장한 형태가 이 챕터의 Robot Vision이다. 핵심 구분은 다음 네 축이다.

  • 관절 로봇 vs SCARA — SCARA는 Z translation을 별도로 결정해야 한다.
  • camera + calibration plate vs 3D sensor + 3D object — 후자는 plate를 못 쓰는 환경 대안.
  • moving camera (eye-in-hand) vs stationary camera (eye-to-hand)
  • camera를 사전에 calibration하느냐, hand-eye와 동시에 하느냐

10.1 3D Pick의 좌표 변환 체인

// 1. 객체 자세를 카메라 좌표계에서 얻음
find_surface_model → pose_cam_obj

// 2. hand-eye 결과로 카메라↔로봇 변환
cam_in_base   (stationary camera)
또는
cam_in_tool   (eye-in-hand)

// 3. 객체를 로봇 base 좌표계로
pose_base_obj = cam_in_base ∘ pose_cam_obj
또는
pose_base_obj = base_tool ∘ cam_in_tool ∘ pose_cam_obj

// 4. grasp offset 합성 후 로봇으로 전송
pose_base_grasp = pose_base_obj ∘ obj_to_grasp
SCARA의 Z 함정 SCARA는 회전축이 평행하기 때문에 일반 hand-eye 식만으로는 카메라의 Z translation을 결정할 수 없다. HALCON은 calibrate_hand_eye_scara와 별도의 Z 결정 절차를 따로 둔다. 시리즈 I 08편의 표준 캘리브레이션을 그대로 적용하면 Z가 부정확해진다.

실무 함정

Calibration 정확도

3D 정밀도의 상한은 calibration 정밀도이다. plate가 휘었거나, 작업 거리에서 한참 떨어진 거리에서 calibration 했거나, image 전 영역을 커버하지 않으면 그 뒤의 어떤 처리도 그 한계를 넘지 못한다.

표면 광학 특성

고광택 금속·검은 고무·반투명 플라스틱·유리. 어떤 3D 방법도 이들 표면에서 동시에 잘 동작하지 않는다. 대상이 정해진 시점에 어떤 표면 특성을 가지는지 먼저 보고 방법을 골라야 한다. 코팅·스프레이를 허용할 수 있느냐가 종종 결정적이다.

Point cloud 노이즈와 outlier

"matching이 이상하다"의 80%는 모델·알고리즘이 아니라 입력 point cloud 정리가 부실해서이다. 평면 제거·segmentation·outlier 제거를 데이터셋에 맞게 튜닝하지 않으면 score가 낮아지고 false match가 늘어난다.

좌표계와 단위

m·mm 혼용, transform 방향 반대, plate pose와 camera pose 혼동, pose 표기법(ZYX vs XYZ Euler) 차이. 3D 디버깅 시간의 절반은 이런 곳에서 나간다. transform chain을 표로 그려두는 습관이 가장 효과적이다.

속도-정밀도 트레이드오프

surface matching의 sampling distance, shape model의 pose range, stereo의 baseline·resolution. 어디서든 정밀도를 올리면 시간·메모리를 잃는다. 사이클 타임·정밀도·안정성 셋 중 둘만 동시에 만족시킬 수 있다.

핵심 정리 · 시리즈 마무리

  • 3D 정보 획득에는 stereo·sheet of light·structured light·DFF·photometric·ToF 등 다양한 길이 있고, 표면 특성과 대상 크기가 선택을 좌우한다.
  • 어떤 방법이든 결과는 3D object model이라는 공통 컨테이너로 흘러 들어가 matching·primitive fitting·visualization으로 이어진다.
  • Surface-based 3D matching은 point cloud 위에서 동작하므로 bin picking·로봇 정렬의 사실상 표준이다.
  • Robot Vision은 camera calibration + hand-eye calibration + 3D matching이 모두 정렬되어야 의미 있는 결과가 나온다.
  • 3D 시스템 디버깅은 알고리즘 튜닝보다 좌표계·단위·표면 광학 점검이 먼저이다.
