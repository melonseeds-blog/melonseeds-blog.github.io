[Ch10] AI 시스템의 테스트 환경 — 기존과의 차이

AI 시스템은 다양한 운영 환경에서 사용되고, 그 결과 테스트 환경도 다양해진다. 전통적 시스템과 구별되는 AI 테스트 환경 요소는 다음 여섯 가지다.

요소테스트 환경에 미치는 영향
자가학습(Self-learning)자가학습·일부 자율 시스템은 처음 배포 시 완전히 정의되지 않은 운영 환경 변화에 적응해야 한다. 정의되지 않은 변화를 모방하는 환경 구성은 본질적으로 어렵고, 테스터의 상상력과 일정 수준의 임의성이 필요하다.
자율성(Autonomy)자율 시스템은 인간 개입 없이 환경 변화에 적응해야 하고, 운영자에게 자율성이 다시 양도되는 상황도 인식해야 한다. 일부 시스템은 자율성 양도 상황을 식별·모방하기 위해 극단적 환경이 필요할 수 있다. 위험한 환경에서 작업하는 게 목적인 시스템이라면 그런 환경을 대변하는 위험 환경 구축이 쉽지 않다.
다중 에이전트(Multi-agent)다중 에이전트 시스템이 다른 AI 시스템과 함께 동작해야 한다면, 테스트 환경은 SUT가 상호작용하는 AI 시스템의 비결정성을 모방할 수 있도록 일정 수준의 비결정성을 가져야 한다.
설명 가능성(Explainability)일부 AI 시스템은 결정 과정 이해가 어렵다. 배포 전에 이를 이해해야 한다면 테스트 환경에 결정법 설명 도구가 포함되어야 한다.
하드웨어AI 시스템을 호스팅하는 일부 하드웨어, 특히 AI 전용 프로세서(AI-specific processor)는 그 목적으로 설계된 것이다. 테스트 환경에 그 하드웨어를 포함해야 할지를 테스트 계획에서 따져야 한다.
빅 데이터대량·초고속·고다양성 데이터를 사용하는 시스템이라면 테스트 환경 일부로 빅 데이터를 구축하기 위한 신중한 계획과 구현이 필요하다.
암기 팁 6요소를 한 줄로: "자(가학습)·자(율)·다(중에이전트)·설(명가능성)·하(드웨어)·빅(데이터)". 이 여섯이 AI 테스트 환경을 전통적인 것과 구분한다.

[Ch10] 가상 테스트 환경 (시뮬레이터)

AI 시스템 테스트에서 가상 테스트 환경(virtual test environment)을 쓰면 다음 일곱 가지 이점이 있다.

7가지 이점

이점설명과 예시
위험한 시나리오SUT, 상호작용 시스템(인간 포함), 운영 환경(나무·건물 등)을 위험에 빠뜨리지 않고 테스트 가능
이상 시나리오실제로는 너무 많은 시간·비용이 필요한 시나리오 테스트. 예: 개기일식, 4대 버스가 동시에 같은 교차로 진입. 현실에서 만들기 어려운 경계 케이스도 더 쉽고 재현 가능하게 구현
극단적 시나리오현실 구현이 불가능한 경우 테스트 가능. 예: 핵 재난, 먼 우주 탐사
시간 집약적 시나리오시간을 단축해 테스트 가능(예: 1초에 여러 번). 실시간으로는 몇 시간·며칠 걸릴 시나리오를 압축. 클라우드에서 병렬 실행도 가능해 실제 하드웨어로는 불가능한 동시 시나리오를 처리
관찰 가능성·제어 가능성훨씬 높은 제어 가능성 — 비정상적 금융 거래 조건을 반복 발생시킬 수 있다. 디지털 환경 전부를 지속 모니터링·기록할 수 있어 관찰 가능성도 우수
가용성아직 개발되지 않았거나 너무 비싼 하드웨어 컴포넌트가 필요한 시스템 테스트를 시뮬레이션으로 실행 가능

대표 가상 테스트 환경 도구

특정 시스템 전용, 도메인 지원용, 범용 등 다양하다. 실러버스가 인용하는 예시는 다음과 같다.

  • Morse (Modular Open Robots Simulation Engine) — 블렌더 게임 엔진 기반의 범용 모바일 로봇 시뮬레이터.
  • AI Habitat — Facebook AI가 만든 시뮬레이션 플랫폼. 가상 로봇 같은 구현된 에이전트를 사실적 3D 환경에서 훈련.
  • NVIDIA DRIVE Constellation — 자율주행을 위한 확장 가능 개방형 플랫폼. 클라우드 기반으로 수십억 마일의 자율주행 테스트 생성 가능.
  • MATLAB / Simulink — 훈련 데이터 준비, ML 모델 생성, 합성 데이터로 AI 시스템 실행 시뮬레이션 제공.
도메인 예 — 자율주행·금융·스마트시티
  • 자율주행 — 사고·악천후·드문 교통 상황을 안전하게 반복 재현
  • 금융 — 비정상 거래 조건을 반복 발생시켜 모델 반응 검증
  • 스마트시티 — 교통량·이벤트·재난 같은 거시 시나리오를 시간 단축 실행

테스팅에 AI 활용하기

여기서부터는 화살표 방향이 바뀐다. 지금까지는 "AI 시스템을 테스트하는 법"이었다면, 이제는 "테스팅 활동을 AI로 어떻게 도울 수 있는가"가 주제다.

[Ch11] 테스팅을 위한 AI 기술 — 개요

Harman[B24]에 따르면 소프트웨어 엔지니어링 커뮤니티는 다음 세 가지 AI 기술 범위를 사용한다.

AI 기술테스팅 활용 예
퍼지논리 + 확률적 방법확률 문제 처리에 AI 활용. 베이지안 기법으로 시스템 고장 분석·예측, 컴포넌트 오류 가능성 추정, 인간 상호작용의 무작위성 반영
분류·학습·예측프로젝트 계획에서 비용 예측, 결함 예측. ML로 구현되며 결함 관리(11.2), 결함 예측(11.5), GUI 테스팅(11.6)에 활용
컴퓨터 기반 검색·최적화크고 복잡한 검색 공간에서 최적화 문제 해결. 테스트 케이스 작성(11.3), 커버리지 달성용 최소 케이스 식별, 회귀 케이스 최적화(11.4)

현재 AI로 어려운 테스팅 활동

실러버스 11.1.1 토론에 따르면 다음 활동은 현재 AI로 구현하기 비현실적이다.

  • 테스트 오라클을 지정하기
  • 모호성 해결과 누락된 정보 도출을 위해 이해관계자와 소통하기
  • 사용자 경험 개선을 제안하기
  • 이해관계자의 가정에 도전하고 불편한 질문 던지기
  • 사용자 필요사항을 이해하기

일부 작업에 활용 가능한 약인공지능(narrow AI)과 아직 없는 강인공지능(general AI)은 구분해서 논의해야 한다.

[Ch11] AI로 보고된 결함 분석하기

결함 보고서는 보통 분류·우선순위 할당·중복 식별을 거친다. 이 활동을 결함 분류·분석(defect triage)이라고 한다. AI는 다음 세 갈래로 이 활동을 돕는다.

활동AI 활용 방법
분류 (Categorization)NLP로 결함 보고서 텍스트를 분석해 영향 받는 기능 영역 등 주제 추출. k-최근접 이웃(k-NN)이나 서포트 벡터 머신(SVM) 같은 클러스터링 알고리즘에 메타데이터와 함께 제공해 적절한 분류와 중복 결함을 찾아낸다. 대규모 자동화 결함 보고 시스템(예: Windows·Firefox)에 특히 유용
심각도 (Criticality)가장 심각한 결함 특성으로 훈련된 ML 모델로 주된 시스템 장애를 일으킬 가능성이 높은 결함을 식별
배정 (Assignment)결함 내용과 이전 개발자 배정 기록을 기반으로 특정 결함을 수정하기 가장 적합한 개발자를 제안

[Ch11] AI로 테스트 케이스 작성하기

AI로 테스트를 작성하면 테스트 산출물을 빠르게 만들고 커버리지(코드·요구사항)를 최대화하는 데 효과적이다. 베이시스 후보는 다음과 같다.

  • 소스 코드
  • 사용자 인터페이스
  • 기계가 읽을 수 있는 테스트 모델
  • 시스템 하위 동작 관찰값·계측값·로그 파일
또 다시 오라클 문제 필요한 동작을 정의한 테스트 모델이 베이시스가 아니라면, AI가 자동 생성한 테스트도 결국 오라클 문제를 겪는다. AI 도구가 주어진 테스트 데이터의 기대 결과를 알지 못하기 때문이다.

대응 방법은 두 가지다.

  • 백투백 테스팅 — 슈도 오라클로 쓸 적절한 시스템이 있을 때(Ch9.3 참조).
  • 단순 장애 기준 — "애플리케이션 응답 없음", 시스템 크래시 같은 명백한 장애가 발생하지 않는다는 정도의 기대 결과로 테스트.

한 연구[B27]에 따르면 AI 기반 테스트 작성 도구는 비-AI 퍼지 테스팅 도구와 비교해 같은 커버리지를 달성하면서 장애를 일으키는 데 필요한 평균 단계를 약 15,000개에서 약 100개로 줄였다. 디버깅이 훨씬 쉬워진다는 의미다.

[Ch11] AI로 회귀 테스트 스위트 최적화

시스템이 변경되면 새로운 테스트가 만들어지고 회귀 스위트에 추가된다. 스위트가 너무 커지는 것을 막으려면 잦은 최적화로 테스트 케이스를 선택·우선순위 부여·보강해야 한다.

AI 기반 도구는 다음 정보를 분석해 회귀 스위트를 최적화한다.

  • 이전 테스트 결과
  • 관련 결함
  • 최근 변경 사항
  • 오류 발생 빈도가 높은 기능
  • 최근 변경의 영향을 받은 코드 실행 테스트
연구 결과 수치
  • 회귀 테스트 스위트 크기를 50% 줄여도 대부분 결함 식별 가능[B28]
  • 지속적 통합 프로세스에서 장애 검출 큰 감소 없이 테스트 수행 시간 40% 단축 가능[B29]

[Ch11] AI로 결함 예측

결함 예측은 다음 셋 중 하나 이상을 예측한다.

  • 결함 존재 여부
  • 존재하는 결함 수
  • 결함 발견 가능성

결과는 보통 테스팅 우선순위 결정에 쓰인다(예: 결함이 더 예측되는 컴포넌트에 더 많은 테스트 수행).

결함 예측의 입력 변수

일반적으로 다음 측정지표 기반이다.

  • 소스 코드 측정지표
  • 프로세스 측정지표
  • 인력·조직에 대한 측정지표

고려할 잠재 요소가 너무 많아 사람의 능력을 넘는다. 그래서 ML 기반 접근이 주류다. 결함 예측은 유사한 상황(같은 코드 기반 또는 같은 개발자)의 이전 경험을 기반으로 할 때 가장 효과적이다.

의외의 연구 결과 Nagappan 등[B32]에 따르면 결함 예측에 가장 큰 영향을 미치는 변수는 코드 라인 수·순환 복잡도 같은 널리 쓰이는 소스 코드 측정지표가 아니라 인력·조직에 대한 측정지표인 것으로 밝혀졌다. 누가 어떻게 일했는지가 코드의 어떤 모양보다도 결함을 잘 설명한다는 뜻이다.

[Ch11] AI로 사용자 인터페이스 테스팅

AI 활용 GUI를 통한 테스트 (Testing through the GUI)

GUI를 통한 테스트는 수동 테스팅의 일반적 접근이며 테스트 자동화의 출발점이다. 전통적 자동화는 UI 요소 좌표나 정의된 객체명/위젯을 쓰는 캡처/재생 방식이지만, 다음 단점이 있다.

  • 객체 식별의 취약성
  • 인터페이스 변경에 민감
  • 코드 변경에 민감
  • 플랫폼 변경에 민감

AI는 이 취약성을 보완한다. AI 기반 도구는 다양한 기준(XPath, 라벨, ID, 클래스, X/Y 좌표)으로 올바른 객체를 식별하고, 과거 데이터로 가장 안정적인 식별 기준을 선택한다. 예: 특정 영역의 버튼 ID가 릴리즈마다 바뀌면, AI 도구는 시간이 지남에 따라 ID의 중요도를 낮추고 다른 기준에 의존한다.

시각 정보 기반 테스팅은 이미지 인식으로 실제 사용자와 같은 인터페이스에서 GUI 객체와 상호작용한다. 코드나 인터페이스 정의 접근이 필요 없어 완전 비해체적(non-intrusive)·근간 기술 독립적이다. 전체 화면 레이아웃에 영향받지 않고 이미지·버튼·텍스트 필드와 직접 상호작용하는 스크립트를 만들 수 있다.

AI 활용 GUI 테스트 (Testing of the GUI)

ML 모델(예: 휴리스틱·지도학습)로 UI 화면의 인수 가능 여부도 결정할 수 있다. 이런 모델 기반 도구는 다음을 찾는다.

  • 잘못 렌더링된 요소
  • 접근 불가하거나 식별 어려운 객체
  • GUI 시각적 모습의 다양한 문제

이미지 인식도 컴퓨터 비전의 한 형태이지만, 다른 형태로는 스크린샷 비교를 통해 레이아웃·크기·위치·색상·글꼴·기타 가시 속성에 의도하지 않은 변경이 없었는지 확인하는 데 쓸 수 있다. 이는 회귀 테스팅 지원에 효과적이다.

스크린 인수 가능 여부 점검 기술 + 비교 도구를 결합하면 더 정교한 AI 기반 회귀 테스팅 도구가 된다. UI 변경을 사용자가 수용할 수 있는지, 사람이 점검해야 하는지를 조언한다. 다양한 브라우저·기기·플랫폼에서 호환성 테스팅 지원에도 쓰인다.

두 영역의 구분
  • GUI를 통한 테스트 — GUI를 도구로 써서 시스템을 테스트(기능 검증). AI가 객체 식별을 안정화.
  • GUI 자체 테스트 — GUI가 올바른지 검증(시각적 회귀). AI가 렌더링 문제를 찾아냄.

연습 문제

Q1. AI 시스템의 테스트 환경이 전통적 테스트 환경과 다른 요소로 옳지 않은 것은?
  • 자가학습 — 정의되지 않은 환경 변화를 모방해야 한다
  • 다중 에이전트 — 상호작용 AI의 비결정성을 모방해야 한다
  • 고정 결정성 — 입력별로 항상 같은 출력이 보장된다
  • AI 전용 프로세서 — 특수 하드웨어를 환경에 포함할지 고려해야 한다
정답: C. AI 시스템은 오히려 비결정성·확률성이 특징이다. 그래서 환경에도 일정 수준의 비결정성이 필요하다.
Q2. 가상 테스트 환경의 이점으로 옳은 두 개를 고르시오.
  • 실제 발생을 기다리기 어려운 이상 시나리오를 재현 가능하게 만든다
  • 시간을 단축해 며칠 걸릴 시나리오를 빠르게 실행 가능
  • 실제 운영 환경과 100% 일치하는 결과를 보장한다
  • AI 시스템의 비결정성을 완전히 제거한다
정답: A, B. C는 과장(시뮬레이션의 본질적 한계 존재), D는 잘못된 진술(가상 환경도 비결정성을 모방할 수 있어야 함)이다.
Q3. AI를 활용한 결함 분석에서 NLP와 클러스터링 알고리즘이 주로 사용되는 활동은?
  • 결함 보고서의 분류와 중복 식별
  • 결함이 발생한 코드 라인의 직접 수정
  • 요구사항 문서 자동 작성
  • 사용자 경험 개선 제안
정답: A. NLP가 텍스트 주제를 뽑고 k-NN, SVM 같은 클러스터링이 유사 결함을 묶는다.
Q4. AI 기반 결함 예측에 대한 설명으로 옳은 것은?
  • 모든 코드 라인의 정확한 결함 위치를 100% 정확히 예측한다
  • 인력·조직 측정지표가 코드 라인 수·복잡도보다 결함 예측에 더 큰 영향을 미친다는 연구가 있다
  • 훈련 데이터가 다른 코드 기반에서 왔을 때 가장 효과적이다
  • 결과는 테스트가 아닌 배포 자동화에만 쓰인다
정답: B. Nagappan 등의 연구 결과. 같은 코드 기반·같은 개발자 이력일 때 가장 효과적이라는 점도 함께 기억할 것.
Q5. AI 기반 GUI 테스트 자동화 도구가 전통적 캡처/재생 접근의 단점을 보완하는 방식으로 옳은 것은?
  • 모든 객체를 X/Y 좌표 하나만으로 고정 식별한다
  • XPath·라벨·ID·클래스·좌표 등 다양한 기준으로 객체를 식별하고, 과거 데이터로 가장 안정적인 기준을 선택한다
  • 객체 식별을 완전히 포기하고 매번 사람이 클릭한다
  • 인터페이스가 변경될 때마다 스크립트를 처음부터 다시 작성한다
정답: B. 다중 기준 + 과거 데이터 기반 선택이 핵심이다.
Q6. 현재 약인공지능으로 구현하기 비현실적인 테스팅 활동이 아닌 것은?
  • 이해관계자의 가정에 도전하고 불편한 질문 던지기
  • NLP를 사용한 결함 보고서 중복 식별
  • 사용자 필요사항 이해하기
  • 사용자 경험 개선 제안하기
정답: B. 결함 보고서 중복 식별은 이미 AI로 잘 수행되는 영역이다. 나머지는 강인공지능 수준이 필요하다.
