WPF 컨트롤 확장 3가지

WPF에서 "재사용 가능한 UI 단위"를 만드는 방법은 크게 세 가지다. 각자 목적과 비용이 다르므로 상황에 맞게 선택한다.

UserControl은 조합, Custom Control은 새 컨트롤, ControlTemplate은 외관 교체.
방법목적외관 커스텀테마화적용 비용
UserControl화면 한 조각 묶기제한적불가매우 낮음
Custom Control새 컨트롤 제공완전가능높음
ControlTemplate기존 컨트롤 외관 교체완전가능중간

UserControl — 빠른 조합

UserControl은 기존 컨트롤들을 XAML로 조합해 하나로 묶는 방식이다. .xaml과 .xaml.cs 한 쌍이 생기며, View 한 조각으로 쓴다.

만들기

<!-- LabeledTextBox.xaml -->
<UserControl x:Class="VisionApp.Controls.LabeledTextBox"
             xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml">
    <StackPanel Orientation="Horizontal">
        <TextBlock Text="{Binding Label, RelativeSource={RelativeSource AncestorType=UserControl}}"
                   Width="80" VerticalAlignment="Center"/>
        <TextBox Text="{Binding Value, RelativeSource={RelativeSource AncestorType=UserControl},
                                Mode=TwoWay, UpdateSourceTrigger=PropertyChanged}"
                 Width="120"/>
    </StackPanel>
</UserControl>
// LabeledTextBox.xaml.cs
public partial class LabeledTextBox : UserControl
{
    public static readonly DependencyProperty LabelProperty =
        DependencyProperty.Register(nameof(Label), typeof(string),
            typeof(LabeledTextBox), new PropertyMetadata(string.Empty));

    public static readonly DependencyProperty ValueProperty =
        DependencyProperty.Register(nameof(Value), typeof(string),
            typeof(LabeledTextBox),
            new FrameworkPropertyMetadata(string.Empty,
                FrameworkPropertyMetadataOptions.BindsTwoWayByDefault));

    public string Label
    {
        get => (string)GetValue(LabelProperty);
        set => SetValue(LabelProperty, value);
    }

    public string Value
    {
        get => (string)GetValue(ValueProperty);
        set => SetValue(ValueProperty, value);
    }

    public LabeledTextBox()
    {
        InitializeComponent();
    }
}

사용

<Window xmlns:ctrl="clr-namespace:VisionApp.Controls">
    <StackPanel>
        <ctrl:LabeledTextBox Label="Exposure" Value="{Binding Exposure}"/>
        <ctrl:LabeledTextBox Label="Gain"     Value="{Binding Gain}"/>
    </StackPanel>
</Window>
UserControl의 강점 한 화면에서만 쓰는 합성 컨트롤·페이지 일부에 가장 적합하다. 코드비하인드에서 바로 이벤트를 다룰 수 있어서 진입 장벽이 낮다.
UserControl은 외관 커스텀이 어렵다 XAML이 고정되므로 사용처에서 Template을 교체할 수 없다. "사용자가 외관을 바꿀 수 있어야 하는 컨트롤"이면 Custom Control을 선택한다.

Custom Control — 진짜 새 컨트롤

Custom Control은 Control(또는 그 파생)을 상속해 만든다. 기본 외관은 Themes/Generic.xaml에 ControlTemplate으로 제공한다. 라이브러리·재사용 컨트롤·테마화가 필요할 때 선택한다.

클래스 정의

// LedIndicator.cs
public class LedIndicator : Control
{
    static LedIndicator()
    {
        // Generic.xaml의 기본 스타일을 자동으로 찾도록 한다.
        DefaultStyleKeyProperty.OverrideMetadata(typeof(LedIndicator),
            new FrameworkPropertyMetadata(typeof(LedIndicator)));
    }

    public static readonly DependencyProperty IsOnProperty =
        DependencyProperty.Register(nameof(IsOn), typeof(bool),
            typeof(LedIndicator), new PropertyMetadata(false));

    public static readonly DependencyProperty OnColorProperty =
        DependencyProperty.Register(nameof(OnColor), typeof(Brush),
            typeof(LedIndicator), new PropertyMetadata(Brushes.LimeGreen));

    public bool IsOn
    {
        get => (bool)GetValue(IsOnProperty);
        set => SetValue(IsOnProperty, value);
    }

    public Brush OnColor
    {
        get => (Brush)GetValue(OnColorProperty);
        set => SetValue(OnColorProperty, value);
    }
}

Themes/Generic.xaml

<!-- Themes/Generic.xaml — 경로와 이름 모두 정확해야 한다 -->
<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
                    xmlns:local="clr-namespace:VisionApp.Controls">

    <Style TargetType="{x:Type local:LedIndicator}">
        <Setter Property="Width"  Value="20"/>
        <Setter Property="Height" Value="20"/>
        <Setter Property="Template">
            <Setter.Value>
                <ControlTemplate TargetType="{x:Type local:LedIndicator}">
                    <Grid>
                        <Ellipse x:Name="PART_Light"
                                 Fill="#333" Stroke="#111" StrokeThickness="1"/>
                    </Grid>
                    <ControlTemplate.Triggers>
                        <Trigger Property="IsOn" Value="True">
                            <Setter TargetName="PART_Light" Property="Fill"
                                    Value="{Binding OnColor,
                                            RelativeSource={RelativeSource TemplatedParent}}"/>
                        </Trigger>
                    </ControlTemplate.Triggers>
                </ControlTemplate>
            </Setter.Value>
        </Setter>
    </Style>

</ResourceDictionary>

AssemblyInfo.cs 설정

// 외부 라이브러리에서 Generic.xaml을 인식시키려면 필요하다.
[assembly: ThemeInfo(
    ResourceDictionaryLocation.None,
    ResourceDictionaryLocation.SourceAssembly)]

사용 측

<ctrl:LedIndicator IsOn="{Binding CameraConnected}"
                   OnColor="LimeGreen" Width="24" Height="24"/>
Generic.xaml의 위치·이름은 고정이다 반드시 프로젝트 루트의 Themes/Generic.xaml이어야 한다. 폴더 이름이 다르거나 파일이 누락되면 컨트롤은 아무것도 그려지지 않은 빈 박스로 보인다. Custom Control 디버깅의 첫 번째 의심 지점이다.

ControlTemplate — 외관 교체

ControlTemplate은 기존 컨트롤의 시각적 구조를 통째로 갈아끼우는 도구다. 동작(누름·포커스·바인딩)은 그대로 유지된다.

<!-- 둥근 파스텔 버튼 -->
<Window.Resources>
    <Style x:Key="PillButton" TargetType="Button">
        <Setter Property="Background"  Value="#FFB199"/>
        <Setter Property="Foreground"  Value="#3D2A20"/>
        <Setter Property="FontWeight"  Value="SemiBold"/>
        <Setter Property="Padding"     Value="14,6"/>
        <Setter Property="Template">
            <Setter.Value>
                <ControlTemplate TargetType="Button">
                    <Border x:Name="Bd"
                            Background="{TemplateBinding Background}"
                            CornerRadius="16" Padding="{TemplateBinding Padding}">
                        <ContentPresenter HorizontalAlignment="Center"
                                          VerticalAlignment="Center"/>
                    </Border>
                    <ControlTemplate.Triggers>
                        <Trigger Property="IsMouseOver" Value="True">
                            <Setter TargetName="Bd" Property="Background" Value="#FFC9B5"/>
                        </Trigger>
                        <Trigger Property="IsPressed" Value="True">
                            <Setter TargetName="Bd" Property="Background" Value="#E89A82"/>
                        </Trigger>
                    </ControlTemplate.Triggers>
                </ControlTemplate>
            </Setter.Value>
        </Setter>
    </Style>
</Window.Resources>

<Button Style="{StaticResource PillButton}" Content="검사 시작"/>
TemplateBinding과 ContentPresenter TemplateBinding은 템플릿이 적용된 컨트롤의 속성(예: Background)을 참조한다. ContentPresenter는 Content를 그릴 자리 표시자다. 이 둘이 없으면 외관은 바꿔도 컨텐츠가 사라진다.

DataTemplate vs ControlTemplate

혼동하기 쉬운 두 가지를 명확히 구분한다.

구분ControlTemplateDataTemplate
대상컨트롤(Button, ListBoxItem 등)데이터 객체(ViewModel)
역할컨트롤 시각 구조 정의데이터를 어떻게 그릴지 정의
사용 위치Control.TemplateItemTemplate, ContentTemplate
DataContextTemplatedParent해당 데이터 항목
<!-- DataTemplate — InspectionResult를 카드로 표시 -->
<ListBox ItemsSource="{Binding Results}">
    <ListBox.ItemTemplate>
        <DataTemplate DataType="{x:Type vm:InspectionResult}">
            <Border Background="#FFF8F0" CornerRadius="8" Padding="10" Margin="4">
                <StackPanel>
                    <TextBlock Text="{Binding PartId}"  FontWeight="Bold"/>
                    <TextBlock Text="{Binding Score, StringFormat={}{0:F2}}"/>
                </StackPanel>
            </Border>
        </DataTemplate>
    </ListBox.ItemTemplate>
</ListBox>

Style — 속성 묶음과 상속

Style은 여러 Setter를 하나로 묶어 재사용하는 단위다. BasedOn으로 상속할 수 있다.

<Window.Resources>
    <!-- 기본 스타일 -->
    <Style x:Key="BaseButton" TargetType="Button">
        <Setter Property="FontSize"   Value="13"/>
        <Setter Property="Padding"    Value="10,4"/>
        <Setter Property="Foreground" Value="#222"/>
    </Style>

    <!-- 상속 + 추가 -->
    <Style x:Key="PrimaryButton"
           TargetType="Button"
           BasedOn="{StaticResource BaseButton}">
        <Setter Property="Background" Value="#3B82F6"/>
        <Setter Property="Foreground" Value="White"/>
        <Setter Property="FontWeight" Value="Bold"/>
    </Style>

    <!-- 키 없는 스타일 — 해당 타입 전체에 자동 적용 -->
    <Style TargetType="TextBox">
        <Setter Property="Margin"  Value="0,2"/>
        <Setter Property="Padding" Value="6,2"/>
    </Style>
</Window.Resources>
키 없는 Style은 암시적으로 적용된다 x:Key가 없으면 해당 스코프 내 모든 같은 타입 컨트롤에 자동 적용된다. 디자인 시스템의 베이스라인을 깔 때 유용하다.

Trigger · DataTrigger · EventTrigger

Trigger는 "어떤 조건이면 어떤 속성을 바꿔라"는 선언적 규칙이다. 3가지 종류가 있다.

종류발동 조건예시
Trigger의존성 속성 값IsMouseOver=True
DataTrigger바인딩 값{Binding State}=Error
EventTrigger이벤트 발생MouseEnter 시 애니메이션
MultiTrigger여러 조건 ANDIsFocused AND IsMouseOver
MultiDataTrigger여러 바인딩 ANDState=Run AND HasError=True
<Style TargetType="Border" x:Key="StatusCard">
    <Setter Property="Background" Value="#EEE"/>
    <Style.Triggers>
        <!-- 1) 속성 Trigger -->
        <Trigger Property="IsMouseOver" Value="True">
            <Setter Property="Background" Value="#DDD"/>
        </Trigger>

        <!-- 2) DataTrigger — ViewModel 값 기반 -->
        <DataTrigger Binding="{Binding State}" Value="Error">
            <Setter Property="Background" Value="#FECACA"/>
        </DataTrigger>
        <DataTrigger Binding="{Binding State}" Value="Ok">
            <Setter Property="Background" Value="#A7F3D0"/>
        </DataTrigger>

        <!-- 3) MultiDataTrigger -->
        <MultiDataTrigger>
            <MultiDataTrigger.Conditions>
                <Condition Binding="{Binding IsRunning}" Value="True"/>
                <Condition Binding="{Binding HasError}"  Value="True"/>
            </MultiDataTrigger.Conditions>
            <Setter Property="BorderBrush"     Value="Red"/>
            <Setter Property="BorderThickness" Value="2"/>
        </MultiDataTrigger>

        <!-- 4) EventTrigger — 스토리보드 애니메이션 -->
        <EventTrigger RoutedEvent="MouseEnter">
            <BeginStoryboard>
                <Storyboard>
                    <DoubleAnimation Storyboard.TargetProperty="Opacity"
                                     To="0.85" Duration="0:0:0.15"/>
                </Storyboard>
            </BeginStoryboard>
        </EventTrigger>
    </Style.Triggers>
</Style>
Trigger 우선순위 — 마지막에 정의된 것이 이긴다 같은 속성을 여러 Trigger가 건드리면 XAML에서 나중에 선언된 Trigger가 최종값을 결정한다. 또한 인라인 속성·로컬값이 Style보다 항상 우선한다. "왜 색이 안 바뀌지?"의 90%는 우선순위 문제다.

Resource — Static vs Dynamic

Resource는 XAML에 정의해 둔 재사용 가능한 객체(브러시·스타일·템플릿)다. 참조 방법이 두 가지다.

참조해석 시점런타임 교체 반응성능
StaticResourceXAML 로드 시 1회반영 안 됨빠름
DynamicResource매번 추적즉시 반영느림
<!-- App.xaml — 애플리케이션 전역 리소스 -->
<Application.Resources>
    <SolidColorBrush x:Key="AccentBrush" Color="#FF7A45"/>
    <SolidColorBrush x:Key="BgBrush"     Color="#FFFFFF"/>
</Application.Resources>

<!-- 사용 측 -->
<Border Background="{StaticResource  BgBrush}"/>     <!-- 한 번만 해석 -->
<Border Background="{DynamicResource BgBrush}"/>    <!-- 런타임 교체 반응 -->

리소스 탐색 순서

WPF는 다음 순서로 키를 찾는다. 위에서 발견되면 거기서 멈춘다.

  1. 요소 자신의 Resources
  2. 부모 → 조부모 → ... → Window.Resources
  3. Application.Resources
  4. 시스템 리소스 / 테마

Theme — 다크/라이트 교체

테마는 ResourceDictionary를 통째로 갈아끼우는 방식으로 구현한다. DynamicResource로 참조해야 즉시 반영된다.

<!-- Themes/Light.xaml -->
<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation">
    <SolidColorBrush x:Key="BgBrush"   Color="#FFFFFF"/>
    <SolidColorBrush x:Key="FgBrush"   Color="#1F2937"/>
    <SolidColorBrush x:Key="CardBrush" Color="#F9FAFB"/>
</ResourceDictionary>

<!-- Themes/Dark.xaml -->
<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation">
    <SolidColorBrush x:Key="BgBrush"   Color="#0F172A"/>
    <SolidColorBrush x:Key="FgBrush"   Color="#E2E8F0"/>
    <SolidColorBrush x:Key="CardBrush" Color="#1E293B"/>
</ResourceDictionary>
// 런타임 테마 교체
public static class ThemeManager
{
    public static void Apply(string themeName)
    {
        var dict = new ResourceDictionary
        {
            Source = new Uri($"/Themes/{themeName}.xaml", UriKind.Relative)
        };

        var merged = Application.Current.Resources.MergedDictionaries;
        // 기존 테마 제거
        var old = merged.FirstOrDefault(d =>
            d.Source != null && d.Source.OriginalString.Contains("/Themes/"));
        if (old != null) merged.Remove(old);
        merged.Add(dict);
    }
}

// 사용
ThemeManager.Apply("Dark");

Attached Behavior

코드비하인드 없이 컨트롤에 동작을 "붙이는" 기법이다. System.Windows.Interactivity(또는 Microsoft.Xaml.Behaviors.Wpf NuGet)을 쓴다.

// Microsoft.Xaml.Behaviors.Wpf NuGet 사용
using Microsoft.Xaml.Behaviors;

public class SelectAllOnFocusBehavior : Behavior<TextBox>
{
    protected override void OnAttached()
    {
        AssociatedObject.GotFocus += OnGotFocus;
    }

    protected override void OnDetaching()
    {
        AssociatedObject.GotFocus -= OnGotFocus;
    }

    private void OnGotFocus(object sender, RoutedEventArgs e)
    {
        AssociatedObject.SelectAll();
    }
}
<TextBox xmlns:i="http://schemas.microsoft.com/xaml/behaviors"
         xmlns:b="clr-namespace:VisionApp.Behaviors">
    <i:Interaction.Behaviors>
        <b:SelectAllOnFocusBehavior/>
    </i:Interaction.Behaviors>
</TextBox>

첨부 속성 방식

가벼운 동작은 첨부 속성(Attached Property)만으로도 충분하다.

public static class FocusOnLoadHelper
{
    public static readonly DependencyProperty EnabledProperty =
        DependencyProperty.RegisterAttached(
            "Enabled", typeof(bool), typeof(FocusOnLoadHelper),
            new PropertyMetadata(false, OnChanged));

    public static void SetEnabled(DependencyObject obj, bool value)
        => obj.SetValue(EnabledProperty, value);

    public static bool GetEnabled(DependencyObject obj)
        => (bool)obj.GetValue(EnabledProperty);

    private static void OnChanged(DependencyObject d, DependencyPropertyChangedEventArgs e)
    {
        if (d is FrameworkElement fe && (bool)e.NewValue)
        {
            fe.Loaded += (_, __) => fe.Focus();
        }
    }
}
<TextBox xmlns:h="clr-namespace:VisionApp.Helpers"
         h:FocusOnLoadHelper.Enabled="True"/>

산업 비전 UI 적용

비전 검사 화면은 상태 시각화가 핵심이다. 검사 결과 카드·노드 컨트롤·게이지를 각자 적절한 도구로 만든다.

검사 결과 카드 — DataTemplate + DataTrigger

<DataTemplate DataType="{x:Type vm:InspectionResult}">
    <Border x:Name="Card" CornerRadius="8" Padding="12" Margin="4"
            Background="#F3F4F6" BorderThickness="1" BorderBrush="#E5E7EB">
        <StackPanel>
            <TextBlock Text="{Binding PartId}"  FontWeight="Bold"/>
            <TextBlock Text="{Binding Score, StringFormat={}{0:F3}}"
                       FontSize="11" Foreground="#6B7280"/>
        </StackPanel>
    </Border>
    <DataTemplate.Triggers>
        <DataTrigger Binding="{Binding Verdict}" Value="OK">
            <Setter TargetName="Card" Property="Background" Value="#DCFCE7"/>
            <Setter TargetName="Card" Property="BorderBrush" Value="#16A34A"/>
        </DataTrigger>
        <DataTrigger Binding="{Binding Verdict}" Value="NG">
            <Setter TargetName="Card" Property="Background" Value="#FEE2E2"/>
            <Setter TargetName="Card" Property="BorderBrush" Value="#DC2626"/>
        </DataTrigger>
    </DataTemplate.Triggers>
</DataTemplate>

노출 게이지 — Custom Control

public class ExposureGauge : Control
{
    static ExposureGauge()
    {
        DefaultStyleKeyProperty.OverrideMetadata(typeof(ExposureGauge),
            new FrameworkPropertyMetadata(typeof(ExposureGauge)));
    }

    public static readonly DependencyProperty ValueProperty =
        DependencyProperty.Register(nameof(Value), typeof(double),
            typeof(ExposureGauge), new PropertyMetadata(0.0));

    public static readonly DependencyProperty MaxValueProperty =
        DependencyProperty.Register(nameof(MaxValue), typeof(double),
            typeof(ExposureGauge), new PropertyMetadata(100.0));

    public double Value
    {
        get => (double)GetValue(ValueProperty);
        set => SetValue(ValueProperty, value);
    }

    public double MaxValue
    {
        get => (double)GetValue(MaxValueProperty);
        set => SetValue(MaxValueProperty, value);
    }
}

데이터 플로우 노드 — Custom Control + ControlTemplate

블록 에디터의 노드는 입출력 포트·헤더·바디·드래그 동작을 갖춘다. Custom Control로 정의하고 사용처에서 ControlTemplate으로 스킨을 바꿀 수 있도록 한다. 자세한 구현은 11편에서 다룬다.

흔한 함정

1. UserControl로 모든 걸 해결하려 한다 팀 라이브러리에서 외관·테마를 통제해야 하는 컨트롤을 UserControl로 만들면, 나중에 외관 교체가 필요해질 때 전체를 다시 짜야 한다. 라이브러리 컨트롤은 Custom Control이 정답이다.
2. Generic.xaml 경로·이름 누락 반드시 Themes/Generic.xaml이어야 하고, AssemblyInfo.cs의 ThemeInfo가 설정돼 있어야 한다. 누락 시 컨트롤은 빈 박스로 보인다.
3. Trigger 우선순위 — 로컬값이 항상 이긴다 XAML 인라인 속성(Background="Red")은 Style·Trigger보다 우선한다. Trigger로 색을 바꾸려면 인라인 속성을 빼고 Style의 Setter로 옮긴다.
4. Resource 키 충돌 같은 x:Key가 여러 ResourceDictionary에 있으면 탐색 순서상 가까운 것이 이긴다. 디자인 시스템은 키 네이밍 규칙(Brush.Bg.Primary 같은 접두어)을 정해 두는 게 좋다.
5. DynamicResource 남용으로 성능 저하 DynamicResource는 매 참조마다 추적 비용이 든다. 런타임 교체가 필요한 항목(테마 색)에만 쓰고, 정적인 값은 StaticResource를 쓴다.
6. ContentPresenter 누락으로 Content가 사라진다 ControlTemplate에서 ContentPresenter(또는 TextBlock의 경우 ContentPresenter 자리에 해당 표시자)를 빼면 외관은 보여도 텍스트·자식 요소가 사라진다.
