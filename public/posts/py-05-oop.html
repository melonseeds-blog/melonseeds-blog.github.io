Python OOP 개요

Python에서는 모든 것이 객체다. 정수 3도, 함수도, 심지어 클래스 자체도 객체다. type(3)은 int를 반환하고, type(int)는 type을 반환한다. 클래스도 결국 type이라는 메타클래스의 인스턴스인 셈이다.

클래스 정의는 간단하다. class 키워드 하나로 시작하고, 접근 제어자(public/private)나 인터페이스 키워드는 없다. C++/Java처럼 헤더를 따로 두지도 않는다.

class Dog:
    pass

d = Dog()
print(type(d))   # <class '__main__.Dog'>
print(isinstance(d, Dog))  # True

이 단순함의 대가는 모든 규칙이 컨벤션이라는 점이다. 비공개는 언더스코어로, 추상 메서드는 abc 모듈로, 인터페이스는 덕 타이핑으로 표현한다. 컴파일러가 막아 주지 않으니 개발자가 약속을 지켜야 한다.

class와 인스턴스

__init__과 self

__init__은 생성자가 아니라 초기화자다. 객체 생성은 __new__가 담당하고, __init__은 이미 만들어진 객체에 속성을 채워 넣는다. 첫 인자 self는 인스턴스 자신을 가리키며, 호출 시 자동으로 전달된다.

class Dog:
    def __init__(self, name, age):
        self.name = name   # 인스턴스 변수
        self.age = age

d = Dog("Rex", 3)
print(d.name, d.age)   # Rex 3

인스턴스 변수 vs 클래스 변수

인스턴스 변수는 객체마다 따로 존재한다. 클래스 변수는 클래스 자체에 한 번만 존재하고 모든 인스턴스가 공유한다.

class Dog:
    species = "Canis lupus familiaris"   # 클래스 변수 (공유)

    def __init__(self, name):
        self.name = name                  # 인스턴스 변수 (개별)

a = Dog("Rex")
b = Dog("Buddy")
print(a.species, b.species)   # 둘 다 "Canis lupus familiaris"

Dog.species = "Dog"           # 클래스를 통해 바꾸면 모두 반영
print(a.species, b.species)   # Dog Dog

a.species = "Mutant"          # 인스턴스 속성 새로 생성 (shadowing)
print(a.species, b.species)   # Mutant Dog
속성 조회 순서 Python은 속성을 찾을 때 인스턴스 → 클래스 → 부모 클래스 순으로 탐색한다. a.species를 대입하는 순간 인스턴스 사전에 새 항목이 생기고, 이후 a.species 조회는 인스턴스 수준에서 끝난다.

메서드 세 종류

Python 메서드는 세 가지가 있다. 어떤 인자를 자동으로 받느냐, 어떤 자원에 접근할 수 있느냐가 다르다.

종류데코레이터첫 인자접근 가능주 용도
instance method없음self인스턴스 + 클래스일반 동작
classmethod@classmethodcls클래스만대체 생성자, 클래스 상태 변경
staticmethod@staticmethod없음아무것도 자동 전달 안 됨유틸성 함수, 네임스페이스 묶기
class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    # instance method — 그 객체의 상태에 의존
    def is_weekend(self):
        import datetime
        return datetime.date(self.year, self.month, self.day).weekday() >= 5

    # classmethod — 대체 생성자 패턴이 대표적
    @classmethod
    def from_string(cls, s):
        y, m, d = map(int, s.split("-"))
        return cls(y, m, d)        # cls는 서브클래스 호환

    # staticmethod — 클래스와 논리적으로 묶이지만 self/cls 둘 다 불필요
    @staticmethod
    def is_leap(year):
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

d = Date.from_string("2026-05-15")
print(d.is_weekend(), Date.is_leap(2024))   # False True
대체 생성자는 classmethod로 같은 클래스를 여러 방식으로 만들고 싶을 때 __init__을 복잡하게 만들지 말고 @classmethod로 팩토리를 추가하자. cls(...)로 만들면 서브클래스에서 상속받았을 때도 올바른 타입이 나온다.

속성과 접근 제어

접근 제어 — 컨벤션이 전부다

Python은 private 키워드가 없다. 대신 이름 규약을 쓴다.

이름의미실제 동작
namepublic아무 제한 없음
_nameprotected (컨벤션)"건드리지 마" 신호. 강제력 없음.
__namename mangling_ClassName__name으로 변형. 우연한 충돌 방지용.
__name__dunderPython 예약. 사용자 정의 금지.
class Account:
    def __init__(self, balance):
        self._balance = balance        # protected (관습)
        self.__secret = "pin1234"      # name mangling

a = Account(100)
print(a._balance)            # 100 (가능하지만 권장 안 함)
# print(a.__secret)          # AttributeError
print(a._Account__secret)    # "pin1234" (변형된 이름)

@property — 메서드를 속성처럼

처음엔 단순 속성으로 두었다가 나중에 검증/계산이 필요해지면 @property로 바꾸면 된다. 호출 측 코드는 그대로 두어도 된다.

class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value < 0:
            raise ValueError("radius must be non-negative")
        self._radius = value

    @property
    def area(self):                    # 읽기 전용 — setter 없음
        import math
        return math.pi * self._radius ** 2

c = Circle(5)
print(c.radius, c.area)    # 5 78.539...
c.radius = 10              # setter 호출
# c.area = 0               # AttributeError: can't set attribute

상속과 MRO

기본 상속과 super()

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)         # 부모 초기화
        self.breed = breed

    def speak(self):                   # 오버라이드
        return "Woof!"

d = Dog("Rex", "Shiba")
print(d.name, d.breed, d.speak())   # Rex Shiba Woof!
print(isinstance(d, Animal))         # True

다중 상속과 MRO (C3 선형화)

Python은 다중 상속을 허용한다. 같은 이름의 메서드가 여러 부모에 있으면 MRO(Method Resolution Order)가 어떤 것을 호출할지 정한다. Python은 C3 선형화라는 알고리즘으로 MRO를 계산한다.

다이아몬드 상속 — Python은 C3 선형화로 호출 순서를 결정한다
class A:
    def hello(self):
        print("A.hello")

class B(A):
    def hello(self):
        print("B.hello")
        super().hello()

class C(A):
    def hello(self):
        print("C.hello")
        super().hello()

class D(B, C):                  # 왼쪽이 먼저
    def hello(self):
        print("D.hello")
        super().hello()

D().hello()
print(D.__mro__)
실행 결과
D.hello B.hello C.hello A.hello (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)

super()는 "부모"가 아니라 "MRO에서 다음 클래스"를 가리킨다. B.hello가 super().hello()를 호출하면 A가 아니라 C가 호출되는 이유다. 다이아몬드라도 A.hello는 한 번만 실행된다.

매직 메서드 (dunder)

이름 앞뒤에 언더스코어 두 개가 붙은 메서드를 dunder(double underscore)라고 부른다. Python의 내장 연산자/함수는 대부분 dunder 호출로 구현되어 있다. len(x)는 x.__len__()을, a + b는 a.__add__(b)를 호출한다.

매직 메서드 — 역할별로 묶어 보면 외우기 쉽다

__repr__ vs __str__

둘 다 객체를 문자열로 만든다. __repr__은 개발자용(디버깅, REPL 출력), __str__은 사용자용(print, str())이다. __str__이 없으면 __repr__이 대신 사용된다.

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"   # eval로 복원 가능한 형태

    def __str__(self):
        return f"({self.x}, {self.y})"            # 사람이 읽기 좋게

p = Point(1, 2)
print(p)         # (1, 2)        — __str__
print(repr(p))   # Point(x=1, y=2) — __repr__

__eq__와 __hash__

__eq__를 정의하면 ==의 동작이 바뀐다. 그런데 Python은 __eq__를 사용자가 정의하면 자동으로 __hash__를 None으로 만들어 버린다. 그러면 그 객체는 set/dict 키로 못 쓴다.

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __hash__(self):
        return hash((self.x, self.y))   # eq에 사용한 필드와 동일하게

p1, p2 = Point(1, 2), Point(1, 2)
print(p1 == p2)        # True
print({p1, p2})        # {Point(1, 2)} — 같은 객체로 취급
__eq__를 정의하면 __hash__도 함께 고려하자 규칙: a == b이면 hash(a) == hash(b)여야 한다. 객체를 불변(immutable)으로 설계하고 __hash__에 동일한 필드들을 묶어 넣자. 변경 가능한 객체라면 __hash__ = None으로 두어 해시 불가능하게 만드는 것이 안전하다.

__len__, __iter__, __getitem__

class Deck:
    def __init__(self):
        self.cards = [f"{r}{s}" for s in "SHDC" for r in "A23456789TJQK"]

    def __len__(self):
        return len(self.cards)

    def __getitem__(self, i):
        return self.cards[i]            # 슬라이스도 자동 지원

    def __iter__(self):
        return iter(self.cards)

    def __contains__(self, card):
        return card in self.cards

d = Deck()
print(len(d))         # 52
print(d[0], d[-1])    # AS KC
print("AS" in d)      # True
for c in d:           # __iter__ 호출
    pass

__call__ — 객체를 함수처럼

class Adder:
    def __init__(self, n):
        self.n = n

    def __call__(self, x):
        return x + self.n

add5 = Adder(5)
print(add5(10))    # 15 — 객체를 함수처럼 호출
print(callable(add5))   # True

연산자 오버로드

연산자도 dunder의 일종이다. 산술/비트/비교 연산자가 모두 매직 메서드에 매핑된다. __radd__처럼 앞에 r이 붙으면 좌측 피연산자가 처리하지 못했을 때 우측이 호출된다.

연산자메서드역방향
a + b__add____radd__
a - b__sub____rsub__
a * b__mul____rmul__
a / b__truediv____rtruediv__
a // b__floordiv____rfloordiv__
a == b__eq__좌우 모두 시도
a < b__lt____gt__ 시도
-a__neg__—
class Vec2:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):
        return Vec2(self.x + other.x, self.y + other.y)

    def __mul__(self, k):                # Vec * scalar
        return Vec2(self.x * k, self.y * k)

    def __rmul__(self, k):               # scalar * Vec (좌측이 int면 여기로)
        return self.__mul__(k)

    def __neg__(self):
        return Vec2(-self.x, -self.y)

    def __eq__(self, other):
        return isinstance(other, Vec2) and self.x == other.x and self.y == other.y

    def __repr__(self):
        return f"Vec2({self.x}, {self.y})"

a = Vec2(1, 2)
b = Vec2(3, 4)
print(a + b)        # Vec2(4, 6)
print(3 * a)        # Vec2(3, 6) — __rmul__ 덕분
print(-a)           # Vec2(-1, -2)

dataclass

주로 데이터를 담는 클래스라면 __init__, __repr__, __eq__를 매번 손으로 쓰는 게 지겹다. @dataclass 데코레이터(Python 3.7+)는 이를 자동 생성한다.

from dataclasses import dataclass, field

@dataclass
class Point:
    x: float
    y: float
    label: str = "origin"           # 기본값

p = Point(1.0, 2.0)
print(p)                # Point(x=1.0, y=2.0, label='origin')
print(p == Point(1.0, 2.0))   # True — __eq__ 자동 생성

옵션이 풍부하다. frozen=True로 불변 객체를 만들고, order=True로 비교 연산자까지 자동 생성한다. 가변 기본값에는 field(default_factory=...)를 사용한다.

@dataclass(frozen=True, order=True)
class Version:
    major: int
    minor: int
    patch: int = 0

v1 = Version(1, 2, 3)
v2 = Version(1, 3, 0)
print(v1 < v2)         # True — order=True 덕분
print(hash(v1))         # frozen=True여서 해시 가능
# v1.major = 2         # FrozenInstanceError

@dataclass
class Bag:
    items: list = field(default_factory=list)   # [] 직접 쓰면 위험 (함정 참고)

    def __post_init__(self):
        # __init__ 직후에 호출되는 후처리 훅
        self.items = list(self.items)   # 방어적 복사

abc 모듈 — 추상 베이스 클래스

인터페이스 키워드는 없지만, abc.ABC를 상속하면 추상 메서드를 강제할 수 있다. 추상 메서드를 구현하지 않은 서브클래스는 인스턴스화 시점에 TypeError가 발생한다.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        ...

    @abstractmethod
    def perimeter(self):
        ...

    def describe(self):                  # 구체 메서드도 함께 둘 수 있음
        return f"area={self.area()}, peri={self.perimeter()}"

class Rect(Shape):
    def __init__(self, w, h):
        self.w, self.h = w, h

    def area(self):
        return self.w * self.h

    def perimeter(self):
        return 2 * (self.w + self.h)

# Shape()         # TypeError: Can't instantiate abstract class Shape
r = Rect(3, 4)
print(r.describe())   # area=12, peri=14
Protocol — 더 가벼운 인터페이스 Python 3.8+의 typing.Protocol은 상속 없이 "이런 메서드가 있으면 OK"를 타입 힌트 수준에서 표현한다. 덕 타이핑을 정적 타입 체커에 알려 주는 방법이다. 상속 강제 없이 인터페이스만 표현하고 싶다면 Protocol이 더 가볍다.

가장 큰 인식 차이는 가상 함수의 기본값이다. C++은 virtual로 명시한 함수만 동적 디스패치되지만, Python은 모든 인스턴스 메서드가 동적으로 해석된다. 그래서 베이스 클래스가 호출한 메서드가 서브클래스에서 오버라이드되면 자동으로 서브 버전이 실행된다.

흔한 함정

함정 1 — 클래스 변수에 가변 객체

class Box:
    items = []          # 클래스 변수 (모든 인스턴스가 공유!)

    def add(self, x):
        self.items.append(x)

a = Box()
b = Box()
a.add(1)
print(b.items)   # [1] — 의도와 다름!
가변 기본값은 __init__ 안에서 만들자 리스트/딕셔너리/세트 같은 가변 객체를 클래스 변수로 두면 모든 인스턴스가 같은 객체를 공유한다. 함수의 가변 기본 인자(def f(x=[]):)와 같은 함정이다. 인스턴스마다 별도여야 한다면 __init__에서 self.items = []로 만들자. @dataclass를 쓴다면 field(default_factory=list)를 사용한다. 
class Box:                  # 올바른 버전
    def __init__(self):
        self.items = []     # 인스턴스마다 새 리스트

함정 2 — __eq__만 정의하고 __hash__ 잊기

__eq__를 정의하면 Python이 __hash__를 None으로 설정한다. set이나 dict에 못 넣게 된다.

class P:
    def __init__(self, x): self.x = x
    def __eq__(self, other): return self.x == other.x

# {P(1), P(2)}   # TypeError: unhashable type: 'P'

해결: 같은 필드로 __hash__를 함께 구현하거나, @dataclass(frozen=True, eq=True)를 사용한다.

함정 3 — 다중 상속 MRO 혼동

다중 상속에서 super()는 "다음 부모"가 아니라 "MRO의 다음 클래스"다. 협력적 상속(cooperative multiple inheritance)을 의도하지 않았다면 모든 부모가 super().__init__(...)를 호출하도록 일관되게 설계해야 한다.

class A:
    def __init__(self, **kw):
        super().__init__(**kw)        # object까지 안전하게 도달
        print("A init")

class B(A):
    def __init__(self, **kw):
        super().__init__(**kw)
        print("B init")

class C(A):
    def __init__(self, **kw):
        super().__init__(**kw)
        print("C init")

class D(B, C):
    def __init__(self, **kw):
        super().__init__(**kw)
        print("D init")

D()
# A init → C init → B init → D init  (MRO 역순으로 출력)
의심스러우면 __mro__를 찍어 보자 SomeClass.__mro__ 또는 SomeClass.mro()로 호출 순서를 바로 확인할 수 있다. 다이아몬드 구조가 복잡해질 때 가장 빠른 디버깅 도구다.

함정 4 — __del__에 자원 해제 의존

C++ 소멸자처럼 결정적 호출을 기대하면 안 된다. 순환 참조가 있으면 GC가 한참 뒤에 정리하거나, 인터프리터 종료 시 호출되지 않을 수도 있다. 자원 해제는 __del__ 대신 with 문(컨텍스트 매니저, 다음 글에서 다룸)을 쓰는 것이 정석이다.
