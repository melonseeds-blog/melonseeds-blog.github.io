픽셀 단위 연산 개요

픽셀 단위 연산(element-wise operation)은 같은 위치의 픽셀끼리 독립적으로 계산하는 연산이다. 출력 이미지의 (x, y) 픽셀은 오직 입력 이미지의 (x, y) 픽셀에만 의존한다 — 이웃 픽셀을 보지 않는다. 필터처럼 주변을 훑는 연산과 구분되는 가장 단순하면서도 자주 쓰이는 연산 부류다.

연산 대상은 크게 두 가지다. 두 이미지 간 연산(이미지 + 이미지)과 이미지-스칼라 간 연산(이미지 + 상수)이다. 전자는 합성·차영상에, 후자는 밝기·대비 조절에 쓴다.

분류대표 함수용도
산술 연산add, subtract, multiply, divide이미지 합성, 밝기 조절, 정규화
가중 블렌딩addWeighted반투명 합성, 페이드 인/아웃
차영상absdiff변화 검출, 기준 영상 비교
비트 연산bitwise_and/or/xor/not마스킹, ROI 추출, 영역 합성
비교 연산compare, min, max, inRange임계 처리, 색 범위 검출
OpenCV 연산 함수는 SIMD로 최적화되어 있다 픽셀을 직접 루프로 순회하며 더하는 것보다 cv::add 같은 내장 함수가 훨씬 빠르다. 내부적으로 SIMD 명령과 멀티스레딩을 활용하기 때문이다. 픽셀 연산은 가능한 한 내장 함수로 처리한다.

산술 연산과 포화

가장 기본은 두 이미지를 더하고 빼고 곱하고 나누는 것이다. OpenCV는 cv::add, cv::subtract, cv::multiply, cv::divide를 제공한다. 모두 같은 위치 픽셀끼리 계산한다.

cv::Mat src1 = cv::imread("a.jpg");
cv::Mat src2 = cv::imread("b.jpg");
cv::Mat dst;

cv::add(src1, src2, dst);        // dst = src1 + src2
cv::subtract(src1, src2, dst);   // dst = src1 - src2
cv::multiply(src1, src2, dst);   // dst = src1 * src2 (픽셀별 곱)
cv::divide(src1, src2, dst);     // dst = src1 / src2 (픽셀별 나눗셈)

포화 연산 — 클리핑 vs 래핑

8비트 이미지의 픽셀값 범위는 0~255다. 그런데 200 + 100 = 300처럼 결과가 범위를 벗어나면 어떻게 될까? 두 가지 처리 방식이 있다.

  • 포화(saturation) — 범위를 벗어난 값을 끝값으로 자른다. 300 → 255, -50 → 0. OpenCV 연산 함수가 자동으로 하는 방식이다.
  • 래핑(wrap-around) — 오버플로가 한 바퀴 돈다. 300 → 44 (300 % 256). C/C++의 일반 + 연산자가 uchar에 하는 방식이다.
8비트 오버플로 처리: cv::add는 포화시키지만, uchar에 일반 + 를 쓰면 값이 한 바퀴 돌아 엉뚱한 결과가 나온다.
// 포화 — OpenCV 연산 함수는 자동으로 클리핑
cv::Mat a(1, 1, CV_8UC1, cv::Scalar(200));
cv::Mat b(1, 1, CV_8UC1, cv::Scalar(100));
cv::Mat sum;
cv::add(a, b, sum);
std::cout << "cv::add  : " << (int)sum.at<uchar>(0, 0) << std::endl;  // 255

// 래핑 — uchar 변수에 직접 더하면 오버플로가 한 바퀴 돈다
uchar pa = 200, pb = 100;
uchar wrap = pa + pb;  // 사실상 (200 + 100) % 256
std::cout << "uchar +  : " << (int)wrap << std::endl;            // 44
실행 결과 (콘솔)
cv::add : 255 uchar + : 44
cv::Mat 끼리의 + 연산자는 포화된다 헷갈리기 쉬운데, cv::Mat c = a + b;처럼 Mat 객체끼리 쓰는 +는 OpenCV가 오버로딩해 두어 포화 연산을 한다. 래핑이 일어나는 건 uchar·int 같은 스칼라 변수에 직접 연산할 때다. 픽셀을 at<uchar>()로 꺼내 손으로 더하면 래핑되니 주의한다.

addWeighted — 가중 블렌딩

두 이미지를 단순히 더하는 대신 가중치를 주어 섞으면 반투명 합성이 된다. cv::addWeighted는 다음 식을 계산한다.

dst = alpha · src1 + beta · src2 + gamma

alpha는 첫 번째 이미지의 비중, beta는 두 번째 이미지의 비중, gamma는 전체에 더해지는 밝기 보정값이다. 보통 alpha + beta = 1로 맞추면 전체 밝기가 유지되면서 두 이미지가 자연스럽게 섞인다.

cv::Mat img1 = cv::imread("photo.jpg");
cv::Mat img2 = cv::imread("texture.jpg");

// 두 이미지를 7:3 비율로 블렌딩
cv::Mat blended;
cv::addWeighted(img1, 0.7, img2, 0.3, 0.0, blended);

// 페이드 인/아웃 — alpha를 0 → 1 로 변화시키며 반복
for (double alpha = 0.0; alpha <= 1.0; alpha += 0.05)
{
    cv::Mat frame;
    cv::addWeighted(img1, 1.0 - alpha, img2, alpha, 0.0, frame);
    cv::imshow("Fade", frame);
    cv::waitKey(30);
}

두 이미지의 크기와 타입이 정확히 같아야 한다. 다르면 예외가 난다. 크기가 다르면 cv::resize로 먼저 맞춘다.

워터마크나 반투명 오버레이도 addWeighted로 반투명 도형을 그리려면 별도 레이어에 도형을 그린 뒤 addWeighted로 원본에 섞으면 된다. alpha를 0.2~0.3으로 낮추면 은은한 오버레이가, 0.5면 또렷한 반투명이 된다.

차영상 (absdiff)

cv::absdiff는 두 이미지의 절대 차이를 구한다. dst = |src1 - src2|. 단순 subtract와 달리 음수가 0으로 잘리지 않고 절댓값으로 살아남기 때문에, 어느 쪽이 더 밝든 달라진 부분이 모두 드러난다.

산업 검사에서 매우 자주 쓴다. 기준 영상(정상 제품)과 검사 영상(현재 제품)을 absdiff로 비교하면 결함·이물·누락이 밝게 나타난다.

cv::Mat reference = cv::imread("good_sample.jpg", cv::IMREAD_GRAYSCALE);
cv::Mat current   = cv::imread("test_sample.jpg", cv::IMREAD_GRAYSCALE);

// 두 영상의 절대 차이
cv::Mat diff;
cv::absdiff(reference, current, diff);

// 차이가 임계값 이상인 픽셀만 남긴다 (잡음 제거)
cv::Mat changeMask;
cv::threshold(diff, changeMask, 30, 255, cv::THRESH_BINARY);

// 변화 영역의 픽셀 수로 결함 여부 판정
int changedPixels = cv::countNonZero(changeMask);
if (changedPixels > 500)
{
    std::cout << "결함 의심 — 변화 픽셀 " << changedPixels << "개" << std::endl;
}
차영상은 조명·정렬에 민감하다 absdiff는 픽셀 위치가 정확히 맞는다는 전제로 동작한다. 카메라가 흔들리거나 제품 위치가 조금만 어긋나도 윤곽선 전체가 차이로 잡힌다. 실전에서는 정합(alignment)을 먼저 하고, 조명을 일정하게 유지하는 것이 핵심이다.

비트 연산

비트 연산은 픽셀값을 이진 비트 단위로 처리한다. OpenCV는 bitwise_and, bitwise_or, bitwise_xor, bitwise_not 네 가지를 제공한다. 이미지 처리에서 비트 연산이 중요한 진짜 이유는 마스킹의 토대가 되기 때문이다.

cv::Mat a = cv::imread("a.jpg");
cv::Mat b = cv::imread("b.jpg");
cv::Mat dst;

cv::bitwise_and(a, b, dst);   // 두 비트가 모두 1일 때만 1
cv::bitwise_or(a, b, dst);    // 둘 중 하나라도 1이면 1
cv::bitwise_xor(a, b, dst);   // 두 비트가 다를 때만 1
cv::bitwise_not(a, dst);      // 비트 반전 — 색 반전 (네거티브)

bitwise_not은 인자가 하나다. 모든 비트를 뒤집으므로 255 - 픽셀값과 같은 효과 — 이미지의 네거티브가 된다.

연산0/255 마스크에서의 동작주 용도
bitwise_and마스크가 255인 곳만 원본 통과, 0인 곳은 검정ROI만 남기기
bitwise_or두 영역을 합침여러 영역 합성
bitwise_xor겹치지 않는 영역만 남김차이 영역 추출
bitwise_not마스크의 안팎을 뒤집음배경/전경 반전
0/255 마스크에서 비트 연산은 곧 "통과 / 차단"이다 값이 255(11111111)면 and가 원본 비트를 그대로 통과시키고, 0(00000000)이면 모든 비트를 0으로 만든다. 그래서 0/255로 된 마스크와 bitwise_and를 하면 마스크가 흰 영역만 남고 나머지는 검게 지워진다.

마스킹

마스크는 "어느 픽셀을 처리할지" 지정하는 흑백 도장이다. 형식은 CV_8UC1(8비트 1채널)이고 값은 0 또는 255만 쓴다. 255인 곳은 "여기 적용", 0인 곳은 "건드리지 않음"을 뜻한다.

bitwise_and(원본, 원본, 결과, 마스크): 마스크가 흰(255) 영역만 원본이 통과하고, 검은(0) 영역은 0으로 지워진다.

bitwise_and로 ROI만 남기기

대부분의 OpenCV 연산 함수는 마지막 인자로 mask를 받는다. bitwise_and에 마스크를 주면 마스크가 255인 픽셀만 결과에 살아남는다.

cv::Mat image = cv::imread("scene.jpg");

// 원형 마스크 생성 — 검은 바탕에 흰 원
cv::Mat mask = cv::Mat::zeros(image.size(), CV_8UC1);
cv::circle(mask, cv::Point(image.cols / 2, image.rows / 2),
           150, cv::Scalar(255), cv::FILLED);

// 마스크가 흰 영역(원 안)만 남기고 나머지는 검게
cv::Mat result;
cv::bitwise_and(image, image, result, mask);

여기서 src1과 src2에 똑같이 image를 넣는 게 핵심이다. image & image는 원본 그대로지만, mask 인자 때문에 마스크가 0인 곳은 결과가 0이 된다.

copyTo로 선택 복사

copyTo에 마스크를 넘기면 마스크가 255인 픽셀만 대상에 복사된다. 대상의 나머지 픽셀은 건드리지 않는다 — bitwise_and처럼 0으로 지우는 게 아니라 기존 값을 유지한다. 합성에 더 유용한 경우가 많다.

cv::Mat background = cv::imread("background.jpg");
cv::Mat foreground = cv::imread("object.jpg");
cv::Mat mask = cv::imread("object_mask.png", cv::IMREAD_GRAYSCALE);

// 마스크가 255인 픽셀만 background에 덮어쓴다
foreground.copyTo(background, mask);
// → mask가 0인 곳의 background 픽셀은 그대로 유지
마스크는 반드시 8UC1, 값은 0 또는 255 마스크를 컬러(3채널)로 만들거나, 값을 0/1로 채우거나, CV_32F 타입으로 주면 동작이 어긋난다. 1로 채운 마스크는 bitwise_and에서 거의 검은 결과를 내고, copyTo의 mask 인자는 0이 아닌 모든 값을 통과로 보지만 타입은 CV_8UC1이어야 한다. 마스크는 항상 CV_8UC1, 값은 0과 255로 유지한다.

실전 — 로고 합성

지금까지 배운 연산을 모아 배경 사진에 로고를 얹는 고전 예제를 만든다. 로고에 투명 영역이 있을 때 단순히 add하면 배경이 비쳐 보이거나 색이 섞인다. 비트 연산으로 깔끔하게 처리하는 흐름은 다음과 같다.

  1. 로고에서 마스크를 만든다 (로고 모양 = 흰색, 배경 = 검정).
  2. 마스크를 반전해 역마스크를 만든다 (로고 모양 = 검정).
  3. 배경의 로고 자리를 역마스크로 비운다 (로고 들어갈 구멍).
  4. 로고에서 마스크로 로고 픽셀만 추출한다.
  5. 구멍 뚫린 배경과 추출한 로고를 add한다.
cv::Mat background = cv::imread("scene.jpg");
cv::Mat logo = cv::imread("logo.png");

// 배경에서 로고를 놓을 좌상단 영역을 ROI로 잡는다
cv::Rect roiRect(20, 20, logo.cols, logo.rows);
cv::Mat roi = background(roiRect);   // 얕은 참조 — roi 수정 시 background도 바뀜

// 1. 로고 → 그레이스케일 → 임계 처리로 마스크 생성
cv::Mat logoGray, mask, maskInv;
cv::cvtColor(logo, logoGray, cv::COLOR_BGR2GRAY);
cv::threshold(logoGray, mask, 10, 255, cv::THRESH_BINARY);  // 로고 모양 = 흰색

// 2. 역마스크 — 로고 모양이 검정
cv::bitwise_not(mask, maskInv);

// 3. 배경 ROI에서 로고 자리를 비운다 (역마스크가 흰 곳만 남김)
cv::Mat bgHole;
cv::bitwise_and(roi, roi, bgHole, maskInv);

// 4. 로고에서 로고 픽셀만 추출 (마스크가 흰 곳만 남김)
cv::Mat logoOnly;
cv::bitwise_and(logo, logo, logoOnly, mask);

// 5. 구멍 뚫린 배경 + 로고 픽셀을 합쳐 ROI에 다시 쓴다
cv::Mat merged;
cv::add(bgHole, logoOnly, merged);
merged.copyTo(roi);   // roi는 background의 일부 → background에 반영됨

cv::imshow("Logo Composite", background);
cv::waitKey(0);
구멍을 먼저 뚫는 이유 배경의 로고 자리를 미리 0으로 비워두면, 로고 픽셀을 add할 때 0 + 로고값 = 로고값이 되어 색이 섞이지 않는다. 구멍을 안 뚫고 그냥 더하면 배경색과 로고색이 합산돼 포화되거나 탁해진다. 더 짧게 가려면 4번까지 한 뒤 logoOnly.copyTo(roi, mask) 한 줄로 끝낼 수도 있다.

스칼라 연산 — 밝기·대비

이미지에 상수를 더하거나 곱하면 밝기와 대비가 조절된다. 이미지-스칼라 연산이다.

  • 밝기 — 모든 픽셀에 같은 값을 더한다. +50이면 전체가 밝아진다.
  • 대비 — 모든 픽셀에 같은 값을 곱한다. ×1.5면 밝은 곳과 어두운 곳의 차이가 벌어진다.
cv::Mat img = cv::imread("photo.jpg");

// 밝기 +60 — 모든 채널에 60을 더한다 (포화로 안전)
cv::Mat brighter;
cv::add(img, cv::Scalar(60, 60, 60), brighter);

// 밝기 -40 — 어둡게
cv::Mat darker;
cv::subtract(img, cv::Scalar(40, 40, 40), darker);

// 대비 ×1.4 — multiply 또는 convertTo 사용
cv::Mat highContrast;
cv::multiply(img, cv::Scalar(1.4, 1.4, 1.4), highContrast);

// 밝기와 대비를 한 번에: dst = alpha*src + beta
// alpha = 대비(1.4), beta = 밝기(+30)
cv::Mat adjusted;
img.convertTo(adjusted, -1, 1.4, 30);

밝기·대비를 동시에 조절할 때는 convertTo(dst, rtype, alpha, beta)가 가장 깔끔하다. dst = alpha · src + beta를 한 번에 계산하고 포화 처리도 자동이다. rtype에 -1을 주면 원본과 같은 타입을 유지한다.

cv::Scalar는 채널별 값이다 cv::Scalar(60, 60, 60)은 BGR 세 채널에 각각 60을 더한다는 뜻이다. 채널마다 다른 값을 주면 색 균형(화이트 밸런스)을 손볼 수 있다. 1채널 이미지면 첫 값만 쓰인다.

비교 연산

픽셀값을 비교해 조건을 만족하는 위치를 찾는 연산이다. 결과는 보통 0/255 마스크로 나오므로 그대로 마스킹에 이어 쓸 수 있다.

cv::Mat a = cv::imread("a.jpg", cv::IMREAD_GRAYSCALE);
cv::Mat b = cv::imread("b.jpg", cv::IMREAD_GRAYSCALE);
cv::Mat dst;

// compare — 픽셀별 비교, 참인 곳 255
cv::compare(a, b, dst, cv::CMP_GT);   // a > b 인 픽셀 = 255

// min / max — 픽셀별 최솟값 / 최댓값
cv::min(a, b, dst);   // 두 이미지 중 더 어두운 픽셀 선택
cv::max(a, b, dst);   // 더 밝은 픽셀 선택

// inRange — 값이 [lower, upper] 범위 안이면 255
cv::Mat colorImg = cv::imread("scene.jpg");  // BGR
cv::Mat colorMask;
cv::inRange(colorImg, cv::Scalar(0, 100, 0),
                      cv::Scalar(80, 255, 80), colorMask);
// → 초록 계열 픽셀만 255인 마스크
함수동작대표 용도
compare두 이미지 픽셀 비교, 참이면 255조건부 마스크 생성
min / max픽셀별 최소/최대 선택밝기 합성, 노이즈 억제
inRange값이 범위 안이면 255색 기반 객체 검출
threshold임계값 기준 이진화전경/배경 분리

inRange는 색 기반 검출의 핵심이다. BGR보다 HSV 색공간에서 쓰면 조명 변화에 더 강인하다 — 색상(Hue)이 밝기와 분리되기 때문이다. 색공간 변환은 다음 글에서 다룬다.

흔한 함정

산술·논리 연산에서 거의 모두가 한 번씩 밟는 함정들이다.

포화와 래핑 혼동

at<uchar>()으로 꺼낸 값을 손으로 더하면 래핑된다 cv::add나 Mat끼리의 +는 포화되지만, at<uchar>()로 픽셀을 꺼내 uchar 변수에서 직접 더하면 오버플로가 한 바퀴 돈다. 밝은 픽셀이 갑자기 어둡게 보인다면 이걸 의심한다. 픽셀을 직접 다룰 땐 cv::saturate_cast<uchar>()로 감싼다. 
uchar p = image.at<uchar>(y, x);  // 예: 220

// 나쁨 — 220 + 80 = 300 이 44로 래핑
uchar bad = p + 80;

// 좋음 — saturate_cast가 255로 클리핑
uchar good = cv::saturate_cast<uchar>(p + 80);  // 255

마스크 타입·값 오류

마스크는 8UC1, 값은 0/255 — 컬러도 0/1도 아니다 마스크를 3채널로 만들면 함수가 거부하거나 채널별로 따로 동작해 의도와 어긋난다. 값을 0/1로 채운 마스크를 bitwise_and에 쓰면 거의 검은 결과가 나온다 (1 = 00000001은 최하위 비트만 통과). 마스크는 cv::Mat::zeros(size, CV_8UC1)로 만들고 255로만 칠한다.

크기·타입 불일치

두 이미지의 size와 type이 정확히 같아야 한다 add, addWeighted, absdiff, 비트 연산 모두 두 입력의 크기와 타입이 일치해야 한다. CV_8UC3와 CV_8UC1을 더하거나, 1920×1080과 1280×720을 섞으면 예외가 난다. 미리 cv::resize와 cv::cvtColor(또는 convertTo)로 맞춘다. 
// 크기가 다르면 먼저 맞춘다
if (img2.size() != img1.size())
{
    cv::resize(img2, img2, img1.size());
}

// 채널 수가 다르면 변환한다 (그레이 → BGR)
if (img2.channels() != img1.channels())
{
    cv::cvtColor(img2, img2, cv::COLOR_GRAY2BGR);
}

cv::Mat dst;
cv::addWeighted(img1, 0.5, img2, 0.5, 0.0, dst);  // 이제 안전

addWeighted 가중치 합 오해

addWeighted의 alpha + beta가 꼭 1이어야 하는 건 아니다. 합이 1보다 크면 결과가 밝아지고(포화 가능), 작으면 어두워진다. 자연스러운 블렌딩을 원하면 1로 맞추는 게 관례일 뿐, 의도적으로 밝기를 올리려면 합을 1보다 크게 줘도 된다 — 다만 그 효과를 모르고 쓰면 "왜 이렇게 밝지?"가 된다.

정리하면 Mat 연산은 포화되지만 uchar 직접 연산은 래핑된다. 마스크는 8UC1 + 0/255로 통일한다. 두 이미지를 섞기 전엔 size와 type을 맞춘다. absdiff는 변화 검출에, bitwise_and + 마스크는 ROI 추출에, copyTo(dst, mask)는 선택 합성에 쓴다. 이 네 가지가 픽셀 연산의 뼈대다.
