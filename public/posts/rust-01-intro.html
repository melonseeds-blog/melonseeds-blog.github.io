Rust 입문 — 왜 Rust인가, rustup·Cargo·Hello World

2026-06-25 약 8분 분량 Rust 시리즈
이 편에서 배우는 것 Rust가 무엇을 약속하는 언어인지 — 가비지 컬렉터 없이도 메모리 안전을 보장하고, 자료 경쟁(data race) 없는 동시성을 컴파일 단계에서 강제하며, 그러면서 C++급 네이티브 성능을 낸다 — 를 먼저 짚는다. 그다음 공식 도구 rustup으로 툴체인을 설치하고, 빌드·패키지 관리자 cargo로 첫 프로젝트를 만들어 실행한다. 마지막으로 Cargo.toml과 src/main.rs가 어떤 역할을 하는지, println!이 왜 매크로인지까지 살펴본다. 명령어·버전 세부는 공식 문서를 함께 확인한다.

왜 Rust인가

Rust를 한 문장으로 요약하면 "가비지 컬렉터 없이 메모리 안전을 보장하는 시스템 프로그래밍 언어"다. C·C++이 주던 저수준 제어와 성능은 그대로 두면서, 그 둘에서 흔하던 메모리 오류를 컴파일러가 미리 잡는다는 점이 핵심 차별점이다.

구체적으로 세 가지를 약속한다.

  • 메모리 안전 — 소유권(ownership)·빌림(borrowing)·수명(lifetime) 규칙을 컴파일러가 검사한다. 해제된 메모리 참조(use-after-free), 중복 해제, 댕글링 포인터 같은 부류를 런타임이 아니라 컴파일 시점에 막는다.
  • 자료 경쟁 없는 동시성 — 같은 데이터를 여러 스레드가 안전하지 않게 공유하면 컴파일이 거부된다. "두려움 없는 동시성(fearless concurrency)"이라 부르는 이유다. 동시성 버그의 큰 갈래인 data race를 타입 시스템으로 배제한다.
  • 네이티브 성능 — 런타임이나 GC가 없고 LLVM 기반으로 기계어까지 컴파일된다. 추상화에 런타임 비용을 거의 더하지 않는 "제로 비용 추상화"를 지향하므로, 성능 특성은 C·C++과 같은 급으로 본다.

정리하면 Rust는 "안전이냐, 성능이냐"라는 오래된 양자택일을 컴파일러의 정적 검사로 우회한다. 검사를 통과한 코드는 GC 일시정지 없이 빠르게 돌고, 통과 자체가 일정 부류의 버그가 없다는 보장이 된다.

C++ 경험자가 받을 첫인상 C++에서 RAII와 스마트 포인터로 관례적으로 지키던 것들 — 누가 메모리를 소유하는가, 언제 해제되는가 — 을 Rust는 언어 규칙으로 강제한다. std::unique_ptr의 이동 의미가 모든 값의 기본 동작이라고 보면 감이 빠르다. 처음엔 컴파일러와 다투는 느낌이지만, 통과한 코드는 메모리·동시성 측면에서 상당히 안심하고 쓸 수 있다.

rustup으로 설치하기

Rust는 rustup이라는 공식 툴체인 설치·관리자로 설치하는 것을 표준으로 한다. rustup은 컴파일러(rustc), 빌드 도구(cargo), 표준 라이브러리, 문서를 한 묶음으로 설치하고, 안정(stable)·베타·나이틀리 같은 여러 툴체인을 한 시스템에서 전환하게 해 준다.

리눅스·macOS에서는 공식 스크립트를 받아 실행한다.

# rustup 설치 (Linux / macOS) — 공식 설치 스크립트
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Windows에서는 공식 사이트(rustup.rs)에서 rustup-init.exe를 내려받아 실행한다. 설치가 끝나면 새 터미널을 열고 버전을 확인한다.

# 설치 확인 — 컴파일러와 Cargo 버전이 출력되면 성공
rustc --version
cargo --version

이후 툴체인을 최신 안정판으로 올리거나 상태를 보는 것도 rustup으로 한다.

# 설치된 툴체인을 최신 stable로 업데이트
rustup update

# 현재 활성 툴체인과 설치 상태 확인
rustup show

핵심은 시스템 패키지 매니저로 rustc를 직접 까는 대신 rustup을 거치는 것이다. 그래야 버전 관리와 업데이트가 한 도구로 일관되게 끝난다.

Cargo와 프로젝트 구조

Cargo는 Rust의 공식 빌드 시스템 겸 패키지 매니저다. 프로젝트 생성, 컴파일, 의존성(크레이트) 내려받기, 테스트 실행, 배포까지 하나의 도구로 처리한다. 새 프로젝트는 cargo new로 만든다.

# 실행 파일(바이너리) 프로젝트 생성
cargo new hello_rust

# 생성된 폴더로 이동
cd hello_rust

이렇게 하면 다음 구조가 만들어진다. 빌드 산출물은 target/에 쌓이며 보통 버전 관리에서 제외한다(생성된 .gitignore가 이를 처리한다).

hello_rust/
├── Cargo.toml      // 프로젝트 메타데이터와 의존성 선언
├── .gitignore
└── src/
    └── main.rs     // 프로그램 진입점(main 함수)이 있는 소스

Cargo.toml — 프로젝트의 명세서

Cargo.toml은 TOML 형식의 매니페스트로, 패키지 이름·버전·Rust 에디션과 의존성을 적는다. cargo new가 만들어 주는 초기 내용은 이렇다.

[package]
name = "hello_rust"
version = "0.1.0"
edition = "2021"

# 외부 크레이트는 여기에 적으면 cargo가 받아서 빌드한다
[dependencies]

외부 라이브러리(크레이트)가 필요하면 [dependencies] 아래 한 줄을 추가하기만 하면 된다. 예를 들어 난수 크레이트 rand를 쓰려면 rand = "0.8"을 적고 cargo build를 돌리면, Cargo가 중앙 레지스트리(crates.io)에서 호환 버전을 받아 함께 빌드한다.

C++과 이렇게 다르다 — 도구가 하나로 합쳐져 있다 C++에서는 보통 빌드 시스템(CMake)과 패키지 매니저(vcpkg/Conan)를 따로 두고, CMakeLists.txt와 매니페스트를 함께 관리한다. Rust는 Cargo.toml 한 파일에 의존성을 적고 cargo build 한 번이면 의존성 해결·다운로드·컴파일·링크가 끝난다. 빌드·의존성·테스트·실행이 모두 cargo 하나의 하위 명령으로 통일돼 있어, 새 프로젝트를 받아 돌리기까지의 진입 비용이 눈에 띄게 낮다.
작업C++ (전형적 조합)Rust (Cargo)
프로젝트 생성디렉터리·CMakeLists.txt 수동 작성cargo new 이름
빌드cmake -B build 후 cmake --build buildcargo build
의존성 추가vcpkg/Conan 매니페스트 + 빌드 연동Cargo.toml에 한 줄 + cargo build
테스트 실행GoogleTest 등 별도 설정·연결cargo test (기본 내장)
실행산출물 경로를 찾아 직접 실행cargo run

Hello World와 println!

cargo new가 만들어 준 src/main.rs를 열면 이미 동작하는 프로그램이 들어 있다.

// src/main.rs — 모든 실행 파일은 main 함수에서 시작한다
fn main() {
    println!("Hello, world!");
}

읽어 둘 것이 두 가지다. 첫째, fn main()은 프로그램의 진입점이다. 둘째, println!은 함수가 아니라 매크로다 — 이름 끝의 느낌표(!)가 매크로 호출을 나타낸다. println!은 컴파일 시점에 포맷 문자열을 해석해 인자 개수·타입에 맞는 출력 코드를 생성하므로, 형식 문자열과 인자가 맞지 않으면 컴파일 단계에서 걸린다.

이제 빌드하고 실행한다. 두 단계를 한 번에 하려면 cargo run이면 된다(필요하면 먼저 빌드한다).

# 컴파일만
cargo build

# 컴파일 후 곧바로 실행 — 가장 자주 쓰는 명령
cargo run

출력은 다음과 같다.

   Compiling hello_rust v0.1.0 (/path/to/hello_rust)
    Finished dev [unoptimized + debuginfo] target(s)
     Running `target/debug/hello_rust`
Hello, world!

변수와 포맷 출력

조금 더 손대 본다. 아래 예제는 변수를 만들고 {} 자리표시자로 값을 끼워 출력한다. 소유권·빌림 규칙을 어기지 않는 평범한 코드다.

fn main() {
    // 변수는 기본이 불변(immutable)이다
    let name = "Rust";
    let year = 2015;

    // {} 자리에 인자를 순서대로 끼워 넣는다
    println!("{} 첫 안정판은 {}년에 나왔다.", name, year);

    // 바꿀 값은 mut으로 명시해야 한다
    let mut count = 0;
    count += 1;
    println!("count = {}", count);
}

두 가지가 C·C++ 감각과 다르다. 변수는 let으로 선언하면 기본이 불변이라, 재할당하려면 mut을 붙여야 한다. 그리고 타입을 적지 않아도 컴파일러가 추론한다(여기서 year는 정수, name은 문자열 슬라이스로 추론된다).

문자열을 빌려 함수에 넘기는 형태도 보자. 소유권을 넘기지 않고 빌림(&str)으로 참조만 전달하면, 호출한 쪽이 값을 그대로 계속 쓸 수 있다.

// 문자열을 소유하지 않고 참조(&str)로만 빌려 쓴다
fn greet(who: &str) {
    println!("Hello, {}!", who);
}

fn main() {
    let name = String::from("world");

    // &name으로 빌려 넘긴다 — 소유권은 main이 계속 갖는다
    greet(&name);

    // 빌림이 끝났으므로 name을 여전히 사용할 수 있다
    println!("아직 쓸 수 있다: {}", name);
}

만약 greet가 &str이 아니라 String을 값으로 받았다면 소유권이 함수로 이동해, 그 뒤 main에서 name을 다시 쓰는 줄이 컴파일 오류가 났을 것이다. 빌림으로 받았기 때문에 위 코드는 문제없이 컴파일되고 실행된다. 이 소유권·빌림 규칙이 Rust 학습의 본 줄기이며, 다음 편에서 본격적으로 다룬다.

정리와 다음 편

  • 왜 Rust인가 — GC 없이 메모리 안전, 자료 경쟁 없는 동시성, C++급 네이티브 성능을 컴파일러의 정적 검사로 한꺼번에 얻는다.
  • 설치 — 공식 도구 rustup으로 툴체인을 설치하고 rustc --version·cargo --version으로 확인한다.
  • Cargo — cargo new로 생성하고 cargo run으로 실행한다. 빌드·의존성·테스트가 한 도구에 통합돼, C++의 CMake+패키지 매니저 조합보다 진입이 단순하다.
  • 구조 — Cargo.toml은 명세서, src/main.rs의 fn main()이 진입점, println!은 컴파일 시점에 검사되는 매크로다.
  • 다음 편 — Rust의 본 줄기인 소유권·빌림·수명 규칙을 코드로 파고든다.
