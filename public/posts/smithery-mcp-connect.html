왜 Smithery 이야기가 나오나

Claude나 다른 AI 에이전트에 "우리 DB를 읽어라", "Slack에 올려라", "브라우저를 조작해라" 같은 바깥 능력을 붙이려면 도구 연결이 필요하다. 그 연결의 표준이 MCP(Model Context Protocol)다. 문제는 이런 MCP 서버를 매번 손으로 찾고 설정하기가 번거롭다는 것이다.

Smithery.ai는 이 번거로움을 줄여 준다. 필요한 MCP 서버를 한곳에서 검색해 명령 한 줄로 붙이게 해 주는 곳이라, 교육이나 실무에서 "에이전트 확장은 Smithery부터"라는 말이 나온다.

Smithery.ai란 무엇인가

Smithery.ai는 MCP 서버 레지스트리다. 흔히 "MCP 생태계의 Docker Hub"라고 부른다. 수천 개의 MCP 서버를 모아 두고, 검색·설치·호스팅을 한곳에서 할 수 있게 한다.

  • 검색·설치 — 원하는 기능의 서버를 찾아 CLI로 로컬에 설치한다.
  • 호스팅 — 직접 서버를 돌리지 않고 Smithery가 운영하는 원격 엔드포인트로 바로 쓸 수도 있다.
  • Toolbox(메타-MCP) — 하나의 MCP 서버가 레지스트리의 여러 서버를 런타임에 연결해 준다. 서버를 일일이 등록하지 않아도 된다.

레지스트리 탐색과 CLI는 무료이고, 호스팅·고사용량은 유료 구간이 있다.

MCP냐 Skill이냐 — 용어 정리

가장 헷갈리는 부분이다. 결론부터: Smithery는 기본적으로 MCP 서버를 제공한다. 다만 최근에는 이런 확장을 통칭 "skill"이라 부르는 흐름이 있어, Smithery도 "흩어진 컨텍스트를 AI를 위한 skill로 바꾼다"는 표현을 쓰고, 최근엔 skill 항목까지 다룬다. 그래서 용어가 섞여 보인다.

둘의 기술적 차이는 이렇다.

구분MCP 서버Agent Skill
본질외부 도구·데이터에 연결하는 프로토콜절차·지식을 담은 패키지(SKILL.md)
예GitHub·Slack·DB·브라우저 접근"PR 만들 때 이 절차를 따라라"
실행서버가 도구를 제공, 모델이 호출모델이 그 자리에서 절차를 따름
실무에선 자주 뭉뚱그린다 엄밀히는 MCP(연결)와 Skill(절차)이 다르지만, 현장에서는 "에이전트에 붙이는 확장"을 통틀어 skill이라 부르곤 한다. Smithery에서 무언가를 붙일 때 대부분은 MCP 서버 연결이라고 보면 된다. MCP와 Skill의 구조적 차이는 Claude Code를 구조로 이해하기에서 더 자세히 다룬다.

Claude에 연결하는 법

가장 쉬운 길은 서버 페이지가 만들어 주는 명령을 그대로 복사하는 것이다. Smithery는 각 서버마다 클라이언트(Claude·Cursor 등)를 고르면 붙일 명령을 자동으로 생성해 준다.

  1. 서버 찾기 — smithery.ai/servers에서 원하는 기능(예: github, slack, filesystem)을 검색한다.
  2. 클라이언트 선택 — 서버 페이지에서 연결 대상(Claude Code / Claude Desktop 등)을 고르면 설치 명령이 생성된다.
  3. 명령 실행 — 생성된 CLI 명령을 터미널에 붙여 실행한다. Smithery CLI가 설정 파일을 대신 수정해 준다.
  4. 확인·재시작 — Claude를 재시작하고 연결됐는지 확인한다.

명령 예시

서버 페이지가 주는 명령은 대개 이런 형태다(서버·버전에 따라 다르니 실제 페이지의 명령을 쓴다).

# Smithery CLI로 서버를 설치하며 Claude에 연결
npx @smithery/cli install <server-name> --client claude

# Claude Code에 MCP를 직접 추가하는 방법
claude mcp add <name> -- npx -y <server-package>

# 환경변수(API 키 등)가 필요한 서버
claude mcp add --transport stdio <name> --env API_KEY=여기에_키 -- npx -y <server-package>

# 연결된 MCP 목록 확인
claude mcp list
두 갈래를 기억하면 쉽다 (1) 로컬 설치 — 내 PC에서 npx로 서버를 돌린다. (2) Smithery 호스팅(원격) — 설치 없이 Smithery가 운영하는 원격 엔드포인트에 연결한다. 서버를 직접 관리하기 싫으면 호스팅이 편하고, 사내 데이터처럼 밖으로 내보내면 안 되는 건 로컬이 맞다.

붙이기 전 확인할 것

  • 신뢰 — MCP 서버는 내 파일·계정에 접근할 수 있다. 게시자·인기도·소스를 확인하고, 출처가 불확실한 서버는 피한다.
  • 키 관리 — API 키·토큰은 설정 파일이나 환경변수로 들어간다. 저장소에 올리지 않도록 주의한다.
  • 사내 데이터 — 회사 데이터를 다루는 서버는 원격 호스팅보다 로컬 실행이 안전할 수 있다. 데이터가 어디로 가는지 확인한다.
  • 버전 변동 — Smithery CLI·명령 문법은 자주 바뀐다. 이 글의 명령은 예시이며, 정확한 건 서버 페이지와 공식 문서를 따른다.

정리

  • Smithery.ai = MCP 서버 레지스트리 — 필요한 MCP 서버를 검색·설치·호스팅하는 "MCP의 Docker Hub".
  • MCP냐 Skill이냐 — 기본은 MCP 서버 연결이다. 현장에서 skill이라 불러도 실체는 대부분 MCP다.
  • 연결은 "서버 페이지 명령 복사 → 실행 → 확인"이 가장 쉽다. 로컬 설치와 원격 호스팅 두 갈래가 있다.
  • 붙이기 전 신뢰·키·데이터 흐름을 확인한다. 명령 문법은 공식 문서 기준으로.
