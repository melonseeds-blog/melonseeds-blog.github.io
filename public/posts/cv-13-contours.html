윤곽선이란?

윤곽선(contour)은 같은 밝기(또는 색)를 가진 픽셀들이 만드는 연속된 경계점들의 곡선이다. 이진 영상에서는 흰색 객체와 검은색 배경이 만나는 경계가 바로 윤곽선이 된다. OpenCV는 윤곽선을 점들의 목록, 즉 std::vector<cv::Point>로 표현하고, 영상에 객체가 여러 개면 그 목록이 다시 벡터로 묶여 std::vector<std::vector<cv::Point>>가 된다.

윤곽선은 산업 검사에서 매우 핵심적인 도구다. 객체의 개수를 세고, 면적·둘레로 크기를 재고, 형상을 분류하고, 무게중심으로 위치를 찾는 작업이 전부 윤곽선 위에서 이루어진다. 엣지 검출이 "경계 픽셀"을 찾는 것이라면, 윤곽선 검출은 그 경계를 이어진 하나의 객체 단위로 묶어준다는 점이 다르다.

이진 영상의 흰색 객체 경계를 추출하면, 각 객체가 점들의 목록으로 표현된다.

findContours — 윤곽 검출

cv::findContours는 이진 영상을 입력받아 윤곽선을 찾는다. 입력은 반드시 8비트 단일 채널(CV_8UC1) 이진 영상이어야 한다. 보통 threshold나 Canny로 만든 영상을 넣는다.

#include <opencv2/opencv.hpp>
#include <iostream>

int main()
{
    cv::Mat src = cv::imread("shapes.png", cv::IMREAD_GRAYSCALE);
    if (src.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    // 이진화 — findContours의 입력은 이진 영상이어야 한다
    cv::Mat binary;
    cv::threshold(src, binary, 127, 255, cv::THRESH_BINARY);

    // 윤곽선 검출
    std::vector<std::vector<cv::Point>> contours;
    std::vector<cv::Vec4i> hierarchy;
    cv::findContours(binary, contours, hierarchy,
                     cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

    std::cout << "검출된 윤곽 개수: " << contours.size() << std::endl;
    for (size_t i = 0; i < contours.size(); ++i)
    {
        std::cout << "  contour[" << i << "] 점 개수: "
                  << contours[i].size() << std::endl;
    }
    return 0;
}
실행 결과 (콘솔)
검출된 윤곽 개수: 3 contour[0] 점 개수: 4 contour[1] 점 개수: 64 contour[2] 점 개수: 4

Retrieval mode — 무엇을 가져올지

네 번째 인자 retrieval mode는 윤곽을 어디까지, 어떤 관계로 가져올지 정한다.

모드동작hierarchy용도
RETR_EXTERNAL가장 바깥 윤곽만형제만구멍 무시, 객체 외곽만 필요할 때
RETR_LIST모든 윤곽, 계층 없음없음(평면)관계 필요 없이 전부 나열
RETR_CCOMP모든 윤곽, 2단계외곽/구멍 2층외곽과 구멍만 구분하면 될 때
RETR_TREE모든 윤곽, 완전한 트리전체 트리중첩 객체의 모든 관계가 필요할 때

Approximation method — 점을 어떻게 저장할지

다섯 번째 인자는 윤곽의 점을 얼마나 촘촘히 저장할지 정한다.

// CHAIN_APPROX_NONE — 경계의 모든 점을 그대로 저장
//   사각형 하나라도 둘레의 픽셀 수만큼 점이 생긴다
cv::findContours(binary, contours, hierarchy,
                 cv::RETR_EXTERNAL, cv::CHAIN_APPROX_NONE);
// → 사각형 윤곽 점 개수: 약 400 (둘레 전체)

// CHAIN_APPROX_SIMPLE — 직선 구간은 끝점만 남긴다
//   사각형이면 꼭짓점 4개로 압축된다
cv::findContours(binary, contours, hierarchy,
                 cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
// → 사각형 윤곽 점 개수: 4
findContours의 입력은 이진 영상(8UC1)이다 컬러 영상이나 그레이스케일 원본을 그대로 넣으면 안 된다. 반드시 threshold·Canny·adaptiveThreshold 등으로 0과 255만 가진 단일 채널 영상을 만든 뒤 넘긴다. 0이 아닌 픽셀은 모두 객체로 취급된다.
구버전 OpenCV는 입력 영상을 수정한다 OpenCV 3.x 이하의 findContours는 입력 이진 영상을 내부에서 변형했다. 4.x부터는 원본을 보존하지만, 버전이 섞인 환경이라면 안전하게 binary.clone()을 넘기는 습관을 들이는 편이 좋다.

계층 구조 (hierarchy)

구멍이 뚫린 도넛 모양 객체를 생각해 보자. 바깥 원과 안쪽 구멍이라는 두 개의 윤곽이 나오고, 둘은 부모-자식 관계다. hierarchy는 이 관계를 담는 배열이다. 각 윤곽 i마다 cv::Vec4i 하나가 대응하고, 네 정수는 각각 다음을 가리킨다.

인덱스의미설명
hierarchy[i][0]Next같은 계층의 다음 형제 윤곽 인덱스
hierarchy[i][1]Previous같은 계층의 이전 형제 윤곽 인덱스
hierarchy[i][2]First_Child첫 번째 자식 윤곽 인덱스
hierarchy[i][3]Parent부모 윤곽 인덱스

해당하는 윤곽이 없으면 값은 -1이다. 예를 들어 hierarchy[i][3] == -1이면 i는 최상위(외곽) 윤곽이고, hierarchy[i][2] != -1이면 자식(구멍)을 가진 객체다.

도넛(외곽 #0 → 구멍 #1 → 내부 객체 #2)과 별도 사각형(#3)의 계층. Next·Child·Parent로 트리가 만들어진다.

계층을 이용하면 "구멍을 가진 객체만" 또는 "최상위 객체만" 같은 필터링이 가능하다.

std::vector<std::vector<cv::Point>> contours;
std::vector<cv::Vec4i> hierarchy;
cv::findContours(binary, contours, hierarchy,
                 cv::RETR_TREE, cv::CHAIN_APPROX_SIMPLE);

for (size_t i = 0; i < contours.size(); ++i)
{
    bool isTopLevel = (hierarchy[i][3] == -1);  // 부모 없음
    bool hasHole    = (hierarchy[i][2] != -1);  // 자식 있음

    if (isTopLevel && hasHole)
    {
        std::cout << "윤곽 " << i << " : 구멍을 가진 외곽 객체" << std::endl;
    }
    else if (isTopLevel)
    {
        std::cout << "윤곽 " << i << " : 속이 꽉 찬 외곽 객체" << std::endl;
    }
    else
    {
        std::cout << "윤곽 " << i << " : 내부 윤곽 (구멍 또는 중첩)" << std::endl;
    }
}
RETR_EXTERNAL은 구멍을 아예 무시한다 도넛을 RETR_EXTERNAL로 검출하면 바깥 원 윤곽 하나만 나온다. 구멍 정보가 필요하면 RETR_CCOMP나 RETR_TREE를 써야 한다. 반대로 구멍이 검출에 방해가 된다면 RETR_EXTERNAL이 가장 깔끔하다.

drawContours — 윤곽 그리기

cv::drawContours는 검출한 윤곽을 영상 위에 그린다. 세 번째 인자 contourIdx로 그릴 윤곽을 고르고, -1이면 전체를 그린다. 두께를 cv::FILLED(또는 -1)로 주면 윤곽 내부를 채운다.

cv::Mat canvas;
cv::cvtColor(binary, canvas, cv::COLOR_GRAY2BGR);  // 컬러로 그리기 위해 변환

// 모든 윤곽을 초록색 2px 선으로
cv::drawContours(canvas, contours, -1, cv::Scalar(0, 255, 0), 2);

// 특정 인덱스 하나만 빨간색으로
cv::drawContours(canvas, contours, 1, cv::Scalar(0, 0, 255), 3);

// 윤곽 내부를 채우기 (마스크 만들 때 유용)
cv::Mat mask = cv::Mat::zeros(binary.size(), CV_8UC1);
cv::drawContours(mask, contours, 0, cv::Scalar(255), cv::FILLED);

cv::imshow("contours", canvas);
cv::imshow("mask", mask);
cv::waitKey(0);

채우기 모드는 특정 객체만 남긴 마스크를 만들 때 특히 자주 쓴다. 위 코드의 mask는 0번 윤곽 내부만 255인 단일 채널 영상이 되고, 이를 원본에 copyTo의 마스크로 넘기면 그 객체만 추출된다.

hierarchy를 함께 넘기면 계층 기반으로 그릴 수 있다 drawContours에 hierarchy와 maxLevel 인자를 주면, 지정한 윤곽과 그 자식들을 깊이 단위로 그릴 수 있다. 도넛의 외곽과 구멍을 한 번에 칠하면서 구멍은 비워두는 식의 표현이 가능하다.

윤곽 특징 — 면적·둘레·외접 도형

윤곽선 하나를 손에 쥐면, 그로부터 객체의 크기와 형태를 정량적으로 뽑아낼 수 있다. 가장 많이 쓰는 함수들을 정리한다.

함수반환의미
contourAreadouble윤곽이 둘러싼 면적(픽셀 수)
arcLengthdouble윤곽의 둘레 길이
boundingRectcv::Rect축에 정렬된 최소 외접 사각형
minAreaRectcv::RotatedRect회전을 허용한 최소 면적 사각형
minEnclosingCircle중심·반지름윤곽을 감싸는 최소 원
convexHull점 목록윤곽을 감싸는 볼록 껍질
같은 윤곽에서 뽑아낸 세 가지 외접 도형. 용도에 따라 골라 쓴다.
for (const auto& contour : contours)
{
    // 면적과 둘레
    double area = cv::contourArea(contour);
    double perimeter = cv::arcLength(contour, true);  // true = 닫힌 윤곽

    // 축 정렬 외접 사각형
    cv::Rect box = cv::boundingRect(contour);

    // 회전을 허용한 최소 면적 사각형
    cv::RotatedRect rotated = cv::minAreaRect(contour);
    cv::Point2f corners[4];
    rotated.points(corners);  // 네 꼭짓점 좌표

    // 최소 외접 원
    cv::Point2f center;
    float radius = 0.0f;
    cv::minEnclosingCircle(contour, center, radius);

    // 볼록 껍질
    std::vector<cv::Point> hull;
    cv::convexHull(contour, hull);

    std::cout << "면적=" << area
              << ", 둘레=" << perimeter
              << ", bbox=" << box
              << ", 회전각=" << rotated.angle
              << ", 외접원 반지름=" << radius
              << ", hull 점 수=" << hull.size() << std::endl;
}

boundingRect는 빠르고 계산이 간단해 ROI를 잘라낼 때 좋고, minAreaRect는 객체가 기울어져 있을 때 실제 가로·세로 치수와 회전각을 정확히 준다. 산업 검사에서 부품의 기울기를 보정할 때 minAreaRect.angle이 핵심 입력이 된다.

arcLength의 두 번째 인자 closed를 정확히 줘야 한다 findContours가 만든 윤곽은 항상 닫힌 곡선이므로 arcLength(contour, true)가 맞다. false로 주면 시작점과 끝점을 잇지 않아 둘레가 한 변만큼 짧게 나온다. 뒤에서 다룰 approxPolyDP의 epsilon 계산이 둘레에 비례하므로, 이 실수는 도형 인식까지 어긋나게 만든다.

모멘트 (moments)

모멘트(moment)는 윤곽의 픽셀 분포를 수치로 요약한 값이다. cv::moments는 윤곽(또는 이진 영상)을 받아 cv::Moments 구조체를 돌려준다. 이 안의 값들로 면적, 무게중심, 방향을 계산한다.

가장 기본적인 공간 모멘트 m00은 면적이고, 무게중심 좌표는 (cx, cy) = (m10/m00, m01/m00)로 구한다.

for (const auto& contour : contours)
{
    cv::Moments mu = cv::moments(contour);

    if (mu.m00 == 0.0)  // 면적 0 윤곽 — 0으로 나누기 방지
        continue;

    // 무게중심 (centroid)
    double cx = mu.m10 / mu.m00;
    double cy = mu.m01 / mu.m00;

    // m00은 contourArea와 (거의) 같은 면적값
    std::cout << "무게중심=(" << cx << ", " << cy << ")"
              << ", 면적(m00)=" << mu.m00 << std::endl;

    // 주축 방향 — 중심 모멘트로 객체가 기운 각도 추정
    double angle = 0.5 * std::atan2(2 * mu.mu11,
                                    mu.mu20 - mu.mu02);
    std::cout << "  주축 각도(rad)=" << angle << std::endl;
}

Hu 모멘트 — 회전·스케일 불변 형상 기술자

일반 모멘트는 객체의 위치·크기·회전에 따라 값이 변한다. Hu 모멘트는 이 7개 값을 조합해 이동·회전·스케일에 불변하도록 만든 형상 기술자다. 같은 모양이면 크기가 다르고 돌아가 있어도 비슷한 Hu 값이 나오므로, 형상 매칭에 쓰인다.

cv::Moments mu = cv::moments(contour);

double hu[7];
cv::HuMoments(mu, hu);  // 7개의 Hu 불변 모멘트

// 값의 동적 범위가 매우 크므로 로그 스케일로 보는 것이 일반적
for (int i = 0; i < 7; ++i)
{
    double sign = (hu[i] < 0) ? -1.0 : 1.0;
    double logHu = sign * std::log10(std::abs(hu[i]) + 1e-30);
    std::cout << "Hu[" << i << "] = " << logHu << std::endl;
}

// 두 윤곽의 형상 유사도 — matchShapes가 내부적으로 Hu 모멘트 사용
double dist = cv::matchShapes(contourA, contourB,
                              cv::CONTOURS_MATCH_I1, 0.0);
std::cout << "형상 거리(작을수록 유사) = " << dist << std::endl;
형상 분류에는 matchShapes가 편하다 Hu 모멘트를 직접 비교하기보다, cv::matchShapes를 쓰면 두 윤곽의 형상 거리를 한 줄로 얻는다. 기준 도형의 윤곽을 미리 만들어 두고, 검출된 윤곽과의 거리가 임계값보다 작으면 같은 형상으로 판정하는 식으로 활용한다.

윤곽 근사 (approxPolyDP)

cv::approxPolyDP는 Douglas-Peucker 알고리즘으로 윤곽의 꼭짓점 수를 줄인다. 원래 곡선에서 크게 벗어나지 않는 선에서 점을 솎아내, 복잡한 윤곽을 단순한 다각형으로 바꾼다. 핵심 인자는 epsilon — 원본 곡선과 근사 곡선 사이의 최대 허용 거리다.

for (const auto& contour : contours)
{
    double peri = cv::arcLength(contour, true);

    // epsilon은 둘레에 비례해서 정한다 (보통 1~5%)
    std::vector<cv::Point> approx;
    cv::approxPolyDP(contour, approx, 0.02 * peri, true);

    int vertices = static_cast<int>(approx.size());
    std::cout << "근사 후 꼭짓점 수: " << vertices << std::endl;
}

근사된 다각형의 꼭짓점 개수를 세면 곧바로 도형 인식이 된다. 삼각형은 3개, 사각형은 4개, 꼭짓점이 많고 볼록하면 원에 가깝다.

std::string classifyShape(const std::vector<cv::Point>& contour)
{
    double peri = cv::arcLength(contour, true);
    std::vector<cv::Point> approx;
    cv::approxPolyDP(contour, approx, 0.04 * peri, true);

    const size_t v = approx.size();

    if (v == 3)
    {
        return "Triangle";
    }
    else if (v == 4)
    {
        // 가로세로 비율로 정사각형 / 직사각형 구분
        cv::Rect r = cv::boundingRect(approx);
        double ratio = static_cast<double>(r.width) / r.height;
        return (ratio >= 0.95 && ratio <= 1.05) ? "Square" : "Rectangle";
    }
    else if (v == 5)
    {
        return "Pentagon";
    }
    else
    {
        // 꼭짓점이 많으면 원에 가깝다 — 원형도로 확인
        double area = cv::contourArea(contour);
        double circularity = 4.0 * CV_PI * area / (peri * peri);
        return (circularity > 0.8) ? "Circle" : "Polygon";
    }
}
epsilon은 절대값이 아니라 둘레 비례로 준다 approxPolyDP에 epsilon = 3.0처럼 고정값을 주면, 작은 객체는 뭉개지고 큰 객체는 거의 근사가 안 된다. 항상 0.02 * arcLength(...)처럼 둘레에 비례한 값을 써야 크기가 달라도 일관된 결과가 나온다. 도형 인식이 안정적으로 동작하려면 이 비율(보통 1~5%) 튜닝이 핵심이다.

볼록성 — isContourConvex·convexityDefects

윤곽이 볼록(convex)한지 오목(concave)한지는 객체 상태 판정에 유용하다. 별 모양이나 손가락을 편 손은 오목하고, 동전이나 정상적인 부품은 볼록한 경우가 많다.

isContourConvex — 볼록 여부 판별

for (const auto& contour : contours)
{
    // 근사한 다각형으로 판별하는 편이 노이즈에 강하다
    std::vector<cv::Point> approx;
    cv::approxPolyDP(contour, approx,
                     0.02 * cv::arcLength(contour, true), true);

    bool convex = cv::isContourConvex(approx);
    std::cout << (convex ? "볼록한 윤곽" : "오목한 윤곽") << std::endl;
}

convexityDefects — 결함(오목한 부분) 검출

convexityDefects는 윤곽과 그 볼록 껍질 사이의 움푹 들어간 부분을 찾는다. 손가락 사이의 골, 부품의 깨진 곳, 겹친 객체의 연결부 등을 검출하는 데 쓴다. 볼록 껍질을 인덱스 형태로 구해야 한다는 점에 주의한다.

const std::vector<cv::Point>& contour = contours[0];

// 볼록 껍질을 "점 인덱스"로 구한다 (returnPoints = false)
std::vector<int> hullIdx;
cv::convexHull(contour, hullIdx, false);

// 결함 검출 — 껍질 인덱스가 정렬되어 있어야 한다
std::vector<cv::Vec4i> defects;
if (hullIdx.size() > 3)
{
    cv::convexityDefects(contour, hullIdx, defects);

    for (const cv::Vec4i& d : defects)
    {
        int startIdx = d[0];   // 결함 시작점 인덱스
        int endIdx   = d[1];   // 결함 끝점 인덱스
        int farIdx   = d[2];   // 껍질에서 가장 먼 점 인덱스
        float depth  = d[3] / 256.0f;  // 깊이 (고정소수점 → 실수)

        // 일정 깊이 이상인 결함만 의미 있는 것으로 취급
        if (depth > 10.0f)
        {
            cv::Point farPoint = contour[farIdx];
            std::cout << "결함 위치=" << farPoint
                      << ", 깊이=" << depth << std::endl;
        }
    }
}
convexityDefects의 hull은 인덱스여야 한다 convexHull을 점 좌표(vector<Point>)로 받으면 convexityDefects가 예외를 던진다. 반드시 returnPoints = false로 호출해 vector<int> 인덱스를 얻어야 한다. 또한 깊이 값 d[3]은 8비트 고정소수점이므로 256.0f로 나눠야 실제 픽셀 거리가 된다.

실전 — 객체 세기·면적 필터링·형상 분류

지금까지의 도구를 묶으면 산업 검사의 전형적인 파이프라인이 완성된다. 영상에서 객체를 세고, 노이즈를 면적으로 걸러내고, 각 객체의 형상을 분류해 결과를 그린다.

#include <opencv2/opencv.hpp>
#include <iostream>

// 면적 임계값 — 이보다 작은 윤곽은 노이즈로 본다
constexpr double kMinArea = 200.0;

int main()
{
    cv::Mat src = cv::imread("parts.png", cv::IMREAD_GRAYSCALE);
    if (src.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    // 1) 이진화 — Otsu로 임계값 자동 결정
    cv::Mat binary;
    cv::threshold(src, binary, 0, 255,
                  cv::THRESH_BINARY | cv::THRESH_OTSU);

    // 2) 윤곽 검출 — 외곽만
    std::vector<std::vector<cv::Point>> contours;
    cv::findContours(binary, contours, cv::RETR_EXTERNAL,
                     cv::CHAIN_APPROX_SIMPLE);

    cv::Mat result;
    cv::cvtColor(src, result, cv::COLOR_GRAY2BGR);

    int validCount = 0;
    for (const auto& contour : contours)
    {
        // 3) 면적 필터링 — 작은 노이즈 제거
        double area = cv::contourArea(contour);
        if (area < kMinArea)
            continue;

        ++validCount;

        // 4) 형상 분류
        double peri = cv::arcLength(contour, true);
        std::vector<cv::Point> approx;
        cv::approxPolyDP(contour, approx, 0.04 * peri, true);

        std::string shape;
        if (approx.size() == 3)      shape = "Tri";
        else if (approx.size() == 4) shape = "Quad";
        else                         shape = "Round";

        // 5) 무게중심에 라벨, 외접 사각형 표시
        cv::Moments mu = cv::moments(contour);
        cv::Point center(static_cast<int>(mu.m10 / mu.m00),
                         static_cast<int>(mu.m01 / mu.m00));

        cv::Rect box = cv::boundingRect(contour);
        cv::rectangle(result, box, cv::Scalar(0, 255, 0), 2);
        cv::putText(result, shape, center,
                    cv::FONT_HERSHEY_SIMPLEX, 0.6,
                    cv::Scalar(0, 0, 255), 2);
    }

    std::cout << "유효 객체 개수: " << validCount << std::endl;
    cv::imshow("result", result);
    cv::waitKey(0);
    return 0;
}
실행 결과 (콘솔)
유효 객체 개수: 7

이 파이프라인의 각 단계는 독립적으로 교체할 수 있다. 조명이 불균일하면 threshold를 adaptiveThreshold로 바꾸고, 객체가 붙어 있으면 morphologyEx로 분리하고, 형상 분류를 matchShapes 기반으로 정교화하는 식이다. 윤곽선이 검사 로직의 공통 인터페이스 역할을 한다.

면적뿐 아니라 비율·원형도로 거르면 더 견고하다 면적 필터링만으로는 길쭉한 노이즈를 못 거를 수 있다. boundingRect의 가로세로 비율, 4πA/P²로 계산하는 원형도(circularity), 외접 사각형 면적 대비 윤곽 면적 비율(extent) 같은 지표를 함께 쓰면 원하는 객체만 정확히 골라낼 수 있다.

흔한 함정

윤곽선 처리에서 거의 모두가 한 번씩 밟는 함정들이다.

입력이 이진 영상이 아님

findContours에 컬러·그레이스케일 원본을 넣지 않는다 findContours는 입력을 0(배경)과 0이 아닌 값(객체)으로만 해석한다. 그레이스케일 원본을 넣으면 거의 모든 픽셀이 객체로 잡혀 의미 없는 윤곽이 쏟아진다. 반드시 threshold 등으로 만든 CV_8UC1 이진 영상을 넘긴다.

입력 영상이 변형됨 (구버전)

OpenCV 3.x 이하에서는 findContours가 입력 이진 영상을 내부에서 수정했다. 검출 후 그 영상을 다시 쓰려고 하면 망가져 있다. 4.x는 보존하지만, 버전 호환이 걱정되면 복사본을 넘긴다.

cv::Mat binary;
cv::threshold(src, binary, 127, 255, cv::THRESH_BINARY);

// 안전 — 복사본을 넘겨 원본 binary를 보존
std::vector<std::vector<cv::Point>> contours;
cv::findContours(binary.clone(), contours,
                 cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

// binary를 이후 마스크 연산 등에 그대로 재사용 가능

RETR_EXTERNAL로 구멍을 놓침

구멍 검사가 필요한데 RETR_EXTERNAL을 쓰면 안 된다 링·와셔·O링처럼 내부 구멍이 검사 대상이라면 RETR_EXTERNAL은 외곽만 주고 구멍을 버린다. 구멍의 유무·크기·위치가 필요하면 RETR_CCOMP나 RETR_TREE로 검출한 뒤 hierarchy로 자식 윤곽을 찾는다.

면적 0 윤곽과 0으로 나누기

아주 작은 윤곽이나 직선 형태의 윤곽은 contourArea가 0을 반환할 수 있다. 모멘트로 무게중심을 구할 때 m00이 0이면 0으로 나누기가 발생해 nan이나 크래시로 이어진다.

cv::Moments mu = cv::moments(contour);

// 나쁨 — m00이 0이면 nan
// cv::Point c(mu.m10 / mu.m00, mu.m01 / mu.m00);

// 좋음 — 항상 m00을 먼저 검사
if (mu.m00 > 0.0)
{
    cv::Point c(static_cast<int>(mu.m10 / mu.m00),
                static_cast<int>(mu.m01 / mu.m00));
    // c 사용
}

approxPolyDP epsilon을 고정값으로 줌

epsilon은 둘레 비례, closed 인자도 빠뜨리지 않는다 approxPolyDP의 epsilon을 상수로 박으면 객체 크기에 따라 결과가 들쭉날쭉해진다. 0.02 * arcLength(contour, true) 형태로 둘레에 비례시킨다. 또 마지막 closed 인자를 true로 줘야 닫힌 다각형으로 근사된다 — 여기서 false를 주면 도형 인식의 꼭짓점 수가 어긋난다.
정리하면 입력은 이진 영상으로 만들고, 필요하면 복사본을 넘기고, 구멍이 중요하면 RETR_TREE를 쓰고, 모멘트는 m00을 먼저 검사하고, approxPolyDP의 epsilon은 둘레에 비례시킨다. 이 다섯 가지가 윤곽선 처리 버그의 대부분을 막아준다.
