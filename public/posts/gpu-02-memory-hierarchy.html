왜 메모리 계층이 중요한가

GPU는 연산 자체가 빠르다. RTX 4090 기준 단정밀도 FP32 연산 능력이 80 TFLOPS를 넘는다. 하지만 메모리 대역폭은 1 TB/s 수준이다. 단순히 나눠 보면 연산 한 번에 데이터 한 바이트도 못 가져오는 비율이다. 그래서 대부분의 CUDA 커널은 연산이 아니라 메모리에 묶인다(memory-bound).

해결책은 두 가지다. 더 빠른 메모리에 데이터를 옮겨 재사용하거나, 한 번에 가져오는 데이터 양을 늘려 결합(coalesce)한다. 둘 다 GPU 메모리 계층을 정확히 이해해야 가능하다.

GPU 메모리 계층 — 위로 갈수록 빠르고 작으며, 아래로 갈수록 크고 느리다

Global Memory — 크지만 느린 본거지

GPU에서 가장 큰 메모리다. 보통 수 GB ~ 수십 GB(DRAM). 모든 스레드가 읽고 쓸 수 있으며 호스트(CPU)에서도 cudaMemcpy로 접근한다. 대신 지연 시간이 수백 사이클로 가장 느리다.

// 호스트에서 global memory 할당과 데이터 전송
float* d_input = nullptr;
float* d_output = nullptr;

cudaMalloc(&d_input, n * sizeof(float));
cudaMalloc(&d_output, n * sizeof(float));

cudaMemcpy(d_input, h_input, n * sizeof(float), cudaMemcpyHostToDevice);

// 커널에서 global memory 직접 접근
__global__ void scale(const float* in, float* out, float k, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n)
    {
        out[i] = in[i] * k;   // global read + global write
    }
}

scale<<<(n + 255) / 256, 256>>>(d_input, d_output, 2.0f, n);

cudaMemcpy(h_output, d_output, n * sizeof(float), cudaMemcpyDeviceToHost);
cudaFree(d_input);
cudaFree(d_output);

메모리 결합(coalescing)

같은 warp(32 스레드)가 연속된 주소를 동시에 읽으면 한 번의 트랜잭션으로 처리된다. 이 결합이 깨지면 대역폭이 수 배 떨어진다.

// 좋은 예 — 연속 접근, 결합됨
__global__ void good(const float* in, float* out)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    out[i] = in[i];   // thread 0 → in[0], thread 1 → in[1] ... 32개가 한 번에
}

// 나쁜 예 — stride 접근, 결합 깨짐
__global__ void bad(const float* in, float* out, int stride)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    out[i] = in[i * stride];   // thread 0 → in[0], thread 1 → in[32] ... 32회 트랜잭션
}
Global만 쓰는 코드의 함정 간단해서 처음에는 모두 global로 짠다. 그러나 같은 데이터를 여러 스레드가 반복해서 읽는 패턴(컨볼루션, 행렬 곱)에서는 global을 그대로 두면 대역폭이 병목이 된다. 재사용 데이터는 __shared__로 옮긴다.

Shared Memory — 블록 안의 초고속 캐시

같은 블록에 속한 스레드끼리 공유하는 온칩 메모리다. L1 캐시와 같은 물리 공간을 나눠 쓰며 지연 시간이 수십 사이클로 global보다 100배쯤 빠르다. 크기는 SM당 48 KB ~ 228 KB(아키텍처에 따라 다름).

키워드는 __shared__. 컴파일 타임 고정 크기 또는 런타임 동적 크기로 선언한다.

// 정적 shared memory — 크기가 컴파일 타임에 결정
__global__ void staticShared()
{
    __shared__ float tile[256];

    int tid = threadIdx.x;
    tile[tid] = tid * 1.0f;

    __syncthreads();   // 블록 내 모든 스레드가 도달할 때까지 대기

    // 이후 tile[] 안전하게 읽기
}

// 동적 shared memory — 커널 런치 시 3번째 인자로 크기 지정
__global__ void dynamicShared(int n)
{
    extern __shared__ float sdata[];   // 크기 미지정
    int tid = threadIdx.x;
    sdata[tid] = tid;
    __syncthreads();
}

// 호출 시: 256 * sizeof(float) 바이트 만큼 동적 할당
dynamicShared<<<1, 256, 256 * sizeof(float)>>>(256);
__syncthreads()는 필수 Shared에 쓴 직후 다른 스레드가 그 값을 읽는다면 반드시 __syncthreads()로 블록 동기화를 해야 한다. 빠뜨리면 경쟁 상태가 발생한다.

이미지 처리에서 흔한 패턴은 타일(tile) 로딩이다. 한 블록이 처리할 영역을 한 번 global에서 shared로 옮긴 뒤 그 안에서 여러 번 재사용한다.

// 3x3 박스 블러 — shared memory 타일 사용
constexpr int kTile = 16;
constexpr int kRadius = 1;

__global__ void boxBlurShared(const unsigned char* in, unsigned char* out, int w, int h)
{
    __shared__ unsigned char tile[kTile + 2 * kRadius][kTile + 2 * kRadius];

    int gx = blockIdx.x * kTile + threadIdx.x;
    int gy = blockIdx.y * kTile + threadIdx.y;
    int lx = threadIdx.x + kRadius;
    int ly = threadIdx.y + kRadius;

    // 중심 픽셀 로드
    if (gx < w && gy < h)
    {
        tile[ly][lx] = in[gy * w + gx];
    }
    // 경계(halo) 픽셀은 일부 스레드만 로드 — 생략

    __syncthreads();

    if (gx < w && gy < h)
    {
        int sum = 0;
        for (int dy = -kRadius; dy <= kRadius; ++dy)
            for (int dx = -kRadius; dx <= kRadius; ++dx)
                sum += tile[ly + dy][lx + dx];

        out[gy * w + gx] = sum / 9;
    }
}

Constant Memory — 읽기 전용 브로드캐스트

크기는 작다(보통 64 KB). 실체는 DRAM이지만 전용 constant 캐시를 거친다. warp 안의 모든 스레드가 같은 주소를 읽을 때 한 번의 캐시 히트로 32개에 동시 브로드캐스트되어 매우 빠르다.

커널 매개변수처럼 모든 스레드가 공통으로 쓰는 작은 룩업 테이블, 필터 계수, 변환 행렬에 적합하다.

// 전역 스코프에 선언
__constant__ float c_kernel[9];   // 3x3 필터 계수

void uploadKernel(const float* h_kernel)
{
    // 호스트 → constant memory 복사 전용 API
    cudaMemcpyToSymbol(c_kernel, h_kernel, 9 * sizeof(float));
}

__global__ void conv3x3(const float* in, float* out, int w, int h)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x < 1 || x >= w - 1 || y < 1 || y >= h - 1) return;

    float sum = 0.0f;
    for (int j = -1; j <= 1; ++j)
        for (int i = -1; i <= 1; ++i)
        {
            // 모든 스레드가 같은 c_kernel 원소를 동시에 읽음 → 브로드캐스트 효과
            sum += in[(y + j) * w + (x + i)] * c_kernel[(j + 1) * 3 + (i + 1)];
        }
    out[y * w + x] = sum;
}
스레드마다 다른 주소를 읽으면 직렬화된다 Constant는 "모두가 같은 값"일 때만 빠르다. warp 안에서 서로 다른 인덱스에 접근하면 순차 처리되어 오히려 global보다 느려진다.

Texture / Surface Memory — 2D 공간 캐시

그래픽스 텍스처에서 유래한 메모리다. 실체는 global이지만 2D 공간 지역성에 최적화된 캐시를 거친다. 픽셀이 가까이 있을수록 캐시 적중률이 높다.

이미지 처리에서 매력은 두 가지다. 하나는 경계 처리(clamp, wrap, mirror)가 자동, 다른 하나는 선형 보간이 하드웨어로 처리된다는 점이다. 워핑이나 리샘플링 커널에서 코드가 짧아진다.

// CUDA 5.0+ 의 텍스처 오브젝트 API
cudaArray* cuArray = nullptr;
cudaChannelFormatDesc desc = cudaCreateChannelDesc<unsigned char>();
cudaMallocArray(&cuArray, &desc, width, height);
cudaMemcpy2DToArray(cuArray, 0, 0, h_image, width, width, height,
                    cudaMemcpyHostToDevice);

cudaResourceDesc resDesc{};
resDesc.resType = cudaResourceTypeArray;
resDesc.res.array.array = cuArray;

cudaTextureDesc texDesc{};
texDesc.addressMode[0] = cudaAddressModeClamp;   // x 경계 — 자동 클램프
texDesc.addressMode[1] = cudaAddressModeClamp;   // y 경계
texDesc.filterMode = cudaFilterModeLinear;       // 양선형 보간
texDesc.readMode = cudaReadModeNormalizedFloat;  // 0~255 → 0.0~1.0
texDesc.normalizedCoords = 0;                    // 정수 좌표 사용

cudaTextureObject_t tex = 0;
cudaCreateTextureObject(&tex, &resDesc, &texDesc, nullptr);

// 커널 — 회전 변환
__global__ void rotate(cudaTextureObject_t tex, float* out, int w, int h, float theta)
{
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x >= w || y >= h) return;

    float cx = w * 0.5f, cy = h * 0.5f;
    float u = cosf(theta) * (x - cx) - sinf(theta) * (y - cy) + cx;
    float v = sinf(theta) * (x - cx) + cosf(theta) * (y - cy) + cy;

    // 부동소수 좌표 → 하드웨어가 양선형 보간 + 경계 클램프 자동 처리
    out[y * w + x] = tex2D<float>(tex, u + 0.5f, v + 0.5f);
}

Register — 스레드 전용 최고속

가장 빠른 메모리다. 지연 시간 0에 가깝다. 단, 스레드 전용이라 다른 스레드와 공유 불가. 커널 안에서 선언한 지역 변수는 컴파일러가 자동으로 레지스터에 배치한다.

__global__ void simple(const float* in, float* out, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // 레지스터
    float a = 0.0f;                                   // 레지스터
    float b = 1.0f;                                   // 레지스터

    if (i < n)
    {
        a = in[i];          // global → register
        b = a * a + 2.0f;   // 레지스터끼리 연산
        out[i] = b;         // register → global
    }
}

SM당 레지스터는 정해져 있다(예: 65536개 × 32bit). 커널이 스레드당 레지스터를 너무 많이 쓰면 동시에 돌릴 수 있는 스레드 수(점유율, occupancy)가 줄어든다. 컴파일 옵션 --maxrregcount 또는 __launch_bounds__로 한도를 둘 수 있다.

// 블록당 최대 256 스레드, SM당 최소 2블록 동시 실행을 컴파일러에 힌트
__global__ void __launch_bounds__(256, 2) heavyKernel(float* data)
{
    // 컴파일러는 이 한도에 맞게 레지스터 사용을 조절한다
}

Local Memory — 사실은 global, spill 주의

이름은 "local"이지만 실체는 global DRAM 영역의 한 구역이다. 다음 두 경우에 자동으로 사용된다.

  • 스레드 안의 큰 배열(인덱싱이 컴파일 타임에 결정되지 않는 경우)
  • 레지스터가 부족해서 변수가 밀려나는 register spill
// 거의 확실히 local memory로 떨어지는 코드
__global__ void localExample()
{
    float buf[128];   // 큰 지역 배열 → 레지스터에 다 못 들어감

    int i = threadIdx.x % 128;
    buf[i] = 1.0f;          // 동적 인덱스 → 레지스터 배치 불가
    // ... 사용
}
spill을 못 알아차리는 함정 커널 성능이 갑자기 떨어졌는데 원인을 모르겠다면 spill일 가능성이 높다. nvcc -Xptxas=-v로 빌드하면 스레드당 레지스터 수와 stack/local 사용량이 출력된다. stack frame이 0이 아니면 spill이 발생한 것이다.

// nvcc -Xptxas=-v -arch=sm_86 kernel.cu

Unified Memory — 자동 관리

호스트와 디바이스가 같은 포인터를 공유한다. 드라이버가 페이지 단위로 자동 마이그레이션한다. 코드가 훨씬 짧아지지만 첫 접근 시 페이지 폴트가 발생해 성능은 수동 관리보다 떨어질 수 있다.

float* data = nullptr;
cudaMallocManaged(&data, n * sizeof(float));   // CPU/GPU 양쪽에서 같은 포인터

// 호스트에서 초기화
for (int i = 0; i < n; ++i) data[i] = i;

// 그대로 커널에 넘김 — cudaMemcpy 필요 없음
scale<<<blocks, threads>>>(data, data, 2.0f, n);
cudaDeviceSynchronize();

// 호스트가 다시 읽음 — 자동 마이그레이션
std::cout << data[0] << std::endl;

cudaFree(data);

// 힌트로 성능 보완 가능
cudaMemPrefetchAsync(data, n * sizeof(float), 0);   // 디바이스 0으로 미리 옮김
언제 쓰면 좋은가 프로토타입과 호스트·디바이스 자료구조가 복잡하게 얽힌 코드에서 유용하다. 산업용 고성능 파이프라인은 보통 cudaMalloc + cudaMemcpyAsync + pinned memory 조합으로 명시적 관리한다.

대표 패턴 — Global → Shared 타일링

행렬 곱은 메모리 계층 활용의 교과서 예제다. naive 버전은 같은 행/열을 N번씩 읽어 global 대역폭에 묶인다. shared로 옮기면 N배 가까이 빨라진다.

// Naive 버전 — global 반복 읽기
__global__ void matmulNaive(const float* A, const float* B, float* C, int N)
{
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;
    if (row >= N || col >= N) return;

    float sum = 0.0f;
    for (int k = 0; k < N; ++k)
    {
        sum += A[row * N + k] * B[k * N + col];   // 매번 global
    }
    C[row * N + col] = sum;
}
// Tiled 버전 — shared memory에 16x16 블록을 옮겨 재사용
constexpr int kTile = 16;

__global__ void matmulTiled(const float* A, const float* B, float* C, int N)
{
    __shared__ float As[kTile][kTile];
    __shared__ float Bs[kTile][kTile];

    int row = blockIdx.y * kTile + threadIdx.y;
    int col = blockIdx.x * kTile + threadIdx.x;

    float sum = 0.0f;

    for (int t = 0; t < N / kTile; ++t)
    {
        // 1) global → shared 로 한 타일씩 로드
        As[threadIdx.y][threadIdx.x] = A[row * N + (t * kTile + threadIdx.x)];
        Bs[threadIdx.y][threadIdx.x] = B[(t * kTile + threadIdx.y) * N + col];
        __syncthreads();

        // 2) shared 안에서 16번 재사용
        for (int k = 0; k < kTile; ++k)
        {
            sum += As[threadIdx.y][k] * Bs[k][threadIdx.x];
        }
        __syncthreads();
    }

    C[row * N + col] = sum;
}

여기에 필터 계수처럼 모든 스레드가 공유하는 작은 데이터는 __constant__로, 변환 행렬·룩업 테이블 등도 같은 패턴이다. "공통 작은 값 → constant, 재사용 큰 블록 → shared, 나머지 → global"로 정리하면 일관성 있는 설계가 된다.

흔한 함정 정리

Global만 쓰는 코드

"동작은 하니까" 그대로 두면 대역폭이 병목이 된다. nvprof 또는 Nsight Compute에서 memory throughput과 compute throughput을 비교한다. 메모리만 높으면 shared 후보다.

__syncthreads() 누락

Shared에 쓰고 바로 다른 스레드가 읽는 곳에는 반드시 __syncthreads(). 빠지면 결과가 가끔 틀린다(가장 디버깅하기 어려운 종류).

Register spill 무시

-Xptxas=-v로 빌드해 stack frame이 0인지 확인. 큰 지역 배열은 가능한 한 shared로 옮기거나 알고리즘을 쪼갠다.

Constant를 다른 인덱스로 접근

모든 스레드가 같은 주소를 읽을 때만 빠르다. c_table[threadIdx.x]처럼 스레드마다 다른 인덱스면 직렬화되어 오히려 손해다. 그런 경우는 그냥 global이 낫다.

결합 안 되는 접근 패턴

구조체 배열(AoS) 대신 배열 구조체(SoA)로 바꾸면 결합이 살아난다. 이미지에서는 row-major + warp가 같은 행을 처리하도록 그리드를 짠다.

Unified Memory에 모든 걸 맡기기

편하지만 페이지 폴트가 잦으면 성능이 들쭉날쭉해진다. 핵심 핫 데이터는 cudaMemPrefetchAsync로 미리 옮기거나 명시적 cudaMalloc으로 관리한다.

다음 글 예고 다음 편(gpu-03)에서는 첫 CUDA 커널을 직접 작성하면서 그리드·블록·스레드 인덱싱 규칙을 정리한다. 이 글에서 다룬 메모리 계층은 이후 모든 커널의 토대가 된다.
