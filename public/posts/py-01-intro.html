Python이란?

Python은 1991년 Guido van Rossum이 발표한 인터프리터 언어다. 한 줄씩 해석하며 실행하므로 컴파일 단계가 없다. 가독성 좋은 문법과 풍부한 라이브러리 덕에 데이터·웹·자동화·머신러닝까지 거의 모든 영역에서 표준이 되었다.

핵심 특성

  • 동적 타이핑 — 변수에 타입을 미리 선언하지 않는다. 런타임에 타입이 결정된다.
  • 인터프리터 언어 — 가장 널리 쓰이는 구현은 CPython(C로 작성된 표준 인터프리터). 그 외 PyPy(JIT), Jython, IronPython 등이 있다.
  • 다중 패러다임 — 절차적·객체지향·함수형을 모두 지원한다.
  • GC 기반 메모리 관리 — 참조 카운팅 + 순환 GC.
  • 들여쓰기 문법 — 중괄호 대신 들여쓰기로 블록을 구분한다.

항목PythonC++

왜 "느린" Python이 AI의 표준이 되었나? 실제 연산은 NumPy·PyTorch처럼 C·C++·CUDA로 작성된 백엔드가 처리한다. Python은 "지휘자" 역할만 한다. 즉 편한 문법으로 빠른 라이브러리를 호출하는 구조다.

설치

2026년 기준 안정 버전은 Python 3.12+이다. 무조건 3.x를 설치한다.

Windows

python.org에서 인스톨러를 받는 방식을 가장 권장한다. 설치 시 "Add python.exe to PATH"를 반드시 체크한다.

# 설치 확인 (PowerShell)
python --version
# Python 3.12.3

# Windows에서 여러 버전이 설치된 경우 py 런처 사용
py -3.12 --version
py -3.11 --version

# 대안: winget
winget install Python.Python.3.12

macOS

# Homebrew (권장)
brew install python@3.12

# 또는 python.org 공식 인스톨러
# 시스템 기본 Python은 절대 건드리지 않는다.

Linux

# Ubuntu/Debian
sudo apt update
sudo apt install python3 python3-venv python3-pip

# Fedora/RHEL
sudo dnf install python3 python3-pip

# 버전 확인
python3 --version
시스템 Python을 절대 건드리지 말 것 Linux/macOS는 OS 자체가 시스템 Python에 의존한다. 시스템 Python에 pip install로 패키지를 설치하면 OS가 망가질 수 있다. 항상 가상환경을 쓰자.

REPL — 대화형 셸

REPL은 Read-Eval-Print Loop의 약자. 한 줄씩 입력하면 즉시 실행·출력한다. C++에는 없는 강력한 학습 도구다.

# 표준 REPL 시작
python
# 또는
python3
>>> 1 + 2
3
>>> name = "Python"
>>> f"Hello, {name}!"
'Hello, Python!'
>>> import math
>>> math.sqrt(2)
1.4142135623730951
>>> exit()

IPython — 개선된 REPL

자동완성·하이라이팅·magic 명령을 지원한다.

pip install ipython
ipython
In [1]: %timeit sum(range(1000))
8.5 μs ± 0.1 μs per loop

In [2]: ?str.split    # 도움말
In [3]: !ls            # 셸 명령 실행

Jupyter Notebook

브라우저 기반의 노트북. 코드·결과·그래프·텍스트를 한 문서에 섞을 수 있다. 데이터 분석·연구의 사실상 표준이다.

pip install jupyterlab
jupyter lab

첫 프로그램

파일로 저장해 실행해 보자. 파일명은 hello.py로 한다.

# hello.py
def greet(name: str) -> str:
    return f"Hello, {name}!"

if __name__ == "__main__":
    print(greet("World"))
python hello.py
실행 결과
Hello, World!

Shebang — Unix 스크립트로 만들기

Linux/macOS에서 파일 첫 줄에 인터프리터 경로를 적으면 실행 가능한 스크립트가 된다.

#!/usr/bin/env python3
# 첫 줄에 위 라인을 추가
print("Hello from shebang!")
chmod +x hello.py
./hello.py

가상환경 (venv)

Python 입문자가 가장 먼저 익혀야 하는 개념이다. 가상환경은 프로젝트별로 독립된 Python 인터프리터·패키지 디렉터리를 만드는 도구다.

프로젝트마다 독립된 가상환경을 둬서 의존성 충돌을 방지한다.

생성과 활성화

# 프로젝트 디렉터리로 이동
cd my-project

# 가상환경 생성 (.venv 폴더가 만들어진다)
python -m venv .venv

# 활성화 — Windows (PowerShell)
.venv\Scripts\Activate.ps1

# 활성화 — Windows (cmd)
.venv\Scripts\activate.bat

# 활성화 — macOS / Linux
source .venv/bin/activate

# 활성화되면 프롬프트 앞에 (.venv) 표시
(.venv) $ python --version
Python 3.12.3

# 비활성화
(.venv) $ deactivate
.venv는 Git에 올리지 말 것 가상환경 폴더는 OS·경로 의존적이라 다른 머신에서 동작하지 않는다. .gitignore에 .venv/를 추가하고, 의존성은 requirements.txt로 관리한다.

pip — 패키지 관리

pip는 Python 표준 패키지 매니저다. PyPI(Python Package Index)에서 패키지를 받아온다.

# 가상환경 활성화 후
(.venv) $ pip install numpy
(.venv) $ pip install opencv-python==4.10.0   # 버전 고정
(.venv) $ pip install "torch>=2.0,<3.0"        # 범위 지정

# 설치된 패키지 목록
(.venv) $ pip list

# 특정 패키지 정보
(.venv) $ pip show numpy

# 업그레이드
(.venv) $ pip install --upgrade numpy

# 제거
(.venv) $ pip uninstall numpy

requirements.txt

프로젝트의 의존성을 텍스트 파일로 고정해 협업자가 동일 환경을 재현할 수 있게 한다.

# 현재 설치된 모든 패키지를 파일로 저장
(.venv) $ pip freeze > requirements.txt
# requirements.txt 내용 예시
numpy==1.26.4
opencv-python==4.10.0.84
pandas==2.2.2
matplotlib==3.8.4
# 협업자가 재현 — 새 venv 만들고 한 줄로 복원
python -m venv .venv
source .venv/bin/activate         # 또는 .venv\Scripts\Activate.ps1
pip install -r requirements.txt

현대 패키지 매니저 — uv·poetry·conda

pip + venv는 표준이지만 느리고 의존성 해결이 단순하다. 최근에는 더 강력한 도구들이 표준 자리를 노린다.

도구특징언제 쓰나
uvRust로 작성. pip의 10~100배. venv·pip·pyenv를 통합2025년 이후 새 프로젝트의 기본. 강력 추천
poetry의존성 해결·잠금 파일(poetry.lock)·빌드·게시 일체화라이브러리 배포·중대형 프로젝트
condaPython 외 C/C++ 바이너리·CUDA까지 관리. Anaconda 배포판데이터 사이언스·과학 계산·복잡한 네이티브 의존성
pip + venv표준 도구. 추가 설치 불필요학습·간단한 스크립트
# uv 예시 — 가장 빠른 흐름
pip install uv
uv venv                       # .venv 생성
uv pip install numpy opencv-python
uv pip freeze > requirements.txt

# poetry 예시
pip install poetry
poetry new my-project
poetry add numpy
poetry install

# conda 예시
conda create -n vision python=3.12
conda activate vision
conda install -c conda-forge opencv numpy

IDE 선택

  • VS Code + Python 확장 — 무료, 가장 범용. 디버거·노트북·타입 체크 모두 통합.
  • PyCharm — JetBrains. 리팩터링·디버깅이 강력. Community(무료)/Professional(유료).
  • JupyterLab — 노트북 기반. 데이터 탐색·시각화에 최적.
  • Cursor / Claude Code — AI 페어 프로그래밍을 전제로 한 최신 도구.
VS Code에서 가상환경 인식시키기 Ctrl+Shift+P → "Python: Select Interpreter" → 프로젝트의 .venv 선택. 이후 통합 터미널은 자동으로 venv를 활성화한다.

Python 2 vs 3

Python 2는 2020년 1월 1일부로 EOL(End of Life). 보안 업데이트도 없다. 무조건 Python 3을 쓴다.

# Python 2 — 절대 쓰지 말 것
print "hello"           # 문법 오류 (Py3)
print 5 / 2             # 2 (정수 나눗셈)

# Python 3 — 표준
print("hello")
print(5 / 2)            # 2.5 (실수)
print(5 // 2)           # 2  (정수 나눗셈은 //)
오래된 튜토리얼 주의 구글에서 검색하다 보면 print를 함수가 아닌 문(statement)으로 쓰는 자료가 나온다. 그건 Python 2 코드다. 무시하고 Python 3 자료를 찾자.

산업·비전 관점에서의 Python

머신비전·딥러닝 분야에서 Python은 사실상 표준 언어다. 그 이유는 분명하다.

  • NumPy — N차원 배열의 표준. 이미지는 결국 uint8 배열이다.
  • OpenCV (cv2) — C++ OpenCV의 Python 바인딩. 거의 모든 함수가 동일하게 노출된다.
  • PyTorch / TensorFlow — 딥러닝 학습·추론의 표준. C++ 백엔드 + Python 프런트엔드.
  • scikit-image / Pillow — 보조 이미지 처리.
  • matplotlib / plotly — 결과 시각화.
import cv2
import numpy as np

# 이미지 로드 — OpenCV는 BGR 순서로 반환
img = cv2.imread("sample.png")
print(img.shape, img.dtype)     # (H, W, 3) uint8

# 그레이스케일 변환
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

# 가우시안 블러
blurred = cv2.GaussianBlur(gray, (5, 5), sigmaX=1.0)

# Canny 엣지
edges = cv2.Canny(blurred, threshold1=50, threshold2=150)

cv2.imwrite("edges.png", edges)

C++과의 역할 분담

실무에서 둘은 적이 아니라 짝이다.

단계주로 쓰는 언어이유
알고리즘 프로토타이핑·실험Python빠른 반복, Jupyter, 풍부한 시각화
모델 학습Python (PyTorch)GPU 백엔드는 C++/CUDA가 처리
딥러닝 추론 — 연구Python편의성
딥러닝 추론 — 양산 장비C++ (TensorRT, ONNX Runtime)저지연, 메모리 제어, 배포 단순
카메라·그래버 SDK 통합C++실시간성, 벤더 SDK 대부분 C/C++
장비 GUIC++ (Qt) / C# (WPF)네이티브 성능·배포 용이
흔한 흐름 Python으로 빠르게 알고리즘을 만들고 검증한다. 양산 장비에 들어갈 때는 C++로 포팅하거나 ONNX/TensorRT로 변환해 C++ 추론 엔진에서 돌린다.

흔한 함정

1. 시스템 Python에 패키지를 직접 설치 sudo pip install ...은 OS의 의존성을 깨뜨릴 수 있다. 최신 pip(PEP 668)는 시스템 Python에 설치를 거부한다. 반드시 venv 안에서만 설치하자.
2. 가상환경 없이 여러 프로젝트 공용으로 설치 A 프로젝트는 numpy 1.21, B 프로젝트는 numpy 1.26이 필요할 때 충돌한다. 프로젝트 = 가상환경이 1:1이 되도록 하자.
3. requirements.txt 없이 협업 "내 컴에선 되는데" 문제의 99%가 의존성 누락이다. pip freeze > requirements.txt를 습관화한다.
4. Windows에서 python과 py 혼용 Windows에는 python(PATH 위 첫 번째) / py(Python Launcher) 두 명령이 있다. 멀티 버전 환경에서는 py -3.12로 명시하는 편이 안전하다.
5. 스크립트 이름을 표준 모듈명과 동일하게 numpy.py나 email.py처럼 표준 라이브러리/패키지명과 같은 파일명을 쓰면 import가 자기 자신을 불러 미친 에러가 발생한다.
