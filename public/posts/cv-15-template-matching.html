템플릿 매칭이란?

템플릿 매칭(template matching)은 작은 템플릿 이미지를 큰 입력 이미지 위에서 한 픽셀씩 슬라이딩하며, 각 위치에서 두 이미지가 얼마나 닮았는지 점수를 매겨 가장 닮은 위치를 찾는 기법이다. 발상 자체는 단순하다 — 찾고 싶은 패턴을 오려서 이미지 전체를 훑는다.

입력 이미지 크기가 W × H, 템플릿 크기가 w × h라면, 템플릿이 들어갈 수 있는 좌상단 위치의 개수는 (W - w + 1) × (H - h + 1)이다. 각 위치마다 닮음 점수를 하나씩 계산하므로, 결과는 그 크기의 점수 맵(2차원 행렬)이 된다.

템플릿이 입력 이미지 위를 슬라이딩하며 위치마다 닮음 점수를 계산해 점수 맵을 만든다.

OpenCV에서는 이 전체 과정을 cv::matchTemplate 함수 하나로 처리한다. 슬라이딩 루프를 직접 짤 필요는 없다.

점수 맵은 입력보다 약간 작다 템플릿이 이미지 밖으로 나갈 수 없으므로, 점수 맵의 크기는 (W - w + 1) × (H - h + 1)이다. 점수 맵의 좌표는 매칭된 영역의 좌상단 픽셀을 가리킨다는 점을 기억한다.

matchTemplate — 6가지 매칭 방법

cv::matchTemplate(image, templ, result, method)는 입력 image와 템플릿 templ을 받아 점수 맵 result를 채운다. result의 타입은 항상 CV_32FC1(32비트 float 1채널)이다. 핵심은 네 번째 인자 method — 닮음을 어떻게 정의하느냐를 고르는 값이다. 6가지가 있다.

#include <opencv2/opencv.hpp>
#include <iostream>

int main()
{
    // 입력 이미지와 찾을 템플릿을 그레이스케일로 읽는다
    cv::Mat image = cv::imread("scene.png", cv::IMREAD_GRAYSCALE);
    cv::Mat templ = cv::imread("part.png", cv::IMREAD_GRAYSCALE);

    if (image.empty() || templ.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    // 점수 맵 — matchTemplate이 알아서 크기/타입을 잡아준다
    cv::Mat result;

    // TM_CCOEFF_NORMED: 가장 무난한 선택. 결과는 -1 ~ 1, 클수록 닮음
    cv::matchTemplate(image, templ, result, cv::TM_CCOEFF_NORMED);

    std::cout << "result 크기: " << result.cols << " x " << result.rows
              << ", 타입: CV_32FC1" << std::endl;
    return 0;
}
실행 결과 (콘솔)
result 크기: 561 x 401, 타입: CV_32FC1

6가지 방법은 크게 세 계열로 나뉜다 — SQDIFF(제곱차), CCORR(상호상관), CCOEFF(상관계수). 각 계열에 정규화하지 않은 버전과 _NORMED(정규화) 버전이 있다.

method의미좋은 매칭은값 범위
TM_SQDIFF픽셀 차이의 제곱 합최솟값 (0에 가까움)0 ~ 큰 값
TM_SQDIFF_NORMED제곱차를 에너지로 정규화최솟값 (0에 가까움)0 ~ 1
TM_CCORR픽셀값 곱의 합 (상호상관)최댓값0 ~ 큰 값
TM_CCORR_NORMED상호상관을 에너지로 정규화최댓값0 ~ 1
TM_CCOEFF평균을 뺀 뒤 상호상관 (밝기 오프셋 제거)최댓값음수 ~ 양수
TM_CCOEFF_NORMED평균 제거 + 정규화 = 사실상 NCC최댓값-1 ~ 1
SQDIFF는 최솟값, CCORR/CCOEFF는 최댓값이 정답이다 가장 흔한 실수다. TM_SQDIFF 계열은 "차이"를 재므로 작을수록 닮은 것이고, TM_CCORR·TM_CCOEFF 계열은 "닮음"을 재므로 클수록 닮은 것이다. method를 바꿔놓고 minMaxLoc의 반환값을 그대로 쓰면 정반대 위치를 가리킨다.

어떤 method를 골라야 하나

실무에서는 거의 항상 TM_CCOEFF_NORMED를 쓴다. 평균을 빼서 밝기 오프셋에 강하고, 정규화 덕분에 값이 -1 ~ 1로 고정되어 임계값을 정하기 쉽다. 속도가 매우 중요하고 조명이 완벽히 일정하다면 TM_SQDIFF가 가장 빠르지만, 산업 현장에서 조명이 완벽한 경우는 드물다.

결과 해석 — 점수 맵과 minMaxLoc

matchTemplate은 점수 맵을 채워줄 뿐, "객체가 어디 있다"고 알려주지는 않는다. 점수 맵에서 피크를 직접 찾아야 한다. cv::minMaxLoc이 행렬 전체의 최솟값·최댓값과 그 위치를 한 번에 돌려준다.

cv::Mat result;
cv::matchTemplate(image, templ, result, cv::TM_CCOEFF_NORMED);

double minVal, maxVal;
cv::Point minLoc, maxLoc;
cv::minMaxLoc(result, &minVal, &maxVal, &minLoc, &maxLoc);

// TM_CCOEFF_NORMED는 "클수록 닮음" → maxLoc이 정답 위치
cv::Point matchLoc = maxLoc;

// matchLoc은 매칭 영역의 좌상단. 사각형으로 그리려면 템플릿 크기를 더한다
cv::Rect matchRect(matchLoc, cv::Size(templ.cols, templ.rows));

cv::Mat display;
cv::cvtColor(image, display, cv::COLOR_GRAY2BGR);
cv::rectangle(display, matchRect, cv::Scalar(0, 0, 255), 2);

std::cout << "매칭 점수: " << maxVal
          << ", 위치: (" << matchLoc.x << ", " << matchLoc.y << ")" << std::endl;
실행 결과 (콘솔)
매칭 점수: 0.987421, 위치: (243, 118)

method 계열에 따라 minLoc을 쓸지 maxLoc을 쓸지 갈린다. 분기 코드를 한 번 만들어 두면 method를 바꿔도 안전하다.

double minVal, maxVal;
cv::Point minLoc, maxLoc;
cv::minMaxLoc(result, &minVal, &maxVal, &minLoc, &maxLoc);

cv::Point matchLoc;
double matchScore;

// SQDIFF 계열은 최솟값이 정답, 나머지는 최댓값이 정답
if (method == cv::TM_SQDIFF || method == cv::TM_SQDIFF_NORMED)
{
    matchLoc = minLoc;
    matchScore = minVal;   // 0에 가까울수록 좋음
}
else
{
    matchLoc = maxLoc;
    matchScore = maxVal;   // 1에 가까울수록 좋음
}

NORMED 방법이 조명에 강한 이유

정규화하지 않은 TM_CCORR는 픽셀값의 곱을 합한다. 그런데 입력 이미지의 밝은 영역은 픽셀값 자체가 크기 때문에, 템플릿과 닮지 않았어도 곱의 합이 커진다. 즉 밝기에 점수가 휘둘린다. _NORMED 버전은 템플릿과 입력 패치 각각의 에너지(픽셀값 제곱합의 제곱근)로 나눠 이 영향을 제거한다. 밝기가 두 배가 되어도 분자와 분모가 같이 커져 점수는 그대로다.

TM_CCOEFF 계열은 한 걸음 더 나간다. 곱하기 전에 각 패치의 평균을 빼준다. 이러면 조명이 전체적으로 밝아지거나 어두워지는 오프셋 변화까지 상쇄된다. 정규화까지 더한 TM_CCOEFF_NORMED가 조명 변화에 가장 강건한 이유다.

점수 맵 자체를 시각화해 보면 이해가 빠르다 cv::normalize(result, vis, 0, 255, cv::NORM_MINMAX, CV_8U)로 점수 맵을 8비트로 펴서 imshow하면, 객체 위치에 또렷한 밝은 점(피크)이 보인다. 피크가 흐릿하거나 여러 개면 매칭이 불안정하다는 신호다.

다중 객체 검출과 중복 제거

minMaxLoc은 피크 하나만 돌려준다. 같은 패턴이 이미지에 여러 개 있다면, 점수 맵에서 임계값 이상인 위치를 전부 골라내야 한다.

cv::Mat result;
cv::matchTemplate(image, templ, result, cv::TM_CCOEFF_NORMED);

const double kMatchThreshold = 0.8;  // 0.8 이상이면 매칭으로 인정

// 임계값 이상인 픽셀만 골라낸다 (마스크 생성)
cv::Mat mask;
cv::threshold(result, mask, kMatchThreshold, 1.0, cv::THRESH_BINARY);
mask.convertTo(mask, CV_8U);

// 임계값을 넘은 모든 좌표를 수집한다
std::vector<cv::Point> locations;
cv::findNonZero(mask, locations);

std::cout << "임계값 이상 후보: " << locations.size() << "개" << std::endl;
실행 결과 (콘솔)
임계값 이상 후보: 1483개

그런데 후보가 1483개나 나온다. 객체가 1483개일 리는 없다. 진짜 매칭 위치 주변의 픽셀들도 점수가 높아 임계값을 같이 넘기 때문이다. 하나의 객체가 수십~수백 개의 인접한 후보 점으로 뭉쳐 나온다. 이 중복을 제거해야 한다 — 이것이 NMS(Non-Maximum Suppression, 비최대 억제)의 개념이다.

NMS — 겹치는 후보 중 최고만 남기기

NMS의 원리는 간단하다. 점수가 높은 후보부터 보면서, 이미 채택한 후보와 너무 가까운(겹치는) 후보는 버린다. 가장 단순한 거리 기반 구현은 다음과 같다.

// 후보 (점수, 위치) 쌍을 모은다
std::vector<std::pair<float, cv::Point>> candidates;
for (const cv::Point& pt : locations)
{
    candidates.push_back({ result.at<float>(pt), pt });
}

// 점수 내림차순 정렬 — 높은 점수부터 채택
std::sort(candidates.begin(), candidates.end(),
          [](const auto& a, const auto& b) { return a.first > b.first; });

std::vector<cv::Point> finalMatches;
const int kMinDistance = templ.cols / 2;  // 이 거리 안쪽은 같은 객체로 본다

for (const auto& cand : candidates)
{
    bool tooClose = false;
    for (const cv::Point& kept : finalMatches)
    {
        // 이미 채택한 매칭과 가까우면 중복으로 간주하고 버린다
        if (cv::norm(cand.second - kept) < kMinDistance)
        {
            tooClose = true;
            break;
        }
    }
    if (!tooClose)
    {
        finalMatches.push_back(cand.second);
    }
}

std::cout << "중복 제거 후 객체: " << finalMatches.size() << "개" << std::endl;
실행 결과 (콘솔)
중복 제거 후 객체: 7개
박스 IoU 기반 NMS도 있다 위 코드는 중심 거리로 중복을 판정하는 가장 단순한 방식이다. OpenCV의 cv::dnn::NMSBoxes는 사각형끼리의 IoU(겹친 넓이 비율)로 더 정밀하게 억제한다. 객체 크기가 일정한 템플릿 매칭에서는 거리 기반으로도 충분히 잘 동작한다.

다중 스케일 매칭

matchTemplate은 템플릿과 입력의 크기가 같다고 가정한다. 카메라 거리가 달라져 객체가 템플릿보다 크거나 작게 찍히면 점수가 뚝 떨어진다. 정공법은 템플릿(또는 입력)을 여러 크기로 바꿔가며 매칭을 반복하고, 그중 점수가 가장 높은 스케일을 채택하는 것이다.

cv::Mat image = cv::imread("scene.png", cv::IMREAD_GRAYSCALE);
cv::Mat templ = cv::imread("part.png", cv::IMREAD_GRAYSCALE);

double bestScore = -1.0;
cv::Point bestLoc;
double bestScale = 1.0;

// 템플릿을 0.5배 ~ 1.5배까지 훑는다
for (double scale = 0.5; scale <= 1.5; scale += 0.1)
{
    cv::Mat scaledTempl;
    cv::resize(templ, scaledTempl, cv::Size(), scale, scale);

    // 스케일을 키운 템플릿이 입력보다 커지면 건너뛴다
    if (scaledTempl.cols > image.cols || scaledTempl.rows > image.rows)
    {
        continue;
    }

    cv::Mat result;
    cv::matchTemplate(image, scaledTempl, result, cv::TM_CCOEFF_NORMED);

    double minVal, maxVal;
    cv::Point minLoc, maxLoc;
    cv::minMaxLoc(result, &minVal, &maxVal, &minLoc, &maxLoc);

    // 모든 스케일을 통틀어 가장 높은 점수를 기억한다
    if (maxVal > bestScore)
    {
        bestScore = maxVal;
        bestLoc = maxLoc;
        bestScale = scale;
    }
}

std::cout << "최적 스케일: " << bestScale
          << ", 점수: " << bestScore << std::endl;
실행 결과 (콘솔)
최적 스케일: 1.2, 점수: 0.961037
스케일 루프는 그만큼 느려진다 스케일 단계를 11번 돌면 매칭 비용도 대략 11배다. 게다가 이건 스케일만 해결할 뿐 회전은 여전히 못 잡는다. 회전까지 다루려면 각도 루프를 한 겹 더 씌워야 하는데, 그쯤 되면 템플릿 매칭으로 버티는 게 맞는지 의심해야 한다.

NCC — 정규화 상호상관

NCC(Normalized Cross-Correlation, 정규화 상호상관)는 두 이미지 패치가 얼마나 닮았는지를 재는 고전적인 지표다. OpenCV의 TM_CCOEFF_NORMED가 사실상 NCC와 같다. 수식은 다음과 같다.

NCC는 평균을 빼서 밝기 오프셋을, 에너지로 나눠서 대비(contrast) 변화를 상쇄한다.

분자는 템플릿과 입력 패치에서 각각 평균을 뺀 뒤 곱해 더한 값이다. 평균을 빼므로 조명이 전체적으로 밝아져도 영향이 없다. 분모는 두 패치의 에너지(표준편차에 비례)를 곱한 것의 제곱근으로, 이걸로 나누면 대비가 두 배가 되어도 점수가 변하지 않는다. 결과는 항상 -1 ~ 1 범위다 — 1은 완벽히 닮음, 0은 무관, -1은 명암이 정반대.

NCC 점수해석
0.95 ~ 1.0거의 동일 — 안정적인 매칭
0.8 ~ 0.95닮음 — 실무 임계값을 보통 이 구간에 둠
0.5 ~ 0.8애매 — 변형·노이즈 가능성, 오검출 위험
< 0.5거의 무관 — 매칭 실패로 간주
NCC가 밝기·대비에 강한 것이지, 만능은 아니다 NCC는 조명 변화에는 강하지만 형상 변화(회전·스케일·원근)에는 여전히 무력하다. 픽셀을 위치 그대로 1:1 대응시켜 비교하기 때문이다. 다음 절의 한계가 바로 여기서 나온다.

템플릿 매칭의 한계

템플릿 매칭은 단순하고 빠르지만, 가정이 깨지면 급격히 무너진다. 근본 원인은 하나다 — 템플릿의 픽셀과 입력의 픽셀을 위치 그대로 1:1로 비교하기 때문이다. 픽셀 배치가 조금만 어긋나도 점수가 떨어진다.

변형템플릿 매칭의 반응대응책
회전몇 도만 돌아가도 점수 급락. 회전 불변성 전혀 없음각도 루프 반복, 또는 shape-based matching
스케일 변화크기가 다르면 픽셀이 어긋나 매칭 실패다중 스케일 루프 (느림)
원근·시점 변화평면이 기울면 형상이 일그러져 대응 불가특징점 매칭 + 호모그래피
부분 가림(occlusion)일부만 가려도 전체 점수가 깎임부분 매칭, 또는 특징점 기반
배경 변화템플릿에 배경이 섞이면 배경까지 비교해 오검출마스크 사용, 배경 없는 템플릿
조명 변화NORMED 계열이면 어느 정도 견딤TM_CCOEFF_NORMED 사용

회전과 스케일을 루프로 우회할 수는 있지만, 각도 36단계 × 스케일 11단계면 매칭을 396번 돌려야 한다. 실시간 산업 검사에서는 감당하기 어렵다. 그래서 변형이 큰 상황에서는 다른 접근으로 넘어간다.

  • Shape-based matching — 픽셀값이 아니라 엣지(윤곽선)의 방향을 비교한다. HALCON, MVTec 같은 산업용 라이브러리의 핵심 기능으로, 회전·스케일·조명·부분 가림에 강건하다.
  • 특징점 매칭 — ORB, SIFT 같은 알고리즘으로 양쪽 이미지에서 특징점을 뽑아 대응시킨다. 회전·스케일·원근 변화까지 다룰 수 있다. 다음 글에서 자세히 다룬다.
"회전·스케일이 없다"는 가정은 명시적으로 확인해야 한다 템플릿 매칭을 적용하기 전에 "이 대상은 정말 항상 같은 각도·같은 크기로 들어오는가?"를 반드시 따져본다. 컨베이어 위 부품이 회전 가능하거나, 카메라 거리가 들쭉날쭉하면 템플릿 매칭은 처음부터 잘못된 도구다. 가정이 깨지는 걸 모른 채 임계값만 낮추면 오검출이 폭증한다.

산업 검사 관점

한계가 많다고 템플릿 매칭이 쓸모없는 건 아니다. 가정이 맞아떨어지는 상황에서는 빠르고 확실하다. 산업 검사 현장에서 템플릿 매칭이 잘 맞는 조건은 명확하다.

조건템플릿 매칭 적합도
대상이 항상 같은 방향(회전 없음)적합 — 회전 불변성이 필요 없음
카메라-대상 거리 고정(스케일 일정)적합 — 다중 스케일 루프 불필요
지그·픽스처로 위치가 안정적적합 — 탐색 범위(ROI)를 좁혀 더 빠름
외형 변화 없는 인쇄·각인·마크적합 — 픽셀 패턴이 반복적
부품이 자유롭게 회전·기울어짐부적합 — shape-based matching으로
조명이 크게 변하거나 부분 가림 발생부적합 — 특징점 매칭 검토

전형적인 적용 예는 위치 정렬(alignment)이다. PCB나 라벨처럼 위치는 약간씩 흔들리지만 외형은 동일한 대상에서, 기준 마크를 템플릿으로 잡아 매칭하면 정확한 좌표를 빠르게 얻는다. 그 좌표를 기준으로 검사 ROI를 보정하는 식이다. 이때 탐색 영역을 ROI로 좁히면 매칭이 훨씬 빨라지고 오검출도 줄어든다.

도구 선택의 사다리 외형·각도·크기가 고정 → 템플릿 매칭(가장 빠름). 회전·스케일은 변하지만 형상은 유지 → shape-based matching(HALCON 시리즈에서 다룸). 원근·시점까지 변함 → 특징점 매칭 + 호모그래피(다음 글). 위에서부터 시도하고, 가정이 깨지는 지점에서 한 단계 내려간다.

흔한 함정

템플릿 매칭에서 거의 모두가 한 번씩 밟는 함정들이다.

SQDIFF와 CCORR의 최소/최대 혼동

method를 바꾸면 minLoc/maxLoc도 바꿔야 한다 TM_SQDIFF 계열은 minLoc이 정답, TM_CCORR·TM_CCOEFF 계열은 maxLoc이 정답이다. method만 TM_SQDIFF로 바꾸고 maxLoc을 그대로 쓰면, 가장 안 닮은 위치를 객체라고 가리킨다. 매칭이 "이상하게 엉뚱한 곳"을 찍으면 이 혼동부터 의심한다. 
cv::matchTemplate(image, templ, result, cv::TM_SQDIFF);

double minVal, maxVal;
cv::Point minLoc, maxLoc;
cv::minMaxLoc(result, &minVal, &maxVal, &minLoc, &maxLoc);

// 나쁨 — SQDIFF인데 maxLoc을 쓰면 가장 안 닮은 위치를 가리킨다
// cv::Point wrong = maxLoc;

// 좋음 — SQDIFF는 차이가 작을수록 닮음이므로 minLoc
cv::Point matchLoc = minLoc;

NORMED 아닌 method를 조명 변하는 곳에 사용

TM_CCORR나 TM_SQDIFF는 픽셀값의 절대 크기에 직접 반응한다. 조명이 조금만 변해도 점수가 출렁여 임계값을 정하기 어렵다. 조명이 일정하지 않은 현장에서는 반드시 _NORMED 계열, 그중에서도 평균까지 빼주는 TM_CCOEFF_NORMED를 쓴다.

// 나쁨 — 조명이 변하는 라인에서 TM_CCORR는 점수가 불안정
// cv::matchTemplate(image, templ, result, cv::TM_CCORR);

// 좋음 — 밝기 오프셋·대비 변화에 강건
cv::matchTemplate(image, templ, result, cv::TM_CCOEFF_NORMED);

템플릿에 배경이 섞여 들어감

템플릿은 객체만, 배경은 빼고 잘라야 한다 템플릿을 넉넉하게 잘라 배경 픽셀이 포함되면, 매칭 점수가 "객체 + 그 배경"을 함께 평가한다. 같은 객체라도 배경이 다른 위치에서는 점수가 떨어지고, 배경이 우연히 비슷한 엉뚱한 곳에서 점수가 오른다. 템플릿은 객체 경계에 딱 맞춰 자르거나, 그게 어려우면 마스크를 함께 넘긴다. 
// matchTemplate은 5번째 인자로 마스크를 받는다 (TM_SQDIFF, TM_CCORR_NORMED 등에서 지원)
// 마스크에서 0인 픽셀은 매칭 계산에서 제외된다
cv::Mat mask = cv::imread("part_mask.png", cv::IMREAD_GRAYSCALE);

cv::Mat result;
cv::matchTemplate(image, templ, result, cv::TM_CCORR_NORMED, mask);
// → 템플릿의 배경 영역을 마스크로 가려 객체 픽셀만 비교

회전·스케일이 없다는 가정을 검증 안 함

가정이 깨지면 임계값을 낮춰도 해결되지 않는다 대상이 살짝 회전하거나 크기가 변하는데 단일 템플릿으로 매칭하면, 점수가 전반적으로 낮아진다. 이때 임계값을 낮춰 억지로 통과시키면 오검출이 같이 늘어난다. 회전·스케일 변형이 의심되면 임계값을 만지지 말고, 다중 스케일/각도 루프나 shape-based matching으로 도구를 바꾼다.
정리하면 method 계열에 맞춰 minLoc/maxLoc을 쓰고, 조명이 변하면 TM_CCOEFF_NORMED를 쓰고, 템플릿은 배경 없이 자르고, 회전·스케일 가정을 먼저 검증한다. 이 네 가지만 지켜도 템플릿 매칭 버그의 대부분을 피한다. 그래도 안 되면 그건 템플릿 매칭의 한계이지 코드의 버그가 아니다 — 다음 글의 특징점 매칭으로 넘어갈 때다.
