강의 개요

"Claude Code 101"은 Anthropic이 공식 강의 플랫폼에 올린 입문 코스다. 분량은 12 lectures, 약 1시간, 난이도는 Beginner로 표기되어 있다. 대상은 Claude Code를 처음 써 보는 개발자이며, 별도의 사전 지식은 요구하지 않지만 터미널과 git 기본 정도는 알고 있어야 따라가기 편하다.

강의는 크게 4개 섹션과 마지막 퀴즈로 구성된다. (1) Claude Code가 무엇인가, (2) 첫 프롬프트까지, (3) 일상 워크플로, (4) 커스터마이즈 순서다. 본문에서는 각 섹션을 자기 말로 다시 풀어 정리한다.

왜 101이 따로 있는가 Anthropic은 동일 도구에 대해 101(개념·설치 중심)과 in Action(실전 통합 중심)을 분리해서 제공한다. 101은 "왜 이 도구를 쓰는가"에 시간을 더 쓰고, in Action은 "내 프로젝트에 어떻게 끼워 넣는가"에 시간을 쓴다.

What is Claude Code?

이 섹션은 두 개의 차시로 구성된다. 도구의 정체성과 내부 동작 모델을 잡아 주는 부분이다.

L1What is Claude Code? (What is Claude Code?)

Claude Code는 터미널 기반의 코딩 에이전트다. IDE 안에서 자동완성을 해 주는 도구라기보다는, 코드베이스를 읽고 파일을 편집하고 명령을 실행하는 "협업자"에 가깝다. Cursor·Copilot처럼 에디터에 종속되지 않고 터미널 어디서든 호출할 수 있다는 점이 핵심이다.

L2How Claude Code works (How Claude Code works)

내부적으로는 LLM이 도구(tool)를 호출하면서 작업을 수행한다. Read·Edit·Bash·Grep 같은 표준 도구가 있고, 모델은 사용자의 의도를 보고 어떤 도구를 어떤 순서로 부를지 스스로 결정한다. 이 "도구 호출 루프"가 Claude Code 작동의 본질이다.

Your first prompt

실제로 도구를 손에 쥐는 섹션이다. 설치와 첫 실행까지 다룬다.

L3설치 (Installing Claude Code)

npm 글로벌 설치 한 줄로 끝난다. Mac·Linux·Windows(WSL 권장) 모두 지원한다. VS Code·JetBrains·Claude Desktop·웹에서도 같은 백엔드에 접속할 수 있다는 점이 강조된다. 즉 설치 위치가 어디든 동일한 Claude Code 세션을 쓰는 셈이다.

L4첫 프롬프트 (Your first prompt)

프로젝트 폴더에서 claude 한 번 치면 대화가 시작된다. 강의는 "이 코드베이스에 대해 설명해 줘"처럼 탐색형 질문을 첫 프롬프트로 권장한다. 도구가 어떻게 파일을 읽고 어떤 순서로 답을 구성하는지 직접 보는 것이 가장 빠른 학습이다.

첫 프롬프트는 짧게 강의가 일관되게 강조하는 점은 "처음부터 완벽한 프롬프트를 쓰려 하지 말 것"이다. 짧게 묻고 결과를 보고 다시 지시하는 식으로 가야 도구의 한계와 강점이 손에 잡힌다.

Daily workflows

가장 길고 가장 실용적인 섹션이다. 매일 쓰는 사람 기준의 동선을 다룬다.

L5탐색-계획-코드-커밋 (The explore → plan → code → commit workflow)

강의가 제시하는 표준 4단계 워크플로다. 먼저 코드베이스를 탐색하게 하고("explore"), 변경 계획을 글로 받게 하고("plan"), 동의한 뒤에야 실제 편집을 시키고("code"), 마지막에 git 커밋까지 시킨다("commit"). 처음부터 "코드 짜 줘"라고 시키면 잘못된 가정 위에서 만든다는 점이 핵심 교훈이다.

L6컨텍스트 관리 (Context management)

LLM은 컨텍스트 윈도우라는 유한한 작업 메모리를 가진다. 세션이 길어지면 자동으로 압축되긴 하지만, 작업 단위마다 새 세션을 쓰는 것이 일반적으로 더 안전하다. /clear로 명시적으로 비우는 습관도 같이 다룬다.

L7코드 리뷰 (Code review)

변경 diff를 Claude에게 던져서 리뷰를 받게 한다. 사람이 놓치기 쉬운 누락된 에러 처리·중복 코드·테스트 누락을 빠르게 짚어 준다. 강의는 "본인이 쓴 코드를 다시 한번 점검받는 페어 프로그래머"의 관점으로 쓰라고 안내한다.

Customizing Claude Code

여기서부터가 Claude Code를 "내 도구"로 만드는 지점이다. 다섯 개 축이 등장한다.

L8CLAUDE.md (The CLAUDE.md file)

프로젝트 루트에 두면 매 세션 시작 시 자동으로 컨텍스트에 들어간다. 코딩 컨벤션·디렉터리 구조·자주 쓰는 명령을 적어 두면 매번 다시 설명할 필요가 없다. 본 블로그의 실전 활용 가이드에서도 같은 점을 강조했다.

L9Subagents (Subagents)

특정 역할(예: 리뷰어, 테스터, 데이터 분석가)에 특화된 별도의 에이전트를 만들어 두고, 메인 세션이 필요할 때 위임한다. 컨텍스트를 분리해서 메인 에이전트의 윈도우를 절약하는 효과가 크다. 자세한 내용은 별도 강의("Introduction to Subagents")에서 깊게 다룬다.

L10Skills (Skills)

"Claude에게 같은 절차를 매번 설명하지 말고 한번 가르쳐 두자"는 메커니즘이다. Markdown 한 장으로 절차를 정의해 두면 트리거 조건이 맞을 때 자동으로 로드된다. 마찬가지로 별도 강의("Introduction to Agent Skills")가 따로 있다.

L11MCP (MCP)

Model Context Protocol. Claude Code가 외부 도구(Slack·Gmail·DB·내부 사내 API 등)와 표준 방식으로 연결되게 해 주는 프로토콜이다. 강의는 "이미 만들어진 MCP 서버를 붙이는 것"에서 시작하고, 직접 작성은 in Action 코스에서 다룬다.

L12Hooks (Hooks)

세션 라이프사이클(PreToolUse·PostToolUse·Stop 등)의 특정 시점에 자기 스크립트를 끼워 넣는 메커니즘이다. 자동 포매팅·금지된 명령 차단·작업 종료 시 알림 같은 자동화에 쓴다. 메모리·설정 파일이 아니라 settings.json에 정의된다는 점이 중요하다.

실무 적용 포인트

강의 자체는 입문용이지만, 듣고 나서 바로 써 보면 다음 네 가지가 가장 큰 차이를 만든다.

CLAUDE.md를 가장 먼저 깐다

코드 한 줄을 시키기 전에 CLAUDE.md에 코딩 컨벤션·금지 사항·디렉터리 구조를 정리한다. 그래야 매 세션에서 "Allman 중괄호 써", "raw new/delete 금지야"를 반복해서 말할 필요가 없어진다.

계획부터 받는다

"바로 코드 짜 줘" 대신 "이 변경을 어떻게 할지 계획부터 글로 적어 줘"가 거의 항상 더 좋은 결과를 낸다. 잘못된 가정은 계획 단계에서 잡는 게 훨씬 싸다.

작업 단위마다 세션 분리

한 세션을 며칠씩 끌고 가지 않는다. 작업 하나가 끝나면 닫고 다음 작업은 새 세션으로 시작한다. 컨텍스트가 오염되면 모델의 판단력이 눈에 띄게 떨어진다.

커스터마이즈는 천천히

Subagents·Skills·MCP·Hooks는 모두 강력하지만 한꺼번에 다 도입하면 디버깅이 어려워진다. 일주일 정도 기본만 쓰면서 "어디가 반복 작업인가"를 식별한 뒤 그 자리에 맞는 도구를 하나씩 추가한다.

한계와 더 알아볼 것

101은 의도적으로 얇게 만든 강의다. 다음 세 가지는 별도 코스에서 보충해야 한다.

  • Subagents 깊이 있는 설계 — "Introduction to Subagents"에서 다룬다. 본 블로그의 확장 강의 정리에서 다시 본다.
  • Skills 작성과 공유 — "Introduction to Agent Skills"가 별도로 있다. 같은 글에서 함께 정리한다.
  • 실전 통합과 SDK·Hooks 심화 — "Claude Code in Action"이 별도로 있다. 실전 워크플로 정리에서 본다.
이 강의에 어울리는 다음 단계 101을 끝낸 직후라면 자기 프로젝트에 CLAUDE.md를 깔고, 작업 하나를 "탐색-계획-코드-커밋" 흐름으로 통과시키는 것이 가장 좋다. 그 다음 Subagents/Skills로 넘어가면 자연스럽다.
