임계화란?

임계화(thresholding)는 픽셀을 임계값(threshold) 기준으로 둘 또는 그 이상의 그룹으로 나누는 연산이다. 가장 흔한 형태는 그레이스케일 영상을 입력받아 이진 영상(0 또는 255만 가지는 영상)으로 바꾸는 것이다. 어떤 픽셀이 밝으면 객체(전경), 어두우면 배경 — 이렇게 한 장의 영상을 의미 있는 두 영역으로 가른다.

이 단순한 연산이 중요한 이유는 임계화가 segmentation의 가장 기본이기 때문이다. 객체를 배경에서 분리해야 그다음 단계인 윤곽선 검출, 블롭 분석, 면적·치수 측정이 가능하다. 임계화가 흔들리면 그 위에 쌓는 모든 검사가 흔들린다.

임계화는 입력 히스토그램의 어디에 경계선을 긋느냐의 문제다. 핵심 질문은 늘 하나다 — 그 경계선을 어떻게 정할 것인가. 사람이 직접 정하면 전역 임계화, 알고리즘이 히스토그램을 보고 자동으로 정하면 Otsu·삼각형, 픽셀마다 주변을 보고 따로 정하면 적응형 임계화다.

임계화는 거의 항상 그레이스케일에 적용한다 컬러 영상은 채널마다 값이 달라 하나의 임계값으로 나누기 어렵다. 보통 cvtColor로 그레이스케일로 바꾼 뒤 임계화한다. 색 정보가 분리에 꼭 필요하면 HSV 변환 후 특정 채널에 적용하기도 한다.

전역 임계화 (threshold)

전역 임계화는 영상 전체에 고정된 하나의 임계값을 적용한다. OpenCV에서는 cv::threshold 함수를 쓴다.

#include <opencv2/opencv.hpp>

int main()
{
    // 그레이스케일로 읽는다
    cv::Mat gray = cv::imread("part.png", cv::IMREAD_GRAYSCALE);
    if (gray.empty())
    {
        std::cerr << "이미지를 열 수 없습니다." << std::endl;
        return -1;
    }

    cv::Mat binary;
    // 임계값 127보다 크면 255, 작으면 0
    double usedThresh = cv::threshold(gray, binary, 127, 255, cv::THRESH_BINARY);

    std::cout << "적용된 임계값: " << usedThresh << std::endl;

    cv::imshow("binary", binary);
    cv::waitKey(0);
    return 0;
}

threshold의 인자는 차례로 입력 영상, 출력 영상, 임계값, 최대값(maxval), 타입이다. 반환값은 실제로 사용된 임계값인데, 전역 임계화에서는 입력한 값이 그대로 나오지만 Otsu·삼각형을 쓰면 자동으로 계산된 값이 나온다.

5가지 임계화 타입

다섯 번째 인자인 타입이 임계값을 넘는·못 넘는 픽셀을 어떻게 처리할지 결정한다. 픽셀값을 src, 임계값을 T, 최대값을 maxval이라 하면 다음과 같다.

타입src > T 일 때src ≤ T 일 때용도
THRESH_BINARYmaxval0가장 일반적인 이진화 (밝은 객체)
THRESH_BINARY_INV0maxval반전 이진화 (어두운 객체)
THRESH_TRUNCTsrc 그대로밝은 부분만 잘라 상한 고정
THRESH_TOZEROsrc 그대로0임계값 이하를 배경으로 제거
THRESH_TOZERO_INV0src 그대로임계값 초과를 제거
cv::Mat gray = cv::imread("part.png", cv::IMREAD_GRAYSCALE);

cv::Mat bin, binInv, trunc, toZero, toZeroInv;

// 임계값 127 기준 5가지 타입을 각각 적용한다
cv::threshold(gray, bin,       127, 255, cv::THRESH_BINARY);
cv::threshold(gray, binInv,    127, 255, cv::THRESH_BINARY_INV);
cv::threshold(gray, trunc,     127, 255, cv::THRESH_TRUNC);
cv::threshold(gray, toZero,    127, 255, cv::THRESH_TOZERO);
cv::threshold(gray, toZeroInv, 127, 255, cv::THRESH_TOZERO_INV);

// BINARY 와 BINARY_INV 는 결과가 정확히 반대다
// TRUNC / TOZERO 계열은 0/255 가 아니라 원래 밝기를 일부 보존한다
BINARY 계열만 이진 영상을 만든다 THRESH_BINARY와 THRESH_BINARY_INV만 결과가 0/maxval 두 값으로 떨어진다. TRUNC·TOZERO 계열은 밝기를 일부 남기므로 이진화가 아니라 밝기 클리핑에 가깝다. segmentation 목적이면 BINARY 계열을 쓴다.

전역 임계화의 한계

전역 임계화는 빠르고 간단하지만 치명적인 약점이 있다 — 조명이 불균일하면 영상 전체를 하나의 임계값으로 나눌 수 없다. 한쪽이 밝고 다른 쪽이 어두운 영상에서는, 밝은 쪽 배경이 어두운 쪽 객체보다 더 밝을 수 있다. 이러면 어떤 임계값을 골라도 한쪽은 반드시 틀린다.

전역 임계화 vs 적응형 임계화: 조명이 불균일한 영상에서의 차이.
조명 불균일에 전역 임계화를 쓰면 반드시 한쪽이 깨진다 그림자, 비네팅, 한쪽으로 치우친 조명이 있는 영상에서 단일 임계값은 밝은 영역 기준으로 맞추면 어두운 영역이 통째로 객체가 되고, 어두운 영역 기준으로 맞추면 밝은 영역의 객체가 사라진다. 이 경우 답은 적응형 임계화이거나, 애초에 조명을 균일하게 만드는 것이다.

Otsu 임계화 — 자동 임계값

전역 임계화의 또 다른 불편함은 임계값을 사람이 정해야 한다는 점이다. 영상이 조금만 바뀌어도 다시 튜닝해야 한다. Otsu 임계화는 이 임계값을 히스토그램에서 자동으로 찾는다.

원리는 이렇다. 임계값을 0부터 255까지 모두 시도해 보면서, 그 값으로 픽셀을 두 클래스(전경/배경)로 나눴을 때 두 클래스 간 분산(between-class variance)이 최대가 되는 지점을 고른다. 클래스 간 분산이 크다는 건 두 그룹이 밝기 면에서 가장 뚜렷하게 갈라진다는 뜻이다.

Otsu는 THRESH_OTSU 플래그를 타입에 OR로 더해서 쓴다. 이때 threshold에 넘기는 임계값 인자는 무시되므로 보통 0을 넣는다.

cv::Mat gray = cv::imread("part.png", cv::IMREAD_GRAYSCALE);

cv::Mat otsu;
// 임계값 인자(0)는 무시된다. Otsu 가 자동으로 계산한다
double otsuT = cv::threshold(gray, otsu, 0, 255,
                             cv::THRESH_BINARY | cv::THRESH_OTSU);

std::cout << "Otsu 가 찾은 임계값: " << otsuT << std::endl;
실행 결과 (콘솔)
Otsu 가 찾은 임계값: 138

Otsu는 히스토그램이 양봉(bimodal)일 때, 즉 전경과 배경이 각각 뚜렷한 봉우리를 이룰 때 가장 잘 동작한다. 두 봉우리 사이의 골짜기에 정확히 임계값을 놓기 때문이다.

Otsu는 두 봉우리 사이 골짜기에 임계값을 놓아 클래스 간 분산을 최대화한다.
Otsu도 전역 임계화의 일종이다 Otsu는 임계값을 자동으로 찾아줄 뿐, 결국 영상 전체에 하나의 임계값을 적용한다. 따라서 조명 불균일 문제는 Otsu로도 해결되지 않는다. 자동 임계값과 조명 대응은 별개의 문제다.

삼각형 알고리즘 (THRESH_TRIANGLE)

Otsu는 양봉 히스토그램을 가정한다. 그런데 실제 영상은 봉우리가 하나뿐인 단봉(unimodal) 히스토그램인 경우도 많다 — 예를 들어 어두운 배경에 작은 객체 몇 개만 있는 형광 영상이나 결함 검출 영상이 그렇다. 이때 Otsu는 골짜기를 찾지 못해 엉뚱한 값을 낸다.

삼각형 알고리즘은 다른 접근을 쓴다. 히스토그램에서 가장 높은 봉우리와 히스토그램의 끝점을 직선으로 잇고, 그 직선에서 히스토그램 곡선까지의 수직 거리가 최대가 되는 밝기를 임계값으로 삼는다. 봉우리가 하나여도 동작하므로 단봉 히스토그램에 유리하다.

cv::Mat gray = cv::imread("defect.png", cv::IMREAD_GRAYSCALE);

cv::Mat tri;
// THRESH_TRIANGLE 도 임계값 인자는 무시된다
double triT = cv::threshold(gray, tri, 0, 255,
                            cv::THRESH_BINARY | cv::THRESH_TRIANGLE);

std::cout << "삼각형 알고리즘 임계값: " << triT << std::endl;

// 같은 영상에서 Otsu 와 비교해 본다
cv::Mat otsu;
double otsuT = cv::threshold(gray, otsu, 0, 255,
                             cv::THRESH_BINARY | cv::THRESH_OTSU);
std::cout << "Otsu 임계값: " << otsuT << std::endl;
항목THRESH_OTSUTHRESH_TRIANGLE
원리클래스 간 분산 최대화봉우리-끝점 직선까지 거리 최대화
가정하는 히스토그램양봉 (bimodal)단봉 (unimodal)
잘 맞는 상황전경·배경이 비슷한 양으로 뚜렷이 갈릴 때배경이 압도적이고 객체가 작을 때
약한 상황한쪽 클래스가 매우 작을 때전경·배경이 균형 잡힌 양봉일 때
사용법THRESH_BINARY | THRESH_OTSUTHRESH_BINARY | THRESH_TRIANGLE
둘 다 돌려보고 히스토그램으로 판단한다 검사 대상 영상의 히스토그램을 한 번 그려보면 양봉인지 단봉인지 바로 보인다. 양봉이면 Otsu, 봉우리가 하나로 치우쳤으면 삼각형 알고리즘이 안정적이다. 둘 다 자동이므로 후보 영상 몇 장에 둘 다 적용해 결과를 비교하면 빠르게 결정할 수 있다.

적응형 임계화 (adaptiveThreshold)

적응형 임계화는 조명 불균일 문제의 정공법이다. 영상 전체에 하나의 임계값을 쓰는 대신, 픽셀마다 그 픽셀 주변의 작은 영역을 보고 임계값을 따로 계산한다. 한쪽이 어둡든 밝든, 그 지역의 평균 밝기를 기준으로 판단하므로 조명 그라데이션에 강하다.

cv::Mat gray = cv::imread("uneven.png", cv::IMREAD_GRAYSCALE);

cv::Mat adaptive;
cv::adaptiveThreshold(
    gray, adaptive,
    255,                              // maxValue
    cv::ADAPTIVE_THRESH_GAUSSIAN_C,   // 주변 영역 가중 방식
    cv::THRESH_BINARY,                // BINARY 또는 BINARY_INV 만 가능
    11,                               // blockSize — 주변 영역 크기 (홀수!)
    2);                               // C — 평균에서 뺄 상수

cv::imshow("adaptive", adaptive);
cv::waitKey(0);

핵심 파라미터

적응형 임계화의 동작을 좌우하는 인자는 세 가지다.

인자값의미
adaptiveMethodADAPTIVE_THRESH_MEAN_C주변 blockSize 영역의 단순 평균을 기준으로
adaptiveMethodADAPTIVE_THRESH_GAUSSIAN_C주변 영역을 가우시안 가중 평균 (중심에 가중치)
blockSize3, 5, 7, 11, 15 ...임계값 계산에 쓰는 주변 영역 크기. 반드시 홀수
C보통 2 ~ 10계산된 지역 평균에서 빼는 상수. 클수록 임계가 엄격해져 노이즈가 줄어듦

임계값은 픽셀마다 (주변 영역의 평균) - C로 정해진다. blockSize는 "주변"의 범위를 정한다. 너무 작으면 노이즈에 민감하고, 너무 크면 다시 전역 임계화처럼 둔해진다. 검출하려는 객체보다 약간 큰 정도가 무난하다. C는 미세 조정용 — 배경 노이즈가 객체로 잡히면 C를 키운다.

blockSize는 반드시 홀수여야 한다 blockSize는 주변 영역의 중심 픽셀이 명확히 하나로 정해져야 하므로 홀수만 허용된다. 짝수를 넣으면 OpenCV가 예외를 던진다. 변수로 계산해서 넘길 때는 blockSize | 1처럼 강제로 홀수로 만들거나, 짝수면 1을 더하는 방어 코드를 두는 편이 안전하다.
adaptiveThreshold는 8비트 1채널 입력만 받는다 adaptiveThreshold는 CV_8UC1 입력만 처리하고, 타입도 THRESH_BINARY 또는 THRESH_BINARY_INV만 받는다. Otsu 플래그와 함께 쓸 수 없다. 컬러나 16비트 영상은 미리 그레이스케일 8비트로 변환해야 한다.

전처리와의 조합

임계화는 단독으로 쓰기보다 앞뒤로 다른 연산과 묶을 때 결과가 훨씬 안정적이다. 핵심은 두 가지 — 임계화 전에는 블러로 노이즈를 줄이고, 임계화 후에는 모폴로지로 결과를 정리한다.

임계화 전 — 블러로 노이즈 억제

입력에 노이즈가 많으면 임계값 근처의 픽셀들이 제멋대로 0/255로 튀어 이진 영상에 점들이 흩뿌려진다. 가우시안 블러로 먼저 부드럽게 만들면 이런 잡티가 크게 줄어든다. 특히 Otsu 앞에 가우시안 블러를 두는 조합은 OpenCV 공식 튜토리얼에서도 권장한다.

cv::Mat gray = cv::imread("noisy.png", cv::IMREAD_GRAYSCALE);

// 1) 블러로 노이즈를 먼저 줄인다
cv::Mat blurred;
cv::GaussianBlur(gray, blurred, cv::Size(5, 5), 0);

// 2) 그다음 Otsu 임계화 — 노이즈가 줄어 임계값이 더 안정적이다
cv::Mat binary;
cv::threshold(blurred, binary, 0, 255,
              cv::THRESH_BINARY | cv::THRESH_OTSU);

임계화 후 — 모폴로지로 정리

임계화 결과에는 보통 작은 구멍이나 떨어져 나온 점들이 남는다. 모폴로지 연산으로 이를 정리한다. 열림(opening)은 작은 흰 점(노이즈)을 제거하고, 닫힘(closing)은 객체 안의 작은 검은 구멍을 메운다.

cv::Mat binary;  // 임계화 결과라고 가정

// 3x3 사각형 구조 요소
cv::Mat kernel = cv::getStructuringElement(cv::MORPH_RECT, cv::Size(3, 3));

// 열림 — 흩어진 작은 흰 점 제거
cv::Mat opened;
cv::morphologyEx(binary, opened, cv::MORPH_OPEN, kernel);

// 닫힘 — 객체 내부의 작은 구멍 메우기
cv::Mat cleaned;
cv::morphologyEx(opened, cleaned, cv::MORPH_CLOSE, kernel);

// cleaned 는 윤곽선 검출·블롭 분석에 바로 쓸 수 있는 깔끔한 이진 영상
전형적인 파이프라인: 그레이 → 블러 → 임계화 → 모폴로지 대부분의 검사는 이 네 단계로 깔끔한 이진 영상을 얻는다. 이 순서를 기본 틀로 잡고, 영상 특성에 따라 블러 커널 크기나 모폴로지 횟수만 조정하면 된다.

임계화 방법 선택 가이드

어떤 방법을 쓸지는 두 가지로 결정된다 — 조명이 균일한가, 그리고 히스토그램이 어떤 모양인가.

상황히스토그램권장 방법
조명 균일, 임계값을 알고 고정 가능상관없음threshold + 고정값
조명 균일, 영상마다 밝기가 조금씩 변함양봉 (bimodal)THRESH_OTSU
조명 균일, 배경이 압도적이고 객체가 작음단봉 (unimodal)THRESH_TRIANGLE
조명 불균일 (그림자·비네팅·치우친 조명)봉우리가 뭉개짐adaptiveThreshold
조명 불균일하지만 객체 크기가 다양함—adaptiveThreshold + blockSize 튜닝, 또는 조명 개선
가장 좋은 선택은 조명을 고치는 것이다 알고리즘 선택 이전에, 조명을 균일하게 만들 수 있다면 그게 최선이다. 조명이 균일하면 Otsu나 고정 임계값처럼 단순하고 빠른 방법이 안정적으로 동작한다. 적응형 임계화는 어쩔 수 없을 때의 대응책이지 1순위 해법이 아니다.

산업 검사 관점

산업용 비전 검사에서 임계화는 거의 모든 검사의 출발점이다. 치수 측정, 결함 검출, 위치 정렬, 카운팅 — 무엇을 하든 먼저 객체를 배경에서 안정적으로 분리해야 한다. 임계화가 프레임마다 흔들리면 그 위에 쌓은 측정값도 함께 흔들리고, 검사 시스템 전체의 신뢰도가 무너진다.

여기서 핵심 원칙이 하나 나온다 — 임계화를 알고리즘으로 어렵게 푸는 대신, 조명 설계로 임계화를 쉽게 만든다. 백라이트로 실루엣을 만들면 객체와 배경의 대비가 극단적으로 커져서 어떤 임계값을 써도 잘 갈린다. 동축 조명, 돔 조명, 편광 필터 같은 조명 설계가 결국 임계화의 안정성을 결정한다.

좋은 조명 한 번이 알고리즘 튜닝 100번을 이긴다 현장에서 임계화가 불안정하면 코드를 더 복잡하게 만들기 전에 조명부터 본다. 백라이트 하나로 양봉 히스토그램이 만들어지면, 그 뒤로는 Otsu 한 줄로 끝난다. 조명에 투자하는 편이 알고리즘을 정교하게 다듬는 것보다 거의 항상 더 싸고 더 견고하다.

또 하나, 산업 검사에서는 임계화 결과의 재현성이 중요하다. 같은 부품을 100번 찍으면 100번 같은 이진 영상이 나와야 한다. 그래서 자동 임계화(Otsu·삼각형)를 쓰더라도, 정상 영상들에서 계산된 임계값의 분포를 모니터링해 두면 좋다. 임계값이 평소 범위를 크게 벗어나면 조명이 바뀌었거나 카메라에 문제가 생겼다는 신호다.

흔한 함정

임계화에서 반복적으로 마주치는 실수들이다.

조명 불균일인데 전역 임계화

그림자가 있는데 threshold 한 줄로 끝내려 한다 조명이 한쪽으로 치우쳤거나 그림자가 있는 영상에 전역 임계화(Otsu 포함)를 쓰면, 임계값을 어떻게 잡아도 한쪽 영역이 통째로 객체가 되거나 사라진다. 이런 영상은 처음부터 adaptiveThreshold로 가거나 조명을 고쳐야 한다. 전역 임계화로 버티려고 임계값을 미세 조정하는 건 시간 낭비다.

Otsu의 가정을 무시

Otsu는 두 가지를 전제한다 — 입력이 그레이스케일이고, 히스토그램이 양봉이라는 것. 컬러 영상을 그냥 넣거나, 봉우리가 하나뿐인 단봉 히스토그램에 Otsu를 쓰면 임계값이 엉뚱한 곳에 찍힌다.

// 나쁨 — 컬러 영상에 바로 Otsu (의미 없는 결과)
// cv::Mat color = cv::imread("part.png");          // CV_8UC3
// cv::threshold(color, out, 0, 255,
//               cv::THRESH_BINARY | cv::THRESH_OTSU);

// 좋음 — 그레이스케일로 변환 후 적용
cv::Mat color = cv::imread("part.png");
cv::Mat gray;
cv::cvtColor(color, gray, cv::COLOR_BGR2GRAY);
cv::threshold(gray, out, 0, 255,
              cv::THRESH_BINARY | cv::THRESH_OTSU);

// 단봉 히스토그램이면 Otsu 대신 THRESH_TRIANGLE 을 고려한다

adaptiveThreshold의 blockSize에 짝수

blockSize에 짝수를 넣으면 예외가 난다 계산한 값을 그대로 blockSize로 넘기다 보면 짝수가 들어가 런타임 예외로 이어진다. 객체 크기에서 blockSize를 유도할 때는 size | 1로 강제 홀수화하거나, 짝수면 1을 더하는 방어 코드를 항상 넣는다. blockSize는 1보다 커야 한다는 제약도 있다. 
int estimated = objectSize / 2;        // 짝수가 나올 수 있다
int blockSize = estimated | 1;         // 강제로 홀수화
if (blockSize < 3) blockSize = 3;      // 최소값 보장

cv::adaptiveThreshold(gray, dst, 255,
                      cv::ADAPTIVE_THRESH_GAUSSIAN_C,
                      cv::THRESH_BINARY, blockSize, 2);

임계값 하드코딩

threshold(gray, dst, 127, ...) 가 영원히 통할 거라는 착각 개발할 때 쓴 영상에서 127이 잘 맞았다고 그 값을 코드에 박아두면, 조명이 약간만 바뀌거나 카메라를 교체하거나 부품 표면이 달라지는 순간 검사가 무너진다. 가능하면 Otsu·삼각형 같은 자동 임계화를 쓰고, 고정값이 꼭 필요하면 최소한 설정 파일·파라미터로 빼서 현장에서 조정할 수 있게 한다. 임계값을 상수로 박는 건 가장 흔하고 가장 취약한 실수다.
정리하면 조명이 균일하면 Otsu(양봉)나 삼각형(단봉)으로 자동 임계화하고, 조명이 불균일하면 adaptiveThreshold로 간다. 임계화 앞에는 블러, 뒤에는 모폴로지를 붙이고, blockSize는 홀수로, 임계값은 하드코딩하지 않는다. 그리고 무엇보다 — 알고리즘으로 고생하기 전에 조명부터 본다.
