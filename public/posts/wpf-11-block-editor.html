데이터 플로우 에디터란

데이터 플로우 에디터는 처리 단계를 노드(Node, 블록)로, 데이터 흐름을 연결선(Edge, Wire)으로 시각화하여 파이프라인을 마우스로 조립하는 도구다. 코드 대신 그래프를 그려 알고리즘을 구성하기 때문에 비개발자도 비전 검사 흐름을 빠르게 시제품화한다.

대표적인 사례는 다음과 같다.

도구분야특징
HALCON HDevelop머신비전스크립트 + 시각 디버깅. 그래프형은 HDevEngine
MVTec Merlic머신비전완전한 노드 그래프 UI
Adaptive Vision Studio머신비전대표적인 데이터 플로우 비전 IDE
NI LabVIEW계측/제어G 언어. 와이어가 곧 데이터
Unreal Blueprint게임 로직실행 핀 + 데이터 핀 분리
Blender Geometry Nodes3D 모델링기하 변환 파이프라인
Node-REDIoT웹 기반 메시지 라우팅

ImagingLib Viewer의 목표는 이 중 Adaptive Vision Studio에 가깝다. C++ 코어 라이브러리(IProcessBlock)를 WPF가 시각적으로 편집·실행한다.

핵심 요구사항

구현 전에 무엇을 만들지 정리한다. 너무 많이 욕심내면 끝이 없으므로 MVP 범위를 좁힌다.

  • 노드 추가/삭제 — 팔레트에서 끌어다 놓거나 컨텍스트 메뉴로 생성
  • 노드 드래그 — 캔버스 위에서 자유 이동
  • 포트 연결 — 출력 포트 → 입력 포트, 타입 호환 검사
  • 줌·팬 — 마우스 휠 줌, 중간 버튼 또는 스페이스+드래그로 팬
  • 선택 — 단일/다중 선택, Delete 키로 삭제
  • 직렬화 — JSON으로 저장/복원
  • 실행 — 토폴로지 정렬 후 노드별 처리 호출

WPF 구성요소 선택

WPF에서 자유 배치 캔버스를 만드는 방법은 두 가지다.

방식장점단점
Canvas 직접 사용간단, 절대좌표 명확MVVM과 거리, Children에 직접 추가 필요
ItemsControl + Canvas ItemsPanelItemsSource 바인딩, MVVM 친화ItemContainerStyle로 Canvas.Left/Top 바인딩 필요

실무는 후자를 택한다. ViewModel의 ObservableCollection<NodeViewModel>이 곧 화면이다. 9편의 MVVM 패턴 위에 그대로 얹는다.

<ItemsControl ItemsSource="{Binding Nodes}">
    <ItemsControl.ItemsPanel>
        <ItemsPanelTemplate>
            <Canvas IsItemsHost="True" Background="#1E1E1E"/>
        </ItemsPanelTemplate>
    </ItemsControl.ItemsPanel>

    <ItemsControl.ItemContainerStyle>
        <Style TargetType="ContentPresenter">
            <Setter Property="Canvas.Left" Value="{Binding X}"/>
            <Setter Property="Canvas.Top"  Value="{Binding Y}"/>
        </Style>
    </ItemsControl.ItemContainerStyle>

    <ItemsControl.ItemTemplate>
        <DataTemplate DataType="{x:Type vm:NodeViewModel}">
            <local:NodeControl />
        </DataTemplate>
    </ItemsControl.ItemTemplate>
</ItemsControl>
ItemContainerStyle이 왜 필요한가 ItemsControl은 각 아이템을 ContentPresenter로 감싸 ItemsPanel에 넣는다. Canvas.Left·Canvas.Top은 그 ContentPresenter에 설정되어야 한다. NodeControl 안에 직접 Canvas.Left를 줘도 무시된다.

노드(Node) 컨트롤

노드는 세 부분으로 나뉜다 — 헤더(제목/타입), 본문(파라미터 요약·미리보기), 포트(입력/출력).

노드 = 헤더 + 본문 + 포트. 출력 포트와 입력 포트가 베지에 곡선으로 연결된다.

NodeControl은 UserControl로 만든다. ViewModel의 InputPorts/OutputPorts를 ItemsControl로 표시한다.

연결선(Connection)

연결선은 Path로 그린다. 3차 베지에 곡선이 자연스럽다. 두 포트 위치를 받아 컨트롤 포인트를 계산한다.

public sealed class ConnectionView : Shape
{
    public static readonly DependencyProperty StartPointProperty =
        DependencyProperty.Register(nameof(StartPoint), typeof(Point), typeof(ConnectionView),
            new FrameworkPropertyMetadata(default(Point), FrameworkPropertyMetadataOptions.AffectsRender));

    public static readonly DependencyProperty EndPointProperty =
        DependencyProperty.Register(nameof(EndPoint), typeof(Point), typeof(ConnectionView),
            new FrameworkPropertyMetadata(default(Point), FrameworkPropertyMetadataOptions.AffectsRender));

    public Point StartPoint { get => (Point)GetValue(StartPointProperty); set => SetValue(StartPointProperty, value); }
    public Point EndPoint   { get => (Point)GetValue(EndPointProperty);   set => SetValue(EndPointProperty, value); }

    protected override Geometry DefiningGeometry
    {
        get
        {
            // Horizontal tangent: control points pulled along X axis.
            double dx = Math.Max(40, Math.Abs(EndPoint.X - StartPoint.X) * 0.5);
            var c1 = new Point(StartPoint.X + dx, StartPoint.Y);
            var c2 = new Point(EndPoint.X   - dx, EndPoint.Y);

            var figure = new PathFigure { StartPoint = StartPoint };
            figure.Segments.Add(new BezierSegment(c1, c2, EndPoint, isStroked: true));
            return new PathGeometry(new[] { figure });
        }
    }
}

XAML에서는 또 하나의 ItemsControl을 같은 캔버스에 겹쳐 두고 Connections 컬렉션을 표시한다.

<ItemsControl ItemsSource="{Binding Connections}">
    <ItemsControl.ItemsPanel>
        <ItemsPanelTemplate><Canvas IsItemsHost="True"/></ItemsPanelTemplate>
    </ItemsControl.ItemsPanel>
    <ItemsControl.ItemTemplate>
        <DataTemplate>
            <local:ConnectionView Stroke="#F59E0B" StrokeThickness="2"
                                  StartPoint="{Binding StartPoint}"
                                  EndPoint="{Binding EndPoint}"/>
        </DataTemplate>
    </ItemsControl.ItemTemplate>
</ItemsControl>
연결선이 노드 뒤에 깔리도록 Z-order를 정한다 Connections 패널을 Nodes 패널보다 먼저(아래에) 둔다. 그래야 노드가 연결선을 덮어 깔끔해 보인다.

드래그·연결 인터랙션

노드 드래그

가장 간단한 방법은 Attached Behavior다. 코드 비하인드 대신 첨부 동작으로 묶으면 재사용성이 높다.

public static class DraggableBehavior
{
    public static readonly DependencyProperty IsEnabledProperty =
        DependencyProperty.RegisterAttached("IsEnabled", typeof(bool), typeof(DraggableBehavior),
            new PropertyMetadata(false, OnIsEnabledChanged));

    public static void SetIsEnabled(DependencyObject d, bool v) => d.SetValue(IsEnabledProperty, v);
    public static bool GetIsEnabled(DependencyObject d) => (bool)d.GetValue(IsEnabledProperty);

    private static Point s_startMouse;
    private static Point s_startPos;
    private static bool  s_dragging;

    private static void OnIsEnabledChanged(DependencyObject d, DependencyPropertyChangedEventArgs e)
    {
        if (d is FrameworkElement fe && (bool)e.NewValue)
        {
            fe.MouseLeftButtonDown += (s, ev) =>
            {
                if (fe.DataContext is not NodeViewModel vm) return;
                s_startMouse = ev.GetPosition(Application.Current.MainWindow);
                s_startPos   = new Point(vm.X, vm.Y);
                s_dragging   = true;
                fe.CaptureMouse();
            };
            fe.MouseMove += (s, ev) =>
            {
                if (!s_dragging || fe.DataContext is not NodeViewModel vm) return;
                var cur = ev.GetPosition(Application.Current.MainWindow);
                vm.X = s_startPos.X + (cur.X - s_startMouse.X);
                vm.Y = s_startPos.Y + (cur.Y - s_startMouse.Y);
            };
            fe.MouseLeftButtonUp += (s, ev) =>
            {
                s_dragging = false;
                fe.ReleaseMouseCapture();
            };
        }
    }
}

NodeControl에서 local:DraggableBehavior.IsEnabled="True"로 켠다. 좌표를 ViewModel의 X/Y에 쓰면 Canvas.Left/Canvas.Top 바인딩이 자동 갱신된다.

포트 드래그로 연결 만들기

출력 포트를 누르고 있다가 입력 포트에서 떼면 연결선이 생긴다. 드래그 도중에는 임시 연결선이 마우스를 따라가야 한다.

public sealed class GraphCanvas : Canvas
{
    private PortViewModel? _dragSource;
    private ConnectionView? _temp;

    public void BeginConnection(PortViewModel source, Point start)
    {
        _dragSource = source;
        _temp = new ConnectionView
        {
            Stroke = Brushes.Orange,
            StrokeThickness = 2,
            StrokeDashArray = new DoubleCollection { 4, 2 },
            StartPoint = start,
            EndPoint   = start
        };
        Children.Add(_temp);
        CaptureMouse();
    }

    protected override void OnMouseMove(MouseEventArgs e)
    {
        if (_temp != null)
        {
            _temp.EndPoint = e.GetPosition(this);
        }
    }

    protected override void OnMouseLeftButtonUp(MouseButtonEventArgs e)
    {
        if (_temp == null || _dragSource == null) return;

        // Hit-test the element under the cursor.
        var hit = InputHitTest(e.GetPosition(this)) as FrameworkElement;
        if (hit?.DataContext is PortViewModel target && CanConnect(_dragSource, target))
        {
            var graph = (GraphViewModel)DataContext;
            graph.AddConnection(_dragSource, target);
        }

        Children.Remove(_temp);
        _temp = null;
        _dragSource = null;
        ReleaseMouseCapture();
    }

    private static bool CanConnect(PortViewModel a, PortViewModel b)
        => a.Direction != b.Direction
        && a.OwnerNode  != b.OwnerNode
        && a.DataType   == b.DataType;
}
포트의 화면 좌표 계산은 좌표 변환을 거쳐야 한다 포트 Ellipse는 노드 안 깊이 위치한다. 캔버스 기준 좌표가 필요할 때는 port.TransformToAncestor(canvas).Transform(new Point(width/2, height/2))로 변환한다. 노드의 Canvas.Left만 읽으면 포트의 실제 위치와 어긋난다.

줌·팬

캔버스 자체에 RenderTransform으로 MatrixTransform을 걸어 변환한다. ScaleTransform·TranslateTransform을 따로 두기보다 행렬 하나로 두는 편이 조합이 깔끔하다.

public sealed partial class GraphCanvasHost : UserControl
{
    private readonly MatrixTransform _xf = new();
    private Point _panStart;
    private bool  _panning;

    public GraphCanvasHost()
    {
        InitializeComponent();
        Canvas.RenderTransform = _xf;
    }

    private void OnMouseWheel(object s, MouseWheelEventArgs e)
    {
        double scale = e.Delta > 0 ? 1.1 : 1.0 / 1.1;
        Point center = e.GetPosition(Canvas);

        var m = _xf.Matrix;
        m.ScaleAtPrepend(scale, scale, center.X, center.Y);
        _xf.Matrix = m;
    }

    private void OnMouseDown(object s, MouseButtonEventArgs e)
    {
        if (e.MiddleButton == MouseButtonState.Pressed)
        {
            _panStart = e.GetPosition(this);
            _panning  = true;
            CaptureMouse();
        }
    }

    private void OnMouseMove(object s, MouseEventArgs e)
    {
        if (!_panning) return;
        var cur = e.GetPosition(this);
        var dx  = cur.X - _panStart.X;
        var dy  = cur.Y - _panStart.Y;
        _panStart = cur;

        var m = _xf.Matrix;
        m.Translate(dx, dy);
        _xf.Matrix = m;
    }

    private void OnMouseUp(object s, MouseButtonEventArgs e)
    {
        _panning = false;
        ReleaseMouseCapture();
    }
}
화면 좌표 ↔ 캔버스 좌표 줌·팬이 걸리면 마우스의 화면 좌표와 캔버스 내부 좌표가 다르다. 노드 배치·히트 테스트는 항상 e.GetPosition(canvas)로 캔버스 좌표를 얻은 뒤 사용한다.

선택 처리

선택은 ViewModel의 책임이다. NodeViewModel.IsSelected를 토글하고, 뷰는 DataTrigger로 외곽선을 강조한다.

public void SelectNode(NodeViewModel node, bool addToSelection)
{
    if (!addToSelection)
    {
        foreach (var n in Nodes) n.IsSelected = false;
    }
    node.IsSelected = true;
}

// Delete key handler at the canvas level.
public void DeleteSelected()
{
    var doomed = Nodes.Where(n => n.IsSelected).ToList();
    foreach (var n in doomed)
    {
        // Cascade: remove connections touching this node first.
        var related = Connections.Where(c => c.Source.OwnerNode == n || c.Target.OwnerNode == n).ToList();
        foreach (var c in related) Connections.Remove(c);
        Nodes.Remove(n);
    }
}

박스 선택(러버밴드)은 빈 캔버스에서 좌클릭 드래그 시 Rectangle을 그리고, 종료 시 박스 안에 들어온 노드를 모두 선택한다. 박스 영역과 노드의 Rect를 Rect.Contains로 검사한다.

데이터 모델

UI를 한 줄도 건드리지 않고 그래프를 만들 수 있을 만큼 ViewModel이 자기 완결적이어야 한다. MVVM(9편)의 원칙을 그대로 따른다.

클래스책임주요 멤버
PortViewModel입출력 단자Name, Direction, DataType, OwnerNode
NodeViewModel처리 블록 1개Id, Title, X/Y, IsSelected, InputPorts, OutputPorts, Parameters
ConnectionViewModel포트 간 연결Source, Target, StartPoint/EndPoint(파생)
GraphViewModel그래프 전체Nodes, Connections, AddNode/AddConnection/Remove
public enum PortDirection { Input, Output }

public sealed class PortViewModel : ObservableObject
{
    public string Name { get; init; } = "";
    public PortDirection Direction { get; init; }
    public Type DataType { get; init; } = typeof(object);
    public NodeViewModel OwnerNode { get; internal set; } = default!;

    // Cached screen-space position, updated when the node moves.
    private Point _position;
    public Point Position { get => _position; set => SetProperty(ref _position, value); }
}

public sealed class NodeViewModel : ObservableObject
{
    public Guid Id { get; } = Guid.NewGuid();
    public string Title { get; init; } = "Node";
    public string BlockType { get; init; } = "";

    private double _x, _y;
    public double X { get => _x; set => SetProperty(ref _x, value); }
    public double Y { get => _y; set => SetProperty(ref _y, value); }

    private bool _isSelected;
    public bool IsSelected { get => _isSelected; set => SetProperty(ref _isSelected, value); }

    public ObservableCollection<PortViewModel> InputPorts  { get; } = new();
    public ObservableCollection<PortViewModel> OutputPorts { get; } = new();
    public Dictionary<string, object> Parameters { get; } = new();
}

public sealed class ConnectionViewModel : ObservableObject
{
    public PortViewModel Source { get; init; } = default!;
    public PortViewModel Target { get; init; } = default!;

    // Derived from port positions; recomputed when nodes move.
    public Point StartPoint => Source.Position;
    public Point EndPoint   => Target.Position;
}

public sealed class GraphViewModel : ObservableObject
{
    public ObservableCollection<NodeViewModel> Nodes { get; } = new();
    public ObservableCollection<ConnectionViewModel> Connections { get; } = new();

    public void AddConnection(PortViewModel a, PortViewModel b)
    {
        var (src, dst) = a.Direction == PortDirection.Output ? (a, b) : (b, a);

        // Reject duplicate connections targeting the same input port.
        var existing = Connections.FirstOrDefault(c => c.Target == dst);
        if (existing != null) Connections.Remove(existing);

        Connections.Add(new ConnectionViewModel { Source = src, Target = dst });
    }
}

직렬화

JSON으로 저장한다. System.Text.Json이 표준이다. DTO 분리가 핵심이다. ViewModel을 그대로 직렬화하면 순환 참조(Port → OwnerNode → Ports → ...)가 생긴다. 평탄한 DTO로 변환한다.

public record GraphDto(List<NodeDto> Nodes, List<ConnectionDto> Connections);

public record NodeDto(
    Guid Id, string BlockType, string Title,
    double X, double Y, Dictionary<string, object> Parameters);

public record ConnectionDto(
    Guid SourceNodeId, string SourcePort,
    Guid TargetNodeId, string TargetPort);

public static class GraphSerializer
{
    public static string Save(GraphViewModel g)
    {
        var dto = new GraphDto(
            g.Nodes.Select(n => new NodeDto(n.Id, n.BlockType, n.Title, n.X, n.Y, n.Parameters)).ToList(),
            g.Connections.Select(c => new ConnectionDto(
                c.Source.OwnerNode.Id, c.Source.Name,
                c.Target.OwnerNode.Id, c.Target.Name)).ToList());

        return JsonSerializer.Serialize(dto, new JsonSerializerOptions { WriteIndented = true });
    }

    public static GraphViewModel Load(string json, IBlockFactory factory)
    {
        var dto = JsonSerializer.Deserialize<GraphDto>(json)
                  ?? throw new InvalidDataException("Empty graph.");

        var graph = new GraphViewModel();
        var byId  = new Dictionary<Guid, NodeViewModel>();

        foreach (var nd in dto.Nodes)
        {
            var node = factory.Create(nd.BlockType);  // Builds ports based on block type.
            node.X = nd.X; node.Y = nd.Y;
            foreach (var kv in nd.Parameters) node.Parameters[kv.Key] = kv.Value;
            graph.Nodes.Add(node);
            byId[nd.Id] = node;
        }

        foreach (var cd in dto.Connections)
        {
            var src = byId[cd.SourceNodeId].OutputPorts.First(p => p.Name == cd.SourcePort);
            var dst = byId[cd.TargetNodeId].InputPorts .First(p => p.Name == cd.TargetPort);
            graph.Connections.Add(new ConnectionViewModel { Source = src, Target = dst });
        }
        return graph;
    }
}

실행 (토폴로지 정렬)

그래프를 실행하려면 의존성 순서대로 노드를 처리해야 한다. DAG(방향 비순환 그래프) 가정에서 Kahn's algorithm으로 토폴로지 정렬한다.

public static IReadOnlyList<NodeViewModel> TopologicalSort(GraphViewModel g)
{
    var indeg = g.Nodes.ToDictionary(n => n, _ => 0);
    foreach (var c in g.Connections) indeg[c.Target.OwnerNode]++;

    var ready = new Queue<NodeViewModel>(indeg.Where(kv => kv.Value == 0).Select(kv => kv.Key));
    var order = new List<NodeViewModel>();

    while (ready.Count > 0)
    {
        var n = ready.Dequeue();
        order.Add(n);
        foreach (var c in g.Connections.Where(c => c.Source.OwnerNode == n))
        {
            var t = c.Target.OwnerNode;
            if (--indeg[t] == 0) ready.Enqueue(t);
        }
    }

    if (order.Count != g.Nodes.Count)
    {
        throw new InvalidOperationException("Cycle detected in graph.");
    }
    return order;
}

public async Task ExecuteAsync(GraphViewModel g, CancellationToken ct = default)
{
    var order = TopologicalSort(g);
    var portOutputs = new Dictionary<PortViewModel, object?>();

    foreach (var node in order)
    {
        ct.ThrowIfCancellationRequested();

        // Gather inputs from upstream output ports.
        var inputs = new Dictionary<string, object?>();
        foreach (var inPort in node.InputPorts)
        {
            var conn = g.Connections.FirstOrDefault(c => c.Target == inPort);
            inputs[inPort.Name] = conn != null ? portOutputs[conn.Source] : null;
        }

        // Invoke the actual block (delegates to C++ core via C++/CLI).
        var block = _registry.Resolve(node.BlockType);
        var outputs = await block.RunAsync(inputs, node.Parameters, ct);

        foreach (var (name, value) in outputs)
        {
            var outPort = node.OutputPorts.First(p => p.Name == name);
            portOutputs[outPort] = value;
        }
    }
}
비전 파이프라인 예시 Source → GaussianBlur → Canny → ContourFind → Measure → Verdict. 각 노드가 위 순서로 실행되며, 이전 노드 출력 Image가 다음 노드의 입력으로 그대로 전달된다.

ImagingLib Viewer 적용

WPF는 시각적 편집만 담당한다. 실제 영상 처리는 C++ 코어가 한다. 두 세계를 잇는 다리는 12편에서 다룰 C++/CLI 래퍼다.

코어 측의 인터페이스는 다음과 같다.

// C++/CLI projection of ImagingLib::Core::IProcessBlock.
public interface IProcessBlock
{
    string TypeId { get; }                      // e.g. "GaussianBlur"
    IReadOnlyList<PortSpec> InputSpecs  { get; }
    IReadOnlyList<PortSpec> OutputSpecs { get; }

    Task<IReadOnlyDictionary<string, object?>> RunAsync(
        IReadOnlyDictionary<string, object?> inputs,
        IReadOnlyDictionary<string, object>  parameters,
        CancellationToken ct);
}

public sealed record PortSpec(string Name, Type DataType);

BlockFactory가 TypeId에서 NodeViewModel을 빌드한다.

public sealed class BlockFactory : IBlockFactory
{
    private readonly Dictionary<string, Func<IProcessBlock>> _ctors = new();

    public void Register(string typeId, Func<IProcessBlock> ctor) => _ctors[typeId] = ctor;

    public NodeViewModel Create(string typeId)
    {
        var block = _ctors[typeId]();
        var node  = new NodeViewModel { BlockType = typeId, Title = typeId };

        foreach (var ps in block.InputSpecs)
        {
            var port = new PortViewModel { Name = ps.Name, Direction = PortDirection.Input,  DataType = ps.DataType };
            port.OwnerNode = node;
            node.InputPorts.Add(port);
        }
        foreach (var ps in block.OutputSpecs)
        {
            var port = new PortViewModel { Name = ps.Name, Direction = PortDirection.Output, DataType = ps.DataType };
            port.OwnerNode = node;
            node.OutputPorts.Add(port);
        }
        return node;
    }
}

각 노드에는 파라미터 패널이 붙는다. 노드 선택 시 우측 패널이 Parameters 딕셔너리를 자동 바인딩하여 슬라이더/숫자 입력으로 표시한다. kernel·sigma 값을 바꾸면 ViewModel만 갱신되고, 사용자가 Run을 누르면 위의 ExecuteAsync가 새 파라미터로 코어를 호출한다.

성능 고려

실무 그래프는 보통 20~100개 노드, 무거운 경우 500개에 이른다. 다음을 챙기면 큰 문제는 없다.

  • UI 가상화 — 화면 밖 노드는 렌더링 생략. 기본 ItemsControl은 가상화하지 않으므로 VirtualizingStackPanel.IsVirtualizing="True" 또는 직접 viewport culling 적용. Canvas는 가상화가 어렵기 때문에 보이는 영역 노드만 컬렉션에 노출하는 방식이 현실적이다.
  • 연결선 캐싱 — 한쪽 끝 노드가 움직일 때만 해당 연결선이 다시 그려지도록 FrameworkPropertyMetadataOptions.AffectsRender를 정확히 표시한다.
  • 드래그 throttling — MouseMove는 초당 수백 번 발생한다. 매 이벤트마다 무거운 계산 금지. 좌표만 갱신.
  • 오프스크린 미리보기 — 노드 본문에 영상 썸네일을 표시할 때는 작은 해상도로 다운샘플링.
  • 대형 그래프 그리드 표시 끄기 — 격자 배경을 VisualBrush로 깔면 비싸다. 줌이 클 때만 그린다.

흔한 함정

1. Canvas 절대좌표에만 의존 노드를 canvas.Children.Add로 직접 넣고 Canvas.SetLeft로 위치를 박으면 MVVM이 깨진다. 직렬화·Undo도 어려워진다. ItemsControl + ItemContainerStyle 바인딩이 정도.
2. 좌표 변환 헷갈림 화면 좌표·캔버스 좌표·줌/팬 후 좌표를 구분하지 않으면 포트가 빗나간다. 항상 e.GetPosition(canvas)로 같은 좌표계를 쓰고, 포트의 캔버스 좌표는 TransformToAncestor(canvas)로 구한다.
3. 직렬화 시 순환 참조 Port가 OwnerNode를 참조하고, Node가 Ports를 가진다. ViewModel 그대로 JSON 변환하면 무한 루프 또는 깊이 초과. DTO를 따로 두고 Id 기반 평탄화.
4. MVVM 깨고 코드 비하인드 남발 드래그·연결·선택을 NodeControl.xaml.cs에 잔뜩 박으면 테스트가 불가능해진다. Attached Behavior로 묶고, 상태는 ViewModel에 두는 규칙을 지킨다.
5. 사이클 검사 누락 사용자가 출력 → 입력을 자기 자신의 조상으로 연결하면 무한 루프. 연결 추가 전에 DFS로 사이클을 검사한다.
6. 포트 위치를 한 번만 계산 노드가 움직이거나 사이즈가 바뀌면 포트 좌표가 변한다. LayoutUpdated·SizeChanged·노드 위치 변경 모두에서 PortViewModel.Position을 갱신해야 연결선이 따라온다.
